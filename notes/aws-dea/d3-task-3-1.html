Orchestration

Skill 3.1.1Orchestrate data pipelines (for example, Amazon Managed Workflows for Apache Airflow [Amazon MWAA], AWS Step Functions).

Orchestration is covered in depth on Task 1.3: the Step Functions error model, Standard versus Express, redrive, MWAA sensors, trigger rules and Airflow 3. In short, choose Step Functions for serverless, event-driven workflows that call AWS APIs directly, and MWAA for Python-defined DAGs, complex scheduling and teams that already know Airflow.

MWAA: Glue job, then Athena query 
from airflow.sdk import DAG
from airflow.providers.amazon.aws.operators.glue import GlueJobOperator
from airflow.providers.amazon.aws.operators.athena import AthenaOperator

with DAG("daily_orders",
         schedule="0 2 * * *"):
    etl = GlueJobOperator(
        task_id="orders_etl",
        job_name="orders-etl")
    report = AthenaOperator(
        task_id="daily_report",
        query="SELECT * FROM sales_v",
        database="retail",
        workgroup="etl")
    etl >> report

The airflow.sdk import is Airflow 3; on Airflow 2 environments import DAG from airflow. Both operators wait for completion by default.

Troubleshooting workflows

Skill 3.1.2Troubleshoot Amazon managed workflows.

Most workflow failures are not in your code. They are in networking, permissions, dependencies, capacity or quotas — and each service records the evidence in a predictable place.

MWAA: where to look

MWAA sends each enabled log type to its own CloudWatch log group, named airflow-<Env>-<LogType>: DAGProcessing, Scheduler, Task, WebServer and Worker, each at INFO, WARNING, ERROR or CRITICAL. Two special streams in the Scheduler group matter: requirements_install_ip holds pip errors from requirements.txt, and streams prefixed startup_script_execution_ip hold startup script output.

SymptomUsual cause and fix
Environment creation stuck or failedNetworking: MWAA needs two private subnets in two AZs and a security group with a self-referencing rule. With public routing the subnets need a NAT route; with private routing they need VPC endpoints (including an S3 gateway endpoint) and no NAT. Also check the execution role's S3 and CloudWatch permissions — blank logs usually mean the role cannot write them
S3 bucket rejectedThe DAG bucket must have Block Public Access and versioning on, and the S3 URI must not end in /
Update fails or rolls back after a requirements.txt changeInstall took over 20 minutes or a package conflicts. Pin versions, keep the Airflow --constraint line, and for private networks ship wheels in plugins.zip with --no-index
"Broken DAG" or a DAG does not appearAn import error (often a missing package). MWAA syncs S3 every 30 seconds, but new DAGs appear only on the scheduler's dag_dir_list_interval. List errors with dags list-import-errors
Tasks stuck in queuedMore tasks than worker slots, or autoscaling not yet caught up. Raise --min-workers, stagger schedules, or reduce concurrency
"The scheduler does not seem to be running"Check that the security group allows port 5432 to the metadata database; database errors are usually a symptom, not the cause

Test DAGs and requirements locally first with AWS's MWAA Docker images (the aws-mwaa-docker-images repository, which replaced the older local runner). For metrics, watch SchedulerHeartbeat, ImportErrors, TotalParseTime, QueuedTasks and TasksStarving in the AmazonMWAA namespace, and CPU, memory and queue age in AWS/MWAA.

More warm workers for a backlog 
aws mwaa update-environment \

  --max-workers 10

Step Functions: reading a failed execution

Standard workflows keep an event history for every execution (90 days), which shows the failing state, its input and the error name. Express workflows keep no history — turn on CloudWatch Logs.

ErrorUsually means
States.PermissionsThe state machine's role lacks permission for the API it called
States.TimeoutTimeoutSeconds exceeded or a heartbeat missed
States.TaskFailedAny task error other than a timeout; a child workflow's timeout also arrives as this
Lambda.TooManyRequestsExceptionThe function is throttled — retry with backoff or raise concurrency
Lambda.Unknown / Sandbox.TimedoutAn unhandled error or the function timed out
States.DataLimitExceededState input or output over 256 KiB — pass S3 pointers instead
States.RuntimeA path error such as InputPath on a missing field; not retriable

A Standard execution fails when its history reaches 25,000 events, a hard limit. A long loop over many items can hit it even though every step succeeds. Use a Distributed Map, start child executions, or continue as a new execution.

  • CloudWatch Logs: levels ALL, ERROR, FATAL or OFF; includeExecutionData adds inputs and outputs. Standard workflows log nothing by default. Name log groups with the /aws/vendedlogs/states prefix to avoid CloudWatch resource-policy size limits.
  • X-Ray tracing shows time spent in each state and service call (not for Distributed Map children).
  • EventBridge receives Step Functions Execution Status Change events (Standard workflows only) for alerting on FAILED, TIMED_OUT or ABORTED.
  • Metrics in AWS/States: ExecutionsFailed, ExecutionsTimedOut, ExecutionThrottled, ExecutionTime.

Glue workflows can resume a failed run from the failed node; keep each workflow under 100 jobs, crawlers and triggers.

SDKs

Skill 3.1.3Call SDKs to access Amazon features from code.

Data engineers mostly use boto3, the AWS SDK for Python, inside Lambda functions, Glue jobs (boto3 is preinstalled and uses the job role) and Airflow tasks. API pagination and retry concepts are on Task 1.1; here are the SDK mechanics.

Credentials, clients and threads

  • Credential chain: boto3 tries, in order, parameters passed in code, environment variables, assume-role and web identity providers, IAM Identity Center, the shared credentials and config files, and finally container credentials and the EC2 instance metadata service. In Lambda and Glue the role's credentials arrive automatically — never put access keys in code.
  • Clients map one-to-one to the service API and are generally thread-safe (but not shareable across processes). Resources (the object-style interface) are feature-frozen: AWS "does not intend to add new features" to them. Resources and sessions are not thread-safe.
  • Create clients once, outside the Lambda handler, so warm invocations reuse them.

Retries and timeouts

Retry modeBehaviour
legacyStill the boto3 default: 5 total attempts
standard3 attempts, exponential backoff up to 20 seconds, more error types retried
adaptiveStandard plus client-side rate limiting (experimental)

In a Config object, max_attempts excludes the first call, while in the config file and AWS_MAX_ATTEMPTS it includes it. Use total_max_attempts to say exactly how many calls you mean. Connect and read timeouts default to 60 seconds, and the connection pool to 10.

Run an Athena query and poll with backoff 
import time
import boto3
from botocore.config import Config

cfg = Config(
    retries={"mode": "standard",
             "total_max_attempts": 5},
    connect_timeout=5,
    read_timeout=60)
athena = boto3.client(
    "athena", config=cfg)

DONE = ("SUCCEEDED", "FAILED",
        "CANCELLED")

qid = athena.start_query_execution(
    QueryString="SELECT * FROM orders"
                " WHERE dt = ?",
    ExecutionParameters=["'2026-11-07'"],
    QueryExecutionContext={
        "Database": "retail"},
    WorkGroup="etl")["QueryExecutionId"]

delay = 1
while True:
    q = athena.get_query_execution(
        QueryExecutionId=qid)
    st = q["QueryExecution"]["Status"]
    if st["State"] in DONE:
        break
    time.sleep(delay)
    delay = min(delay * 2, 20)

if st["State"] != "SUCCEEDED":
    raise RuntimeError(
        st.get("StateChangeReason"))

Paginators and waiters

Paginators hide NextToken loops: get_paginator(...).paginate(...) yields every page, and .search() filters with JMESPath. Waiters poll until a resource reaches a state.

Glue, Athena, EMR Serverless and the Redshift Data API have no boto3 waiters — you poll yourself, as above. EMR has cluster_running, cluster_terminated and step_complete; Redshift has cluster_available and snapshot_available.

Every partition of a table (paginator) 
glue = boto3.client("glue")
pages = glue.get_paginator(
    "get_partitions").paginate(
    DatabaseName="retail",
    TableName="clickstream")

for page in pages:
    for p in page["Partitions"]:
        print(p["Values"])
Add an EMR step and wait for it 
emr = boto3.client("emr")
CLUSTER = "j-2AXXXXXXGAPLF"

step_id = emr.add_job_flow_steps(
    JobFlowId=CLUSTER,
    Steps=[{
        "Name": "orders-etl",
        "ActionOnFailure": "CONTINUE",
        "HadoopJarStep": {
            "Jar": "command-runner.jar",
            "Args": [
                "spark-submit",
                "--deploy-mode",
                "cluster",
                "s3://retail-code/etl.py",
            ],
        },
    }],
)["StepIds"][0]

emr.get_waiter("step_complete").wait(
    ClusterId=CLUSTER, StepId=step_id,
    WaiterConfig={"Delay": 30,

Errors

Service errors raise botocore.exceptions.ClientError; branch on e.response["Error"]["Code"] (for example ThrottlingException), or catch modelled exceptions such as glue.exceptions.ConcurrentRunsExceededException. ParamValidationError means the request was malformed before it was sent.

AWS SDK for pandas

AWS SDK for pandas (the awswrangler package, also published as a Lambda layer) wraps boto3 for DataFrame work: wr.athena.read_sql_query runs a query and returns a DataFrame, and wr.s3.to_parquet with dataset=True writes partitioned Parquet and registers the table in the Glue catalog.

Query, transform, write back (Python) 
import awswrangler as wr

df = wr.athena.read_sql_query(
    "SELECT * FROM orders",
    database="retail")

wr.s3.to_parquet(
    df=df,
    path="s3://retail-lake/cur/orders/",
    dataset=True,
    partition_cols=["dt"],
    mode="overwrite_partitions",
    database="retail",
    table="orders_curated")

The AWS SDK for JavaScript v2 reached end of support on September 8, 2025, and the AWS SDK for Java 1.x on December 31, 2025. Use JavaScript v3 and Java 2.x.

Service features

Skill 3.1.4Use the features of AWS services to process data (for example, Amazon EMR, Amazon Redshift, AWS Glue).

Choosing among EMR, Glue and Redshift is on Task 1.2. This section covers the features you use once you have chosen.

Amazon EMR

  • Steps are units of work (a Spark job, a Hive script) submitted to a cluster. ActionOnFailure decides what a failure does: CONTINUE to the next step, CANCEL_AND_WAIT (cancel pending steps, keep the cluster waiting) or TERMINATE_CLUSTER.
  • Step concurrency: StepConcurrencyLevel runs up to 256 steps in parallel (default 1). With a level above 1, steps cannot use CANCEL_AND_WAIT or TERMINATE_CLUSTER.
  • Auto-termination ends an idle cluster after a timeout (default 60 minutes, 1 minute to 7 days), on by default in the console from EMR 6.4.0. It is the safety net for clusters someone forgot.
  • Bootstrap actions run on every node after launch and before applications are installed — for system packages and agents. Up to 16 per cluster; a failing one fails the node.
  • EMR Studio is a free notebook IDE for EMR clusters, though AWS now points to SageMaker Unified Studio. EMR Serverless jobs run with start-job-run and a sparkSubmit job driver.
Submit a Spark step (CLI) 
aws emr add-steps \

Amazon Redshift

Stored procedures (PL/pgSQL, run with CALL) package multi-statement ELT logic inside the warehouse. They run as the caller by default (SECURITY INVOKER); SECURITY DEFINER runs with the owner's rights. AWS reserves the sp_ prefix for procedure names.

Reload one day of orders 
CREATE OR REPLACE PROCEDURE
  sp_load_orders(p_dt date,
                 n OUT int)
AS $$
BEGIN
  DELETE FROM orders WHERE dt = p_dt;
  INSERT INTO orders
    SELECT * FROM stg_orders
    WHERE dt = p_dt;
  SELECT INTO n count(*)
    FROM orders WHERE dt = p_dt;
END;
$$ LANGUAGE plpgsql;

CALL sp_load_orders('2026-11-07');
  • Scheduled queries in Query Editor v2 run SQL on a cron or frequency schedule through EventBridge and the Redshift Data API, with optional SNS notification. Schedule history is kept only 24 hours and scheduled runs do not appear in query history.
  • UDFs: SQL UDFs and Lambda UDFs (call any code); Python UDFs are unsupported after June 30, 2026.
  • Other in-warehouse processing — materialized views, MERGE, Redshift ML, streaming ingestion — is on Task 2.1 and Task 1.2.

Data APIs

Skill 3.1.5Consume and maintain data APIs.

Consuming APIs (pagination, retries, rate limits) is on Task 1.1, and serving data through API Gateway and AppSync on Task 1.2. Maintaining an API means changing it without breaking its consumers and keeping it healthy.

API Gateway featureUse it for
Stages and stage variablesSeparate dev, test and prod deployments; ${stageVariables.name} points each stage at a different backend or Lambda alias (not for secrets)
Canary releasesSend a percentage of a stage's traffic to a new deployment, then promote or roll back
VersioningA new path (/v2/sales) or stage for breaking changes, so existing clients keep working
Usage plans and API keysPer-client quotas and throttling for partners
ThrottlingThe account default is 10,000 requests per second with a 5,000 burst (lower in some newer Regions); over the limit returns 429
CachingResponses cached per stage for 300 seconds by default (up to 3,600), GET only by default
Request validationReject requests with missing parameters or bodies that fail a JSON Schema model (400) before they reach the backend

Monitor with 4XXError, 5XXError, Count, Latency (the whole round trip) and IntegrationLatency (the backend only). A large gap between the two latencies points at API Gateway itself; a high IntegrationLatency points at the backend query.

Lambda function URLs are a simpler HTTPS endpoint for one function, with IAM or no auth. They have no usage plans, API keys, caching or request validation, and throttle only through reserved concurrency. Partner-facing data APIs usually need API Gateway.

When consuming third-party APIs, keep their keys in Secrets Manager with rotation, and read them at run time rather than baking them into code or job parameters.

Preparing data

Skill 3.1.6Prepare data for transformation (for example, AWS Glue DataBrew and Amazon SageMaker Unified Studio).

Before the main transformation, data needs cleaning and shaping: fixing formats, removing duplicates, filling gaps, masking sensitive fields. These tools let analysts do that visually, without writing Spark.

AWS Glue DataBrew

DataBrew is a visual data-preparation service with "over 250 ready-made transformations". It is still active, with no closure notice.

ConceptWhat it is
DatasetA read-only pointer to data in S3, the Glue catalog, Redshift, JDBC sources or Snowflake
ProjectAn interactive session on a sample — the first 500 rows by default, up to 5,000
RecipeAn ordered list of transformation steps. Publish it to create a version that jobs can use
Recipe jobApplies a recipe to the full dataset and writes the output (CSV, Parquet, Avro, ORC, JSON and more) to S3, the catalog, Redshift or JDBC
Profile jobProduces column statistics and detects PII; the data quality side is on Task 3.4

Jobs default to 5 nodes and a 2,880-minute timeout, and can run on a schedule (no more often than every 5 minutes) or from Step Functions. PII transforms include masking, hashing, substitution, shuffling and deterministic encryption. Pricing is $1.00 per 30-minute interactive session and $0.48 per node-hour for jobs.

Querying

Skill 3.1.7Query data (for example, Amazon Athena).

Athena runs SQL over the lake at $5 per TB scanned. Its DDL is based on HiveQL and its DML on Trino, so CREATE EXTERNAL TABLE follows Hive rules while SELECT follows Trino's — the reason some syntax works in one and not the other. Engine version 3 is the only version listed. Workgroups, quotas and cost controls are on Task 1.2; partitioning and compression are on Task 2.4.

Parameterized queries

Parameters keep user input out of the SQL text. Two forms: execution parameters (? placeholders with values in ExecutionParameters, as in the SDK example above) and prepared statements (PREPARE and EXECUTE ... USING, saved in a workgroup, up to 1,000 per workgroup). Both work for SELECT, INSERT INTO, CTAS and UNLOAD, with positional parameters only.

Prepared statement 
PREPARE orders_by_dt FROM
SELECT order_id, amount
FROM retail.orders
WHERE dt = ? AND amount > ?;

EXECUTE orders_by_dt
USING '2026-11-07', 100;

Nested and JSON data

UNNEST turns an array into rows; note that a NULL or empty array produces no rows, silently dropping the parent unless you use a LEFT JOIN. json_extract_scalar returns a string from a JSON path; json_extract returns JSON text.

One row per item in each order 
SELECT o.order_id, t.sku
FROM retail.orders o
CROSS JOIN UNNEST(o.skus) AS t(sku);
Pull a field out of a JSON string 
SELECT json_extract_scalar(
         payload, '$.device.os') AS os
FROM retail.clickstream
WHERE dt = '2026-11-07';

Views, plans and exports

  • Views: classic Athena views are Athena-only. Data Catalog views (CREATE PROTECTED MULTI DIALECT VIEW ... SECURITY DEFINER) work across Athena, Redshift and EMR Spark and let users query the view without access to its base tables, which must be registered with Lake Formation.
  • EXPLAIN shows the plan and is free. EXPLAIN ANALYZE actually runs the query and bills for the data scanned.
  • UNLOAD writes query results to S3 as Parquet, ORC, Avro, JSON or text, with up to 100 partitions. The destination must be empty.
  • Managed query results (June 2025) store results without an S3 bucket of your own, at no cost, for 24 hours — but without query result reuse.
Export a day's orders as Parquet 
UNLOAD (SELECT order_id, amount, dt
        FROM retail.orders
        WHERE dt = '2026-11-07')
TO 's3://retail-lake/export/o_20261107/'
WITH (format = 'PARQUET',
      compression = 'SNAPPY')

Quotas and Spark

The default active DML query quota is per Region: 200 in us-east-1, 150 in several large Regions, and 20 in many others. Running plus queued queries over the quota return TooManyRequestsException, so a pipeline that fans out hundreds of queries needs its own concurrency limit (or capacity reservations). DML queries time out after 30 minutes by default.

Athena for Apache Spark runs PySpark in notebooks at $0.35 per DPU-hour, both in the Athena console and as the default Spark runtime of SageMaker Unified Studio notebooks.

Lambda

Skill 3.1.8Use AWS Lambda to automate data processing.

Lambda is the default glue for small, event-driven steps: react to a file, validate it, start the heavy job, tidy up. Limits and concurrency are on Task 1.2 and Task 1.4; stream processing is on Task 1.1.

New file in S3 → start the Glue job 
import urllib.parse
import boto3

glue = boto3.client("glue")

def handler(event, context):
    runs = []
    for rec in event["Records"]:
        s3 = rec["s3"]
        bucket = s3["bucket"]["name"]
        key = urllib.parse.unquote_plus(
            s3["object"]["key"])
        r = glue.start_job_run(
            JobName="orders-etl",
            Arguments={
                "--src_bucket": bucket,
                "--src_key": key},
            JobRunQueuingEnabled=True)
        runs.append(r["JobRunId"])
    return {"runs": runs}

S3 URL-encodes object keys in events, hence unquote_plus. Letting an error propagate makes Lambda's asynchronous retries and failure destination handle it.

Never write output back to the bucket and prefix that triggers the function. Lambda's recursive loop detection now covers S3 (as well as SQS, SNS and EventBridge custom buses) and stops a loop after about 16 invocations — but it does not cover DynamoDB, and a loop costs money until it is caught. Write to another bucket or prefix and filter the trigger by prefix or suffix.

Asynchronous invocations

S3 and EventBridge invoke Lambda asynchronously. Lambda queues the event, retries failures up to 2 times (0–2) and keeps an event for up to 6 hours. Then:

  • Destinations (preferred) send the event and the result or error to SQS, SNS, Lambda, EventBridge or, for failures, S3.
  • Dead-letter queues (standard SQS or SNS) receive only the event body.
No retries, failures to a queue 
aws lambda put-function-event-invoke-config \
  --function-name start-orders-etl \
  --maximum-retry-attempts 0 \
  --destination-config file://dest.json
dest.json 
{
  "OnFailure": {
    "Destination":
      "arn:aws:sqs:us-east-1:111111111111:etl-failed"
  }
}

Lambda with SQS

For a buffered queue of work items, Lambda polls SQS in batches (up to 10,000 with a batching window; 10 for FIFO). Set the queue's visibility timeout to at least six times the function timeout, turn on ReportBatchItemFailures so one bad message does not redeliver the whole batch, and give the queue a dead-letter queue with maxReceiveCount of at least 5.

  • Packaging: up to 5 layers and 250 MB unzipped, or a container image up to 10 GB for heavy libraries such as pandas.
  • Powertools for AWS Lambda provides a batch processor for partial failures and an idempotency utility backed by DynamoDB.
  • Lambda durable functions (December 2025) checkpoint progress so one function can run multi-step work for up to a year — an alternative to Step Functions for code-first workflows.

Event patterns

Values in a list are OR'd; separate fields are AND'd. Content filters include prefix, suffix, anything-but, numeric, exists, wildcard, equals-ignore-case, cidr and $or.

Any orders- job that fails or times out 
{
  "source": ["aws.glue"],
  "detail-type": [
    "Glue Job State Change"
  ],
  "detail": {
    "jobName": [{"prefix": "orders-"}],
    "state": ["FAILED", "TIMEOUT"]
  }
}

wildcard and the prefix, suffix and wildcard forms of anything-but work in event bus rules but not in EventBridge Pipes filters.

Shaping and delivering

An input transformer picks fields from the event (InputPathsMap, up to 100 variables) and builds the target's input (InputTemplate) — for example a short alert message instead of the whole event.

Input transformer for a chat alert 
{
  "InputPathsMap": {
    "job": "$.detail.jobName",
    "st": "$.detail.state"
  },
  "InputTemplate":
    "\"Glue job <job> is <st>\""
}
  • Retries: targets are retried for up to 24 hours and 185 attempts by default, with backoff. Lower these with the target's retry policy when old events are useless.
  • Dead-letter queue: a standard SQS queue in the same Region per target. Permission errors and deleted targets go there immediately, without retries, with the error in message attributes.
  • Cross-account: the receiving bus's resource policy allows the sender, and new cross-account bus targets need an IAM role. Events cannot be forwarded a third hop.
  • Schema registry: EventBridge can discover event schemas and generate code bindings.

EventBridge Scheduler in practice

  • Expressions: at() for one time, rate(), and six-field cron(), in any IANA time zone. In a daylight-saving spring-forward gap the invocation is skipped.
  • Flexible time windows (up to 1,440 minutes) let Scheduler spread many schedules instead of firing them all at once.
  • Universal targets call almost any AWS API directly (arn:aws:scheduler:::aws-sdk:glue:startJobRun), so no Lambda is needed to start a job. Read-only actions such as get and list are not allowed.
  • The default quota is 10 million schedules per Region, and completed one-time schedules still count — set ActionAfterCompletion to DELETE.
Nightly Glue run, any time in a 30-minute window 
aws scheduler create-schedule \
  --name nightly-orders \
  --schedule-expression \
    "cron(0 2 * * ? *)" \
  --schedule-expression-timezone \
    "America/New_York" \
  --flexible-time-window \
    '{"Mode": "FLEXIBLE",
      "MaximumWindowInMinutes": 30}' \
  --target file://target.json

Key takeaways

  • Orchestration: Step Functions optimized integrations with .sync wait for Glue, Athena, EMR, EMR Serverless and DataBrew jobs; MWAA uses the Amazon provider operators (GlueJobOperator, AthenaOperator, RedshiftDataOperator).
  • MWAA troubleshooting: two private subnets in two AZs, NAT for public routing or VPC endpoints for private routing; a versioned bucket with Block Public Access; pip errors in the requirements_install_ip stream; port 5432 for the scheduler heartbeat; more min workers for queued tasks.
  • Step Functions troubleshooting: event history for Standard (Express needs CloudWatch Logs); States.Permissions means the role; Standard executions fail at 25,000 history events; status-change events come only from Standard workflows.
  • boto3: clients are thread-safe, resources and sessions are not and resources are feature-frozen. Default retry mode is still legacy; max_attempts in Config excludes the first call. No waiters for Glue, Athena, EMR Serverless or the Redshift Data API — poll with backoff. AWS SDK for pandas wraps Athena and Parquet writes for DataFrames.
  • EMR: ActionOnFailure CONTINUE, CANCEL_AND_WAIT or TERMINATE_CLUSTER; up to 256 concurrent steps; auto-termination after 60 idle minutes by default; bootstrap actions run before applications install.
  • Redshift: PL/pgSQL stored procedures with CALL (invoker rights by default); Query Editor v2 scheduled queries keep history only 24 hours. Glue: 5.1 is the default version, Flex only on G.1X and G.2X, default timeout 480 minutes on 5.0+, job run queuing waits instead of failing.
  • Data APIs: stages, stage variables and canaries for safe change; usage plans for partners; account throttle 10,000 RPS with 5,000 burst; cache TTL 300 s by default; compare Latency with IntegrationLatency.
  • DataBrew: projects work on a sample (500 rows by default, up to 5,000); recipes must be published before jobs use them; $1 per 30-minute session and $0.48 per node-hour; still active. Unified Studio offers visual ETL on Glue and notebooks defaulting to Athena for Apache Spark.
  • Athena: Hive DDL, Trino DML; positional parameters with ExecutionParameters or prepared statements; UNNEST drops rows with empty arrays; EXPLAIN ANALYZE runs and bills; UNLOAD needs an empty destination; active DML quota is per Region (20 in many).
  • Lambda: async invocations retry 0–2 times within up to 6 hours, then go to a destination (preferred) or DLQ; do not write to the triggering prefix — loop detection covers S3 but not DynamoDB. SQS visibility timeout at least six times the function timeout, with ReportBatchItemFailures.
  • EventBridge: list values OR, fields AND; input transformers reshape events; targets retry for 24 hours and 185 attempts, and permission errors go straight to the DLQ. Scheduler: flexible windows, universal targets that call APIs directly, 10 million schedules per Region, and ActionAfterCompletion=DELETE for one-time schedules.
