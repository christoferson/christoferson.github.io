Visualizing data

Skill 3.2.1Visualize data by using AWS services and tools (for example, DataBrew, Amazon QuickSight).

Two very different kinds of visualization appear in this skill. Quick Sight builds dashboards for business users. DataBrew profiles show data engineers what a dataset looks like — distributions, gaps and outliers — before they transform it.

Amazon Quick Sight

A dataset either imports into SPICE, Quick Sight's in-memory engine, or uses direct query against the source on every interaction.

SPICE full refreshes can be daily, weekly or monthly, and hourly only on Enterprise. Incremental refresh (Enterprise, SQL sources such as Redshift and Athena) replaces only a look-back window based on a date column, and can run every 15 or 30 minutes — but a 15-minute, 30-minute or hourly schedule cannot be combined with other schedules on the same dataset.

Calculations that analysts need

Table calculations work over the rows of a visual: runningSum, percentOfTotal, and windowAvg, which AWS describes as the way "to calculate a moving average". Level-aware calculations compute at a different grain from the visual, such as each store's share of its region (sum({amount}, [{region}])), or before filters are applied (sumOver(..., PRE_FILTER)).

Calculated field: 7-day moving average 
windowAvg(
  sum({amount}),
  [{sale_date} ASC],
  6,
  0
)

The arguments are the measure, the sort, the number of rows before the current row (6) and the number after (0), so the window is seven rows.

windowAvg counts data points, not days. If some days have no sales, a "6 rows back" window reaches further than a week. Aggregate at day granularity and fill gaps in the dataset first.

Enterprise-only features

  • Row-level security: a permissions dataset maps users or groups to the values they may see. A user with no rule sees no rows. Column-level security hides restricted columns.
  • VPC connections reach private Redshift, RDS, Aurora and OpenSearch. Athena does not use a VPC connection: you choose the workgroup and grant Quick Sight access to the results bucket and any KMS key.
  • ML insights: anomaly detection and forecasting, both using the Random Cut Forest algorithm. Anomaly detection needs at least 15 data points, a date and a category field, and does not work on datasets with row-level security.
  • Generative BI through Amazon Q: build visuals from a description, executive summaries, and questions over Topics, now moving into Amazon Quick chat.

Quick Sight is priced per user (for example Author $24 and Reader $3 a month) or with Reader capacity pricing per 30-minute session. Amazon Quick adds plan-based pricing with a monthly infrastructure fee.

DataBrew profiles

A DataBrew project has three views: Grid (the sample rows), Schema (column details) and Profile, which appears after a profile job runs over the dataset. The profile shows:

  • A data profile overview: row and column counts, duplicate rows, and a correlation matrix (Pearson, the first 10 numeric columns by default).
  • Column statistics: distinct, unique and missing values (DataBrew counts null and empty strings as missing), min, max, mean, median, percentiles, skewness, value distributions and the most common values.
  • Outliers, detected by Z-score with a default threshold of 3.
  • Data quality results from rulesets attached to the profile job, on the dataset's Data Quality tab and as DataBrew Ruleset Validation Result events.

Match the audience. A dashboard of sales trends for managers → Quick Sight. "What does this new supplier feed actually contain?" → a DataBrew profile job. Quick Sight for people consuming results; DataBrew for people preparing data.

Verifying and cleaning

Skill 3.2.2Verify and clean data (for example, Lambda, Athena, QuickSight, Jupyter Notebooks, Amazon SageMaker Data Wrangler).

Analysis is only as good as its input. Verification asks "is this data what we expect?" (counts, nulls, duplicates, ranges, schema); cleaning fixes what it can. Each tool in the skill fits a different point in the pipeline. Formal data quality rules are on Task 3.4.

Amazon Quick SightSpotting oddities visually and cleaning in dataset prep (filters, type changes, excluded fields)
Jupyter notebooksAd hoc exploration in Python or Spark
Data Wrangler (in SageMaker Canvas)Preparing data for machine learning, with an automatic data quality report

Checking files on arrival with Lambda

Tag each new CSV valid or invalid 
import csv
import io
import urllib.parse
import boto3

s3 = boto3.client("s3")
REQUIRED = {"order_id", "store_id",
            "amount"}

def handler(event, context):
    rec = event["Records"][0]["s3"]
    bucket = rec["bucket"]["name"]
    key = urllib.parse.unquote_plus(
        rec["object"]["key"])
    obj = s3.get_object(
        Bucket=bucket, Key=key)
    # the header is in the first line
    head = obj["Body"].read(65536)
    first = head.decode().splitlines()[0]
    cols = set(next(csv.reader(
        io.StringIO(first))))
    ok = REQUIRED <= cols
    s3.put_object_tagging(
        Bucket=bucket, Key=key,
        Tagging={"TagSet": [{
            "Key": "validation",
            "Value": "valid" if ok
                     else "invalid"}]})

Downstream jobs can then read only objects tagged valid, while a lifecycle rule or alert handles the rest. Lambda suits checks that fit in 15 minutes and 10 GB of memory; full-table checks belong in Athena or Glue.

Checking a table with Athena

Nulls, duplicates and impossible values 
SELECT
  count(*) AS row_count,
  count_if(order_id IS NULL)
    AS null_ids,
  count(*) - count(DISTINCT order_id)
    AS duplicate_ids,
  count_if(amount < 0) AS negative,
  approx_distinct(store_id) AS stores,
  max(order_ts) AS latest_order
FROM retail.orders
WHERE dt = '2026-11-07';

approx_distinct trades a 2.3% standard error for far less memory than COUNT(DISTINCT). To clean, write the corrected data to a new table with CTAS, or to an Iceberg table with MERGE or DELETE.

Notebooks

Several services offer Jupyter notebooks for exploratory checks: SageMaker AI notebook instances and Studio JupyterLab; SageMaker Unified Studio notebooks; EMR Studio on EMR clusters; Glue interactive sessions on serverless Spark (idle timeout 2,880 minutes by default); and Athena notebooks with Spark (below).

SageMaker Data Wrangler

"Amazon SageMaker Data Wrangler has been integrated into Amazon SageMaker Canvas"; in the current Studio experience you reach it through Canvas. It imports from S3, Athena, Redshift and 50+ other sources, offers over 300 built-in transforms plus custom PySpark, pandas and SQL, and exports flows to SageMaker Pipelines, Feature Store, S3 or Python code.

Its Data Quality and Insights report is the verification feature to know. It reports missing and invalid values, outliers, duplicates and anomalous rows, checks the target column for class imbalance and target leakage, and trains a quick XGBoost model to estimate how predictive the data is. It runs on the first 50,000 rows or on the full dataset as a SageMaker Processing job. Canvas also offers natural-language data preparation through Amazon Bedrock.

SQL queries and views

Skill 3.2.3Use SQL in Amazon Redshift and Athena to query data or to create views.

A view is a saved query that behaves like a table. It stores no data (a materialized view does), so it always shows current results, and it lets you give analysts a clean, stable interface over messy tables — renamed columns, joins done, sensitive columns left out.

Views in Redshift

Revenue by region and day 
CREATE OR REPLACE VIEW sales_by_region AS
SELECT region, sale_date,
       SUM(amount) AS revenue
FROM daily_sales
GROUP BY region, sale_date;
  • A normal view is checked against its tables when created, and those tables cannot be dropped while it exists. A late-binding view (WITH NO SCHEMA BINDING) is checked only at query time and is the only kind that can reference Spectrum external tables (Task 2.4).
  • You cannot insert, update or delete through a view. For precomputed results, use a materialized view (Task 2.1).
  • QUALIFY filters on a window function's result without a subquery, for example the top store in each region each day.
Best store per region per day (Redshift) 
SELECT region, store_id, sale_date,
       amount
FROM daily_sales ds
QUALIFY RANK() OVER (
  PARTITION BY region, sale_date
  ORDER BY amount DESC) = 1;

Views in Athena

Rank stores within region and day 
CREATE OR REPLACE VIEW
  retail.store_rank AS
SELECT region, store_id, sale_date,
  amount,
  rank() OVER (
    PARTITION BY region, sale_date
    ORDER BY amount DESC) AS rnk
FROM retail.daily_sales;

A plain Athena view works only in Athena: Redshift Spectrum cannot query it, and Athena for Apache Spark cannot read it either. For a view several engines can use, create a Data Catalog view (CREATE PROTECTED MULTI DIALECT VIEW ... SECURITY DEFINER) over Lake Formation-managed tables (Task 3.1).

Window functions differ from GROUP BY in one essential way: in AWS's words, "unlike group functions that aggregate result rows, window functions retain all rows". Each row keeps its detail and gains a computed column. The aggregation patterns built on both are in skill 3.2.6.

Spark notebooks

Skill 3.2.4Use Athena notebooks that use Apache Spark to explore data.

Athena for Apache Spark runs PySpark interactively without clusters: start a notebook and Spark is ready in seconds, billed per DPU-hour ($0.35). It suits exploration that is awkward in SQL — Python logic, plots, machine-learning-style feature checks.

Two release versions

VersionWhere you use it
PySpark engine version 3 (Spark 3.2)Notebooks in the Athena console, in a Spark-enabled workgroup
Apache Spark 3.5SageMaker Unified Studio notebooks and Spark Connect clients — not Athena console notebooks or the notebook APIs

  3. Opening it starts a session; each cell you run is a calculation. A notebook has one active session at a time.

  • Formats: Parquet, ORC, JSON, CSV and text; Iceberg, Hudi and Delta Lake tables, but only one of those table formats per notebook.
  • Version 3 limits: no Lake Formation, no partition-projection tables, no Athena SQL views, no pip install (add libraries as files), no MLlib or RDDs.
  • Encryption: a workgroup KMS key encrypts notebooks, and a Spark encryption option protects traffic between nodes and local disk.

Provisioned or serverless

Skill 3.2.5Describe tradeoffs between provisioned services and serverless services.

AWS's analytics decision guide puts it this way: self-managed options "grant users greater control over the infrastructure and configurations, but they require more operational effort", while serverless options "abstract away much of the operational burden, providing automatic scalability, high availability". The cost side follows from utilization: you pay for provisioned capacity whether or not you use it, and for serverless capacity only when you do — at a higher unit price.

Glue is serverless only. More detail on each capacity model is on Task 1.2 and Task 2.1.

Two old rules no longer hold. "Serverless can't be reserved" — Redshift Serverless now has reservations. "Serverless always has a minimum charge" — Aurora Serverless and OpenSearch Serverless NextGen collections can scale to zero. The trade-off is still real, but read the current option before choosing.

Scenario cues: "unpredictable", "intermittent", "a few hours a week", "small team, no ops" → serverless. "Steady 24/7", "predictable", "needs Spot / HDFS / a specific instance type", "lowest cost at constant high utilization" → provisioned, ideally with reservations.

Aggregation patterns

Skill 3.2.6Define data aggregation, rolling average, grouping, and pivoting.

TermMeaning
AggregationCombining many rows into one value: SUM, COUNT, AVG, MIN, MAX
GroupingAggregating separately for each value of one or more columns (GROUP BY region), with optional subtotals (ROLLUP, CUBE, GROUPING SETS)
Rolling (moving) averageThe average over a window that slides with each row, such as the last 7 days; it smooths noise in a trend
PivotingTurning row values into columns (one column per category); unpivoting turns columns back into rows

Rolling average

The window is the current row plus the six before it. On a table with exactly one row per day this is a 7-day average; if days can be missing, fill them first or the window stretches further back.

7-day rolling revenue (Redshift and Athena) 
SELECT sale_date, revenue,
  AVG(revenue) OVER (
    ORDER BY sale_date
    ROWS BETWEEN 6 PRECEDING
      AND CURRENT ROW) AS avg_7d
FROM (
  SELECT sale_date,
         SUM(amount) AS revenue
  FROM daily_sales
  GROUP BY sale_date
) AS t;

This statement runs in both engines because the frame is written out. In Redshift an ORDER BY inside an aggregate window function requires an explicit ROWS frame; leave it out and the query fails. In Athena leaving it out silently gives a running total-style average from the first row, not a 7-day one.

Grouping with subtotals

ROLLUP(region, category) produces the totals for each region and category, a subtotal per region, and a grand total — the same as GROUPING SETS((region, category), (region), ()). CUBE adds every combination, including per-category totals. GROUPING() returns 1 on the subtotal rows, telling a "total" NULL from a real NULL.

Revenue with region subtotals and a grand total 
SELECT region, category,
  GROUPING(region, category) AS lvl,
  SUM(amount) AS revenue
FROM daily_sales
GROUP BY ROLLUP (region, category)
ORDER BY region, category;

Redshift allows up to 64 grouping sets per query, where CUBE of two columns counts as four.

Pivoting

Redshift has a PIVOT operator in the FROM clause. It supports only COUNT, SUM, MIN, MAX and AVG, the IN list must be constants, and it cannot be applied to a join.

One column per category (Redshift) 
SELECT *
FROM (SELECT region, category, amount
      FROM daily_sales)
PIVOT (
  SUM(amount) FOR category
  IN ('shoes', 'apparel', 'home')
);

Athena does not document a PIVOT operator, so pivot with conditional aggregation — which also works in Redshift and any SQL engine.

The same pivot with conditional aggregation 
SELECT region,
  SUM(CASE WHEN category = 'shoes'
      THEN amount END) AS shoes,
  SUM(CASE WHEN category = 'apparel'
      THEN amount END) AS apparel,
  SUM(CASE WHEN category = 'home'
      THEN amount END) AS home
FROM daily_sales
GROUP BY region;

Redshift's UNPIVOT reverses a pivot and skips NULLs unless you add INCLUDE NULLS. In Quick Sight, a pivot table visual does the same interactively, and the new data prep experience has Pivot and Unpivot steps (SPICE only).

Key takeaways

  • QuickSight is now Amazon Quick Sight (within Amazon Quick, October 2025); APIs and IAM actions still say quicksight. SPICE holds up to 2 billion rows or 2 TB per dataset on Enterprise; direct query hits the source on every view.
  • Hourly SPICE refresh is Enterprise only; incremental refresh (Enterprise, SQL sources) can run every 15 or 30 minutes. Row- and column-level security, VPC connections and ML insights are Enterprise; a user with no RLS rule sees no rows; Athena needs no VPC connection.
  • windowAvg(measure, sort, 6, 0) is a seven-row moving average in Quick Sight — rows, not days. Level-aware calculations compute at a different grain or before filters.
  • DataBrew profile jobs show missing values (null and empty), distributions, Z-score outliers and a Pearson correlation matrix, plus data quality rule results.
  • Verification: Lambda checks files on arrival, Athena checks whole tables (count_if, duplicates, approx_distinct), notebooks explore. Data Wrangler now lives in SageMaker Canvas; its Data Quality and Insights report flags missing values, duplicates, outliers, imbalance and target leakage.
  • Views store no data. Redshift late-binding views are needed for Spectrum tables; QUALIFY filters on window results. Plain Athena views work only in Athena — use Data Catalog multi-dialect views for other engines.
  • Athena Spark notebooks: a Spark-enabled workgroup, one session per notebook, idle timeout 20 minutes, 1-DPU coordinator and executors, up to 20 concurrent DPUs by default; %%sql and %matplot magics. PySpark engine v3 (console notebooks) reaches end of life on April 1, 2027; Spark 3.5 runs through Unified Studio.
  • Provisioned suits steady load and needs control; serverless suits spiky load and small teams. Redshift Serverless now has reservations, and Aurora Serverless and OpenSearch Serverless NextGen can scale to zero. MSK Serverless is IAM-only; EMR Serverless has no HDFS; Lambda stops at 15 minutes.
  • SQL patterns: Redshift requires an explicit ROWS frame for ordered aggregate windows, Athena defaults to a running frame. ROLLUP gives subtotals and a grand total, with GROUPING() marking them. Redshift has PIVOT (five aggregates, constant IN list); in Athena, pivot with CASE inside SUM.
