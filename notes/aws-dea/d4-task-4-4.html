Task 4.4: Prepare logs for audit

An auditor needs logs that are complete, cover every account, cannot have been altered, are kept as long as the rules say, and can be searched. This task covers building that evidence trail with CloudTrail and CloudWatch Logs, querying it with CloudTrail Lake and its successors, and bringing in the services that handle security logs at scale.

CloudTrail for audit

Skill 4.4.1Use AWS CloudTrail to track API calls.

For audit, one trail per account is not enough: someone could create an account without one, or switch it off. The answer is an organization trail, delivered to a bucket the data accounts cannot touch.

Organization trails

  • Created by the management account or a CloudTrail delegated administrator (up to three per organization), after enabling trusted access for CloudTrail in AWS Organizations.
  • It logs every account in the organization, including accounts added later. Member accounts can see the trail but cannot change, stop or delete it.
  • Log files land under AWSLogs/<org-id>/<account-id>/CloudTrail/<region>/<yyyy>/<mm>/<dd>/.
Organization trail, all Regions, validated, encrypted 
aws cloudtrail create-trail \
  --name org-trail \
  --s3-bucket-name retail-org-trail \
  --is-organization-trail \
  --is-multi-region-trail \
  --enable-log-file-validation \
  --kms-key-id alias/cloudtrail-logs

# CLI trails do not log until started
aws cloudtrail start-logging \
  --name org-trail

From the CLI, create-trail with no options makes a single-Region trail with no log file validation, and a CLI-created trail records nothing until start-logging. The console turns all three on for you.

The trail bucket

The bucket policy lets the CloudTrail service write, limited to this trail through aws:SourceArn. For an organization trail, one statement covers the management account's own prefix and another the organization's prefix.

Bucket policy (organization statement shown) 
{
  "Sid": "AWSCloudTrailOrganizationWrite",
  "Effect": "Allow",
  "Principal": {
    "Service": "cloudtrail.amazonaws.com"
  },
  "Action": "s3:PutObject",
  "Resource":
    "arn:aws:s3:::retail-org-trail/AWSLogs/o-retail01/*",
  "Condition": {
    "StringEquals": {
      "s3:x-amz-acl":
        "bucket-owner-full-control",
      "aws:SourceArn":
        "arn:aws:cloudtrail:us-east-1:111111111111:trail/org-trail"
    }
  }
}

The full policy also has an s3:GetBucketAcl statement and a write statement for AWSLogs/111111111111/*. If the bucket becomes unreachable, CloudTrail retries delivery for 30 days, and those attempts are billed.

Encrypting the logs

Without further settings, log files are encrypted with SSE-S3. SSE-KMS with a customer managed key adds control over who can read them: readers need S3 read access and kms:Decrypt. The key must be in the bucket's Region, and its policy must let CloudTrail generate data keys for this trail.

Key policy statement for CloudTrail 
{
  "Sid": "AllowCloudTrailEncryptLogs",
  "Effect": "Allow",
  "Principal": {
    "Service": "cloudtrail.amazonaws.com"
  },
  "Action": "kms:GenerateDataKey*",
  "Resource": "*",
  "Condition": {
    "StringEquals": {
      "aws:SourceArn":
        "arn:aws:cloudtrail:us-east-1:111111111111:trail/org-trail"
    },
    "StringLike": {
      "kms:EncryptionContext:aws:cloudtrail:arn":
        "arn:aws:cloudtrail:*:111111111111:trail/*"
    }
  }
}

If the KMS key is disabled or its policy is wrong, CloudTrail stops delivering logs. An audit trail that silently stopped is worse than none, so alarm on trail delivery errors and protect the key as carefully as the bucket.

Proving logs were not altered

Log file integrity validation lets you prove, later, that log files are exactly as CloudTrail delivered them:

  • CloudTrail hashes each log file with SHA-256, and every hour delivers a digest file listing the last hour's files and their hashes, signed with SHA-256 with RSA.
  • Each digest includes the previous digest's signature, so the digests form a chain; a missing digest breaks it.
  • Digests go to the same bucket under CloudTrail-Digest/, so you can give them stricter policies.
Check a member account's logs for one week 
aws cloudtrail validate-logs \
  --trail-arn "$ORG_TRAIL_ARN" \
  --start-time 2026-11-01T00:00:00Z \
  --end-time 2026-11-07T00:00:00Z \
  --account-id 222222222222 \
  --region us-east-1 \
  --verbose

Results flag each file as valid, modified (hash value doesn't match), deleted (not found) or moved. For an organization trail --account-id is required, and validation runs per Region. It also proves that no logs were delivered for a period when that is the case.

Validation detects tampering; it does not prevent it, and turning it on validates nothing until someone runs validate-logs. The CLI also cannot validate files that were moved or downloaded.

Preventing tampering

  • A separate Log Archive account owns the bucket, so administrators of the data accounts cannot delete logs. AWS Control Tower sets this up.
  • S3 Object Lock in compliance mode: nobody, including the root user, can delete or shorten retention (Task 2.3).
  • MFA Delete on the bucket — but it cannot be combined with lifecycle rules.
  • SCPs deny cloudtrail:StopLogging, DeleteTrail, UpdateTrail and PutEventSelectors to everyone except an administration role.
  • Lifecycle rules move older logs to Glacier classes; trails otherwise keep logs indefinitely.
SCP: only the admin role may change trails 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "ProtectCloudTrail",
    "Effect": "Deny",
    "Action": [
      "cloudtrail:DeleteTrail",
      "cloudtrail:PutEventSelectors",
      "cloudtrail:StopLogging",
      "cloudtrail:UpdateTrail"
    ],
    "Resource": "*",
    "Condition": {
      "ArnNotLike": {
        "aws:PrincipalARN":
          "arn:aws:iam::*:role/OrgTrailAdmin"
      }
    }
  }]
}

Alerting on sensitive API calls

Sending the trail to CloudWatch Logs (the log group must be in the trail's account) allows metric filters and alarms on specific calls — the pattern behind the CIS benchmark controls in Security Hub. CloudTrail does not send events larger than 256 KB to CloudWatch Logs or EventBridge.

Metric filter: S3 bucket policy or ACL changes 
{ ($.eventSource = s3.amazonaws.com) &&
  (($.eventName = PutBucketPolicy) ||
   ($.eventName = DeleteBucketPolicy) ||
   ($.eventName = PutBucketAcl)) }

For near-real-time reaction instead of a metric, an EventBridge rule on AWS API Call via CloudTrail can invoke a function the moment a bucket policy changes.

Application logs

Skill 4.4.2Use Amazon CloudWatch Logs to store application logs.

Application logs become audit evidence when they are kept long enough, protected from deletion and alteration, readable only by the right people, and gathered from every account into one place.

Getting logs in, in a useful shape

  • Lambda: AWS recommends the JSON log format (--logging-config LogFormat=JSON); the default is still plain text.
  • EC2 and on-premises servers: the CloudWatch agent.
  • Containers: the awslogs log driver, or FireLens (Fluent Bit or Fluentd) to route logs to CloudWatch or other destinations with task metadata added.
  • Glue, EMR, Redshift and RDS logging are covered on Task 3.3.

Write structured JSON with consistent fields (user, request ID, dataset, action, outcome). Every later step — metric filters, Logs Insights, Athena — depends on being able to filter on fields rather than parse free text.

Retention and protection

  • Log group retention runs from 1 day to 3,653 days (about 10 years); never-expire is the default. Longer retention means exporting to S3.
  • Account-level retention policies set retention for all log groups or a name prefix, and override a log group's own setting — even a longer one — so a careless policy can delete evidence.
  • Encrypt with a customer managed KMS key per log group (symmetric keys only). Disabling or deleting the key makes the logs unreadable.
  • Log group deletion protection, and SCPs denying logs:DeleteLogGroup and logs:PutRetentionPolicy, stop logs being removed.
  • Restrict reading with IAM; viewing values masked by a data protection policy additionally needs logs:Unmask.

Or: one centralization rule for the organization 
aws observabilityadmin \
  create-centralization-rule-for-organization \
  --rule-name central-logs \
  --rule file://central-rule.json

The rule names the source Regions and scope (organization, OUs or accounts), the destination account and Region, an optional backup Region, KMS handling, and a naming pattern for destination log groups such as /central/${source.accountId}${source.logGroup}. Copied events gain @aws.account and @aws.region fields so you can still tell where they came from.

CloudTrail Lake

Skill 4.4.3Use AWS CloudTrail Lake for centralized logging queries.

"AWS CloudTrail Lake will no longer be open to new customers starting on May 31, 2026. For capabilities similar to CloudTrail Lake, explore CloudWatch." Existing customers can keep using it, with critical fixes and security updates only; no end-of-support date has been announced. The exam guide still names it, so know what it does — and know that a new design today would use CloudWatch or a trail plus Athena.

What it is

  • Events are stored in event data stores: immutable collections, chosen with advanced event selectors, of CloudTrail events, Insights events, AWS Config configuration items, Audit Manager evidence, or events from outside AWS sent through channels.
  • Organization event data stores collect from every account; they are created by the management account or a delegated administrator.
  • Queries are SQL — "all valid Trino SELECT statements and functions" — where the table name is the event data store ID. Results are kept 7 days and can be delivered to S3.
  • Retention is up to 3,653 days with one-year extendable pricing, or up to 2,557 days with seven-year pricing.
  • Federation registers an event data store as a Glue table (database aws:cloudtrail) governed by Lake Formation, so Athena can query it at Athena prices.
  • Managed and custom dashboards, and a natural-language query generator in some Regions.
Who deleted the most objects in October? 
SELECT userIdentity.arn AS caller,
       COUNT(*) AS deletes
FROM <event-data-store-id>
WHERE eventSource = 's3.amazonaws.com'
  AND eventName = 'DeleteObject'
  AND eventTime >=
      timestamp '2026-10-01 00:00:00'
  AND eventTime <
      timestamp '2026-11-01 00:00:00'
GROUP BY 1
ORDER BY 2 DESC
LIMIT 10
Run it from the CLI 
aws cloudtrail start-query \
  --query-statement file://deletes.sql \
  --delivery-s3-uri \
    s3://retail-audit-results/lake/

aws cloudtrail get-query-results \
  --query-id "$QUERY_ID"

Pricing is per GB ingested (for example $0.75 per GB for CloudTrail events with one-year extendable retention) and $0.005 per GB scanned. DeleteObject is a data event, so the event data store must select S3 data events for this query to return anything.

After CloudTrail Lake

  • Migrate to CloudWatch: AWS's recommended path ingests CloudTrail events into CloudWatch Logs (now possible without a trail, through CloudWatch telemetry rules), where they get CloudTrail-specific field indexes and Logs Insights, OpenSearch PPL and SQL queries. History moves with an import task (aws logs create-import-task); data from before 2023 is not migrated.
  • Trail to S3 plus Athena remains the low-cost, long-history option (next section).
  • Existing account-level event data stores do not pick up new accounts added to the organization; organization event data stores do.

Analyzing audit logs

Skill 4.4.4Analyze logs by using AWS services (for example, Athena, CloudWatch Logs Insights, Amazon OpenSearch Service).

Query syntax and limits are on Task 3.3. For audit, the deciding questions are how far back the evidence goes and what each query costs.

Logs Insights over CloudTrail: who deleted buckets? 
filter eventName = "DeleteBucket"
| fields @timestamp, userIdentity.arn,
    requestParameters.bucketName,
    sourceIPAddress

Athena over VPC Flow Logs in Parquet: rejected traffic 
SELECT srcaddr, dstport, COUNT(*) AS n
FROM vpc_flow_logs_parquet
WHERE action = 'REJECT'
  AND year = '2026' AND month = '11'
  AND day = '06'
GROUP BY srcaddr, dstport
ORDER BY n DESC
LIMIT 20
  • Athena tables for CloudTrail (with partition projection) and VPC Flow Logs follow AWS-documented DDL; Hive-compatible flow log prefixes let MSCK REPAIR TABLE load the partitions.
  • Security Lake tables are queried in Athena by a query-access subscriber through Lake Formation (next section).
  • OpenSearch Security Analytics runs detectors with prepackaged Sigma rules (mapped to MITRE ATT&CK) against log types such as CloudTrail, raising findings and alerts. OpenSearch can also query Security Lake and CloudWatch Logs directly.

An auditor asking about "the last two years" points to S3 plus Athena (or Security Lake): Logs Insights cannot see data past its retention, and keeping years of logs in CloudWatch costs more than in S3. An incident responder asking about "the last hour" points to Logs Insights or OpenSearch.

Integrating services

Skill 4.4.5Integrate various AWS services to perform logging (for example, Amazon EMR in cases of large volumes of log data).

Amazon Security Lake

Security Lake builds a security data lake in your own account's S3, collecting logs and normalizing them to the open OCSF schema as Parquet (current sources use Apache Iceberg tables).

  • Native sources: CloudTrail management events and S3 and Lambda data events, VPC Flow Logs, Route 53 Resolver query logs, Security Hub findings, EKS audit logs and AWS WAF logs, plus custom and third-party sources.
  • Security Lake pulls its own copy of each source — except CloudTrail management events, which require a multi-Region organization trail logging read and write management events.
  • Rollup Regions consolidate data from contributing Regions, which also helps meet data residency rules.
  • Subscribers get either data access (S3 objects plus notifications) or query access (Lake Formation tables for Athena and similar engines), with up to 10 sources per subscriber.
  • Pricing is per GB ingested and normalized, plus the S3, Glue and query costs underneath.
Athena over Security Lake flow logs 
SELECT *
FROM "amazon_security_lake_glue_db_us_east_1"
  ."amazon_security_lake_table_us_east_1_vpc_flow_2_0"
WHERE time_dt > TIMESTAMP '2026-11-01'
  AND src_endpoint.ip = '192.0.2.1'
ORDER BY time_dt DESC
LIMIT 25

Transporting logs with Firehose

Amazon Data Firehose is the usual pipe from log sources (subscription filters, applications, Kinesis) to storage and analytics:

  • To S3, with dynamic partitioning into prefixes by fields in the records and format conversion from JSON to Parquet or ORC using a Glue schema — ready for Athena.
  • To Apache Iceberg tables, including S3 Tables.
  • To OpenSearch, Splunk, Datadog and other partners, or any HTTP endpoint.

VPC Flow Logs straight to S3 as Parquet

Flow logs can be delivered to S3 every 5 minutes as Parquet with Hive-compatible, hourly partitions; AWS says Parquet queries run "10 to 100 times faster" than gzipped text.

Flow logs for Athena 
aws ec2 create-flow-logs \
  --resource-type VPC \
  --resource-ids vpc-00112233344556677 \
  --traffic-type ALL \
  --log-destination-type s3 \
  --log-destination \
    arn:aws:s3:::retail-flow-logs/vpc/ \
  --destination-options \
    '{"FileFormat": "parquet",
      "HiveCompatiblePartitions": true,
      "PerHourPartition": true}'

EMR for very large log volumes

When log volumes reach terabytes a day, or analysis needs custom parsing, joins with other data, sessionization or machine learning, a Spark job on EMR (or EMR Serverless for scheduled runs) can process raw logs at scale and write compact, partitioned Parquet that Athena then queries cheaply. CloudTrail files are gzipped JSON documents, each holding a Records array.

CloudTrail to partitioned Parquet (PySpark on EMR) 
import sys
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

out = sys.argv[1]
spark = SparkSession.builder \
    .appName("ct-to-parquet") \
    .getOrCreate()

raw = (spark.read
       .option("multiLine", True)
       .json("s3://retail-org-trail/"
             "AWSLogs/o-retail01/*/"
             "CloudTrail/*/2026/11/*/"))

# one row per API call
ev = raw.select(
    F.explode("Records").alias("r"))

df = ev.select(
    F.col("r.eventTime").alias("ts"),
    F.col("r.eventSource").alias("src"),
    F.col("r.eventName").alias("name"),
    F.col("r.userIdentity.arn")
     .alias("arn"),
    F.col("r.recipientAccountId")
     .alias("account"),
    F.to_date("r.eventTime").alias("dt"))

(df.write.mode("append")
   .partitionBy("account", "dt")
   .parquet(out))
Run it nightly on EMR Serverless 
aws emr-serverless start-job-run \
  --application-id "$APP_ID" \
  --execution-role-arn "$JOB_ROLE_ARN" \
  --job-driver file://ct-job.json

The rest of the audit picture

  • AWS Config records what each resource's configuration was at any time, complementing CloudTrail's record of who called which API (Task 4.5).
  • AWS Control Tower creates the Log Archive account, an organization trail and protected log buckets as part of a landing zone.

Key takeaways

  • Audit-grade CloudTrail: a multi-Region organization trail from the management account or a delegated admin (up to 3), which members cannot change, delivering to a bucket in a separate Log Archive account. CLI trails start single-Region, unvalidated and not logging until start-logging.
  • Log file validation: SHA-256 hashes, hourly signed digest files in CloudTrail-Digest/, chained together. It detects, not prevents; run validate-logs (with --account-id for organization trails). Prevent tampering with Object Lock compliance mode, SCPs denying StopLogging and DeleteTrail, and the separate account.
  • SSE-KMS for trail logs: key in the bucket's Region, key policy for cloudtrail.amazonaws.com, readers need kms:Decrypt. A disabled key stops delivery.
  • CloudWatch Logs as evidence: structured JSON, retention up to 3,653 days (export to S3 for longer), KMS per log group, deletion protection. Account-level retention policies override log groups' settings.
  • Centralize with log centralization rules (new data only, first copy free), cross-account subscription destinations (same Region as the log group, aws:PrincipalOrgID policy), or cross-account observability for querying in place.
  • CloudTrail Lake closed to new customers on May 31, 2026. It offers immutable event data stores, Trino SQL with the store ID as table name, up to 10 years' retention, Athena federation. New designs: CloudTrail into CloudWatch, or a trail to S3 plus Athena.
  • Analysis: Athena for long history in S3 (cheapest per TB with Parquet), Logs Insights for recent CloudWatch data only, OpenSearch for search, dashboards and Sigma-based detection.
  • Integration: Security Lake normalizes security logs to OCSF in your S3 (CloudTrail management events need an organization trail); Firehose converts and partitions logs into S3, Iceberg, OpenSearch or Splunk; VPC Flow Logs go straight to S3 as Parquet; EMR Spark turns terabytes of raw logs into partitioned Parquet for Athena.
