How to use this page

Read each list from the top: posts are newest first, and a newer post on the same design usually replaces an older one. A note saying a post predates a feature means it describes an older approach; the design still works, but the current answer may use the newer feature. The posts come mainly from the AWS Security Blog, with some from the Architecture, Management and Governance, and Containers blogs, and the dates are publication dates.

The exam guide was written before some recent changes, such as the renaming of the original Security Hub to Security Hub CSPM, so a question may still use older names. The status changes on the cheat sheet list what has changed.

awssamplesawssecurityreferencearchitectureexamples

  • URL: aws-security-reference-architecture-examples (not archived; last push 2026-11-14 per the GitHub API; linked from the SRA guide's code-repo.html page)
  • What it is: AWS-maintained sample code, not documentation. GitHub description: "Example solutions demonstrating how to implement patterns within the AWS Security Reference Architecture guide using CloudFormation (including Customizations for AWS Control Tower) and Terraform." The README says configurations are "deliberately very restrictive" and "intended to illustrate an implementation pattern rather than provide a complete solution". Licence: documentation CC-BY-SA-4.0, sample code MIT-0.
  • Account model assumed: an AWS Organizations multi-account environment, with or without a Control Tower landing zone (Organizations is always required). Solutions run from the Org Management account and delegate administration to the Security Tooling account (called Audit in Control Tower), with logs delivered to the Log Archive account; the README asks for the Security Tooling and Log Archive accounts to exist (names may differ) and for the OU structure to follow the SRA design guidance (Security, Infrastructure, Workloads OUs).
  • Compatibility notice: compatible with AWS Control Tower 4.0; in CT 4.0 the AWS Config and CloudTrail integrations are optional and must be enabled in the landing zone for SRA solutions to work.
  • Deployment options:
    • Easy Setup (recommended) for Control Tower: CloudFormation StackSets/Stacks or Customizations for AWS Control Tower (CfCT); one template whose parameters choose which solutions to deploy - easy_setup
    • Easy Setup for Organizations without Control Tower: CloudFormation StackSets/Stacks.
    • Manual setup: deploy Common Prerequisites once, optionally the CfCT setup, then individual solutions by StackSets or CfCT.
    • Quick Setup: deprecated (replaced by Easy Setup).
    • Terraform edition: terraform - common pre-requisite module, then terraform_stack.py applies config.tfvars across accounts and governed Regions. Terraform solutions listed: CloudTrail, IAM Access Analyzer, IAM Password Policy, Inspector, Macie, GuardDuty, Security Hub, Register Delegated Administrator (8).

    • common_cfct_setup - prepares Customizations for AWS Control Tower when CfCT is the deployment method.
    • commonregisterdelegatedadministrator - registers delegated administrators for services (dependency of Config, Access Analyzer and others).
