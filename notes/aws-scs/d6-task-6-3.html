Task 6.3: Evaluate the compliance of AWS resources

Knowing at any moment which resources break the rules, fixing them automatically where it's safe, telling the right people when it isn't, and producing evidence an auditor will accept: AWS Config rules, conformance packs and aggregators, Security Hub CSPM standards, AWS's own audit reports in Artifact, and architecture reviews against the Well-Architected Security pillar.

Overview

Task 6.3

Evaluate the compliance of AWS resources.

Tasks 6.1 and 6.2 prevent and deploy; this task checks what actually exists. The exam tests which tool answers which question: is this resource configured correctly (Config), how does the organization score against a standard (Security Hub CSPM), where is the evidence for the auditor (conformance packs and exports, or Audit Manager for existing customers), what does AWS itself certify (Artifact), and is the architecture sound (Well-Architected Tool). Security Hub CSPM set-up, aggregation and automation rules are in Task 1.1; Guard-based Config rules and the required-tags rule in Task 6.2.

Running example. The same company now has a PCI DSS audit coming. The security tooling account (222222222222) is the delegated administrator for Config and Security Hub CSPM; it deploys conformance packs to every account, aggregates compliance from the whole organization, fixes simple issues automatically, and pages the team for the rest. The auditors want AWS's own PCI attestation and evidence of the company's controls, and the architecture team runs a Well-Architected review before go-live.

Detecting, remediating and notifying

Skill 6.3.1Create or enable rules to detect and remediate noncompliant AWS resources and to send notifications (for example, by using AWS Config to aggregate alerts and remediate non-compliant resources, Security Hub).

AWS Config rules

Rule types, triggers and results

  • Managed rules (Owner: AWS): hundreds of predefined checks, some with parameters. Custom Lambda rules (CUSTOM_LAMBDA): your function receives the configuration item and calls PutEvaluations. Custom policy rules (CUSTOM_POLICY): Guard rules, no function needed.
  • Triggers: configuration changes (scoped by resource type, one resource or a tag), periodic (1, 3, 6, 12 or 24 hours; 24 is the default), or both.
  • Results: COMPLIANT, NON_COMPLIANT, NOT_APPLICABLE, or ERROR (for example a bad parameter).
  • Service-linked rules are created by Security Hub CSPM, Control Tower, conformance packs and organization rules; you can't edit or delete them directly, only through the service that owns them.
  • Proactive evaluation checks a resource configuration before it exists (start-resource-evaluation), but it never blocks or fixes anything, and the current documentation lists only two managed rules that support it. To block deployments, use CloudFormation hooks or Control Tower proactive controls (Task 6.2).
Flag IAM access keys older than 90 days, checked daily (AWS CLI, Config managed rule with a parameter) 
aws configservice put-config-rule --config-rule '{
  "ConfigRuleName": "access-keys-rotated",
  "Source": { "Owner": "AWS", "SourceIdentifier": "ACCESS_KEYS_ROTATED" },
  "InputParameters": "{\"maxAccessKeyAge\":\"90\"}",
  "MaximumExecutionFrequency": "TwentyFour_Hours"
}'

InputParameters is a JSON string inside the JSON (up to 1,024 characters). An account can have up to 1,000 rules per Region, counting rules in conformance packs.

Rules only see what Config records

  • A rule can't evaluate a resource type the recorder doesn't record; Security Hub CSPM reports such controls as WARNING.
  • Continuous recording costs $0.003 per configuration item, daily $0.012 (us-east-1 example prices), and daily recording can delay findings by up to 24 hours. Firewall Manager needs continuous recording.
  • Record global IAM resources (users, groups, roles, policies) in one Region only, and deploy rules that check them only there, to avoid duplicate items and evaluations.
  • Service-linked configuration recorders (November 2024) let services such as Security Hub CSPM, the new Security Hub and CloudWatch record what they need. If a paid one records a type continuously, that type is billed at the continuous rate even when your own recorder is set to daily.

Organization rules and conformance packs

Deploying rules to every account

Config has two delegated-administrator service principals: config-multiaccountsetup.amazonaws.com for organization rules and conformance packs, and config.amazonaws.com for aggregators. An organization can have up to 3 Config delegated administrators.

Make the security tooling account the Config administrator for both (AWS CLI, management account) 
aws organizations enable-aws-service-access --service-principal config-multiaccountsetup.amazonaws.com
aws organizations enable-aws-service-access --service-principal config.amazonaws.com
aws organizations register-delegated-administrator --service-principal config-multiaccountsetup.amazonaws.com --account-id 222222222222
aws organizations register-delegated-administrator --service-principal config.amazonaws.com --account-id 222222222222
  • Organization rules (put-organization-config-rule): API and CLI only, per Region, applied to accounts that join later, and member accounts can't change them.
  • A conformance pack is a YAML template of rules and remediation actions deployed as one unit, to an account and Region or the whole organization (put-organization-conformance-pack). AWS publishes more than 100 sample packs ("Operational Best Practices for" PCI DSS 4.0, NIST 800-53, HIPAA, CIS, the Well-Architected Security pillar and others). A pack's compliance score is the percentage of compliant rule and resource combinations.
  • Limits: 50 conformance packs per account and 50 organization packs, each with up to 130 rules.
  • Process checks are pack entries for requirements Config can't check (such as offsite backup media); you set their status by hand.

An organization conformance pack creates rules and remediation in member accounts through a service-linked role, even if member IAM policies deny config:PutConfigRule. Its delivery bucket, if used, must have a name starting with awsconfigconforms. Rules and packs deployed from the management account and from the delegated administrator can't see each other.

Aggregators

One view of every account and Region

An aggregator collects configuration and compliance data from chosen accounts, all Regions or the whole organization, at no extra charge. It is read-only: you can't deploy rules or remediate through it. An account-based aggregator needs put-aggregation-authorization in each source account and Region; an organization aggregator needs no authorization, just a role with the AWSConfigRoleForOrganizations policy.

Create an organization aggregator and count non-compliant resources across it (AWS CLI, security tooling account) 
aws configservice put-configuration-aggregator --configuration-aggregator-name org-compliance \
  --organization-aggregation-source '{"RoleArn": "arn:aws:iam::222222222222:role/config-org-aggregator", "AllAwsRegions": true}'

aws configservice select-aggregate-resource-config --configuration-aggregator-name org-compliance \
  --expression "SELECT configuration.complianceType, COUNT(*) WHERE resourceType = 'AWS::Config::ResourceCompliance' GROUP BY configuration.complianceType"

Advanced queries use a subset of SQL over current configuration (no FROM, JOIN or DISTINCT, no deleted resources). Results export to CSV or JSON, which is also a simple way to hand an auditor an inventory.

Remediation

Systems Manager Automation from Config rules

A Config rule never fixes anything by itself. Attach a remediation configuration that runs a Systems Manager Automation runbook (AWS-owned such as AWS-EnableS3BucketEncryption or AWSConfigRemediation-*, or your own), manually from the console or automatically on NON_COMPLIANT.

Turn default encryption back on for any bucket the rule flags (AWS CLI, remediation configuration) 
aws configservice put-remediation-configurations --remediation-configurations '[{
  "ConfigRuleName": "s3-bucket-sse-enabled",
  "TargetType": "SSM_DOCUMENT",
  "TargetId": "AWS-EnableS3BucketEncryption",
  "Parameters": {
    "AutomationAssumeRole": { "StaticValue": { "Values": ["arn:aws:iam::111111111111:role/config-remediation"] } },
    "BucketName": { "ResourceValue": { "Value": "RESOURCE_ID" } },
    "SSEAlgorithm": { "StaticValue": { "Values": ["AES256"] } }
  },
  "Automatic": true,
  "MaximumAutomaticAttempts": 5,
  "RetryAttemptSeconds": 60
}]'
  • Automatic remediation requires AutomationAssumeRole; RESOURCE_ID passes the flagged resource. Check each runbook's parameters before using it.
  • If remediation fails the maximum number of times within the retry window, Config adds a remediation exception for that resource to stop a loop. You can add exceptions yourself (put-remediation-exceptions, with an optional expiry) for resources that are allowed to stay non-compliant; they are still evaluated, just not remediated.
  • The API can't attach remediation to service-linked rules (organization rules, conformance pack rules, Security Hub rules): put it in the conformance pack template.
  • Auto remediation can run on a resource that has just become compliant, because it works from a periodic snapshot, so use runbooks that are safe to re-run.

Remediating Security Hub CSPM findings

Security Hub CSPM findings go to EventBridge as Security Hub Findings - Imported (automatic responses) or Security Hub Findings - Custom Action (an analyst chooses an action in the console), targeting Lambda, Step Functions or Systems Manager Automation. Automated Security Response on AWS (version 4.1 in November 2026) packages ready-made remediation playbooks for both Security Hub CSPM and the new Security Hub across accounts (Task 2.1).

Notifications

SNS or EventBridge

Config's delivery channel can send every notification (configuration changes, snapshots, compliance changes) to one SNS topic, all or nothing. For targeted alerts, match the Config Rules Compliance Change event in EventBridge and send it to SNS, chat or a ticketing system.

Page the team when any bucket fails the encryption rule (EventBridge pattern, built from the documented compliance change message) 
{
  "source": ["aws.config"],
  "detail-type": ["Config Rules Compliance Change"],
  "detail": {
    "messageType": ["ComplianceChangeNotification"],
    "configRuleName": ["s3-bucket-sse-enabled"],
    "newEvaluationResult": { "complianceType": ["NON_COMPLIANT"] }
  }
}

Events are delivered on a best-effort basis, and there are no events for resource types that aren't recorded. Archived Security Hub CSPM control findings are kept for only 30 days, so send findings to S3 through EventBridge if they're needed as evidence.

Security Hub CSPM standards

Standards, status and score

Security Hub CSPM runs controls (mostly Config service-linked rules) grouped into standards: AWS Foundational Security Best Practices, CIS AWS Foundations Benchmark (v5.0.0 recommended; v3.0.0, v1.4.0 and v1.2.0 also available), NIST SP 800-53 Rev. 5, NIST SP 800-171 Rev. 2, PCI DSS (v4.0.1 recommended, v3.2.1 still available), AWS Resource Tagging, AI Security Best Practices, CRI Profile v2.2, and the service-managed AWS Control Tower standard. Enable a new version before disabling the old one.

  • A finding's compliance status is PASSED, FAILED, WARNING (couldn't check, for example the resource type isn't recorded) or NOT_AVAILABLE. Since July 2025 a status change updates the existing finding instead of creating a new one.
  • Consolidated control findings (one finding per check across all standards) is on by default for accounts enabled since February 2023.
  • The security score is passed controls divided by enabled controls with data, updated every 24 hours. Disable controls that don't apply rather than suppressing their findings: suppressing every failed finding makes a control pass and inflates the score.
  • Some controls take parameters, set per control or in central configuration policies.
Warn about certificates 30 days before expiry instead of the default (AWS CLI, Security Hub CSPM control parameter) 
aws securityhub update-security-control --security-control-id ACM.1 \
  --parameters '{"daysToExpiration": {"ValueType": "CUSTOM", "Value": {"Integer": 30}}}'

Collecting and organizing evidence

Skill 6.3.2Use AWS audit services to collect and organize evidence (for example, AWS Audit Manager, AWS Artifact).

AWS Audit Manager

How it works, for existing customers

Audit Manager maps frameworks (prebuilt ones such as PCI DSS, HIPAA, SOC 2 and GDPR, or custom) to controls, and an assessment continuously collects evidence for the accounts in scope:

  • Compliance checks from Config rules and Security Hub CSPM controls, user activity from CloudTrail, configuration data from API calls (daily, weekly or monthly), and manual evidence (uploads, S3 imports, text answers).
  • Evidence from CloudTrail, API calls and manual sources is always inconclusive, which doesn't mean failed; only Config and Security Hub evidence has a compliance result.
  • Audit owners delegate control sets (not whole assessments) to experts, who review evidence and add comments.
  • The assessment report is a zip of a PDF summary and evidence folders written to an S3 bucket, with a checksum file you can verify through the API. A customer managed KMS key must be in the same Region as the assessment and bucket.

Audit Manager collects evidence; it doesn't decide whether you're compliant, doesn't remediate, and isn't open to new accounts. For a new design, the AWS answer is Config conformance packs (with advanced query exports and configuration history as evidence) plus Security Hub CSPM or Control Tower, and partner tools for frameworks such as SOC 2, GDPR and ISO 27001 that have no conformance pack.

AWS Artifact

AWS's side of the shared responsibility model

AWS Artifact is a free self-service portal for AWS's own compliance documents: SOC, PCI DSS, ISO and other reports and certifications, plus third-party reports from some AWS Marketplace sellers. They prove what AWS does; your own controls still need your own evidence. Downloads are watermarked for the user and may be shared only within your company and with regulators and auditors. Some reports require accepting terms first.

Download AWS's PCI DSS attestation for the auditors (AWS CLI) 
aws artifact list-reports
aws artifact get-term-for-report --report-id report-0123456789abcdef --report-version 1
aws artifact get-report --report-id report-0123456789abcdef --report-version 1 --term-token <token>
  • Agreements such as the HIPAA Business Associate Addendum can be accepted per account, or as an organization agreement from the management account only, which covers all current and future member accounts.
  • Permissions are fine-grained (artifact:ListReports, artifact:GetReport, artifact:AcceptAgreement and others, with condition keys such as artifact:ReportSeries); the old artifact:Get permission has been removed from the managed policy.
  • Notifications of new or updated reports and agreements come through AWS User Notifications.
  • Assurance Assistant (June 2026) answers compliance questionnaires about AWS's controls, with citations.

"The auditor needs AWS's SOC 2 or PCI attestation" points to AWS Artifact. "Accept the BAA for every account, including future ones" points to an Artifact organization agreement from the management account. "Show evidence of our own controls over time" points to Config (or Audit Manager for existing customers).

Evaluating architecture

Skill 6.3.3Use AWS services to evaluate architecture for compliance with AWS security best practices (for example, AWS Well-Architected Framework tool).

The Security pillar

Design principles and areas

The Security pillar (last revised November 2024) has seven design principles: implement a strong identity foundation, maintain traceability, apply security at all layers, automate security best practices, protect data in transit and at rest, keep people away from data, and prepare for security events. Its best practices fall into seven areas: security foundations, identity and access management, detection, infrastructure protection, data protection, incident response, and application security. These map closely onto this exam's domains.

AWS Well-Architected Tool

Workloads, lenses and milestones

The Well-Architected Tool is a question-based review, not a resource scanner. You define a workload, answer each pillar's questions, and get high risk issues (HRIs) and medium risk issues (MRIs) plus an improvement plan.

Register the payments workload for review (AWS CLI) 
aws wellarchitected create-workload --workload-name payments-api \
  --description "Card payments API" --environment PRODUCTION \
  --review-owner security-architecture@example.com \
  --aws-regions us-east-1 us-west-2 --lenses wellarchitected
  • Lenses: the Well-Architected Framework lens is always applied; add catalog lenses (Serverless, SaaS, Financial Services, Machine Learning, Generative AI and others) or custom lenses written in JSON with your own questions, up to 20 per workload.
  • Milestones save the state of a review at design, go-live and later, so you can show improvement over time.
  • Review templates pre-fill answers for similar workloads, and profiles prioritize questions by business context.
  • Sharing workloads, lenses, templates and profiles works with accounts, users, OUs or the organization, but only in the same Region. Organization sharing must be turned on from the Well-Architected Tool in the management account. Deny wellarchitected:CreateWorkloadShare to prevent sharing.
  • Integrations: Trusted Advisor checks linked to the workload's resources (Business Support+ or higher), a Jira connector for improvement items, a dashboard of risks across workloads, and EventBridge events.
  • The new Well-Architected Agent (preview) continuously analyzes environments and recommends improvements.

Trusted Advisor

Automated checks

Trusted Advisor checks accounts across cost, performance, security, fault tolerance, service limits and operational excellence, and shows Security Hub CSPM Foundational Security Best Practices results when that standard and Config are enabled. With Basic or Developer Support you get only a few security checks (public EBS and RDS snapshots, S3 bucket permissions, root MFA, unrestricted ports, STS global endpoint use), refreshed manually; the full set, the API, EventBridge events and the organizational view need Business Support+, Enterprise or Unified Operations. The Developer, Business and Enterprise On-Ramp plans end on 1 January 2027.

A Well-Architected review records the team's answers; it doesn't prove resources are configured that way. Pair it with continuous checks (Config, Security Hub CSPM, Trusted Advisor). And a workload shared in us-east-1 isn't visible to reviewers in another Region.

"Review a new workload against AWS security best practices before launch and track improvements" points to the Well-Architected Tool with milestones. "Apply the company's own security questions to every review" points to a custom lens shared with the organization.

Key takeaways

  • Config rules: managed, custom Lambda or Guard; change, periodic or both; only recorded types are evaluated; proactive evaluation never blocks; service-linked rules are changed through their owning service.
  • Record global IAM types in one Region; daily recording is cheaper per change but delays findings up to 24 hours; Firewall Manager needs continuous recording.
  • Two Config delegated-admin principals (config-multiaccountsetup for org rules and packs, config for aggregators); organization rules are CLI only; org conformance packs override member IAM denies and need an awsconfigconforms bucket.
  • Aggregators are free and read-only; account-based ones need authorization in every source; advanced queries are limited SQL with CSV or JSON export.
  • Rules don't fix: remediation is SSM Automation with AutomationAssumeRole, retries then a remediation exception; put remediation for service-linked rules in the pack template.
  • Notify through EventBridge Config Rules Compliance Change (targeted) or the SNS delivery channel (everything); keep Security Hub CSPM findings in S3 for evidence.
  • Security Hub CSPM: FSBP, CIS v5.0.0, NIST, PCI DSS v4.0.1, tagging, AI and CRI standards; PASSED, FAILED, WARNING, NOT_AVAILABLE; score is passed over enabled; disable, don't suppress.
  • Audit Manager collects evidence (inconclusive isn't failed), delegates control sets, doesn't remediate, and is closed to new accounts; conformance packs are the recommended replacement.
  • Artifact: AWS's reports and agreements (organization agreements from the management account cover future accounts); fine-grained permissions; watermarked and confidential.
  • Well-Architected: seven Security pillar principles and areas; workloads, lenses, custom lenses, milestones, Region-scoped sharing; Trusted Advisor's full checks need Business Support+ or higher.
