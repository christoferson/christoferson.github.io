The exam

KCSA at a glance
Format
Online, proctored, multiple choice: 60 questions in 90 minutes, taken through PSI
Passing score
75%; results within 24 hours
Cost and validity
US$250 including one free retake; 12 months to take it; certification valid 2 years (renewed by passing the exam again or by passing CKS)
Level and language
Beginner, no prerequisites; English only
Curriculum
1 Overview of Cloud Native Security 14% · 2 Kubernetes Cluster Component Security 22% · 3 Kubernetes Security Fundamentals 22% · 4 Kubernetes Threat Model 16% · 5 Platform Security 16% · 6 Compliance and Security Frameworks 10%; unchanged since June 2024
Kubestronaut
KCSA is one of the five exams (with KCNA, CKA, CKAD and CKS) needed for the title

Domain 1: Overview of Cloud Native Security

The 4Cs, cloud and infrastructure (Topic 1.1)

ClueAnswer
Four layers, each built on the outer oneCloud, Cluster, Container, Code: a kubernetes.io model, not a CNCF one (4Cs)
Lifecycle phases in the CNCF whitepaperDevelop, Distribute, Deploy, Runtime (phases)
Who secures what on managed KubernetesProvider: control plane, etcd, data centers; you: workloads, RBAC, network policy, images. Managed doesn't mean private (shared responsibility)
Kubelet with no hardeningAnonymous requests allowed, AlwaysAllow, read-only port 10255 open (ports)
Pods reaching cloud credentialsBlock 169.254.169.254 with egress NetworkPolicy; lower the metadata hop limit (metadata)
Secrets in etcd are readableEncryptionConfiguration with KMS v2; identity first means no encryption (etcd)
Check node configuration against a benchmarkCIS Kubernetes Benchmark with kube-bench (Aqua, not CNCF) (nodes)

Controls, frameworks and isolation (Topic 1.2)

ClueAnswer
Preventive, detective, corrective, deterrent, compensatingControl functions (NIST IR 8286r1); not the same as categories (controls)
Several independent layers; minimum rights; never trust the network locationDefense in depth; least privilege; zero trust (SP 800-207) (principles)
Image, registry, orchestrator, container, host OSThe five risk areas of NIST SP 800-190 (frameworks)
Kernel features that isolate a containerNamespaces, cgroups, capabilities, seccomp, AppArmor or SELinux (kernel)
Stop setuid binaries gaining privilegesallowPrivilegeEscalation: false (sets no_new_privs)
Root in the container is not root on the nodeUser namespaces, hostUsers: false
Own kernel per Pod, or a user-space kernelKata Containers (VMs) or gVisor, chosen with a RuntimeClass (sandboxes)
Hostile tenantsHard multi-tenancy: separate nodes or clusters, not just namespaces (nodes and clusters)

Images and application code (Topic 1.3)

ClueAnswer
Image reference that can't be repointedA digest (@sha256:...); tags are mutable (tags and digests)
Changing the tag later doesn't change pullingimagePullPolicy is set once, at creation
Pull from a private registrydocker-registry Secret + imagePullSecrets, same namespace as the Pod (private registries)
Other Pods reuse a cached private imageAlwaysPullImages admission, or the kubelet's KubeletEnsureSecretPulledImages (cached images)
Secret passed as a build argumentPersists in the image; use RUN --mount=type=secret (building)
Scan finds CVEs but the build passesTrivy exits 0 unless --exit-code 1 (scanning)
Severity; likelihood of exploitation; "not affected"CVSS; EPSS; VEX
Source analysis; running-app tests; dependency checksSAST; DAST; SCA (code)

Domain 2: Kubernetes Cluster Component Security

Control plane components and etcd (Topic 2.1)

ClueAnswer
Group that skips RBAC and webhookssystem:masters; never put people in it (API server)
Allow anonymous only for health checksAuthenticationConfiguration anonymous.conditions
API server talks to any kubelet without checkingSet --kubelet-certificate-authority; kubeadm doesn't
Component that holds the CA key and ServiceAccount signing keykube-controller-manager (controller manager)
A Pod placed without the schedulerSetting nodeName directly; turn off --profiling on the scheduler (scheduler)
Any certificate etcd trustsFull access to all data: give etcd its own CA (etcd)
Old insecure ports such as 10251 and 10252Removed; current secure ports 6443, 10259, 10257

Kubelet, runtime, kube-proxy and the Pod (Topic 2.2)

ClueAnswer
Hardened kubeletAnonymous off, Webhook authorization, read-only port 0, client CA file (kubelet API)
Permission that equals exec on every nodeget on nodes/proxy (kubelet authorization)
Kubelet may only change its own Node and PodsNode authorizer + NodeRestriction admission (identity)
Kubelet serving certificate CSRNever approved automatically
Mounting the containerd socketRoot on the node (runtime)
Service externalIPs used to intercept trafficCVE-2020-8554, no patch: block with admission (kube-proxy)
Fields that break the Pod boundaryprivileged, hostPath, hostNetwork, hostPID, hostIPC (Pod)
Pods that admission never seesStatic Pods from the kubelet's manifest directory

Networking, clients and storage (Topic 2.3)

ClueAnswer
Pod-to-Pod traffic by defaultAllowed and unencrypted (Pod network)
Write access to /opt/cni/binRoot code execution on the node
dnsPolicy that isn't the defaultDefault (node's DNS); the default is ClusterFirst (DNS)
Capability that allows packet spoofingNET_RAW: drop it (Restricted drops ALL)
Ingress controller retired in March 2026Ingress NGINX (CVE-2025-1974); move to Gateway API (Services)
Untrusted kubeconfigIts exec plugin can run any command; kuberc credentialPluginPolicy limits plugins (kubeconfig)
Habits to avoid--insecure-skip-tls-verify, shared admin kubeconfigs, long-lived tokens in CI (client habits)
Only one Pod may use a volumeReadWriteOncePod; access modes aren't write protection (volumes)
Keep data when the claim is deletedreclaimPolicy: Retain; encrypt via the StorageClass (stored data)

Domain 3: Kubernetes Security Fundamentals

Pod Security Standards and Admission (Topic 3.1)

ClueAnswer
The three levelsPrivileged, Baseline, Restricted (standards)
Blocks host namespaces, privileged and hostPath, but allows rootBaseline (Baseline)
Must set non-root, drop ALL, seccomp, no privilege escalationRestricted, and every field must be set explicitly (Restricted)
Reject, log, or warn the userPSA modes enforce, audit, warn (PSA)
Deployment accepted, but no Pods appearenforce checks Pods only; the error is in the ReplicaSet's events
Version label written 1.37Needs the v: v1.37 (labels)
Namespace with no labelsGets the cluster default, out of the box privileged
Is kube-system exempt?Not by default (exemptions)
PodSecurityPolicyRemoved in 1.25; use PSA or a policy engine (PSP)

Authentication and authorization (Topic 3.2)

ClueAnswer
Kubernetes has no user objectsUsers come from certificates, OIDC or other authenticators; ServiceAccounts are objects (identities)
Best authentication for peopleOIDC with MFA; static token files "not recommended for production" (methods)
Mounted token shows 3607 secondsExtended up to 1 year for old clients; set automountServiceAccountToken: false if unused (tokens)
Revoke a client certificateImpossible: use short lifetimes and remove RBAC bindings (certificates)
Authorization mode if none is setAlwaysAllow; kubeadm sets Node,RBAC. RBAC has no deny rules (authorization)
list on SecretsReturns their contents
Check someone's rightskubectl auth can-i --list --as=...
Change the role a binding grantsroleRef is immutable: delete and recreate (RBAC)
Verbs that allow privilege escalationescalate, bind, impersonate; edit can act as any ServiceAccount in the namespace (escalation)

Secrets (Topic 3.3)

ClueAnswer
Base64Encoding, not encryption; stored unencrypted in etcd by default (Secrets)
Who can read a namespace's Secrets indirectlyAnyone who can create Pods (or Deployments) there (readers)
Pod won't start; Secret missingNon-optional Secrets block start-up (using Secrets)
Secret values in the audit logLog Secrets at Metadata level only (leaks)
Envelope encryption with an external keyKMS v2 (KMS v1 deprecated 1.28, off by default 1.29) (KMS)
Encryption turned on, old Secrets still plaintextRewrite them: existing objects aren't re-encrypted
Sync from an external vaultExternal Secrets Operator, Secrets Store CSI driver, SOPS for Git (external managers)

Isolation, segmentation and NetworkPolicy (Topic 3.4)

ClueAnswer
Do namespaces block traffic?No: they scope names, RBAC and quotas, not the network (namespaces)
Cap a tenant's total resourcesResourceQuota; LimitRange sets per-container defaults (quotas)
When is a Pod isolated?Once a policy selects it for that direction; rules only add allows (NetworkPolicy)
One list item vs twonamespaceSelector and podSelector in one item = AND; separate items = OR
Default-deny egress, then nothing resolvesAllow DNS to kube-dns on port 53 (default deny)
What NetworkPolicy can't doL7 rules, logging, explicit deny, hostNetwork Pods; needs a CNI that enforces it (limits)
Cluster admin rules above namespace policiesClusterNetworkPolicy tiers: Admin, then NetworkPolicy, then Baseline (ClusterNetworkPolicy)

Audit logging (Topic 3.5)

ClueAnswer
Is auditing on by default?No: needs --audit-policy-file and a backend (auditing)
RequestReceived, ResponseStarted, ResponseComplete, PanicAudit stages
None, Metadata, Request, RequestResponseAudit levels
Which rule applies?The first match: specific rules first (policy)
Where events goLog file or webhook backend; ship off-cluster (backends)
Who ran exec, read Secrets or changed RBACQuery user, verb, objectRef in the events (detection)
What the audit log missesAnything not through the API server: direct etcd, kubelet, runtime and in-container actions (blind spots)

Domain 4: Kubernetes Threat Model

Trust boundaries and data flow (Topic 4.1)

ClueAnswer
Where the level of trust changesA trust boundary (definitions)
Process, data store, data flow, external entityData flow diagram elements
Internet, API server, master components, master data, worker, containerThe six trust zones of the 2019 Kubernetes security audit (zones)
Weakest direction by defaultControl plane to node: the API server doesn't verify the kubelet (weak crossings)
Tunnel from control plane to nodesKonnectivity (flows)

Persistence, denial of service, malicious code (Topic 4.2)

ClueAnswer
Two threat matrices for KubernetesMicrosoft Threat Matrix for Kubernetes; MITRE ATT&CK® Containers (matrices)
Staying in the cluster after a fixPersistence: CronJobs, backdoor containers, static Pods, malicious admission webhooks; hunt for them (persistence)
One Pod uses all node CPU and memoryRequests and limits, LimitRange, ResourceQuota, podPidsLimit, API Priority and Fairness (DoS)
Unexpected cryptominerResource hijacking; detect with Falco, Tetragon or KubeArmor (malicious code)
Contain a compromised PodLabel it, isolate with a quarantine NetworkPolicy, cordon, keep evidence before deleting (response)
Quarantine policy, but traffic still flowsNetworkPolicies are additive: other allow policies still apply

Network attackers, sensitive data, privilege escalation (Topic 4.3)

ClueAnswer
Attacker sniffing or spoofing Pod trafficmTLS, default-deny NetworkPolicy, drop NET_RAW (network)
Encryption at rest, yet Secrets still leakIt protects etcd, not anyone allowed to read through the API (sensitive data)
Container to nodeprivileged, hostPath, hostPID: blocked by Baseline; privilege escalation and root: Restricted (escalation)
Inside the APIcreate Pods, escalate, bind, impersonate, read Secrets
Signals in the audit logexec, Secret reads, new RoleBindings, privileged Pods (detection)
What can this ServiceAccount do?kubectl auth can-i --list --as=system:serviceaccount:NS:SA (self-checks)

Domain 5: Platform Security

Supply chain and image repository (Topic 5.1)

ClueAnswer
Source code, materials, build pipelines, artifacts, deploymentsThe five stages in the CNCF supply chain paper (supply chain)
Build L1, L2, L3SLSA levels (v1.2 adds a Source track); there's no Build L4 (SLSA)
Signing without long-lived keysSigstore keyless: cosign, Fulcio certificates, Rekor log; verify identity and issuer (signing)
SPDX or CycloneDXSBOM formats (SBOMs)
Signed record of each build step; secure update metadatain-toto; TUF (both CNCF Graduated) (in-toto and TUF)
Registry with scanning, signing and replicationHarbor; pull only through trusted mirrors (repository)
Reject unsigned images at deploy timeAdmission: Kyverno ImageValidatingPolicy, Sigstore policy-controller, Ratify; pin digests (verifying)

Observability and service mesh (Topic 5.2)

ClueAnswer
Kubernetes Events as evidenceNot an audit trail: kept for an hour by default (telemetry)
Detect; detect and enforce; LSM enforcementFalco; Tetragon; KubeArmor (runtime tools)
What mTLS givesEncryption and authentication, not authorization (mesh)
Istio accepts plaintextPERMISSIVE is the default; apply PeerAuthentication STRICT (Istio)
L7 DENY rule ignored in ambient modeztunnel handles L4 only; use a waypoint (ambient)
Linkerd's default policyAll traffic allowed, including unauthenticated
Workload identity standardSPIFFE IDs, issued by SPIRE or the mesh

PKI and connectivity (Topic 5.3)

ClueAnswer
CAs in a kubeadm clusterkubernetes-ca, etcd-ca, front-proxy-ca, plus the sa key pair (PKI)
Kubernetes certificate revocationNone: keep lifetimes short; CA rotation is disruptive (rotation)
Distribute CA bundles; give Pods certificatesClusterTrustBundle; Pod certificates (both GA in 1.37) (workload certificates)
Automate certificates from ACME or a vaultcert-manager (CNCF Graduated) (cert-manager)
TLS from the gateway to the backendGateway API BackendTLSPolicy (edge)
Control plane traffic to nodesKonnectivity, EgressSelectorConfiguration (connectivity)

Admission control (Topic 5.4)

ClueAnswer
Order of admissionMutating, then schema validation, then validating (phases)
Does admission see reads? exec?Reads skip admission; exec (CONNECT) goes through it
Kubelet can edit other nodesEnable NodeRestriction; it's off by default upstream (plugins)
Webhook down, requests still passfailurePolicy: Ignore; the default is Fail (webhooks)
Admission can't guard its own configurationProtect webhook configs with RBAC; manifest-based admission (beta 1.37) (risks)
In-process policy in CELValidatingAdmissionPolicy (GA 1.30); MutatingAdmissionPolicy (GA 1.36) (CEL)
Policy enginesKyverno (YAML and CEL), OPA Gatekeeper (Rego), Kubewarden (Wasm) (engines)

Threat modeling, automation and tooling (Topic 6.2)

ClueAnswer
What are we working on? What can go wrong? ...The four questions of the Threat Modeling Manifesto (threat modeling)
Spoofing, Tampering, Repudiation, Information disclosure, DoS, Elevation of privilegeSTRIDE: authentication, integrity, non-repudiation, confidentiality, availability, authorization (STRIDE)
Seven risk-centric stages; privacy threats; organizational riskPASTA; LINDDUN; OCTAVE (other frameworks)
Goal at the root, AND/OR childrenAttack trees (Schneier)
Find threats in a design vs catalogue observed attacksFrameworks vs threat matrices (matrices)
Lint manifests in CIKubeLinter, Checkov, kubesec, Polaris, Conftest; make them fail the build (scanners)
Cluster against CIS or NSA/CISAkube-bench, trivy k8s --compliance, Kubescape (compliance scanners)
Test admission policies before deployingkyverno apply/test, gator (policy tests)
Undo manual changes in the clusterGitOps drift correction: Argo CD needs selfHeal; Flux every interval (in the cluster)
