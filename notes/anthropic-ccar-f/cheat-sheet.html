The exam

CCAR-F at a glance
Version
Exam guide version 1.1 (November 2026). It changed only registration, identification and support; domains and task statements are the same as version 1.0.
Format
60 multiple-choice and multiple-response items in 120 minutes, framed by four scenarios drawn at random from a published set of six.
Scoring
Scaled 100 to 1,000; pass at 720.
Cost, delivery, validity
US$125 per attempt; Pearson VUE, online or at a test center; valid for 12 months. Registration is open only to people at organizations in the Claude Partner Network.
Domains
1 Agentic Architecture & Orchestration 27% · 2 Tool Design & MCP Integration 18% · 3 Claude Code Configuration & Workflows 20% · 4 Prompt Engineering & Structured Output 20% · 5 Context Management & Reliability 15% · 30 task statements

How to read the tables. The exam guide reflects the products when it was written. Where Claude has changed since, the answer gives the guide's expected answer first and today's behaviour after it; the last section lists every such difference.

Domain 1: Agentic Architecture & Orchestration

Agentic loops (Task 1.1)

ClueAnswer
When should the loop continue?Only while stop_reason is tool_use; branch on everything else (stop reasons)
Loop ends by checking for text, or after 10 iterationsWrong: end on the stop reason; an iteration cap is a safety net that reports an error (anti-patterns)
How tool results go backOne user message right after the assistant turn: a tool_result per call, matched by tool_use_id, results first, is_error: true for failures (returning results)
pause_turnA server tool paused a long turn: send the response back to continue
Steps can't be predicted in advanceModel-driven agent loop; a predefined workflow when the path is known; must-always rules in code (model-driven or predefined)

Coordinators and subagents (Task 1.2)

ClueAnswer
Subagents should share findings with each otherHub and spoke: everything goes through the coordinator, for observability and consistent error handling (hub and spoke)
Subagent "doesn't know" what the coordinator learnedIsolated context: put everything it needs in the brief; only its final message returns (isolated context)
Report misses whole areas of the topicDecomposition too narrow: partition by subtopic or source and check coverage of the whole question (partitioning)
Same research pipeline for every questionScale subagents to the query: one for a fact, a few for a comparison, many for broad research (how many)
Gaps after the first synthesisRefinement loop: find gaps, re-delegate targeted queries, re-synthesise, stop at coverage or a limit (refinement)

Invoking subagents and passing context (Task 1.3)

ClueAnswer
Coordinator can't spawn subagentsGuide: add Task to allowedTools. Today the tool is Agent, and allowed_tools only pre-approves; block with disallowed_tools (spawning tool)
Subagent chosen for the wrong jobSharpen the AgentDefinition description; restrict tools, size model (defining subagents)
Synthesizer can't attribute claimsPass complete findings as structured data with content and source metadata separated (complete findings)
Independent subagents run one after anotherSeveral Agent calls in one coordinator response (parallel)
Try two approaches from the same analysisFork the session (resume plus fork_session=True); files aren't branched (forking)

Enforced workflows and handoffs (Task 1.4)

ClueAnswer
Agent sometimes refunds before verifying the customerA programmatic prerequisite gate on the refund tool, using state your code set; a stronger prompt isn't deterministic (prerequisite gate)
Gate in the Agent SDKPreToolUse hook returning permissionDecision: "deny" with a reason Claude can act on (gate behaviour)
One message raises three issuesDecompose, investigate in parallel with shared context, reply with one unified resolution (several concerns)
Human agent has to re-ask everythingSelf-contained handoff: ID, issue, root cause, amount, steps taken, recommendation, as required tool fields (handoffs)

Hooks (Task 1.5)

ClueAnswer
Tools return dates in three formatsPostToolUse hook that normalises results (updatedToolOutput), keeping their shape (normalising)
Refunds over $500 must never go throughPreToolUse deny with a reason that redirects to escalation (intercepting calls)
Hook or prompt?Hook when a rule must always hold; prompt for judgement; both for important rules (hooks or prompts)
Rewrite a result to undo an actionCan't: PostToolUse runs after the side effect; block it before, in PreToolUse (rewriting rules)

Task decomposition (Task 1.6)

ClueAnswer
Predictable, multi-aspect work needing consistent coveragePrompt chaining: fixed steps with code gates between them (choosing)
Open-ended investigationDynamic decomposition: map, rank by impact, plan, re-plan as dependencies appear (adaptive plan)
Review of 14 files misses issues and contradicts itselfPer-file local passes plus one cross-file integration pass (chained review)

Sessions (Task 1.7)

ClueAnswer
Continue a specific earlier investigationclaude --resume <name> (name it with -n or /rename); --continue is only the latest; SDK resume= (resuming)
Code changed since the session ranResume and say which files changed, so it re-reads just those (after changes)
Most earlier tool results are staleStart fresh with a structured summary instead of resuming (resume or fresh)
Branch the conversation/branch, --fork-session or fork_session=True; never resume one session in two places (forking)

Domain 2: Tool Design & MCP Integration

Tool interfaces (Task 2.1)

ClueAnswer
Claude picks the wrong one of two similar toolsRewrite the descriptions: what, when, when not, inputs, outputs, limits; distinct names (descriptions)
One tool does everythingSplit it; consolidate thin wrappers that are always chained (split or consolidate)
strict: trueGuarantees schema-valid inputs, not the right tool choice (inputs)
MCP tool, resource or prompt?Tools for actions (model), resources for catalogs and context (application), prompts for templates (user) (MCP primitives)
More than 30 to 50 toolsTool search with deferred loading (many tools)

Structured error responses (Task 2.2)

ClueAnswer
Tool failed: protocol error or result?Result with isError: true, so the model sees it; JSON-RPC errors are for bad requests (two kinds)
"Operation failed"Too vague: add a category, a retryable flag and the next step (why it fails)
Business-rule or permission failureDon't retry: explain and hand off or escalate (categories)
Search found nothingSuccess with an empty result, not an error (empty results)

Tools across agents and tool_choice (Task 2.3)

ClueAnswer
Agent with 18 tools misuses themFewer, role-specific tools per subagent; cross-role needs as one narrow tool (fewer tools)
Limit a subagent's toolsAgentDefinition.tools (omit it and it inherits all) (scoping)
Must call some tool, type unknownGuide: tool_choice: any. Fable 5.2, Mythos 5.2, Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1 reject it with a 400: use auto plus strict tools and check a tool was called (forcing not allowed)
Run one particular step firstGuide: force the named tool; same model limits apply (tool_choice)

MCP servers in Claude Code (Task 2.4)

ClueAnswer
Share a server with the whole teamProject scope: .mcp.json, committed (scopes)
Personal server for every projectUser scope in ~/.claude.json; local scope is this project only, and the default
Token in .mcp.json${VAR} expansion; never commit secrets (shared file)
Common system such as GitHub or JiraUse an existing server; build custom ones for team-specific workflows (choosing servers)

Built-in tools (Task 2.5)

ClueAnswer
Find files by nameGlob; content is Grep; a known file is Read (choosing)
Edit fails: text not uniqueMore surrounding context or replace_all; no anchor at all: Read then Write (Edit fallbacks)
Understand an unfamiliar moduleIncrementally: Grep for entry points, Read ranges, follow imports (exploring)

Domain 4: Prompt Engineering & Structured Output

Explicit criteria (Task 4.1)

ClueAnswer
Too many false positivesExplicit, categorical criteria for what to report and skip; "be conservative" or "high confidence only" don't work (why not)
Inconsistent severity ratingsDefine each level by impact with a concrete code example (severity)
One category is noisy, developers ignore allDisable that category temporarily, fix and test its criteria, re-enable (trust)

Few-shot examples (Task 4.2)

ClueAnswer
Detailed instructions, still inconsistent outputFew-shot examples aimed at the ambiguous cases, each with its reasoning (when examples help)
How many?Guide: 2 to 4 targeted examples; Claude's prompting guide: 3 to 5 (choosing)
Extraction invents values or leaves fields emptyExamples across varied layouts, including real nulls (extraction)

Structured output (Task 4.3)

ClueAnswer
Guaranteed valid JSONA tool whose input schema is the output, with strict: true, or JSON outputs (output_config.format) (tools as output)
JSON valid but the totals don't add upSchemas fix syntax, not semantics: validate in code (syntax vs semantics)
Model fabricates a missing fieldMake it nullable; enums with other plus a detail field (schema design)

Validation and retries (Task 4.4)

ClueAnswer
Extraction fails validationRetry with the document, the failed output and the specific errors; cap retries (retry with feedback)
Field isn't in the documentRetrying can't help: null with a reason, route to review (when retries can't help)
Is it a misread or an inconsistent document?Self-checking fields: stated_total vs calculated_total, conflict_detected (self-checking)

Batch processing (Task 4.5)

ClueAnswer
Halve the cost of pre-merge reviewsNo: blocking work stays synchronous; batches for overnight or weekly jobs (batch or sync)
30-hour SLA with batchesSubmit every 4 hours (interval + 24 h + margin ≤ SLA) (SLA)
Match results to inputscustom_id; results come in any order (offer)
Some items failedResubmit only those, fixed for their failure (chunk oversized ones) (pipeline)
Agent with tool calls in a batchA batch request can't run tools mid-request; give it everything up front (can't do)

Multi-instance review (Task 4.6)

ClueAnswer
"Review your own code carefully"Weak: use an independent instance without the generator's reasoning (self-review)
Which findings reach developers?A verification pass with confidence per finding: post, triage or drop; calibrate the threshold (verification)

Domain 5: Context Management & Reliability

Long interactions (Task 5.1)

ClueAnswer
Agent forgets the refund amount after an hourA case facts block in every prompt, outside the summarised history (case facts)
Order lookups bloat the contextTrim tool results to the relevant fields before they enter history (trimming)
Findings in the middle get missedKey findings first, sections with headers, question last (position)
Coordinator's context fills with subagent proseStructured findings with metadata instead of reasoning (lean outputs)

Escalation (Task 5.2)

ClueAnswer
"I want to talk to a person"Escalate immediately, no investigation first (request vs frustration)
Angry customer, simple refundAcknowledge and offer the fix; escalate if they repeat the request
Competitor price match, policy covers own site onlyPolicy gap: escalate (policy gaps)
Escalate on sentiment or self-rated confidenceUnreliable proxies for complexity (misleading signals)
Two customers match the nameAsk for another identifier; never pick (several matches)

Error propagation (Task 5.3)

ClueAnswer
Timeout returned as an empty listSilent suppression: keep access failures apart from valid empty results (failed or empty)
One source down, whole run abortsAnti-pattern: continue with partial results and mark the gap (anti-patterns)
What the error report should holdFailure type, query attempted, attempts, retryable, partial results, alternatives (report)
Transient failure in a subagentRetry locally with backoff; propagate only what it can't fix (local recovery)

Codebase exploration (Task 5.4)

ClueAnswer
Answers drift to "typical patterns"Context degradation: scratchpad files, subagents, /compact (degradation)
Next phase needs the last phase's resultsSummarise the phase and inject it into the new subagents' prompts (phase summaries)
Recover a multi-agent job after a crashEach agent exports state to a known location; the coordinator loads a manifest on resume (manifests)

Human review (Task 5.5)

ClueAnswer
97% accurate overall, so stop reviewing?Check accuracy per document type and field first (aggregates)
Which confidence is safe to auto-accept?Per-field thresholds calibrated on a labelled validation set (calibration)
Keep measuring auto-accepted workStratified random sampling for audit (audit)
Not enough reviewersRoute low confidence and contradictory sources, ordered by risk (routing)

Provenance (Task 5.6)

ClueAnswer
Final report can't say who said whatClaim-source mappings preserved through every step (lost attribution)
Two credible sources give different figuresKeep both with sources; the coordinator reconciles; never pick one arbitrarily (conflicts)
9% versus 18%, different yearsChange over time, not a contradiction: require dates (dates)
Everything rendered as bullet pointsFinancial as tables, news as prose, technical as lists; separate established from contested (rendering)

Numbers worth knowing

API and SDK
Message Batches
50% off; up to 24 hours; 100,000 requests or 256 MB per batch; results kept 29 days
Context window
1M tokens on current models; up to 128k output tokens per request
Tool catalogs
Tool search beyond about 30 to 50 tools
SDK retries
Transient errors (408, 409, 429, 5xx) retried twice by default
Context editing
Clears old tool results after 100,000 input tokens by default, keeping the last 3
Claude Code
CLAUDE.md
Keep each file under about 200 lines; imports up to four hops
MCP output
Capped at 25,000 tokens by default
After compaction
Up to five recent files re-read; skill bodies up to 5,000 tokens each, 25,000 total
Few-shot
Guide 2 to 4 examples; prompting docs 3 to 5
Support agent
Escalation accuracy target 95%+; deflection typically 70 to 80%
