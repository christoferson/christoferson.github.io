2.4: MCP Servers in Claude Code

Connecting MCP servers to Claude Code and to Agent SDK applications: which scope to configure a server in, keeping its credentials out of Git, how several servers work together, and how resources and prompts reach the conversation.

Overview

Task 2.4

Integrate MCP servers into Claude Code and agent workflows.

The exam guide asks you to know project-level .mcp.json for shared team tooling versus user-level ~/.claude.json for personal or experimental servers, environment variable expansion (such as ${GITHUB_TOKEN}) to keep secrets out of version control, that tools from all configured servers are available together, and that MCP resources can expose content catalogs so the agent needs fewer exploratory calls. In practice: configure shared servers with expanded tokens, keep personal ones in user scope, write descriptions good enough that Claude doesn't fall back to built-in tools such as Grep, and prefer an existing community server over building your own unless the workflow is specific to your team.

Sources: the Claude Code MCP documentation and settings reference, the Agent SDK MCP and custom tools documentation, the MCP specification and the Claude API MCP connector page, checked on 8 November 2026 against Claude Code 2.1.303 (claude mcp --help), paraphrased. The JSON was validated, the Python was run with claude-agent-sdk 0.2.179 (the tool handler only), and no servers were actually added.

Running example. The shop's developers want two servers in their repository: an inventory server that runs locally against the stock database, and the company's hosted orders server. One developer also wants to try an experimental analytics server without affecting anyone else.

Three scopes

Task 2.4Where a server's configuration lives, and who gets it.

ScopeStored inReaches
local (the default)~/.claude.json, under the current project's pathOnly you, only in this project
project.mcp.json at the project root, committedEveryone who clones the repository
user~/.claude.json, top levelOnly you, in all your projects

When the same server name appears in more than one place, local beats project, which beats user (then plugin servers and claude.ai connectors). The winning entry is used whole; fields aren't merged.

Plain claude mcp add is local, not user. The exam guide describes two scopes, project and user. There's a third, local, and it's the default: a server added without --scope is stored in ~/.claude.json but only for the current project. Use --scope user for your personal servers everywhere, and --scope project to write .mcp.json. (MCP's local scope has nothing to do with .claude/settings.local.json.)

A shared .mcp.json

Task 2.4Team servers with credentials kept out of Git.

.mcp.json (project, committed) 
{
  "mcpServers": {
    "inventory": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "gear-stock-mcp"],
      "env": {
        "DB_URL": "${INVENTORY_DB_URL}"
      }
    },
    "orders": {
      "type": "http",
      "url": "https://orders.example/mcp",
      "headers": {
        "X-Api-Key": "${ORDERS_API_KEY}"
      }
    }
  }
}
  • ${VAR} is replaced with each developer's own environment variable; ${VAR:-default} supplies a fallback. Expansion works in command, args, env, url and headers.
  • An unset variable with no default doesn't stop the server from loading: the literal ${VAR} text is used and claude mcp list shows a warning. So a server that "connects but fails to authenticate" may just be missing a variable.
  • Always set "type": "http" for remote servers: an entry with a url but no type is treated as stdio.
  • As a safeguard, Anthropic credential variables such as ANTHROPIC_API_KEY expand to nothing in a remote server's url and headers, so a repository can't send your key to its server.

Adding servers from the CLI

Task 2.4claude mcp commands that produce the file above.

Adding the servers (shell) 
# stdio server, shared via .mcp.json
claude mcp add --transport stdio \
  --scope project inventory \
  --env 'DB_URL=${INVENTORY_DB_URL}' \
  -- npx -y gear-stock-mcp

# http server, shared via .mcp.json
claude mcp add --transport http \
  --scope project orders \
  https://orders.example/mcp \
  --header 'X-Api-Key: ${ORDERS_API_KEY}'

# personal experiment, all projects
claude mcp add --transport http \
  --scope user analytics \
  https://analytics.example/mcp

claude mcp list

Single quotes stop the shell expanding ${...}, so the reference itself is saved. Everything after -- is the server's own command. Other commands: claude mcp add-json (paste a JSON entry), get, remove, and login or /mcp in a session for OAuth.

Two small CLI traps. --env accepts several values, so putting the server name straight after it makes the CLI read the name as another variable; put another option in between, as above. And claude mcp remove deletes stored OAuth tokens without revoking them; run claude mcp logout first.

Approval and trust

Task 2.4Why a cloned repository's servers don't just start.

In an interactive session, Claude Code asks before it uses servers from a project's .mcp.json; claude mcp list shows them as "Pending approval" until then, and claude mcp reset-project-choices clears your answers. The settings enableAllProjectMcpServers, enabledMcpjsonServers and disabledMcpjsonServers approve or reject servers, but a repository can't approve its own: committed in .claude/settings.json, they're ignored in a folder you haven't trusted. Non-interactive runs (claude -p) and Agent SDK sessions skip the prompt, which is why CI should run only trusted repositories (task 3.6). Organizations can allow or deny servers centrally with managed settings.

Using servers in a session

Task 2.4Tools, resources and prompts from several servers at once.

PrimitiveHow it appears in Claude Code
ToolsAs mcp__<server>__<tool>, alongside built-in tools; all connected servers' tools are available together
ResourcesType @ to pick them next to files, as @server:scheme://path (for example @orders:catalog://categories); a mentioned resource is fetched and attached
PromptsAs commands: /mcp__server__prompt, listed in the / menu
  • Tool search is on by default. At the start of a session only tool names (and server instructions) load; full definitions load when needed. The exam guide's "discovered at connection time and available simultaneously" still holds, but the details now arrive on demand, and servers connect in the background, so a slow server's tools may appear after the first turn. "alwaysLoad": true on a server opts it out.
  • Output limits. A warning appears when one tool result exceeds 10,000 tokens, and results are capped at 25,000 tokens by default (MAX_MCP_OUTPUT_TOKENS changes it). MCP_TIMEOUT is the server startup timeout, not a per-call limit.
  • /mcp shows each server's status, runs OAuth sign-in, reconnects, and switches a server off for the project.

When Claude ignores your server. If Claude greps the repository instead of using your issue-tracker server, the fix is usually the server's tool descriptions: say what the tool covers that the built-ins can't (task 2.1). Exposing a catalog (issue summaries, documentation structure, database schema) as a resource also saves a series of exploratory calls.

MCP in the Agent SDK

Task 2.4External and in-process servers for your own agents.

Pass servers in mcp_servers (a dictionary keyed by name; the key becomes the mcp__key__tool prefix), or let the SDK read .mcp.json through the project setting source. For a small tool that lives in your application, an in-process server needs no subprocess:

stock_tools.py (Python, Agent SDK) 
from claude_agent_sdk import (
    ClaudeAgentOptions,
    create_sdk_mcp_server,
    tool,
)

STOCK = {"tent-2p": 14, "stove": 0}


@tool(
    "check_stock",
    "Units in stock for one gear SKU. "
    "Returns a count; 0 means sold out.",
    {"sku": str},
)
async def check_stock(args):
    sku = args["sku"]
    if sku not in STOCK:
        # tell Claude it failed, and why
        return {
            "content": [{
                "type": "text",
                "text": f"Bad SKU {sku}",
            }],
            "is_error": True,
        }
    n = STOCK[sku]
    return {"content": [{
        "type": "text",
        "text": f"{sku}: {n} in stock",
    }]}


gear = create_sdk_mcp_server(
    name="gear",
    version="1.0.0",
    tools=[check_stock],
)

options = ClaudeAgentOptions(
    # key "gear" -> mcp__gear__<tool>
    mcp_servers={"gear": gear},
    allowed_tools=[
        "mcp__gear__check_stock",
    ],
)
  • MCP tools need approval: list them in allowed_tools (or use a permission callback). acceptEdits doesn't cover them.
  • A server that fails to connect doesn't raise an exception. Check each server's status in the session's init message, or Claude may quietly carry on with built-in tools.
  • The SDK doesn't run interactive OAuth: get the token in your application and pass it in headers.

Choosing and building servers

Task 2.4Existing servers versus your own, and transports.

For a common system such as an issue tracker, an existing community or vendor server is usually the better choice: it's maintained by others and already well described. Build your own when the workflow is specific to your team (the shop's refund rules, say). The docs also warn to trust each server you install: one that fetches outside content can expose you to prompt injection.

Transports and versions. MCP's standard transports are stdio and Streamable HTTP. The older HTTP+SSE transport was replaced in the 2025-03-26 spec and is formally deprecated; Claude Code labels --transport sse deprecated and falls back to SSE automatically when an http server needs it. The current spec revision, 2026-07-28, makes MCP stateless (no initialization handshake or sessions). On the API side, the MCP connector lets the Messages API call remote MCP servers directly; it's still in beta, supports tools only (no resources or prompts), and can't reach local stdio servers.

Key takeaways

  • Scopes: local (default; ~/.claude.json, this project), project (.mcp.json, committed, team), user (~/.claude.json, all your projects). Local beats project beats user.
  • Keep secrets out of .mcp.json with ${VAR} or ${VAR:-default}; an unset variable only warns. Set "type": "http" on remote servers.
  • claude mcp add --scope project|user; project servers need approval in interactive sessions and can't approve themselves.
  • All servers' tools are available as mcp__server__tool, loaded on demand through tool search; resources via @server:..., prompts as /mcp__server__prompt. Output is capped at 25,000 tokens by default.
  • Agent SDK: mcp_servers plus allowed_tools; in-process tools with @tool and create_sdk_mcp_server; failed servers don't raise.
  • Prefer existing servers for common systems; build custom ones for team-specific workflows. SSE is deprecated in favour of Streamable HTTP.
