Overview

Task 5.5

Design human review workflows and confidence calibration.

The exam guide asks you to know four things:

  • an aggregate accuracy figure such as 97% can hide poor results on particular document types or fields;
  • stratified random sampling measures the error rate of high-confidence extractions and catches new kinds of error;
  • field-level confidence scores should be calibrated on a labelled validation set before they route review;
  • accuracy has to be checked per document type and field before high-confidence extractions are automated.

In practice it asks you to sample auto-accepted work by stratum, analyse accuracy by segment before reducing review, calibrate per-field thresholds on labelled data, and send low-confidence or contradictory documents to people in a sensible order.

Related pages: designing the extraction schema is task 4.3, and validation with feedback loops is task 4.4. Confidence-based routing of review findings is task 4.6.

An overall accuracy figure can hide a weak document type or field

Task 5.5Good on average, bad where it counts.

Take a team that extracts totals and due dates from supplier documents with Claude. Most are invoices; a few are credit notes and receipts. Two reviewers can check about 300 documents a day, out of several thousand.

In the test data behind the example, totals are extracted correctly 98.9% of the time overall. That sounds ready to automate. But almost every document is an invoice, and invoices are nearly perfect. On credit notes, which are rare, the total is wrong one time in ten, often because the sign is lost and a refund is read as a charge. The overall figure is dominated by the common case and says almost nothing about the rare one.

The same happens across fields. A document-level "correct" can average a reliable total with an unreliable due date. So accuracy has to be measured per segment, meaning each combination of document type and field, before anyone decides to review less. Claude's evaluation guidance points the same way: test sets should mirror the real mix of inputs, including edge cases, and most tasks need several success criteria rather than one number.

Calibrate, validate, route and audit, in that order

Task 5.5Calibrate, validate, route, audit.

review_calibration.py (Python)Optional 
"""Decide which extractions a person must check: per-segment accuracy, calibrated field thresholds,
routing with a priority, and a stratified audit sample of what was auto-accepted."""
import random
from collections import defaultdict

# Each field the model extracts comes back as {"value", "confidence" (0-1), "evidence"}, plus a document-level
# "conflict" flag when the source contradicts itself (two different totals, say). A labelled record adds "correct".


def calibrate(labelled: list[dict], target: float = 0.99, min_n: int = 50) -> dict:
    """Per field: the lowest confidence threshold above which the labelled set is at least `target` accurate.
    Run this first; segment_accuracy then checks each segment above these thresholds."""
    by_field = defaultdict(list)
    for r in labelled:
        by_field[r["field"]].append((r["confidence"], r["correct"]))
    thresholds = {}
    for field, rows in by_field.items():
        rows.sort(key=lambda r: -r[0])
        best, ok = None, 0
        for i, (conf, correct) in enumerate(rows, 1):   # walk down from the most confident
            ok += correct
            last_at_conf = i == len(rows) or rows[i][0] != conf
            if last_at_conf and i >= min_n and ok / i >= target:
                best = conf                              # everything at or above conf is still accurate enough
        thresholds[field] = best                         # None: no threshold meets the target, always review
    return thresholds


def segment_accuracy(labelled: list[dict], thresholds: dict, target: float = 0.99, min_n: int = 50) -> dict:
    """Accuracy per (document type, field) of what WOULD be auto-accepted. The overall figure can hide a weak segment."""
    seg = defaultdict(lambda: [0, 0])
    for r in labelled:
        t = thresholds.get(r["field"])
        if t is None or r["confidence"] < t:
            continue                                     # would go to review anyway
        s = seg[(r["doc_type"], r["field"])]
        s[0] += r["correct"]
        s[1] += 1
    return {k: {"accuracy": ok / n, "n": n, "validated": n >= min_n and ok / n >= target} for k, (ok, n) in seg.items()}


def route(doc: dict, thresholds: dict, segments: dict) -> dict:
    reasons = []
    if doc.get("conflict"):
        reasons.append("source contradicts itself")
    for field, x in doc["fields"].items():
        t = thresholds.get(field)
        if not segments.get((doc["doc_type"], field), {}).get("validated"):
            reasons.append(f"{field}: segment not validated")
        elif t is None or x["confidence"] < t:
            reasons.append(f"{field}: confidence {x['confidence']:.2f} below {t}")
    if not reasons:
        return {"route": "auto"}
    # Limited reviewers: contradictions and high-value documents first, then the least confident.
    lowest = min(x["confidence"] for x in doc["fields"].values())
    priority = 2 * bool(doc.get("conflict")) + (doc.get("amount", 0) > 5000) + (1 - lowest)
    return {"route": "review", "priority": round(priority, 2), "reasons": reasons}


def audit_sample(auto_accepted: list[dict], per_stratum: int = 20, seed: int | None = None) -> list[dict]:
    """Random sample from every document type, so rare types are checked too; reviewers label these to keep
    measuring the error rate of auto-accepted work and to spot new kinds of error."""
    rng = random.Random(seed)
    strata = defaultdict(list)
    for d in auto_accepted:
        strata[d["doc_type"]].append(d)
    return [d for docs in strata.values() for d in rng.sample(docs, min(per_stratum, len(docs)))]

The extraction itself returns, for each field, a value, a confidence between 0 and 1, and the evidence it relied on. A document-level conflict flag is set when the source contradicts itself. The four functions then answer four questions, in order: above what confidence is each field trustworthy, which segments have earned automation, which documents go to people and in what order, and how we keep checking what was let through.

Set each field's confidence threshold on labelled data

Task 5.5Thresholds set on labelled data, per field.

A confidence score is only useful once you know what it means. "0.9" from the model is a self-report, and on its own it's no more reliable than the self-reported confidence task 5.2 warns against for escalation. Calibration turns it into something measurable. Take a labelled validation set where people have marked each extracted field right or wrong. For each field, find the lowest confidence above which accuracy still meets the target.

  • Per field: due dates and totals get their own thresholds (0.95 and 0.51 in the test), because the model's confidence means different things for different fields.
  • Whole confidence levels only: the threshold is checked only after every item at a given confidence has been counted. In an early version of the example, ties were sorted correct-first, which made a half-wrong confidence level look safe.
  • Enough labels: with fewer than 50 labelled items there's no threshold, and the field is always reviewed. Ten correct answers prove nothing.
  • Recalibrate when the model, the prompt or the document mix changes.

Automate only the segments that meet the target on their own

Task 5.5Every document type and field checked before automation.

segment_accuracy measures what would actually be automated: the labelled items above each field's threshold, grouped by document type and field. A segment is validated only with enough items and accuracy at the target. Invoice totals and invoice due dates pass. Credit-note totals, at 90% even above the threshold, don't, so every credit note keeps going to a person however confident the model is. Reducing review is decided per segment, never from the overall figure.

Route unvalidated, low-confidence and contradictory documents, highest risk first

Task 5.5Who goes to a person, and who first.

A document goes to review if any of these holds:

  • a field's segment isn't validated;
  • a field's confidence is below its threshold;
  • the source is ambiguous or contradicts itself: two different totals on one invoice is a question for a person, however confident the model is about which one it picked.

Each routed document carries its reasons, so the reviewer knows what to check.

Reviewer time is limited, so the queue is ordered. Contradictions come first, then high-value documents, then the least confident. When the queue is longer than a day's capacity, what's left at the end is the lowest-risk work. Reviewers' corrections become new labelled data for the next calibration (the feedback loop in task 4.4).

Sample auto-accepted work by stratum so quiet regressions show up

Task 5.5Stratified random sampling of high-confidence output.

Once extractions are accepted without review, nobody looks at them, so nobody would notice if they got worse: a supplier changes its invoice layout, a new document type appears. audit_sample takes a random sample of auto-accepted documents every day and sends it to reviewers to label.

  • Stratified: the sample is drawn from each document type separately, so the seven receipts are all checked, not swamped by 500 invoices in a simple random sample.
  • Random within each stratum, so the measured error rate is an honest estimate for that type, and new error patterns turn up where nobody thought to look.
  • Acted on: errors found in the audit lower the segment's measured accuracy. If it falls below the target, the segment goes back to full review until it's recalibrated.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
Extraction is 98% accurate overall, so a team wants to stop reviewing. Most documents are invoices; credit notes are rare. What must they check first?
  1. A. Nothing; 98% is enough
  2. B. Accuracy per document type and field, since a rare type can be much worse
  3. C. The model’s average confidence
  4. D. The number of reviewers
Answer
B
Why
The overall figure is dominated by the common case; automation is decided per segment.
Question 2
Scenario
The model reports 0.9 confidence on a field. How should that be used for routing?
  1. A. Accept anything above 0.9
  2. B. Only after calibrating a per-field threshold on a labelled validation set
  3. C. Ignore confidence entirely
  4. D. Average it with other fields
Answer
B
Why
Raw confidence is a self-report; calibration on labelled data shows what accuracy each level really gives.
Question 3
Scenario
An invoice shows two different totals, and the model is highly confident in the one it picked. What should happen?
  1. A. Auto-accept because confidence is high
  2. B. Send it to review: a contradictory source needs a person
  3. C. Drop the document
  4. D. Retry until the totals match
Answer
B
Why
Confidence about which value was picked doesn’t resolve a contradiction in the source.
Question 4
Scenario
Auto-accepted extractions are no longer reviewed. How does the team notice if a supplier’s new layout breaks them?
  1. A. Wait for complaints
  2. B. Draw a stratified random sample of auto-accepted work each day for labelling
  3. C. Review only the largest documents
  4. D. Re-run every extraction
Answer
B
Why
Sampling each document type separately gives an honest error rate per type and surfaces new kinds of error.

Key takeaways

  • An overall accuracy figure can hide a weak document type or field; measure accuracy per segment (document type by field).
  • Have the model output field-level confidence, then calibrate per-field thresholds on a labelled validation set; without enough labels, there's no threshold.
  • Validate each segment on what would actually be automated before reducing review; unvalidated segments stay fully reviewed.
  • Route low confidence, unvalidated segments and ambiguous or contradictory sources to people, with reasons, ordered by risk to fit limited capacity.
  • Keep a stratified random audit of auto-accepted work to measure ongoing error rates and catch new error patterns; feed corrections back into calibration.
