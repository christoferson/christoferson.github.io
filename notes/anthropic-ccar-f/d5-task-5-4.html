5.4: Context in Large Codebase Exploration

Keeping a long investigation of a big repository sharp: specific questions handed to subagents, findings written to files rather than trusted to memory, phases that start from a summary, and state that survives a crash.

Overview

Task 5.4

Manage context effectively in large codebase exploration.

The exam guide asks you to know four things:

  • long sessions degrade: answers become inconsistent and drift to "typical patterns" instead of the specific classes found earlier;
  • scratchpad files keep key findings across context boundaries;
  • subagents keep verbose exploration out of the main agent, which coordinates;
  • for crash recovery, each agent exports state to a known location and the coordinator loads a manifest on resume.

In practice it asks you to spawn subagents for specific questions, keep and consult scratchpad files, summarise each phase before starting the next, build manifest-based recovery, and use /compact when discovery output fills the context.

The built-in Explore and Plan subagents are described in task 3.4. Resuming and forking sessions is task 1.7. Keeping exact facts through a long conversation is task 5.1.

Sources: the Claude Code documentation on the context window and sessions, and the Agent SDK documentation on the agent loop and structured outputs, checked on 19 November 2026 and paraphrased. The coordinator is my own and was tested with claude-agent-sdk 0.2.185 against a fake query(), including a failed run and a resume.

Running example. A developer at the outdoor-gear shop has to change how refunds work in a large, unfamiliar monorepo. First they need to know where the tests are and how a refund travels from the API to the payment provider. Then they need to know which refund steps are untested and how provider errors are handled.

How long sessions degrade

Task 5.4The symptoms of a context full of discovery output.

Exploring a codebase is mostly reading: dozens of files, long grep results, test output. All of it stays in the conversation. Two hours in, the guide's symptoms appear. The agent gives a different answer to a question it answered earlier. And instead of "RefundService.issue() calls PaymentGateway.reverse()", it says "refund services usually call a payment gateway". The specific findings are still somewhere in the context, buried under everything read since, and the answer falls back on general knowledge.

Claude's API documentation calls the general effect context rot: accuracy and recall drop as the token count grows (task 5.1). A bigger window delays it but doesn't cure it. The remedies below all reduce what the main conversation has to hold.

Questions for subagents

Task 5.4Verbose exploration in a separate context; the main agent keeps the big picture.

A subagent works in its own context window. Its file reads, searches and dead ends stay there, and only its summary (plus a small metadata trailer, in Claude Code) comes back. So the main agent hands out specific, answerable questions:

  • "Find all test files, the framework they use and how they are run."
  • "Trace the refund flow's dependencies from the API route to the payment provider."

The main agent then works with two short answers instead of the forty files behind them. A vague delegation ("look around the payments code") brings back a vague summary. A specific question brings back something the coordinator can build on.

A phased exploration

Task 5.4All four techniques in one coordinator.

explore_coordinator.py (Python, Agent SDK)Optional 
"""Explore a large codebase in phases: isolated explorers, a scratchpad of findings, and a manifest for crash recovery."""
import asyncio
import json
from pathlib import Path

from claude_agent_sdk import ClaudeAgentOptions, ResultMessage, query

STATE = Path(".explore")                  # the known location every agent's state is exported to
MANIFEST = STATE / "manifest.json"
SCRATCHPAD = STATE / "scratchpad.md"

PHASES = [
    {"tests": "Find all test files, the framework they use and how they are run.",
     "refund-flow": "Trace the refund flow's dependencies from the API route to the payment provider."},
    {"refund-gaps": "Which steps of the refund flow have no test covering them?",
     "provider-errors": "How are payment-provider errors handled at each step of the refund flow?"},
]

FINDINGS = {"type": "object", "required": ["answer", "key_files", "facts"], "properties": {
    "answer": {"type": "string"},
    "key_files": {"type": "array", "items": {"type": "string"}},
    "facts": {"type": "array", "items": {"type": "string"},
              "description": "Short facts naming the specific classes, functions and files found"},
    "open_questions": {"type": "array", "items": {"type": "string"}}}}


def load_manifest() -> dict:
    return json.loads(MANIFEST.read_text()) if MANIFEST.exists() else {"phase": 0, "agents": {}, "phase_summaries": []}


def save_manifest(m: dict):
    MANIFEST.write_text(json.dumps(m, indent=1))


def explorer_prompt(question: str, summaries: list[str]) -> str:
    earlier = "\n".join(summaries) or "None yet: this is the first phase."
    return (f"<findings_from_earlier_phases>\n{earlier}\n</findings_from_earlier_phases>\n"
            f"Question: {question}\n"
            "Answer from what you find in this repository. Name the actual classes, functions and files; "
            "don't describe what such code typically looks like.")


async def explore(name: str, question: str, summaries: list[str]) -> dict:
    options = ClaudeAgentOptions(allowed_tools=["Read", "Grep", "Glob"], disallowed_tools=["Write", "Edit", "Bash"],
                                 output_format={"type": "json_schema", "schema": FINDINGS}, max_turns=40)
    async for message in query(prompt=explorer_prompt(question, summaries), options=options):
        if isinstance(message, ResultMessage):
            if message.subtype == "success" and not message.is_error and message.structured_output:
                return message.structured_output
            raise RuntimeError(f"{name}: {message.subtype}")
    raise RuntimeError(f"{name}: no result")


def note(name: str, findings: dict):
    """Append to the scratchpad: the record the coordinator re-reads instead of trusting its memory."""
    with SCRATCHPAD.open("a") as f:
        f.write(f"\n## {name}\n" + "\n".join(f"- {x}" for x in findings["facts"])
                + f"\nKey files: {', '.join(findings['key_files'])}\n")


async def run():
    STATE.mkdir(exist_ok=True)
    m = load_manifest()                                       # on resume, finished work is skipped, not redone
    for p in range(m["phase"], len(PHASES)):
        pending = {n: q for n, q in PHASES[p].items() if m["agents"].get(n, {}).get("status") != "done"}
        results = await asyncio.gather(*(explore(n, q, m["phase_summaries"]) for n, q in pending.items()),
                                       return_exceptions=True)
        for (name, _), res in zip(pending.items(), results):
            if isinstance(res, Exception):
                m["agents"][name] = {"status": "failed", "error": str(res)}
                continue
            (STATE / f"{name}.json").write_text(json.dumps(res, indent=1))   # each agent's state exported
            note(name, res)
            m["agents"][name] = {"status": "done", "state_file": f"{name}.json"}
            save_manifest(m)                                                  # a crash after this keeps the work
        if any(m["agents"].get(n, {}).get("status") != "done" for n in PHASES[p]):
            save_manifest(m)
            raise SystemExit(f"phase {p} incomplete; fix and rerun to resume")
        # Summarise the phase before the next one starts; the summary goes into every next-phase prompt.
        m["phase_summaries"].append(f"Phase {p + 1}: " + " ".join(
            json.loads((STATE / f"{n}.json").read_text())["answer"] for n in PHASES[p]))
        m["phase"] = p + 1
        save_manifest(m)
    return SCRATCHPAD.read_text()


if __name__ == "__main__":
    print(asyncio.run(run()))
  • Each question runs in its own query() session: separate context, read-only tools, and Write, Edit and Bash explicitly blocked. The questions in a phase run in parallel. Inside an interactive session you'd get the same isolation by letting Claude spawn subagents; driving them from code makes the phases and the recovery explicit.
  • Structured findings: each explorer returns JSON with an answer, key files and short facts naming specific classes, through the SDK's output_format. The coordinator checks the result's subtype and reads structured_output; a run that hit its turn limit is recorded as failed, not silently skipped.
  • The prompt forbids generic answers: "name the actual classes, functions and files; don't describe what such code typically looks like".

Scratchpad files

Task 5.4Findings on disk, consulted instead of remembered.

Every finished explorer's facts and key files are appended to .explore/scratchpad.md. When a later question comes up ("does the provider-error path have tests?"), the agent reads the scratchpad rather than relying on something it saw two hours and a compaction ago. A file doesn't degrade, isn't summarised and survives the session.

In an interactive Claude Code session the same idea is simply an instruction: "keep a findings file in notes/refunds.md; add each key finding with its file path, and check it before answering". Claude's prompting guidance for work that spans several context windows says the same: keep state in files, structured where possible, so a fresh context can pick up from the filesystem.

Summaries between phases

Task 5.4The next phase starts from what the last one concluded.

The second-phase questions ("which refund steps have no test?") depend on the first phase's answers. The coordinator therefore summarises phase 1 when it ends and puts that summary at the top of every phase-2 prompt, in <findings_from_earlier_phases>. A phase-2 explorer starts knowing where the tests live and what the refund path is, without re-exploring either and without inheriting phase 1's transcripts. Subagents don't see the parent's history (task 1.3), so anything they need has to be in the prompt.

Manifests for crash recovery

Task 5.4Each agent's state exported; the coordinator resumes from a manifest.

  • Export to a known location: each explorer's result goes to .explore/<name>.json as soon as it finishes.
  • The manifest (.explore/manifest.json) records the current phase, each agent's status and state file, and the phase summaries. It's saved after every agent, so a crash loses at most the work in flight.
  • On resume the coordinator loads the manifest, skips agents marked done, reruns only failed or missing ones, and injects the saved phase summaries into their prompts. In the test, the provider-errors explorer hits its turn limit, the run stops, and a rerun in a fresh process calls only that one explorer.

Session resumption (task 1.7) restores a single conversation. A manifest restores a whole multi-agent job, including what the coordinator had decided between agents.

/compact and what survives it

Task 5.4Shrinking an interactive session that's full of discovery output.

In Claude Code, /compact replaces the conversation with a structured summary. Pass instructions to steer it: /compact keep the refund call chain and the list of test files. Otherwise the summary keeps what the automatic pass guesses is important. Claude Code also compacts automatically as the window fills; /autocompact sets how full it gets first, and /context shows what's using the space. /clear is the better choice when switching to unrelated work.

What survives compaction:

  • Re-injected from disk: the system prompt, the project-root CLAUDE.md and unscoped rules, auto memory, and a plan written in plan mode.
  • Re-read: up to five of the most recently modified files Claude read or edited. A file over 5,000 tokens comes back only as a path reference.
  • Summarised away: path-scoped rules and nested CLAUDE.md files (they reload only when a matching file is touched again), context added by hooks, and everything Claude read and concluded.

That's why findings belong in a file: the scratchpad is still there after compaction, when the conversation's version of them is a sentence in a summary. In the Agent SDK, compaction is automatic too. You can put "what to preserve" instructions in CLAUDE.md, run a PreCompact hook (for example to archive the transcript), or send /compact as a prompt.

Key takeaways

  • Long exploration sessions degrade: inconsistent answers, and "typical patterns" instead of the specific classes found earlier.
  • Delegate specific questions ("find all test files", "trace the refund flow") to subagents; their verbose reads stay in their own context and only a summary returns.
  • Keep key findings in scratchpad files and consult them for later questions; files survive compaction and new sessions.
  • Summarise each phase before starting the next and inject the summary into the new subagents' prompts.
  • For crash recovery, export each agent's state to a known location and keep a manifest the coordinator loads on resume. Use /compact with focus instructions when discovery output fills an interactive session.
