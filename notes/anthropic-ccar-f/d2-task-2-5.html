2.5: Built-in Tools

The file and shell tools that Claude Code and the Agent SDK give Claude out of the box: what each one is for, how to pick between them, and how to explore an unfamiliar codebase without reading all of it.

Overview

Task 2.5

Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively.

The exam guide asks you to know that Grep searches file contents and Glob matches file paths, that Read and Write work on whole files while Edit makes a targeted change by matching unique text, and what to do when Edit can't find a unique match. In practice it asks you to build understanding incrementally (search for entry points, then read and follow imports) instead of reading everything up front, including tracing usage through wrapper modules.

Sources: the Claude Code documentation (tools reference, permissions, subagents, Agent SDK agent loop) and the Claude API text editor and bash tool pages, checked on 8 November 2026 against Claude Code 2.1.303, paraphrased.

Running example. A customer reports that refunds at the shop come out too high. Nobody on call knows the refunds code, so Claude has to find where the amount is calculated in the TypeScript repository, fix it and prove the fix.

The six core tools

Task 2.5What each tool does, and its limits.

ToolDoesWorth knowing
ReadReturns a file's contents with line numbersoffset and limit for big files; up to 25,000 tokens per call; also images, PDFs (page ranges) and notebooks; can't list folders
EditReplaces an exact string in a fileold_string must match exactly, whitespace included, and appear once (or set replace_all); no regex
WriteCreates a file or overwrites it completelyNo append or merge; for partial changes, Claude uses Edit
GrepSearches file contents (built on ripgrep)Default output is matching file paths only; content mode shows lines; filter with glob or type; respects .gitignore
GlobFinds files by name patternResults sorted by modification time, capped at 100; doesn't respect .gitignore by default
BashRuns a shell commandThe working folder carries over between calls, environment variables don't; 2-minute default timeout, 10-minute maximum; long jobs can run in the background

Read, Grep and Glob run without asking inside the working folder; Edit, Write and Bash need permission (apart from a built-in set of read-only shell commands). Claude Code has many other built-in tools, such as WebFetch, WebSearch, NotebookEdit, AskUserQuestion, Skill and Agent.

Choosing a tool

Task 2.5Matching the tool to the question.

You want toUseShop example
Find files by name or extensionGlobsrc/**/*refund*.ts, every **/*.test.tsx
Find where something appears in codeGrepCallers of calculateRefund, an error message, an import
Look at a file you've locatedRead, with a range for big filesLines 40 to 70 of refunds.ts
Change a few linesEditFix one operator
Create a file or replace all of itWriteA new test file
Run somethingBashpnpm vitest run src/orders

Why the dedicated tools over cat, grep and find? The file tools need no permission prompt inside the project, give structured results (line numbers, output modes, sorting, caps), work with Read and Edit permission rules and read-before-edit tracking, and the Agent SDK can run read-only tools in parallel, while Edit, Write and Bash run one at a time. The docs don't say this in one sentence; it follows from how the tools are described.

Edit and its fallbacks

Task 2.5Making targeted changes, and recovering when the match isn't unique.

Edit checks four things: no deny rule blocks reading the file; the file has been read first (a partial view doesn't count); old_string matches exactly; and it matches exactly once.

Edit fails becauseDo this
The text appears several timesInclude more surrounding lines in old_string so it's unique, or set replace_all: true if every occurrence should change
No unique anchor exists at allRead the whole file and Write it back with the change (the exam guide's fallback)
The text isn't foundRead the file again: it changed, or the whitespace differs

The current docs suggest the first two remedies before falling back to Read and Write, since rewriting a whole file costs more and risks unrelated changes.

Exploring a codebase

Task 2.5Searching first, then reading only what matters.

Reading every file up front fills the context with code that doesn't matter. Search narrows the field, then Read follows the trail. Here's the refund investigation as the tool inputs Claude would send:

1. Glob: candidate files by name 
{
  "pattern": "src/**/*refund*.ts"
}
2. Grep: which files use the function 
{
  "pattern": "calculateRefund",
  "type": "ts",
  "output_mode": "files_with_matches"
}
3. Grep: the matching lines 
{
  "pattern": "restockingFee",
  "path": "src/orders",
  "output_mode": "content"
}
4. Read: just the relevant range 
{
  "file_path":
    "/repo/src/orders/refunds.ts",
  "offset": 40,
  "limit": 30
}
5. Edit: one unique line 
{
  "file_path":
    "/repo/src/orders/refunds.ts",
  "old_string":
    "return total + restockingFee;",
  "new_string":
    "return total - restockingFee;"
}
6. Bash: prove it with the tests 
{
  "command":
    "pnpm vitest run src/orders",
  "timeout": 300000
}

When a function is reached through a wrapper module (say src/orders/index.ts re-exports it under other names), list the names the wrapper exports, then Grep for each one, so you find every caller and not only those that use the original name. For a broad investigation, the built-in Explore subagent can do the searching in its own context and return just a summary (task 3.4).

Permissions per tool

Task 2.5How permission rules name the built-in tools.

RuleCovers
Read(./secrets/**)Read, Grep and Glob on those paths
Edit(src/**)Edit, Write and NotebookEdit
Bash(pnpm test *)Commands starting pnpm test; every part of a compound command must be allowed
WebFetch(domain:example.com)Fetches from that domain

Rules that silently never match. Write(path), Grep(path) and Glob(path) are accepted but never match anything: write Edit(...) or Read(...) instead. Rules are checked deny, then ask, then allow, and a specific allow can't override a broader deny. In paths, // is the filesystem root, while a single leading / is relative to the settings file's location, not absolute.

What changed

Task 2.5Differences between the exam guide and today's Claude Code.

The Task tool is now Agent. The tool that launches subagents was renamed from Task to Agent in Claude Code 2.1.63 (February 2026). Old Task(...) references in settings and agent definitions still work as aliases, and current SDK examples put "Agent" in allowedTools. The exam guide still says a coordinator's allowedTools must include "Task". Also note that allowedTools only pre-approves tools; to restrict which tools exist, use tools or disallowedTools.

Glob and Grep aren't always present. Since 2.1.117 (April 2026), native builds on macOS, Linux and WSL leave Glob and Grep out by default; Claude searches with find and grep through Bash, which run fast built-in replacements. They come back if you name them in --tools or --allowedTools (or the SDK options), if Bash is denied, or for a subagent that lists them without Bash. On Windows they're still default. Two smaller changes: since 2.1.228, newer models may edit a file they haven't read if reading it wouldn't need permission, and LS and MultiEdit are no longer in the tools list.

Not the same as the API tools. The Claude API's text editor tool (str_replace_based_edit_tool, with old_str and new_str) and bash tool are client tools that your application implements; the API bash tool keeps one shell alive, so environment variables persist. Claude Code's Edit and Bash are run by Claude Code itself and behave as described above.

Key takeaways

  • Glob finds files by name; Grep finds content (paths only by default, content for lines); Read views a known file (use ranges); Edit changes exact, unique text; Write creates or replaces whole files; Bash runs commands.
  • Edit not unique: add surrounding context or use replace_all; with no usable anchor, Read then Write.
  • Explore incrementally: Glob or Grep for entry points, Read the relevant ranges, follow imports, Grep each name a wrapper exports, then test with Bash.
  • Read(...) rules cover Grep and Glob; Edit(...) covers Write; Write(path), Grep(path) and Glob(path) never match. Deny wins.
  • Task was renamed Agent (2.1.63); allowedTools pre-approves, it doesn't restrict. Glob and Grep are off by default on macOS, Linux and WSL since 2.1.117.
