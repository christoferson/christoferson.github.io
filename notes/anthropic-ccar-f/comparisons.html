Agent or workflow

Domain 1. Who decides the next step. Covered in task 1.1.

OptionWho decidesChoose it when
Agent loopClaude, from each tool resultThe number and order of steps can't be predicted
Predefined workflowYour code pathsThe steps are known; you need predictability and audit
Agent plus code rulesClaude, inside limits your code enforcesFlexible work with rules that must always hold

Prompt, gate or hook

Domain 1. How strongly a rule holds. Covered in task 1.4 and task 1.5.

MechanismGuaranteeUse for
System prompt instructionProbabilistic: usually followed, occasionally notJudgement, tone, preferred order of steps
Prerequisite gate in codeDeterministic: the tool refuses until state your code set says soVerify identity before refunds; sequence that must hold
Agent SDK hookDeterministic, outside the model; deny wins in every modePolicy limits (refunds over $500), normalising results

PreToolUse or PostToolUse

Domain 1. When the hook runs decides what it can do. Covered in task 1.5.

HookRunsCan
PreToolUseBefore the tool executesAllow, deny with a reason, ask, or rewrite the input; stops side effects
PostToolUseAfter a successful callReplace what Claude sees (updatedToolOutput), add context; can't undo the action

Chaining or dynamic decomposition

Domain 1. Fixed steps or steps chosen as you go. Covered in task 1.6.

ApproachHow it worksFits
Prompt chainingFixed sequence of calls with checks between themPredictable, multi-aspect work: reviews, draft-review-refine
Dynamic decompositionPlan, act, re-plan from what each step revealsOpen-ended investigations, unfamiliar codebases
Per-file plus integration passesParallel local passes, then one cross-file passLarge multi-file reviews

OptionWhat you getChoose it when

Fresh session with a summaryClean context seeded with findings and decisionsEarlier tool results are stale
