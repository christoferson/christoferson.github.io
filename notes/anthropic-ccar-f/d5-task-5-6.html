5.6: Provenance and Uncertainty in Synthesis

Combining many sources without losing track of who said what: claims that carry their source and excerpt all the way to the report, dates that keep old figures from looking like contradictions, and disagreements shown rather than quietly settled.

Overview

Task 5.6

Preserve information provenance and handle uncertainty in multi-source synthesis.

The exam guide asks you to know four things:

  • attribution is lost when summarisation compresses findings without keeping the claim-source mapping;
  • the synthesis agent must preserve and merge those mappings;
  • conflicting statistics from credible sources are annotated with their sources rather than settled by picking one;
  • publication and collection dates stop differences over time from being read as contradictions.

In practice it asks you to:

  • have subagents output claim-source mappings (URLs, document names, excerpts) and dates;
  • finish the analysis with conflicts included and annotated, so the coordinator decides how to reconcile them;
  • separate well-established from contested findings, keeping each source's own wording and method;
  • render financial data as tables, news as prose and technical findings as lists.

This page follows on from two earlier tasks. Structured, metadata-rich outputs between agents are task 5.1, and coverage gaps from unavailable sources are task 5.3.

Sources: the exam guide for the synthesis principles; Claude's Citations documentation for the mechanism, checked on 19 November 2026 and paraphrased. The code is my own and was tested with anthropic 2.10.0 against a mocked API.

Running example. The outdoor-gear shop's research system has subagents read a market report, a trade survey, a gear-testing lab's write-up and a news article before a buyer decides whether to stock more ultralight tents.

How attribution gets lost

Task 5.6Each summarising step drops a little of "according to whom".

A subagent reads the market report and writes "ultralight tents have about 18% of the market". The coordinator condenses four such summaries into a paragraph, and the synthesis step condenses that into "ultralight is about 15% of the market". By the end, nobody can say where 15% came from. It's actually an average of two sources that disagree. Nor can anyone tell that one figure was a survey estimate and the other a retailer panel count.

The fix is to stop passing prose. Every claim travels as a record that keeps its source, its supporting excerpt, its date and its method. Later steps are told to merge these records, never to rewrite them into unattributed text.

Claim-source mappings from citations

Task 5.6Subagents return claims with the exact supporting passage.

source_agent.py (Python, anthropic SDK)Optional 
"""A subagent that analyses one source with Citations enabled and returns claim-source mappings.
Citations can't be combined with structured outputs (400), so the structure is built from the citation blocks."""
import json

import anthropic

client = anthropic.Anthropic()

ASK = """List each claim this source makes about ultralight tents, one per line, in the form
kind | metric | value | period | claim
kind is financial, news or technical; metric, value and period may be "-" if the claim has none.
Cite the source for every line. Report the source's own wording and qualifiers ("estimated", "survey of 200")."""


def analyse(source: dict) -> list[dict]:
    """source: {"name", "url", "text", "published", "collected", "method"}"""
    meta = {k: source[k] for k in ("url", "published", "collected", "method")}
    response = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=3000,
        messages=[{"role": "user", "content": [
            {"type": "document", "source": {"type": "text", "media_type": "text/plain", "data": source["text"]},
             "title": source["name"], "context": json.dumps(meta),       # metadata the model sees but never cites
             "citations": {"enabled": True}},
            {"type": "text", "text": ASK}]}],
    )
    # Rebuild lines from text blocks in order, collecting each line's citations as we go.
    lines, text, cites = [], "", []
    for block in (b for b in response.content if b.type == "text"):
        *finished, rest = block.text.split("\n")
        for part in finished:                        # each newline closes the current line
            lines.append((text + part, cites))
            text, cites = "", []
        text += rest
        cites += [c.cited_text for c in (block.citations or [])]   # a block's citations go with the line it ends on
    lines.append((text, cites))

    claims = []
    for line, excerpts in lines:
        fields = [f.strip() for f in line.split("|")]
        if len(fields) != 5 or not excerpts:         # an uncited line is not a claim we can use
            continue
        kind, metric, value, period, claim = [None if f == "-" else f for f in fields]
        claims.append({"kind": kind, "metric": metric, "value": value, "period": period, "claim": claim,
                       "source": source["name"], "excerpts": excerpts, **meta})
    return claims
  • Citations on the document: with "citations": {"enabled": true}, each cited part of Claude's answer comes back as a text block with a citations list. For a plain-text document, each citation gives the cited_text, the document's index and title, and the start and end character positions.
  • Why not ask for quotes in the prompt: the API extracts cited_text itself, so citations are guaranteed to point into the documents provided. Anthropic's evaluations also found them significantly more likely to pick the most relevant passage than prompt-based quoting. And cited_text doesn't count toward output tokens.
  • Metadata through context: a document's title and context are shown to the model but never cited. Here context carries the URL, publication date, collection period and method as JSON.
  • No structured outputs here: citations and structured outputs can't be combined in one request; the API returns a 400. So the subagent asks for one claim per line and builds the record in code. Each line's citations become its excerpts, and a line with no citation is dropped.

Dates and changes over time

Task 5.69% and 18% can both be true.

One source says ultralight tents have 9% of the market and another says 18%. That's a contradiction only if both describe the same period. If the 9% is from a 2024 survey and the 18% from 2026, it's growth, and the more interesting finding. Without dates in the records, the synthesis can't tell the difference and may average the two or call the sources unreliable.

So every claim carries the period its data was collected in, and the publication date. The merge compares values only within the same metric and period. Values from different periods go into a "changes over time" section instead.

Conflicting figures

Task 5.6Annotate the conflict; don't pick a winner.

merge_claims.py (Python)Optional 
"""Merge claim-source mappings from several subagents without losing attribution, separate settled from
contested findings, and render each kind of content in a form that suits it."""
from collections import defaultdict


def merge(claims: list[dict]) -> dict:
    by_metric, other = defaultdict(list), []
    for c in claims:
        (by_metric[c["metric"]] if c["metric"] else other).append(c)
    established, contested, trends = [], [], []
    for metric, cs in by_metric.items():
        periods = defaultdict(list)
        for c in cs:
            periods[c["period"]].append(c)
        for period, same in periods.items():
            if len({c["value"] for c in same}) > 1:
                contested.append({"metric": metric, "period": period, "values": same})   # every value, every source
            else:
                established.append({"metric": metric, "period": period, "value": same[0]["value"], "sources": same})
        if len(periods) > 1:                       # different periods: a change over time, not a contradiction
            trends.append({"metric": metric, "points": sorted(            # a contested period shows all its values
                ((p, " or ".join(sorted({c["value"] for c in cs_})), ", ".join(sorted({c["source"] for c in cs_})))
                 for p, cs_ in periods.items()), key=lambda x: str(x[0]))})
    return {"established": established, "contested": contested, "trends": trends, "other": other}


def cite(c: dict) -> str:
    return f"[{c['source']}, {c['published']}, {c['method']}]"


def render(m: dict) -> str:
    out = ["## Established findings"]
    fin = [e for e in m["established"] if e["sources"][0]["kind"] == "financial"]
    if fin:                                        # financial data: a table
        out += ["| Metric | Period | Value | Sources |", "|---|---|---|---|"]
        out += [f"| {e['metric']} | {e['period']} | {e['value']} | {'; '.join(cite(c) for c in e['sources'])} |" for e in fin]
    out += [f"- {c['claim']} {cite(c)}" for c in m["other"] if c["kind"] == "technical"]   # technical: a list
    out += ["## Contested findings"]
    for x in m["contested"]:                       # never pick one: show each value with who says it and how
        out.append(f"- {x['metric']} ({x['period']}): " + "; ".join(
            f"{c['value']} according to {cite(c)}, \"{c['excerpts'][0]}\"" for c in x["values"]))
    if m["trends"]:
        out += ["## Changes over time"]
        out += [f"- {t['metric']}: " + ", then ".join(f"{v} in {p} ({s})" for p, v, s in t["points"]) for t in m["trends"]]
    news = [c for c in m["other"] if c["kind"] == "news"]
    if news:                                       # news: prose that keeps each outlet's own characterisation
        out += ["## In the news", " ".join(f"{c['claim']} {cite(c)}" for c in news)]
    return "\n".join(out)
  • Same metric, same period, different values is a real conflict: 18% from a buyer survey and 12% from a retailer panel for the first quarter of 2026. Both sources are credible, and the difference probably comes from how each measured.
  • Keep both: merge records every value with its source, method and excerpt under contested. Choosing the higher, the newer or the first one found would present a guess as a fact.
  • Annotate, then let the coordinator decide: the analysis finishes with the conflict included and labelled. The coordinator then chooses how to handle it: ask a subagent to check both methods, prefer one source for a stated reason, or pass the disagreement through to the reader. A subagent that quietly resolves a conflict takes that decision away from the agent with the wider view.

Established vs contested, by content type

Task 5.6Report structure that shows how solid each finding is.

render builds the report in explicit sections:

  • Established findings: values no source disputes, each with its sources.
  • Contested findings: every value, who reported it, how they measured it, and the excerpt.
  • Changes over time: the trend, with each point's source.

Each source's own characterisation survives: "an estimated 18%", "according to unnamed sources". These qualifiers tell the reader how much weight to give a claim, and summarising tends to strip them first.

Each kind of content is also shown in a form that suits it, rather than everything as bullet points:

  • Financial figures go in a table of metric, period, value and sources, so they can be compared.
  • News is short prose that keeps the outlet's framing.
  • Technical findings ("silnylon sags when wet") are a structured list.

Key takeaways

  • Summarising findings as prose loses attribution; pass claims as records with source, URL or document name, excerpt, date and method, and have every later step preserve and merge them.
  • The Citations API returns the exact supporting passage with guaranteed-valid document pointers, and cited_text doesn't count toward output tokens. It can't be combined with structured outputs (400), so build records from the citation blocks.
  • Require publication and collection dates, so a 2024 figure and a 2026 figure read as a change over time, not a contradiction.
  • When credible sources conflict on the same metric and period, keep every value with its attribution and method; the coordinator decides how to reconcile, never an arbitrary pick.
  • Report established and contested findings in separate sections, keep sources' own qualifiers, and render financial data as tables, news as prose and technical findings as lists.
