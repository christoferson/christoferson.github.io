EventBridge event patterns

Patterns match on any field of the event. Values in a list are ORed; separate fields are ANDed. The // comments are annotations only: JSON doesn't allow comments, so remove them before use.

A CodePipeline execution failed

Use whenNotifying the team or opening a ticket when any pipeline fails.

{
  "source": ["aws.codepipeline"],
  "detail-type": ["CodePipeline Pipeline Execution State Change"],
  "detail": {
    "state": ["FAILED"],
    "pipeline": ["orders-pipeline"]        // remove to match every pipeline
  }
}

Watch forStage-level and action-level events have their own detail types (... Stage Execution State Change, ... Action Execution State Change).

High-severity GuardDuty finding

Use whenPaging on-call or starting automated containment.

{
  "source": ["aws.guardduty"],
  "detail-type": ["GuardDuty Finding"],
  "detail": {
    "severity": [{ "numeric": [">=", 7] }]    // high (7.0-8.9) and critical (9.0-10.0)
  }
}

Watch forIn a multi-account setup, create the rule in the GuardDuty administrator account, which receives every member's findings.

A resource became noncompliant in AWS Config

Use whenTriggering remediation or notifying the owner.

{
  "source": ["aws.config"],
  "detail-type": ["Config Rules Compliance Change"],
  "detail": {
    "configRuleName": ["restricted-ssh"],
    "newEvaluationResult": {
      "complianceType": ["NON_COMPLIANT"]
    }
  }
}

A specific API call, from CloudTrail

Use whenReacting within seconds to a sensitive change, such as opening a security group.

{
  "source": ["aws.ec2"],
  "detail-type": ["AWS API Call via CloudTrail"],
  "detail": {
    "eventSource": ["ec2.amazonaws.com"],
    "eventName": ["AuthorizeSecurityGroupIngress"]
  }
}

Watch forNeeds a CloudTrail trail. Events arrive only on the default bus in the Region of the call (us-east-1 for IAM). Read-only calls need the rule state ENABLED_WITH_ALL_CLOUDTRAIL_MANAGEMENT_EVENTS.

An exposed access key (AWS Health)

Use whenAutomatically deactivating keys AWS has found in public code.

{
  "source": ["aws.health"],
  "detail-type": ["AWS Health Event"],
  "detail": {
    "service": ["RISK"],
    "eventTypeCode": ["AWS_RISK_CREDENTIALS_EXPOSED"]
  }
}

Auto Scaling failed to launch an instance

Use whenAlerting on capacity, quota or launch template problems.

{
  "source": ["aws.autoscaling"],
  "detail-type": ["EC2 Instance Launch Unsuccessful"],
  "detail": {
    "AutoScalingGroupName": ["web-asg"]
  }
}

An ECS task stopped unexpectedly

Use whenCatching crashes and out-of-memory kills.

{
  "source": ["aws.ecs"],
  "detail-type": ["ECS Task State Change"],
  "detail": {
    "lastStatus": ["STOPPED"],
    "stopCode": [{ "anything-but": "UserInitiated" }],   // ignore deliberate stops
    "clusterArn": ["arn:aws:ecs:us-east-1:222222222222:cluster/prod"]
  }
}

IAM trust policies

A trust policy (AssumeRolePolicyDocument) says who may assume a role. What the role can do is in its separate permissions policies.

Another account's role (cross-account)

Use whenA pipeline in the tooling account 111111111111 deploys into this account.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { AWS: arn:aws:iam::111111111111:role/PipelineServiceRole }
      Action: sts:AssumeRole

Watch forThe caller also needs sts:AssumeRole on this role's ARN in its own permissions. Both sides must allow.

An AWS service

Use whenCloudFormation, CodeBuild, Lambda or EC2 acts with this role.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { Service: cloudformation.amazonaws.com }   # codebuild, lambda, ec2, ecs-tasks...
      Action: sts:AssumeRole
      Condition:
        StringEquals: { aws:SourceAccount: "222222222222" }    # confused-deputy protection

Watch forECS tasks use ecs-tasks.amazonaws.com, not ecs.amazonaws.com.

A third party, with an external ID

Use whenA SaaS vendor (monitoring, cost tools) needs access to your account.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { AWS: arn:aws:iam::444444444444:root }
      Action: sts:AssumeRole
      Condition:
        StringEquals: { sts:ExternalId: acme-7f3c91 }

GitHub Actions through OIDC

Use whenAn external CI system deploys without stored access keys.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { Federated: arn:aws:iam::222222222222:oidc-provider/token.actions.githubusercontent.com }
      Action: sts:AssumeRoleWithWebIdentity
      Condition:
        StringEquals:
          token.actions.githubusercontent.com:aud: sts.amazonaws.com
          token.actions.githubusercontent.com:sub: repo:acme/orders:ref:refs/heads/main

Watch forWithout the sub condition, any GitHub repository could assume the role.

Any role in the organization

Use whenA shared role (for example, read-only audit) should be assumable from every account in the organization without listing them.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { AWS: "*" }
      Action: sts:AssumeRole
      Condition:
        StringEquals: { aws:PrincipalOrgID: o-a1b2c3d4e5 }
        ArnLike: { aws:PrincipalArn: "arn:aws:iam::*:role/SecurityAudit*" }

Watch for"Principal": "*" is only safe with conditions like these; Access Analyzer flags it otherwise.

CloudFormation resource policies

Attributes on a resource that control what happens when it's created, updated, replaced or deleted.

Keep data when a resource is deleted or replaced

Use whenDatabases, buckets and volumes must survive stack deletion or an update that replaces them.

OrdersDb:
  Type: AWS::RDS::DBInstance
  DeletionPolicy: Snapshot            # on stack delete or removal from template: Delete | Retain | RetainExceptOnCreate | Snapshot
  UpdateReplacePolicy: Snapshot       # when an update replaces it with a new resource
  Properties:
    ...

Watch forSnapshot works only on resources that support snapshots (RDS, EBS volumes, ElastiCache, Redshift, Neptune, DocumentDB). S3 buckets use Retain.

Wait for instances to finish bootstrapping

Use whenThe stack should succeed only after the application on new instances is actually running.

WebAsg:
  Type: AWS::AutoScaling::AutoScalingGroup
  CreationPolicy:
    ResourceSignal:
      Count: 2                         # signals needed
      Timeout: PT15M                    # fail (and roll back) if not received
  Properties:
    ...

# at the end of the instance user data:
# /opt/aws/bin/cfn-signal -e $? --stack ${AWS::StackName} --resource WebAsg --region ${AWS::Region}

Watch for"Stack times out waiting for signals" means the user data failed, cfn-signal isn't installed, or the instance can't reach the CloudFormation endpoint.

Roll out a new launch template to an Auto Scaling group

Use whenUpdating instances gradually during a stack update, keeping capacity.

WebAsg:
  Type: AWS::AutoScaling::AutoScalingGroup
  UpdatePolicy:
    AutoScalingRollingUpdate:          # replace instances in batches
      MinInstancesInService: 2
      MaxBatchSize: 1
      PauseTime: PT10M
      WaitOnResourceSignals: true      # each new instance must cfn-signal
    # or AutoScalingReplacingUpdate: { WillReplace: true }  -- a whole new group, then swap (fast rollback)

Watch forRolling updates in place batch by batch; replacing creates a new group and deletes the old one only on success, so rollback is quick.

Protect critical resources from updates (stack policy)

Use whenNobody should replace or delete the production database through a stack update by accident.

{
  "Statement": [
    { "Effect": "Allow", "Principal": "*", "Action": "Update:*", "Resource": "*" },
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": ["Update:Replace", "Update:Delete"],
      "Resource": "LogicalResourceId/OrdersDb"
    }
  ]
}

Watch forOnce a stack policy exists, anything not explicitly allowed is denied, so include the allow-all statement. Termination protection is separate: it blocks deleting the whole stack.
