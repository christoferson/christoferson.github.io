Overview

Task statement 6.2

Apply automation for security controls and data protection.

This task is about choosing the right control for a threat and then making sure it's applied everywhere, automatically, including in accounts created next month. Typical scenarios: "block SQL injection on the public ALB in every account", "certificates keep expiring", "find S3 objects containing credit card numbers across 200 accounts", or "encrypt an existing unencrypted RDS database".

Network security components

Knowledge

Security groups and network ACLs

Security groupNetwork ACL
Applies toA network interface (instance, task, Lambda in a VPC, endpoint, load balancer)A whole subnet
StateStateful: replies are allowed automaticallyStateless: replies need their own rule (ephemeral ports 1024–65535)
RulesAllow onlyAllow and deny, evaluated in number order, first match wins
SourceCIDR, prefix list, or another security groupCIDR only
Typical useMain access control between tiersBlocking a specific IP range at the subnet edge; a coarse second layer

Referencing security groups instead of IP addresses keeps rules valid as instances scale. This allows only the ALB to reach the application on port 8080:

AppSecurityGroup:
  Type: AWS::EC2::SecurityGroup
  Properties:
    GroupDescription: App tier
    VpcId: !Ref Vpc
    SecurityGroupIngress:
      - IpProtocol: tcp
        FromPort: 8080
        ToPort: 8080
        SourceSecurityGroupId: !Ref AlbSecurityGroup   # only from the load balancer
  • Routing as a control: private subnets have no route to an internet gateway. Gateway endpoints (S3, DynamoDB) and interface endpoints (PrivateLink) let them reach AWS services without the internet, and endpoint policies limit what can be reached.
  • Admin access: Session Manager replaces SSH and bastion hosts, so no inbound port 22 is needed.

"Block traffic from a specific malicious IP address" needs a deny: a network ACL rule at the subnet, or an AWS WAF IP set for HTTP traffic. Security groups can't deny.

A new outbound NACL rule set that forgets the ephemeral port range breaks return traffic, because NACLs are stateless. "Connections time out after adding NACL rules" usually means this.

Knowledge

AWS Network Firewall

A managed, stateful firewall for VPC traffic, including traffic that isn't HTTP. It sits in its own subnet, and route tables send traffic through its endpoints.

  • Stateless rule groups: fast 5-tuple filtering (source, destination, ports, protocol).
  • Stateful rule groups: Suricata-compatible rules, domain lists (allow only .amazonaws.com and github.com outbound), and AWS managed threat signatures.
  • TLS inspection: optional decryption of outbound or inbound TLS, using a certificate you provide through ACM.
  • Centralized inspection: one inspection VPC attached to a Transit Gateway inspects traffic between VPCs and to the internet for many accounts.
  • Logs: alert and flow logs to CloudWatch Logs, S3 or Data Firehose.

"Allow outbound internet access only to approved domains" or "inspect east-west traffic between VPCs" is Network Firewall. Security groups and NACLs can't filter by domain name.

Knowledge

AWS WAF and AWS Shield

AWS WAF filters HTTP(S) requests at layer 7. A web ACL contains rules and attaches to CloudFront, an ALB, an API Gateway REST API, AppSync, a Cognito user pool, App Runner or Verified Access. It can't attach to a Network Load Balancer.

waf-web-acl.yaml 
WebAcl:
  Type: AWS::WAFv2::WebACL
  Properties:
    Scope: REGIONAL                     # CLOUDFRONT for distributions (created in us-east-1)
    DefaultAction: { Allow: {} }
    VisibilityConfig:
      SampledRequestsEnabled: true
      CloudWatchMetricsEnabled: true
      MetricName: orders-acl
    Rules:
      - Name: CommonRules
        Priority: 0
        OverrideAction:   # use Count: {} to test a rule group first
          None: {}
        Statement:
          ManagedRuleGroupStatement:
            VendorName: AWS
            Name: AWSManagedRulesCommonRuleSet
        VisibilityConfig:
          SampledRequestsEnabled: true
          CloudWatchMetricsEnabled: true
          MetricName: common
      - Name: SqlInjection
        Priority: 1
        OverrideAction: { None: {} }
        Statement:
          ManagedRuleGroupStatement:
            VendorName: AWS
            Name: AWSManagedRulesSQLiRuleSet
        VisibilityConfig:
          SampledRequestsEnabled: true
          CloudWatchMetricsEnabled: true
          MetricName: sqli
      - Name: RateLimitPerIp
        Priority: 2
        Action: { Block: {} }
        Statement:
          RateBasedStatement:   # requests per 5 minutes
            Limit: 2000
            AggregateKeyType: IP
        VisibilityConfig:
          SampledRequestsEnabled: true
          CloudWatchMetricsEnabled: true
          MetricName: rate

WebAclAssociation:
  Type: AWS::WAFv2::WebACLAssociation
  Properties:
    ResourceArn: !Ref PublicAlb
    WebACLArn: !GetAtt WebAcl.Arn
  • Other rule types: IP sets, geo match, Bot Control, account takeover prevention, CAPTCHA and challenge.
  • WAF logs go to CloudWatch Logs, S3 or Data Firehose (log group names must start with aws-waf-logs-).
Shield StandardShield Advanced
CostFree, automatic for every accountMonthly subscription per organization, plus data transfer
Protects againstCommon layer 3 and 4 attacks (SYN floods, UDP reflection)Larger and layer 7 attacks on CloudFront, Route 53, Global Accelerator, ELB and Elastic IPs
ExtrasNoneShield Response Team (SRT) support, cost protection for scaling during an attack, automatic layer 7 mitigation through WAF, health-based detection, attack visibility

"Get help from AWS during a DDoS attack" or "credits for scaling costs caused by a DDoS attack" is Shield Advanced. "Block SQL injection or cross-site scripting" is AWS WAF.

Certificates and public key infrastructure

Knowledge

A TLS certificate binds a domain name to a public key, signed by a certificate authority (CA) that clients trust. Public CAs are trusted by browsers; a private CA is trusted only by systems you configure, which is enough for internal services and mutual TLS.

ServiceWhat it does
AWS Certificate Manager (ACM)Issues free public certificates and renews them automatically. Deploys them to integrated services: ELB, CloudFront, API Gateway, App Runner. Can also import third-party certificates.
AWS Private CARuns your own private CA hierarchy (root and subordinate CAs). Issues private certificates for internal endpoints, devices, mTLS clients and IAM Roles Anywhere.
ACM with Private CAACM requests and auto-renews private certificates from your Private CA for integrated services.

Renewal

Certificate typeRenewal
ACM public, DNS validatedAutomatic, as long as the validation CNAME record stays in DNS and the certificate is in use
ACM public, email validatedSomeone must approve the renewal email
ACM private (from Private CA)Automatic
ImportedNever automatic: you import the new certificate yourself
certificate.yaml 
SiteCertificate:
  Type: AWS::CertificateManager::Certificate
  Properties:
    DomainName: shop.example.com
    SubjectAlternativeNames: [ www.shop.example.com ]
    ValidationMethod: DNS
    DomainValidationOptions:
      - DomainName: shop.example.com
        HostedZoneId: Z0123456789ABCDEF     # CloudFormation creates the validation record in Route 53

To catch expiring certificates (mostly imported ones):

  1. ACM emits expiration eventsDaily "ACM Certificate Approaching Expiration" events to EventBridge, starting 45 days before expiry (the number of days is configurable).
  2. AWS Config checks every accountThe managed rule acm-certificate-expiration-check marks certificates expiring within a set number of days as noncompliant.
  3. An EventBridge rule notifies or actsSends to SNS, opens an OpsItem, or starts automation that imports a renewed certificate.

A certificate for CloudFront must be in us-east-1. Certificates for ALBs and API Gateway regional endpoints must be in the same Region as the resource. ACM certificates can't be copied between Regions; request one per Region.

"Internal microservices must authenticate each other with certificates" is mutual TLS with certificates from AWS Private CA. ALB and API Gateway custom domains support mTLS with a trust store of your CA certificates.

Data management

Knowledge

Protect data according to how sensitive it is: classify it first, then apply encryption, key controls and access controls to match.

  1. ClassifyDefine levels (public, internal, confidential, restricted) and tag resources, for example data-classification=confidential. Macie finds data that is sensitive but not labelled as such.
  2. EncryptAt rest with KMS keys, in transit with TLS. Restricted data may need customer managed keys or CloudHSM.
  3. Control keysKey policies decide who can use and manage each key. Separate key administrators from key users.
  4. Control accessIAM and resource policies, S3 Block Public Access, ABAC on the classification tag, VPC endpoint conditions.
  5. Retain and protectBackups, versioning, S3 Object Lock for immutable records, lifecycle rules for deletion.

KMS key types

Key typeWho controls itNotes
AWS owned keyAWS, shared across accountsDefault for many services. Not visible to you, no audit trail of its use.
AWS managed key (aws/s3, aws/ebs)AWS, in your accountVisible and logged in CloudTrail. You can't change the key policy, so it can't be shared across accounts. Rotated every year.
Customer managed keyYouYour own key policy, grants, rotation schedule, cross-account use, and disabling or deletion
  • Key policy: every KMS key has one, and it's the primary control. IAM policies only work for a key if the key policy allows the account (the default "Principal": {"AWS": "arn:aws:iam::<account>:root"} statement does that).
  • Grants: temporary, programmatic permission for a service to use a key (EBS and RDS use them).
  • Rotation: automatic rotation for customer managed keys, every 90 to 2,560 days (365 by default), plus on-demand rotation. The key ID stays the same and old data still decrypts.
  • Multi-Region keys: related keys with the same key material in several Regions, so data encrypted in one Region can be decrypted in another (DR, global tables).
  • Deletion: scheduled with a 7 to 30 day waiting period. Disable the key first and watch CloudTrail for failed uses.
kms-key.yaml 
DataKey:
  Type: AWS::KMS::Key
  Properties:
    EnableKeyRotation: true
    KeyPolicy:
      Version: "2012-10-17"
      Statement:
        - Sid: AccountRootCanManageViaIam
          Effect: Allow
          Principal:
            AWS: arn:aws:iam::222222222222:root
          Action: kms:*
          Resource: "*"
        - Sid: KeyAdministrators                       # manage the key, can't use it
          Effect: Allow
          Principal:
            AWS: arn:aws:iam::222222222222:role/KeyAdminRole
          Action: [ kms:Describe*, kms:Put*, kms:Enable*, kms:Disable*, kms:ScheduleKeyDeletion, kms:CancelKeyDeletion, kms:TagResource ]
          Resource: "*"
        - Sid: KeyUsersThroughS3Only                   # use the key, only via S3
          Effect: Allow
          Principal:
            AWS: arn:aws:iam::222222222222:role/OrdersAppRole
          Action: [ kms:Encrypt, kms:Decrypt, kms:GenerateDataKey* ]
          Resource: "*"
          Condition:
            StringEquals:
              kms:ViaService: s3.us-east-1.amazonaws.com

Sharing encrypted snapshots, AMIs or S3 objects across accounts fails with an AWS managed key. Re-encrypt with a customer managed key and grant the other account in its key policy.

Automating security controls in multi-account and multi-Region environments

Skill

The pattern is the same for every service: enable it from the organization, give one security account delegated administrator rights, turn it on in all accounts and Regions automatically (including new ones), and aggregate findings in one place.

ServiceWhat it automates
AWS OrganizationsSCPs, RCPs and declarative policies applied to OUs; trusted access and delegated administrators for security services
AWS Control TowerA governed landing zone: log archive and audit accounts, Account Factory, and controls turned on per OU
AWS Security HubSecurity standards checked in every account, findings aggregated across accounts and Regions, automation rules
AWS Firewall ManagerWAF web ACLs, security group policies, Network Firewall, Shield Advanced and DNS Firewall applied across accounts, including new resources
AWS ConfigOrganization-wide rules and conformance packs, with automatic remediation through Systems Manager Automation
AWS Systems ManagerPatching (patch policies through Quick Setup), State Manager configuration, Automation runbooks across accounts and Regions, Session Manager

Control Tower controls

Control behaviorImplemented withExample
Preventive: stops the actionSCPs or RCPsDisallow changes to the log archive bucket
Detective: reports noncomplianceAWS Config rulesDetect S3 buckets without public access blocked
Proactive: blocks a noncompliant resource before CloudFormation creates itCloudFormation hooksRequire encryption on new RDS instances

Controls are also grouped as mandatory (always on), strongly recommended and elective. Account customizations beyond controls use Account Factory for Terraform (AFT), Customizations for Control Tower (CfCT) or account blueprints.

Security Hub across the organization

AWS now calls the posture-checking part of the service (standards and controls) Security Hub CSPM, alongside a newer Security Hub experience that correlates findings across GuardDuty, Inspector, Macie and posture checks. Exam questions describe the standards and controls features below.

Assume the security account 555555555555 is the delegated administrator, and the home Region is us-east-1.

  1. Delegate administrationFrom the management account, make 555555555555 the Security Hub delegated administrator.
  2. Use central configurationIn 555555555555, create a configuration policy: enable Security Hub, the AWS Foundational Security Best Practices and CIS standards, and disable controls you don't need.
  3. Associate the policy with targetsApply it to the organization root or to OUs, in every chosen Region. New accounts inherit it.
  4. Aggregate RegionsLink all Regions to us-east-1 so one console shows every finding.
  5. Automate responsesAutomation rules update or suppress findings; EventBridge rules on Security Hub Findings - Imported start remediation.
  • Security Hub controls rely on AWS Config being enabled and recording in each account and Region.
  • Findings use the AWS Security Finding Format (ASFF) and include GuardDuty, Inspector, Macie, IAM Access Analyzer, Firewall Manager and partner products.

Firewall Manager

Prerequisites: AWS Organizations, a Firewall Manager administrator account, and AWS Config enabled in every account. A Firewall Manager policy then says, for example, "every ALB tagged public=true in the Workloads OU gets this WAF web ACL", and it applies to new accounts and new ALBs automatically.

"Ensure every new ALB in every account gets the company WAF rules" is Firewall Manager. Deploying a web ACL with StackSets covers today's ALBs but not ones created later.

"Enable a security service in all existing and future accounts and Regions with the least effort" is always delegated administrator + organization auto-enable, not a script that loops over accounts.

Combining security controls for defense in depth

Skill

Defense in depth means several independent layers, so a gap in one is caught by another. Follow a request to a public web application, from the internet to the data:

  1. Edge
  2. CloudFront with ACM certificateTLS from the user; Shield Standard (or Advanced) absorbs DDoS traffic.
  3. AWS WAFBlocks SQL injection, cross-site scripting, bad bots and floods from one IP.
  4. Network
  5. Network ACLSubnet-level allow and deny by CIDR.
  6. Network FirewallInspects traffic between VPCs and filters outbound traffic by domain.
  7. Security groupsOnly the ALB can reach the app; only the app can reach the database.
  8. Compute and identity
  9. Hardened, patched instancesInspector finds vulnerabilities, Patch Manager fixes them, IMDSv2 protects role credentials.
  10. Least-privilege rolesThe application's role can only touch its own table and secret.
  11. Data
  12. Encryption and key policiesKMS encryption at rest, TLS to the database, Macie checks S3 for exposed sensitive data.
  13. Detection and response
  14. GuardDuty, Config, Security Hub, DetectiveDetect threats and misconfigurations, aggregate findings, investigate root cause.
  15. Automated remediationEventBridge and Systems Manager Automation isolate instances, revoke access or fix configuration.
ServiceKind of controlAnswers
AWS Config rulesDetective (configuration)Is this resource configured correctly?
Amazon GuardDutyDetective (threats)Is something malicious happening (compromised credentials, crypto mining, unusual API calls)?
Amazon InspectorDetective (vulnerabilities)Which instances, images and functions have known CVEs or open network paths?
Amazon DetectiveInvestigativeWhat led to this finding, and what else did this principal or IP do?
Security HubAggregation and postureWhat's our overall posture across all accounts?
WAF, Shield, Network Firewall, security groups, NACLsPreventive (network)Should this traffic be allowed?
ACM, KMSPreventive (data)Is the data protected if traffic or storage is exposed?

When several answers each add one control, prefer the one that adds a missing layer (for example, WAF in front of an ALB that only has security groups) over one that duplicates an existing layer.

Automating the discovery of sensitive data at scale

Skill

Amazon Macie finds sensitive data (personal data, financial data, credentials) in S3 using machine learning and pattern matching. It also reports bucket-level risks such as public or unencrypted buckets.

FeatureWhat it does
Automated sensitive data discoveryContinuously samples objects across all buckets and gives each bucket a sensitivity score. The low-effort, organization-wide option.
Sensitive data discovery jobsOne-time or scheduled full scans of chosen buckets, for complete coverage of specific data
Managed data identifiersBuilt-in detectors: credit card numbers, passport numbers, AWS secret keys, names, addresses
Custom data identifiersYour own regex plus keywords, for example employee IDs like EMP-\d{6}
Allow listsText or patterns to ignore (test card numbers, a company's public address)

At scale:

  1. Delegate administrationMake the security account the Macie delegated administrator for the organization.
  2. Auto-enable member accountsMacie is turned on for existing and new accounts. It's a Regional service, so repeat for each Region in use.
  3. Turn on automated discoverySampling covers every bucket; add scheduled jobs for buckets that need full scans.
  4. Store resultsDetailed discovery results go to an S3 bucket encrypted with a KMS key.
  5. Act on findingsFindings go to Security Hub and EventBridge. A rule can notify the data owner, tag the object, or start a Lambda function that moves or locks it down.
aws macie2 create-classification-job \
  --job-type SCHEDULED \
  --schedule-frequency-details '{"weeklySchedule":{"dayOfWeek":"SUNDAY"}}' \
  --name weekly-customer-exports \
  --s3-job-definition '{"bucketDefinitions":[{"accountId":"222222222222","buckets":["customer-exports"]}]}' \
  --custom-data-identifier-ids 1a2b3c4d-employee-id

Macie scans S3 only. "Find personal data in RDS or DynamoDB" isn't Macie (unless the data is exported to S3). And Macie finds sensitive data; it doesn't encrypt or block it, so pair it with EventBridge automation.

KMS or CloudHSM

AWS KMSAWS CloudHSM
TenancyMulti-tenant managed serviceSingle-tenant HSMs in your VPC; only you have access to the keys
IntegrationBuilt into almost every AWS serviceThrough standard APIs (PKCS#11, JCE, OpenSSL); KMS can use it as a custom key store
OperationsFully managed, highly availableYou manage users and keys, and run at least two HSMs in different AZs for availability
Choose whenThe default for encryption at restRegulations require dedicated HSMs or exclusive key control; Oracle TDE; SSL offload; custom cryptography

For keys held entirely outside AWS, KMS also supports an external key store (XKS), and imported key material lets you bring your own key material into a KMS key.

In transit

  • Public endpoints: ACM certificates on CloudFront, ALB, NLB TLS listeners and API Gateway, with a modern TLS security policy. Redirect HTTP to HTTPS on the ALB, and use viewer protocol policy redirect-to-https on CloudFront.
  • End to end: if traffic must stay encrypted to the instance, use HTTPS target groups (ALB re-encrypts) or TCP pass-through on an NLB, with certificates on the targets (Private CA).
  • Databases: require TLS, for example the RDS PostgreSQL parameter rds.force_ssl = 1, and connect with the RDS CA bundle.
  • AWS APIs and S3: deny non-TLS requests with aws:SecureTransport.
  • Hybrid: Site-to-Site VPN (IPsec), or MACsec on dedicated Direct Connect connections.

"Encrypt an existing unencrypted RDS database with minimal effort" is snapshot, copy with encryption, restore, then switch the application endpoint. There's no "enable encryption" option on a running instance.

"Must use FIPS-validated, single-tenant hardware that AWS cannot access" points to CloudHSM, not KMS. Without the single-tenant or exclusive-control requirement, KMS with a customer managed key is the simpler answer.

Key takeaways

  • Security groups: stateful, allow only, can reference other groups. NACLs: stateless, ordered allow and deny by subnet (remember ephemeral ports). Network Firewall: domain filtering and deep inspection, centrally through Transit Gateway.
  • WAF for layer 7 attacks and rate limiting on CloudFront, ALB and API Gateway (not NLB). Shield Advanced for SRT help, cost protection and advanced DDoS mitigation.
  • ACM public certificates auto-renew when DNS validated; imported certificates don't. Watch expiry with EventBridge events and the Config rule. CloudFront certificates live in us-east-1. Private CA for internal certificates and mTLS.
  • Classify with tags and Macie; customer managed KMS keys for control and cross-account sharing; separate key admins from key users; rotation and multi-Region keys.
  • Scale controls with delegated administrators and auto-enable: Security Hub central configuration and Region aggregation, Control Tower controls (preventive SCPs, detective Config rules, proactive hooks), Firewall Manager for WAF and security groups on future resources, Config conformance packs, Systems Manager patch policies.
  • Defense in depth: edge, network, compute, identity, data and detection layers; pick answers that close a missing layer.
  • Macie: S3 only; automated discovery for organization-wide coverage, jobs for full scans, custom identifiers and allow lists; act on findings with EventBridge.
  • Encrypt existing EBS and RDS through encrypted snapshot copies; enforce TLS and the right KMS key with bucket policies; CloudHSM only for single-tenant or exclusive-control requirements.
