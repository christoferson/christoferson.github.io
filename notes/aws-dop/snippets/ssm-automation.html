Systems Manager Automation runbooks

Multi-step operations written as documents: call AWS APIs, wait for resources, run commands on instances, pause for approval and branch on results, then run the same runbook across many resources, accounts and Regions. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

An Automation runbook is an SSM document with schemaVersion: '0.3'. Its mainSteps run in order, each step running one action such as aws:executeAwsApi or aws:runCommand. Steps pass values to later steps through outputs, referenced as {{ stepName.outputName }}.

A custom runbook: stop, snapshot, start

Use whenAn operation needs several API calls in order, waiting between them, such as taking a consistent snapshot of a stopped instance.

SnapshotStoppedInstance.yaml 
description: Stop an instance, snapshot its root volume, start it again
schemaVersion: '0.3'
assumeRole: '{{ AutomationAssumeRole }}'
parameters:
  AutomationAssumeRole:
    type: String
  InstanceId:
    type: String
mainSteps:
  - name: getRootVolume
    action: aws:executeAwsApi
    inputs:
      Service: ec2
      Api: DescribeInstances
      InstanceIds:
        - '{{ InstanceId }}'
    outputs:
      - Name: volumeId
        Selector: $.Reservations[0].Instances[0].BlockDeviceMappings[0].Ebs.VolumeId
        Type: String

  - name: stopInstance
    action: aws:executeAwsApi
    inputs:
      Service: ec2
      Api: StopInstances
      InstanceIds:
        - '{{ InstanceId }}'

  - name: waitUntilStopped   # polls until the value matches
    action: aws:waitForAwsResourceProperty
    timeoutSeconds: 600
    inputs:
      Service: ec2
      Api: DescribeInstances
      InstanceIds:
        - '{{ InstanceId }}'
      PropertySelector: $.Reservations[0].Instances[0].State.Name
      DesiredValues:
        - stopped

  - name: snapshot
    action: aws:executeAwsApi
    inputs:
      Service: ec2
      Api: CreateSnapshot
      VolumeId: '{{ getRootVolume.volumeId }}'
      Description: 'Taken by automation {{ automation:EXECUTION_ID }}'
    outputs:
      - Name: snapshotId
        Selector: $.SnapshotId
        Type: String

  - name: startInstance
    action: aws:executeAwsApi
    inputs:
      Service: ec2
      Api: StartInstances
      InstanceIds:
        - '{{ InstanceId }}'

  - name: checkRunning   # fails at once if the value doesn't match
    action: aws:assertAwsResourceProperty
    inputs:
      Service: ec2
      Api: DescribeInstances
      InstanceIds:
        - '{{ InstanceId }}'
      PropertySelector: $.Reservations[0].Instances[0].State.Name
      DesiredValues:
        - pending
        - running
outputs:
  - snapshot.snapshotId

Watch forService and Api use the Boto3 names (ec2, DescribeInstances), and every other input is passed straight to that API. waitForAwsResourceProperty keeps polling until the timeout; assertAwsResourceProperty checks once and fails the step if the value doesn't match.

Run a command on the instance

Use whenA step must run inside the operating system, such as restarting a service or collecting logs, between API calls.

- name: restartApp
  action: aws:runCommand
  timeoutSeconds: 300
  inputs:
    DocumentName: AWS-RunShellScript   # AWS-RunPowerShellScript on Windows
    InstanceIds:
      - '{{ InstanceId }}'
    Parameters:
      commands:
        - systemctl restart orders
        - systemctl is-active orders

Watch forThe instance must be a managed node: SSM Agent running, an instance profile with AmazonSSMManagedInstanceCore, and network access to the Systems Manager endpoints. A non-zero exit code fails the step.

Pause for approval

Use whenA person must confirm before a disruptive step, such as stopping a production instance.

- name: approveStop
  action: aws:approve
  timeoutSeconds: 3600   # default 7 days, maximum 30 days
  onFailure: Abort
  inputs:
    NotificationArn: arn:aws:sns:us-east-1:222222222222:AutomationApprovals
    Message: 'Approve stopping {{ InstanceId }} for a snapshot'
    MinRequiredApprovals: 1
    Approvers:
      - arn:aws:iam::222222222222:role/OpsLead

Watch forThe SNS topic name must start with Automation. Approvers (up to 10) approve or reject in the Systems Manager console while the execution shows Waiting. aws:approve isn't supported in multi-account and multi-Region runs.

Run a Python script

Use whenA step needs logic that a single API call can't express, such as filtering or combining results.

- name: findOldSnapshots
  action: aws:executeScript
  inputs:
    Runtime: python3.11
    Handler: handler   # function name; takes (events, context)
    InputPayload:
      volumeId: '{{ getRootVolume.volumeId }}'
      keep: 7
    Script: |-
      import boto3

      def handler(events, context):
          ec2 = boto3.client("ec2")
          snaps = ec2.describe_snapshots(
              Filters=[{"Name": "volume-id", "Values": [events["volumeId"]]}]
          )["Snapshots"]
          snaps.sort(key=lambda s: s["StartTime"], reverse=True)
          old = [s["SnapshotId"] for s in snaps[events["keep"]:]]
          return {"oldSnapshots": old, "count": len(old)}
  outputs:
    - Name: oldSnapshots
      Selector: $.Payload.oldSnapshots   # the returned value is under $.Payload
      Type: StringList
    - Name: count
      Selector: $.Payload.count
      Type: Integer

Watch forA script step runs for at most 10 minutes, and API calls inside it use the runbook's assume role. Unlike aws:executeAwsApi, it doesn't retry throttled calls automatically. Raising an exception fails the step.

Branch and handle failure

Use whenThe next step depends on a parameter or an earlier output, or a failure must trigger cleanup instead of stopping.

- name: chooseAction
  action: aws:branch
  inputs:
    Choices:
      - NextStep: deleteOldSnapshots
        Variable: '{{ findOldSnapshots.count }}'
        NumericGreater: 0
    Default: done   # no choice matched

- name: deleteOldSnapshots
  action: aws:executeScript
  maxAttempts: 3   # retry the step before it counts as failed
  onFailure: step:notifyFailure   # Abort (default), Continue, or step:name
  onCancel: step:notifyFailure
  nextStep: done
  inputs:
    Runtime: python3.11
    Handler: handler
    InputPayload:
      ids: '{{ findOldSnapshots.oldSnapshots }}'
    Script: |-
      import boto3
      def handler(events, context):
          ec2 = boto3.client("ec2")
          for snap_id in events["ids"]:
              ec2.delete_snapshot(SnapshotId=snap_id)

- name: notifyFailure
  action: aws:executeAwsApi
  isEnd: true   # stop here after notifying
  inputs:
    Service: sns
    Api: Publish
    TopicArn: arn:aws:sns:us-east-1:222222222222:ops-alerts
    Message: 'Snapshot cleanup failed: {{ automation:EXECUTION_ID }}'

- name: done
  action: aws:sleep
  isEnd: true
  inputs:
    Duration: PT1S

Watch forWithout nextStep, steps run in file order, so the failure handler needs isEnd: true or the normal path would fall into it. aws:branch also supports And, Or and Not, and string, numeric and Boolean comparisons.

The Automation service role

Use whenA runbook must run with fixed permissions instead of the caller's, for example when EventBridge, Config or a maintenance window starts it.

AutomationServiceRole:
  Type: AWS::IAM::Role
  Properties:
    RoleName: SnapshotAutomationRole
    AssumeRolePolicyDocument:
      Version: "2012-10-17"
      Statement:
        - Effect: Allow
          Principal:
            Service: ssm.amazonaws.com
          Action: sts:AssumeRole
          Condition:
            StringEquals:
              aws:SourceAccount: !Ref AWS::AccountId
    ManagedPolicyArns:
      - arn:aws:iam::aws:policy/service-role/AmazonSSMAutomationRole
    Policies:
      - PolicyName: snapshot-actions
        PolicyDocument:
          Version: "2012-10-17"
          Statement:
            - Effect: Allow
              Action:
                - ec2:DescribeInstances
                - ec2:StopInstances
                - ec2:StartInstances
                - ec2:CreateSnapshot
              Resource: "*"

Watch forWhoever starts the runbook with this role needs iam:PassRole on it. If AutomationAssumeRole is left empty, the runbook runs with the caller's permissions.

Run across many resources

Use whenThe same runbook must run on every instance with a tag, a few at a time, stopping if too many fail.

aws ssm start-automation-execution \
  --document-name SnapshotStoppedInstance \
  --parameters AutomationAssumeRole=arn:aws:iam::222222222222:role/SnapshotAutomationRole \
  --target-parameter-name InstanceId \
  --targets Key=tag:Env,Values=prod \
  --max-concurrency 10% \
  --max-errors 2
# InstanceId is filled in from each matching instance
# 10% run at once; stop starting new ones after 2 failures

Watch for--target-parameter-name names the runbook parameter that receives each target. Targets can also be a resource group (Key=ResourceGroup) or explicit values (Key=ParameterValues).

Run in many accounts and Regions

Use whenA central operations account runs one runbook in every account of an OU and several Regions.

aws ssm start-automation-execution \
  --document-name AWS-RestartEC2Instance \
  --parameters AutomationAssumeRole=arn:aws:iam::555555555555:role/AWS-SystemsManager-AutomationAdministrationRole \
  --target-parameter-name InstanceId \
  --targets Key=tag:Env,Values=prod \
  --target-locations '[{
      "Accounts": ["ou-ab12-cdef3456"],
      "IncludeChildOrganizationUnits": true,
      "Regions": ["us-east-1", "eu-west-1"],
      "ExecutionRoleName": "AWS-SystemsManager-AutomationExecutionRole",
      "TargetLocationMaxConcurrency": "2",
      "TargetLocationMaxErrors": "1"
  }]'
  • AWS-SystemsManager-AutomationAdministrationRole lives in the central account; the caller needs iam:PassRole on it.
  • AWS-SystemsManager-AutomationExecutionRole must exist in every target account (deploy it with a StackSet).
  • Targeting OUs works only from the management account or a Systems Manager delegated administrator.

Watch forA custom runbook must be shared with the target accounts before it can run there. The central execution's step outputs are the IDs of the child executions in each account and Region.

Start from EventBridge or Config

Use whenA runbook should run automatically when something happens (an event) or when a resource becomes noncompliant.

EventBridge rule target 
Targets:
  - Id: snapshot-on-tag
    Arn: !Sub arn:aws:ssm:${AWS::Region}:${AWS::AccountId}:automation-definition/SnapshotStoppedInstance:$DEFAULT
    RoleArn: !GetAtt EventsToSsmRole.Arn   # may start automation and pass the role
    InputTransformer:
      InputPathsMap:
        instance: $.detail.instance-id
      InputTemplate: |
        {
          "InstanceId": ["<instance>"],
          "AutomationAssumeRole": ["arn:aws:iam::222222222222:role/SnapshotAutomationRole"]
        }
AWS Config remediation 
EncryptBucketRemediation:
  Type: AWS::Config::RemediationConfiguration
  Properties:
    ConfigRuleName: s3-bucket-server-side-encryption-enabled
    TargetType: SSM_DOCUMENT
    TargetId: AWS-EnableS3BucketEncryption
    Automatic: true
    MaximumAutomaticAttempts: 3
    RetryAttemptSeconds: 60
    Parameters:
      BucketName:
        ResourceValue:
          Value: RESOURCE_ID   # the noncompliant bucket
      AutomationAssumeRole:
        StaticValue:
          Values:
            - !GetAtt RemediationRole.Arn

Watch forRunbook parameters are passed as lists in the EventBridge input. The EventBridge role needs ssm:StartAutomationExecution plus iam:PassRole on the runbook's assume role.

AWS-owned runbooks

Use whenA common operation already has a runbook maintained by AWS; use it before writing your own.

RunbookWhat it does
AWS-RestartEC2Instance, AWS-StopEC2Instance, AWS-StartEC2InstanceRestart, stop or start instances
AWS-CreateImageCreate an AMI from an instance
AWS-UpdateLinuxAmi, AWS-UpdateWindowsAmiLaunch from a source AMI, patch it, and create a new AMI (a "golden AMI" pipeline)
AWS-PatchInstanceWithRollbackPatch an instance and restore its root volume if patching fails
AWS-ResizeInstanceChange an instance's type
AWSSupport-ExecuteEC2RescueDiagnose and fix an unreachable instance with EC2Rescue
AWSSupport-ContainEC2InstanceIsolate an instance for incident response
AWSConfigRemediation-*Fix common Config rule findings, for example AWSConfigRemediation-EnforceEC2InstanceIMDSv2

Watch forAWS-owned runbooks still run with your permissions or your assume role, so that role needs every permission the runbook's steps use.
