Config rules and remediation

Rules that check resource configuration after deployment, the automation that fixes what they find, and the ways to roll both out to a whole organization. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

AWS Config records each resource's configuration as it changes. A rule evaluates those records and marks each resource COMPLIANT or NON_COMPLIANT. Rules detect; they don't prevent. A remediation attached to a rule runs a Systems Manager Automation document to fix noncompliant resources. Every rule needs the configuration recorder to be recording the resource types it checks.

Managed rule on configuration changes

Use whenAn AWS-written check exists for the requirement, such as "every S3 bucket has versioning".

s3-versioning-rule.yaml 
S3VersioningRule:
  Type: AWS::Config::ConfigRule
  Properties:
    ConfigRuleName: s3-bucket-versioning-enabled
    Source:
      Owner: AWS
      SourceIdentifier: S3_BUCKET_VERSIONING_ENABLED   # the identifier, not the rule name
    Scope:
      ComplianceResourceTypes:
        - AWS::S3::Bucket
    InputParameters:
      isMfaDeleteEnabled: "false"   # optional rule parameter

Watch forThe SourceIdentifier can differ from the rule's documented name: the rule restricted-ssh has the identifier INCOMING_SSH_DISABLED. Configuration-change rules evaluate within minutes of a change.

Periodic managed rule

Use whenThe check depends on time passing rather than on a configuration change, such as access key age.

AccessKeysRotatedRule:
  Type: AWS::Config::ConfigRule
  Properties:
    ConfigRuleName: access-keys-rotated
    Source:
      Owner: AWS
      SourceIdentifier: ACCESS_KEYS_ROTATED
    MaximumExecutionFrequency: TwentyFour_Hours   # One_Hour ... TwentyFour_Hours
    InputParameters:
      maxAccessKeyAge: "90"   # days

Watch forRules on global IAM resources only need to run in one Region; deploying them everywhere repeats the same evaluations. The rule ignores root user access keys.

Custom rule written in Guard

Use whenNo managed rule fits, and the check is a condition on the configuration item that needs no code.

EncryptedVolumesRule:
  Type: AWS::Config::ConfigRule
  Properties:
    ConfigRuleName: ebs-volumes-encrypted
    Scope:
      ComplianceResourceTypes:
        - AWS::EC2::Volume
    Source:
      Owner: CUSTOM_POLICY
      SourceDetails:
        - EventSource: aws.config
          MessageType: ConfigurationItemChangeNotification
      CustomPolicyDetails:
        PolicyRuntime: guard-2.x.x
        PolicyText: |
          rule volume_encrypted when resourceType == "AWS::EC2::Volume" {
            configuration.encrypted == true
          }

Watch forThe Guard rule checks the configuration item Config recorded (fields under configuration), not a CloudFormation template. EnableDebugLogDelivery: true sends evaluation details to CloudWatch Logs while you develop the rule.

Custom rule backed by Lambda

Use whenThe check needs logic or a lookup that Guard can't express, such as calling another API.

lambda-rule.yaml 
ConfigCanInvoke:
  Type: AWS::Lambda::Permission
  Properties:
    FunctionName: !GetAtt TagCheckFunction.Arn
    Action: lambda:InvokeFunction
    Principal: config.amazonaws.com
    SourceAccount: !Ref AWS::AccountId

RequiredTagRule:
  Type: AWS::Config::ConfigRule
  DependsOn: ConfigCanInvoke
  Properties:
    ConfigRuleName: instances-have-owner-tag
    Scope:
      ComplianceResourceTypes:
        - AWS::EC2::Instance
    Source:
      Owner: CUSTOM_LAMBDA
      SourceIdentifier: !GetAtt TagCheckFunction.Arn
      SourceDetails:
        - EventSource: aws.config
          MessageType: ConfigurationItemChangeNotification
tag_check.py 
import json
import boto3

config = boto3.client("config")

def handler(event, context):
    item = json.loads(event["invokingEvent"])["configurationItem"]
    tags = item.get("tags") or {}
    compliant = "Owner" in tags

    # report the result back to Config
    config.put_evaluations(
        Evaluations=[{
            "ComplianceResourceType": item["resourceType"],
            "ComplianceResourceId": item["resourceId"],
            "ComplianceType": "COMPLIANT" if compliant else "NON_COMPLIANT",
            "Annotation": "Owner tag present" if compliant else "Missing Owner tag",
            "OrderingTimestamp": item["configurationItemCaptureTime"],
        }],
        ResultToken=event["resultToken"],
    )

Watch forThe function must call put_evaluations with the event's resultToken; Config doesn't read the return value. The function's role needs config:PutEvaluations.

Automatic remediation

Use whenA noncompliant resource should be fixed without a person acting, such as turning versioning back on.

S3VersioningRemediation:
  Type: AWS::Config::RemediationConfiguration
  Properties:
    ConfigRuleName: !Ref S3VersioningRule
    TargetType: SSM_DOCUMENT
    TargetId: AWS-ConfigureS3BucketVersioning   # AWS-owned Automation runbook
    Parameters:
      BucketName:
        ResourceValue:
          Value: RESOURCE_ID   # filled with the noncompliant bucket
      VersioningState:
        StaticValue:
          Values:
            - Enabled
      AutomationAssumeRole:
        StaticValue:
          Values:
            - !GetAtt RemediationRole.Arn
    Automatic: true
    MaximumAutomaticAttempts: 5   # default 5, up to 25
    RetryAttemptSeconds: 60   # default 60

Watch forIf the attempts all fail within RetryAttemptSeconds, Config adds a remediation exception for that resource and stops retrying. The AutomationAssumeRole needs a trust policy for ssm.amazonaws.com and the permissions the runbook uses (here s3:PutBucketVersioning).

Rule for the whole organization

Use whenThe same rule must exist in every member account, including accounts created later.

OrgAccessKeysRotated:
  Type: AWS::Config::OrganizationConfigRule
  Properties:
    OrganizationConfigRuleName: org-access-keys-rotated
    OrganizationManagedRuleMetadata:
      RuleIdentifier: ACCESS_KEYS_ROTATED
      InputParameters: '{"maxAccessKeyAge":"90"}'   # a JSON string here
      MaximumExecutionFrequency: TwentyFour_Hours
    ExcludedAccounts:
      - "999999999999"   # for example a sandbox account

Watch forOnly the management account or a delegated administrator can create organization rules; register the delegate for config-multiaccountsetup.amazonaws.com. Member accounts can't change or delete the rule. Config must already be recording in each account.

Conformance pack

Use whenA set of rules and their remediations should be deployed and reported on as one unit, such as a compliance framework.

SecurityBaselinePack:
  Type: AWS::Config::OrganizationConformancePack
  Properties:
    OrganizationConformancePackName: security-baseline
    TemplateS3Uri: s3://examplecorp-config/security-baseline.yaml
    ExcludedAccounts:
      - "999999999999"

Watch forThe pack template contains ordinary AWS::Config::ConfigRule and AWS::Config::RemediationConfiguration resources. AWS publishes sample packs (for example CIS and NIST mappings). For one account, use AWS::Config::ConformancePack instead.

Aggregator and advanced query

Use whenOne account needs to see configuration and compliance across all accounts and Regions.

OrgAggregator:
  Type: AWS::Config::ConfigurationAggregator
  Properties:
    ConfigurationAggregatorName: org-aggregator
    OrganizationAggregationSource:
      RoleArn: !GetAtt AggregatorRole.Arn   # AWSConfigRoleForOrganizations policy
      AllAwsRegions: true
# find unencrypted EBS volumes in every account
aws configservice select-aggregate-resource-config \
  --configuration-aggregator-name org-aggregator \
  --expression "SELECT accountId, awsRegion, resourceId
                WHERE resourceType = 'AWS::EC2::Volume'
                AND configuration.encrypted = false"

Watch forAn aggregator only reads: it collects data but doesn't deploy rules. Deploy rules with organization rules, conformance packs or StackSets.
