Logs Insights and Athena queries

Queries for troubleshooting and investigation: Logs Insights over recent logs in CloudWatch Logs, Athena over long histories in S3. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

Use Logs Insights for interactive queries over recent data already in CloudWatch Logs; you pay per GB scanned in the chosen time range. Use Athena for SQL over logs stored in S3 (CloudTrail, ALB, VPC Flow Logs) across months or years; partitions keep the scanned data, and the cost, small.

CloudWatch Logs Insights

Top errors by message

Use whenAn alarm fired and you want the most frequent errors in the time window.

fields @timestamp, @message
| filter @message like /ERROR/
| stats count(*) as errors by @message
| sort errors desc
| limit 20

Watch forMessages that contain IDs or timestamps are all unique, so each counts once. Group by a stable field instead (for example errorType in JSON logs, or a value extracted with parse).

Latency percentiles per route

Use whenFinding which API route is slow, from JSON logs with route and latencyMs fields.

# JSON fields are discovered automatically
filter ispresent(latencyMs)
| stats pct(latencyMs, 50) as p50,
        pct(latencyMs, 99) as p99,
        count(*) as requests
        by route, bin(5m)
| sort p99 desc

Watch forAverages hide slow outliers; use p99 (or p95) for latency questions. bin(5m) buckets results into 5-minute intervals so you can see when it started.

Lambda cold starts and memory

Use whenDeciding whether a function needs provisioned concurrency or more memory.

# every invocation writes one REPORT line
filter @type = "REPORT"
| stats count(*) as invocations,
        count(@initDuration) as coldStarts,
        max(@initDuration) as maxInitMs,
        max(@maxMemoryUsed / 1000 / 1000) as maxUsedMB,
        max(@memorySize / 1000 / 1000) as allocatedMB
        by bin(1h)

Watch for@initDuration appears only on cold starts, so counting it counts cold starts. Many cold starts with long init times point to provisioned concurrency (or SnapStart); used memory near the allocation points to more memory.

Parse a plain-text log line

Use whenLogs aren't JSON, for example 2026-10-30T08:00:01Z level=WARN user=alice action=checkout.

# glob: each * becomes a field, in order
parse @message "level=* user=* action=*" as level, user, action
| filter level = "WARN"
| stats count(*) as warnings by user, action
| sort warnings desc

# or a regular expression with named groups
# parse @message /level=(?<level>\w+) user=(?<user>\S+)/

Watch forFields created by parse exist only for this query. To alarm on them, use a metric filter instead; Logs Insights is for investigation, not alerting.

CloudTrail: access denied by principal

Use whenA trail delivers to CloudWatch Logs and you want to know who is hitting permission errors.

fields userIdentity.arn, eventSource, eventName, errorCode
| filter errorCode like /AccessDenied|UnauthorizedOperation/
| stats count(*) as denied by userIdentity.arn, eventName
| sort denied desc
| limit 20

Watch forError codes vary by service (AccessDenied, AccessDeniedException, Client.UnauthorizedOperation), so match a pattern, not one exact value. A sudden burst from one principal can mean stolen credentials probing permissions.

VPC Flow Logs: top rejected sources

Use whenChecking whether a connection problem is a security group or network ACL, or who is scanning you.

# default-format flow logs: fields are discovered automatically
filter action = "REJECT"
| stats count(*) as rejects by srcAddr, dstAddr, dstPort
| sort rejects desc
| limit 20

Watch forRejected inbound traffic but accepted replies (or the reverse) points to a network ACL, which is stateless. Flow logs record metadata only, never packet contents.

Athena

CloudTrail table with partition projection

Use whenQuerying a trail's S3 logs for one account and Region without adding partitions by hand.

-- a subset of columns; the JSON SerDe ignores fields you leave out
CREATE EXTERNAL TABLE cloudtrail_logs_pp (
  useridentity STRUCT<
    type: STRING, principalid: STRING, arn: STRING,
    accountid: STRING, accesskeyid: STRING, username: STRING>,
  eventtime STRING,
  eventsource STRING,
  eventname STRING,
  awsregion STRING,
  sourceipaddress STRING,
  useragent STRING,
  errorcode STRING,
  errormessage STRING,
  requestparameters STRING,
  readonly STRING,
  recipientaccountid STRING
)
PARTITIONED BY (`timestamp` STRING)
ROW FORMAT SERDE 'org.apache.hive.hcatalog.data.JsonSerDe'
STORED AS INPUTFORMAT 'com.amazon.emr.cloudtrail.CloudTrailInputFormat'
OUTPUTFORMAT 'org.apache.hadoop.hive.ql.io.HiveIgnoreKeyTextOutputFormat'
LOCATION 's3://org-cloudtrail-logs/AWSLogs/222222222222/CloudTrail/us-east-1'
TBLPROPERTIES (
  'projection.enabled' = 'true',
  'projection.timestamp.type' = 'date',
  'projection.timestamp.format' = 'yyyy/MM/dd',
  'projection.timestamp.range' = '2025/01/01,NOW',
  'projection.timestamp.interval' = '1',
  'projection.timestamp.interval.unit' = 'DAYS',
  -- where each day's files live
  'storage.location.template' = 's3://org-cloudtrail-logs/AWSLogs/222222222222/CloudTrail/us-east-1/${timestamp}'
)

Watch forPartition projection works out partitions from the table properties, so you never run ALTER TABLE ADD PARTITION or a crawler. An organization trail adds the organization ID to the path (AWSLogs/o-.../<account>/...); project account and Region as extra partitions to query them all.

Everything one access key did

Use whenInvestigating an exposed or compromised access key.

SELECT eventtime, eventsource, eventname,
       awsregion, sourceipaddress, errorcode
FROM cloudtrail_logs_pp
WHERE useridentity.accesskeyid = 'AKIAEXAMPLEKEY123456'
  -- filter on the partition so Athena reads only 7 days of files
  AND "timestamp" >= date_format(current_date - interval '7' day, '%Y/%m/%d')
ORDER BY eventtime;

Watch forAlways filter on the partition column. Without it Athena scans every file in the trail, which is slow and expensive. Repeat for every Region the key could have used.

ALB 5xx errors by target

Use whenFinding out whether 5xx errors come from one bad target or from the load balancer itself (table alb_access_logs from the Athena docs).

SELECT target_ip, target_port,
       elb_status_code, target_status_code,
       count(*) AS requests
FROM alb_access_logs
WHERE elb_status_code >= 500
GROUP BY target_ip, target_port, elb_status_code, target_status_code
ORDER BY requests DESC
LIMIT 20;

Watch forA 5xx with target_status_code of - was generated by the load balancer: 502 (bad response from the target), 503 (no healthy targets) or 504 (target timed out). Errors concentrated on one target_ip point to one unhealthy instance.

VPC Flow Logs: rejects by port

Use whenFlow logs go to S3 and you need weeks of history (table vpc_flow_logs from the Athena docs).

SELECT dstport, protocol, count(*) AS rejects
FROM vpc_flow_logs
WHERE action = 'REJECT'
GROUP BY dstport, protocol
ORDER BY rejects DESC
LIMIT 20;
-- protocol 6 = TCP, 17 = UDP

Watch forFlow logs to S3 can use Parquet and Hive-compatible prefixes, which make Athena queries much cheaper. Steady rejects on 22 or 3389 from many sources are scans; one source and one port is usually a misconfigured rule.
