AppSpec files

The file that tells CodeDeploy what to deploy and which scripts or functions to run at each lifecycle event, for EC2 and on-premises servers, ECS and Lambda. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

The AppSpec file (appspec.yml, or appspec.yaml for ECS and Lambda) is part of the deployment revision. On EC2 and on-premises, hooks run scripts on the instance; on ECS and Lambda, hooks run Lambda functions.

EC2 and on-premises AppSpec

Use whenDeploying an application bundle to instances that run the CodeDeploy agent, in place or blue/green.

appspec.yml (root of the revision) 
version: 0.0
os: linux                                    # or windows
files:
  - source: /app                           # path inside the revision
    destination: /opt/orders                # path on the instance
permissions:
  - object: /opt/orders
    owner: orders
    group: orders
    mode: 750
    type: [ directory ]
hooks:
  ApplicationStop:                          # runs the script from the PREVIOUS revision
    - location: scripts/stop.sh
      timeout: 60
      runas: root
  BeforeInstall:
    - location: scripts/install_deps.sh
      timeout: 300
      runas: root
  AfterInstall:
    - location: scripts/configure.sh
      timeout: 120
      runas: orders
  ApplicationStart:
    - location: scripts/start.sh
      timeout: 60
      runas: orders
  ValidateService:                          # fail here and the deployment fails (and can roll back)
    - location: scripts/health_check.sh
      timeout: 120
      runas: orders

Watch forversion is always 0.0. A broken ApplicationStop script in the currently deployed revision makes every new deployment fail; fix it by deploying with "ignore ApplicationStop failures" or removing the old script. A script that exceeds its timeout fails the event.

In-place hook order behind a load balancer

Use whenDeciding which hook a script belongs in. Steps marked CodeDeploy are run by CodeDeploy itself and can't run scripts.

  1. BeforeBlockTrafficYour scriptBefore the instance is taken out of the load balancer.
  2. BlockTrafficCodeDeployDeregisters the instance and waits for connection draining.
  3. AfterBlockTrafficYour scriptThe instance no longer receives traffic.
  4. ApplicationStopYour scriptStops the running app, using the previous revision's script.
  5. DownloadBundleCodeDeployThe agent copies the revision to a temporary folder.
  6. BeforeInstallYour scriptBack up, install dependencies, decrypt files.
  7. InstallCodeDeployCopies files to their destinations from the files section.
  8. AfterInstallYour scriptConfigure the app, change permissions.
  9. ApplicationStartYour scriptStart the services.
  10. ValidateServiceYour scriptCheck that the new version works.
  11. BeforeAllowTrafficYour scriptLast chance before traffic returns.
  12. AllowTrafficCodeDeployRegisters the instance with the load balancer again.
  13. AfterAllowTrafficYour scriptThe instance is serving traffic again.

Watch forWithout a load balancer, the three block-traffic and three allow-traffic events are skipped. A deployment stuck at BlockTraffic or AllowTraffic usually means long deregistration delay or failing target group health checks.

ECS blue/green AppSpec

Use whenCodeDeploy shifts traffic from the current (blue) task set to a new (green) one behind an ALB or NLB.

appspec.yaml 
version: 0.0
Resources:
  - TargetService:
      Type: AWS::ECS::Service
      Properties:
        TaskDefinition: <TASK_DEFINITION>      # CodePipeline's CodeDeployToECS action fills this in
        LoadBalancerInfo:
          ContainerName: orders                # must match the task definition
          ContainerPort: 8080
        PlatformVersion: LATEST              # Fargate only
Hooks:
  - BeforeInstall: CodeDeployHook_BeforeInstall
  - AfterInstall: CodeDeployHook_AfterInstall
  - AfterAllowTestTraffic: CodeDeployHook_RunTests   # green receives only test-listener traffic
  - BeforeAllowTraffic: CodeDeployHook_BeforeAllowTraffic
  - AfterAllowTraffic: CodeDeployHook_AfterAllowTraffic

Watch forAfterAllowTestTraffic is where automated tests run against the green tasks through the test listener, before any production traffic moves. The managed policy AWSCodeDeployRoleForECS only allows invoking functions whose names start with CodeDeployHook_.

Lambda AppSpec

Use whenShifting an alias from one function version to another, with checks before and after.

appspec.yaml 
version: 0.0
Resources:
  - OrdersFunction:
      Type: AWS::Lambda::Function
      Properties:
        Name: orders-api
        Alias: live                           # callers invoke the alias, never a version
        CurrentVersion: "7"                   # version the alias points to now
        TargetVersion: "8"                    # version to shift traffic to
Hooks:
  - BeforeAllowTraffic: CodeDeployHook_PreTraffic   # test version 8 before any traffic
  - AfterAllowTraffic: CodeDeployHook_PostTraffic  # check after all traffic has moved

Watch forLambda has only these two hooks. With SAM you don't write this file: AutoPublishAlias and DeploymentPreference (with Hooks: PreTraffic / PostTraffic) generate it.

A lifecycle hook Lambda function

Use whenRunning a test from an ECS or Lambda hook and telling CodeDeploy whether to continue.

codedeploy_hook.py 
import boto3, urllib.request

codedeploy = boto3.client("codedeploy")

def handler(event, context):
    status = "Succeeded"
    try:
        # test the new version, e.g. through the test listener on port 8443
        with urllib.request.urlopen("https://orders-test.internal.example.com:8443/health", timeout=10) as r:
            if r.status != 200:
                status = "Failed"
    except Exception:
        status = "Failed"

    # CodeDeploy waits for this call; without it the hook times out and fails
    codedeploy.put_lifecycle_event_hook_execution_status(
        deploymentId=event["DeploymentId"],
        lifecycleEventHookExecutionId=event["LifecycleEventHookExecutionId"],
        status=status,                          # "Succeeded" or "Failed"
    )

Watch forThe function's role needs codedeploy:PutLifecycleEventHookExecutionStatus. If the function never reports, the deployment waits until the hook times out (up to an hour), then fails. Reporting Failed triggers rollback when automatic rollback is on.

Deployment group with traffic shifting and automatic rollback

Use whenDefining how fast traffic shifts and when CodeDeploy rolls back, for an ECS blue/green service.

deployment-group.yaml 
OrdersDeploymentGroup:
  Type: AWS::CodeDeploy::DeploymentGroup
  Properties:
    ApplicationName: !Ref OrdersApp              # application with ComputePlatform: ECS
    ServiceRoleArn: !GetAtt CodeDeployEcsRole.Arn
    DeploymentConfigName: CodeDeployDefault.ECSCanary10Percent5Minutes
    DeploymentStyle:
      DeploymentType: BLUE_GREEN
      DeploymentOption: WITH_TRAFFIC_CONTROL
    BlueGreenDeploymentConfiguration:
      DeploymentReadyOption:
        ActionOnTimeout: CONTINUE_DEPLOYMENT
      TerminateBlueInstancesOnDeploymentSuccess:
        Action: TERMINATE
        TerminationWaitTimeInMinutes: 15          # keep blue for a fast manual rollback
    ECSServices:
      - { ClusterName: prod, ServiceName: orders }
    LoadBalancerInfo:
      TargetGroupPairInfoList:
        - TargetGroups: [ { Name: orders-blue }, { Name: orders-green } ]
          ProdTrafficRoute:
            ListenerArns: [ !Ref ProdListener ]
          TestTrafficRoute:
            ListenerArns: [ !Ref TestListener ]
    AlarmConfiguration:
      Enabled: true
      Alarms: [ { Name: orders-5xx-high }, { Name: orders-p99-latency-high } ]
    AutoRollbackConfiguration:
      Enabled: true
      Events: [ DEPLOYMENT_FAILURE, DEPLOYMENT_STOP_ON_ALARM ]
PlatformPredefined configurations
EC2 and on-premisesCodeDeployDefault.OneAtATime (the default), HalfAtATime, AllAtOnce; custom minimum healthy hosts, optionally per Availability Zone
ECSCodeDeployDefault.ECSCanary10Percent5Minutes, ECSCanary10Percent15Minutes, ECSLinear10PercentEvery1Minutes, ECSLinear10PercentEvery3Minutes, ECSAllAtOnce
LambdaCodeDeployDefault.LambdaCanary10Percent5Minutes (also 10, 15, 30 minutes), LambdaLinear10PercentEvery1Minute (also 2, 3, 10 minutes), LambdaAllAtOnce

Watch forAlarms only stop a deployment if they're listed in AlarmConfiguration; rollback on them also needs DEPLOYMENT_STOP_ON_ALARM. Behind a Network Load Balancer, ECS supports only CodeDeployDefault.ECSAllAtOnce.
