S3 bucket and KMS key policies

Resource policies that decide who can reach your data and your keys: sharing across accounts, enforcing TLS and encryption, locking access to a network or the organization, and letting AWS services deliver logs. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

A resource policy is attached to the bucket or key itself and names the principals allowed to use it. For access from another account, both sides must allow: the resource policy here, and an identity policy in the caller's account. The // comments are annotations only; remove them before use.

S3 bucket policies

Cross-account read for a role

Use whenA role in another account (here an analytics role in 222222222222) must read objects in this account's bucket.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListTheBucket",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::222222222222:role/AnalyticsRole"
      },
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::shared-reports"            // bucket ARN for List
    },
    {
      "Sid": "ReadTheObjects",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::222222222222:role/AnalyticsRole"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::shared-reports/*"          // object ARN for Get
    }
  ]
}

Watch fors3:ListBucket needs the bucket ARN and s3:GetObject needs /*; mixing them up gives Access Denied. If objects use SSE-KMS, the key policy must also allow the role kms:Decrypt.

Deny requests without TLS

Use whenData in transit must always be encrypted, for compliance or a Security Hub control.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::orders-data",
        "arn:aws:s3:::orders-data/*"
      ],
      "Condition": {
        "Bool": { "aws:SecureTransport": "false" }
      }
    }
  ]
}

Watch forIt's a deny, so it applies to everyone, including the bucket owner. Include both the bucket and the object ARNs.

Require SSE-KMS with a specific key

Use whenEvery object must be encrypted with the approved customer managed key, not SSE-S3 or another key.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyWrongKey",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::orders-data/*",
      "Condition": {
        "StringNotEqualsIfExists": {                       // IfExists: requests without the header use default encryption
          "s3:x-amz-server-side-encryption-aws-kms-key-id":
            "arn:aws:kms:us-east-1:222222222222:key/1234abcd-12ab-34cd-56ef-1234567890ab"
        }
      }
    }
  ]
}

Watch forPair this with default bucket encryption set to the same key. Use StringNotEquals instead if every upload must send the header explicitly. Buckets that receive ALB access logs support only SSE-S3.

Allow access only through a VPC endpoint

Use whenData must never be read or written from outside the private network.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOutsideTheEndpoint",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::orders-data",
        "arn:aws:s3:::orders-data/*"
      ],
      "Condition": {
        "StringNotEquals": {
          "aws:SourceVpce": "vpce-0a1b2c3d4e5f67890"
        },
        "ArnNotLike": {   // escape hatch
          "aws:PrincipalArn": "arn:aws:iam::222222222222:role/BucketAdminRole"
        }
      }
    }
  ]
}

Watch forWithout an exception, this also blocks the console and administrators, who don't come through the endpoint, and you can lock yourself out (only the root user can then delete the policy). aws:SourceIp doesn't work for traffic through a VPC endpoint; use aws:SourceVpce or aws:SourceVpc.

Allow only principals in the organization

Use whenAny account in the organization may read the bucket, including accounts created later, without listing account IDs.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "OrgRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [ "s3:GetObject", "s3:ListBucket" ],
      "Resource": [
        "arn:aws:s3:::org-artifacts",
        "arn:aws:s3:::org-artifacts/*"
      ],
      "Condition": {
        "StringEquals": {
          "aws:PrincipalOrgID": "o-a1b2c3d4e5"
        }
      }
    }
  ]
}

Watch forTo stop any bucket in the organization being reached from outside, even with a misconfigured bucket policy, use a resource control policy (RCP) instead of editing every bucket.

CloudTrail log delivery

Use whenA trail (here the organization trail from management account 000000000000) writes to a bucket in the log archive account.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AWSCloudTrailAclCheck",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudtrail.amazonaws.com"
      },
      "Action": "s3:GetBucketAcl",
      "Resource": "arn:aws:s3:::org-cloudtrail-666666666666",
      "Condition": {
        "StringEquals": {
          "aws:SourceArn": "arn:aws:cloudtrail:us-east-1:000000000000:trail/org-trail"
        }
      }
    },
    {
      "Sid": "AWSCloudTrailWrite",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudtrail.amazonaws.com"
      },
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::org-cloudtrail-666666666666/AWSLogs/*",
      "Condition": {
        "StringEquals": {
          "s3:x-amz-acl": "bucket-owner-full-control",
          "aws:SourceArn": "arn:aws:cloudtrail:us-east-1:000000000000:trail/org-trail"   // only this trail
        }
      }
    }
  ]
}

Watch for"Trail creation fails" or "logs stop arriving" usually means this policy, or a KMS key policy that doesn't allow cloudtrail.amazonaws.com kms:GenerateDataKey* (scoped with aws:SourceArn and kms:EncryptionContext:aws:cloudtrail:arn).

CloudFront origin access control

Use whenA private bucket must be readable only through one CloudFront distribution, not directly.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontOAC",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::shop-assets/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::222222222222:distribution/E1A2B3C4D5E6F7"   // only this distribution
        }
      }
    }
  ]
}

Watch forOrigin access control (OAC) replaces the older origin access identity (OAI) and supports SSE-KMS buckets; the key policy must then allow cloudfront.amazonaws.com kms:Decrypt with the same AWS:SourceArn. Keep S3 Block Public Access on.

KMS key policies

Every KMS key has exactly one key policy, and it's the primary control: IAM policies only work for a key if the key policy lets the account delegate to IAM.

Separate key administrators from key users

Use whenThe people who manage a key must not be able to decrypt data with it, and the application should use it only through one service.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EnableIAMPolicies",                          // the default statement: lets IAM policies grant access
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::222222222222:root"
      },
      "Action": "kms:*",
      "Resource": "*"
    },
    {
      "Sid": "KeyAdministrators",                          // manage, but no Encrypt or Decrypt
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::222222222222:role/KeyAdminRole"
      },
      "Action": [
        "kms:Create*", "kms:Describe*", "kms:Enable*", "kms:List*", "kms:Put*",
        "kms:Update*", "kms:Revoke*", "kms:Disable*", "kms:Get*", "kms:Delete*",
        "kms:TagResource", "kms:UntagResource",
        "kms:ScheduleKeyDeletion", "kms:CancelKeyDeletion"
      ],
      "Resource": "*"
    },
    {
      "Sid": "KeyUsersThroughS3Only",                      // use, only via S3 in this Region
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::222222222222:role/OrdersAppRole"
      },
      "Action": [ "kms:Encrypt", "kms:Decrypt", "kms:ReEncrypt*", "kms:GenerateDataKey*", "kms:DescribeKey" ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "kms:ViaService": "s3.us-east-1.amazonaws.com"
        }
      }
    }
  ]
}

Watch forIn a key policy, "Resource": "*" means "this key". Removing the root statement without another admin can make the key unmanageable, so AWS Support has to recover it.

Cross-account use of a key

Use whenA deploy role in production 222222222222 must decrypt pipeline artifacts encrypted with a key in tooling 111111111111.

// 1. Key policy, in 111111111111: trust the other account (or a specific role)
{
  "Sid": "AllowProductionToDecrypt",
  "Effect": "Allow",
  "Principal": {
    "AWS": "arn:aws:iam::222222222222:role/CrossAccountDeployRole"
  },
  "Action": [ "kms:Decrypt", "kms:DescribeKey" ],
  "Resource": "*"
}

// 2. Identity policy on the role, in 222222222222: allow the key by ARN
{
  "Effect": "Allow",
  "Action": [ "kms:Decrypt", "kms:DescribeKey" ],
  "Resource": "arn:aws:kms:us-east-1:111111111111:key/1234abcd-12ab-34cd-56ef-1234567890ab"
}

Watch forBoth statements are needed. AWS managed keys (aws/s3, aws/ebs) can't be shared at all because you can't edit their key policy; use a customer managed key.

Allow CloudWatch Logs to encrypt a log group

Use whenA log group must be encrypted with a customer managed key.

{
  "Sid": "AllowCloudWatchLogs",
  "Effect": "Allow",
  "Principal": {   // Regional service principal
    "Service": "logs.us-east-1.amazonaws.com"
  },
  "Action": [ "kms:Encrypt", "kms:Decrypt", "kms:ReEncrypt*", "kms:GenerateDataKey*", "kms:Describe*" ],
  "Resource": "*",
  "Condition": {
    "ArnEquals": {
      "kms:EncryptionContext:aws:logs:arn": "arn:aws:logs:us-east-1:222222222222:log-group:/app/orders"   // only this log group
    }
  }
}

Watch forThe principal is logs.<region>.amazonaws.com, in the key's Region. "Associating the key fails" or "logs stop arriving after encrypting the log group" points to this statement being missing.
