IAM trust policies

Who may assume a role: another account, an AWS service, a third party, GitHub Actions, or any role in the organization. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

DOP-C02IAMSTSYAML5 snippets

On this page

  1. Another account's role (cross-account)
  2. An AWS service
  3. A third party, with an external ID
  4. GitHub Actions through OIDC
  5. Any role in the organization

A trust policy (AssumeRolePolicyDocument) says who may assume a role. What the role can do is in its separate permissions policies.

Another account's role (cross-account)

Use whenA pipeline in the tooling account 111111111111 deploys into this account.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal:
        AWS: arn:aws:iam::111111111111:role/PipelineServiceRole
      Action: sts:AssumeRole

Watch forThe caller also needs sts:AssumeRole on this role's ARN in its own permissions. Both sides must allow.

An AWS service

Use whenCloudFormation, CodeBuild, Lambda or EC2 acts with this role.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal:   # codebuild, lambda, ec2, ecs-tasks...
        Service: cloudformation.amazonaws.com
      Action: sts:AssumeRole
      Condition:
        StringEquals:   # confused-deputy protection
          aws:SourceAccount: "222222222222"

Watch forECS tasks use ecs-tasks.amazonaws.com, not ecs.amazonaws.com.

A third party, with an external ID

Use whenA SaaS vendor (monitoring, cost tools) needs access to your account.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal:
        AWS: arn:aws:iam::444444444444:root
      Action: sts:AssumeRole
      Condition:
        StringEquals:
          sts:ExternalId: acme-7f3c91

GitHub Actions through OIDC

Use whenAn external CI system deploys without stored access keys.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal:
        Federated: arn:aws:iam::222222222222:oidc-provider/token.actions.githubusercontent.com
      Action: sts:AssumeRoleWithWebIdentity
      Condition:
        StringEquals:
          token.actions.githubusercontent.com:aud: sts.amazonaws.com
          token.actions.githubusercontent.com:sub: repo:acme/orders:ref:refs/heads/main

Watch forWithout the sub condition, any GitHub repository could assume the role.

Any role in the organization

Use whenA shared role (for example, read-only audit) should be assumable from every account in the organization without listing them.

AssumeRolePolicyDocument:
  Version: "2012-10-17"
  Statement:
    - Effect: Allow
      Principal: { AWS: "*" }
      Action: sts:AssumeRole
      Condition:
        StringEquals:
          aws:PrincipalOrgID: o-a1b2c3d4e5
        ArnLike:
          aws:PrincipalArn: "arn:aws:iam::*:role/SecurityAudit*"

Watch for"Principal": "*" is only safe with conditions like these; Access Analyzer flags it otherwise.
