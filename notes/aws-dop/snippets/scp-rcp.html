Service and resource control policies

Organization guardrails: service control policies (SCPs) that cap what principals in member accounts can do, and resource control policies (RCPs) that cap what anyone can do to resources in those accounts. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

Both policy types are attached to the organization root, an OU or an account, and both only limit: neither grants anything, so principals still need identity or resource policies. SCPs limit principals in member accounts (including their root users); RCPs limit access to resources in member accounts, whoever the caller is. Neither affects the management account, and neither restricts service-linked roles. SCPs have no Principal element; RCPs must use "Principal": "*", only Deny statements, and no NotAction.

Stay in the organization

Use whenMember accounts must never leave and escape the guardrails.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyLeaveOrganization",
    "Effect": "Deny",
    "Action": "organizations:LeaveOrganization",
    "Resource": "*"
  }]
}

Approved Regions only

Use whenData residency or cost rules allow only some Regions.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyOutsideApprovedRegions",
    "Effect": "Deny",
    "NotAction": [                          // global services, served from us-east-1
      "iam:*", "organizations:*", "sts:*", "support:*",
      "cloudfront:*", "route53:*", "waf:*", "wafv2:*", "shield:*",
      "budgets:*", "ce:*", "health:*", "globalaccelerator:*",
      "s3:ListAllMyBuckets", "ec2:DescribeRegions"
    ],
    "Resource": "*",
    "Condition": {
      "StringNotEquals": {
        "aws:RequestedRegion": ["us-east-1", "eu-west-1"]
      },
      "ArnNotLike": {
        "aws:PrincipalArn": "arn:aws:iam::*:role/BreakGlassRole"
      }
    }
  }]
}

Watch forWithout the NotAction exemptions, IAM, CloudFront, Route 53 and other global services break outside us-east-1. AWS's published example has a longer list; check it before use.

Protect security services

Use whenNobody in a workload account may switch off logging or threat detection, except the security team's role.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "ProtectSecurityTooling",
    "Effect": "Deny",
    "Action": [
      "cloudtrail:StopLogging", "cloudtrail:DeleteTrail", "cloudtrail:UpdateTrail",
      "config:StopConfigurationRecorder", "config:DeleteConfigurationRecorder", "config:DeleteDeliveryChannel",
      "guardduty:DeleteDetector", "guardduty:UpdateDetector", "guardduty:DisassociateFromAdministratorAccount",
      "securityhub:DisableSecurityHub", "securityhub:DisassociateFromAdministratorAccount"
    ],
    "Resource": "*",
    "Condition": {
      "ArnNotLike": {   // exemption
        "aws:PrincipalArn": "arn:aws:iam::*:role/SecurityAdminRole"
      }
    }
  }]
}

Watch forExempt by aws:PrincipalArn with ArnNotLike, not by naming a principal: SCPs have no Principal element.

Block the root user in member accounts

Use whenMember account root users should never be used for day-to-day actions.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyMemberRoot",
    "Effect": "Deny",
    "Action": "*",
    "Resource": "*",
    "Condition": {
      "StringLike": {
        "aws:PrincipalArn": "arn:aws:iam::*:root"
      }
    }
  }]
}

Watch forSCPs do apply to member root users (but not the management account's). With centralized root access, the management account can also remove member root credentials and run privileged root tasks itself.

Require IMDSv2

Use whenInstance role credentials must be protected from SSRF attacks through IMDSv1.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "LaunchOnlyWithImdsv2",
      "Effect": "Deny",
      "Action": "ec2:RunInstances",
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringNotEquals": {
          "ec2:MetadataHttpTokens": "required"
        }
      }
    },
    {
      "Sid": "NoCredentialsFromImdsv1",
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": {   // only on instance-role requests
        "NumericLessThan": {
          "ec2:RoleDelivery": "2.0"
        }
      }
    }
  ]
}

Watch forA declarative policy (or the account-level IMDS defaults with enforcement) is the newer way to require IMDSv2 across accounts; it also blocks launches that ask for IMDSv1.

No IAM users or access keys

Use whenPeople must federate through IAM Identity Center and workloads must use roles.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyLongTermCredentials",
    "Effect": "Deny",
    "Action": [ "iam:CreateUser", "iam:CreateAccessKey", "iam:CreateLoginProfile" ],
    "Resource": "*",
    "Condition": {
      "ArnNotLike": {
        "aws:PrincipalArn": "arn:aws:iam::*:role/BreakGlassRole"
      }
    }
  }]
}

Keep account-level protections on

Use whenS3 Block Public Access and EBS encryption by default, once on, must stay on.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "LockAccountProtections",
    "Effect": "Deny",
    "Action": [
      "s3:PutAccountPublicAccessBlock",       // account-level Block Public Access
      "ec2:DisableEbsEncryptionByDefault"
    ],
    "Resource": "*",
    "Condition": {
      "ArnNotLike": {
        "aws:PrincipalArn": "arn:aws:iam::*:role/SecurityAdminRole"
      }
    }
  }]
}

Watch forTurn the protections on first (for example with a StackSet or Config remediation), then lock them with the SCP.

RCP: S3 data perimeter

Use whenNo principal outside the organization may reach your buckets, even if a bucket policy is misconfigured.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "EnforceOrgIdentityPerimeter",
    "Effect": "Deny",
    "Principal": "*",                         // required, and the only value allowed
    "Action": "s3:*",
    "Resource": "*",
    "Condition": {
      "StringNotEqualsIfExists": {
        "aws:PrincipalOrgID": "o-a1b2c3d4e5"
      },
      "BoolIfExists": {   // let AWS services (CloudTrail...) write
        "aws:PrincipalIsAWSService": "false"
      }
    }
  }]
}

Watch forWithout the aws:PrincipalIsAWSService exemption, service principals such as cloudtrail.amazonaws.com are blocked from delivering logs. Real perimeters also exempt approved partner accounts or public buckets, often by resource tag.

RCP: HTTPS only for S3

Use whenEvery bucket in the organization must refuse unencrypted requests, without editing each bucket policy.

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyInsecureTransport",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": "*",
    "Condition": {
      "BoolIfExists": {
        "aws:SecureTransport": "false"
      }
    }
  }]
}

Watch forRCPs cover only supported services (S3, KMS, STS, SQS, Secrets Manager, DynamoDB, ECR and others) and don't apply to AWS managed KMS keys. The same deny in a single bucket policy protects only that bucket.
