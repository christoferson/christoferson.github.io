SAM gradual deployments

Shipping a new Lambda version to a small share of traffic first, checking it with alarms and test hooks, and rolling back automatically. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

SAM is a CloudFormation transform. Adding AutoPublishAlias and DeploymentPreference to a function makes SAM publish a new version on every code change and create a CodeDeploy application and deployment group that shifts the alias from the old version to the new one.

Minimal SAM template

Use whenStarting a serverless application; every other snippet builds on this.

template.yaml 
AWSTemplateFormatVersion: "2010-09-09"
Transform: AWS::Serverless-2016-10-31   # makes this a SAM template

Globals:   # defaults for every function
  Function:
    Runtime: python3.12
    MemorySize: 256
    Timeout: 10
    Tracing: Active   # X-Ray

Resources:
  OrdersFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/orders/
      Handler: app.handler
      Policies:   # SAM policy templates
        - DynamoDBCrudPolicy:
            TableName: !Ref OrdersTable

  OrdersTable:
    Type: AWS::Serverless::SimpleTable

Watch forDeploying needs CAPABILITY_IAM (SAM creates roles) and CAPABILITY_AUTO_EXPAND when the template contains nested applications or macros.

Canary deployment with alarms and hooks

Use whenNew versions should take 10% of traffic first and roll back automatically if errors rise.

template.yaml 
OrdersFunction:
  Type: AWS::Serverless::Function
  Properties:
    CodeUri: src/orders/
    Handler: app.handler
    AutoPublishAlias: live   # new version + alias "live" on each code change
    DeploymentPreference:
      Type: Canary10Percent5Minutes   # 10% for 5 minutes, then 100%
      Alarms:   # any alarm in ALARM: roll back
        - !Ref OrdersErrorsAlarm
        - !Ref OrdersLatencyAlarm
      Hooks:
        PreTraffic: !Ref PreTrafficHook   # runs before any traffic shifts
        PostTraffic: !Ref PostTrafficHook   # runs after 100% has shifted

OrdersErrorsAlarm:
  Type: AWS::CloudWatch::Alarm
  Properties:
    Namespace: AWS/Lambda
    MetricName: Errors
    Dimensions:
      - Name: Resource
        Value: !Sub "${OrdersFunction}:live"   # the alias
      - Name: FunctionName
        Value: !Ref OrdersFunction
    Statistic: Sum
    Period: 60
    EvaluationPeriods: 1
    Threshold: 1
    ComparisonOperator: GreaterThanOrEqualToThreshold
    TreatMissingData: notBreaching

Watch forDeploymentPreference only works with AutoPublishAlias. Event sources in the template (API, SQS, schedules) are wired to the alias, so they follow the traffic shift; anything that calls the function by plain name or $LATEST doesn't.

Deployment preference types

Use whenChoosing how fast traffic moves to the new version.

# canary: one small step, then the rest
Canary10Percent5Minutes
Canary10Percent10Minutes
Canary10Percent15Minutes
Canary10Percent30Minutes

# linear: equal 10% steps at a fixed interval
Linear10PercentEvery1Minute
Linear10PercentEvery2Minutes
Linear10PercentEvery3Minutes
Linear10PercentEvery10Minutes

# everything at once (still gets hooks and alarm rollback)
AllAtOnce

Watch for"Least time exposed to a bad version with real traffic" is canary; "gradual and even" is linear. For other percentages, create a custom CodeDeploy deployment configuration and put its name in Type.

A pre-traffic hook function

Use whenThe new version must pass a smoke test before it receives any traffic.

template.yaml 
PreTrafficHook:
  Type: AWS::Serverless::Function
  Properties:
    FunctionName: CodeDeployHook_OrdersPreTraffic   # prefix the default role allows
    CodeUri: src/hooks/
    Handler: pre_traffic.handler
    DeploymentPreference:
      Enabled: false   # don't gradually deploy the hook itself
    Environment:
      Variables:
        NEW_VERSION: !Ref OrdersFunction.Version   # version under test
    Policies:
      - Version: "2012-10-17"
        Statement:
          - Effect: Allow
            Action: codedeploy:PutLifecycleEventHookExecutionStatus
            Resource: !Sub arn:aws:codedeploy:${AWS::Region}:${AWS::AccountId}:deploymentgroup:${ServerlessDeploymentApplication}/*
          - Effect: Allow
            Action: lambda:InvokeFunction
            Resource: !Ref OrdersFunction.Version

The handler invokes NEW_VERSION with a test event, then reports the result:

import os, boto3, json

codedeploy = boto3.client("codedeploy")
lam = boto3.client("lambda")

def handler(event, context):
    status = "Succeeded"
    try:
        resp = lam.invoke(FunctionName=os.environ["NEW_VERSION"],
                          Payload=json.dumps({"test": True}))
        if resp.get("FunctionError"):
            status = "Failed"
    except Exception:
        status = "Failed"
    codedeploy.put_lifecycle_event_hook_execution_status(
        deploymentId=event["DeploymentId"],
        lifecycleEventHookExecutionId=event["LifecycleEventHookExecutionId"],
        status=status)   # "Failed" stops the deployment and rolls back

Watch forA hook that never calls PutLifecycleEventHookExecutionStatus leaves the deployment waiting until it times out and fails. With the CodeDeploy role SAM creates, hook function names must start with CodeDeployHook_.

Provisioned concurrency on the alias

Use whenLatency-sensitive functions must not have cold starts, even right after a deployment.

OrdersFunction:
  Type: AWS::Serverless::Function
  Properties:
    CodeUri: src/orders/
    Handler: app.handler
    AutoPublishAlias: live   # required: provisioned on the alias
    ProvisionedConcurrencyConfig:
      ProvisionedConcurrentExecutions: 10
    DeploymentPreference:
      Type: Linear10PercentEvery1Minute

Watch forProvisioned concurrency can't be set on $LATEST, only on a version or alias, which is why AutoPublishAlias is needed. It's billed while allocated; scale it with Application Auto Scaling on the alias if load varies.

API events and stage canaries

Use whenAn API fronts the function and you need to choose where the canary happens.

OrdersApi:
  Type: AWS::Serverless::Api   # REST API
  Properties:
    StageName: prod
    CanarySetting:   # stage-level canary (REST APIs only)
      PercentTraffic: 10   # share sent to the newest API deployment

OrdersFunction:
  Type: AWS::Serverless::Function
  Properties:
    CodeUri: src/orders/
    Handler: app.handler
    AutoPublishAlias: live
    Events:
      CreateOrder:
        Type: Api   # or HttpApi for an HTTP API
        Properties:
          RestApiId: !Ref OrdersApi
          Path: /orders
          Method: post

Watch forNormally you use one or the other. DeploymentPreference shifts traffic between Lambda versions behind the same API. A stage CanarySetting splits traffic between two API deployments (for example, a changed API definition) and is promoted manually.

samconfig.toml and deploy commands

Use whenDeploying the same template to several environments with saved settings.

samconfig.toml 
version = 0.1

[default.deploy.parameters]
stack_name = "orders-dev"
region = "us-east-1"
resolve_s3 = true   # SAM manages the artifact bucket
capabilities = "CAPABILITY_IAM"
confirm_changeset = false

[prod.deploy.parameters]
stack_name = "orders-prod"
region = "us-east-1"
resolve_s3 = true
capabilities = "CAPABILITY_IAM"
confirm_changeset = true   # review the change set first
parameter_overrides = "Stage=prod"
sam build   # install dependencies, prepare artifacts
sam deploy --guided   # first time: prompts, then writes samconfig.toml
sam deploy --config-env prod   # use the [prod] settings
sam sync --watch --stack-name orders-dev   # dev only: pushes code changes directly

Watch forsam sync updates code without going through a CloudFormation deployment, so it skips gradual deployment. Never use it for production.

Pipelines with sam pipeline

Use whenYou want a ready-made multi-stage CI/CD pipeline for a SAM application.

sam pipeline bootstrap --stage dev   # per stage: deploy role, CloudFormation role, artifact bucket
sam pipeline bootstrap --stage prod   # run again for each account or Region
sam pipeline init   # generates the pipeline definition

Watch forsam pipeline init can generate configurations for CodePipeline, GitHub Actions, GitLab CI/CD, Jenkins and Bitbucket Pipelines. Gradual deployment still comes from DeploymentPreference in the template, not from the pipeline.
