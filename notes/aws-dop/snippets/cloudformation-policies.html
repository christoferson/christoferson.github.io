Attributes on a resource that control what happens when it's created, updated, replaced or deleted.

Keep data when a resource is deleted or replaced

Use whenDatabases, buckets and volumes must survive stack deletion or an update that replaces them.

OrdersDb:
  Type: AWS::RDS::DBInstance
  DeletionPolicy: Snapshot            # on stack delete or removal from template: Delete | Retain | RetainExceptOnCreate | Snapshot
  UpdateReplacePolicy: Snapshot       # when an update replaces it with a new resource
  Properties:
    ...

Watch forSnapshot works only on resources that support snapshots (RDS, EBS volumes, ElastiCache, Redshift, Neptune, DocumentDB). S3 buckets use Retain.

Wait for instances to finish bootstrapping

Use whenThe stack should succeed only after the application on new instances is actually running.

WebAsg:
  Type: AWS::AutoScaling::AutoScalingGroup
  CreationPolicy:
    ResourceSignal:
      Count: 2                         # signals needed
      Timeout: PT15M                    # fail (and roll back) if not received
  Properties:
    ...

# at the end of the instance user data:
# /opt/aws/bin/cfn-signal -e $? --stack ${AWS::StackName} --resource WebAsg --region ${AWS::Region}

Watch for"Stack times out waiting for signals" means the user data failed, cfn-signal isn't installed, or the instance can't reach the CloudFormation endpoint.

Roll out a new launch template to an Auto Scaling group

Use whenUpdating instances gradually during a stack update, keeping capacity.

WebAsg:
  Type: AWS::AutoScaling::AutoScalingGroup
  UpdatePolicy:
    AutoScalingRollingUpdate:          # replace instances in batches
      MinInstancesInService: 2
      MaxBatchSize: 1
      PauseTime: PT10M
      WaitOnResourceSignals: true      # each new instance must cfn-signal
    # or AutoScalingReplacingUpdate: { WillReplace: true }  -- a whole new group, then swap (fast rollback)

Watch forRolling updates in place batch by batch; replacing creates a new group and deletes the old one only on success, so rollback is quick.

Protect critical resources from updates (stack policy)

Use whenNobody should replace or delete the production database through a stack update by accident.

{
  "Statement": [
    { "Effect": "Allow", "Principal": "*", "Action": "Update:*", "Resource": "*" },
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": ["Update:Replace", "Update:Delete"],
      "Resource": "LogicalResourceId/OrdersDb"
    }
  ]
}

Watch forOnce a stack policy exists, anything not explicitly allowed is denied, so include the allow-all statement. Termination protection is separate: it blocks deleting the whole stack.
