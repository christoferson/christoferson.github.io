Route 53 records

DNS records and health checks that move traffic between targets and Regions: alias records, health checks of several kinds, and failover, weighted, latency and geolocation routing. Each snippet shows when to use it, the code with comments, and the detail that usually decides the exam answer.

The examples use the domain example.com in hosted zone Z0123456789ABCDEFGHIJ, with the application running in us-east-1 and eu-west-1. Records that share a name and type and use a routing policy (failover, weighted, latency, geolocation) each need a unique SetIdentifier; Route 53 chooses among them on every query.

Alias record to an ALB

Use whenPointing a name, including the zone apex example.com, at a load balancer, CloudFront distribution, API Gateway or S3 website.

app-dns.yaml 
AppRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    AliasTarget:
      DNSName: !GetAtt AppLoadBalancer.DNSName
      # the ALB's own zone ID, not your hosted zone's
      HostedZoneId: !GetAtt AppLoadBalancer.CanonicalHostedZoneID
      EvaluateTargetHealth: true   # unhealthy if the ALB has no healthy targets

Watch forAlias records have no TTL of their own and queries to them are free; a CNAME can't be used at the zone apex. EvaluateTargetHealth lets an alias take part in failover without a separate health check.

HTTPS health check

Use whenRoute 53 should probe a public endpoint and mark it unhealthy when the application stops answering.

UsEastHealthCheck:
  Type: AWS::Route53::HealthCheck
  Properties:
    HealthCheckConfig:
      Type: HTTPS
      FullyQualifiedDomainName: us-east-1.app.example.com
      Port: 443
      # a deep check that also tests the database
      ResourcePath: /health
      RequestInterval: 10   # 10 (fast, extra cost) or 30 seconds
      FailureThreshold: 3   # consecutive failures before unhealthy
      EnableSNI: true
    HealthCheckTags:
      - Key: Name
        Value: app-us-east-1

Watch forHealth checkers run from the internet, so the endpoint must be public and its security group must allow the Route 53 health checker IP ranges. A /health page that only returns 200 from the web server misses database failures; make the check exercise real dependencies.

Failover: primary and secondary

Use whenActive-passive disaster recovery: all traffic goes to the primary Region until its health check fails.

PrimaryRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: primary-us-east-1
    Failover: PRIMARY
    HealthCheckId: !Ref UsEastHealthCheck
    AliasTarget:
      DNSName: !GetAtt UsEastAlb.DNSName
      HostedZoneId: !GetAtt UsEastAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

SecondaryRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: secondary-eu-west-1
    Failover: SECONDARY   # answered only while PRIMARY is unhealthy
    AliasTarget:
      DNSName: !GetAtt EuWestAlb.DNSName
      HostedZoneId: !GetAtt EuWestAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

Watch forFailover takes the health check's detection time (interval × failure threshold) plus the time clients keep cached answers. For non-alias records, a low TTL (60 seconds) shortens that delay.

Weighted records for blue/green and canary

Use whenShifting a share of traffic to a new environment, then moving the rest once it looks healthy.

BlueRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: CNAME
    TTL: "60"
    SetIdentifier: blue
    Weight: 90   # share = weight / sum of weights
    ResourceRecords:
      - blue-alb-123456.us-east-1.elb.amazonaws.com

GreenRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: CNAME
    TTL: "60"
    SetIdentifier: green
    Weight: 10   # canary: 10% of queries
    ResourceRecords:
      - green-alb-654321.us-east-1.elb.amazonaws.com

Watch forWeights run from 0 to 255. A weight of 0 drains a record (it gets no traffic while others have weight), and if every record is 0, Route 53 answers them equally. DNS-based shifting is coarse: cached answers keep some clients on the old target, so ALB weighted target groups shift faster.

Latency records per Region

Use whenActive-active in several Regions: each user goes to the Region with the lowest latency, and away from a Region whose health check fails.

UsEastLatency:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: us-east-1
    Region: us-east-1   # the Region the target runs in
    HealthCheckId: !Ref UsEastHealthCheck
    AliasTarget:
      DNSName: !GetAtt UsEastAlb.DNSName
      HostedZoneId: !GetAtt UsEastAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

EuWestLatency:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: eu-west-1
    Region: eu-west-1
    HealthCheckId: !Ref EuWestHealthCheck
    AliasTarget:
      DNSName: !GetAtt EuWestAlb.DNSName
      HostedZoneId: !GetAtt EuWestAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

Watch forLatency routing measures network latency between users and AWS Regions, not distance; geography-based rules need geolocation or geoproximity instead. Each Region's capacity must absorb the other's traffic when a Region is removed.

Health check from a CloudWatch alarm

Use whenThe resource is private (in a VPC, without a public endpoint) or health depends on a metric such as error rate.

ApiErrorsHealthCheck:
  Type: AWS::Route53::HealthCheck
  Properties:
    HealthCheckConfig:
      Type: CLOUDWATCH_METRIC
      AlarmIdentifier:
        Name: internal-api-errors   # unhealthy while the alarm is in ALARM
        Region: us-east-1
      # Healthy | Unhealthy | LastKnownStatus
      InsufficientDataHealthStatus: LastKnownStatus

Watch forRoute 53 health checkers can't reach private IP addresses. Publishing a metric (or using an existing one such as ALB 5xx count), alarming on it, and basing the health check on the alarm is the standard way to health-check private resources.

Calculated health check

Use whenA Region counts as healthy only if enough of its parts are healthy, for example the web tier and the API both.

UsEastRegionHealth:
  Type: AWS::Route53::HealthCheck
  Properties:
    HealthCheckConfig:
      Type: CALCULATED
      ChildHealthChecks:
        - !Ref UsEastHealthCheck
        - !Ref ApiErrorsHealthCheck
      HealthThreshold: 2   # how many children must be healthy

Watch forThe parent evaluates only its children's status and doesn't probe anything itself. Point the failover or latency record's HealthCheckId at the calculated check so the Region fails over when any required part fails.

Geolocation with a default

Use whenUsers in specific countries or continents must reach a specific deployment, for compliance or localized content.

EuropeRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: europe
    GeoLocation:
      ContinentCode: EU
    AliasTarget:
      DNSName: !GetAtt EuWestAlb.DNSName
      HostedZoneId: !GetAtt EuWestAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

DefaultRecord:
  Type: AWS::Route53::RecordSet
  Properties:
    HostedZoneId: Z0123456789ABCDEFGHIJ
    Name: app.example.com
    Type: A
    SetIdentifier: default
    GeoLocation:
      CountryCode: "*"   # everyone not matched elsewhere
    AliasTarget:
      DNSName: !GetAtt UsEastAlb.DNSName
      HostedZoneId: !GetAtt UsEastAlb.CanonicalHostedZoneID
      EvaluateTargetHealth: true

Watch forWithout a default (CountryCode: "*") record, users from unmatched locations, and queries whose location can't be determined, get no answer at all. The most specific match wins: country over continent.

Routing control health check

Use whenFailover between Regions must be a deliberate operator decision, made with Application Recovery Controller routing controls, rather than automatic.

UsEastRoutingControlCheck:
  Type: AWS::Route53::HealthCheck
  Properties:
    HealthCheckConfig:
      Type: RECOVERY_CONTROL
      # healthy while the routing control is On
      RoutingControlArn: !Ref UsEastRoutingControl

Watch forAttach this health check to the us-east-1 failover or latency record. Turning the routing control Off (through the highly available ARC cluster endpoints) marks it unhealthy, so Route 53 stops sending traffic there even if the Region looks healthy.
