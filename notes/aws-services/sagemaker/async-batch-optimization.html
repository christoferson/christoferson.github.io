Async, batch and inference optimization

The inference options that don't answer while the caller waits, and the tools that make any endpoint faster or cheaper: asynchronous endpoints that queue work and can scale to zero, batch transform over whole datasets, optimization jobs for large language models, AWS's inference recommendations and benchmarks, SageMaker Neo, the metrics to watch, and the security settings, quotas and prices that apply.

Choosing an inference option

  • Real-time: an answer within 60 seconds for payloads up to 6 MB, on instances that run all the time (or scale to zero with inference components).
  • Serverless: the same synchronous call for intermittent traffic that tolerates cold starts; no GPUs, 4 MB payloads.
  • Asynchronous: in AWS's words, for "requests with large payload sizes (up to 1GB), long processing times (up to one hour), and near real-time latency requirements". Requests queue, results land in S3, and the endpoint can scale to zero between bursts.
  • Batch transform: "get inferences from large datasets" and "run inference when you don't need a persistent endpoint". A job reads a whole S3 prefix, writes one output file per input file and shuts down.

Exams often contrast them: a nightly scoring run over a data lake is batch; a 20-minute video or document analysis that a user waits for by notification is async; a fraud check during checkout is real-time; a rarely used internal tool is serverless.

Asynchronous inference

Add an AsyncInferenceConfig to the endpoint configuration; the endpoint then accepts only asynchronous calls. Callers put the input in S3 (or send up to 128,000 bytes inline) and call InvokeEndpointAsync, which returns HTTP 202 straight away with the output location. SageMaker queues the request, runs it, writes the result to S3 and, if configured, notifies SNS.

An async endpoint with notifications, and a request (Python, boto3) 
import boto3

sm = boto3.client("sagemaker")
smr = boto3.client("sagemaker-runtime")

sm.create_endpoint_config(
    EndpointConfigName="docs-async-cfg",
    ProductionVariants=[{
        "VariantName": "variant1",
        "ModelName": "doc-summarizer",
        "InstanceType": "ml.g5.xlarge",
        "InitialInstanceCount": 1,
    }],
    AsyncInferenceConfig={
        # 1 to 1000; leave it out and SageMaker picks a value
        "ClientConfig": {"MaxConcurrentInvocationsPerInstance": 4},
        "OutputConfig": {
            "S3OutputPath": "s3://ml-111111111111/async/out/",
            "S3FailurePath": "s3://ml-111111111111/async/failed/",
            "KmsKeyId": "arn:aws:kms:us-east-1:111111111111:key/1234abcd-12ab-34cd-56ef-1234567890ab",
            "NotificationConfig": {
                "SuccessTopic": "arn:aws:sns:us-east-1:111111111111:async-ok",
                "ErrorTopic": "arn:aws:sns:us-east-1:111111111111:async-err",
                # Only responses of 128 KB or less are embedded in the message
                "IncludeInferenceResponseIn": ["SUCCESS_NOTIFICATION_TOPIC"],
            },
        },
    },
)
sm.create_endpoint(EndpointName="docs-async", EndpointConfigName="docs-async-cfg")
sm.get_waiter("endpoint_in_service").wait(EndpointName="docs-async")

r = smr.invoke_endpoint_async(
    EndpointName="docs-async",
    # Or Body= up to 128,000 bytes; never both
    InputLocation="s3://ml-111111111111/async/in/req-0001.json",
    ContentType="application/json",
    InferenceId="req-0001",
    RequestTTLSeconds=3600,         # time allowed in the queue: 60 to 21600, default 21600
    InvocationTimeoutSeconds=1800,  # processing time: 1 to 3600, default 900
)
# The result isn't there yet; poll this S3 key or wait for SNS
print(r["InferenceId"], r["OutputLocation"], r["FailureLocation"])
  • Prebuilt containers need environment variables to use the full payload size and timeout: TS_MAX_REQUEST_SIZE, TS_MAX_RESPONSE_SIZE and TS_DEFAULT_RESPONSE_TIMEOUT for TorchServe, or the MMS_ equivalents for Multi Model Server and Hugging Face containers. Without them, large or slow requests fail early.
  • Notifications carry the endpoint, input and output locations, the inference ID and invocationStatus; subscribe an SQS queue or Lambda function to drive the next step.
  • Not supported with async: multi-model endpoints, shadow tests, Marketplace containers and Inf1 with deployment guardrails. Instance pools do work, including scaling from zero.
  • SDK V3: mb.deploy(..., inference_config=AsyncInferenceConfig(output_path=..., failure_path=..., notification_config=...)) from sagemaker.core.inference_config, then endpoint.invoke_async(...).

Scaling async endpoints to zero

Async endpoints have been able to scale to zero instances since long before inference components: requests that arrive meanwhile wait in the queue. AWS recommends tracking the backlog per instance, plus a step policy that wakes the endpoint as soon as anything waits.

Backlog-based scaling with a wake-up policy (Python, boto3; continues the example above) 
aas = boto3.client("application-autoscaling")
cw = boto3.client("cloudwatch")
resource_id = "endpoint/docs-async/variant/variant1"
dim = "sagemaker:variant:DesiredInstanceCount"

aas.register_scalable_target(ServiceNamespace="sagemaker", ResourceId=resource_id,
                             ScalableDimension=dim, MinCapacity=0, MaxCapacity=5)

# Async endpoints don't publish Invocations, so track the queue instead
aas.put_scaling_policy(
    PolicyName="backlog-per-instance", ServiceNamespace="sagemaker", ResourceId=resource_id,
    ScalableDimension=dim, PolicyType="TargetTrackingScaling",
    TargetTrackingScalingPolicyConfiguration={
        "TargetValue": 5.0,
        "CustomizedMetricSpecification": {
            "MetricName": "ApproximateBacklogSizePerInstance", "Namespace": "AWS/SageMaker",
            "Dimensions": [{"Name": "EndpointName", "Value": "docs-async"}], "Statistic": "Average",
        },
        "ScaleInCooldown": 600, "ScaleOutCooldown": 300,
    },
)

# Without this, a scaled-to-zero endpoint waits until the backlog passes the target
step = aas.put_scaling_policy(
    PolicyName="HasBacklogWithoutCapacity-ScalingPolicy", ServiceNamespace="sagemaker",
    ResourceId=resource_id, ScalableDimension=dim, PolicyType="StepScaling",
    StepScalingPolicyConfiguration={
        "AdjustmentType": "ChangeInCapacity", "MetricAggregationType": "Average", "Cooldown": 300,
        "StepAdjustments": [{"MetricIntervalLowerBound": 0, "ScalingAdjustment": 1}],
    },
)
cw.put_metric_alarm(
    AlarmName="docs-async-backlog-no-capacity", Namespace="AWS/SageMaker",
    MetricName="HasBacklogWithoutCapacity",
    Dimensions=[{"Name": "EndpointName", "Value": "docs-async"}],
    Statistic="Average", Period=60, EvaluationPeriods=2, DatapointsToAlarm=2, Threshold=1,
    ComparisonOperator="GreaterThanOrEqualToThreshold", AlarmActions=[step["PolicyARN"]],
)

When several policies apply, the one asking for the most capacity wins. The cooldowns are an example; tune them to how long a request takes.

Async metrics (AWS/SageMaker)

By endpoint: ApproximateBacklogSize, ApproximateBacklogSizePerInstance, ApproximateAgeOfOldestRequest and HasBacklogWithoutCapacity. By variant: TimeInBacklog, TotalProcessingTime, ExpiredRequests (the TTL ran out), InvocationFailures, RequestDownloadFailures, ResponseUploadFailures and NotificationFailures. Invocations, InvocationsPerInstance and OverheadLatency are not published for async endpoints. Logs are in /aws/sagemaker/Endpoints/NAME, with the inference ID on each line.

Batch transform

A transform job starts instances for an existing model, splits each S3 input file into requests, calls the container's /invocations, writes FILE.out for each input and stops. Results keep the order of the input records.

Score CSV files, dropping the ID column for the model and keeping it in the output (Python, boto3) 
sm.create_transform_job(
    TransformJobName="churn-batch-2026-11-10",
    ModelName="churn-xgb",
    # MultiRecord packs many lines into each request; needs a SplitType other than None
    BatchStrategy="MultiRecord",
    MaxConcurrentTransforms=4,
    # Concurrent transforms x payload must be 100 MB or less
    MaxPayloadInMB=6,
    ModelClientConfig={"InvocationsTimeoutInSeconds": 600, "InvocationsMaxRetries": 3},
    TransformInput={
        "DataSource": {"S3DataSource": {"S3DataType": "S3Prefix", "S3Uri": "s3://ml-111111111111/churn/in/"}},
        "ContentType": "text/csv",
        "SplitType": "Line",
    },
    TransformOutput={
        "S3OutputPath": "s3://ml-111111111111/churn/out/",
        "Accept": "text/csv",
        "AssembleWith": "Line",
        "KmsKeyId": "alias/ml-batch-output",
    },
    TransformResources={"InstanceType": "ml.m5.xlarge", "InstanceCount": 2},
    DataProcessing={
        "InputFilter": "$[1:]",     # the model sees every column except column 0 (the ID)
        "JoinSource": "Input",      # append the prediction to the original row
        "OutputFilter": "$[0,-1]",  # keep only the ID and the prediction
    },
)
sm.get_waiter("transform_job_completed_or_stopped").wait(TransformJobName="churn-batch-2026-11-10")
  • Input: an S3Prefix or a ManifestFile (not an augmented manifest), optionally Gzip-compressed. SplitType is None (each object is one request), Line, RecordIO or TFRecord.
  • Filters and joins (JSONPath): only JSON, JSON Lines and CSV; for CSV, both SplitType and AssembleWith must be Line and only index paths work. With JSON, the prediction goes in a SageMakerOutput attribute.
  • Parallelism: files are divided between instances by S3 key, so a single large file uses only one instance; split the data into at least as many files as instances. MaxConcurrentTransforms should match the container's workers.
  • Errors: an .out file is written only if its whole input file succeeds; other files continue, but the job ends Failed. Add an S3 lifecycle rule to clean up incomplete multipart uploads. A job has no run-time limit setting.
  • SDK V3: Transformer(model_name=..., instance_count=2, instance_type="ml.m5.xlarge", strategy="MultiRecord", assemble_with="Line", output_path=...) from sagemaker.core.transformer, then .transform(data, content_type="text/csv", split_type="Line", input_filter=..., join_source="Input", output_filter=...).
  • Batch data capture (DataCaptureConfig) records inputs and outputs for monitoring; Model Monitor itself has been closed to new customers since 30 July 2026.

Optimizing LLM inference

An inference optimization job (CreateOptimizationJob) prepares a large language model for a specific instance type and writes an optimized copy to S3, with a recommended Large Model Inference (LMI) container image to serve it.

  • Quantization: smaller weights for less GPU memory and higher throughput: INT4-AWQ, FP8 or INT8-SmoothQuant (OPTION_QUANTIZE; SmoothQuant only with compilation).
  • Compilation: ahead-of-time compilation with TensorRT-LLM on GPUs or the AWS Neuron SDK on Inferentia and Trainium, so new instances don't compile at startup. Neuron supports compilation only.
  • Speculative decoding: a small draft model proposes tokens that the main model checks in one pass. Use SageMaker's draft model, a JumpStart one or your own; or, since 25 November 2025, train EAGLE heads (EAGLE 2 or 3, chosen by architecture) on your own data for up to 2.5 times the throughput. Compilation and speculative decoding can't be combined.
  • Fast model loading: pre-shards the weights (OPTION_TENSOR_PARALLEL_DEGREE, which must divide the instance's GPU count) so they stream straight from S3 to the GPUs. Sharded models deploy to inference-component endpoints and can't use network isolation.
Quantize a model to AWQ for ml.g6.12xlarge (Python, boto3) 
sm.create_optimization_job(
    OptimizationJobName="llama31-8b-awq",
    RoleArn="arn:aws:iam::111111111111:role/SageMakerExecutionRole",
    ModelSource={"S3": {"S3Uri": "s3://ml-111111111111/models/llama-3-1-8b/",
                        "ModelAccessConfig": {"AcceptEula": True}}},
    DeploymentInstanceType="ml.g6.12xlarge",
    OptimizationConfigs=[{"ModelQuantizationConfig": {"OverrideEnvironment": {"OPTION_QUANTIZE": "awq"}}}],
    OutputConfig={"S3OutputLocation": "s3://ml-111111111111/optimized/llama31-8b-awq/"},
    StoppingCondition={"MaxRuntimeInSeconds": 36000},
)

job = sm.describe_optimization_job(OptimizationJobName="llama31-8b-awq")
# Status is upper case: INPROGRESS, COMPLETED, FAILED ...
print(job["OptimizationJobStatus"], job.get("OptimizationOutput", {}).get("RecommendedInferenceImage"))

Deploy the output by creating a model from the S3 location and the recommended image. For EAGLE, the configuration is {"ModelSpeculativeDecodingConfig": {"Technique": "EAGLE", "TrainingDataSource": {"S3Uri": ..., "S3DataType": "S3Prefix"}}} with training data in ShareGPT or OpenAI chat format; the job runs four training jobs in a row (AWS's examples allow 5 days). In SDK V3, ModelBuilder.optimize(instance_type=..., quantization_config=..., output_path=...) runs the job and returns a model you then deploy. Optimization jobs bill for the instances they use.

Inference recommendations and benchmarks

Since 21 April 2026, AWS calls its generative AI inference recommendations "the recommended approach for most customers", with manual optimization jobs the do-it-yourself route. You give a model (Hugging Face format with safetensors) and one goal (lowest cost, lowest time to first token, or highest throughput); SageMaker tries optimizations, benchmarks them on up to three instance types with NVIDIA AIPerf, and returns ranked deployment configurations with measured latency, throughput and cost.

Get recommendations and deploy the best one (Python, SageMaker Python SDK V3) 
from sagemaker.serve import ModelBuilder

mb = ModelBuilder(model="s3://ml-111111111111/models/qwen3-8b/",
                  role_arn="arn:aws:iam::111111111111:role/SageMakerExecutionRole")

# One target: "throughput", "ttft-ms" or "cost"; up to three instance types
mb.generate_deployment_recommendations(
    performance_target="ttft-ms",
    instance_types=["ml.g6e.2xlarge", "ml.g5.2xlarge"],
    output_path="s3://ml-111111111111/recommendations/qwen3-8b/",
)
for rec in mb.recommendations:
    print(rec)

mb.deploy(role="arn:aws:iam::111111111111:role/SageMakerExecutionRole", recommendation_index=0)
  • APIs: CreateAIWorkloadConfig (the traffic to simulate: concurrency, prompt and output token counts, streaming, or your own data), CreateAIRecommendationJob, and CreateAIBenchmarkJob, which load-tests an existing endpoint through its OpenAI-compatible API (list the inference components, or it fails). Results can go to MLflow (June 2026), and LoRA adapters can be included (July 2026).
  • Studio: Jobs, Inference optimization; custom benchmarks typically take one to three hours, and the test endpoints are deleted afterwards.
  • Cost and quotas: no service fee, but you pay for the benchmark compute (existing training plan reservations can be used); 2 parallel recommendation and 2 parallel benchmark jobs by default.
  • Classic Inference Recommender is still available for any model: CreateInferenceRecommendationsJob with JobType Default (instance recommendations within about 45 minutes) or Advanced (a custom load test with traffic phases and latency limits, about 2 hours), for real-time or serverless endpoints. Exams still name it as the way to choose an instance type.

SageMaker Neo

Neo compiles trained models (TensorFlow, Keras, PyTorch, MXNet, ONNX, TF-Lite, XGBoost and others) for a target: cloud instance families such as ml_c5, ml_g4dn and ml_inf1, or edge devices such as NVIDIA Jetson and Raspberry Pi, with a small runtime (DLR) on the device. Start a job with CreateCompilationJob: InputConfig (the S3 artifact, the framework and the input shape in DataInputConfig) and OutputConfig (a TargetDevice, or a TargetPlatform by OS, architecture and accelerator). Its framework versions are old (PyTorch up to 2.0, for example); for current LLMs on Inferentia2 and Trainium use Neuron through optimization jobs.

SageMaker Edge Manager reached end of life on 26 April 2024: its console, packaging jobs and device fleets are gone and its APIs no longer work. AWS suggests ONNX Runtime with AWS IoT Greengrass V2 for managing models on devices. MLA-C02 dropped "SageMaker Neo edge optimization"; AIP-C01 still lists Neo as in scope.

Metrics to watch

  • Latency: ModelLatency is the time inside your container and OverheadLatency is SageMaker's own time, both in microseconds; total latency adds the network. A rising OverheadLatency on serverless points at cold starts, as does ModelSetupTime.
  • Traffic and errors: Invocations, InvocationsPerInstance, Invocation4XXErrors, Invocation5XXErrors and InvocationModelErrors; concurrency metrics ConcurrentRequestsPerModel and ConcurrentRequestsPerCopy.
  • Instances: CPU, memory, GPU, GPU memory and disk in /aws/sagemaker/Endpoints (batch jobs in /aws/sagemaker/TransformJobs, without disk).
  • Detailed observability (18 June 2026, on by default for new real-time endpoint configurations): OpenTelemetry metrics for time to first token, inter-token latency, KV cache, queue depth, tokens per second and per-GPU use, lifecycle events such as cold starts, a SageMaker AI Insights dashboard in CloudWatch and PromQL queries. No extra SageMaker charge; CloudWatch charges may apply. MetricsConfig also sets publish frequency (10 to 300 seconds) and per-instance and per-GPU dimensions.

Security, quotas and pricing

  • Async permissions: the execution role needs s3:GetObject, s3:PutObject and s3:AbortMultipartUpload on the objects, s3:ListBucket on the bucket, and sns:Publish on the topics (plus KMS permissions for encrypted topics). Callers need sagemaker:InvokeEndpointAsync. OutputConfig.KmsKeyId encrypts results in S3.
  • Batch encryption and network: TransformOutput.KmsKeyId (the key policy must allow the model's role), VolumeKmsKeyId (not on instance types with local NVMe storage) and a key for captured data. The model's VpcConfig and network isolation apply to batch jobs too.
  • Quotas: 4 instances across all transform jobs by default and per-type transform quotas at 0 on new accounts; 2 parallel Neo compilation jobs; async endpoints share the endpoint instance quotas.
  • Pricing: async and batch bill per instance-hour for the instances running (AWS's async example: ml.c5.xlarge at $0.20 an hour for 77.5 hours, $16.38 a month); there's no charge for S3 reads and writes in the same Region. SageMaker Savings Plans cover batch transform; async isn't named.

What's changed

  • 2026: generative AI inference recommendations and benchmarks (21 April); instance pools for real-time and async endpoints (May); MLflow tracking for recommendation jobs (June); detailed observability (18 June); automatic container image caching (30 June); LoRA adapters in recommendations (July); Model Monitor closed to new customers (30 July).
  • 2025: EAGLE speculative decoding trained on your data (25 November).
  • 2024: Edge Manager end of life (26 April); fast model loading in optimization jobs (November); SageMaker renamed SageMaker AI (3 December); container caching and Fast Model Loader (6 December).
