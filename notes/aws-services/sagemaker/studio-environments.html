How Studio is organized

SageMaker Studio is a web environment (free to use; you pay for the instances and storage behind it) built from four levels:

  • Domain: one per team or environment, in a Region. It holds the network settings (VPC, subnets, internet access), the authentication mode, default settings for users and spaces, an optional EFS file system and the encryption key.
  • User profile: one per person, with its own settings (execution role, security groups, allowed instance types and images) that override the domain defaults.
  • Space: a persistent workspace with its own EBS volume. A private space belongs to one user; a shared space is open to everyone in the domain, with real-time co-editing.
  • App: what runs in a space on an ML instance: JupyterLab 4, Code Editor (based on Code-OSS, with Open VSX extensions and the AWS Toolkit), plus RStudio, Canvas and MLflow. Each space runs one app.

Which environment to use: Studio for teams (several IDEs, idle shutdown, remote IDEs, MLflow, Identity Center sign-in); a notebook instance for one person who wants a single Jupyter VM with no domain; Unified Studio when the same people also work on data and analytics (lakehouse, SQL, Spark, Bedrock) in governed projects.

Creating a domain

Quick setup or custom setup

  • Quick setup (about 20 seconds since June 2026) creates a domain and one user in the default VPC with public internet access, a new execution role with broad policies (AmazonSageMakerFullAccess, Canvas policies, AmazonS3FullAccess and model customization access), and an S3 bucket. It's for trying things, not for production. It doesn't create EFS, so RStudio doesn't appear until you enable EFS with UpdateDomain.
  • Custom setup lets you choose the authentication mode, users, apps, VPC, subnets and security groups, KMS key and storage limits. Use it, or CloudFormation (AWS::SageMaker::Domain), for anything shared.
  • Since October 2026, new customers can also sign up straight into Studio with a Google, GitHub or Apple login and free credits, without setting up an AWS account the usual way.

IAM or IAM Identity Center

AuthMode is fixed at creation. With SSO (Identity Center, organization instances only) users sign in through the access portal and you assign groups; Amazon Q Developer settings need it. With IAM users open Studio from the console or through presigned URLs (CreatePresignedDomainUrl), and only IAM domains let you restrict access to particular VPCs, VPC endpoints or IP ranges.

A VPC-only domain with idle shutdown, a user, a private JupyterLab space, and a presigned URL (Python, boto3) 
import boto3

sm = boto3.client("sagemaker", region_name="us-east-1")
ROLE = "arn:aws:iam::111111111111:role/SageMakerStudioExecutionRole"

domain_id = sm.create_domain(
    DomainName="ml-team",
    AuthMode="IAM",
    AppNetworkAccessType="VpcOnly",
    VpcId="vpc-0example",
    # Private subnets only in VpcOnly mode
    SubnetIds=["subnet-0aaa", "subnet-0bbb"],
    # Encrypts the domain's EFS and EBS volumes; can't be changed later
    KmsKeyId="arn:aws:kms:us-east-1:111111111111:key/EXAMPLE-KEY-ID",
    DefaultUserSettings={
        "ExecutionRole": ROLE,
        "SecurityGroups": ["sg-0team"],
        "DefaultLandingUri": "studio::",
        "StudioWebPortal": "ENABLED",
        "SpaceStorageSettings": {"DefaultEbsStorageSettings": {"DefaultEbsVolumeSizeInGb": 5, "MaximumEbsVolumeSizeInGb": 100}},
        "JupyterLabAppSettings": {
            "DefaultResourceSpec": {"InstanceType": "ml.t3.medium"},
            # Shut apps down after 2 idle hours; users may choose 1 to 8 hours
            "AppLifecycleManagement": {"IdleSettings": {
                "LifecycleManagement": "ENABLED",
                "IdleTimeoutInMinutes": 120, "MinIdleTimeoutInMinutes": 60, "MaxIdleTimeoutInMinutes": 480,
            }},
        },
    },
    # Shared spaces take their role from here, not from user settings
    DefaultSpaceSettings={"ExecutionRole": ROLE},
    # Records the user profile name as the role session's source identity in CloudTrail
    DomainSettings={"ExecutionRoleIdentityConfig": "USER_PROFILE_NAME"},
)["DomainId"]
# Wait until describe_domain shows Status InService

# User security groups are added to the domain's; other user settings override the domain's
sm.create_user_profile(DomainId=domain_id, UserProfileName="user-a", UserSettings={"SecurityGroups": ["sg-0usera"]})

sm.create_space(
    DomainId=domain_id,
    SpaceName="user-a-jl",
    OwnershipSettings={"OwnerUserProfileName": "user-a"},
    SpaceSharingSettings={"SharingType": "Private"},
    SpaceSettings={"AppType": "JupyterLab", "SpaceStorageSettings": {"EbsStorageSettings": {"EbsVolumeSizeInGb": 20}}},
)
# Starting the app starts the instance (JupyterLab and Code Editor apps are named "default")
sm.create_app(DomainId=domain_id, SpaceName="user-a-jl", AppType="JupyterLab", AppName="default",
              ResourceSpec={"InstanceType": "ml.m5.large"})

url = sm.create_presigned_domain_url(
    DomainId=domain_id, UserProfileName="user-a", SpaceName="user-a-jl",
    # Single-use link valid 5 to 300 seconds; the session lasts 30 minutes to 12 hours
    ExpiresInSeconds=300, SessionExpirationDurationInSeconds=43200,
    LandingUri="app:JupyterLab:",
)["AuthorizedUrl"]

Spaces and apps

  • Storage: each JupyterLab or Code Editor space has its own EBS volume mounted at /home/sagemaker-user; apps can't see each other's volumes. The default size is 5 GB and users can grow it to 100 GB unless you change the limit (up to 16,384 GB); a volume can be resized only once every six hours. Data outside the home folder is lost when the app stops.
  • Start and stop: starting an app (CreateApp) starts an instance; stopping it is DeleteApp, which releases the instance but keeps the space's files. Deleting the space deletes its volume. Stop the space before changing its instance type; GPU instances need a GPU image.
  • Idle shutdown (JupyterLab and Code Editor, SageMaker Distribution 2.0 or later): set at domain or user level with a timeout between 60 and 525,600 minutes (the console default is 7 days), and a minimum and maximum each user may choose within; set all three to the same value to enforce one. An app is idle when JupyterLab has no kernels or terminals running, or Code Editor has no file changes, open files or terminal activity. Running apps pick up new settings only after a restart.
  • Recovery mode (April 2025) starts an app in a minimal environment with a terminal and file browser to fix a broken Conda setup or a full disk.
  • Images: apps run the SageMaker Distribution image (PyTorch, TensorFlow, scikit-learn, pandas, JupyterLab and Code Editor). Major versions come every six months with 18 months of support; 4.x is current and 3.x reached end of support on 29 September 2026. Amazon Q Developer is built into both IDEs, and the AWS AI/ML skill from the Agent Toolkit for AWS is pre-installed in JupyterLab (October 2026) for coding agents.

Lifecycle configurations and images

Lifecycle configurations

A Studio lifecycle configuration is a shell script that runs each time an app starts: install packages, set Git or proxy settings, or add auto-shutdown on older images. It must finish within 5 minutes (run long work in the background with nohup), is stored base64-encoded (up to 16,384 characters) and logs to CloudWatch group /aws/sagemaker/studio. Attach scripts to the domain or user profile: users can pick only from the attached list, a default one is preselected, and a built-in one set by the admin always runs first.

Create a JupyterLab lifecycle configuration and make it the domain default (AWS CLI) 
cat > lcc.sh <<'EOF'
#!/bin/bash
set -eux
pip install --quiet sagemaker-mlflow
EOF

LCC_ARN=$(aws sagemaker create-studio-lifecycle-config \
  --studio-lifecycle-config-name jl-mlflow \
  --studio-lifecycle-config-content "$(openssl base64 -A -in lcc.sh)" \
  --studio-lifecycle-config-app-type JupyterLab \
  --query StudioLifecycleConfigArn --output text)

aws sagemaker update-domain --domain-id d-exampleid --default-user-settings "{
  \"JupyterLabAppSettings\": {
    \"LifecycleConfigArns\": [\"$LCC_ARN\"],
    \"DefaultResourceSpec\": {\"LifecycleConfigArn\": \"$LCC_ARN\"}
  }
}"

Enforce approved scripts with the sagemaker:StudioLifecycleConfigArns condition key on CreateApp, CreateSpace and the domain and user profile actions.

Custom images

To bring your own image: push it to ECR in the same Region, then CreateImage, CreateImageVersion and CreateAppImageConfig (with JupyterLabAppImageConfig or CodeEditorAppImageConfig), and add it to the domain's CustomImages. The image must run as UID 1000 and GID 100, can't change the home mount path, and must not use /opt/ml. Building on a SageMaker Distribution image keeps idle shutdown and remote access working. Restrict images with sagemaker:ImageArns.

Remote IDE access

Since July 2025 you can open a Studio space from a local VS Code, and since March 2026 from Kiro or Cursor, through a deep link in Studio, the AWS Toolkit, or SSH. The connection goes through Systems Manager Session Manager.

  • Requirements: the space needs at least 8 GB of memory (ml.t3.medium and other small types aren't supported), SageMaker Distribution 2.7 or later, and Remote Access turned on (SpaceSettings.RemoteAccess). Locally: the Remote-SSH extension, the Session Manager plugin and a recent IDE and Toolkit.
  • Permissions: sagemaker:StartSession on the space. Scope it to the user's own spaces; a wildcard lets anyone open anyone's space.
  • Private subnets: add the ssm and ssmmessages VPC endpoints, plus an HTTP proxy for the IDE server download (VS Code also supports a pre-packaged server installed by a lifecycle configuration). Cursor can't connect to spaces without outbound internet.

Remote IDE sessions authenticate with IAM credentials even on Identity Center domains, and a session can stay alive for up to 12 hours after the user signs out of Identity Center. If that's not acceptable, deny CreateSpace and UpdateSpace with sagemaker:RemoteAccess set to ENABLED (see Security).

VPC-only mode

In the default PublicInternetOnly mode only EFS traffic uses your VPC; everything else goes through a VPC managed by SageMaker AI with internet access. In VpcOnly mode all traffic goes through your subnets and there's no internet unless you add a NAT gateway.

  • Subnets: private only, across Availability Zones, with 2 to 4 IP addresses per user.
  • Security groups: allow NFS (TCP 2049) to EFS and TCP 8192-65535 within the group. Give each user profile its own security group: one shared self-referencing group lets every user's apps reach every other's.
  • Interface endpoints: sagemaker.api and sagemaker.runtime (needed for notebooks, training and hosting), S3, sts and logs for the Python SDK, servicecatalog for Projects, ssm and ssmmessages for remote IDEs, and any other service your code calls.
  • Studio UI over PrivateLink: an interface endpoint for aws.sagemaker.REGION.studio (with the API endpoint for presigned URLs); allow websockets through firewalls. On IAM domains, restrict CreatePresignedDomainUrl with aws:SourceVpce or aws:SourceVpc.

Force the mode across accounts with an SCP that denies sagemaker:CreateDomain unless sagemaker:AppNetworkAccessType is VpcOnly.

Notebook instances

A notebook instance is one ML instance running Jupyter (conda kernels for Python, PyTorch and R), with an EBS volume where only /home/ec2-user/SageMaker persists. It's still supported and common in exam questions.

Amazon Linux 2 notebook instances reached end of support on 30 June 2026. Since 1 July 2026 you can't create AL2 instances or restart stopped ones, and since 1 August AWS upgrades the remaining ones to Amazon Linux 2023 in phases. The default platform is notebook-al2023-v1 (JupyterLab 4, dnf instead of yum; not available on ml.p2, p3, p3dn, inf1 or g3). Migrate in place: stop the instance, call UpdateNotebookInstance with PlatformIdentifier=notebook-al2023-v1, then start it; files in /home/ec2-user/SageMaker are kept.

  • Network: with a SubnetId SageMaker adds a network interface in your VPC. DirectInternetAccess=Disabled (allowed only with a subnet) removes the SageMaker-provided internet path, so the VPC needs a NAT gateway or VPC endpoints to reach S3 and SageMaker.
  • Root access is Enabled by default; disable it for users, but lifecycle scripts still run as root.
  • Lifecycle configurations: an OnCreate script (first creation) and an OnStart script (every start), each limited to 5 minutes or the instance fails to start; logs go to /aws/sagemaker/NotebookInstances. The AWS samples repository includes an idle auto-stop script, the usual answer to "notebooks left running".
  • Other settings: VolumeSizeInGB 5 to 16,384 (default 5), KmsKeyId for the volume, Git repositories, and IMDSv2 only (MinimumInstanceMetadataServiceVersion). AWS patches the software at least every 90 days; restart monthly to pick up fixes.

Studio Classic and Unified Studio

From Studio Classic to Studio

Studio Classic (the JupyterServer app type) can't be onboarded and has had no updates since the end of 2024 (feature status). Moving an existing domain is mostly a setting change: test in a separate domain, set DefaultLandingUri to studio::, check the execution role's permissions and VPC endpoints, then optionally move custom images and lifecycle scripts, copy home-directory data from the Classic EFS with AWS DataSync, and move Data Wrangler flows to Canvas. Classic stays reachable as an app inside Studio meanwhile.

From Studio to Unified Studio

An open-source AWS tool (June 2025) imports a SageMaker AI domain, its user profiles and spaces into a Unified Studio project, and jobs, models, endpoints and pipelines become visible there. It works only for IAM-authenticated domains that use a single domain-level execution role, into a Unified Studio domain in the same account, Region and VPC, and it doesn't move RStudio or shared spaces. Users can use both portals during the transition, and administrators can then turn off Studio access.

Managed MLflow

SageMaker AI runs MLflow for you to track experiments (parameters, metrics, artifacts), compare runs, register models and, since MLflow 3 (July 2025), trace generative AI applications. Compute and the metadata store live in the service; artifacts go to your S3 bucket. There are two forms, and AWS says to prefer MLflow Apps:

A policy that grants only sagemaker-mlflow:* works for Tracking Servers but not for MLflow Apps, whose clients need sagemaker:CallMlflowAppApi. App calls appear in CloudTrail only as data events (all named CallMlflowApp), which are off by default.

Create an MLflow App with automatic registration into the SageMaker Model Registry (AWS CLI; flag names follow the API's parameter names) 
aws sagemaker create-mlflow-app \
  --name team-mlflow \
  --artifact-store-uri s3://mlflow-artifacts-111111111111 \
  --role-arn arn:aws:iam::111111111111:role/MlflowAppServiceRole \
  --model-registration-mode AutoModelRegistrationEnabled

The service role trusts sagemaker.amazonaws.com and needs S3 access to the artifact bucket plus sagemaker:CreateModelPackageGroup, CreateModelPackage, UpdateModelPackage, DescribeModelPackageGroup and AddTags for registration. Open the MLflow UI from Studio or with CreatePresignedMlflowAppUrl.

Log a run, register the model and trace Bedrock calls (Python; pip install sagemaker-mlflow and an mlflow version that matches the server) 
import mlflow
from mlflow.models import infer_signature
from sklearn.datasets import make_regression
from sklearn.ensemble import RandomForestRegressor

# The app or tracking server ARN is the tracking URI; the plugin signs requests with SigV4
mlflow.set_tracking_uri("arn:aws:sagemaker:us-east-1:111111111111:mlflow-app/app-EXAMPLE")
mlflow.set_experiment("demand-rf")

X, y = make_regression(n_features=4, n_informative=2, random_state=0)
params = {"n_estimators": 50, "random_state": 42}
with mlflow.start_run() as run:
    model = RandomForestRegressor(**params).fit(X, y)
    mlflow.log_params(params)
    mlflow.log_metric("train_r2", model.score(X, y))
    mlflow.sklearn.log_model(model, name="model", signature=infer_signature(X, model.predict(X)), input_example=X[:3])

# With automatic registration this also creates a SageMaker model package group and version
mv = mlflow.register_model(f"runs:/{run.info.run_id}/model", "demand-rf")
client = mlflow.MlflowClient()
print(client.get_model_version("demand-rf", mv.version).tags["sagemaker.model_package_arn"])

# MLflow 3 tracing: record every boto3 bedrock-runtime call made after this
mlflow.bedrock.autolog()
  • Registry sync: an MLflow registered model becomes a model package group named after it with a short suffix; model names can't contain spaces. Stage aliases such as sagemakerlifecycle-staging-pending map to SageMaker lifecycle stages, but deployment from Studio still needs the package's ModelApprovalStatus set to Approved.
  • Training jobs log to MLflow with MlflowConfig (MlflowResourceArn, MlflowExperimentName, MlflowRunName) on CreateTrainingJob; it accepts an app or a tracking server ARN.
  • Downloads through managed MLflow are limited to 200 MB. Don't delete the service role or change its trust while the app is in use, and allow up to 15 minutes for role changes to apply.

Pricing and cost controls

  • Studio is free; JupyterLab and Code Editor apps bill per instance-hour while running, and each space's EBS volume bills until the space is deleted, even with the app stopped. EFS (if enabled) bills at EFS rates.
  • Notebook instances bill per instance-hour while InService, plus the volume.
  • RStudio: the small RStudioServerPro app is free; larger ones and RSession apps bill per instance. You need a Posit licence.
  • Free tier (first two months): 250 hours a month of ml.t3.medium for Studio notebooks or notebook instances. SageMaker Savings Plans cover Studio and notebook instances.
  • Controls: built-in idle shutdown, auto-stop lifecycle scripts for notebook instances, sagemaker:InstanceTypes to restrict sizes, HiddenInstanceTypes in the UI, per-instance-type quotas (Code Editor on GPU starts at 0), Budgets, and the tags Studio adds automatically to resources created in shared spaces.

Security

Which execution role runs the code

Code in a private space runs as the user profile's execution role, or the domain default if the profile has none; a shared space uses DefaultSpaceSettings.ExecutionRole; remote IDE deep links use the space's role, falling back to the domain's. Many users often share one role, so set ExecutionRoleIdentityConfig to USER_PROFILE_NAME to record who acted, and use trusted identity propagation (Identity Center domains, August 2025) for per-user access to S3 Access Grants, Lake Formation, Athena, EMR and Redshift.

Keeping users out of each other's spaces

Studio policies can reference the caller's domain and profile as policy variables. Custom policies must also allow sagemaker:AddTags, because Studio tags what it creates.

Let users start apps only in their own private spaces or in shared spaces, and block remote IDE access (identity policy, adapted from the documented isolation examples) 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AppsInOwnPrivateSpaces",
      "Effect": "Allow",
      "Action": ["sagemaker:CreateApp", "sagemaker:DeleteApp"],
      "Resource": "arn:aws:sagemaker:*:111111111111:app/*",
      "Condition": {
        "ArnLike": { "sagemaker:OwnerUserProfileArn": "arn:aws:sagemaker:*:111111111111:user-profile/${sagemaker:DomainId}/${sagemaker:UserProfileName}" },
        "StringEquals": { "sagemaker:SpaceSharingType": "Private" }
      }
    },
    {
      "Sid": "AppsInSharedSpaces",
      "Effect": "Allow",
      "Action": ["sagemaker:CreateApp", "sagemaker:DeleteApp"],
      "Resource": "arn:aws:sagemaker:*:111111111111:app/*",
      "Condition": { "StringEquals": { "sagemaker:SpaceSharingType": "Shared" } }
    },
    {
      "Sid": "NoRemoteIde",
      "Effect": "Deny",
      "Action": ["sagemaker:CreateSpace", "sagemaker:UpdateSpace"],
      "Resource": "*",
      "Condition": { "StringEquals": { "sagemaker:RemoteAccess": "ENABLED" } }
    }
  ]
}

Other controls

  • Presigned URLs (IAM domains): allow CreatePresignedDomainUrl only on the user's own profile and only from your VPC endpoint; IAM policies are checked again on every request and websocket frame.
  • Condition keys on domains and spaces: sagemaker:AppNetworkAccessType, sagemaker:AuthMode, sagemaker:VpcSubnets, sagemaker:VpcSecurityGroupIds, sagemaker:VolumeKmsKeyArn, sagemaker:InstanceTypes, sagemaker:ImageArns, sagemaker:StudioLifecycleConfigArns and sagemaker:RemoteAccess; on notebook instances also sagemaker:RootAccess and sagemaker:DirectInternetAccess.
  • Encryption: the domain KmsKeyId covers EFS and EBS and is fixed at creation; notebook instances and MLflow Apps take their own keys; MLflow artifacts follow the S3 bucket's encryption.
  • Logging: CloudTrail records CreateDomain, CreatePresignedDomainUrl, CreateApp, StartSession and the rest; lifecycle script output goes to CloudWatch Logs.

What's changed

  • 2026: Kiro and Cursor as remote IDEs (26 March); AL2023 becomes the notebook instance default (15 May); GPU capacity for Studio from training plans (18 May); quick setup in under 20 seconds (2 June); AL2 notebook instances end of support (30 June) and automatic upgrades (from 1 August); Hugging Face one-click to Studio (6 July); KMS keys for MLflow Apps (24 August); SageMaker Distribution 3.x end of support (29 September); the AI/ML skill pre-installed in JupyterLab (13 October); sign-in with Google, GitHub or Apple (15 October); MLflow Apps on MLflow 3.16 (27 October); Identity Center domains across Regions (5 November).
  • 2025: Amazon Q Developer in Code Editor (January); recovery mode (April); the Studio to Unified Studio upgrade tool (June); JupyterLab 1 and 3 on notebook instances unsupported (30 June); VS Code remote access and managed MLflow 3.0 (10 July); trusted identity propagation for Studio (August); AL2023 notebook instances (9 October); serverless MLflow Apps (2 December); in-place notebook platform migration (5 December); faster custom image starts with SOCI indexing (December).
