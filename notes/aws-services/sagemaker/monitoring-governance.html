What changed in 2026

SageMaker Model Monitor, Clarify and Role Manager (with A2I, Debugger, Ground Truth and others) moved to maintenance: closed to new customers from 30 July 2026. Customers already using them can carry on, and AWS keeps them running and secure but adds no features. AWS doesn't define exactly who counts as an existing customer. Model Cards, Model Dashboard, the Model Registry, lineage and data capture are unaffected.

  • Instead of Model Monitor, AWS points to its open-source monitoring solutions (the aws-samples/sample-aiops-on-amazon-sagemakerai repository: drift reports with the Evidently library, results in MLflow, alerts through SNS, dashboards in QuickSight) plus CloudWatch endpoint metrics with anomaly detection. Existing users should delete monitoring schedules they no longer need, because each run starts a Processing job.
  • Instead of Clarify, compute the standard bias metrics with pandas and scikit-learn ("standardized arithmetic, not a library dependency"), explanations with the open-source SHAP library Clarify itself uses, and track results in MLflow; for foundation models use fmeval or Amazon Bedrock Evaluations and Guardrails. In Pipelines, a ClarifyCheck step becomes a Processing step.
  • Instead of Role Manager, create roles with IAM (or IaC) and AWS managed policies, and tighten them with IAM Access Analyzer policy generation; roles it already made keep working.

The exams moved too: MLA-C02 (since 29 September 2026) tests baselines, drift detection, bias and explanation as concepts, with CloudWatch, Bedrock evaluations and "drift detection pipelines" as the named tools; AIP-C01 still lists Clarify and Model Monitor as in scope; AIF-C01 names Model Cards, Bedrock Guardrails and Bedrock Model Evaluations. The Model Monitor and Clarify sections below are for existing users and exam scenarios.

Capturing inference data

Data capture works without Model Monitor and feeds any monitoring approach: SageMaker copies a sample of requests and responses to S3 asynchronously, without slowing calls.

Capture 20% of requests and responses on a real-time endpoint (Python, boto3) 
import boto3

sm = boto3.client("sagemaker")
sm.create_endpoint_config(
    EndpointConfigName="churn-cfg-capture",
    ProductionVariants=[{
        "VariantName": "AllTraffic", "ModelName": "churn-v14",
        "InstanceType": "ml.m5.xlarge", "InitialInstanceCount": 2,
    }],
    DataCaptureConfig={
        "EnableCapture": True,
        "InitialSamplingPercentage": 20,
        "DestinationS3Uri": "s3://ml-111111111111/capture",
        "KmsKeyId": "alias/ml-capture",
        "CaptureOptions": [{"CaptureMode": "Input"}, {"CaptureMode": "Output"}],
        # Without this, captured payloads are stored base64-encoded
        "CaptureContentTypeHeader": {"CsvContentTypes": ["text/csv"]},
    },
)
# Then update the endpoint to this configuration
sm.update_endpoint(EndpointName="churn-ep", EndpointConfigName="churn-cfg-capture")
  • Files are JSON Lines under DESTINATION/ENDPOINT/VARIANT/yyyy/mm/dd/hh/, a few minutes after the calls; each record holds the input, the output and eventMetadata with an eventId and, if the caller passed InferenceId to InvokeEndpoint, that ID.
  • Batch transform captures with DataCaptureConfig on CreateTransformJob; GenerateInferenceId adds an ID and time to each record.
  • Limits: capture pauses if the instance disk is over 75% full; serverless endpoints can't capture.

Model Monitor

Model Monitor compares captured traffic with a baseline on a schedule and reports violations. Four monitor types:

  • Data quality: missing values, wrong types, new categories and distribution drift in the inputs. No labels needed.
  • Model quality: accuracy, precision, recall, F1, AUC, RMSE and so on, by joining predictions with ground-truth labels you upload later.
  • Bias drift: Clarify's post-training bias metrics on live predictions (needs labels).
  • Feature attribution drift: changes in the SHAP ranking of features; alerts when the ranking similarity (NDCG) drops below 0.90.
Baseline from the training data, then an hourly data-quality schedule (Python, SageMaker Python SDK V2 as exams show it) 
from sagemaker.model_monitor import CronExpressionGenerator, DefaultModelMonitor
from sagemaker.model_monitor.dataset_format import DatasetFormat

role = "arn:aws:iam::111111111111:role/SageMakerExecutionRole"
monitor = DefaultModelMonitor(role=role, instance_count=1, instance_type="ml.m5.xlarge",
                              volume_size_in_gb=20, max_runtime_in_seconds=3600)

# Writes statistics.json and constraints.json; review and edit the constraints
monitor.suggest_baseline(
    baseline_dataset="s3://ml-111111111111/churn/train/train.csv",
    dataset_format=DatasetFormat.csv(header=True),
    output_s3_uri="s3://ml-111111111111/monitor/baseline",
    wait=True,
)

monitor.create_monitoring_schedule(
    monitor_schedule_name="churn-data-quality-hourly",
    endpoint_input="churn-ep",
    output_s3_uri="s3://ml-111111111111/monitor/reports",
    statistics=monitor.baseline_statistics(),
    constraints=monitor.suggested_constraints(),
    schedule_cron_expression=CronExpressionGenerator.hourly(),
    enable_cloudwatch_metrics=True,
)

In SDK V3 the same classes are in sagemaker.core.model_monitor; ModelQualityMonitor, ModelBiasMonitor and ModelExplainabilityMonitor cover the other types.

  • Baselines: the analyzer (Spark and Deequ) needs lowercase column names; the drift check compares distributions with a default threshold of 0.1 (linf_robust is based on the Kolmogorov-Smirnov test).
  • Schedules: hourly (cron(0 * ? * * *)), every N hours, or daily; runs can start up to 20 minutes late. NOW runs once over a window (DataAnalysisStartTime and DataAnalysisEndTime, at most 24 hours apart). Batch transform outputs can be monitored too.
  • Results: constraint_violations.json (data_type_check, completeness_check, baseline_drift_check, missing_column_check, extra_column_check, categorical_values_check) and CloudWatch metrics such as feature_baseline_drift_NAME, on which you set alarms.
  • Customization: preprocessing and postprocessing scripts (data and model quality monitors only) filter or reshape records; your own container can implement any check.
  • Limits: tabular data only; no multi-model endpoints; an inference pipeline is monitored as a whole; delete the schedule before the endpoint.

Model quality and drift

  • Ground truth: upload labels as JSON Lines to s3://.../yyyy/mm/dd/hh/ (by when you collected them), each with the eventId or your inferenceId, for example {"groundTruthData": {"data": "1", "encoding": "CSV"}, "eventMetadata": {"eventId": "..."}, "eventVersion": "0"}. Labels that arrive days later are handled with offsets such as start_time_offset="-P8D".
  • Hourly model quality schedules need MaxRuntimeInSeconds of 1,800 or less, because the merge job and the monitoring job share the hour.
  • Set problem_type (BinaryClassification, MulticlassClassification or Regression) and which attribute holds the prediction or probability.
  • Exam pattern: inputs changed but no labels yet is data quality drift; predictions are getting worse against labels is model quality; outcomes differ between groups is bias drift; the model relies on different features is feature attribution drift. The usual response is to investigate, then retrain on recent data through the pipeline.

Clarify: bias and explainability

  • Pre-training bias (in the data, before any model): class imbalance (CI), difference in proportions of labels (DPL), Kullback-Leibler (KL), Jensen-Shannon (JS), Lp-norm, total variation distance (TVD), Kolmogorov-Smirnov (KS) and conditional demographic disparity (CDD, method code CDDL).
  • Post-training bias (in the model's predictions): difference in positive proportions in predicted labels (DPPL), disparate impact (DI), difference in conditional acceptance and rejection, accuracy difference (AD), recall difference (RD), treatment equality (TE), flip test (FT), generalized entropy (GE) and others.
  • Explainability: Kernel SHAP feature attributions (global and per record) and partial dependence plots; online explainability (ExplainerConfig on the endpoint configuration) returns SHAP values with each prediction.
  • Configuration: the facet is the sensitive attribute (such as age or gender), label_values_or_threshold defines the positive outcome, and group_name groups records for CDD.
A pre-training bias report (Python, SageMaker Python SDK V3) 
from sagemaker.core.clarify import BiasConfig, DataConfig, SageMakerClarifyProcessor

role = "arn:aws:iam::111111111111:role/SageMakerExecutionRole"
processor = SageMakerClarifyProcessor(role=role, instance_count=1, instance_type="ml.m5.xlarge")

data_config = DataConfig(
    s3_data_input_path="s3://ml-111111111111/loans/train.csv",
    s3_output_path="s3://ml-111111111111/clarify/pre-training",
    label="approved",
    headers=["approved", "age_group", "income", "loan_amount", "term"],
    dataset_type="text/csv",
)
# Is "approved = 1" as common for age_group 1 as for everyone else?
bias_config = BiasConfig(label_values_or_threshold=[1], facet_name="age_group", facet_values_or_threshold=[1])

processor.run_pre_training_bias(data_config=data_config, data_bias_config=bias_config,
                                methods=["CI", "DPL", "KL", "CDDL"])

The job writes analysis.json and a report (notebook, HTML and PDF) to the output path. In SDK V2 the classes are in sagemaker.clarify. Model Cards can read Clarify and Model Monitor result files as evaluation details.

Monitoring without Model Monitor

AWS's replacement samples run the checks as ordinary jobs: a Processing job (on a schedule, or as a pipeline step after batch transform) reads the training baseline and recent captured data, computes drift with Evidently, logs the report to MLflow and publishes to SNS if something drifted.

The core of a drift check inside a Processing job (Python, Evidently and MLflow) 
import boto3
import mlflow
import pandas as pd
from evidently import DataDefinition, Dataset, Report
from evidently.presets import DataDriftPreset

baseline = pd.read_csv("/opt/ml/processing/baseline/train.csv")
current = pd.read_csv("/opt/ml/processing/current/recent.csv")

snapshot = Report(metrics=[DataDriftPreset()]).run(
    reference_data=Dataset.from_pandas(baseline, data_definition=DataDefinition()),
    current_data=Dataset.from_pandas(current, data_definition=DataDefinition()),
)
snapshot.save_html("/opt/ml/processing/output/drift.html")

# Log to a SageMaker MLflow App (needs the sagemaker-mlflow plugin)
mlflow.set_tracking_uri("arn:aws:sagemaker:us-east-1:111111111111:mlflow-app/app-churn")
mlflow.set_experiment("churn-monitoring")
with mlflow.start_run(run_name="drift-check"):
    mlflow.log_artifact("/opt/ml/processing/output/drift.html")

# The AWS sample alerts only when columns drifted; read that from the report
# (snapshot.dict()), whose metric names depend on the Evidently version
boto3.client("sns").publish(
    TopicArn="arn:aws:sns:us-east-1:111111111111:ml-alerts",
    Subject="Churn model drift report",
    Message="Drift report logged to MLflow experiment churn-monitoring",
)

The AWS samples pin evidently>=0.7.20, mlflow 3.10 and sagemaker-mlflow 0.2. Other samples in the repository trigger Lambda functions on new capture files, build QuickSight dashboards over an Athena table, and evaluate LLM endpoints with MLflow and Bedrock judges.

  • Operational monitoring: CloudWatch alarms with anomaly detection on ModelLatency, Invocation5XXErrors or utilization learn normal daily and weekly patterns and alert on deviations (see metrics to watch).
  • Bias metrics yourself: CI is (n_a - n_d) / (n_a + n_d) for the advantaged and disadvantaged groups, and DPL is the difference in their positive-label rates; both are a few lines of pandas.

Monitoring generative AI models

  • Performance: detailed observability on real-time endpoints (time to first token, inter-token latency, KV cache, GPU) in the SageMaker AI Insights dashboard.
  • Safety: Amazon Bedrock Guardrails can check text from any model with ApplyGuardrail, so a SageMaker-hosted model's prompts and answers can be filtered for harmful content, denied topics and sensitive information.
  • Quality: Bedrock evaluations accept your own responses (modelResponses in the dataset), so an LLM judge can score a SageMaker model's answers without Bedrock calling it; MLflow GenAI evaluations do the same inside your code.
Check a SageMaker model's answer with a guardrail (Python, boto3) 
import boto3

brt = boto3.client("bedrock-runtime")
answer = "..."  # text returned by your SageMaker endpoint

resp = brt.apply_guardrail(
    guardrailIdentifier="gr-support-01",
    guardrailVersion="3",
    source="OUTPUT",
    content=[{"text": {"text": answer}}],
)
if resp["action"] == "GUARDRAIL_INTERVENED":
    answer = resp["outputs"][0]["text"]  # the guardrail's blocked or masked message

Model Cards and Model Dashboard

A model card documents a model for reviewers and auditors: overview, intended uses and risk rating (High, Medium, Low or Unknown), business details, training details, evaluation results and additional information such as ethical considerations and caveats. Its status moves through Draft, PendingReview, Approved and Archived.

Create a draft model card (Python, boto3) 
import json

import boto3

sm = boto3.client("sagemaker")
sm.create_model_card(
    ModelCardName="churn-xgb",
    ModelCardStatus="Draft",
    # Content is a JSON string (up to 100,000 characters) in the model card schema
    Content=json.dumps({
        "model_overview": {"model_description": "Predicts customer churn in the next 90 days",
                           "model_owner": "ml-platform"},
        "intended_uses": {"purpose_of_model": "Prioritize retention offers",
                          "risk_rating": "Medium"},
        "additional_information": {"caveats_and_recommendations": "Retrain quarterly; not for credit decisions"},
    }),
    SecurityConfig={"KmsKeyId": "alias/model-cards"},
)
sm.create_model_card_export_job(ModelCardExportJobName="churn-xgb-pdf", ModelCardName="churn-xgb",
                                OutputConfig={"S3OutputPath": "s3://ml-111111111111/model-cards/"})
  • Versions: every edit except a status change creates a new, immutable version (100 per account by default); archived cards can't be edited but can still be exported to PDF.
  • Model Registry: each model package version can carry its own simplified card (since June 2024), so the documentation travels with the version that gets approved.
  • Sharing: share cards with other accounts through AWS RAM, read-only or with export; KMS-encrypted cards also need the key policy to allow that account.
  • Model Dashboard (in the console) lists every model with its risk rating, endpoint health, latest batch job and the status of its Model Monitor monitors, and opens each model's lineage graph, card and alert history. For new customers the monitor columns stay empty, since Model Monitor is closed to them.

Access, audit and compliance

  • Roles without Role Manager: AWS maps its personas to managed policies: AmazonSageMakerFullAccess for data scientists, plus AmazonSageMakerPipelinesIntegrations for MLOps, AmazonSageMakerReadOnly, the Canvas policies, AmazonSageMakerFeatureStoreAccess, AmazonSageMakerModelRegistryFullAccess and AmazonSageMakerModelGovernanceUseAccess (model cards and monitoring alerts). AmazonSageMakerJobFullAccess and AmazonSageMakerJobRuntimeAccess (June 2026) are for job execution roles. Start broad, then let IAM Access Analyzer generate a tighter policy from 30 to 90 days of CloudTrail activity.
  • CloudTrail: every control-plane call (creating jobs, models, endpoints, approvals) is a management event, logged by default.
  • AWS Config has about 35 managed SageMaker rules, such as sagemaker-endpoint-configuration-kms-key-configured, sagemaker-notebook-no-direct-internet-access, sagemaker-model-isolation-enabled, sagemaker-model-in-vpc and sagemaker-domain-in-vpc, to detect configurations that break policy.
  • GuardDuty AI Protection (July 2026) analyzes model invocation events from SageMaker AI and Bedrock for anomalous use and cost harvesting with stolen credentials, without a trail; it's out of scope for MLA-C02 and AIF-C01.
  • Data lineage and catalogs: SageMaker's own lineage tracking, AWS Glue Data Catalog (which AIP-C01 names for data lineage) and the SageMaker Catalog in Unified Studio for publishing and subscribing to governed data.

InvokeEndpoint calls are CloudTrail data events: not logged unless you add data events to a trail (an extra cost), not shown in Event history, and recorded without the request body. To audit who called a model with what, log at the application or use data capture.

Quotas and pricing

  • Model Monitor: at most 10 monitoring schedules (not adjustable); each run is a Processing job billed per instance-second, with up to 30 hours a month of built-in monitoring included (AWS's example: a daily 5-minute job on ml.m5.4xlarge costs about $2.31 a month).
  • Clarify and the replacement jobs bill as Processing jobs; data capture costs only the S3 storage.
  • Model cards: 100 versions and 20 concurrent export jobs by default, no separate charge listed.
  • Other services: CloudWatch anomaly detection alarms, CloudTrail data events, AWS Config rule evaluations and GuardDuty AI Protection (per GB of events analyzed) are billed by those services.

What's changed

  • 2026: endpoint enhanced metrics (April); new job execution managed policies (4 June); detailed observability for inference (18 June); Model Monitor, Clarify, Role Manager and others moved to maintenance (announced 30 June, closed to new customers 30 July); GuardDuty AI Protection covering SageMaker AI (July); MLA-C02 replaced MLA-C01 without naming Clarify or Model Monitor (29 September); AIF-C01 guide 1.2 names Model Cards (29 October).
  • 2025: last release of the fmeval library (July); AWS's AIOps samples repository created (September).
  • 2024: model cards integrated with the Model Registry and an updated model governance policy (4 June).
