Data preparation and Feature Store

Getting data ready for training and serving: Processing jobs for scripted preparation at scale, Canvas with Data Wrangler for visual preparation and no-code models, Feature Store for sharing consistent features between training and inference, what happened to Ground Truth and A2I, and where the other AWS data services fit.

Choosing a data preparation tool

  • Processing jobs: your own Python, scikit-learn or Spark code on managed instances, started from a notebook or as a pipeline step. The default for repeatable feature engineering and evaluation.
  • Canvas with Data Wrangler: visual preparation with 300+ transforms, data quality reports and a chat assistant, for analysts or for exploring data before writing code; flows export to Processing, Pipelines, Feature Store or Python.
  • Feature Store: where finished features live, so training and real-time inference read the same values.
  • Other AWS services: AWS Glue and Spark on Amazon EMR for large ETL, AWS Glue DataBrew for visual cleaning outside SageMaker (250+ transforms), AWS Glue Data Quality for rule-based validation, Amazon Athena for SQL over S3, and data processing jobs in SageMaker Unified Studio.

MLA-C02 Domain 1 (28% of the exam) names Glue, DataBrew, Spark on EMR, Data Wrangler and Feature Store for transforming and storing features, and DataBrew and Glue Data Quality for validation; AIP-C01 Task 1.3 names Glue Data Quality, Data Wrangler and SageMaker Processing.

Processing jobs

A Processing job starts instances, copies or streams the inputs under /opt/ml/processing/, runs your container (any image, with ContainerEntrypoint and arguments), uploads whatever the code writes to the output folders, and stops. AWS provides scikit-learn and Spark images; any other image works too.

  • Inputs (up to 10): S3 prefixes or manifests, in File mode (copied first) or Pipe mode (streamed; Gzip input only works with Pipe), either FullyReplicated to every instance or ShardedByS3Key to split objects between instances. A DatasetDefinition can run an Athena or Redshift query and feed the result as an input; it defaults to ShardedByS3Key.
  • Outputs (up to 10): S3 locations uploaded at the end (EndOfJob) or while running (Continuous), with one KMS key for all of them. A Feature Store output only names the feature group; your script still writes the records.
  • Instances: 1 to 100 per job, with a storage volume of 1 to 16,384 GB (local NVMe on instance types that have it, which can't take a VolumeKmsKeyId). Since September 2026, InstancePreferences lists up to five instance types to fall back through when capacity is short.
  • Run time: the account quota caps jobs at 5 days by default (adjustable; the API allows 9), and the SDK sets 24 hours if you don't.
  • Inside the container: /opt/ml/config/resourceconfig.json lists the hosts for multi-instance work; logs and CPU, memory, GPU and disk metrics go to CloudWatch. Don't put secrets in Environment.

On a new account, the per-instance-type quotas for processing are 0 for almost every type, including ml.m5.xlarge; only ml.t3.medium, ml.t3.large and ml.t3.xlarge start above zero. The first job fails with ResourceLimitExceeded until you request an increase (see the overview's quotas).

Processing in code

SDK V3 has no SKLearnProcessor: use ScriptProcessor with the scikit-learn image (or FrameworkProcessor to upload a whole source folder with requirements).

Split and scale data with scikit-learn (Python, SageMaker Python SDK V3) 
from sagemaker.core import image_uris
from sagemaker.core.helper.session_helper import Session, get_execution_role
from sagemaker.core.processing import ScriptProcessor
from sagemaker.core.shapes import ProcessingInput, ProcessingOutput, ProcessingS3Input, ProcessingS3Output

session = Session()
region = session.boto_region_name

processor = ScriptProcessor(
    image_uri=image_uris.retrieve(framework="sklearn", region=region, version="1.2-1",
                                  py_version="py3", instance_type="ml.m5.xlarge"),
    instance_type="ml.m5.xlarge",
    instance_count=1,
    base_job_name="churn-prep",
    role=get_execution_role(),
    sagemaker_session=session,
)
processor.run(
    code="code/preprocess.py",
    inputs=[ProcessingInput(input_name="raw", s3_input=ProcessingS3Input(
        s3_uri="s3://ml-111111111111/churn/raw/", local_path="/opt/ml/processing/input",
        s3_data_type="S3Prefix", s3_input_mode="File"))],
    outputs=[ProcessingOutput(output_name=name, s3_output=ProcessingS3Output(
        s3_uri=f"s3://ml-111111111111/churn/{name}/", local_path=f"/opt/ml/processing/{name}",
        s3_upload_mode="EndOfJob")) for name in ("train", "validation", "test")],
    arguments=["--test-size", "0.2"],
)
code/preprocess.py: what runs inside the container (Python) 
import argparse
import glob

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

parser = argparse.ArgumentParser()
parser.add_argument("--test-size", type=float, default=0.2)
args = parser.parse_args()

df = pd.concat(pd.read_csv(f) for f in glob.glob("/opt/ml/processing/input/*.csv"))
df = df.drop_duplicates().dropna(subset=["churned"])

train, rest = train_test_split(df, test_size=args.test_size * 2, stratify=df["churned"], random_state=42)
validation, test = train_test_split(rest, test_size=0.5, stratify=rest["churned"], random_state=42)

# Fit the scaler on training data only, to avoid leaking test information
numeric = ["tenure_months", "monthly_charges"]
scaler = StandardScaler().fit(train[numeric])
for name, part in (("train", train), ("validation", validation), ("test", test)):
    part = part.copy()
    part[numeric] = scaler.transform(part[numeric])
    # Built-in XGBoost wants the label first and no header
    cols = ["churned"] + [c for c in part.columns if c != "churned"]
    part[cols].to_csv(f"/opt/ml/processing/{name}/{name}.csv", header=False, index=False)
The same preparation on Spark across two instances (Python, SageMaker Python SDK V3) 
from sagemaker.core.helper.session_helper import get_execution_role
from sagemaker.core.spark.processing import PySparkProcessor

spark = PySparkProcessor(base_job_name="churn-spark-prep", framework_version="3.5",
                         role=get_execution_role(), instance_count=2, instance_type="ml.m5.xlarge",
                         max_runtime_in_seconds=3600)
spark.run(
    submit_app="code/spark_prep.py",
    arguments=["--in", "s3://ml-111111111111/churn/raw/", "--out", "s3://ml-111111111111/churn/prepared/"],
    # Keep the Spark UI event logs to inspect the job afterwards
    spark_event_logs_s3_uri="s3://ml-111111111111/spark-logs/",
)

Canvas and Data Wrangler

SageMaker Canvas is the no-code workspace in SageMaker AI, and Data Wrangler now lives inside it: the new Studio doesn't run the classic Data Wrangler interface, and Canvas can import classic Data Wrangler flows.

  • Data preparation: import from S3, Athena, Redshift (provisioned clusters, not Redshift Serverless), Snowflake, Databricks, JDBC databases and 40+ SaaS sources; build a data flow from 300+ transforms; run the Data Quality and Insights report (missing values, outliers, target leakage, a quick model); or describe changes in plain language with chat for data prep (three Regions, using a Claude model on Bedrock), which writes editable code. Data over 5 GB is processed by EMR Serverless automatically.
  • Export a flow as a Processing job, a pipeline, a Feature Store ingestion notebook, a serial inference pipeline step or Python code, so production runs the same transforms.
  • Models without code: numeric and categorical prediction, time series forecasting, image and text classification, built by AutoML (Autopilot's engine, up to 250 candidates). Quick build takes 2 to 20 minutes; Standard build takes 2 to 4 hours and gives the most accurate model. Ready-to-use models (built on Textract, Rekognition and Comprehend) and Amazon Q Developer guidance are included.
  • Cost: $1.90 per session hour while logged in, plus training and EMR Serverless charges. Log out to stop session charges; each user's 100 GB storage volume is billed until the user profile is deleted.

Feature Store concepts

A feature group is a table of features with a record identifier (such as customer_id) and an event time. It has an online store, an offline store, or both.

  • Online store: the latest record per identifier, read in milliseconds with GetRecord during inference. Tiers: Standard (default), Standard_V2 (September 2026, adds partial updates with UpdateRecord; migrating to it is one-way) and InMemory (ElastiCache-based for the lowest latency, online-only groups, no customer managed KMS key). A TTL deletes records a set time after their event time.
  • Offline store: every version of every record as Parquet in S3, with a Glue Data Catalog table (Glue format, partitioned by hour, or Apache Iceberg, partitioned by day) for Athena or Spark. Writes appear within about 15 minutes.
  • Throughput: OnDemand or Provisioned read and write units (provisioned only for Standard online or offline-only groups); switching to on-demand is allowed once every 24 hours.
  • Write rules: PutRecord replaces the whole record. A record with an older event time than the stored one goes only to the offline store, which is how late-arriving history is backfilled without changing what inference sees.
  • Ingestion paths: PutRecord from streaming code (Kinesis or Kafka consumers), BatchWriteRecord (25 records per call, July 2026), the SDK's ingest_dataframe, a Spark connector on EMR, Data Wrangler exports, and feature processors (@feature_processor) that turn a transformation into a scheduled pipeline.

Creating and using a feature group

Create a feature group, write a record and read it back (Python, boto3) 
import time
from datetime import datetime, timezone

import boto3

sm = boto3.client("sagemaker")
fs = boto3.client("sagemaker-featurestore-runtime")

sm.create_feature_group(
    FeatureGroupName="customers",
    RecordIdentifierFeatureName="customer_id",
    EventTimeFeatureName="event_time",
    FeatureDefinitions=[
        {"FeatureName": "customer_id", "FeatureType": "String"},
        # Iceberg tables need a String event time in ISO-8601
        {"FeatureName": "event_time", "FeatureType": "String"},
        {"FeatureName": "tenure_months", "FeatureType": "Integral"},
        {"FeatureName": "monthly_charges", "FeatureType": "Fractional"},
        {"FeatureName": "support_calls_30d", "FeatureType": "Integral"},
    ],
    OnlineStoreConfig={"EnableOnlineStore": True,
                       "SecurityConfig": {"KmsKeyId": "alias/fs-online"}},
    OfflineStoreConfig={
        "S3StorageConfig": {"S3Uri": "s3://ml-111111111111/feature-store/",
                            "KmsKeyId": "alias/fs-offline"},
        "TableFormat": "Iceberg",
    },
    ThroughputConfig={"ThroughputMode": "OnDemand"},
    RoleArn="arn:aws:iam::111111111111:role/FeatureStoreOfflineRole",
)
while sm.describe_feature_group(FeatureGroupName="customers")["FeatureGroupStatus"] == "Creating":
    time.sleep(15)

now = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
# All values are sent as strings, whatever the feature type
fs.put_record(FeatureGroupName="customers", Record=[
    {"FeatureName": "customer_id", "ValueAsString": "C001"},
    {"FeatureName": "event_time", "ValueAsString": now},
    {"FeatureName": "tenure_months", "ValueAsString": "18"},
    {"FeatureName": "monthly_charges", "ValueAsString": "42.5"},
    {"FeatureName": "support_calls_30d", "ValueAsString": "3"},
])

# At inference time: an empty response means no record for this ID
rec = fs.get_record(FeatureGroupName="customers", RecordIdentifierValueAsString="C001",
                    FeatureNames=["tenure_months", "monthly_charges", "support_calls_30d"])
print({f["FeatureName"]: f["ValueAsString"] for f in rec.get("Record", [])})
  • Batch reads: BatchGetRecord takes up to 100 identifiers across feature groups; ListRecords (July 2026) pages through identifiers in the online store.
  • Deletes: DeleteRecord with SoftDelete (the default, blanks the features) or HardDelete (removes the online record); both add an is_deleted row to the offline store.
  • SDK V3 (since May 2026, sagemaker-mlops 3.8 or later): FeatureGroupManager.create(...), ingest_dataframe(...) and FeatureGroup.get(...).get_record(...) in sagemaker.mlops.feature_store, plus Lake Formation settings for the offline store.
  • Sharing: AWS RAM shares the feature group catalog (to discover groups) and individual groups with read, read-write or admin access.

Training sets and the offline store

A training set must use the feature values as they were at each label's time, or the model learns from information it won't have at inference (data leakage). The offline store keeps every version, and AWS's query picks the latest non-deleted record as of a given time:

Latest record per customer as of 1 October 2026 (SQL, Amazon Athena) 
-- Replace the table with the name from DescribeFeatureGroup
SELECT * FROM (
  SELECT *,
         row_number() OVER (
           PARTITION BY customer_id
           ORDER BY event_time DESC, api_invocation_time DESC, write_time DESC
         ) AS row_num
  FROM sagemaker_featurestore.customers_1731300000
  WHERE event_time <= '2026-10-01T00:00:00Z'
)
WHERE row_num = 1 AND NOT is_deleted;
  • Table name: the generated Glue table name is in DescribeFeatureGroup under OfflineStoreConfig.DataCatalogConfig (custom names are possible since July 2026). Compare event times as timestamps or ISO strings to match the feature type.
  • Point-in-time joins across feature groups and a label table: the SDK's DatasetBuilder (.point_in_time_accurate_join(), .as_of(), .to_dataframe()) builds the query for you. The developer guide's V3 example imports a FeatureStore class that the SDK doesn't export; use DatasetBuilder.create(...).
  • Columns added to every offline row: write_time, api_invocation_time and is_deleted (reserved names you can't use as features).

Ground Truth and A2I

SageMaker Ground Truth and Amazon Augmented AI (A2I), along with Mechanical Turk, have been closed to new customers since 30 July 2026; existing customers keep using them without new features. Ground Truth Plus ended on 30 June 2026. AWS hasn't named a replacement, and the Ground Truth product page now describes an expert-assisted generative AI customization service.

  • Ground Truth ran labeling jobs for images (bounding boxes, classification, segmentation), text (entities, classification), video and 3D point clouds, with private or vendor workforces, custom HTML templates and automated data labeling (active learning labels the easy items with a model and sends the rest to people), writing an output manifest to S3.
  • A2I sent low-confidence or sampled predictions to human reviewers, built in for Textract and Rekognition and custom for any model.
  • On the exams: MLA-C02 asks you to "label and annotate data" without naming a service and adds human-in-the-loop evaluation; AIP-C01 still lists Ground Truth and A2I as in scope; AIF-C01 mentions labeling and human audits as concepts.

Security, quotas and pricing

  • Processing security: NetworkConfig sets a VPC, network isolation and encryption between instances; output and volume KMS keys as above. Athena and Redshift dataset definitions take their own KMS key.
  • Feature Store keys: the online store uses an AWS owned key and the offline store an AWS managed key unless you supply symmetric customer managed keys. A kms:ViaService condition works only on the online store's key, so one key with that condition for both stores makes creation fail. Every data-plane call needs kms:Decrypt on a customer managed key.
  • Feature Store IAM: sagemaker:PutRecord, GetRecord, BatchGetRecord, DeleteRecord and ListRecords; BatchWriteRecord needs both BatchWriteRecord and PutRecord, and UpdateRecord is authorized as PutRecord (narrow it with sagemaker:IsUpdateRecord). The runtime has a PrivateLink endpoint (sagemaker.featurestore-runtime), and Lake Formation can control column and row access to the offline tables.
  • Quotas: processing jobs as above (4 instances across all jobs, 20 per job); Feature Store 100 feature groups, 2,500 features per group, 350 KB per record, 10,000 requests per second per API, and per record identifier 2,400 reads and 500 writes per second.
  • Pricing (N. Virginia): Processing per instance-hour (ml.m5.xlarge $0.23) plus $0.10 per GB-month of storage; Feature Store Standard $1.25 per million write units, $0.25 per million read units and $0.45 per GB-month (InMemory $0.233 per GB-hour, 5 GiB minimum); Canvas $1.90 per session hour.

What's changed

  • 2026: Glue 5.1 for Unified Studio data processing jobs (March); Feature Store in SDK V3 with Lake Formation access control (12 May); a visual Feature Store interface in Unified Studio (22 May); Ground Truth Plus ended (30 June); Ground Truth, A2I and Mechanical Turk closed to new customers (30 July); BatchWriteRecord, ListRecords and custom offline table names (9 July); UpdateRecord with the Standard_V2 tier (8 September); instance preference lists for processing (15 September); MLA-C02 replaced MLA-C01 (29 September).
  • 2025: Amazon Q Developer in Canvas (February); M7i, C7i and R7i for processing (June); Unified Studio data processing jobs (July); single-GPU P5 for processing (August).
  • 2024: Canvas training priced by instance use (March); Canvas data preparation at petabyte scale through EMR Serverless and import of classic Data Wrangler flows (August); SageMaker renamed SageMaker AI (3 December).
