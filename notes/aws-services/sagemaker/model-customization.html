Which path to choose

AWS's order of attack is the same on SageMaker AI as on Bedrock: try prompt engineering first, add RAG when the model lacks knowledge, and fine-tune when it must consistently learn new behaviour, style or domain expertise. In the Nova documentation's words, "SFT teaches the model how to respond, not what to know." Use SageMaker AI rather than Bedrock customization when you need an open-weight model Bedrock can't tune, a technique Bedrock lacks, or control of the container and infrastructure.

JumpStart: the model hub

SageMaker JumpStart is the catalogue of pretrained models you deploy, fine-tune or evaluate on your own SageMaker AI infrastructure. AWS's decision guide puts it at about 1,000 models. In Studio it's the Models page, with tabs for the public hub (SageMakerPublicHub), your private hubs, and My models (customization outputs appear under Logged). Each model card offers some of Deploy, Fine-tune (the classic training-job path), Customize (the serverless path) and Evaluate.

  • Model types: open-weight foundation models, deployed by model ID; proprietary models, which need an AWS Marketplace subscription and deploy from a model package ARN; and older task-specific models (from TF Hub, PyTorch Hub, Hugging Face and GluonCV) for vision and text tasks.
  • Model IDs look like meta-textgeneration-llama-3-1-8b-instruct or huggingface-llm-falcon-7b-bf16. In SDK V2, model_version="*" means latest, so pin the version if training and deployment must use the same scripts and image.
  • EULAs and gated models: models such as Llama need accept_eula=True (it defaults to False). Gated weights sit in private AWS buckets that SageMaker reads for you. A model you fine-tuned from a gated model doesn't ask for the EULA again when you deploy it.
  • No network by default: JumpStart deploys models with network access disabled. If you enable it, the endpoint can no longer be used from Bedrock (see Bedrock Ready endpoints).
  • Every model has a default instance type; instance_types.retrieve_default(model_id=..., model_version=..., scope="inference") (or scope="training") from sagemaker.core returns it, and hyperparameters.retrieve_default lists a model's training settings.
  • Price: no charge for JumpStart itself; you pay for the instances that train or host the model, and the Marketplace fee for proprietary models.
  • Delisting: on 13 March 2026 AWS removed some models from the catalogue in every Region. Existing endpoints for them keep working.

JumpStart Solutions (the one-click solution templates for fraud, churn, demand forecasting, predictive maintenance and others) and JumpStart Industry: Financial run only in Studio Classic, which takes no new onboarding and can't create new apps. No retirement date was found, but for new work they're effectively unavailable; build the same thing from a model plus a pipeline.

Deploying a JumpStart model

Deploy a JumpStart model and call it (Python, SageMaker Python SDK V3) 
import json

from sagemaker.core.jumpstart.configs import JumpStartConfig
from sagemaker.core.training.configs import Compute
from sagemaker.serve import ModelBuilder

# Gated models (Llama, for example) also need accept_eula=True here
js = JumpStartConfig(model_id="huggingface-llm-falcon-7b-bf16")

# Leave out compute to get the model's default instance type
mb = ModelBuilder.from_jumpstart_config(jumpstart_config=js, compute=Compute(instance_type="ml.g5.2xlarge"))
mb.build(model_name="falcon-7b-demo")
endpoint = mb.deploy(endpoint_name="falcon-7b-demo")

# The payload shape depends on the model's container; this is the text-generation shape
payload = {"inputs": "What are falcons?", "parameters": {"max_new_tokens": 64}}
resp = endpoint.invoke(body=json.dumps(payload), content_type="application/json")
print(json.loads(resp.body.read().decode("utf-8")))
  • SDK V2 (still common in exam material and older notebooks): JumpStartModel(model_id="huggingface-llm-falcon-7b-bf16", model_version="*").deploy(accept_eula=False) returns a predictor with .predict(payload). Note that V2 takes accept_eula on deploy(), V3 on JumpStartConfig.
  • From any client: it's a normal endpoint, so boto3.client("sagemaker-runtime").invoke_endpoint(EndpointName="falcon-7b-demo", ContentType="application/json", Body=json.dumps(payload)) works too.
  • Inference components: pass endpoint_type=EndpointType.INFERENCE_COMPONENT_BASED (from sagemaker.core.enums) to deploy() to put several models or LoRA adapters on one endpoint; the default is a model-based endpoint. The real-time inference page (to come) covers both.
  • VPC and keys: from_jumpstart_config takes network=Networking(vpc_config=..., enable_network_isolation=...) and model_kms_key=....
  • Proprietary models: subscribe in AWS Marketplace, then ModelBuilder(model=ModelPackage.get(model_package_name=ARN), role_arn=..., instance_type="ml.g5.12xlarge"). Marketplace packages carry no JumpStart hosting defaults, so the instance type is required.

Optimized deployments

Since 17 April 2026, more than 30 JumpStart models (Llama 3.1 and 3.2, Mistral, Qwen, Gemma, Phi-3, Falcon3 and others) offer ready-made configurations per use case (content generation, summarization, Q&A, chat) and target: cost optimized, throughput optimized, latency optimized or balanced. Studio shows P50 latency, time to first token and throughput for each before you deploy (model card, Deploy, Performance), to an endpoint or a HyperPod cluster. In code, ModelBuilder has list_deployment_configs(), display_benchmark_metrics() and set_deployment_config(config_name=..., instance_type=...), but AWS doesn't document which config names match the four presets. Don't confuse this with generate_deployment_recommendations(), which runs an inference recommendation job.

Private curated hubs

A private hub holds the models a team is allowed to use: references to public-hub models, proprietary models (each deploying account still needs the Marketplace subscription) and your own content. Users who can see only one private hub land straight in it in Studio. Hubs are in ten commercial Regions plus Tel Aviv (SDK only); the default bucket is sagemaker-hubs-REGION-ACCOUNT.

Create a hub and add an approved model (Python, SageMaker Python SDK V3, run by an admin) 
from sagemaker.core.jumpstart.hub.hub import Hub

hub = Hub(hub_name="approved-models")
hub.create(description="Models approved by the ML platform team", display_name="Approved models")

# Browse candidates, then add a reference (the CreateHubContentReference API)
print(hub.list_sagemaker_public_hub_models(filter="framework == meta"))
hub.create_model_reference(
    model_arn="arn:aws:sagemaker:us-east-1:aws:hub-content/SageMakerPublicHub/Model/meta-textgeneration-llama-3-1-8b-instruct",
    model_name="meta-textgeneration-llama-3-1-8b-instruct",
)

# Users then pick models from the hub: JumpStartConfig(model_id=..., hub_name="approved-models")
  • Sharing: share a hub with other accounts through AWS RAM at three levels: read (describe and list content), read and use (adds DeployHubModel) and full access (adds importing, deleting and managing references).
  • Fine-tuning from a hub needs sagemaker:TrainHubModel on the hub, plus a resource policy on the hub content when it's in another account.
  • Limits: the admin guide says 50 hubs per Region and the quotas table says 100 private hubs per account, with 10,000 content items per hub; check Service Quotas.

Classic JumpStart fine-tuning

The original path runs an ordinary training job with the model's JumpStart training script. It still works for the models that support it (Llama 2, Mistral 7B, Mixtral 8x7B, Falcon, Flan-T5, Gemma 2B and 7B, GPT-J and similar), and exams still describe it as "fine-tune a pretrained JumpStart model on your own data".

Fine-tune with a JumpStart training script, then deploy (Python, SageMaker Python SDK V3) 
from sagemaker.core.jumpstart.configs import JumpStartConfig
from sagemaker.core.training.configs import Compute, InputData
from sagemaker.serve import ModelBuilder
from sagemaker.train import ModelTrainer

# JumpStartConfig doesn't take instance settings; they go in Compute
trainer = ModelTrainer.from_jumpstart_config(
    jumpstart_config=JumpStartConfig(model_id="meta-textgeneration-llama-2-7b", accept_eula=True),
    compute=Compute(instance_type="ml.g5.12xlarge", instance_count=1),
)
trainer.train(input_data_config=[
    InputData(channel_name="train", data_source="s3://ml-111111111111/llama2/train/"),
    InputData(channel_name="validation", data_source="s3://ml-111111111111/llama2/validation/"),
])

# No second EULA prompt for the fine-tuned model
mb = ModelBuilder(model=trainer)
mb.build()
mb.deploy(endpoint_name="llama2-7b-tuned")
  • Domain adaptation: CSV, JSON or TXT, all training data in a single file in one folder; text comes from a Text column, or the first column.
  • Instruction tuning: JSON Lines (several files allowed) plus an optional template.json. The default template builds the prompt from instruction and context and the completion from response, so each line is {"instruction": "...", "context": "...", "response": "..."}; set the instruction_tuned hyperparameter to "True".
  • Hyperparameters (all strings, not every model supports every one): epoch, learning_rate, per_device_train_batch_size, max_input_length, validation_split_ratio, lora_r, lora_alpha (AWS suggests 2 to 4 times lora_r), lora_dropout, int8_quantization and enable_fsdp.
  • SDK V2: JumpStartEstimator(model_id=...).fit({"train": ..., "validation": ...}, accept_eula=True), then .deploy().

Serverless model customization

Launched on 3 December 2025, serverless model customization is now the main path: you choose a model, a technique and a dataset, and SageMaker AI provisions GPUs, runs a pre-optimized recipe and records the result. Under the hood it's a CreateTrainingJob call with a ServerlessJobConfig.

  1. ChooseA base model from the public hub, a technique and a training type: LoRA or full fine-tuning (added 3 August 2026).
  2. Register dataUpload JSONL to S3 and optionally register it as a dataset asset; register reward functions or reward prompts as evaluators.
  3. TrainThe job runs on GPUs SageMaker picks, logs to MLflow, and writes checkpoints and the model to S3.
  4. RecordThe output becomes a logged model in a model package group, with lineage; you can register it, share it through RAM, or chain another technique on top (continuous customization).
  5. Evaluate and deployRun an evaluation job, then deploy to a SageMaker AI endpoint or Amazon Bedrock.
  • Techniques: SFT (supervised fine-tuning on examples), DPO (direct preference optimization on chosen and rejected answers), and reinforcement fine-tuning with GRPO in two forms: RLVR (rewards from code that checks answers) and RLAIF (rewards from an LLM judge). Multi-turn RL and Nova CPT use their own trainers.
  • Models: Qwen (2.5, 3, 3.5, 3.6, 3.8), DeepSeek R1 Distill (Qwen and Llama), Gemma 4, Meta Llama 3.1 to 3.3 and Muse Glimmer, Ministral 3, NVIDIA Nemotron 3 and 3.5, OpenAI gpt-oss 20B and 120B, and Nova Micro, Lite and 2 Lite. Full fine-tuning isn't offered for Llama 3.1 8B, Llama 3.2 1B and 3B, gpt-oss 120B or Nemotron 3 Super.
  • Regions: US East (N. Virginia), US West (Oregon), Asia Pacific (Tokyo) and Europe (Ireland).
  • Sequence length: since 21 October 2026 you can set it (SequenceLength such as "16K"; most models allow up to 16K, some 32K), but SFT and DPO stay fixed at 4K for Qwen3, Qwen2.5, DeepSeek R1 Distill, Llama 3.x and gpt-oss.
  • Coding agents: the AWS AI/ML skill in the Agent Toolkit for AWS (13 October 2026, pre-installed in Studio JupyterLab) guides an agent through customization, replacing the earlier AWS Labs plugin and the December 2025 agent-guided preview.

Datasets and reward functions

All datasets are JSON Lines, one example per line. Open-weight models accept a messages form or a flat form:

One example line per technique (JSON Lines) 
// SFT, messages form (system message optional)
{"messages": [{"role": "system", "content": "Answer in one sentence."}, {"role": "user", "content": "What is a VPC?"}, {"role": "assistant", "content": "A logically isolated network in AWS."}]}
// SFT, flat form
{"prompt": "What is a VPC?", "completion": "A logically isolated network in AWS."}
// DPO: one preferred and one rejected answer
{"prompt": "What is a VPC?", "chosen": "A logically isolated network in AWS.", "rejected": "A kind of server."}
// RLVR: the reward function checks against ground_truth
{"prompt": [{"role": "user", "content": "What is 48 + 24?"}], "reward_model": {"style": "rule", "ground_truth": "72"}}
// RLAIF: an LLM judge scores the answer, ground_truth is a reference
{"prompt": [{"role": "user", "content": "Explain IAM roles to a new developer."}], "reward_model": {"style": "llmj", "ground_truth": "Mentions temporary credentials and trust policies."}}

The comment lines are for reading only; JSON Lines files can't contain comments. DPO in messages form uses chosen and rejected message lists with the same system message.

Reward functions for RLVR

Use a preset (the preset_reward_function hyperparameter: gsm8k, prime_math or prime_code) or your own Lambda function, registered as an evaluator and passed as EvaluatorArn. Each call receives a list of samples and must return one result per sample with the matching id; anything else fails with InvalidLambdaResponseException.

math-reward-SageMaker: score 1 when the last number matches (Python, AWS Lambda) 
import re


def model_answer(sample):
    # Where the answer sits depends on the dataset format
    for key in ("model_response", "response", "completion"):
        if sample.get(key):
            return str(sample[key])
    turns = [m for m in sample.get("messages", []) if m.get("role") == "assistant"]
    return str(turns[-1].get("content", "")) if turns else ""


def lambda_handler(event, context):
    results = []
    for sample in event:
        expected = str(sample.get("reference_answer", {}).get("text", "")).strip()
        numbers = re.findall(r"-?\d+(?:\.\d+)?", model_answer(sample))
        score = 1.0 if numbers and numbers[-1] == expected else 0.0
        results.append({
            "id": sample["id"],
            "aggregate_reward_score": score,
            "metrics_list": [{"name": "exact_match", "value": score, "type": "Reward"}],
        })
    return results

The managed policy only lets SageMaker invoke Lambda functions whose names contain SageMaker (or sagemaker, Sagemaker), so math-reward fails where math-reward-SageMaker works. Raise the Lambda timeout from the 3-second default if the function calls a model as a judge.

RLAIF uses a Bedrock model as the judge (currently gpt-oss 20B or 120B and Qwen3 models) with a built-in prompt template (cot.jinja, evaluate.jinja, faithfulness.jinja, summarize.jinja) or your own Jinja template using {{ prompt }}, {{ model_output }} and {{ ground_truth }} that returns JSON with a score from 0 to 1.

Running a customization job

In Studio: Models, a model card, Customize model, Customize with UI. In code, SDK V3 has one trainer per technique in sagemaker.train: SFTTrainer, DPOTrainer, RLVRTrainer, RLAIFTrainer, CPTTrainer (Nova only) and MultiTurnRLTrainer.

Serverless LoRA fine-tuning of Llama 3.1 8B Instruct (Python, SageMaker Python SDK V3) 
from sagemaker.train import SFTTrainer
from sagemaker.train.common import TrainingType

trainer = SFTTrainer(
    model="meta-textgeneration-llama-3-1-8b-instruct",
    # TrainingType.FULL for full fine-tuning (not offered for this model)
    training_type=TrainingType.LORA,
    model_package_group="support-assistant",
    training_dataset="s3://ml-111111111111/sft/train.jsonl",
    validation_dataset="s3://ml-111111111111/sft/validation.jsonl",
    s3_output_path="s3://ml-111111111111/sft/output/",
    accept_eula=True,
)
# Hyperparameters are attributes, not a constructor dictionary
trainer.hyperparameters.max_epochs = 3
trainer.hyperparameters.learning_rate = 0.0001
trainer.hyperparameters.lora_rank = 16

trainer.train(dry_run=True)  # checks the inputs without starting a job
job = trainer.train(wait=True)

Several AWS documentation pages show SFTTrainer(model_id=..., train_data=..., hyperparameters={...}). That doesn't match the SDK: the arguments are model and training_dataset, and hyperparameters are set as attributes as above. Other useful arguments are compute (serverless by default, or training-job or HyperPod compute), networking, kms_key_id, sequence_length and the MLflow settings.

The same job through the API (Python, boto3) 
import boto3

sm = boto3.client("sagemaker", region_name="us-east-1")
sm.create_training_job(
    TrainingJobName="support-assistant-sft-01",
    RoleArn="arn:aws:iam::111111111111:role/SageMakerCustomizationRole",
    ServerlessJobConfig={
        "BaseModelArn": "arn:aws:sagemaker:us-east-1:aws:hub-content/SageMakerPublicHub/Model/meta-textgeneration-llama-3-1-8b-instruct",
        "JobType": "FineTuning",
        "CustomizationTechnique": "SFT",
        # LORA is the only value; leave Peft out for full fine-tuning
        "Peft": "LORA",
        "AcceptEula": True,
    },
    InputDataConfig=[{"ChannelName": "train", "DataSource": {"S3DataSource": {
        "S3DataType": "S3Prefix", "S3Uri": "s3://ml-111111111111/sft/train.jsonl"}}}],
    OutputDataConfig={"S3OutputPath": "s3://ml-111111111111/sft/output/"},
    ModelPackageConfig={"ModelPackageGroupArn":
        "arn:aws:sagemaker:us-east-1:111111111111:model-package-group/support-assistant"},
    HyperParameters={"max_epochs": "3", "learning_rate": "0.0001", "lora_rank": "16"},
)
  • No instances: with ServerlessJobConfig, AlgorithmSpecification and ResourceConfig are left out. The hub ARN without a version suffix uses the latest model version.
  • CustomizationTechnique takes SFT, DPO, RLVR or RLAIF; JobType is FineTuning or Evaluation. Add MlflowConfig to log to a specific MLflow App and VpcConfig to run in your subnets.
  • Hyperparameter ranges (SFT LoRA): max_epochs 1 to 100, learning_rate 5e-7 to 1e-4, global_batch_size 8 to 1024 in powers of two, lora_rank 8 to 128, lora_alpha 16 to 256. DPO adds adam_beta; RLVR and RLAIF add rollout_n (answers per prompt, 1 to 32), kl_loss_coef and prompt and response lengths.

Evaluating customized models

An evaluation is the same API with JobType="Evaluation" and one of three EvaluationType values:

  • BenchmarkEvaluation: standard benchmarks (MMLU, MMLU-Pro, BBH, GPQA, MATH, StrongReject, IFEval), or your own question-answer set.
  • LLMAJEvaluation: LLM-as-a-judge with built-in metrics or custom metric definitions (name, instructions, rating scale), run through Amazon Bedrock Evaluations and billed by Bedrock. These jobs may send data to other Regions in the same geography.
  • CustomScorerEvaluation: the PRIME_MATH or PRIME_CODE scorers or your reward Lambda; results also include F1, ROUGE and BLEU.

SDK V3 wraps them as BenchMarkEvaluator, LLMAsJudgeEvaluator and CustomScorerEvaluator in sagemaker.train.evaluate; .evaluate() starts the job and .show_results() prints the scores. Compare the base and the customized model on the same set before deploying.

Multi-turn RL and training sessions

Multi-turn reinforcement learning (3 June 2026)

Trains a model as an agent: the job calls your agent environment (on AgentCore Runtime, EKS, EC2, Fargate or anywhere reachable) for whole multi-step episodes and rewards the trajectory. It uses MultiTurnRLTrainer with an agent_env, records trajectories as MLflow traces, and supports Nova 2 Lite and gpt-oss 20B (N. Virginia and Oregon) and Gemma 4 31B and Qwen3.6 27B (Oregon only). Billing is per token.

Training session APIs (22 October 2026)

For researchers who want to write their own training loop without managing GPUs: you open a training session on a hosted model and send it primitives (forward_backward() with a built-in loss such as cross_entropy, ppo or importance_sampling, or your own; optim_step(); sample(); save_weights() to an inference-ready model package; and state save and load). Each call returns a future. Billing is per token for prefill, sampling and training, and your own local code (such as reward scoring) isn't billed as GPU time.

A minimal LoRA training loop on a training session (Python, SageMaker Python SDK V3) 
from sagemaker.train.training_session import AdamParams, ServiceClient

client = ServiceClient(region="us-west-2", role_arn="arn:aws:iam::111111111111:role/SageMakerCustomizationRole")
tc = client.create_lora_training_client(base_model="openai/gpt-oss-20b", rank=32, alpha=64)

# batches: tokenized examples in the format the training sessions guide describes
for batch in batches:
    tc.forward_backward(batch, loss_fn="cross_entropy").result()
    tc.optim_step(AdamParams(learning_rate=1e-5)).result()

tc.save_weights().result()  # an inference-ready model package
tc.stop()

Sessions run in N. Virginia, Oregon and Mumbai on gpt-oss 20B, Gemma 4 (E2B and 31B) and Qwen3.6 and 3.8 27B (not every model in every Region), with a fixed maximum context of 64K or 32K tokens. The control-plane APIs are CreateTrainingSession, DescribeTrainingSession, StopTrainingSession and similar; the operations go to a separate training session runtime endpoint.

Amazon Nova and Nova Forge

Amazon Nova models are customized on SageMaker AI in two ways: through the serverless flow above (Nova Micro, Lite and 2 Lite), or with recipes from the sagemaker-hyperpod-recipes repository on training jobs or HyperPod, which add techniques the serverless path lacks.

  • Nova Micro, Lite and Pro: SFT and DPO (LoRA or full), PPO, distillation from Nova Premier or Pro, and continued pre-training (CPT, HyperPod only).
  • Nova 2 Lite: SFT (text with images, or text with video, but not both in one job), reinforcement fine-tuning (RFT, text only), CPT on HyperPod and multi-turn RL, on ml.p5.48xlarge or ml.p5en.48xlarge. Nova 2 Pro is in preview for Forge customers.
  • Data: SFT uses the Bedrock Converse format ({"schemaVersion": "bedrock-conversation-2024", "system": [...], "messages": [{"role": "user", "content": [{"text": "..."}]}, ...]}), so the same files work for Bedrock customization. Nova 2 SFT takes 8 to 20,000 samples, and text such as User:, Assistant: or [EOS] in the data fails the job. RFT uses an OpenAI-style format with a reference_answer and at least 100 training and 100 evaluation examples.
  • KMS: if you encrypt the outputs with your own key, pass the same key to later jobs and to the Bedrock import, and give the identity that calls CreateTrainingJob (not just the execution role) the grant and data-key permissions.

Nova Forge (GA 2 December 2025)

A subscription for building your own frontier model from Nova: training starts from early pre-, mid- or post-training checkpoints, can mix your data with Nova-curated data (the data_mixing_config setting needs Forge), runs RFT against reward functions in your own environment, and includes a responsible AI toolkit and early access to new Nova models. It's priced as an annual subscription shown in the console. To subscribe, tag your console IAM role forge-subscription=true and open Model training and customization, Nova Forge in the SageMaker AI console. On HyperPod it needs restricted instance groups.

Deploying customized models

Deploy the SFT result to an endpoint or to Bedrock (Python, SageMaker Python SDK V3; trainer from the job above) 
from sagemaker.serve import ModelBuilder
from sagemaker.serve.bedrock_model_builder import BedrockModelBuilder

# Option 1: a SageMaker AI endpoint (LoRA adapters can be inference components)
mb = ModelBuilder(model=trainer)
mb.build()
mb.deploy(endpoint_name="support-assistant")

# Option 2: Amazon Bedrock; open-weight models go through a Custom Model Import job
BedrockModelBuilder(model=trainer).deploy(
    job_name="support-assistant-import",
    imported_model_name="support-assistant",
    role_arn="arn:aws:iam::111111111111:role/SageMakerForBedrock-d-example",
)
  • Open-weight models to Bedrock use Custom Model Import (CreateModelImportJob) and are then called on demand with InvokeModel. Import supports only some architectures: Llama, Mistral and Mixtral, Flan-T5, GPTBigCode, Qwen2 to Qwen3 (Qwen3 without Converse) and gpt-oss (N. Virginia only). Gemma 4, Nemotron, Ministral 3, Muse Glimmer and the newer Qwen models aren't on the list, so serve those on SageMaker AI.
  • Nova models to Bedrock use CreateCustomModel pointing at the model package, then CreateCustomModelDeployment. On-demand use needs a LoRA (parameter-efficient) model trained on or after 16 July 2025, and costs the same as the base model; full-rank models need Provisioned Throughput. The CreateCustomModel API page still says Provisioned Throughput is always required; the newer deployment guide says otherwise.
  • Nova on SageMaker AI endpoints (N. Virginia and Oregon) takes only full-rank or merged-LoRA models; unmerged LoRA and base Nova models run in Bedrock. CONTEXT_LENGTH and MAX_CONCURRENCY environment variables trade context for concurrency per instance.
  • Bedrock Ready endpoints: a JumpStart endpoint marked Bedrock Ready can be registered with Bedrock (endpoint details, Use with Bedrock) so Bedrock's Converse API, Agents, Knowledge Bases and Guardrails can use it. Bedrock Marketplace deploys models from the same public hub onto SageMaker endpoints from the Bedrock side.

Check Regions before you train. Serverless customization runs in N. Virginia, Oregon, Tokyo and Ireland, but Bedrock Custom Model Import is only in N. Virginia, Ohio, Oregon and Frankfurt, so a model customized in Tokyo or Ireland can't be imported into Bedrock in the same Region.

Security, quotas and pricing

  • Execution role: attach AmazonSageMakerModelCustomizationCoreAccess; Studio quick setup does it automatically since 2 June 2026, and custom setup has a Model customization activity. It covers hub reads, training and evaluation jobs, MLflow, model packages, endpoints, reward Lambdas and Bedrock import.
  • Separate service roles (AWS's recommendation): SageMakerForLambda-DOMAIN for reward functions and SageMakerForBedrock-DOMAIN, trusted by Bedrock, which reads the model from S3 for import. Adding the Lambda and Bedrock principals to the execution role's trust policy also works, but AWS calls it less secure.
  • Network and keys: customization jobs take subnets and security groups; without internet access they need VPC endpoints for S3, ECR and CloudWatch Logs. Customer managed KMS keys need the role in the key policy.
  • Governance: limit models with private hubs, RAM permission levels, sagemaker:TrainHubModel and the sagemaker:DirectGatedModelAccess condition (above).
  • Quotas start at 0 for concurrent serverless customization jobs, serverless evaluation jobs, training sessions and multi-turn RL jobs and evaluations. All are adjustable; some feature pages mention 1 or 2, so check Service Quotas and request an increase before the first job.
  • Pricing: SFT and DPO are billed per token (dataset tokens times epochs; AWS's example: Llama 3.1 8B SFT with LoRA at $0.50 per million tokens, 1.5 million tokens for 5 epochs, costs $3.75). RL is billed per hour with per-second billing (AWS's example: $100 an hour for half an hour, $50). Evaluation is billed per input and output token, with judge calls billed by Bedrock. Training sessions and multi-turn RL are billed per token. Classic JumpStart fine-tuning, recipes and endpoints are billed per instance-hour; JumpStart itself is free.
