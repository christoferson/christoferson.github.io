Prompt management

Prompt management (generally available November 2024) stores prompt templates with {{variable}} placeholders, the model and inference settings, and immutable versions, so prompts can change without redeploying code and every call is traceable to a version. It runs in 22 Regions, with no separate charge listed: you pay for the model calls.

Create a chat prompt, version it, and call it by ARN (Python, boto3) 
import boto3

agent = boto3.client("bedrock-agent", region_name="us-east-1")
runtime = boto3.client("bedrock-runtime", region_name="us-east-1")

p = agent.create_prompt(
    name="SupportReply",
    defaultVariant="v1",
    variants=[{
        "name": "v1",
        "modelId": "us.anthropic.claude-haiku-4-5-20251001-v1:0",
        "templateType": "CHAT",
        "templateConfiguration": {"chat": {
            "system": [{"text": "You are a concise support agent for {{product}}."}],
            "messages": [{"role": "user", "content": [{"text": "Customer question: {{question}}"}]}],
            "inputVariables": [{"name": "product"}, {"name": "question"}],
        }},
        "inferenceConfiguration": {"text": {"maxTokens": 400, "temperature": 0.2}},
    }],
)
# Version 1 is immutable: the application pins this ARN
prompt_arn = agent.create_prompt_version(promptIdentifier=p["id"], description="first release")["arn"]

resp = runtime.converse(
    modelId=prompt_arn,
    promptVariables={"product": {"text": "Home Router X"}, "question": {"text": "How do I reset it?"}},
)
print(resp["output"]["message"]["content"][0]["text"])
  • With a prompt ARN as modelId, you can't send system, inferenceConfig, toolConfig or additionalModelRequestFields (define them in the prompt), and any messages you send are appended after the template's. Guardrails apply to the whole prompt.
  • Callers need bedrock:RenderPrompt on the prompt as well as bedrock:InvokeModel; RenderPrompt is logged as a CloudTrail data event (AWS::Bedrock::Prompt), off by default.
  • Use the version ARN (prompt/ID:N) in production; the DRAFT keeps changing. Up to 10 versions per prompt (not adjustable) and 500 prompts per account. The API takes one variant per prompt (the console compares up to three); prompt caching needs the CHAT template type. With InvokeModel, managed prompts work only for Claude and Llama models: prefer Converse.

Prompt optimization

  • Simple optimization (OptimizePrompt, generally available April 2025): rewrites one short prompt for one target model, with no evaluation data; $0.03 per 1,000 tokens. Its supported-model list is old, so check your model.
  • Advanced Prompt Optimization (14 May 2026): an asynchronous job (create_advanced_prompt_optimization_job on the bedrock client) that rewrites up to 10 templates using up to 100 evaluation samples each, scores the results with your criteria, an LLM judge rubric or a Lambda, and compares up to 5 models, including latency, so you can also migrate a prompt to a new model. Mark parts to change or keep with <advpo:optimize> and <advpo:exclude> tags.
  • Since October 2026 it can shorten prompts (set optimizationConfig.shortenPrompt per template in the input file; if the shorter prompt doesn't score at least as well you get the original back, with compressionRatio 1.0) and accepts application inference profiles.
  • There's no service fee, but it runs many model calls (the default optimizer is Claude Sonnet 4.6) billed at on-demand prices: estimate with the formulas on the pricing page. Up to 20 active jobs per Region, in 14 Regions.

Flows

Amazon Bedrock Flows (generally available November 2024) is a fixed workflow of steps you design visually or as JSON: nodes joined by data and conditional connections, with versions and aliases. Use it when the steps are known in advance; when the model should decide the steps, use an AgentCore agent; for long-running orchestration with retries and human approval, consider AWS Step Functions. It costs $0.035 per 1,000 node transitions plus the services the nodes call.

Nodes

  • Input (exactly one; output document) and Output (input document; up to 20).
  • Prompt: a managed prompt by ARN or an inline template; one input per variable, output modelCompletion; optional guardrail.
  • Knowledge base: without a model it returns retrieval results; with a model it generates an answer (guardrails only then). Lambda, Lex (single utterance), S3 storage and S3 retrieval (UTF-8 text).
  • Condition (conditions checked in order, first true wins), Iterator and Collector (one each; items run one at a time), and a loop node (the API models it as Loop, LoopInput and LoopController with up to 1,000 iterations).
  • Inline code (preview; Python 3.12, no internet) and Agent (needs an Agents Classic agent, so unavailable to new accounts).

Inputs pick data with a JSONPath-style expression rooted at $.data (for example $.data.topic). Limits: 40 nodes, 5 condition nodes of 5 conditions, 10 versions and 10 aliases per flow.

A three-node flow (input, managed prompt, output), released through an alias and invoked (Python, boto3) 
agent = boto3.client("bedrock-agent", region_name="us-east-1")
rt = boto3.client("bedrock-agent-runtime", region_name="us-east-1")

nodes = [
    {"type": "Input", "name": "FlowInput", "outputs": [{"name": "document", "type": "Object"}]},
    {"type": "Prompt", "name": "Summarize",
     "configuration": {"prompt": {"sourceConfiguration": {"resource": {"promptArn": SUMMARY_PROMPT_ARN}}}},
     # Input name = the prompt's variable name
     "inputs": [{"name": "topic", "type": "String", "expression": "$.data.topic"}],
     "outputs": [{"name": "modelCompletion", "type": "String"}]},
    {"type": "Output", "name": "FlowOutput",
     "inputs": [{"name": "document", "type": "String", "expression": "$.data"}]},
]
connections = [
    {"name": "InToSummarize", "source": "FlowInput", "target": "Summarize", "type": "Data",
     "configuration": {"data": {"sourceOutput": "document", "targetInput": "topic"}}},
    {"name": "SummarizeToOut", "source": "Summarize", "target": "FlowOutput", "type": "Data",
     "configuration": {"data": {"sourceOutput": "modelCompletion", "targetInput": "document"}}},
]
flow = agent.create_flow(name="Summarizer", executionRoleArn="arn:aws:iam::111111111111:role/FlowsRole",
                         definition={"nodes": nodes, "connections": connections})
# Apply the DRAFT, freeze a version, and point an alias at it
agent.prepare_flow(flowIdentifier=flow["id"])
version = agent.create_flow_version(flowIdentifier=flow["id"])["version"]
alias = agent.create_flow_alias(flowIdentifier=flow["id"], name="prod", routingConfiguration=[{"flowVersion": version}])

resp = rt.invoke_flow(
    flowIdentifier=flow["id"],
    flowAliasIdentifier=alias["id"],
    inputs=[{"content": {"document": {"topic": "S3 storage classes"}}, "nodeName": "FlowInput", "nodeOutputName": "document"}],
)
for event in resp["responseStream"]:
    if "flowOutputEvent" in event:
        print(event["flowOutputEvent"]["content"]["document"])
    elif "flowCompletionEvent" in event:
        print("done:", event["flowCompletionEvent"]["completionReason"])
  • InvokeFlow streams output, completion (SUCCESS or INPUT_REQUIRED) and, with enableTrace, per-node traces. The AWS CLI can't call it. An alias points to exactly one version; the test alias TSTALIASID always runs the DRAFT. Connection and node names allow letters, digits and single underscores, no hyphens.
  • Asynchronous executions (preview): StartFlowExecution runs a flow for up to 24 hours (nodes up to 5 minutes), with GetFlowExecution and per-node events; results are kept 90 days; inline code nodes aren't supported there. Multi-turn flows are also preview and need an agent node.
  • The service role (trusted by bedrock.amazonaws.com for flow/*) needs the permissions of each node: bedrock:InvokeModel, bedrock:RenderPrompt, bedrock:Retrieve, lambda:InvokeFunction, S3 and guardrail actions. InvokeFlow is a CloudTrail data event.

Bedrock Data Automation

Bedrock Data Automation (BDA, generally available March 2025) turns documents, images, audio and video into structured JSON with one API. Standard output gives each modality's defaults (document text, tables and summaries with bounding boxes and confidence; image summaries and text; transcripts, scene summaries and speaker labels for media). Custom output uses blueprints: a schema of fields, each with a natural-language instruction, such as the fields of an invoice. It's also a parser option for customer-managed Knowledge Bases.

An invoice blueprint, a project, an async job and reading the result (Python, boto3) 
import json
import time

import boto3

region, account = "us-east-1", "111111111111"
bda = boto3.client("bedrock-data-automation", region_name=region)
bda_rt = boto3.client("bedrock-data-automation-runtime", region_name=region)
s3 = boto3.client("s3", region_name=region)

schema = {
    "$schema": "http://json-schema.org/draft-07/schema#",
    "class": "Invoice",
    "description": "Supplier invoice",
    "type": "object",
    "properties": {
        "invoice_number": {"type": "string", "inferenceType": "explicit", "instruction": "The invoice number"},
        "invoice_date": {"type": "string", "inferenceType": "inferred", "instruction": "Invoice date in YYYY-MM-DD format"},
        "total_amount": {"type": "number", "inferenceType": "explicit", "instruction": "Grand total including tax"},
    },
}
bp_arn = bda.create_blueprint(blueprintName="invoice-v1", type="DOCUMENT", schema=json.dumps(schema))["blueprint"]["blueprintArn"]

project = bda.create_data_automation_project(
    projectName="invoices",
    # ASYNC projects work only with the async API, SYNC only with the sync API
    projectType="ASYNC",
    standardOutputConfiguration={},
    customOutputConfiguration={"blueprints": [{"blueprintArn": bp_arn, "blueprintStage": "LIVE"}]},
)
# Wait until get_data_automation_project shows the project as COMPLETED before invoking

job = bda_rt.invoke_data_automation_async(
    inputConfiguration={"s3Uri": "s3://docs-111111111111/in/invoice-123.pdf"},
    outputConfiguration={"s3Uri": "s3://docs-111111111111/out/"},
    dataAutomationConfiguration={"dataAutomationProjectArn": project["projectArn"], "stage": "LIVE"},
    # Required on every call, with your own account ID
    dataAutomationProfileArn=f"arn:aws:bedrock:{region}:{account}:data-automation-profile/us.data-automation-v1",
)
while (st := bda_rt.get_data_automation_status(invocationArn=job["invocationArn"]))["status"] in ("Created", "InProgress"):
    time.sleep(5)


def read_s3(uri):
    bucket, key = uri.replace("s3://", "").split("/", 1)
    return json.loads(s3.get_object(Bucket=bucket, Key=key)["Body"].read())


if st["status"] == "Success":
    meta = read_s3(st["outputConfiguration"]["s3Uri"])
    seg = meta["output_metadata"][0]["segment_metadata"][0]
    if seg.get("custom_output_status") == "MATCH":
        print(read_s3(seg["custom_output_path"]))
  • Profiles: BDA always runs through a cross-Region data automation profile (us, na, eu, apac, us-gov, and an opt-in global profile only in Singapore), so IAM needs bedrock:InvokeDataAutomationAsync on the profile in every Region of the geography. Data at rest stays in your Region.
  • Blueprints: JSON Schema with explicit fields (read directly) or inferred fields (derived or normalized); up to 40 document blueprints per project (matched to each document automatically), with a fallback; catalog blueprints exist for invoices, bank statements, driving licences and more. Blueprint instruction optimization (December 2025) tunes the instructions against up to 10 labelled examples.
  • Sync API (InvokeDataAutomation, November 2025): images, and documents up to 10 pages with up to 15 fields, returned inline.
  • Limits: documents up to 3,000 pages and 500 MB (PDF, TIFF, JPEG, PNG, DOC, DOCX; six European languages), video and audio up to 240 minutes. Custom vocabulary through a Data Automation Library (April 2026, free) improves transcription of domain terms. EventBridge notifications avoid polling.
  • Pricing: documents $0.010 per page standard, $0.040 per page custom (up to 30 fields, then $0.0005 per extra field per page); images $0.003 standard, $0.005 custom; video $0.050 and audio $0.006 per minute standard.

Choosing Data Automation (or a model) as a Knowledge Base parser bills every PDF page in the data source, even text-only ones. DOCX files are converted to PDF, so page mapping is lost. And only trusted people should write blueprint instructions: they're prompts.

Bedrock Marketplace

Bedrock Marketplace (December 2024) offers more than 100 specialized and emerging models (the compatibility table lists 140) that you deploy to a SageMaker-managed endpoint you size, then call through Bedrock's APIs, Knowledge Bases, Prompt management and Flows.

Deploy a Marketplace model, call it with Converse, and delete the endpoint (Python, boto3) 
bedrock = boto3.client("bedrock", region_name="us-west-2")
runtime = boto3.client("bedrock-runtime", region_name="us-west-2")

ep = bedrock.create_marketplace_model_endpoint(
    modelSourceIdentifier="arn:aws:sagemaker:us-west-2:aws:hub-content/SageMakerPublicHub/Model/MODEL_NAME/VERSION",
    # Up to 30 characters
    endpointName="mp-demo-1",
    endpointConfig={"sageMaker": {
        "initialInstanceCount": 1,
        "instanceType": "ml.g5.2xlarge",
        "executionRole": "arn:aws:iam::111111111111:role/SagemakerExecutionRoleForBedrock",
    }},
    # Only for gated models
    acceptEula=True,
)["marketplaceModelEndpoint"]
arn = ep["endpointArn"]
# Ready when endpointStatus is InService and status is REGISTERED (10-15 minutes)
while bedrock.get_marketplace_model_endpoint(endpointArn=arn)["marketplaceModelEndpoint"]["endpointStatus"] in ("Creating", "Updating"):
    time.sleep(30)

out = runtime.converse(modelId=arn, messages=[{"role": "user", "content": [{"text": "Hello"}]}])
print(out["output"]["message"]["content"][0]["text"])

# Instances bill per hour while the endpoint exists, even when idle
bedrock.delete_marketplace_model_endpoint(endpointArn=arn)
  • Every Marketplace model supports InvokeModel (with its native body); only some support Converse and streaming. Guardrails go through ApplyGuardrail.
  • IAM: bedrock:InvokeModel on arn:aws:bedrock:REGION:ACCOUNT:marketplace/model-endpoint/all-access plus sagemaker:InvokeEndpoint with the condition aws:CalledViaLast equal to bedrock.amazonaws.com. Tag conditions on the bedrock:*MarketplaceModelEndpoint actions are ignored: put them on the sagemaker:* actions.
  • Cost: the provider's software fee (none for open models) plus SageMaker instance-hours. Change endpoints only through Bedrock: turning off network isolation or changing the container in SageMaker breaks the link. Existing SageMaker endpoints can be registered with RegisterMarketplaceModelEndpoint.
  • Separately, since October 2026 a management account that accepts a private offer for a third-party serverless model can choose Distribute on the purchase confirmation page to give every account in the organization the private price; otherwise member accounts pay public rates.

Other notes

  • Bedrock in SageMaker Unified Studio (formerly Bedrock Studio, then Bedrock IDE; generally available March 2025): a governed, no-code workspace in SageMaker Unified Studio projects, with playgrounds, chat agent and flow apps, knowledge bases, guardrails, prompts and evaluation, where administrators control which models and features each project gets. Separately, a redesigned Bedrock console (June 2026) organizes work into projects around the bedrock-mantle APIs.
  • Session management APIs (still preview since February 2025): CreateSession, CreateInvocation and PutInvocationStep checkpoint state for open-source frameworks, for example LangGraph's BedrockSessionSaver from langgraph-checkpoint-aws; 1,000 steps per session, 1-hour idle timeout, 30-day retention. For new agent state, prefer AgentCore Memory.
  • Agents Classic (formerly Bedrock Agents): closed to new customers since 30 July 2026, in maintenance mode with no end-of-life date. Action groups, knowledge bases, multi-agent collaboration and inline agents keep working for existing users. New work should use the AgentCore Harness or Runtime; the Flows agent node and agent prompt variants depend on Classic.

What's changed

  • 2026: Data Automation custom vocabulary (3 April); Advanced Prompt Optimization (14 May); redesigned Bedrock console (4 June); Agents Classic closed to new customers (30 July); prompt shortening and application profiles in prompt optimization (20 October); private-offer distribution for serverless models (22 October).
  • 2025: Flows multi-turn preview (January); session management preview (February); Data Automation generally available (3 March); Bedrock in SageMaker Unified Studio generally available (13 March); prompt optimization generally available (23 April); Data Automation custom audio and video output (May); Flows asynchronous executions and inline code preview (June); Flows loop node (September); Data Automation sync API (November) and blueprint optimization (December).
  • 2024: Prompt management and Prompt Flows preview (10 July); Prompt management generally available (7 November); Flows generally available and renamed (22 November); Marketplace and Data Automation preview (4 December).
