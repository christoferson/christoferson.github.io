AgentCore Runtime

Serverless hosting for your own agent, MCP server, A2A agent or AG-UI backend, in any framework and with any model. Each session runs in its own isolated microVM (or EC2 instance), for up to 8 hours (or 14 days), billed by the second for CPU actually used.

Concepts

If you'd rather configure an agent than write one, use the Harness, which runs on Runtime. This page is for hosting your own code.

  • Agent runtime: your hosted agent or tool server (a container image or a code zip). Creating one also creates a workload identity for it in AgentCore Identity.
  • Versions: immutable and numbered (1, 2, 3...). Creating makes version 1; every update (image, settings, network, auth) makes a new version.
  • Endpoints: DEFAULT is created automatically and follows the latest version; named endpoints (for example prod) pin a version until you move them, with no downtime. Up to 10 per runtime.
  • Sessions: a runtimeSessionId (at least 33 characters; use a UUID) maps to one dedicated microVM with its own CPU, memory and file system. A session is active while handling a request or reporting background work, idle otherwise, and stopped after the idle timeout (default 15 minutes), the maximum lifetime (default and maximum 8 hours), StopRuntimeSession, or failing health checks. Then the microVM is destroyed and its memory wiped.
  • Calling a stopped session's ID again starts a new, empty microVM. Only mounted storage survives; keep conversations in AgentCore Memory. Existing sessions keep the code they started with, so use a new session ID to test an update.
  • AgentCore doesn't map sessions to users: your backend decides which user owns which session.

Runtime and endpoint names allow letters, digits and underscores only (up to 48 characters), and versions are plain integers. An AWS versioning example uses production-endpoint, version v2.1 and the wrong client: all three fail. Endpoints are managed with the bedrock-agentcore-control client.

Instances (generally available August 2026, 9 Regions) suit long-running or GPU workloads; up to 20 agents can share one instance session and a volume, without isolation from each other. The compute type can't be changed after creation, and you pass the capacity provider instead of a network configuration.

Platform V1 and V2 (microVMs)

Set platformVersion="V2" on create or update (V1 is the default). V2 (generally available 18 September 2026, now in 10 Regions) prepares your environment once, snapshots it, and restores new sessions from the snapshot: AWS measured cold starts of about 2 seconds versus 5 to 30 seconds on V1 for 200 MB to 2 GB images. V2 also reclaims unused memory after 120 seconds, allows 250 connections per session, adds per-session IAM context keys and FUSE mounts, and costs more per unit (see pricing).

  • Creating or updating a V2 runtime takes minutes, and /ping must report healthy within 120 seconds of start-up or creation fails. Poll GetAgentRuntime until READY.
  • Do expensive set-up at module scope so it's in the snapshot, but generate random values, IDs, tokens and timestamps per request: restored copies share the snapshot's state (in Node.js, even crypto output can repeat, so read /dev/urandom).
  • AWS clients created at import time load credentials before the snapshot, so they lack the session context keys (aws:AgentCoreRuntimeSourceSid, aws:AgentCoreRuntimeSourceArn). If your IAM policies use those keys (for example a per-session S3 prefix), create the client in the handler from a new boto3.Session().

Building an agent

Python with the AgentCore SDK

The bedrock-agentcore package (Python 3.10 or later) wraps your code in BedrockAgentCoreApp, a Starlette server that implements the contract: POST /invocations, GET /ping and a /ws WebSocket. Extras add framework support: [strands-agents], [a2a], [ag-ui].

main.py: a streaming Strands agent (Python; requirements: bedrock-agentcore[strands-agents], strands-agents, aws-opentelemetry-distro) 
from bedrock_agentcore import BedrockAgentCoreApp
from strands import Agent

app = BedrockAgentCoreApp()
# Created once per microVM; the default model is on Bedrock (execution role needs bedrock:InvokeModel*)
agent = Agent()


@app.entrypoint
async def invoke(payload, context):
    # payload is the parsed JSON body; context.session_id is the runtime session
    prompt = payload.get("prompt")
    if not isinstance(prompt, str) or not prompt.strip():
        yield {"error": "prompt must be a non-empty string"}
        return
    # Yielding makes the response a server-sent event stream
    async for event in agent.stream_async(prompt):
        yield event


if __name__ == "__main__":
    app.run()
  • The SDK passes the request context only if the second parameter is named exactly context. context.request_headers holds only Authorization and X-Amzn-Bedrock-AgentCore-Runtime-Custom-* headers.
  • Return a dict for a JSON response, or yield (sync or async generator) to stream server-sent events.
  • Validate that the prompt is a string, as above: AWS warns that structured input can smuggle tool-use blocks into the model call.
  • Don't block inside the entrypoint, or /ping stops answering and the session is killed. For background work, use app.add_async_task() and app.complete_async_task() (or a custom @app.ping) so the session reports HealthyBusy and isn't treated as idle.
  • app.run() listens on 0.0.0.0:8080 inside a container and on 127.0.0.1 elsewhere, so a local test with curl http://localhost:8080/invocations works.

Without the SDK, and Node.js

Any HTTP server that follows the contract works, for example FastAPI on 0.0.0.0:8080 with POST /invocations and GET /ping returning {"status": "Healthy"}; your code then reads the session ID header itself. For Node.js, the TypeScript SDK (npm bedrock-agentcore, imported from bedrock-agentcore/runtime) provides the same app object, and zip deployment supports Node.js 22 (compile TypeScript to JavaScript first).

The service contract

  • HTTP (agents): port 8080, POST /invocations (JSON or server-sent events), GET /ping, WebSocket /ws.
  • MCP (tool servers): port 8000, POST /mcp (Streamable HTTP, JSON-RPC); a GET /ping is recommended.
  • A2A (agent-to-agent): port 9000, POST / (JSON-RPC 2.0) and the agent card at /.well-known/agent-card.json.
  • AG-UI (agent front ends): port 8080, POST /invocations streaming AG-UI events, and /ws.
  • Since October 2026 you can change the port (8000 to 12000) and path on microVMs. Containers must listen on 0.0.0.0.
  • /ping returns {"status": "Healthy"} or {"status": "HealthyBusy"}, with an optional time_of_last_update. Change that timestamp only when the status changes: refreshing it on every ping stops sessions from ever going idle, so they run to the 8-hour limit and exhaust your session quota.
  • Payloads up to 100 MB, streaming chunks up to 10 MB, synchronous requests up to 15 minutes, streams and WebSockets up to 60 minutes, background work up to the session's lifetime.
  • Errors: 424 RuntimeClientError means your container returned an error or never became ready (check its logs); 409 RetryableConflictException means the session is still starting or stopping (AWS SDKs retry it; raw HTTP clients must).

Deploying

Container or zip

  • Container: a linux/arm64 image in Amazon ECR, up to 2 GB. You patch the image; AWS patches the host.
  • Direct code (zip): a zip in S3, up to 250 MB zipped and 750 MB unzipped, with ARM64 wheels and files at the root. Runtimes PYTHON_3_12, PYTHON_3_13, PYTHON_3_14 and NODE_22; Python 3.10 and 3.11 are past their update-block date (31 August 2026). AWS patches the language runtime for you.
Build and push an ARM64 image (shell) 
aws ecr create-repository --repository-name support-agent --region us-west-2
aws ecr get-login-password --region us-west-2 | docker login --username AWS --password-stdin 111111111111.dkr.ecr.us-west-2.amazonaws.com
docker buildx create --use
docker buildx build --platform linux/arm64 -t 111111111111.dkr.ecr.us-west-2.amazonaws.com/support-agent:1.0.0 --push .

An "exec format error" in the logs means the image or wheels were built for x86. Images with more than 53 layers and a non-numeric USER fail to mount: use USER 1000 or fewer layers.

CreateAgentRuntime

Create a V2 runtime, wait for it, and pin a prod endpoint (Python, boto3; shapes from the API reference) 
import time

import boto3

ctl = boto3.client("bedrock-agentcore-control", region_name="us-west-2")

r = ctl.create_agent_runtime(
    agentRuntimeName="support_agent",
    agentRuntimeArtifact={"containerConfiguration": {
        "containerUri": "111111111111.dkr.ecr.us-west-2.amazonaws.com/support-agent:1.0.0",
    }},
    roleArn="arn:aws:iam::111111111111:role/AgentRuntimeRole",
    networkConfiguration={"networkMode": "PUBLIC"},
    # HTTP | MCP | A2A | AGUI
    protocolConfiguration={"serverProtocol": "HTTP"},
    lifecycleConfiguration={"idleRuntimeSessionTimeout": 300, "maxLifetime": 3600},
    environmentVariables={"LOG_LEVEL": "info"},
    platformVersion="V2",
)
runtime_id, runtime_arn = r["agentRuntimeId"], r["agentRuntimeArn"]

# V2 creation takes minutes
while (s := ctl.get_agent_runtime(agentRuntimeId=runtime_id))["status"] not in ("READY", "CREATE_FAILED"):
    time.sleep(10)
if s["status"] != "READY":
    raise RuntimeError(s.get("failureReason"))

ctl.create_agent_runtime_endpoint(agentRuntimeId=runtime_id, name="prod", agentRuntimeVersion="1")
  • For a zip, use agentRuntimeArtifact={"codeConfiguration": {"code": {"s3": {"bucket": ..., "prefix": "agent/package.zip"}}, "runtime": "PYTHON_3_13", "entryPoint": ["opentelemetry-instrument", "main.py"]}} (the prefix is the object key).
  • Other settings: authorizerConfiguration (JWT; omit for IAM), requestHeaderConfiguration (up to 20 extra headers passed to your code), filesystemConfigurations, allowedPorts (session endpoints), capacityProviderConfiguration (Instances) and up to 50 environmentVariables (4 KB in total; plain text, so no secrets).
  • UpdateAgentRuntime must resend agentRuntimeArtifact and roleArn every time, and always makes a new version: DEFAULT moves, named endpoints don't until you call UpdateAgentRuntimeEndpoint.

Since 30 June 2026 invocations require MMDSv2 (the token-protected version of the microVM metadata service that serves the role's credentials). Older runtimes fail with "This runtime is not MMDSv2-enabled" until you run update_agent_runtime(..., metadataConfiguration={"requireMMDSV2": True}); the field exists only on update.

AgentCore CLI, CloudFormation and CDK

  • CLI (npm @aws/agentcore): agentcore create --name P --template agent-python-strands (templates also for LangChain, TypeScript Strands and Vercel, A2A, AG-UI and FastMCP), agentcore add runtime --name N --language python --protocol MCP, agentcore dev to run locally, agentcore deploy, agentcore invoke --runtime N --payload '{"prompt": "Hi"}', agentcore logs runtime --name N. Adding a Dockerfile switches the build from zip to container.
  • CloudFormation: AWS::BedrockAgentCore::Runtime and AWS::BedrockAgentCore::RuntimeEndpoint. In CloudFormation ProtocolConfiguration is a plain string (MCP), not the API object.
  • CDK: stable constructs in aws-cdk-lib/aws-bedrockagentcore: Runtime with AgentRuntimeArtifact.fromAsset(dir) or fromCodeAsset(...), runtime.addEndpoint(...), RuntimeAuthorizerConfiguration.usingCognito(...) and grantInvoke.

Invoking

boto3

Call the agent and read either JSON or a stream (Python, boto3) 
import json
import uuid

import boto3

rt = boto3.client("bedrock-agentcore", region_name="us-west-2")
# Reuse the same ID for follow-up turns in this session
session_id = str(uuid.uuid4())

resp = rt.invoke_agent_runtime(
    agentRuntimeArn=RUNTIME_ARN,
    qualifier="prod",
    runtimeSessionId=session_id,
    contentType="application/json",
    payload=json.dumps({"prompt": "Where is my order 1234?"}).encode(),
)
if "text/event-stream" in resp.get("contentType", ""):
    for line in resp["response"].iter_lines(chunk_size=10):
        if line and line.decode().startswith("data: "):
            print(line.decode()[6:])
else:
    print(json.loads(resp["response"].read()))

The response also carries statusCode, runtimeSessionId and MCP session fields. With the AWS CLI, the payload must be a file (--payload fileb://payload.json) and the body is written to an output file you name last. Passing an end-user ID (runtimeUserId) needs the extra action bedrock-agentcore:InvokeAgentRuntimeForUser; with IAM callers it's an unverified label, so AWS recommends JWT auth in production.

HTTPS with a bearer token

Runtimes using JWT auth can't be called with the AWS SDK. Call POST https://bedrock-agentcore.REGION.amazonaws.com/runtimes/URL_ENCODED_ARN/invocations?qualifier=DEFAULT with Authorization: Bearer TOKEN, Content-Type: application/json and the header X-Amzn-Bedrock-AgentCore-Runtime-Session-Id. Encode the ARN with urllib.parse.quote(arn, safe="").

WebSocket, shell commands and stopping sessions

  • Bidirectional streaming (voice, live UIs): connect to wss://bedrock-agentcore.REGION.amazonaws.com/runtimes/ARN/ws with SigV4 headers, a presigned URL or OAuth. It isn't a regular SDK call: use the SDK's AgentCoreRuntimeClient(region=...).generate_ws_connection(runtime_arn=...) with a WebSocket library. Frames up to 64 KB, connections up to 60 minutes.
  • Shell commands into a running session: invoke_agent_runtime_command(agentRuntimeArn=..., runtimeSessionId=..., body={"command": "ls /tmp", "timeout": 60}) streams stdout, stderr and an exit code; interactive shells use agentcore runtime shell --id ID. Commands run as root in the session's VM, so grant these actions narrowly. Runtimes created before 17 March 2026 (commands) or 5 June 2026 (interactive shells) must be redeployed to use them.
  • stop_runtime_session(agentRuntimeArn=..., runtimeSessionId=..., qualifier="DEFAULT") ends a session immediately, which stops billing for it.

Authentication and the execution role

Inbound

Each runtime version uses one mode: IAM (SigV4), the default, or JWT from your identity provider.

Accept tokens from an Amazon Cognito user pool (authorizerConfiguration for create or update, JSON) 
{
  "customJWTAuthorizer": {
    "discoveryUrl": "https://cognito-idp.us-west-2.amazonaws.com/USER_POOL_ID/.well-known/openid-configuration",
    "allowedClients": ["APP_CLIENT_ID"]
  }
}
  • Cognito access tokens have client_id but no aud, so use allowedClients; other providers can use allowedAudience, allowedScopes or customClaims. The token's issuer must match the discovery document.
  • Your code receives the Authorization header only if you add it to requestHeaderConfiguration.
  • allowedWorkloadConfiguration restricts a JWT runtime to calls through your AgentCore Gateway; for IAM runtimes, use a resource-based policy that denies every principal except the Gateway's role.
  • Resource-based policies on the runtime and its endpoint allow cross-account calls; both must allow the caller, and the calls count against the owner's quotas.

Outbound with AgentCore Identity

When a user calls with a JWT, Runtime exchanges it for a workload access token and hands it to your code. SDK decorators then fetch the user's OAuth token or an API key from the Identity token vault, so secrets never sit in your code or environment.

Read the user's Google Drive on their behalf (Python, AgentCore SDK; the provider is created in Identity first) 
from bedrock_agentcore.identity.auth import requires_access_token


@requires_access_token(
    provider_name="google-provider",
    scopes=["https://www.googleapis.com/auth/drive.readonly"],
    auth_flow="USER_FEDERATION",
    # First use: send this consent URL to the user
    on_auth_url=lambda url: print("Authorize at:", url),
)
async def list_drive_files(*, access_token: str):
    ...

auth_flow is USER_FEDERATION (user consent), M2M (client credentials) or ON_BEHALF_OF_TOKEN_EXCHANGE; @requires_api_key(provider_name=...) does the same for API keys. Identity is free when used through Runtime or Gateway.

The execution role

Trust policy with confused-deputy conditions (as in AWS's Runtime permissions page) 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Service": "bedrock-agentcore.amazonaws.com"},
    "Action": "sts:AssumeRole",
    "Condition": {
      "StringEquals": {"aws:SourceAccount": "111111111111"},
      "ArnLike": {"aws:SourceArn": "arn:aws:bedrock-agentcore:us-west-2:111111111111:*"}
    }
  }]
}

The permissions policy needs ECR pull (ecr:BatchGetImage, ecr:GetDownloadUrlForLayer, ecr:GetAuthorizationToken) for containers, CloudWatch Logs on /aws/bedrock-agentcore/runtimes/*, X-Ray, cloudwatch:PutMetricData for the bedrock-agentcore namespace, and whatever your agent calls (for example bedrock:InvokeModel). Any code in the microVM can read these credentials, so scope the role to what the agent needs. Callers need bedrock-agentcore:InvokeAgentRuntime on both the runtime and the endpoint ARN.

Networking and storage

  • VPC mode (networkMode: VPC with subnets and security groups): Runtime places network interfaces in your private subnets (supported Availability Zone IDs only). Public subnets give no internet access: use NAT, and add interface endpoints for ecr.dkr, ecr.api and logs, an S3 gateway endpoint, and the services your agent calls (such as bedrock-runtime). Runtimes created since May 2026 no longer get a hidden S3 path: your VPC governs all traffic.
  • IAM condition keys bedrock-agentcore:subnets and bedrock-agentcore:securityGroups let you require VPC mode on CreateAgentRuntime.
  • Inbound PrivateLink: interface endpoints com.amazonaws.REGION.bedrock-agentcore (data plane) and bedrock-agentcore-control.
  • Session storage (preview, free during preview): a per-session mount (sessionStorage, up to 1 GB) that survives stop and resume of the same session ID; wiped after 14 days unused or on a version update.
  • EFS and S3 Files access points (VPC only, up to 5 mounts in total): storage shared across sessions and agents; open TCP 2049 and grant the role the client mount and write actions.

MCP servers, A2A and AG-UI

An MCP server

Set serverProtocol to MCP and serve Streamable HTTP on 0.0.0.0:8000/mcp. AWS's examples now use version 2 of the MCP Python SDK (mcp>=2.3,<3).

main.py: a stateless MCP tool server (Python, MCP SDK v2, as in the Runtime MCP guide) 
from mcp.server import MCPServer
from starlette.requests import Request
from starlette.responses import JSONResponse

mcp = MCPServer()


@mcp.tool()
def add_numbers(a: int, b: int) -> int:
    """Add two numbers together"""
    return a + b


@mcp.custom_route("/ping", methods=["GET"])
async def ping(request: Request) -> JSONResponse:
    return JSONResponse({"status": "Healthy"})


if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8000, stateless_http=True)
  • Clients connect to https://bedrock-agentcore.REGION.amazonaws.com/runtimes/URL_ENCODED_ARN/invocations?qualifier=DEFAULT with a bearer token and Accept: application/json, text/event-stream; the MCP Inspector works for testing.
  • With MCP protocol versions up to 2025-11-25, most errors come back as HTTP 200 with a JSON-RPC error inside, so check the body (and retry code -32005, a session still starting). From 2026-07-28 the HTTP status reflects the error.
  • Stateful servers (stateless_http=False) are supported for elicitation, sampling and progress on older protocol versions. A runtime can also sit behind an AgentCore Gateway as a target.

A2A and AG-UI

A2A: serve JSON-RPC on port 9000 with an agent card; with Strands, serve_a2a(StrandsA2AExecutor(agent_factory=create_agent)) from bedrock_agentcore.runtime handles the port, ping and card. Callers fetch the card from .../runtimes/ESCAPED_ARN/invocations/.well-known/agent-card.json. AG-UI (March 2026): install bedrock-agentcore[ag-ui] and use serve_ag_ui(agent) to stream AG-UI events to a web front end.

Quotas, pricing and observability

Quotas

Adjustable: 5,000 active sessions per account in us-east-1 and us-west-2 (2,500 elsewhere), 25 new sessions per second, 1,000 data-plane calls per second shared by all invoke, command, shell and stop actions, 1,000 runtimes, 1,000 versions and 10 endpoints per runtime. Fixed: 2 vCPU and 8 GB per microVM session, 2 GB images, 100 MB payloads, 4 KB of environment variables per runtime, control-plane rates of 50 changes, 150 gets and 25 lists per second.

Pricing

  • V1 microVMs: $0.0895 per vCPU-hour and $0.00945 per GB-hour. V2: $0.1276 per vCPU-hour and $0.0169 per GB-hour. Billed per second (1-second minimum, 128 MB memory minimum) from start to termination.
  • CPU isn't billed while the agent waits on I/O (most agent time is spent waiting for models and tools); memory is. Idle time until the timeout is billed too, so short idle timeouts and StopRuntimeSession save money.
  • Instances: the EC2 price plus a management fee (12% in AWS's example, 7.8% for G-series), plus EBS.
  • AWS's worked example: a V2 support agent with 1 million 10-minute sessions a month at 90% I/O wait costs about $0.0067 per session.

Observability and audit

  • Turn on CloudWatch Transaction Search once per account and Region, and start your code with the AWS OpenTelemetry distribution (opentelemetry-instrument) to get agent spans.
  • Logs go to /aws/bedrock-agentcore/runtimes/AGENT_ID-ENDPOINT_NAME/; for runtimes created since July 2026, spans go to the same log group by default.
  • Metrics in AWS/Bedrock-AgentCore: Invocations, Latency, Throttles, SystemErrors, UserErrors, SessionCount, ActiveSessionCount, CPU and memory used, and on V2 OverheadLatency.
  • In CloudTrail, InvokeAgentRuntime, command and shell calls are data events, off by default: add an advanced event selector for AWS::BedrockAgentCore::Runtime.

What's changed

  • November 2026: V2 in 10 Regions, 250 connections per V2 session, OverheadLatency metric; Python SDK 1.25.4.
  • October 2026: session endpoints and custom ports and paths; MCP protocol 2026-07-28; FUSE mounts and session context keys on V2; AgentCore CLI 1.0.
  • September 2026: platform V2 generally available (18 September).
  • August 2026: Instances compute type generally available (6 August); one shared 1,000-per-second data-plane quota; Python 3.10 and 3.11 zip runtimes blocked from updates (31 August).
  • June to July 2026: interactive shells (5 June); MMDSv2 required (30 June); higher default quotas (1 July); per-agent span log groups; Runtime as a Gateway target.
  • March to May 2026: stateful MCP, AG-UI, shell commands and session storage preview (March); Node.js zip deployment (28 April); VPC traffic fully under your control and EFS and S3 Files mounts (May); custom header passthrough.
  • 2025: preview (16 July); VPC, PrivateLink and CloudFormation (September); generally available with A2A (13 October); Python zip deployment (4 November); WebSocket streaming (2 December).
