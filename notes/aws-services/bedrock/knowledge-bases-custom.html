When to choose customer-managed

AWS now recommends Managed Knowledge Bases for most new work, but the customer-managed types (VECTOR, SQL and KENDRA) aren't deprecated. Choose them when you need:

  • Your own vector store that you can inspect, size and query directly.
  • Structured data (natural language to SQL on Redshift) or GraphRAG (Neptune Analytics).
  • Semantic-only search, semantic or hierarchical chunking, model or Data Automation parsing, or a Lambda transformation step.
  • RetrieveAndGenerate with your own prompt template, citations, query decomposition and sessions, startsWith and implicit filters, or Bedrock RAG evaluation jobs.
  • A Region where Managed Knowledge Bases aren't offered.

Choose Managed instead for SaaS connectors, document-level permissions, agentic retrieval, Gateway, Amazon Quick and cross-account access.

Status changes. Since 30 September 2026, new Confluence, SharePoint, Salesforce and web crawler connectors can't be created on customer-managed knowledge bases (existing ones keep working; they also require OpenSearch Serverless). New data sources are S3 or custom. The Kendra GenAI index type is for existing Kendra customers only: Kendra entered maintenance on 30 June 2026 and closed to new customers on 30 July 2026.

Vector stores

You choose the store in storageConfiguration. The console can quick-create OpenSearch Serverless, Aurora PostgreSQL Serverless, Neptune Analytics or S3 Vectors for you; the API needs an existing store.

Amazon S3 Vectors

The cheapest option at scale (generally available December 2025): a vector bucket and index with up to 2 billion vectors per index, sub-second cold queries and about 100 ms warm. Float32 only and semantic search only. Each vector can carry at most 1 KB of metadata and 35 keys, or ingestion fails, so avoid hierarchical chunking with large chunks. Mark AMAZON_BEDROCK_TEXT and AMAZON_BEDROCK_METADATA as non-filterable keys when you create the index; encryption can't be changed after the bucket exists.

Amazon OpenSearch

Serverless collections (hybrid search, binary vectors, startsWith filters; private access through a network policy with source service bedrock.amazonaws.com) and managed clusters (since March 2025; the domain must have public access, version 2.13 or later, 2.16 for binary vectors). The index must use the faiss engine with HNSW; nmslib fails. Custom metadata used in filters needs a keyword type (or a keyword subfield), or filters fail with a "Rewrite first" error.

Amazon Aurora PostgreSQL (pgvector)

Same account, pgvector 0.5.0 or later, the RDS Data API enabled, credentials in Secrets Manager. You create the table and indexes yourself:

Prepare Aurora for a knowledge base (SQL, from the Aurora user guide; use the embedding model's dimension for vector(n)) 
CREATE EXTENSION IF NOT EXISTS vector;
CREATE SCHEMA bedrock_integration;
CREATE ROLE bedrock_user WITH PASSWORD 'password' LOGIN;
GRANT ALL ON SCHEMA bedrock_integration to bedrock_user;
CREATE TABLE bedrock_integration.bedrock_kb (id uuid PRIMARY KEY, embedding vector(1024), chunks text, metadata json, custom_metadata jsonb);
CREATE INDEX ON bedrock_integration.bedrock_kb USING hnsw (embedding vector_cosine_ops) WITH (ef_construction=256);
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (to_tsvector('simple', chunks));
CREATE INDEX ON bedrock_integration.bedrock_kb USING gin (custom_metadata);

Use to_tsvector('english', chunks) for English hybrid search. With metadata filters on pgvector 0.8.0 or later, set hnsw.iterative_scan = 'relaxed_order' on the database, or filtered queries return too few results. The field mapping can't change after the knowledge base is created.

Others

Neptune Analytics for GraphRAG (an empty graph whose vector index, created with the graph, matches the embedding dimension); Pinecone (endpoint and an API key secret), Redis Enterprise Cloud (TLS and certificates in the secret) and MongoDB Atlas (hybrid search needs a text search index; filter fields must be configured in the vector index). Third-party stores need bedrock:AssociateThirdPartyKnowledgeBase for their secret.

Hybrid search (keyword plus semantic) works only on OpenSearch Serverless, Aurora and MongoDB Atlas with a filterable text field; on every other store a HYBRID request silently runs as semantic. The embedding dimension and data type must match the index, and binary vectors work only on OpenSearch.

Creating a knowledge base

An S3 Vectors index and a knowledge base on it with Titan Text Embeddings V2 (Python, boto3) 
import time

import boto3

region, account = "us-east-1", "111111111111"
s3v = boto3.client("s3vectors", region_name=region)
agent = boto3.client("bedrock-agent", region_name=region)

s3v.create_vector_bucket(vectorBucketName="kb-vectors")
s3v.create_index(
    vectorBucketName="kb-vectors",
    indexName="docs-index",
    dimension=1024,
    distanceMetric="cosine",
    dataType="float32",
    # Bedrock stores chunk text and its own metadata here; keep them non-filterable
    metadataConfiguration={"nonFilterableMetadataKeys": ["AMAZON_BEDROCK_TEXT", "AMAZON_BEDROCK_METADATA"]},
)

kb = agent.create_knowledge_base(
    name="docs-kb",
    roleArn=f"arn:aws:iam::{account}:role/BedrockKbServiceRole",
    knowledgeBaseConfiguration={
        "type": "VECTOR",
        "vectorKnowledgeBaseConfiguration": {
            "embeddingModelArn": f"arn:aws:bedrock:{region}::foundation-model/amazon.titan-embed-text-v2:0",
            "embeddingModelConfiguration": {"bedrockEmbeddingModelConfiguration": {
                "dimensions": 1024,
                "embeddingDataType": "FLOAT32",
            }},
        },
    },
    storageConfiguration={
        "type": "S3_VECTORS",
        # indexArn alone, or vectorBucketArn plus indexName; never indexArn plus indexName
        "s3VectorsConfiguration": {"indexArn": f"arn:aws:s3vectors:{region}:{account}:bucket/kb-vectors/index/docs-index"},
    },
)["knowledgeBase"]
kb_id = kb["knowledgeBaseId"]
while agent.get_knowledge_base(knowledgeBaseId=kb_id)["knowledgeBase"]["status"] == "CREATING":
    time.sleep(15)
  • Other stores: "type": "OPENSEARCH_SERVERLESS" with opensearchServerlessConfiguration {collectionArn, vectorIndexName, fieldMapping {vectorField, textField, metadataField}}; "type": "RDS" with rdsConfiguration {resourceArn, credentialsSecretArn, databaseName, tableName, fieldMapping {primaryKeyField, vectorField, textField, metadataField, customMetadataField}}; and similar objects for the rest.
  • Embedding models: Titan Text Embeddings V2 (1,024, 512 or 256 dimensions; the most Regions), Cohere Embed English and Multilingual v3, Cohere Embed v4, Nova Multimodal Embeddings.
  • For multimodal content, set supplementalDataStorageConfiguration (an S3 location for extracted media) at creation: it can't be added later.
  • Service role: trusted by bedrock.amazonaws.com with aws:SourceAccount and aws:SourceArn conditions on knowledge-base/*, with bedrock:InvokeModel on the embedding model, s3:ListBucket and s3:GetObject on the source bucket, and the store's actions (s3vectors:PutVectors, QueryVectors, GetVectors, DeleteVectors, GetIndex; aoss:APIAccessAll; rds-data:ExecuteStatement; and so on).

AWS warns that CreateDataSource and StartIngestionJob don't pass a role, so there's no iam:PassRole check: anyone who manages data sources can ingest anything the knowledge base's role can read, and anyone with bedrock:Retrieve can read everything synced (customer-managed KBs have no document permissions). Scope the role to specific buckets and prefixes, and treat data source actions as privileged.

Data sources and ingestion

  • S3: {"type": "S3", "s3Configuration": {"bucketArn": ..., "inclusionPrefixes": ["policies/"]}} (a general-purpose bucket in the same Region, exactly one prefix, cross-account with bucketOwnerAccountId).
  • Custom: {"type": "CUSTOM"}, with documents pushed by IngestKnowledgeBaseDocuments (up to 25 per call, 6 MB). Direct ingestion also works on S3 sources but doesn't write to the bucket, so the next sync overwrites it unless you mirror the change; never run it during a sync.
  • Metadata: next to each S3 file, FILE.EXT.metadata.json (up to 10 KB), for example {"metadataAttributes": {"department": {"value": {"type": "STRING", "stringValue": "finance"}, "includeForEmbedding": true}}}. includeForEmbedding adds the attribute to the embedded text. CSV files can map columns to content and metadata with a record-based structure file.
  • dataDeletionPolicy: DELETE removes the vectors when the data source or knowledge base is deleted (the store itself stays); RETAIN keeps them. Set it explicitly.
  • Sync: StartIngestionJob is incremental (only one job at a time per knowledge base, five per account, and 0.1 starts per second); text files up to 50 MB, up to 100 GB per job. Formats: TXT, Markdown, HTML, Word, CSV, Excel and PDF, plus images, audio and video with multimodal parsing.
  • Multimodal: Nova Multimodal Embeddings embeds images, audio and video directly (text or image queries, visual similarity) but can't search speech; Data Automation parsing converts media to text (transcripts, scene summaries, OCR) and supports full RetrieveAndGenerate.

Chunking, parsing and transforms

All set in vectorIngestionConfiguration on the data source. The chunking strategy and parser type can't be changed later: create a new data source to change them.

  • Default (omit it): about 300 tokens, respecting sentences.
  • FIXED_SIZE: maxTokens (1 to 8,192) and overlapPercentage (1 to 99).
  • HIERARCHICAL: exactly two levelConfigurations (parent, then child maxTokens) and overlapTokens. Search matches small child chunks and returns their parents, so you get precise matching with broader context (and possibly fewer results).
  • SEMANTIC: maxTokens, bufferSize (0 or 1 neighbouring sentences) and breakpointPercentileThreshold (50 to 99); splits where meaning changes, using a model (extra cost).
  • NONE: one chunk per file, for pre-split content or a Lambda that does its own chunking.
  • Parsing: the default parser extracts text only; BEDROCK_FOUNDATION_MODEL uses a vision model (Claude, Nova or Llama 4) with your parsing prompt to transcribe tables and describe figures; BEDROCK_DATA_AUTOMATION costs $0.010 per page. Both process every PDF (including text-only ones), fall back to the default parser silently on failure, and handle up to 1,000 files per data source.
  • Lambda transformation (customTransformationConfiguration, step POST_CHUNKING, with an intermediate S3 location): your function reads and rewrites batches of chunks, to chunk your own way (with NONE) or to add chunk-level metadata, which overrides file-level metadata.
An S3 source with semantic chunking and model parsing that keeps vectors if the source is deleted (Python, boto3) 
ds = agent.create_data_source(
    knowledgeBaseId=kb_id,
    name="policies-s3",
    dataDeletionPolicy="RETAIN",
    dataSourceConfiguration={"type": "S3", "s3Configuration": {
        "bucketArn": "arn:aws:s3:::policies-111111111111",
        "inclusionPrefixes": ["published/"],
    }},
    # Customer managed key for transient data during sync
    serverSideEncryptionConfiguration={"kmsKeyArn": "arn:aws:kms:us-east-1:111111111111:key/KEY_ID"},
    vectorIngestionConfiguration={
        "chunkingConfiguration": {
            "chunkingStrategy": "SEMANTIC",
            "semanticChunkingConfiguration": {"maxTokens": 512, "bufferSize": 1, "breakpointPercentileThreshold": 95},
        },
        "parsingConfiguration": {
            "parsingStrategy": "BEDROCK_FOUNDATION_MODEL",
            "bedrockFoundationModelConfiguration": {
                "modelArn": "arn:aws:bedrock:us-east-1:111111111111:inference-profile/us.anthropic.claude-haiku-4-5-20251001-v1:0",
                "parsingModality": "MULTIMODAL",
                "parsingPrompt": {"parsingPromptText": "Transcribe all text, render tables as markdown, and describe figures."},
            },
        },
    },
)["dataSource"]
agent.start_ingestion_job(knowledgeBaseId=kb_id, dataSourceId=ds["dataSourceId"])

Retrieve

Hybrid search with a metadata filter, then Cohere reranking (Python, boto3) 
rt = boto3.client("bedrock-agent-runtime", region_name="us-east-1")

r = rt.retrieve(
    knowledgeBaseId=kb_id,
    retrievalQuery={"text": "What is the refund window for annual plans?"},
    retrievalConfiguration={"vectorSearchConfiguration": {
        # Candidates before reranking (1-100)
        "numberOfResults": 20,
        # OpenSearch Serverless, Aurora and MongoDB only
        "overrideSearchType": "HYBRID",
        # andAll and orAll need at least two conditions
        "filter": {"andAll": [
            {"equals": {"key": "doc_type", "value": "policy"}},
            {"greaterThanOrEquals": {"key": "year", "value": 2025}},
        ]},
        "rerankingConfiguration": {
            "type": "BEDROCK_RERANKING_MODEL",
            "bedrockRerankingConfiguration": {
                "numberOfRerankedResults": 5,
                "modelConfiguration": {"modelArn": "arn:aws:bedrock:us-east-1::foundation-model/cohere.rerank-v3-5:0"},
            },
        },
    }},
)
for res in r["retrievalResults"]:
    print(round(res["score"], 3), res["location"].get("s3Location", {}).get("uri"), res["content"]["text"][:80])
  • Filter operators: equals, notEquals, the numeric comparisons, in, notIn, listContains, stringContains and startsWith (OpenSearch Serverless only; neither of the last two on S3 Vectors), combined with andAll and orAll.
  • Implicit filters (implicitFilterConfiguration with up to 25 described attributes and a Claude model) let a model turn "policies from 2025 for finance" into a filter automatically.
  • Rerank API on its own: rt.rerank(queries=[...], sources=[...], rerankingConfiguration={...}) reorders any text list (Amazon Rerank 1.0 or Cohere Rerank 3.5, $2.00 per 1,000 queries of up to 100 documents; Amazon Rerank isn't in us-east-1).
  • numberOfResults is a maximum: hierarchical chunking, table context merging and reranking can return fewer. Guardrails on Retrieve check the query, never the retrieved chunks.

RetrieveAndGenerate

Answer with citations, a custom prompt, a guardrail, query decomposition and a session (Python, boto3) 
MODEL = "arn:aws:bedrock:us-east-1:111111111111:inference-profile/us.anthropic.claude-haiku-4-5-20251001-v1:0"
# $search_results$ is required; without $output_format_instructions$ you lose citations
TEMPLATE = """Answer using only the search results below. If the answer isn't there, say you don't know.
$search_results$
$output_format_instructions$"""


def ask(question, session_id=None):
    req = {
        "input": {"text": question},
        "retrieveAndGenerateConfiguration": {
            "type": "KNOWLEDGE_BASE",
            "knowledgeBaseConfiguration": {
                "knowledgeBaseId": kb_id,
                "modelArn": MODEL,
                "retrievalConfiguration": {"vectorSearchConfiguration": {"numberOfResults": 8}},
                "orchestrationConfiguration": {"queryTransformationConfiguration": {"type": "QUERY_DECOMPOSITION"}},
                "generationConfiguration": {
                    "promptTemplate": {"textPromptTemplate": TEMPLATE},
                    "guardrailConfiguration": {"guardrailId": "GUARDRAIL_ID", "guardrailVersion": "1"},
                    "inferenceConfig": {"textInferenceConfig": {"temperature": 0.2, "maxTokens": 800}},
                },
            },
        },
    }
    # Reuse the ID Bedrock returned; you can't make one up
    if session_id:
        req["sessionId"] = session_id
    r = rt.retrieve_and_generate(**req)
    # Citations are at the top level of the response
    for c in r["citations"]:
        span = c["generatedResponsePart"]["textResponsePart"]["span"]
        sources = [ref["location"].get("s3Location", {}).get("uri") for ref in c["retrievedReferences"]]
        print(span, sources)
    return r["output"]["text"], r["sessionId"]


answer, sid = ask("Who approves travel over 5,000 dollars?")
follow_up, _ = ask("And for international trips?", sid)
  • RetrieveAndGenerateStream streams output text and citation events. sessionConfiguration.kmsKeyArn encrypts session data with your key.
  • Query decomposition splits a complex question into sub-queries before retrieval. Placeholders: $query$, $search_results$, $output_format_instructions$ and $current_time$.
  • "type": "EXTERNAL_SOURCES" answers from a single document you pass (S3 or bytes up to 10 MB) without a knowledge base.

Structured data and GraphRAG

Structured data (type SQL)

A SQL knowledge base turns questions into SQL against Amazon Redshift (provisioned or Serverless, with IAM, user or secret authentication) over Redshift databases or Glue Data Catalog tables. Give it table and column descriptions and up to 10 curated example queries in queryGenerationConfiguration; a sync ingests the schema metadata. Retrieve returns rows, RetrieveAndGenerate answers from them (only 10 results reach the model), and GenerateQuery returns just the SQL (2 per second, English questions).

Get the SQL for a question without running it (Python, boto3) 
sql = rt.generate_query(
    queryGenerationInput={"type": "TEXT", "text": "Top 5 customers by revenue in 2026"},
    transformationConfiguration={
        "mode": "TEXT_TO_SQL",
        "textToSqlConfiguration": {
            "type": "KNOWLEDGE_BASE",
            "knowledgeBaseConfiguration": {"knowledgeBaseArn": "arn:aws:bedrock:us-east-1:111111111111:knowledge-base/SQL_KB_ID"},
        },
    },
)
print(sql["queries"][0]["sql"])

Grant the role's database user SELECT only (create the "IAMR:ROLE_NAME" user and grants before the first sync), and treat generated SQL as untrusted: AWS calls arbitrary text-to-SQL a security risk. Since 10 May 2026 these knowledge bases use cross-Region inference automatically; in Seoul, Mumbai, Singapore and São Paulo requests may leave the local geography. SQL generation is charged per request, plus Redshift.

GraphRAG with Neptune Analytics

A VECTOR knowledge base on NEPTUNE_ANALYTICS storage, with an S3 data source whose contextEnrichmentConfiguration (BEDROCK_FOUNDATION_MODEL, method CHUNK_ENTITY_EXTRACTION, a model such as Claude Haiku 4.5 or Nova) extracts entities and relationships into a graph during ingestion. Queries start with vector search, then follow the graph to related chunks across documents, which helps multi-hop questions. Up to 1,000 files per data source by default (10,000 on request), no graph autoscaling, 7 Regions; the graph isn't deleted with the knowledge base and keeps billing until you delete it.

Security, quotas and pricing

  • Encryption: your KMS key for transient sync data (on the data source), for sessions, and on the vector store itself; S3 and Secrets Manager keys need kms:Decrypt for the role.
  • Network: interface endpoints for bedrock-agent and bedrock-agent-runtime; private OpenSearch Serverless collections; MongoDB Atlas PrivateLink; Aurora through the Data API.
  • Audit and logs: Retrieve and RetrieveAndGenerate are CloudTrail data events (off by default). Ingestion logs (per-document status and chunk counts) go to CloudWatch Logs, S3 or Firehose through log delivery, except for SQL and Kendra types.
  • Quotas (not adjustable): 100 knowledge bases per account, 5 data sources each, Retrieve and RetrieveAndGenerate 20 per second, queries up to 1,000 characters. Far lower than Managed KBs.
  • Pricing: no Knowledge Bases fee. You pay embedding tokens at ingestion and query, the vector store, generation tokens (including decomposition), semantic chunking and parsing model tokens or Data Automation pages, rerank queries, and SQL generation requests.

What's changed

  • 2026: Managed Knowledge Bases recommended in the docs (from March) and generally available (17 June); structured data uses cross-Region inference automatically (10 May); Kendra maintenance (30 June) and closure to new customers (30 July); no new SaaS connectors on customer-managed KBs (30 September); S3 Vectors in more Regions, cheaper queries, 10,000 results per query and metadata pre-filtering.
  • 2025: Data Automation generally available (3 March); GraphRAG generally available (7 March); OpenSearch managed clusters (27 March); hybrid search on Aurora and MongoDB (10 April); S3 Vectors preview (15 July) and general availability (2 December); multimodal retrieval with Nova Multimodal Embeddings (30 November).
  • 2024: hybrid search on OpenSearch (March); multiple data sources (April); MongoDB Atlas (May); semantic and hierarchical chunking, model parsing, Lambda transforms and query decomposition (10 July); binary vectors (November); Rerank, streaming, implicit filters and direct ingestion (1 December); structured data and GraphRAG preview (4 December).
  • 2023: preview (September) and general availability (28 November); Aurora (21 December).
