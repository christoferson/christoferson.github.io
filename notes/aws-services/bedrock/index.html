What Bedrock is

Amazon Bedrock is a fully managed service for building generative AI applications on foundation models from many providers (Amazon Nova, Anthropic Claude, OpenAI, Meta Llama, Mistral, DeepSeek, Qwen, Cohere, xAI and others; more than 100 models) through one set of APIs, with AWS security, logging and billing. You don't manage servers or GPUs for serverless models; you call an API and pay per token. Around the models, Bedrock adds the pieces most applications need:

  • Inference: the Converse, Invoke, OpenAI-compatible and Anthropic-compatible APIs, streaming, tool use, structured outputs, prompt caching, cross-Region inference profiles, service tiers, batch and Provisioned Throughput.
  • Agents: Amazon Bedrock AgentCore, a platform for building, running and operating agents with any framework and model (Harness, Runtime, Gateway, Identity, Memory, Policy, built-in tools, Observability, Evaluations and more).
  • Knowledge: Knowledge Bases for retrieval-augmented generation (RAG), now including a fully managed option, and Bedrock Data Automation for extracting structure from documents, images, audio and video.
  • Safety and quality: Guardrails (content filters, denied topics, sensitive information, grounding and Automated Reasoning checks), Evaluations for models and RAG (automatic metrics, human review and LLM-as-a-judge), AgentCore Evaluations for agents, and model customization (fine-tuning, distillation, importing your own models).

Bedrock has been generally available since September 2023, runs in more than 30 Regions, and model and feature availability varies by Region: always check the model card for the Region you need.

Endpoints and SDK clients

Which client for which job

Bedrock is several APIs under different service names. Picking the wrong boto3 client is the most common first error.

  • bedrock (control plane): list models, inference profiles, Guardrails, Provisioned Throughput, customization and batch jobs, evaluation jobs, invocation logging settings.
  • bedrock-runtime (inference): Converse, ConverseStream, InvokeModel, InvokeModelWithResponseStream, ApplyGuardrail, CountTokens (free), StartAsyncInvoke, plus OpenAI-compatible Chat Completions and Responses (under /openai/v1) and the Anthropic Messages API (under /anthropic).
  • bedrock-agent (build time): Knowledge Bases and data sources, Prompt management, Flows, Agents Classic.
  • bedrock-agent-runtime (run time): Retrieve, RetrieveAndGenerate, AgenticRetrieveStream, Rerank, InvokeFlow.
  • bedrock-agentcore-control and bedrock-agentcore: AgentCore control plane (create runtimes, harnesses, gateways, memories) and data plane (invoke agents and harnesses, memory events, tool sessions).
  • bedrock-data-automation and bedrock-data-automation-runtime: Data Automation projects and blueprints, and running them.

bedrock-runtime or bedrock-mantle

Bedrock has a second inference surface, bedrock-mantle.{region}.api.aws, for the Responses, Chat Completions and Messages APIs. Both use the same inference engine and the same per-token prices. Since August 2026 AWS recommends bedrock-runtime for new applications: it's where Guardrails, model invocation logging, intelligent prompt routing, application inference profiles, Provisioned Throughput and batch work. Use bedrock-mantle only for what exists only there: server-side tools such as web search, background (asynchronous) Responses, OpenAI Projects and Anthropic Workspaces, single-Region use of models that have no in-Region ID on bedrock-runtime, and a few models offered only on mantle.

Traffic on bedrock-mantle is not captured by model invocation logging, can't use Guardrails, uses a different IAM action (bedrock-mantle:CreateInference) and has its own quotas. An application that moves to mantle for one feature silently loses those controls.

Model access

How access works now

  • Since 15 October 2025 all serverless models are enabled by default in commercial Regions: anyone whose IAM policy allows bedrock:InvokeModel on the model can call it. (The console Model access page remains only in AWS GovCloud (US).)
  • For third-party models sold through AWS Marketplace, the first call starts the Marketplace subscription automatically (it can take up to 15 minutes) and accepts the model's licence terms. The caller needs aws-marketplace:Subscribe, Unsubscribe and ViewSubscriptions, and the account needs a valid payment method.
  • Anthropic models need a one-time first-time use form per account (or once in the Organizations management account, inherited by members) for bedrock-runtime.
  • Some models need extra account-level approval even then (an AccessDeniedException that names the model).

Blocking or approving models

Because access is on by default, governance is now done with IAM and SCPs. Denying aws-marketplace:Subscribe doesn't block a model; deny the invoke actions on the model ARN. Foundation model ARNs have no account ID: arn:aws:bedrock:REGION::foundation-model/MODEL_ID.

Block a model until it has been reviewed, and allow only short-term API keys (SCP, built from the documented actions and condition keys) 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnreviewedModel",
      "Effect": "Deny",
      "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
      "Resource": "arn:aws:bedrock:*::foundation-model/MODEL_ID"
    },
    {
      "Sid": "DenyLongTermApiKeys",
      "Effect": "Deny",
      "Action": "bedrock:CallWithBearerToken",
      "Resource": "*",
      "Condition": { "StringEquals": { "bedrock:BearerTokenType": "LONG_TERM" } }
    }
  ]
}

The first call to a model is authorized like any other: if your policy requires aws:SourceIp, remember that key is absent on calls through a VPC endpoint (use aws:SourceVpce instead).

Model IDs and inference profiles

You call a model by an ID, and for most current models that ID is an inference profile rather than a single-Region model ID:

  • In-Region ID (for example amazon.nova-2-lite-v1:0): processed in the Region you call. Many newer models don't have one on bedrock-runtime.
  • Geographic profile (prefix us., eu., jp., au. and others): Bedrock routes each request to a Region within that geography, which keeps data in the geography and gives higher throughput.
  • Global profile (prefix global.): routes to any supported commercial Region, with the highest throughput and about 10% lower price than geographic profiles.
  • Application inference profile: one you create (wrapping a model or a system profile) so you can tag it and track cost per application or team.

Copy IDs from the current model card: many examples in the documentation and on the internet use models that have reached end of life. Inference profiles, quotas, tiers and batch are covered in depth on the inference page.

Calling through a profile needs IAM permission on the inference profile ARN and the foundation model ARN in every Region it can route to. With a Global profile, an SCP that restricts aws:RequestedRegion must also allow the value unspecified, or the calls fail. Global profiles may process data outside your geography, so check them against data residency rules.

First calls

Converse from the AWS CLI

Converse is the API to start with: one request shape for every text and multimodal model, with system prompts, tools, Guardrails and prompt caching. It needs bedrock:InvokeModel; ConverseStream needs bedrock:InvokeModelWithResponseStream.

One question, one answer (AWS CLI v2; the CLI can't stream) 
aws bedrock-runtime converse --region us-east-1 \
  --model-id global.anthropic.claude-sonnet-5-5 \
  --system '[{"text": "You are a concise AWS assistant."}]' \
  --messages '[{"role": "user", "content": [{"text": "Explain Amazon Bedrock in two sentences."}]}]' \
  --inference-config '{"maxTokens": 512, "temperature": 0.5}' \
  --query 'output.message.content[0].text' --output text

Converse, streaming and InvokeModel in Python

The three basic patterns (Python, boto3) 
import json
import boto3

brt = boto3.client("bedrock-runtime", region_name="us-east-1")
# Global profile; use us.anthropic.claude-sonnet-5-5 to keep processing in the US
MODEL = "global.anthropic.claude-sonnet-5-5"

# 1) Converse: same request shape for every model
r = brt.converse(
    modelId=MODEL,
    system=[{"text": "You are a concise AWS assistant."}],
    messages=[{"role": "user", "content": [{"text": "What is a cross-Region inference profile?"}]}],
    inferenceConfig={"maxTokens": 512, "temperature": 0.5},
)
print(r["output"]["message"]["content"][0]["text"])
print(r["stopReason"], r["usage"])  # end_turn | tool_use | max_tokens ..., token counts

# 2) ConverseStream: print text as it arrives, then the usage
s = brt.converse_stream(
    modelId=MODEL,
    messages=[{"role": "user", "content": [{"text": "List three Bedrock features."}]}],
)
for event in s["stream"]:
    if "contentBlockDelta" in event:
        print(event["contentBlockDelta"]["delta"].get("text", ""), end="")
    elif "metadata" in event:
        print("\n", event["metadata"]["usage"])

# 3) InvokeModel: the provider's native body (here Anthropic Messages)
body = {
    "anthropic_version": "bedrock-2023-05-31",
    "max_tokens": 512,
    "messages": [{"role": "user", "content": "Summarize Bedrock in one line."}],
}
resp = brt.invoke_model(modelId=MODEL, body=json.dumps(body))
print(json.loads(resp["body"].read())["content"][0]["text"])

The response's content is a list of blocks. Reading the first block as text works for a plain answer; with tools or reasoning enabled, check each block's type. Converse is portable across models; use InvokeModel when you need a provider-specific feature or a non-chat model (embeddings, images).

API keys and OpenAI- or Anthropic-compatible SDKs

Bedrock API keys (July 2025) let tools that expect a bearer token call Bedrock. Short-term keys last up to 12 hours (or the session length), work in one Region and carry the creator's permissions; AWS recommends them. Long-term keys create an IAM user with a service-specific credential and are meant only for exploration. boto3 picks up a key from AWS_BEARER_TOKEN_BEDROCK.

Call Bedrock with the OpenAI SDK through bedrock-runtime (Python; the model ID is the OpenAI model card's Global ID) 
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://bedrock-runtime.us-east-1.amazonaws.com/openai/v1",
    api_key=os.environ["BEDROCK_API_KEY"],
)
resp = client.responses.create(model="global.openai.gpt-5.6-sol", input="Explain Bedrock in one sentence.")
print(resp.output_text)

The Anthropic SDK works the same way with base_url set to https://bedrock-runtime.us-east-1.amazonaws.com/anthropic. On bedrock-runtime the Responses API is always synchronous.

Quotas and throttling

  • Inference is limited mainly by tokens per minute (TPM) per model per Region, with separate quotas for single-Region and cross-Region (profile) use; some models also have requests per minute. Since September 2026 a per-account Cross-Model Max Tokens Per Day quota replaced the per-model daily quotas. The quota names say InvokeModel, but Converse, Responses and Chat Completions on bedrock-runtime share them.
  • A request reserves its input tokens plus maxTokens when it starts, and output tokens of some newer models count several times toward the quota. A needlessly large maxTokens causes throttling even when replies are short; you're billed only for actual tokens.
  • Prompt cache reads don't count toward TPM; cache writes do. Embedding models are limited by requests per minute.
  • Throttling returns HTTP 429 ThrottlingException: retry with exponential backoff and jitter, and for production add fallbacks across Regions or models; cross-Region profiles raise throughput but aren't an availability guarantee.
  • New accounts can have lower defaults. Request increases in Service Quotas where the quota is adjustable, otherwise through your account team; increases aren't granted for Legacy models.

Model lifecycle

Each model is Active, Legacy or at end of life (EOL), per Region. Once a model is Legacy, new customers can't start using it, existing users can lose access after 15 days without use, and you can't buy new Provisioned Throughput or start new fine-tuning on it; at EOL requests fail and nothing migrates automatically. For models launched before 7 September 2026, AWS gives at least 12 months on Bedrock and 6 months of Legacy, and for EOL dates after 1 February 2026 a final public extended access phase at a higher price set by the provider. Models launched since then show an "EOL no sooner than" date on the model card.

Check a model's lifecycle status before building on it (AWS CLI) 
aws bedrock get-foundation-model --model-identifier anthropic.claude-sonnet-4-5-20250929-v1:0 \
  --query 'modelDetails.modelLifecycle'

Recent examples: Claude Sonnet 4 reached EOL on 14 October 2026, Nova Canvas and Nova Reel on 30 September 2026; Claude Sonnet 4.5 became Legacy on 8 October 2026 with EOL on 8 April 2027; and a large group of open-weight models (Llama 3 and 4, DeepSeek, Mistral, Qwen3 Coder and others) became Legacy on 30 September 2026 with EOL on 30 March 2027. Build a model swap into your release process.

Evaluating models, RAG and agents

Before you choose a model, change a prompt or ship a knowledge base, measure it on your own data. Bedrock has two evaluation services:

  • Amazon Bedrock Evaluations runs evaluation jobs (control plane bedrock client) over a prompt dataset in S3 and writes scores and per-record results to S3. Job types:
    • Automatic (generally available April 2024): algorithmic metrics such as accuracy, robustness and toxicity, on built-in or your own datasets.
    • LLM-as-a-judge (generally available March 2025): a judge model scores answers for quality and responsible-AI metrics, with custom metrics since April 2025.
    • Human: your own work team rates answers.
    • RAG evaluation (generally available March 2025): scores a Knowledge Base on retrieval alone, or on retrieval plus the generated answer (for example correctness, completeness and faithfulness to the retrieved context).
    • Bring your own responses: evaluate answers produced outside Bedrock, from another model or your own RAG pipeline.
  • AgentCore Evaluations (generally available 31 March 2026) scores agents from their traces: built-in evaluators such as Builtin.Helpfulness, tool selection and goal success, custom LLM or code evaluators, and online, on-demand or batch runs. It's covered on the Observability, Evaluations and Optimization page.

Cost: evaluation jobs charge only for the model inference they run (judge-model tokens at on-demand rates); algorithmic scores are free, and human evaluation is $0.21 per completed task. Run the same dataset after every model, prompt or retrieval change and compare. Details, dataset formats and job code: Model and RAG evaluation.

Pricing model

  • On-demand: per million input and output tokens, by model and Region; the same on both endpoints. Cross-Region profiles add no routing fee; Global profiles are about 10% cheaper than geographic ones.
  • Service tiers: Standard (default), Priority (75% more, served first), Flex (50% less, for work that can wait), and Reserved (fixed monthly price for guaranteed tokens per minute, 1- or 3-month terms, through your account team).
  • Batch inference: 50% less than on-demand for supported models, from JSONL files in S3, typically within 24 hours.
  • Prompt caching: cache writes cost more than normal input, cache reads much less, so it pays off for long, repeated prefixes.
  • Provisioned Throughput: hourly per model unit with no commitment, 1 month or 6 months; needed mainly for some custom models.
  • Everything else is priced separately: Knowledge Bases (managed: storage per GB and per retrieval call; customer-managed: your vector store plus embedding tokens), Guardrails per 1,000 text units per policy, AgentCore by consumption (CPU and memory seconds, gateway calls, memory events and records), and customization by training tokens plus model storage.

To see cost per application or team, use application inference profiles with cost allocation tags; the requestMetadata field on Converse also appears in invocation logs for per-request attribution.

Security baseline

IAM

  • Grant bedrock:InvokeModel and bedrock:InvokeModelWithResponseStream only on the model and profile ARNs an application uses; start from AmazonBedrockLimitedAccess or a custom policy rather than AmazonBedrockFullAccess.
  • Useful condition keys: bedrock:InferenceProfileArn (allow a model only through a given profile), bedrock:GuardrailIdentifier (require a guardrail on every call), bedrock:ServiceTier, bedrock:BearerTokenType and bedrock:DataRetentionMode.
  • API keys aren't recorded in CloudTrail; control them with bedrock:CallWithBearerToken and block long-term keys as in the SCP above.

Data protection

  • Your prompts and responses aren't used to train Amazon or third-party models and aren't shared with model providers; models run in AWS-owned deployment accounts the providers can't access.
  • Bedrock doesn't store your content by default, with exceptions for abuse detection: most OpenAI models keep flagged traffic for up to 30 days, and Claude Fable 5 and 5.1 keep all traffic for up to 30 days. A data retention mode (account or project level; none forces zero retention) controls this for the Messages, Chat Completions and Responses APIs, and models that require retention then refuse requests.
  • Use customer managed KMS keys for what Bedrock does store: custom models and customization jobs, Knowledge Base data and vector stores, Guardrails, AgentCore Memory and the credential vault, evaluation jobs and log destinations.

Network

Use interface VPC endpoints so traffic stays off the internet: com.amazonaws.REGION.bedrock-runtime for inference, plus bedrock, bedrock-agent, bedrock-agent-runtime, bedrock-mantle, bedrock-agentcore and FIPS variants as needed. The default endpoint policy allows everything: restrict it to the actions and models the VPC needs.

Logging

Model invocation logging is off by default and is set per account and Region. It records full requests and responses with the caller's identity and token counts to CloudWatch Logs or S3 (bodies over 100 KB go to S3). Logs contain whatever users typed, so encrypt them, restrict access and set retention.

Turn on invocation logging to CloudWatch Logs and S3 (AWS CLI) 
aws bedrock put-model-invocation-logging-configuration --logging-config '{
  "cloudWatchConfig": {
    "logGroupName": "/bedrock/invocations",
    "roleArn": "arn:aws:iam::111111111111:role/bedrock-invocation-logging"
  },
  "s3Config": { "bucketName": "bedrock-invocation-logs-111111111111", "keyPrefix": "us-east-1/" },
  "textDataDeliveryEnabled": true,
  "imageDataDeliveryEnabled": true,
  "embeddingDataDeliveryEnabled": true
}'

In CloudTrail, Converse and InvokeModel calls are management events (logged by default; cross-Region calls are logged in the calling Region with the Region that served them), but Knowledge Base retrievals, flows, prompt rendering and AgentCore invocations are data events you must enable. CloudWatch metrics in the AWS/Bedrock namespace include invocations, latency, time to first token, token counts and throttles; GuardDuty can monitor Bedrock and AgentCore activity.

What's changed

The main developments since 2024, newest first. Feature pages keep their own detailed logs.

  • November 2026: AgentCore Web Answer connector; remaining Claude 3.x models reach EOL in their last Regions.
  • October 2026: Claude Sonnet 4 EOL (14 October); Claude Sonnet 4.5 to Legacy (8 October); structured outputs for Claude on both endpoints; Knowledge Base retrieval instructions; AgentCore Gateway model fallback and AgentCore CLI 1.0.
  • September 2026: new model lifecycle policy (7 September); AgentCore Runtime platform V2 (18 September); Cross-Model Max Tokens Per Day quota (21 September); customer-managed Knowledge Bases stop accepting new Confluence, SharePoint, Salesforce and web crawler connectors, and a large group of open-weight models becomes Legacy (30 September).
  • August 2026: AWS recommends bedrock-runtime for new applications (15 August); AgentCore Runtime Instances, Payments and Agent Registry generally available.
  • July 2026: Agents Classic closed to new customers (30 July).
  • June 2026: AgentCore Harness and Managed Knowledge Bases generally available (17 June); Guardrails InvokeGuardrailChecks API for agent workflows.
  • March to April 2026: AgentCore Policy (March) and Evaluations (31 March) generally available; Guardrails enforcement across accounts (3 April); Harness preview.
  • December 2025: OpenAI-compatible Responses and Chat Completions APIs; reinforcement fine-tuning; AgentCore Policy and Evaluations preview.
  • October to November 2025: AgentCore generally available (13 October); models enabled by default (15 October); Priority, Flex and Reserved service tiers.
  • July to August 2025: API keys (7 July); AgentCore preview (16 July); OpenAI open-weight models and Automated Reasoning checks generally available (5 August).
  • 2024 to early 2025: Guardrails generally available (April 2024); Converse API (May 2024); cross-Region inference and batch at 50% off (August 2024); Custom Model Import (October 2024); LLM-as-a-judge and RAG evaluation (previewed December 2024, generally available March 2025); prompt caching, intelligent prompt routing, Data Automation and Marketplace (previewed December 2024, generally available 2025).
