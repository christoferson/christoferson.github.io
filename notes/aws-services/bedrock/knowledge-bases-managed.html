Managed Knowledge Bases

The recommended way to build retrieval-augmented generation on Bedrock: connect SharePoint, Confluence, Google Drive, S3 and nine other sources, and Bedrock runs parsing, embeddings, the search index, reranking and permission-aware retrieval for you, with an agentic retrieval API that plans searches and writes cited answers.

What Bedrock manages

A Managed Knowledge Base (type MANAGED, generally available 17 June 2026) is a knowledge base where Bedrock runs the whole pipeline: crawling connectors, Smart Parsing of documents and media, a managed embedding model, an auto-scaling store of embeddings, text, metadata and raw files, always-hybrid (keyword plus semantic) search, and a managed reranker. You bring data sources and, optionally, your own embedding or reranking model. It's in the console under Amazon Bedrock AgentCore, Built-in tools, Knowledge Base, but the APIs are the usual bedrock-agent (build) and bedrock-agent-runtime (query) clients. AWS now recommends it over building your own.

Regions: us-east-1, us-west-2, eu-west-1, eu-west-2, eu-central-1, ap-northeast-1, ap-southeast-1, ap-southeast-2 and GovCloud (US-West). GovCloud supports only S3 and custom sources, no document permissions, no managed models (bring your own embedding model) and no agentic retrieval or Gateway target.

Status changes. Since 30 September 2026 customer-managed knowledge bases can't create new Confluence, SharePoint, Salesforce or web crawler connectors (existing ones keep working). Amazon Kendra went into maintenance on 30 June 2026 and closed to new customers on 30 July 2026. AWS points both to Managed Knowledge Bases.

Creating a knowledge base

Create a Managed Knowledge Base with the managed embedding model and wait until active (Python, boto3) 
import time

import boto3

agent = boto3.client("bedrock-agent", region_name="us-east-1")

kb = agent.create_knowledge_base(
    name="support-kb",
    roleArn="arn:aws:iam::111111111111:role/BedrockManagedKBRole",
    knowledgeBaseConfiguration={
        "type": "MANAGED",
        "managedKnowledgeBaseConfiguration": {
            # The default; don't pass an embedding model ARN with MANAGED
            "embeddingModelType": "MANAGED",
            # Optional customer managed key (it sits inside this object)
            "serverSideEncryptionConfiguration": {"kmsKeyArn": "arn:aws:kms:us-east-1:111111111111:key/KEY_ID"},
        },
    },
)["knowledgeBase"]
kb_id = kb["knowledgeBaseId"]
while agent.get_knowledge_base(knowledgeBaseId=kb_id)["knowledgeBase"]["status"] != "ACTIVE":
    time.sleep(10)
  • There's no vector store configuration. Creation takes 2 to 5 minutes (longer with a KMS key).
  • Custom embedding: "embeddingModelType": "CUSTOM" with an embeddingModelArn (Titan Text Embeddings V2, Cohere Embed v3 or v4, Nova Multimodal Embeddings) and embeddingModelConfiguration.bedrockEmbeddingModelConfiguration with 1,024 dimensions and float32. The choice is permanent, and a custom embedding model turns off the free managed reranker.
  • The KMS key encrypts both ingestion data and the index; the creating identity needs kms:CreateGrant, GenerateDataKey and Decrypt through Bedrock, and the service role needs nothing on the key.
Service role trust policy (as in the Managed Knowledge Base permissions page) 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Service": "bedrock.amazonaws.com"},
    "Action": "sts:AssumeRole",
    "Condition": {
      "StringEquals": {"aws:SourceAccount": "111111111111"},
      "ArnLike": {"AWS:SourceArn": "arn:aws:bedrock:us-east-1:111111111111:knowledge-base/*"}
    }
  }]
}

The role needs, depending on sources: s3:ListBucket and s3:GetObject on S3 sources (plus KMS decrypt for encrypted buckets); secretsmanager:GetSecretValue on connector secrets, and PutSecretValue where OAuth refresh tokens rotate; bedrock:InvokeModel for a custom embedding model; and cloudwatch:PutMetricData for the AWS/Bedrock/KnowledgeBases namespace, or retrieval metrics silently don't publish. The caller needs iam:PassRole to bedrock.amazonaws.com. Narrow knowledge-base/* to the KB ID once you have it.

Connectors and syncing

The 12 connectors

A data source uses dataSourceConfiguration.type: MANAGED_KNOWLEDGE_BASE_CONNECTOR, and connectorParameters.type picks the connector (all version: "1"). Credentials always live in Secrets Manager.

  • S3: bucket (cross-account allowed), prefix and regex filters, sidecar metadata files, permissions from ACL files you provide.
  • SHAREPOINT (Online): site URLs, files and pages, date and path filters, Purview sensitivity-label exclusion, up to 30 custom columns as metadata. Entra app-only with a certificate (required for permissions), user sign-in (3LO from the console), or username and password (fails with MFA).
  • ONEDRIVE (for Business), GOOGLEDRIVE (service account with domain-wide delegation for permissions, or one user's OAuth), BOX (client credentials grant for permissions, or one user's OAuth).
  • CONFLUENCE (Cloud; email and API token for permissions), CONFLUENCEONPREM (Data Center, reached privately through a VPC configuration).
  • SALESFORCE (knowledge articles and documents), SERVICENOW (knowledge articles and service catalog), ZENDESK (help center articles and community posts); these three also need connectorType set to the same value.
  • WEB: up to 10 seed URLs or 3 sitemaps, crawl depth up to 10, scope, rate, form or SAML login; no permissions, so every user sees everything it crawls.
  • CUSTOM: you push documents yourself (below).
An S3 source with a daily sync and deletion protection, then a sync (Python, boto3) 
ds = agent.create_data_source(
    knowledgeBaseId=kb_id,
    name="policies-s3",
    # The only option on Managed KBs
    dataDeletionPolicy="DELETE",
    dataSourceConfiguration={
        "type": "MANAGED_KNOWLEDGE_BASE_CONNECTOR",
        "managedKnowledgeBaseConnectorConfiguration": {
            "connectorParameters": {
                "type": "S3",
                "version": "1",
                "connectionConfiguration": {"bucketName": "policies-111111111111", "bucketOwnerAccountId": "111111111111"},
                # maxFileSizeInMegaBytes is a numeric string (default "500")
                "filterConfiguration": {"inclusionPrefixes": ["published/"], "maxFileSizeInMegaBytes": "100"},
                "metadataFilesPrefix": "metadata/",
            },
            # Skip a sync's deletions if it would remove more than 15% of documents
            "deletionProtectionConfiguration": {"deletionProtectionStatus": "ENABLED", "deletionProtectionThreshold": 15},
            "mediaExtractionConfiguration": {"imageExtractionConfiguration": {"imageExtractionStatus": "ENABLED"}},
            # Or {"weekly": {"dayOfWeek": "MONDAY"}} or a monthly day; omit for on-demand only
            "syncSchedule": {"daily": {}},
        },
    },
)["dataSource"]
ds_id = ds["dataSourceId"]
# Creating a data source is asynchronous on Managed KBs
while agent.get_data_source(knowledgeBaseId=kb_id, dataSourceId=ds_id)["dataSource"]["status"] != "AVAILABLE":
    time.sleep(5)

job = agent.start_ingestion_job(knowledgeBaseId=kb_id, dataSourceId=ds_id)["ingestionJob"]
while job["status"] not in ("COMPLETE", "FAILED", "STOPPED"):
    time.sleep(15)
    job = agent.get_ingestion_job(knowledgeBaseId=kb_id, dataSourceId=ds_id, ingestionJobId=job["ingestionJobId"])["ingestionJob"]
print(job["status"], job.get("statistics"), job.get("failureReasons"))
  • Syncs are incremental. Statistics count documents scanned, new, modified, deleted, failed and skipped; textReadyAt says when text became queryable. Up to 50 concurrent ingestion jobs per knowledge base.
  • Most connectors share three blocks: connectionConfiguration (secret, auth type, host), dataEntityConfiguration (what to crawl, such as pages, attachments or archived spaces) and filterConfiguration (include and exclude lists).
  • Custom sources ({"type": "CUSTOM", "version": "1", "aclEnabled": false}) take documents through IngestKnowledgeBaseDocuments (up to 10 per request, inline text or bytes or an S3 location, with inline metadata attributes and an optional access list) and DeleteKnowledgeBaseDocuments; no sync needed.

Parsing, chunking, metadata and media

  • Smart Parsing (free, the default) picks a strategy per document type: PDF, Word and PowerPoint, documents with embedded images, scanned documents, audio and video. Model parsing and Data Automation parsing aren't offered on Managed KBs.
  • Chunking is fixed when the data source is created: the default (300 tokens with 20% overlap; omit chunkingConfiguration), FIXED_SIZE with maxTokens and overlapPercentage, or NONE (one chunk per file). No semantic or hierarchical chunking.
  • Media: with mediaExtractionConfiguration, images (PNG, JPEG, TIFF, GIF, WebP, SVG, HEIC and more, including images inside PDFs and Office files), audio (MP3, WAV, M4A, FLAC, OGG) and video (MP4, MOV, M4V) are transcribed or captioned into searchable text. Extracted text is capped at 30 MB per file.
  • Native multimodal (11 September 2026): with TwelveLabs Marengo Embed 3.0 as a custom embedding model, a separate S3 bucket for multimodal storage (supplementalDataStorageConfiguration) and parsingStrategy: MULTI_MODAL_EMBEDDINGS, media is embedded directly, keeping visual detail; results carry media start and end times. Queries are text only. Expire only the transient_data path in that bucket with a lifecycle rule, never the whole aws/ prefix.
  • Metadata: for S3, a sidecar file FILE.EXT.metadata.json (up to 10 KB) with metadataAttributes such as {"department": {"value": {"type": "STRING", "stringValue": "billing"}}}; connectors add common fields (title, author, dates) automatically. System fields on Managed KBs start with an underscore (_source_uri, _data_source_id).

Retrieve

Hybrid search with filters, reranking and the signed-in user's permissions (Python, boto3) 
rt = boto3.client("bedrock-agent-runtime", region_name="us-east-1")

resp = rt.retrieve(
    knowledgeBaseId=kb_id,
    retrievalQuery={"text": "What is the refund window for annual plans?"},
    retrievalConfiguration={"managedSearchConfiguration": {
        # 1-100, default 5
        "numberOfResults": 8,
        # MANAGED (free, default) | CUSTOM | NONE
        "rerankingModelType": "MANAGED",
        "filter": {"andAll": [
            {"equals": {"key": "department", "value": "billing"}},
            {"greaterThanOrEquals": {"key": "effective_date", "value": "2026-01-01T00:00:00Z"}},
        ]},
    }},
    # A verified email from YOUR authentication; required for permission-enabled sources
    userContext={"userId": "alice@example.com"},
)
for r in resp["retrievalResults"]:
    print(round(r.get("score", 0), 3), r["location"]["type"], r["content"].get("text", "")[:100])
  • Use managedSearchConfiguration; vectorSearchConfiguration is for customer-managed KBs. Search is always hybrid.
  • Filters: equals, notEquals, greaterThan and the other comparisons (numbers or ISO dates), in, notIn, listContains, combined with andAll and orAll. startsWith and stringContains aren't supported on Managed KBs.
  • A custom reranker: "rerankingModelType": "CUSTOM" with rerankingConfiguration naming a Bedrock rerank model such as Cohere Rerank 3.5.
  • GetDocumentContent (with the result's documentId and metadata["_data_source_id"]) returns a presigned URL to the original file or its extracted text, valid for 5 minutes. It needs both bedrock:Retrieve and bedrock:GetDocumentContent, rechecks permissions, and allows only 5 requests per second per knowledge base.
  • For a generated answer, use agentic retrieval (below) or pass the results to Converse yourself: RetrieveAndGenerate doesn't work on Managed KBs.

Agentic retrieval

AgenticRetrieveStream plans sub-queries across up to 5 knowledge bases, retrieves, reads full documents where needed, and streams a cited answer, with traces of each step. It's the reason to pick a Managed KB for complex questions such as comparisons across documents.

Ask a multi-part question and print the answer with its sources (Python, boto3) 
stream = rt.agentic_retrieve_stream(
    messages=[{"role": "user", "content": {"text": "Compare the 2025 and 2026 travel policies for contractors."}}],
    retrievers=[{
        "description": "HR policies from SharePoint",
        "configuration": {"knowledgeBase": {
            "knowledgeBaseId": kb_id,
            "retrievalOverrides": {"maxNumberOfResults": 10},
        }},
    }],
    agenticRetrieveConfiguration={
        # MANAGED: AWS's planning model at a flat price; CUSTOM: your model ARN and tokens
        "foundationModelType": "MANAGED",
        "rerankingModelType": "MANAGED",
        "maxAgentIteration": 3,
    },
    userContext={"userId": "alice@example.com"},
    generateResponse=True,
)
results, answer = [], None
for event in stream["stream"]:
    if "traceEvent" in event:
        a = event["traceEvent"]["attributes"]
        print("trace:", a.get("step"), a.get("status"))
    elif "responseEvent" in event:
        print(event["responseEvent"]["text"], end="")
    elif "result" in event:
        results = event["result"].get("results", [])
        answer = event["result"].get("generatedResponse")
if answer:
    for c in answer.get("citations", []):
        cited = answer["answer"][c["startIndex"]:c["endIndex"]]
        sources = [results[r["resultIndex"]]["sourceRetriever"]["identifier"] for r in c["references"]]
        print(f"\n{cited[:60]!r} cites {sources}")
  • Trace steps include planning, retrieval, speculative retrieval, full document expansion, session history load and code execution in a sandbox. The result event holds deduplicated results and the answer with citations pointing into them. generateResponse=False returns results only.
  • Your own planning model: "foundationModelType": "CUSTOM" with foundationModelConfiguration naming a Bedrock model (or a bedrock-mantle model with a project ID). Guardrails (policyConfiguration.bedrockGuardrailConfiguration) work only with a custom model, only with block actions, and never filter the retrieved references.
  • Retrieval instructions (19 October 2026): a reusable resource with retrievalGuidance (how to search and prioritize), persona, answerFormat and answerPolicy. Content is reviewed asynchronously after CreateRetrievalInstruction (wait for it to become active), versions are immutable, and you apply one with retrievalInstructionConfiguration: {"retrievalInstructionId": ..., "version": ...}. Up to 50 per Region.
  • AgentCore Memory (14 August 2026): memoryConfiguration with a memory ID restores a session's history (sessionBinding with actor and session IDs; then send only the current question), searches long-term records as another retriever, and with persistenceMode: DEFAULT saves each question and answer.
  • Callers need bedrock:AgenticRetrieveStream, bedrock:Retrieve and bedrock:GetDocumentContent on the knowledge bases, bedrock:InvokeModelWithResponseStream, and extra permissions for guardrails, memory and retrieval instructions.

Permission-aware retrieval

With aclEnabled, connectors crawl each document's allowed and denied users and groups and the group memberships; queries then return only what the user in userContext may see. Eight connectors also check permissions in real time with the source at query time (SharePoint, OneDrive, Google Drive, Confluence Cloud and Data Center, Box, Zendesk, Salesforce; ServiceNow partly). S3 and custom sources use access lists you provide; the web crawler has none.

  • The user is identified only by email ({"userId": "alice@example.com"}), which must match exactly in every source; groups come from crawled memberships. Deny overrides allow, and errors fail closed (fewer results, no error).
  • CheckIngestedDocumentAcl and GetIngestedDocumentAcl (September 2026) show whether a user can see a document and its ingested access lists.

AWS's own words: "ACL awareness is not authorization." It's filtering, not a security boundary: your application must authenticate users and pass a verified email. Omit userContext and permission-enabled sources return zero results; documents on such sources without an access entry are never returned. And aclEnabled is permanent per data source, with a default that depends on the auth type (ServiceNow defaults to on): always set it explicitly.

Gateway, Quick, cross-account and private sources

  • AgentCore Gateway: the bedrock-knowledge-bases connector exposes Retrieve and AgenticRetrieveStream as MCP tools for any agent (Gateway). The admin fixes the knowledge base and settings; agents see only the query unless you expose more. The gateway passes userContext through but never derives it from the caller, so your app must add it.
  • Amazon Quick: attach up to 2 Managed KBs per Quick instance (same Region), with permission-aware results for Quick users.
  • Cross-account: a resource policy on the knowledge base (PutResourcePolicy) can allow only bedrock:Retrieve and bedrock:GetDocumentContent, without wildcards; the other account calls with the full knowledge base ARN.
  • Private sources: a VPC configuration (built on VPC Lattice; target address, port, protocol and TLS name) reaches Confluence Data Center or internal websites through an internal load balancer. Up to 5 per account and Region, failed ones included.

Security and operations

  • Network: interface endpoints com.amazonaws.REGION.bedrock-agent and bedrock-agent-runtime.
  • CloudTrail: Retrieve calls are data events on AWS::Bedrock::KnowledgeBase, off by default.
  • Metrics (AWS/Bedrock/KnowledgeBases, free): Invocations, ClientErrors, ServerErrors, Throttles, TotalIterationCount for agentic calls, and RawDataSize per knowledge base, which is what storage is billed on.
  • Ingestion logs: vended application logs to CloudWatch Logs, S3 or Firehose, with per-document crawl, sync and index status and error messages, for example a Logs Insights query filtering event.connector_document_status.Status = "FAILED". Retrieve traces can go to X-Ray.
  • Bedrock keeps queries and retrieval data temporarily for debugging support only, never for training.

Quotas, pricing and evaluation

  • Quotas: 10,000 Managed KBs per Region, 200 data sources and 10 TB of raw data per knowledge base, 10,000 characters per query, Retrieve 600 per minute per knowledge base and 100 per second per account. The agentic retrieval account limit is given as 300 per minute in the user guide but 60 in the service quotas reference, so check Service Quotas for your account.
  • Pricing: $5.00 per GB of raw data per month; $1.00 per 1,000 Retrieve calls; $4.00 per 1,000 AgenticRetrieveStream calls plus $1.00 per 1,000 of the Retrieve calls each one makes (with your own planning model, only the Retrieve calls plus your model's tokens). Managed parsing, embeddings and reranking are free. For example, 20 GB of documents and 100,000 searches a month cost about $100 plus $100.
  • Evaluation: Bedrock's RAG evaluation jobs can't target Managed KBs. Export answers and passages for a bring-your-own evaluation, use AgentCore Evaluations on agent traces, or an open-source framework such as RAGAS.

What's changed

  • 19 October 2026: retrieval instructions for agentic retrieval.
  • September 2026: ServiceNow connector, scheduled syncs and console sign-in for SharePoint, OneDrive and Confluence (4 September); Confluence Data Center connector and permission debugging APIs (9 September); Marengo native multimodal embeddings (11 September); Salesforce and Zendesk connectors (23 September); customer-managed KBs stop accepting new SaaS connectors (30 September).
  • 14 August 2026: AgentCore Memory in agentic retrieval.
  • 17 June 2026: generally available with S3, SharePoint, Confluence, Google Drive, OneDrive, web crawler and custom sources. Box and Singapore were added later.
  • March to April 2026: documentation with agentic retrieval (2 March); Gateway connector (1 April).
