Converse in depth

Messages and content blocks

  • Converse is stateless: send the whole conversation every time, appending each assistant message from output.message unchanged before the next user message.
  • Each content block holds exactly one of: text, image (png, jpeg, gif, webp; bytes, or an S3 location for Nova only), document, video, audio, cachePoint, guardContent, reasoningContent, toolUse, toolResult. Images and documents are allowed only in user messages; SDKs base64-encode bytes for you.
  • Documents (pdf, csv, doc, docx, xls, xlsx, html, txt, md) need an explicit format (Bedrock doesn't infer it from the name), a text block in the same message, and a name of letters, digits, spaces, hyphens and brackets. Keep the name neutral: it reaches the model and can carry prompt injection. With citations enabled, only txt and pdf and no S3 source.
  • inferenceConfig takes maxTokens, temperature, topP and stopSequences; model-specific settings (such as Claude's top_k or thinking) go in additionalModelRequestFields, and additionalModelResponseFieldPaths brings back native response fields. Some models restrict sampling settings (Claude Sonnet 4.5 and Haiku 4.5 accept temperature or top_p, not both, and AWS notes that Claude Sonnet 5 and 5.5 reject temperature): check the model card.
  • modelId can be a model ID, an inference profile, an application profile, a Provisioned Throughput or custom deployment ARN, a prompt router or a Prompt management version.

Response and stop reasons

The response holds output.message, stopReason, usage (with caching, inputTokens excludes cached tokens: total input is inputTokens + cacheReadInputTokens + cacheWriteInputTokens), metrics.latencyMs, the serviceTier that served it and any guardrail or router trace.

  • end_turn, stop_sequence: done. tool_use: run the tools and reply with results.
  • max_tokens: the output (or JSON) is truncated: raise maxTokens or continue.
  • guardrail_intervened, content_filtered: show a safe message and inspect the trace.
  • model_context_window_exceeded: trim or summarize history. malformed_tool_use, malformed_model_output: retry once or reprompt.

Reasoning

Claude models think through additionalModelRequestFields. Adaptive thinking (Claude 4.6 and later) lets the model decide how much to think, steered by an effort level (low, medium, high, xhigh, max) in a separate output_config object.

Multi-turn Converse with adaptive thinking on Claude Sonnet 5.5 (Python, boto3) 
import boto3

brt = boto3.client("bedrock-runtime", region_name="us-east-1")
MODEL = "global.anthropic.claude-sonnet-5-5"

history = [{"role": "user", "content": [{"text": "Plan a three-step database migration."}]}]
r = brt.converse(
    modelId=MODEL,
    system=[{"text": "You are a senior AWS engineer. Be concise."}],
    messages=history,
    # Covers thinking and the answer
    inferenceConfig={"maxTokens": 8000},
    additionalModelRequestFields={
        # Claude 5 returns empty thinking text unless display is "summarized"
        "thinking": {"type": "adaptive", "display": "summarized"},
        # Effort goes here, not inside "thinking"
        "output_config": {"effort": "medium"},
    },
)
msg = r["output"]["message"]
for block in msg["content"]:
    if "reasoningContent" in block:
        print("[thinking]", block["reasoningContent"].get("reasoningText", {}).get("text", ""))
    elif "text" in block:
        print(block["text"])
# Append unchanged: the reasoning blocks carry signatures
history.append(msg)
history.append({"role": "user", "content": [{"text": "Now add a rollback step."}]})
  • Claude 5 and later think by default even if you send no thinking field, so thinking tokens are billed as output and count toward maxTokens. To turn it off use {"type": "disabled"} where allowed; Sonnet 5.5 rejects that and needs {"type": "between_tools"}; Opus 5.5 is adaptive only.
  • The older fixed budget ({"type": "enabled", "budget_tokens": 4000}) is required on Claude 4.5 and earlier, deprecated on 4.6, and returns 400 on Opus 4.7 and later and all Claude 5 models.
  • Pass reasoning blocks back complete and unmodified, in order: any change, or sending them to a different model, is an error (Claude 5.5 binds them to the model and conversation). Thinking can't be combined with sampling changes or forced tool use, and switching thinking modes invalidates the prompt cache.

Streaming

ConverseStream sends messageStart; then per block contentBlockStart (only for tool use), contentBlockDelta (text, reasoning or partial tool input) and contentBlockStop; then messageStop with the stop reason and metadata with usage. Errors such as throttling can also arrive inside the stream.

Rebuild text and tool calls from a stream (Python, boto3; our code on the documented event shapes) 
import json


def stream_turn(brt, model, messages, tool_config):
    blocks, stop, usage = {}, None, None
    resp = brt.converse_stream(modelId=model, messages=messages, toolConfig=tool_config,
                               inferenceConfig={"maxTokens": 2048})
    for ev in resp["stream"]:
        if "contentBlockStart" in ev:
            i = ev["contentBlockStart"]["contentBlockIndex"]
            tu = ev["contentBlockStart"]["start"].get("toolUse")
            if tu:
                blocks[i] = {"toolUse": {"toolUseId": tu["toolUseId"], "name": tu["name"], "input": ""}}
        elif "contentBlockDelta" in ev:
            i = ev["contentBlockDelta"]["contentBlockIndex"]
            d = ev["contentBlockDelta"]["delta"]
            if "text" in d:
                blocks.setdefault(i, {"text": ""})["text"] += d["text"]
                print(d["text"], end="", flush=True)
            elif "toolUse" in d:
                # A partial JSON string: don't parse until the block stops
                blocks[i]["toolUse"]["input"] += d["toolUse"]["input"]
        elif "contentBlockStop" in ev:
            b = blocks.get(ev["contentBlockStop"]["contentBlockIndex"], {})
            if "toolUse" in b:
                b["toolUse"]["input"] = json.loads(b["toolUse"]["input"] or "{}")
        elif "messageStop" in ev:
            stop = ev["messageStop"]["stopReason"]
        elif "metadata" in ev:
            usage = ev["metadata"]["usage"]
    return {"role": "assistant", "content": [blocks[k] for k in sorted(blocks)]}, stop, usage

Some models accept tools only without streaming (Llama 3.1, 3.3 and 4, Mistral Large, Pixtral Large, Writer Palmyra): use Converse for them. Time to first token is measured only on streaming APIs, and the AWS CLI can't stream.

Tool use

With client-side tools, the model asks and your code runs the tool. A tool is a toolSpec with a name (letters, digits, underscores, hyphens, up to 64), a description and an inputSchema (JSON Schema with a top-level object). toolChoice is auto (default), any (must call a tool) or tool (must call a named tool).

A bounded tool loop that handles several tool calls per turn (Python, boto3) 
TOOLS = {"get_order_status": lambda a: {"orderId": a["orderId"], "status": "SHIPPED"}}
tool_config = {
    "tools": [{"toolSpec": {
        "name": "get_order_status",
        "description": "Look up the shipping status of an order by its ID.",
        "inputSchema": {"json": {
            "type": "object",
            "properties": {"orderId": {"type": "string"}},
            "required": ["orderId"],
            "additionalProperties": False,
        }},
        # Validate the model's tool input against the schema
        "strict": True,
    }}],
    "toolChoice": {"auto": {}},
}


def run(brt, model, messages, max_steps=8):
    for _ in range(max_steps):
        r = brt.converse(modelId=model, messages=messages, toolConfig=tool_config, inferenceConfig={"maxTokens": 1024})
        msg = r["output"]["message"]
        messages.append(msg)
        if r["stopReason"] != "tool_use":
            return msg
        results = []
        for block in msg["content"]:
            if "toolUse" not in block:
                continue
            tu = block["toolUse"]
            try:
                out = TOOLS[tu["name"]](tu["input"])
                results.append({"toolResult": {"toolUseId": tu["toolUseId"], "content": [{"json": out}], "status": "success"}})
            except Exception as e:
                # Report the failure to the model instead of crashing
                results.append({"toolResult": {"toolUseId": tu["toolUseId"], "content": [{"text": str(e)}], "status": "error"}})
        # All results in one user turn
        messages.append({"role": "user", "content": results})
    raise RuntimeError("tool loop did not finish")
  • Keep sending the same toolConfig while the history contains tool calls, and bound the loop. Returning all results of a turn in one user message is the Anthropic convention; AWS's docs don't spell it out.
  • Forced tool use (any or tool) depends on the exact model, never silently falls back to auto, isn't supported with thinking, and fails on Claude Opus 5.5, Fable 5.1 and Mythos 5.1. For structured data use structured outputs instead of the old forced-tool trick.
  • Tool definitions and results are billed as tokens, and Claude adds a hidden tool system prompt of a few hundred tokens.
  • Server-side tools run inside Bedrock, but only on the Responses API on bedrock-mantle: your own tools behind a Lambda MCP connector (January 2026) or an AgentCore Gateway with IAM auth (February 2026; require_approval must be never), and the built-in web search for OpenAI GPT-5.4 and later in three US Regions. Web search also needs bedrock-websearch:ExternalWebAccess (not in the full-access policy): without it page fetches fail silently.

Structured outputs

Structured outputs (generally available 4 February 2026; all Claude models on both endpoints since October 2026) force the response to match a JSON Schema, by compiling the schema into a grammar.

Classify a support ticket into a fixed JSON shape (Python, boto3; the schema is passed as a string) 
import json

schema = {
    "type": "object",
    "properties": {
        "category": {"type": "string", "enum": ["billing", "technical", "other"]},
        "urgent": {"type": "boolean"},
        "summary": {"type": "string"},
    },
    "required": ["category", "urgent", "summary"],
    # Required on every object in the schema
    "additionalProperties": False,
}
r = brt.converse(
    modelId="global.anthropic.claude-sonnet-5-5",
    messages=[{"role": "user", "content": [{"text": "Ticket: card charged twice, need a refund today."}]}],
    inferenceConfig={"maxTokens": 512},
    outputConfig={"textFormat": {
        "type": "json_schema",
        "structure": {"jsonSchema": {"name": "ticket", "schema": json.dumps(schema)}},
    }},
)
if r["stopReason"] == "end_turn":
    text = next(b["text"] for b in r["output"]["message"]["content"] if "text" in b)
    print(json.loads(text))
  • On Claude's InvokeModel body the field is output_config.format with the schema as an object (output_format is deprecated); open-weight models use response_format. "strict": true on a tool applies the same validation to tool inputs.
  • Supported: basic types, enums, const, anyOf, internal $ref, common string formats and simple patterns. Not supported: recursion, external refs, numeric and length bounds. At most 12 optional properties in total and 16 union-typed properties.
  • The first request with a new schema compiles it (up to about 90 seconds; cached for 24 hours), so set the client read timeout to at least 120 seconds. A low maxTokens gives truncated JSON. Works with batch and cross-Region inference, not with citations.

Prompt caching

A cache checkpoint stores the processed prefix of a prompt so later requests with the identical prefix read it at a discount and faster. The order is tools, then system, then messages: a change early in the prompt invalidates everything after it.

Cache tools and a long system prompt for an hour, and the conversation for five minutes (Python, boto3) 
r = brt.converse(
    modelId="global.anthropic.claude-sonnet-5-5",
    toolConfig={"tools": [*TOOL_SPECS, {"cachePoint": {"type": "default", "ttl": "1h"}}]},
    system=[{"text": LONG_STABLE_INSTRUCTIONS}, {"cachePoint": {"type": "default", "ttl": "1h"}}],
    messages=[{"role": "user", "content": [{"text": user_question}, {"cachePoint": {"type": "default"}}]}],
    inferenceConfig={"maxTokens": 1024},
)
u = r["usage"]
print(u["inputTokens"], u.get("cacheReadInputTokens", 0), u.get("cacheWriteInputTokens", 0))
  • Minimum prefix per checkpoint: 512 tokens on the Claude 5 family, 1,024 on Opus 4.8, Sonnet 5 and Sonnet 4.6, 4,096 on Opus 4.5 to 4.7 and Haiku 4.5, 1,000 on Nova. Below it the request works but nothing is cached. Up to 4 checkpoints.
  • Time to live: 5 minutes, reset on each hit; 1 hour ("ttl": "1h") on supported models (sending it to others can fail), with 1-hour entries placed before 5-minute ones. OpenAI GPT-5.6 and later use 30 minutes; Nova and older OpenAI models also cache implicitly.
  • Claude can also cache automatically with one top-level cache_control (in Converse, inside additionalModelRequestFields) on recent models.
  • Pricing: cache writes cost more than normal input and reads much less (for example on OpenAI and Kimi models, writes 1.25 times and reads 0.05 times the input price); the exact rates are on each model's pricing row. Cache reads don't count against tokens-per-minute; writes do.
  • The cache lives where the request was processed: cross-Region routing and parallel first requests can create extra writes. No caching in batch. Watch CacheReadInputTokenCount and CacheWriteInputTokenCount in CloudWatch.

Inference profiles

  • Geographic profiles (us., eu., apac., jp., au., in., ca., us-gov.) route within a geography; Global (global.) routes to any commercial Region, about 10% cheaper. The destination Regions depend on the Region you call from and can include Regions you haven't enabled: check them with GetInferenceProfile from each source Region instead of trusting the prefix.
  • CloudTrail logs the call in the source Region with additionalEventData.inferenceRegion; quotas for cross-Region and global use are separate and usually higher. Profiles can't use Provisioned Throughput.
List Australian profiles and see where one routes (AWS CLI) 
aws bedrock list-inference-profiles --region ap-southeast-2 --type-equals SYSTEM_DEFINED \
  --query "inferenceProfileSummaries[?starts_with(inferenceProfileId, 'au.')].inferenceProfileId" --output text
aws bedrock get-inference-profile --region ap-southeast-2 \
  --inference-profile-identifier au.anthropic.claude-sonnet-5-5 --query 'models[].modelArn'

Application inference profiles

A tagged profile for one application, for cost tracking (Python, boto3) 
bedrock = boto3.client("bedrock", region_name="us-east-1")
aip = bedrock.create_inference_profile(
    inferenceProfileName="support-bot-prod",
    modelSource={"copyFrom": "arn:aws:bedrock:us-east-1:111111111111:inference-profile/us.anthropic.claude-sonnet-5-5"},
    tags=[{"key": "CostCenter", "value": "CC-1001"}, {"key": "App", "value": "support-bot"}],
)
# Use as modelId in Converse or InvokeModel
profile_arn = aip["inferenceProfileArn"]

Copy from a foundation model (single Region) or a system profile (multi-Region). They're visible only through the API, rejected by the Responses and Chat Completions APIs, and their tags show in billing only after the payer account activates them as cost allocation tags (up to 24 hours, not retroactive). Up to 1,000 per Region.

IAM for a profile needs the profile ARN and the foundation model ARN in every destination Region (use bedrock:InferenceProfileArn on the model statement to allow it only through the profile). Global profiles also need the Region-less model ARN arn:aws:bedrock:::foundation-model/MODEL, and SCPs that restrict aws:RequestedRegion must allow unspecified. A Region-deny SCP doesn't stop Global routing; to block Global, deny when aws:RequestedRegion equals unspecified.

Service tiers

  • Standard (default), Priority (served first, up to about 25% faster output for most models, 75% more), Flex (lower priority under load, 50% less; for evaluations, labelling and background agents) and Reserved (guaranteed tokens per minute, at least 100,000 input and 10,000 output, for 1 or 3 months through your account team; overflow goes to Standard, and sizing must include cache-write tokens). OpenAI's newest models add Ultrafast at six times the Standard price.
  • Request it with serviceTier={"type": "priority"} on Converse, the boto3 serviceTier parameter (header X-Amzn-Bedrock-Service-Tier) on InvokeModel, or service_tier on the OpenAI-compatible APIs. The response says which tier served it; CloudWatch has ServiceTier and ResolvedServiceTier dimensions.
  • Priority, Standard and Flex share the model's on-demand quota. Restrict tiers with the IAM condition bedrock:ServiceTier (for example deny priority).

Tier support is per model, and the newest Claude models (the 5.5 family, Sonnet 5, Opus 5 and Opus 4.8) currently support only Standard; Claude 4.5 and 4.6 add Reserved; Priority and Flex are mainly on Nova and open-weight models. Check the model card's service tiers row before designing around one. How long Flex requests wait under load isn't documented.

Batch and async

Batch inference processes JSONL files from S3 at 50% of the on-demand price, usually within the timeout you set. Records use the model's InvokeModel body or, since February 2026, the Converse request format.

Summarize a folder of tickets in a batch job (Python, boto3; one JSONL record shown in the comment) 
# Each line: {"recordId": "T-0001", "modelInput": {"messages": [{"role": "user", "content": [{"text": "Summarize: ..."}]}], "inferenceConfig": {"maxTokens": 512}}}
job = bedrock.create_model_invocation_job(
    jobName="ticket-summaries-2026-11-09",
    roleArn="arn:aws:iam::111111111111:role/BedrockBatchRole",
    modelId="us.anthropic.claude-sonnet-4-6",
    modelInvocationType="Converse",
    inputDataConfig={"s3InputDataConfig": {"s3Uri": "s3://batch-in-111111111111/tickets/", "s3InputFormat": "JSONL"}},
    outputDataConfig={"s3OutputDataConfig": {"s3Uri": "s3://batch-out-111111111111/"}},
    # 24 to 168 hours
    timeoutDurationInHours=72,
)
status = bedrock.get_model_invocation_job(jobIdentifier=job["jobArn"])["status"]
  • At least 100 and at most 100,000 records per job and per file, 1 GB per file and 5 GB per job (model-specific). Output files hold each record's input with its output or error, plus a manifest with counts and token totals; output order isn't guaranteed, and EventBridge reports job state changes.
  • On-demand traffic is served first and completion isn't guaranteed. No prompt caching, no Provisioned Throughput, and Converse-format jobs can't use tools. The newest Claude models (the 5.5 family and Sonnet 5) aren't batch-enabled: check the supported list.
  • The OpenAI-compatible Batch API is on bedrock-runtime at /openai/v1/batches, with the role and model passed as headers.
  • StartAsyncInvoke runs long jobs that write to S3, such as Luma Ray2 video and segmented Nova Multimodal Embeddings or Marengo embeddings. Nova Reel and Nova Canvas reached end of life on 30 September 2026.

Routing, token counting and embeddings

  • Intelligent prompt routing: a router ARN as modelId picks between two models of one family by predicted quality (configured routers set a fallback model and a responseQualityDifference); the trace shows which model answered. Now only Nova Lite and Pro and Llama 3.x (Legacy), English-optimized, $1 per 1,000 requests.
  • Latency-optimized inference (performanceConfig={"latency": "optimized"}) is still in preview on a few older models and silently falls back to Standard when its quota runs out.
  • CountTokens (free) returns the input tokens a request would be billed for: brt.count_tokens(modelId=..., input={"converse": {"messages": [...], "system": [...]}}). For Claude models available only through profiles on bedrock-runtime (such as Opus and Haiku 5.5), use bedrock-mantle's /anthropic/v1/messages/count_tokens.
  • Embeddings through InvokeModel, limited by requests per minute: Titan Text Embeddings V2 ({"inputText": ..., "dimensions": 1024, "normalize": true}), Cohere Embed v4 (texts or images, input_type required), Nova Multimodal Embeddings (text, image, audio or video).
  • Speech: InvokeModelWithBidirectionalStream for Nova 2 Sonic, with interruptions and sessions up to 8 minutes.

Throttling, retries and fallback

  • 429 ThrottlingException is your quota: lower maxTokens, spread load or raise quotas. 503 ServiceUnavailable (and 529 overloaded on Anthropic-shaped APIs) is AWS capacity: retry, use Global profiles, fall back to other Regions or models. Never retry ValidationException; ModelNotReadyException is retried automatically; ResourceNotFoundException can mean an end-of-life model.
  • Each request reserves its input plus maxTokens when it starts, and output counts several times on newer models (15 times on Claude Opus 4.8; 10 times on Opus 5.5, Sonnet 5, Opus 5 and GPT-5.6; 5 times on older Claude). Omitting maxTokens reserves the model's maximum, so you're throttled far below your real usage. A per-account daily limit across models (700 million tokens by default) also applies.
  • botocore's read_timeout is 60 seconds by default: long non-streaming generations time out and get retried, paying twice. Raise it or stream. Behind NAT gateways and VPC endpoints, idle connections drop after 350 seconds: enable tcp_keepalive and lower the OS keepalive time.
Bounded retries, long timeouts, and fallback across Regions and models (Python, boto3; our pattern on AWS's guidance) 
import random
import time

import boto3
from botocore.config import Config
from botocore.exceptions import ClientError

cfg = Config(retries={"total_max_attempts": 4, "mode": "standard"}, connect_timeout=10, read_timeout=300, tcp_keepalive=True)
clients = {r: boto3.client("bedrock-runtime", region_name=r, config=cfg) for r in ("us-east-1", "us-west-2")}
CHAIN = [
    ("us-east-1", "global.anthropic.claude-sonnet-5-5"),
    ("us-west-2", "us.anthropic.claude-sonnet-5-5"),
    # A cheaper model as the last resort
    ("us-east-1", "global.anthropic.claude-haiku-5-5"),
]
RETRYABLE = {"ThrottlingException", "ServiceUnavailableException", "ModelNotReadyException",
             "InternalServerException", "ModelTimeoutException", "ResourceNotFoundException"}


def converse_with_fallback(**kw):
    for attempt, (region, model) in enumerate(CHAIN):
        try:
            return clients[region].converse(modelId=model, **kw)
        except ClientError as e:
            if e.response["Error"]["Code"] not in RETRYABLE:
                raise
            time.sleep(random.uniform(0, min(8, 2 ** attempt)))
    raise RuntimeError("all fallbacks exhausted")

Watch InvocationThrottles, EstimatedTPMQuotaUsage, InvocationLatency and TimeToFirstToken in AWS/Bedrock. Ramp traffic gradually, one dimension at a time, with a token-aware client-side limiter.

Cost attribution

  • IAM principal attribution (April 2026; bedrock-mantle since August 2026): cost by caller identity, plus principal or session tags, in Cost Explorer and a new CUR 2.0 export with caller identity data, after the payer account activates the tags. Assume a role per user in gateways to bill by user.
  • Application inference profiles: tags per application, model-specific (Converse and InvokeModel only).
  • Projects (bedrock-mantle, February 2026): one project per application across models, with its own IAM; AWS now recommends them over many profiles.
  • requestMetadata (up to 16 pairs; a body field on Converse, a header on InvokeModel since May 2026) appears only in model invocation logs, never on the bill, and isn't available on bedrock-mantle. Keep personal data out of it.
  • Billing is aggregated per usage type per day, with separate input, output, cache read and cache write usage types (forgetting the cache ones is the commonest reconciliation gap); per-request detail exists only in invocation logs.
