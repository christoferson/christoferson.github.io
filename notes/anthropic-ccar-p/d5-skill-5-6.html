5.6: Bias Source Identification and Mitigation

When outputs differ between groups, finding out why before fixing anything: is the model reacting to how the input is framed, learning from skewed examples or retrieved cases, or being judged by an evaluation that has the bias built in? Each source has a different fix.

Overview

Skill 5.6

Bias Source Identification and Mitigation: "Evaluating the evidence for bias when outputs or a dataset show disparate results across groups, and selecting the mitigation appropriate to its source, distinguishing data bias from prompt-framing and evaluation-design bias."

Exam items show a disparity and some evidence, and ask where it comes from and which mitigation fits. Bias in an LLM judge specifically is skill 4.3; deriving evaluations from the process is skill 4.2.

When results differ across groups, find where the bias comes from before fixing it

Skill 5.6What this skill asks, and a disparity to investigate.

Questions on this skill describe outputs or a dataset that treat groups differently, and ask what the evidence shows and which mitigation fits. The guide separates three sources: how the prompt frames the decision, the data the model learns from, and how the evaluation is designed. Each has its own test and its own fix, and a fix aimed at the wrong source leaves the bias in place.

Take a city’s service-request assistant that assigns each repair a priority from 1 to 4. Reports from the Eastgate district get lower priority than similar reports from other districts.

Borrow Anthropic’s method: change only the group, and measure the change

Skill 5.6From Anthropic’s research on discrimination in model decisions.

  • The method. A model generated decision prompts for 70 scenarios across society, and the demographic details in each prompt were varied systematically while everything else stayed the same.
  • The finding. Without interventions, an earlier Claude model showed both positive and negative discrimination in some settings.
  • The mitigation. Careful prompt engineering significantly reduced both.
  • The caveat. Anthropic states that it doesn’t endorse or permit using language models for automated decisions in the high-risk cases it studied; its Usage Policy requires review by a qualified person for high-risk recommendations.

The lesson for an architect: vary only the group and measure what changes. That isolates the model’s response to the input from everything else.

Prompt framing: the group itself moves the decision

Skill 5.6The test is a swap on otherwise identical cases.

How it shows. The decision changes when only the group, or something that stands in for it such as a district or a name, changes.

The test. Swap the group on otherwise identical cases. In the example, changing “Eastgate” to “Northside” on the same reports raises the priority by a point on average, so the district name itself is moving the decision.

The fix. Remove the group and anything that stands in for it from the decision prompt where it isn’t relevant, state the criteria explicitly (the hazard, the number of people affected, how long it has been open), then run the swap test again. Anthropic’s research shows that changes to the prompt can reduce this kind of bias.

Data: the examples teach the pattern

Skill 5.6Few-shot examples, retrieved past cases or training data skewed by group.

How it shows. The model learns from what it’s given, and what it’s given treats the group differently, or barely includes it.

The test. Audit the examples and retrieved cases by group. In the example, Eastgate makes up 10% of the few-shot examples and none of them is high priority, against 90% elsewhere: the examples teach the pattern.

The fix. Rebalance or replace the examples and retrieved cases, and relabel them against the stated criteria rather than past outcomes.

Evaluation design: the measurement rewards or hides the gap

Skill 5.6Labels copied from past decisions, no per-group results, or a biased grader.

How it shows. The evaluation passes a system that reproduces the gap. Labels copied from past decisions reward repeating history; a single average hides a group’s results; a grader can carry its own bias.

The test. Check where the labels came from and whether results are reported per group. In the example, the test set’s labels are past decisions and there are no per-district results, so the release gate would pass a system that keeps the gap.

The fix. Have reviewers label a test set against the criteria, and add results per group and a measure of the gap to the release gate.

Run all three tests before choosing a fix

Skill 5.6More than one source can be true at once.

The code below runs one test per source on the service-request example, and finds all three: the district name moves the decision, the examples are skewed, and the evaluation can’t see the gap.

"""Find the source of a disparity before choosing the fix.

System: a city's service-request assistant assigns repair priority (1-4) to resident reports. Requests
from the Eastgate district get lower priority than similar ones elsewhere. Three diagnostics, one per
source the exam guide names:
  prompt framing   counterfactual swap: change only the district, keep every other detail
  data             what the model learns from: few-shot examples and retrieved past cases
  evaluation design what the test set's labels and slices were built from"""
from collections import Counter
from statistics import mean


def framing_effect(prioritise, cases: list[dict], swap_to: str) -> float:
    """Mean priority change when only the district is swapped. A non-zero effect means the input wording matters."""
    return round(mean(prioritise(dict(c, district=swap_to)) - prioritise(c) for c in cases), 2)


def data_skew(examples: list[dict], group: str) -> dict:
    """How the group appears in the examples and retrieved cases the prompt carries."""
    share = sum(e["district"] == group for e in examples) / len(examples)
    hi = [e for e in examples if e["district"] == group]
    return {"share_of_examples": round(share, 2),
            "high_priority_rate_in_group": round(mean(e["priority"] >= 3 for e in hi), 2) if hi else None,
            "high_priority_rate_overall": round(mean(e["priority"] >= 3 for e in examples), 2)}


def eval_design(test_set: list[dict]) -> list[str]:
    issues = []
    if Counter(t["label_source"] for t in test_set).most_common(1)[0][0] == "historical decisions":
        issues.append("labels copy past decisions, so the eval rewards repeating any past disparity")
    if not any(t.get("slice") for t in test_set):
        issues.append("no per-district slices, so an average hides the gap")
    return issues


MITIGATIONS = {
    "prompt framing": "remove the attribute or its proxies from the decision prompt where it isn't relevant; "
                      "state the criteria explicitly (hazard, people affected, time open); re-run the swap test",
    "data": "rebalance or replace the examples and retrieved cases; relabel examples by the stated criteria, not by past outcomes",
    "evaluation design": "label a test set against the criteria by reviewers, add per-group slices and a gap metric to the gate",
}

Keep people in the decision where the outcome affects someone’s rights or access to services, and run the tests again after each fix.

“Tell the model to be fair” treats every disparity as a framing problem. If the examples teach the pattern, or the evaluation rewards it, a fairness instruction won’t remove it, and the gate won’t notice it’s still there.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
A loan pre-screening assistant scores applicants from one postcode lower. Swapping only the postcode on otherwise identical applications changes the score. What does this show, and what is the first fix?
  1. A. The examples are skewed; rebalance them
  2. B. Prompt framing: the postcode stands in for a group; remove it where irrelevant and state the criteria
  3. C. The evaluation is biased; relabel it
  4. D. Nothing; postcodes are legitimate
Answer
B
Why
A change in output when only the attribute changes is the signature of framing. Remove the attribute and its stand-ins where they aren’t relevant, state the criteria, and run the swap test again.
Question 2
Scenario
A hiring assistant’s few-shot examples include only senior candidates from two universities, and its ratings favour those universities. Which source is this?
  1. A. Data: the examples teach the pattern
  2. B. Evaluation design
  3. C. A model bug
  4. D. Prompt length
Answer
A
Why
Skewed examples teach the model the pattern. The fix is to rebalance or replace them and label them against the stated criteria.
Question 3
Scenario
An evaluation for a benefits assistant uses past caseworker decisions as its labels and reports one overall accuracy. Why might it miss a disparity?
  1. A. It rewards repeating past decisions and hides group results in an average
  2. B. It has too few cases
  3. C. It uses the wrong model
  4. D. It measures latency
Answer
A
Why
Labels copied from history reward the same gap, and a single average hides how each group fares. Relabel against the criteria and gate on per-group results.
Question 4
Scenario
A team responds to a disparity by adding “treat everyone fairly” to the system prompt. Tests show the examples are skewed. What happens?
  1. A. The disparity disappears
  2. B. The disparity largely remains, because the examples still teach the pattern
  3. C. The disparity reverses
  4. D. The evaluation now detects it
Answer
B
Why
A fairness instruction targets framing only. If the data teaches the pattern, it stays, and an evaluation that can’t see group results won’t notice. Find the source first.

Key takeaways

  • Find the source before mitigating: prompt framing, data, or evaluation design (or several at once).
  • Prompt framing: a swap that changes only the group, or something standing in for it, changes the output; remove the attribute and state the criteria.
  • Data: skewed examples, retrieved cases or training data teach the pattern; audit, rebalance and relabel them against the criteria.
  • Evaluation design: labels copied from past decisions, no per-group results or a biased grader hide or reward the gap; relabel against criteria and gate on per-group results.
  • Test again after each fix, and keep qualified human review for decisions about people in high-risk areas.
