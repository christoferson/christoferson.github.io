5.6: Bias Source Identification and Mitigation

When outputs differ between groups, finding out why before fixing anything: is the model reacting to how the input is framed, learning from skewed examples or retrieved cases, or being judged by an evaluation that has the bias built in? Each source has a different fix.

Overview

Skill 5.6

Bias Source Identification and Mitigation: "Evaluating the evidence for bias when outputs or a dataset show disparate results across groups, and selecting the mitigation appropriate to its source, distinguishing data bias from prompt-framing and evaluation-design bias."

Exam items show a disparity and some evidence, and ask where it comes from and which mitigation fits. Bias in an LLM judge specifically is skill 4.3; deriving evaluations from the process is skill 4.2.

Sources: Anthropic's research post on evaluating and mitigating discrimination in language model decisions (December 2023), checked on 20 November 2026 and paraphrased. The three sources come from the exam guide; the diagnostics and mitigations below are my own, and the code is tested.

Running example. A city's service-request assistant assigns repair priority from 1 to 4. Reports from the Eastgate district get lower priority than similar reports from other districts.

What Anthropic's research did

Skill 5.6A method worth borrowing.

  • Method: a model generated decision prompts for 70 scenarios across society, and the demographic information in each prompt was varied systematically while everything else stayed the same.
  • Finding: without interventions, an earlier Claude model showed both positive and negative discrimination in some settings.
  • Mitigation: careful prompt engineering significantly reduced both.
  • Caveat: Anthropic states it doesn't endorse or permit using language models to make automated decisions in the high-risk use cases it studied; its Usage Policy requires qualified human review for high-risk recommendations.
  • The takeaway for an architect: vary only the group attribute and measure the change. That isolates the model's response to the input from everything else.

Three sources, three tests

Skill 5.6How each source shows itself.

  • Prompt framing: the decision changes when only the group attribute (or a proxy for it, such as a district or a name) changes. Test: a counterfactual swap on otherwise identical cases.
  • Data: the model learns the pattern from what it's given: few-shot examples, retrieved past cases, or fine-tuning data where the group is rare or mostly labelled one way. Test: audit the examples and retrieved cases by group.
  • Evaluation design: the disparity is in how success is measured: labels copied from past decisions (so the evaluation rewards repeating history), no per-group slices (so an average hides the gap), or a grader with its own bias. Test: check where labels came from and whether results are broken out by group.
  • More than one can be true: run all three before deciding.

Diagnosing a disparity

Skill 5.6One test per source, on the running example.

bias_source.py (bias_source.py)Optional 
"""Find the source of a disparity before choosing the fix.

System: a city's service-request assistant assigns repair priority (1-4) to resident reports. Requests
from the Eastgate district get lower priority than similar ones elsewhere. Three diagnostics, one per
source the exam guide names:
  prompt framing   counterfactual swap: change only the district, keep every other detail
  data             what the model learns from: few-shot examples and retrieved past cases
  evaluation design what the test set's labels and slices were built from"""
from collections import Counter
from statistics import mean


def framing_effect(prioritise, cases: list[dict], swap_to: str) -> float:
    """Mean priority change when only the district is swapped. A non-zero effect means the input wording matters."""
    return round(mean(prioritise(dict(c, district=swap_to)) - prioritise(c) for c in cases), 2)


def data_skew(examples: list[dict], group: str) -> dict:
    """How the group appears in the examples and retrieved cases the prompt carries."""
    share = sum(e["district"] == group for e in examples) / len(examples)
    hi = [e for e in examples if e["district"] == group]
    return {"share_of_examples": round(share, 2),
            "high_priority_rate_in_group": round(mean(e["priority"] >= 3 for e in hi), 2) if hi else None,
            "high_priority_rate_overall": round(mean(e["priority"] >= 3 for e in examples), 2)}


def eval_design(test_set: list[dict]) -> list[str]:
    issues = []
    if Counter(t["label_source"] for t in test_set).most_common(1)[0][0] == "historical decisions":
        issues.append("labels copy past decisions, so the eval rewards repeating any past disparity")
    if not any(t.get("slice") for t in test_set):
        issues.append("no per-district slices, so an average hides the gap")
    return issues


MITIGATIONS = {
    "prompt framing": "remove the attribute or its proxies from the decision prompt where it isn't relevant; "
                      "state the criteria explicitly (hazard, people affected, time open); re-run the swap test",
    "data": "rebalance or replace the examples and retrieved cases; relabel examples by the stated criteria, not by past outcomes",
    "evaluation design": "label a test set against the criteria by reviewers, add per-group slices and a gap metric to the gate",
}
  • Framing: swapping "Eastgate" for "Northside" on otherwise identical reports raises priority by a point on average in the planted case, so the district name itself is moving the decision.
  • Data: Eastgate is 10% of the few-shot examples and none of them is high priority, against 90% elsewhere; the examples teach the pattern.
  • Evaluation: the test set's labels are past decisions and there are no per-district slices, so the gate would pass a system that reproduces the gap.

Fixing the right thing

Skill 5.6Mitigation by source.

  • Prompt framing: remove the attribute and its proxies from the decision prompt where they aren't relevant, state the criteria explicitly (hazard, people affected, time open), then re-run the swap test. Anthropic's research shows prompt changes can significantly reduce discrimination; measure, don't assume.
  • Data: rebalance or replace the examples and retrieved cases, and relabel them by the stated criteria rather than by past outcomes.
  • Evaluation design: label a test set against the criteria with reviewers, add per-group slices and a gap metric to the release gate.
  • Keep people in the decision where the outcome affects someone's rights or access to services.

"Tell the model to be fair" treats every disparity as a framing problem. If the examples teach the pattern, or the evaluation rewards it, a fairness instruction won't remove it, and the gate won't notice it's still there.

Key takeaways

  • Find the source before mitigating: prompt framing, data, or evaluation design (or several).
  • Prompt framing: a counterfactual swap that changes only the group attribute or a proxy changes the output; the method Anthropic's discrimination research used.
  • Data: skewed few-shot examples, retrieved cases or training data teach the pattern; audit and rebalance them.
  • Evaluation design: labels copied from past decisions, missing per-group slices or a biased grader hide or reward the gap; relabel against criteria and gate on per-group results.
  • Re-test after each fix, and keep qualified human review for decisions about people in high-risk areas.
