4.6: Cost and Latency Optimization

Using the telemetry to find the few places where most of the money and waiting goes, then applying the cheapest fix that works there, in the order Anthropic recommends, and stopping at any change that would drop quality below the agreed floor.

Overview

Skill 4.6

Cost and Latency Optimization: "Analyzing cost and latency telemetry, including cache hit rates, to determine where spend or latency is concentrated, and specifying the optimization that reduces it without violating the stated quality floor."

Exam items show telemetry (cost by route, cache hit rates, latency percentiles) and a quality floor, and ask which change to make. Pricing a single context is skill 2.4, placing cache breakpoints skill 2.5, and trading accuracy against latency skill 3.3; this skill starts from production data.

Sources: Anthropic's "Optimizing for cost and intelligence" guidance, the rate limits page and Claude Code best practices, checked on 19 and 20 November 2026 and paraphrased. The telemetry and code are my own; the code is tested.

Running example. An insurance broker's platform runs four Claude routes and spent about $39,400 last month. Leadership wants it cut by a third, and every route has a quality floor of 0.90 on its evaluation set.

Where to look in the telemetry

Skill 4.6The views that locate the spend.

  • Cost by route, feature or agent: usually a few routes carry most of the spend; start there, not with an across-the-board change.
  • Cache read share: the share of input tokens read from cache. Anthropic reports a median of 84% for agent loops, and suggests that below about 80% something is breaking the cached prefix. The Console's Usage page charts this cache rate per model.
  • Tokens per request, split by part: tool definitions, retrieved text, history and output, to see what's growing.
  • Latency percentiles per route, and whether a person is waiting at all.
  • The tail: Anthropic recommends pricing the tail of the workload; a few very long sessions can dominate a route's cost.
  • In Claude Code: /usage breaks usage down by skill, subagent, plugin and MCP server, and flags long context or frequent cache misses.

Anthropic's order of levers

Skill 4.6Cheapest and safest first.

  • 1. Caching, which Anthropic calls usually the largest lever: no change to answers, lower cost and faster time to first token.
  • 2. Token hygiene: remove unused tool definitions, trim tool results and duplicate text.
  • 3. Batching for unattended work: half price on every token, which Anthropic calls the second-largest free lever after caching for unattended agent work.
  • 4. A prompt audit: instructions that cause long outputs or unnecessary steps.
  • Then model and effort: upgrade if you're a model or two behind, otherwise sweep effort; tune one model well before adding a second.

Hot spots and their levers

Skill 4.6Telemetry by route, then the first lever that applies.

optimize.py (optimize.py) 
"""Find where spend and latency concentrate, then pick the cheapest safe optimization per hot spot.

Telemetry: one month of request logs from an insurance broker's agent platform, aggregated by route.
Order of levers follows Anthropic's "Optimizing for cost and intelligence": caching first, then token
hygiene, then batching, then a prompt audit; model or effort changes only after those, and only if the
evaluation stays above the quality floor."""

ROUTES = {  # route: monthly cost $, share of input read from cache, p95 s, interactive?, quality on eval
    "policy-compare agent": {"cost": 21_400, "cache_read": 0.31, "p95": 18.0, "interactive": True,  "quality": 0.93},
    "nightly renewal letters": {"cost": 9_800, "cache_read": 0.86, "p95": 40.0, "interactive": False, "quality": 0.95},
    "chat triage":          {"cost": 1_900, "cache_read": 0.88, "p95": 2.1,  "interactive": True,  "quality": 0.97},
    "document intake":      {"cost": 6_300, "cache_read": 0.82, "p95": 6.5,  "interactive": True,  "quality": 0.91,
                             "unused_tool_tokens": 9_000},
}
QUALITY_FLOOR = 0.90


def hot_spots(routes, share=0.8):
    """The few routes that make up most of the spend (Pareto)."""
    total = sum(r["cost"] for r in routes.values())
    acc, out = 0, []
    for name, r in sorted(routes.items(), key=lambda kv: -kv[1]["cost"]):
        out.append((name, round(r["cost"] / total, 2)))
        acc += r["cost"]
        if acc / total >= share:
            break
    return out


def lever(r: dict, eval_delta: dict) -> str:
    if r["cache_read"] < 0.80:
        return "caching: find what breaks the prefix (timestamps, reordered tools, per-user text up front)"
    if r.get("unused_tool_tokens", 0) > 5_000:
        return "token hygiene: drop or defer unused tool definitions; trim tool results"
    if not r["interactive"]:
        return "batching: Message Batches at 50% off; nobody is waiting"
    downgrade = eval_delta.get("smaller model or lower effort")
    if downgrade is not None and r["quality"] + downgrade >= QUALITY_FLOOR:
        return "model/effort: cheaper setting passes the quality floor on the eval"
    return "keep: no safe lever left; revisit the prompt audit"


if __name__ == "__main__":
    print("hot spots:", hot_spots(ROUTES))
    deltas = {"chat triage": {"smaller model or lower effort": -0.02},
              "document intake": {"smaller model or lower effort": -0.04}}
    for name, r in ROUTES.items():
        print(f"{name:24} -> {lever(r, deltas.get(name, {}))}")
run_output.txt (Output)

policy-compare agent     -> caching: find what breaks the prefix (timestamps, reordered tools, per-user text up front)
nightly renewal letters  -> batching: Message Batches at 50% off; nobody is waiting
chat triage              -> model/effort: cheaper setting passes the quality floor on the eval
document intake          -> token hygiene: drop or defer unused tool definitions; trim tool results
  • Policy-compare agent (54% of spend, 31% cache read): far below the 80% mark, so something breaks the prefix. Fixing caching cuts cost and the 18-second p95 together, without touching answers.
  • Nightly renewal letters (25%): already well cached, but nobody waits for them: Batches halve the cost.
  • Document intake (16%): cache rate is fine, but 9,000 tokens of unused tool definitions ride on every call: defer or remove them.
  • Chat triage (5%): small, but a cheaper model setting keeps it above the floor on the evaluation (0.95 against 0.90), so it qualifies; it's the last place to look, not the first.

"Switch every route to a smaller model" is the tempting answer to a cost target. It risks the quality floor everywhere and leaves the real problem, a broken cache on the route that is over half the spend, in place.

Holding the quality floor

Skill 4.6Which levers can and can't move quality.

  • Caching and batching don't change answers: safe by construction, though check batch turnaround fits the schedule.
  • Token hygiene can: removing a tool or trimming a result might remove something a hard case needed; rerun the evaluation.
  • Model and effort changes do: accept them only when the evaluation, ideally the paired design from skill 4.4, shows the new setting above the floor.
  • Watch afterwards: cost per route, cache rate and quality metrics in monitoring, so a later prompt change doesn't quietly undo the saving.

Key takeaways

  • Locate the spend: cost by route, cache read share, tokens by part, latency percentiles and the tail; a few routes usually dominate.
  • A cache read share well below about 80% (Anthropic's agent-loop median is 84%) means something is breaking the prefix: fix that first.
  • Apply levers in Anthropic's order: caching, token hygiene, batching for unattended work, a prompt audit, then model or effort.
  • Caching and batching don't change answers; token hygiene and model or effort changes must be re-evaluated against the quality floor.
  • Monitor cost, cache rate and quality afterwards so savings stick.
