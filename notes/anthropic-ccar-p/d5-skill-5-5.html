5.5: Architectural Controls for Compliance Obligations

Taking an obligation (no vendor storage, protected health information, data in one country, clients kept apart) and choosing the controls that actually satisfy it and produce evidence an auditor can check, while avoiding design choices the obligation quietly rules out.

Overview

Skill 5.5

Architectural Controls for Compliance Obligations: "Evaluating candidate architectural controls (data residency and deployment surface, retention and zero-data-retention configuration, PII detection and redaction, audit logging, tenant isolation) against a stated compliance obligation, and selecting the control set that evidences the obligation."

Exam items state an obligation and offer control sets, some of which address a different obligation. Choosing a surface and runtime under residency constraints is skill 1.6; key handling and authorisation are skill 3.2.

Sources: the Claude documentation on API and data retention and on data residency, checked on 20 November 2026 and paraphrased. The obligations and code are my own; the code is tested. Contract terms are the final word on what an arrangement covers.

What each control does, and doesn't

Skill 5.5Precise scope, from Anthropic's documentation.

  • Zero data retention (ZDR): Anthropic doesn't store prompts or responses at rest after the response is returned. It's an arrangement per organisation, through the sales team; it doesn't cover the Console, Managed Agents (except self-hosted), features marked ineligible such as code execution, or the Fable 5.x and Mythos models, which require 30-day retention. ZDR organisations can't call the API from a browser.
  • HIPAA readiness: a signed BAA and a HIPAA-enabled organisation on the Claude API (or Microsoft Foundry with its HIPAA configuration). It isn't available on Claude Platform on AWS, and doesn't cover Claude Code, Console usage or most beta features. The API rejects ineligible features for HIPAA organisations with a 400. Don't put PHI in JSON schemas: compiled schemas are cached without the same protections.
  • Default retention: Anthropic states conversation content isn't retained by default, except for the models that require 30-day retention, and retained data isn't used for training without permission.
  • Data residency: inference_geo controls where inference runs (US or global); workspace settings can restrict allowed geos; workspace geo controls where data rests (US only today). On Bedrock and Google-managed Vertex, the cloud provider is the data processor and sets the controls.
  • PII redaction, audit logging, tenant isolation: your controls, in your architecture: redact before logs and analytics, record who accessed what, and separate clients by workspace, key, index and tool scope.

Obligation to control to evidence

Skill 5.5Four obligations, each with its control set and what proves it.

compliance_controls.py (compliance_controls.py) 
"""Map each compliance obligation to the architectural controls that evidence it, and catch conflicts.

Facts encoded (Claude API data retention and data residency pages, Nov 2026):
- ZDR: per organization, by arrangement; not for Console, Managed Agents (except self-hosted), Fable 5.x /
  Mythos models (30-day retention required), code execution and other features marked ineligible.
- HIPAA readiness: BAA + HIPAA-enabled organization on the Claude API; not on Claude Platform on AWS,
  Bedrock or Claude Code; ineligible features return 400; no PHI in JSON schemas.
- Residency: inference_geo "us" per request, workspace allowed_inference_geos to enforce it.
- Flagged content may be retained up to 2 years under any arrangement."""

CONTROLS = {
    "no vendor storage of customer content": [
        ("ZDR arrangement for the organization", "contract + account-team confirmation"),
        ("only ZDR-eligible features and models", "request builder allowlist; CI check"),
        ("calls from our back end only", "ZDR orgs can't call the API from browsers"),
    ],
    "PHI under HIPAA": [
        ("signed BAA and HIPAA-enabled organization on the Claude API", "Console HIPAA card, BAA version"),
        ("eligible features only", "the API returns 400 for ineligible ones; keep the error as evidence"),
        ("no PHI in JSON schemas, file names or metadata", "schema review in code review"),
        ("PHI redaction before logs and analytics", "logging pipeline config + sampled audit"),
    ],
    "inference in the US": [
        ("inference_geo 'us' on every request", "usage.inference_geo logged per response"),
        ("workspace allowed_inference_geos = ['us']", "workspace settings export"),
    ],
    "per-client separation and access audit": [
        ("one workspace and scoped key per client", "key inventory by workspace"),
        ("per-client retrieval index and tool scopes", "integration tests: client A can't read client B"),
        ("audit log of who accessed what, with client ID", "log retention policy + sample queries"),
    ],
}


def plan(obligations: list[str], design: dict) -> dict:
    controls = [c for o in obligations for c in CONTROLS[o]]
    conflicts = []
    if "no vendor storage of customer content" in obligations:
        if design["model"].startswith(("claude-fable", "claude-mythos")):
            conflicts.append(f"{design['model']} requires 30-day retention: not available under ZDR without express authorization")
        if design["runtime"] == "managed agents (cloud)":
            conflicts.append("Managed Agents keeps session transcripts until deleted: not covered by ZDR")
        if "code_execution" in design["features"]:
            conflicts.append("code execution is not ZDR-eligible")
    if "PHI under HIPAA" in obligations and design["surface"] in ("claude platform on aws", "bedrock"):
        conflicts.append(f"HIPAA readiness isn't available through Anthropic on {design['surface']}")
    return {"controls": controls, "conflicts": conflicts,
            "residual": "flagged content may still be retained up to 2 years (disclose in the DPIA)"}
  • Evidence matters as much as the control: "we use ZDR" is a claim; the contract, an allowlist that blocks ineligible features, and a CI check are evidence.
  • Some evidence comes from the platform: each response's usage.inference_geo shows where inference ran; a HIPAA organisation's 400 errors show ineligible features were blocked.
  • Isolation is tested, not asserted: an integration test that client A can't read client B's documents is the evidence.

Conflicts to catch early

Skill 5.5Design choices an obligation rules out.

  • ZDR with Fable 5.2: the model requires 30-day retention; not available under ZDR without express authorisation.
  • ZDR with hosted Managed Agents: session transcripts persist until deleted.
  • ZDR with code execution: not an eligible feature.
  • HIPAA on Claude Platform on AWS: HIPAA readiness isn't available there.
  • The test feeds a design with all four and checks each is flagged; a compliant design returns no conflicts.

"Use ZDR to keep data in the US" or "use US inference to stop the vendor storing data" each picks a real control for the wrong obligation. Retention and residency are separate settings with separate evidence.

Residual risk to disclose

Skill 5.5What no configuration removes.

  • Flagged content: even under ZDR or HIPAA arrangements, content flagged by Anthropic's trust and safety systems may be retained for up to 2 years, and data may be kept where the law requires.
  • Third-party integrations: MCP servers, search providers and other tools have their own data handling, outside these arrangements.
  • Your own copies: logs, caches, evaluation sets and traces hold the same data; redact or minimise them under the same obligation.
  • Record these in the impact assessment rather than claiming the obligation is met absolutely.

Key takeaways

  • Match each obligation to controls that address it: ZDR for vendor storage, HIPAA readiness (BAA plus HIPAA-enabled organisation) for PHI, inference_geo and workspace geo restrictions for residency, your own redaction, audit logging and per-client isolation for the rest.
  • Pair every control with evidence: contracts and settings, allowlists and CI checks, logged inference_geo, isolation tests.
  • Catch conflicts: Fable 5.x, hosted Managed Agents and code execution aren't covered by ZDR; HIPAA readiness isn't available on Claude Platform on AWS; no PHI in JSON schemas.
  • Retention and residency are different obligations with different controls.
  • Disclose the residuals: flagged content (up to 2 years), legal holds, third-party tools and your own logs.
