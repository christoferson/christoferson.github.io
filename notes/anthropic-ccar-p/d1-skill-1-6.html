1.6: Deployment Surface and Agent Runtime Selection

Two decisions that constrain everything else: where Claude is called from (Anthropic's API or a cloud provider), and who runs the agent loop (your service, your containers, or Anthropic). Hard constraints decide first; the page then names what each choice costs in features, latency, hosting, state, sandboxing and custody.

Overview

Skill 1.6

Deployment Surface and Agent Runtime Selection: "Selecting a deployment surface (Anthropic API, Amazon Bedrock, Google Vertex AI, Microsoft Foundry) and an agent runtime (Messages API loop, self-hosted Agent SDK or headless Claude Code, Claude Managed Agents) under data residency, compliance, model-availability, and operational-ownership constraints, and justifying the trade-offs the selection imposes on latency, feature availability, hosting, session state, sandboxing, and data custody."

Exam items state constraints and preferences that pull in different directions and ask which combination satisfies the hard ones, and what has to be given up. The guide's own sample question for this skill isn't reproduced here. The runtimes themselves, and how to build on each, are in the developer notes (CCDV-F 1.1).

Sources: the Claude documentation on data residency, Claude on Amazon Bedrock, Claude Managed Agents and Agent SDK hosting, checked on 20 November 2026 and paraphrased. The scenarios and code are my own; the selector is tested. Where a detail varies by model or platform, the page says to check it.

Surfaces

Skill 1.6Where requests go.

  • Claude API (first party): every feature first, including betas, server tools, the Files API, Skills, Batches and Managed Agents. Residency via inference_geo.
  • Claude Platform on AWS: Anthropic-operated, billed through AWS Marketplace, with features typically on the same day as the Claude API; supports inference_geo and Managed Agents.
  • Amazon Bedrock: AWS-operated, IAM authentication, region chosen by inference profile. The bedrock-runtime endpoint doesn't support the Files API, server tools (code execution, web search and fetch), Agent Skills, the MCP connector, Message Batches or Managed Agents; a newer Bedrock endpoint offers the native Messages API shape with fuller parity. Model lifecycle dates are set by AWS.
  • Google Cloud: an Anthropic-managed option (supports inference_geo and Managed Agents) and a Google-managed one (region set by endpoint).
  • Microsoft Foundry: Azure-hosted deployments can use the US Data Zone Standard type to keep inference in the US.

Residency, precisely

Skill 1.6Two settings, often confused.

  • Inference geo: where the model runs, per request or as a workspace default. On the Claude API the values are global (default) and us; US-only costs 1.1 times on all token prices for Claude 4.6 and later. Workspaces can restrict which geos are allowed.
  • Workspace geo: where data is stored at rest and where endpoint processing such as code execution happens. Set when the workspace is created and can't be changed; only us is available today.
  • Other regions: Bedrock's regional inference profiles cover the US, EU, Japan and Asia-Pacific for listed models, at a 10% premium over global. Check that the model you need has a profile in your region.
  • Residency isn't retention: zero data retention controls how long data is kept, not where it's processed. Data residency itself is eligible for ZDR and HIPAA readiness.

Runtimes

Skill 1.6Who runs the loop, and what that means.

  • Messages API loop in your service: you write the loop, tools and state; works on every surface; maximum control and the most code.
  • Self-hosted Agent SDK or headless Claude Code: a ready-made loop with built-in tools, run in your containers. Each session is a CLI subprocess with transcripts on local disk; you own session storage, sandboxing (for example gVisor or Firecracker), scaling and turn limits.
  • Claude Managed Agents (beta): Anthropic runs the harness and holds session state; long-running and asynchronous work with nothing to host. A cloud environment gives a fresh container per session; a self-hosted sandbox runs bash and file tools on your workers, but conversation history and tool results still reach Anthropic. Not ZDR or HIPAA eligible, except fully self-hosted Managed Agents arranged through Anthropic's account team.

Constraints first

Skill 1.6The order of the decision.

  • 1. Hard constraints remove options: a region the Claude API can't serve, a contract that keeps data with one cloud provider, HIPAA or ZDR eligibility, a model that's only on certain surfaces.
  • 2. Operational ownership picks the runtime: must you run the loop yourself (and can you staff it), or should Anthropic? Must tools run inside your network?
  • 3. Preferences come last: newest features, lowest latency, least code. A preference that conflicts with a hard constraint becomes a stated trade-off.

"Use Managed Agents to avoid hosting" fails wherever Managed Agents isn't offered, or where HIPAA or ZDR eligibility is required. "Use the newest model everywhere" fails when that model isn't available on the surface or in the region a hard constraint has already fixed.

Four constraint sets

Skill 1.6The rules as code, run on four organisations.

select_platform.py (select_platform.py) 
"""Choose a deployment surface and an agent runtime from hard constraints first, preferences second.

Facts encoded (Claude docs, November 2026):
- Claude API inference_geo offers "us" (1.1x price) or "global"; workspace geo is "us" only.
- Bedrock sets the region by inference profile; regional (us, eu, jp, apac) costs 10% more than global.
  Its bedrock-runtime endpoint lacks the Files API, server tools, Agent Skills, the MCP connector,
  Message Batches and Managed Agents.
- Claude Platform on AWS is Anthropic-operated, billed through AWS Marketplace, typically same-day features.
- Managed Agents: beta; not ZDR or HIPAA eligible except self-hosted Managed Agents."""
from dataclasses import dataclass, field


@dataclass
class Needs:
    inference_region: str = "any"           # "any", "us", "eu", ...
    must_stay_in_cloud: str = ""            # "aws", "gcp", "azure" if contracts require that provider
    hipaa_or_zdr: bool = False
    newest_features: bool = False           # Skills, server tools, Files API, betas on day one
    host_the_loop: str = "either"           # "us" = we must run it; "anthropic" = we won't run it
    long_running_sessions: bool = False
    tools_on_our_network: bool = False      # internal, non-routable systems


@dataclass
class Choice:
    surface: str
    runtime: str
    tradeoffs: list = field(default_factory=list)


def choose(n: Needs) -> Choice:
    t = []
    # 1. Surface: residency and provider contracts are hard constraints.
    if n.inference_region not in ("any", "us"):
        surface = "Amazon Bedrock (regional inference profile)"
        t += ["regional endpoint costs 10% more than global",
              "feature lag: no Files API, server tools, Skills, MCP connector, Batches or Managed Agents on bedrock-runtime",
              f"confirm the model you need has a '{n.inference_region}' inference profile"]
    elif n.must_stay_in_cloud == "aws":
        surface = "Claude Platform on AWS"
        t += ["Anthropic-operated, AWS Marketplace billing; features typically same day"]
    elif n.must_stay_in_cloud == "gcp":
        surface = "Claude on Google Cloud"
        t += ["check the feature list for the managed variant you use"]
    elif n.must_stay_in_cloud == "azure":
        surface = "Claude in Microsoft Foundry"
        t += ["US Data Zone Standard deployments keep inference in the US (1.1x)"]
    else:
        surface = "Claude API"
        if n.inference_region == "us":
            t += ["inference_geo='us' adds 1.1x to token prices"]
    # 2. Runtime: who runs the loop, where tools must execute, compliance eligibility.
    managed_ok = surface in ("Claude API", "Claude Platform on AWS", "Claude on Google Cloud") and n.host_the_loop != "us"
    if n.hipaa_or_zdr and managed_ok and n.host_the_loop == "anthropic":
        runtime = "self-hosted Claude Managed Agents (talk to the account team)"
        t += ["you operate the whole service; the only Managed Agents option eligible for ZDR/HIPAA"]
    elif managed_ok and not n.hipaa_or_zdr and (n.long_running_sessions or n.host_the_loop == "anthropic"):
        runtime = "Claude Managed Agents" + (" with a self-hosted sandbox" if n.tools_on_our_network else ", cloud environment")
        t += ["beta; sessions and transcripts held by Anthropic until deleted"]
        if n.tools_on_our_network:
            t += ["you run the sandbox workers; conversation history and tool results still reach Anthropic"]
    elif n.long_running_sessions or n.tools_on_our_network:
        runtime = "self-hosted Agent SDK (or headless Claude Code) in your containers"
        t += ["you own session storage, isolation, scaling and max_turns"]
    else:
        runtime = "Messages API loop in your service"
        t += ["you write the loop, tools and state; maximum control"]
    if n.hipaa_or_zdr:
        t += ["needs a ZDR or HIPAA arrangement with Anthropic; use only features marked eligible"]
    if "self-hosted sandbox" in runtime and surface != "Claude API":
        t += [f"check self-hosted sandbox availability on {surface}"]
    return Choice(surface, runtime, t)


SCENARIOS = {
    "games studio: newest features, nothing to host": Needs(newest_features=True, host_the_loop="anthropic", long_running_sessions=True),
    "clinic software: HIPAA, short calls": Needs(hipaa_or_zdr=True),
    "EU retailer: inference must stay in the EU": Needs(inference_region="eu", long_running_sessions=True),
    "factory: tools on the plant network, AWS contract": Needs(must_stay_in_cloud="aws", long_running_sessions=True, tools_on_our_network=True),
}

if __name__ == "__main__":
    for name, needs in SCENARIOS.items():
        c = choose(needs)
        print(f"{name}\n  surface: {c.surface}\n  runtime: {c.runtime}")
        for x in c.tradeoffs:
            print(f"  - {x}")

The trade-offs to name

Skill 1.6The six the guide lists.

  • Latency: global routing maximises available capacity; regional endpoints trade some of that for residency. Fast mode is only on some surfaces.
  • Feature availability: first-party and Claude Platform on AWS get features first; partner-operated endpoints lag and may lack server tools, Skills, Batches or Managed Agents.
  • Hosting: self-hosted runtimes need containers, scaling and on-call; Managed Agents removes that but is beta.
  • Session state: your store (SDK SessionStore, your database) or Anthropic's (Managed Agents sessions persist until deleted).
  • Sandboxing: your container isolation, Anthropic's per-session container, or your self-hosted sandbox workers.
  • Data custody: which data reaches whom: with a self-hosted sandbox, files stay with you but conversation history and tool results reach Anthropic; on a cloud provider, the provider's terms and logs apply.

Key takeaways

  • Surfaces: Claude API (all features first), Claude Platform on AWS (Anthropic-operated, near same-day features), Bedrock (AWS-operated; bedrock-runtime lacks Files, server tools, Skills, MCP connector, Batches, Managed Agents), Google Cloud, Microsoft Foundry.
  • Inference geo is where the model runs (global or us on the Claude API, 1.1x for US); workspace geo is where data rests (US only, fixed at creation); other regions mean regional cloud profiles at a premium.
  • Runtimes: Messages API loop (most control), self-hosted Agent SDK or headless Claude Code (you own state, sandbox, scale), Managed Agents (Anthropic runs it; beta; not ZDR/HIPAA eligible unless fully self-hosted).
  • Decide by hard constraints, then ownership, then preferences; a conflicting preference becomes a named trade-off.
  • Justify the choice on latency, feature availability, hosting, session state, sandboxing and data custody.
