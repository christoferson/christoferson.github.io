4.5: Root-Cause Isolation from Logs and Traces

A wrong answer can come from five different places: a tool that failed, a model or prompt that isn't the one tested, a search that missed the right document, a model that invented something, or an instruction that wasn't clear. The trace shows which, if you read it in the right order.

Overview

Skill 4.5

Root-Cause Isolation from Logs and Traces: "Isolating the root cause of a failing Claude system from its logs or traces among prompt failure, retrieval failure, hallucination, tool or subagent error, and model mismatch, and specifying the corrective action."

Exam items give a trace excerpt or log lines and ask what went wrong and what to fix. The developer view of failure modes in a single exchange (refusals, under-acting, format drift) is CCDV-F 4.2; designing the telemetry is skill 3.4.

Trace a wrong answer back to what caused it

Skill 4.5What this skill asks, and the five causes it names.

A wrong answer from a Claude system can come from five places: a tool or subagent that failed, the wrong model or prompt version being served, retrieval that missed the right document, a claim the model made up, or an instruction the prompt didn’t make clear. Questions on this skill give a log or trace and ask which cause it shows, and what corrects it.

Take an IT-support assistant that retrieves knowledge-base articles, can hand ticket lookups to a subagent, and answers with citations. Five wrong answers were flagged this week, each with a full trace. The sections below take one cause at a time: what it leaves in the trace, and its fix.

A tool or subagent failed

Skill 4.5Often followed by an answer that sounds confident anyway.

In the trace. An error status or exception on a tool span, or in a subagent’s result. In Agent SDK traces a subagent’s spans sit under the parent’s tool span, so its failure shows in context.

The fix. Return the error to the model so it can adapt rather than guess; retry, or fail the request openly; alert someone; then fix the tool itself (a 403, for example, means a credential or permission problem).

Production isn’t running the model and prompt you evaluated

Skill 4.5A silent fallback, a configuration change, or a new default.

In the trace. The model name on the request spans, or the prompt version, differs from what the evaluation approved.

The fix. Pin the model and prompt versions in configuration, and rerun the evaluation before any switch takes effect.

Retrieval missed the document that answers the question

Skill 4.5The model answered from what it was given, or from general knowledge.

In the trace. The article that answers the question isn’t among the retrieved results.

The fix. Improve the index or the query (chunks with their document context added, keyword and meaning-based search together, reranking), and track how often the failing questions now retrieve the right article.

The model stated something no retrieved text supports

Skill 4.5A hallucination, which can only be called that once retrieval is ruled out.

In the trace. The right article was retrieved, but the answer contains a claim none of the retrieved text supports.

The fix. Anthropic’s guidance on reducing hallucinations: allow the model to say it doesn’t know, have it quote the source before answering, require citations and withdraw claims without one, and restrict it to the documents provided.

Everything going in was right, and the instruction still wasn’t followed

Skill 4.5A prompt failure: what’s left when the other causes are ruled out.

In the trace. The inputs were complete and the claims supported, yet the answer breaks an instruction: the wrong scope, the wrong format, a step it shouldn’t have taken. Anthropic notes that current models follow instructions precisely, so an ambiguous instruction produces a literal answer.

The fix. State the instruction explicitly, or add an example of the borderline case.

Check the causes in order, from the outside in

Skill 4.5Rule out each cause before blaming the next.

  1. Infrastructure first. A failed tool explains a missing document better than the retriever does.
  2. Then configuration. If production isn’t running the evaluated model and prompt, every later check is about the wrong system.
  3. Then the inputs. Only once the right document was retrieved can an unsupported claim be called a hallucination.
  4. Then behaviour. With good inputs and supported claims, what’s left is the instruction.

Whatever the cause, add the failing trace’s input to the evaluation set as a regression test. The code below applies these checks in order to a trace and names the cause; its test plants a failed tool and a missing document together and expects the tool error:

triage.py (triage.py)Optional 
"""Isolate the root cause of a bad answer from one trace of an IT-support assistant.

Pipeline: retrieve knowledge-base articles -> (optionally) a ticket-lookup subagent -> answer with
citations. Evidence is checked in an order where each step rules out a cause before blaming the next:
infrastructure first, then configuration, then inputs to the model, then what the model did with them."""


def triage(t: dict) -> tuple[str, str]:
    # 1. Tool or subagent error: the model was answering without data it asked for.
    for step in t["steps"]:
        if step.get("error"):
            return "tool/subagent error", f"{step['name']} failed ({step['error']}); surface the error to the model, retry or fail the request, alert"
    # 2. Model mismatch: production isn't running what was evaluated.
    if t["served_model"] != t["evaluated_model"] or t["prompt_version"] != t["evaluated_prompt"]:
        return "model mismatch", f"served {t['served_model']} / prompt {t['prompt_version']}, evaluated {t['evaluated_model']} / {t['evaluated_prompt']}; pin versions in config and re-run the eval before switching"
    # 3. Retrieval failure: the article that answers the question never reached the model.
    if t["gold_doc"] not in t["retrieved"]:
        return "retrieval failure", f"{t['gold_doc']} not retrieved; fix the index or query (contextual chunks, hybrid search, reranking), not the prompt"
    # 4. Hallucination: the right article was there, but the answer asserts something it doesn't say.
    unsupported = [c for c in t["claims"] if not c["supported_by"]]
    if unsupported:
        return "hallucination", f"claim not in any retrieved text: {unsupported[0]['text']!r}; require quotes or citations per claim, allow 'I don't know'"
    # 5. Prompt failure: grounded and complete inputs, but the answer breaks an instruction.
    if t["violations"]:
        return "prompt failure", f"{t['violations'][0]}; clarify the instruction or add an example, then add this case to the eval set"
    return "no fault found", "compare with a known-good trace; check the grader"


BASE = {"served_model": "claude-sonnet-5-5", "evaluated_model": "claude-sonnet-5-5", "prompt_version": "v14",
        "evaluated_prompt": "v14", "gold_doc": "KB-2210", "retrieved": ["KB-2210", "KB-1033"],
        "steps": [{"name": "kb_search"}, {"name": "ticket_lookup_subagent"}],
        "claims": [{"text": "Reset the VPN token in the self-service portal", "supported_by": "KB-2210"}],
        "violations": []}

“The answer is wrong, so it’s a hallucination: add ‘don’t make things up’ to the prompt” is the most common misdiagnosis. If the right article was never retrieved, or the ticket subagent failed, no prompt change fixes it.

Record what the diagnosis will need

Skill 4.5You can only isolate a cause you recorded.

  • Each step: its name, status, errors and timing.
  • Each request: the model ID and prompt version.
  • Retrieval: the IDs (and scores) of what was retrieved, so you can check whether the right document was there.
  • The answer: its claims and citations, so support can be checked claim by claim.
  • Subagents: spans linked to the parent, so their failures appear in the parent’s trace.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
A trace shows the knowledge-base search returned three articles, none of them the one that answers the question, and the assistant answered from general knowledge. What is the cause, and the fix?
  1. A. A hallucination; tell the model not to make things up
  2. B. A retrieval failure; improve the index or query and track recall
  3. C. A model mismatch; pin the model
  4. D. A prompt failure; add an example
Answer
B
Why
The answering article was never retrieved, so the model had nothing correct to work from. Fixing retrieval is the remedy; a prompt instruction can’t supply a document that wasn’t found.
Question 2
Scenario
The right article was retrieved, but the answer gives a warranty period the article never mentions. What is the cause?
  1. A. Retrieval failure
  2. B. Hallucination: a claim no retrieved text supports
  3. C. A failed tool
  4. D. Model mismatch
Answer
B
Why
With the right source in context and a claim it doesn’t support, the model invented a detail. The fix is grounding: allow “I don’t know”, quote the source first, and require citations.
Question 3
Scenario
Answers got worse on Tuesday. The trace shows requests served by a different model from the one the evaluation approved, after a configuration change. What should be done?
  1. A. Rewrite the prompt for the new model
  2. B. Pin the model and prompt versions in configuration and rerun the evaluation before any switch
  3. C. Add more retrieval
  4. D. Raise the effort level
Answer
B
Why
The cause is configuration: production isn’t running the evaluated system. Pin versions and make switching depend on a passing evaluation; changing the prompt treats a symptom.
Question 4
Scenario
A trace shows a ticket-lookup subagent returned a 403 error, and the parent then answered confidently without the ticket data. Which check should come first, and what is the fix?
  1. A. Check for hallucination first; add citations
  2. B. The tool failure comes first: return the error to the model, alert, and fix the credential
  3. C. Check the prompt first; clarify the instruction
  4. D. Check the model version first
Answer
B
Why
Infrastructure is checked first, and a failed subagent explains the missing data. Surfacing the error lets the model say it couldn’t look; the 403 points to a credential or permission to fix.

Key takeaways

  • Five causes, five signatures: an error on a tool or subagent span; a model or prompt that differs from the evaluated one; the answering document not retrieved; a claim no retrieved text supports; an instruction broken despite good inputs.
  • Check in order (infrastructure, configuration, inputs, then behaviour) so a downstream symptom isn’t blamed on the wrong cause.
  • Fix the cause: return tool errors to the model and alert; pin versions and re-evaluate; improve retrieval; ground and cite answers; make the instruction explicit.
  • Add each failure to the evaluation set as a regression test, and record enough in every trace to diagnose the next one.
