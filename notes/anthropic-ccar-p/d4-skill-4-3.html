4.3: LLM-as-Judge Design and Bias

When a model grading other models' output keeps disagreeing with people, working out which systematic bias is to blame (where the answer sat, how long it was, who wrote it, or a judge that has changed over time) and fixing that bias rather than the rubric in general.

Overview

Skill 4.3

LLM-as-Judge Design and Bias: "Evaluating the design of an LLM-as-judge or rubric-based evaluation whose results are inconsistent with human review, and selecting the correction that addresses the responsible bias (position, verbosity, self-preference, judge drift)."

Exam items describe a judge's setup and how its results differ from human review, and ask which bias is responsible and which change fixes it. Building and calibrating a judge from scratch is in the developer notes (CCDV-F 4.1).

Sources: Anthropic's guidance on developing tests and grading, checked on 20 November 2026 and paraphrased. The four biases' names come from the exam guide; their diagnostics and corrections below are standard evaluation practice in my words. The setup and code are my own, tested on synthetic judgements.

Running example. A support team uses an LLM judge to compare two draft replies per ticket (a current prompt against a candidate). Human reviewers labelled 300 pairs, and the judge agrees with them on only 68%.

What Anthropic recommends for model graders

Skill 4.3The baseline design.

  • Test reliability first, then scale: model grading is fast, flexible and good for judgement, but only after checking it against human judgements.
  • Detailed, clear rubrics: spell out what earns each score, possibly several rubrics per criterion.
  • Specific outputs: correct/incorrect or a defined 1–5 scale, not open-ended commentary.
  • Reasoning before the verdict: let the grader think through the rubric before it scores.
  • A different model from the generator: Anthropic's grading example says to grade with a different model from the one that produced the output.

Four biases and their signatures

Skill 4.3How each shows up in disagreement with humans.

  • Position bias: the judge favours whichever answer appears first (or last). Signature: swapping A and B changes its verdict; it picks one slot far more often than human labels would explain.
  • Verbosity bias: the judge favours longer, more elaborate answers. Signature: disagreement concentrates on pairs where humans preferred the shorter reply.
  • Self-preference: the judge favours output written by its own model, or in its own style. Signature: agreement with humans drops specifically when the judge's own model wrote the reply humans rejected.
  • Judge drift: the judge's behaviour changes over time, because its model, prompt or rubric changed. Signature: agreement on a fixed calibration set falls from one period to the next while nothing else changed.

Diagnosing against human labels

Skill 4.3One test for each bias.

judge_bias.py (judge_bias.py)Optional 
"""Find which bias makes an LLM judge disagree with human reviewers, so the right correction is applied.

Setup: a support team compares two reply drafts (A, B) per ticket; the judge picks the better one.
Human reviewers labelled 300 pairs. Each diagnostic isolates one bias using those labels."""
from statistics import mean


def position_bias(records):
    """Judge the same pair in both orders: a fair judge's choice of reply doesn't depend on its slot."""
    flips = [r for r in records if r["pick_ab"] != r["pick_ba"]]   # picks given as reply ids
    first_slot = mean(1 if r["pick_ab"] == r["a"] else 0 for r in records)
    return {"inconsistent_when_swapped": round(len(flips) / len(records), 2), "picks_first_slot": round(first_slot, 2)}


def verbosity_bias(records):
    """Among pairs where humans preferred the shorter reply, how often does the judge pick the longer one?"""
    hard = [r for r in records if r["human"] == r["shorter"]]
    return {"picks_longer_when_humans_prefer_shorter": round(mean(r["pick_ab"] != r["shorter"] for r in hard), 2)}


def self_preference(records, judge_model):
    """Agreement with humans, split by whether the judge's own model wrote the reply humans rejected."""
    own = [r for r in records if r["rejected_by"] == judge_model]
    other = [r for r in records if r["rejected_by"] != judge_model]
    agree = lambda rs: round(mean(r["pick_ab"] == r["human"] for r in rs), 2)
    return {"agreement_when_own_model_lost": agree(own), "agreement_otherwise": agree(other)}


def drift(calibration_runs):
    """Same fixed calibration set, judged monthly: agreement with humans should hold steady."""
    return {month: round(acc, 2) for month, acc in calibration_runs}


CORRECTIONS = {
    "position": "judge each pair in both orders; count a win only if it holds both ways, otherwise a tie",
    "verbosity": "rubric criteria that reward completeness, not length; tell the judge length isn't a criterion; "
                 "add short-but-correct anchor examples",
    "self-preference": "use a judge from a different model than the generators being compared",
    "drift": "pin the judge model and prompt; re-check agreement on the fixed calibration set on every change "
             "and monthly; recalibrate when it falls",
}
  • Position: re-judge every pair in the opposite order; the share of verdicts that flip is the bias, measured directly.
  • Verbosity: look only at pairs where humans chose the shorter reply; a fair judge agrees with them, a verbose-biased one picks the longer.
  • Self-preference: split agreement by which model wrote the rejected reply.
  • Drift: rerun a fixed, human-labelled calibration set on a schedule and on every judge change.
  • The tests plant one bias at a time in synthetic judgements and confirm each diagnostic flags only its own.

Choosing the correction

Skill 4.3Fix the bias you found, not everything at once.

  • Position: judge both orders and count a win only when it holds both ways; otherwise record a tie.
  • Verbosity: rubric criteria for completeness and correctness rather than length, an explicit statement that length isn't a criterion, and short-but-correct anchor examples.
  • Self-preference: a judge from a different model than the generators being compared, consistent with Anthropic's grading example.
  • Drift: pin the judge model and prompt; re-check agreement on the calibration set whenever either changes and on a schedule; recalibrate when it falls.

"Rewrite the rubric to be more detailed" is a reasonable general improvement, but it won't fix a judge that flips when answers swap places, or one comparing its own model's output. Diagnose first, then apply the matching correction.

Key takeaways

  • Baseline (Anthropic): check a model grader against human judgements before scaling; detailed rubrics, specific scales, reasoning before the verdict, and a different model from the generator.
  • Position bias: verdicts change when order swaps; fix by judging both orders and counting only consistent wins.
  • Verbosity bias: longer answers win where humans preferred shorter; fix with length-neutral criteria and short anchor examples.
  • Self-preference: agreement drops when the judge's own model lost; fix with a judge from a different model.
  • Judge drift: agreement on a fixed calibration set falls over time; fix by pinning the judge and re-checking on every change and on a schedule.
