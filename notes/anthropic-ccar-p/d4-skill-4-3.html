Overview

Skill 4.3

LLM-as-Judge Design and Bias: "Evaluating the design of an LLM-as-judge or rubric-based evaluation whose results are inconsistent with human review, and selecting the correction that addresses the responsible bias (position, verbosity, self-preference, judge drift)."

Exam items describe a judge's setup and how its results differ from human review, and ask which bias is responsible and which change fixes it. Building and calibrating a judge from scratch is in the developer notes (CCDV-F 4.1).

When an LLM judge disagrees with people, find the bias behind it

Skill 4.3What this skill asks, and a judge that has gone wrong.

An LLM judge is a model that grades other outputs, often by comparing two answers and saying which is better. Questions on this skill describe a judge whose verdicts don’t match human review, and ask which bias is responsible and which correction fixes it. The guide names four biases: position, verbosity, self-preference and drift.

Take a support team that uses an LLM judge to compare two draft replies for each ticket, one from the current prompt and one from a candidate. People labelled 300 of those pairs, and the judge agrees with them on only 68%. Each section below takes one possible cause.

Start from a sound judge design

Skill 4.3What Anthropic recommends for model graders.

  • Check it against people before relying on it. Model grading is fast and flexible and good for judgement calls, but only once its verdicts have been compared with human ones.
  • Give it a detailed rubric that says exactly what earns each score; several rubrics for one criterion if needed.
  • Ask for a specific output: correct or incorrect, or a defined 1-to-5 scale, rather than open-ended comments.
  • Let it reason before the verdict, working through the rubric first.
  • Use a different model from the one being graded. Anthropic’s grading example says to grade with a different model from the one that produced the output.

Position bias: the judge favours one slot

Skill 4.3The answer shown first (or last) wins more often than it should.

How it shows. Swapping the two answers changes the verdict, and the judge picks one position far more often than the human labels would explain.

The test. Judge every pair again with the answers in the opposite order. The share of verdicts that flip measures the bias directly.

The fix. Judge each pair in both orders and count a win only when it holds both ways; otherwise record a tie.

Verbosity bias: the judge favours the longer answer

Skill 4.3Length is mistaken for quality.

How it shows. The disagreements cluster on pairs where people preferred the shorter reply.

The test. Look only at pairs where people chose the shorter reply. A fair judge mostly agrees with them; a judge biased toward length picks the longer one.

The fix. Rubric criteria for completeness and correctness rather than length, a plain statement that length isn’t a criterion, and examples of short replies that score highly.

Self-preference: the judge favours its own model’s writing

Skill 4.3A judge grading output from its own model, or in its own style.

How it shows. Agreement with people drops specifically when the reply people rejected was written by the judge’s own model.

The test. Split the agreement rate by which model wrote the rejected reply.

The fix. Use a judge from a different model than the ones being compared, as Anthropic’s grading example recommends.

Drift: the judge changes over time

Skill 4.3Its model, prompt or rubric changed, and its verdicts moved.

How it shows. Agreement on a fixed set of labelled examples falls from one period to the next while nothing else changed.

The test. Rerun a fixed, human-labelled calibration set on a schedule and whenever the judge changes.

The fix. Pin the judge’s model and prompt to specific versions, recheck agreement on the calibration set whenever either changes and on a schedule, and recalibrate when it falls.

Run one test per bias, then apply only the matching fix

Skill 4.3Diagnose first; a general improvement may fix nothing.

The code below plants one bias at a time in simulated judge verdicts and checks that each test flags only its own bias:

judge_bias.py (judge_bias.py)Optional 
"""Find which bias makes an LLM judge disagree with human reviewers, so the right correction is applied.

Setup: a support team compares two reply drafts (A, B) per ticket; the judge picks the better one.
Human reviewers labelled 300 pairs. Each diagnostic isolates one bias using those labels."""
from statistics import mean


def position_bias(records):
    """Judge the same pair in both orders: a fair judge's choice of reply doesn't depend on its slot."""
    flips = [r for r in records if r["pick_ab"] != r["pick_ba"]]   # picks given as reply ids
    first_slot = mean(1 if r["pick_ab"] == r["a"] else 0 for r in records)
    return {"inconsistent_when_swapped": round(len(flips) / len(records), 2), "picks_first_slot": round(first_slot, 2)}


def verbosity_bias(records):
    """Among pairs where humans preferred the shorter reply, how often does the judge pick the longer one?"""
    hard = [r for r in records if r["human"] == r["shorter"]]
    return {"picks_longer_when_humans_prefer_shorter": round(mean(r["pick_ab"] != r["shorter"] for r in hard), 2)}


def self_preference(records, judge_model):
    """Agreement with humans, split by whether the judge's own model wrote the reply humans rejected."""
    own = [r for r in records if r["rejected_by"] == judge_model]
    other = [r for r in records if r["rejected_by"] != judge_model]
    agree = lambda rs: round(mean(r["pick_ab"] == r["human"] for r in rs), 2)
    return {"agreement_when_own_model_lost": agree(own), "agreement_otherwise": agree(other)}


def drift(calibration_runs):
    """Same fixed calibration set, judged monthly: agreement with humans should hold steady."""
    return {month: round(acc, 2) for month, acc in calibration_runs}


CORRECTIONS = {
    "position": "judge each pair in both orders; count a win only if it holds both ways, otherwise a tie",
    "verbosity": "rubric criteria that reward completeness, not length; tell the judge length isn't a criterion; "
                 "add short-but-correct anchor examples",
    "self-preference": "use a judge from a different model than the generators being compared",
    "drift": "pin the judge model and prompt; re-check agreement on the fixed calibration set on every change "
             "and monthly; recalibrate when it falls",
}

“Rewrite the rubric to be more detailed” is a reasonable general improvement, but it won’t fix a judge that flips when the answers swap places, or one comparing its own model’s output. Find the bias first, then apply its fix.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
An LLM judge compares two summaries per document. When the team swaps which summary is shown first, the verdict changes on 30% of pairs. Which correction fits?
  1. A. Make the rubric more detailed
  2. B. Judge each pair in both orders and count a win only if it holds both ways
  3. C. Use a larger judge model
  4. D. Ask the judge to explain its reasoning
Answer
B
Why
Verdicts that flip when the order changes are position bias, and judging both orders removes it. A better rubric, a bigger model or written reasoning don’t stop the order from influencing the verdict.
Question 2
Scenario
A judge disagrees with human reviewers mostly on pairs where the reviewers preferred the shorter, more direct reply. What is the likely bias, and the fix?
  1. A. Self-preference; switch judge model
  2. B. Verbosity bias; length-neutral criteria and short, high-scoring examples
  3. C. Drift; pin the judge version
  4. D. Position bias; swap the order
Answer
B
Why
Disagreement concentrated where people chose the shorter answer is the signature of verbosity bias. The fix is a rubric that rewards completeness and correctness, says length isn’t a criterion, and shows short answers scoring well.
Question 3
Scenario
A team uses the same model as both the generator and the judge. Agreement with people is fine overall but drops sharply when that model’s reply was the one people rejected. What should change?
  1. A. Use a judge from a different model
  2. B. Add more labelled pairs
  3. C. Lower the judge’s effort
  4. D. Judge both orders
Answer
A
Why
Lower agreement exactly where the judge’s own model lost is self-preference. Anthropic’s grading example recommends a different model from the one that produced the output; more data or order swapping doesn’t address it.
Question 4
Scenario
A judge’s agreement with a fixed set of human-labelled examples was 88% in March and 79% in May, with no change to the products being graded. What explains it, and what prevents it?
  1. A. Verbosity bias; shorter rubric
  2. B. Drift in the judge; pin its model and prompt and recheck on every change
  3. C. Position bias; randomise order
  4. D. Too few test cases; add more
Answer
B
Why
Agreement falling on a fixed calibration set over time means the judge itself changed. Pinning its model and prompt, and rechecking whenever either changes and on a schedule, catches and prevents it.

Key takeaways

  • Start from a sound design: check the judge against people before relying on it, give it a detailed rubric and a specific output, let it reason first, and use a different model from the one being graded.
  • Position bias: verdicts change when the answers swap; judge both orders and count only consistent wins.
  • Verbosity bias: longer answers win where people preferred shorter ones; use length-neutral criteria and short, high-scoring examples.
  • Self-preference: agreement drops when the judge’s own model lost; use a judge from a different model.
  • Drift: agreement on a fixed calibration set falls over time; pin the judge and recheck it on every change and on a schedule.
  • Diagnose first; a more detailed rubric doesn’t fix position bias or self-preference.
