Overview

Task 3.3

Design cost allocation and visibility solutions.

In a multi-account organization the account is the strongest allocation boundary, and tags and cost categories fill in what accounts can't separate. Most of the billing settings below live in the management account. The basics of Cost Explorer, Budgets and cost allocation tags are in the SAA cost-optimized storage notes, which cover the cost tools; this page covers allocation across an organization.

Running example. Finance wants each business unit to see its spend, including its share of the shared-network account (666666666666), enterprise support and the central GenAI account (222222222222). The platform team runs one shared EKS cluster for several teams, and the CFO wants warning before any team's spend jumps.

Status changes to know. The legacy Cost and Usage Report is now a "legacy data export"; CUR 2.0 in AWS Data Exports is recommended, alongside FOCUS 1.0 and 1.2 exports. Amazon Q Developer in the console is now called the AWS assistant. In Cost Anomaly Detection, custom monitors are now customer managed monitors, alongside new AWS managed monitors, and the plain Threshold field is replaced by ThresholdExpression. New: account tags and IAM principal attribution as allocation dimensions, Cost Explorer 18-month forecasts, RI and Savings Plans group sharing (November 2025), and billing views and billing transfer.

Tagging strategy

Skill 3.3.1Design tagging strategies for cost allocation (for example, by using tags for business units, projects, and environments).

  • Accounts first: an account per workload and environment gives exact allocation for everything in it, including charges that can't be tagged. Account tags on Organizations accounts (for example BusinessUnit) now allocate all usage in the account, including credits and refunds.
  • A small, fixed tag set: for example CostCenter, BusinessUnit, Project, Environment and Owner, with exact key spelling and allowed values defined in a tag policy. Keep it short, because every extra key is one more thing teams get wrong.
  • Activate the keys: user-defined and AWS-generated tags appear in billing only after the management account activates them as cost allocation tags. They show up within 24 hours and aren't retroactive unless you request a backfill (up to 12 months).
  • Tag automatically: tags in IaC templates and stacks (CloudFormation stack tags propagate to supported resources), ECS-managed and EKS tags for container cost, and propagate tags from Auto Scaling groups to instances and from instances to volumes.
  • Other dimensions: IAM principal attribution (who called Bedrock), IAM Identity Center user attributes for per-user apps (Amazon Q, QuickSight), and cost categories for anything you can't tag.
Management account: activate the cost allocation tags 
aws ce update-cost-allocation-tags-status \
  --cost-allocation-tags-status \
    TagKey=CostCenter,Status=Active \
    TagKey=BusinessUnit,Status=Active \
    TagKey=Environment,Status=Active

Tags only allocate costs from the moment they're on the resource and activated; backfill can't create history that never existed. Tag keys are case-sensitive in billing, so costcenter and CostCenter are two keys; a tag policy fixes the capitalization. Some charges (support, data transfer on shared paths) can't be tagged at all, which is why accounts and cost categories matter.

Cost reporting and analytics

Skill 3.3.2Configure cost reporting and analytics solutions that use detailed billing data (for example, by using AWS Cost Explorer, AWS Cost and Usage Reports).

  • Cost Explorer for interactive analysis: 13 months of history (38 with the multi-year opt-in), an 18-month forecast, grouping by account, service, tag or cost category, and hourly or resource-level data for the last 14 days (opt-in, paid per usage record). Its API is charged per request.
  • CUR 2.0 through AWS Data Exports for line-item detail: choose columns, filter with SQL, deliver Parquet to S3 daily, and query with Athena or visualize in QuickSight (the cost and usage dashboard). Include resource IDs, the tags map (resource tags, account tags, cost categories, user attributes and IAM principals), and split cost allocation data for containers. FOCUS exports give a vendor-neutral schema for multi-cloud FinOps tools.
  • Billing views let a business unit see only its own cost data in Cost Explorer and Budgets without access to the management account; Cost Optimization Hub gathers savings recommendations across the organization.
  • Amortized vs unblended: report amortized cost (upfront Savings Plans and RI fees spread over the term) for chargeback, and net cost after discounts and credits for what is actually paid.

"Detailed per-resource cost data for Athena" means CUR 2.0 in Data Exports, not Cost Explorer. "Each business unit should see only its own costs" means billing views (or Billing Conductor billing groups), not IAM access to the management account. "Multi-cloud FinOps tool" points to the FOCUS export.

Enforcing tags

Skill 3.3.3Implement policy-based tagging enforcement for cost allocation (for example, by using SCPs, AWS Config rules, tag policies).

  • Tag policies (Organizations) define the exact key capitalization and allowed values. With enforced_for they block noncompliant tag values on listed resource types; report_required_tag_for marks keys as required, enforced through IaC checks (a CloudFormation hook, Terraform or Pulumi). The organization-wide compliance report runs from the management account in us-east-1, refreshes every 48 hours, and doesn't list untagged resources as noncompliant.
  • SCPs block creation without a tag: deny the create action when aws:RequestTag/CostCenter is missing (a Null condition), and limit keys with aws:TagKeys. It only works for actions that support tag-on-create, so check each service.
  • AWS Config required-tags detects existing resources missing up to six tags (with optional allowed values) on about 30 resource types, and conformance packs deploy it org-wide. It doesn't prevent anything, and remediation needs your own automation document.
  • Proactive checks: CloudFormation Guard rules or hooks fail a deployment without the required tags, which catches problems before resources exist.
Tag policy: one spelling of CostCenter, allowed values, enforced on EC2 instances 
{
  "tags": {
    "costcenter": {
      "tag_key": { "@@assign": "CostCenter" },
      "tag_value": { "@@assign": ["BU-RETAIL", "BU-PAYMENTS", "BU-PLATFORM"] },
      "enforced_for": { "@@assign": ["ec2:instance"] }
    }
  }
}
SCP: no EC2 instance without a CostCenter tag 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyRunInstancesWithoutCostCenter",
      "Effect": "Deny",
      "Action": "ec2:RunInstances",
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "Null": { "aws:RequestTag/CostCenter": "true" }
      }
    }
  ]
}

A tag policy alone doesn't require a tag; it only controls values when the tag is used (plus IaC checks for required keys). Put one required key per Deny statement: several keys in one Null block must all be missing before it denies. Member accounts can't read their effective SCPs, so document the tagging rules for developers.

Chargeback and showback

Skill 3.3.4Implement chargeback and showback capabilities for cost allocation (for example, by using cost categories, split cost allocation, token usage monitoring for Amazon Bedrock).

  • Cost categories map costs to business values with ordered rules (first match wins) on account, service, Region, usage type, charge type, tags or other categories. A rule can also take its value from a tag key or account name. Uncategorized costs get a default value, and categories can be nested (teams into business units).
    • Who and where: created in the management account and used in Cost Explorer, Budgets, CUR, Anomaly Detection and RI and Savings Plans group sharing.
    • Timing: changes apply within 24 hours from the start of the month, and can be backdated up to 12 months.
  • Split charge rules spread a shared value (shared networking, support, the platform team) across target values: proportionally to their cost, by fixed percentages, or evenly. The allocated amounts appear only on the cost category's details page and its CSV download, not in CUR, Cost Explorer or Budgets.
  • Split cost allocation data breaks shared EC2 instances behind ECS, EKS or Batch into per-task or per-pod cost. It uses CPU and memory reservations or actual use (for EKS, from requests, Managed Prometheus or Container Insights; GPUs and Trainium by requests). Turn it on in Cost Management preferences; it appears in CUR exports only, with columns such as split cost and unused cost, and namespace and workload tags.
  • Billing Conductor produces pro forma bills per billing group with your own pricing rules (markups, discounts), credits and fees, for resellers or internal rates. The real AWS invoice and discount sharing don't change.
  • Bedrock spend:
    • Application inference profiles with cost allocation tags per team or feature.
    • IAM principal attribution in CUR 2.0 (who called), and request metadata in invocation logs.
    • CloudWatch token metrics (InputTokenCount, OutputTokenCount, cache read and write counts) for near-real-time usage, since billing data arrives later.
    A central GenAI account should pass its costs back to the consuming accounts this way.
Cost category: business units by account and tag, with the shared-network account split proportionally 
aws ce create-cost-category-definition \
  --name BusinessUnit \
  --rule-version CostCategoryExpression.v1 \
  --default-value Unallocated \
  --rules '[
    {"Value": "SharedNetwork",
     "Rule": {"Dimensions": {"Key": "LINKED_ACCOUNT",
       "Values": ["666666666666"], "MatchOptions": ["EQUALS"]}}},
    {"Value": "Retail",
     "Rule": {"Tags": {"Key": "CostCenter",
       "Values": ["BU-RETAIL"], "MatchOptions": ["EQUALS"]}}},
    {"Value": "Payments",
     "Rule": {"Tags": {"Key": "CostCenter",
       "Values": ["BU-PAYMENTS"], "MatchOptions": ["EQUALS"]}}}
  ]' \
  --split-charge-rules '[
    {"Source": "SharedNetwork", "Targets": ["Retail", "Payments"],
     "Method": "PROPORTIONAL"}
  ]'

Split charges aren't in CUR or Cost Explorer, so a chargeback built on CUR must do its own split (or use Billing Conductor). Split cost allocation data isn't in Cost Explorer either, and EKS pods without resource requests get no split cost under the requests method. Rules are first-match, so put shared-cost rules at the top.

Budgets and anomaly alerts

Skill 3.3.5Configure cost monitoring and alerting solutions that include budget thresholds and anomaly detection (for example, by using AWS Budgets, AWS Cost Anomaly Detection).

  • AWS Budgets track cost, usage, or Savings Plans and RI coverage and utilization over a month, quarter, year or custom period, filtered by account, tag or cost category. They alert on actual or forecast spend to email, SNS or chat. Budget actions apply an IAM policy or an SCP, or stop EC2 and RDS instances in the same account, automatically or after approval. Budgets update up to three times a day, so they aren't real-time limits.
  • Cost Anomaly Detection uses machine learning on daily spend patterns and finds unexpected increases without fixed thresholds.
    • AWS managed monitors watch each service, linked account, tag value or cost category value separately (up to 5,000 values) and pick up new ones automatically.
    • Customer managed monitors watch up to 10 accounts or tag values in aggregate.
    • Alerts: above a dollar and/or percentage impact, immediately to SNS or as daily or weekly email, and through EventBridge and AWS User Notifications.
    • Root cause: ranked by service, account, Region and usage type; the AWS assistant can correlate it with CloudTrail.
  • Use both: budgets for planned limits per team and anomaly detection for surprises. Anomaly detection needs about 10 days of history for a new service, can take up to 24 hours to flag, and doesn't cover some charges (support, most Marketplace purchases), so budgets still matter there.
  • Bedrock and other usage spikes show up hours earlier in CloudWatch metrics than in billing: alarm on token counts per model to catch a runaway agent loop quickly.
Anomaly alert: email daily when an anomaly is at least $500 and 20% above expected 
{
  "SubscriptionName": "bu-anomalies-daily",
  "MonitorArnList": ["arn:aws:ce::111111111111:anomalymonitor/example-monitor-id"],
  "Subscribers": [{ "Type": "EMAIL", "Address": "finops@example.com" }],
  "Frequency": "DAILY",
  "ThresholdExpression": {
    "And": [
      { "Dimensions": { "Key": "ANOMALY_TOTAL_IMPACT_ABSOLUTE",
          "Values": ["500"], "MatchOptions": ["GREATER_THAN_OR_EQUAL"] } },
      { "Dimensions": { "Key": "ANOMALY_TOTAL_IMPACT_PERCENTAGE",
          "Values": ["20"], "MatchOptions": ["GREATER_THAN_OR_EQUAL"] } }
    ]
  }
}
CloudWatch alarm: more than 5 million output tokens in an hour for one model 
aws cloudwatch put-metric-alarm \
  --alarm-name bedrock-output-tokens-high \
  --namespace AWS/Bedrock \
  --metric-name OutputTokenCount \
  --dimensions Name=ModelId,Value=example-model-id \
  --statistic Sum --period 3600 --evaluation-periods 1 \
  --threshold 5000000 --comparison-operator GreaterThanThreshold \
  --alarm-actions arn:aws:sns:us-east-1:222222222222:genai-cost-alerts

Immediate anomaly alerts go only to SNS; email subscriptions are daily or weekly. An AWS managed monitor applies one threshold to every value, so route per team with EventBridge or User Notifications filters. Linked account, tag and cost category monitors can only be created in the management account. Budget actions can't stop instances in another account; use an SCP action for that.

Key takeaways

  • Tagging: accounts as the main boundary, account tags, a small fixed tag set, activation as cost allocation tags in the management account (24 hours, backfill up to 12 months).
  • Reporting: Cost Explorer for analysis, CUR 2.0 in Data Exports for line items in Athena, FOCUS for multi-cloud, billing views for per-unit visibility, amortized cost for chargeback.
  • Enforcement: tag policies for values and spelling, SCPs with aws:RequestTag for creation, Config required-tags for detection, IaC checks before deployment.
  • Chargeback: cost categories with first-match rules and split charges (details page only), split cost allocation data for ECS and EKS in CUR, Billing Conductor pro forma bills, Bedrock profiles, principals and token metrics.
  • Alerts: Budgets for planned limits and actions, Cost Anomaly Detection managed monitors with absolute and percentage thresholds, CloudWatch token alarms for fast signals.
