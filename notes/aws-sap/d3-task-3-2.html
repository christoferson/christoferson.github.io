Task 3.2: Optimize data transfer and network costs

Where the network bill comes from and how to shrink it: serving from the edge, keeping traffic private and inside one Availability Zone where possible, replicating only what DR needs, choosing peering, Transit Gateway or PrivateLink by traffic pattern, and keeping AI data and models close together.

Overview

Task 3.2

Optimize data transfer and network costs.

Data transfer is easy to miss in a design and hard to remove later. The rules that drive most answers: inbound is free, internet egress is the most expensive path, traffic between AZs costs $0.01 per GB in each direction, traffic between Regions costs about $0.02 per GB, and every managed hop (NAT gateway, Transit Gateway, interface endpoint) adds a per-GB processing fee. Rates and the full price lists are in the SAA network cost notes; the network designs themselves are on Task 1.4. Prices on this page are us-east-1 list prices.

Running example. Product images and the web app are served worldwide from S3 and ALB origins in us-east-1; dozens of workload VPCs reach each other and on premises through a shared Transit Gateway; private subnets pull container images and S3 data through NAT gateways; customer data is copied to us-west-2 for DR; and the support assistant's RAG pipeline reads documents from S3 and calls Bedrock.

Status changes to know. New: CloudFront flat-rate plans (Free, Pro, Business and Premium per distribution, with no overage charges), Transit Gateway flexible cost allocation through metering policies (November 2025), the Regional NAT gateway (one resource, still billed per AZ), cross-Region PrivateLink (with no premium beyond inter-Region transfer), Direct Connect flat-rate billing for dedicated connections (September 2026), and public IPv4 addresses are charged at $0.005 per hour each.

Content delivery and caching

Skill 3.2.1Design content delivery architectures, origin selection strategies, caching strategies, and failover patterns (for example, by using Amazon CloudFront, Amazon CloudFront Origin Shield).

  • Why CloudFront saves money: transfer from AWS origins to CloudFront is free, CloudFront's internet rate is below EC2's and falls steeply with volume, and every cache hit is a request the origin doesn't serve. Even uncacheable API traffic gains from connection reuse and the AWS backbone.
  • Raise the cache hit ratio: cache policies with the smallest cache key (only the headers, cookies and query strings that change the response), origin request policies to forward other values without caching on them, long TTLs with versioned file names, and compression.
  • Origin Shield adds a central caching layer in one Region in front of the origin: all edge locations fetch through it, so the origin sees far fewer requests. It costs per request that reaches it, so it pays off for viewers spread across many regions, expensive origins (on premises, or video packaging) and multi-CDN setups. Choose the Origin Shield Region closest to the origin.
  • Origin selection: S3 with origin access control for static content, ALB or VPC origins (private ALB, NLB or EC2 with no public IP) for dynamic content, and cache behaviours by path so each part goes to the right origin.
  • Failover: an origin group retries a secondary origin (for example the DR Region's bucket) when the primary returns chosen status codes or times out. It works only for GET, HEAD and OPTIONS, so writes need Route 53 or application failover.
  • Pricing choices:
    • Price classes leave out the most expensive edge regions. Viewers there are still served, from a cheaper region, with more latency.
    • Flat-rate plans include WAF, DDoS protection and DNS for a fixed monthly price, with no overage charges.
    • The Security Savings Bundle gives up to 30% off for a 1-year commitment.
    • S3 Transfer Acceleration speeds large uploads from distant clients, but it is a charge on top of normal transfer.

A cache key that includes every header or cookie makes nearly every request a miss, and you pay origin load and requests for nothing. Global Accelerator never lowers cost (its premium is added on top of normal transfer); choose it for static IPs, non-HTTP traffic or fast failover, and CloudFront for cheaper delivery of HTTP content.

Private, Regional and AZ-aware traffic

Skill 3.2.2Optimize data transfer costs by using strategies such as private connectivity, Regional traffic patterns, and inter-Availability Zone/inter-Region strategies (for example, by using VPC endpoints, NAT gateways, Availability Zone-aware architectures).

  • Keep AWS service traffic off NAT: a NAT gateway charges $0.045 per GB processed on top of its hourly fee. Gateway endpoints for S3 and DynamoDB are free; interface endpoints ($0.01 per AZ-hour plus $0.01 per GB) for ECR, CloudWatch, STS and others are cheaper than NAT once traffic is meaningful. IPv6 traffic can use a free egress-only internet gateway instead of NAT.
  • NAT placement: one NAT gateway per AZ with each subnet routed to its local gateway avoids cross-AZ charges and survives an AZ failure. A single shared gateway saves about $33 a month per AZ dropped but adds $0.01 per GB each way, which suits only low-volume dev and test.
  • AZ-aware design:
    • Same-AZ traffic over private IPs is free; cross-AZ costs $0.01 per GB each way. So keep chatty tiers in one AZ path (zonal service discovery, AZ-aware routing in the mesh or load balancer) while still deploying across AZs for resilience.
    • Read from replicas in the same AZ.
    • Compare AZ IDs, not AZ names, across accounts. The names map to different physical AZs in each account.
  • Use private IPs: traffic to a public or Elastic IP inside the Region is charged like cross-AZ, even in the same AZ, and every public IPv4 address costs $0.005 per hour.
  • Load balancers: ALB cross-zone traffic is free; NLB and Gateway Load Balancer cross-zone is off by default and charged when turned on.
  • Regional patterns: keep compute in the same Region as its data (S3 to any service in the same Region is free), process data where it lands and move only results, and don't route Regional traffic through another Region's inspection VPC unless policy requires it.
Free S3 gateway endpoint for the private subnets' route tables 
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-0a1b2c3d4e5f60001 \
  --vpc-endpoint-type Gateway \
  --service-name com.amazonaws.us-east-1.s3 \
  --route-table-ids rtb-0a1b2c3d4e5f60001 rtb-0a1b2c3d4e5f60002 rtb-0a1b2c3d4e5f60003

Gateway endpoints can't be used from on premises, through a Transit Gateway or from a peered VPC; those paths need interface endpoints. With both S3 endpoint types and private DNS on, VPC traffic can silently use the paid interface endpoint: enable private DNS only for the inbound Resolver endpoint so VPC traffic stays on the free gateway. Cost Explorer shows cross-AZ traffic as DataTransfer-Regional-Bytes, with one line for each direction.

Cost-aware multi-Region replication

Skill 3.2.3Configure cost-aware, multi-Region data replication (for example, by using Amazon S3 Cross-Region Replication, Amazon DynamoDB global tables).

  • S3 Cross-Region Replication costs inter-Region transfer (priced by the source Region, about $0.02 per GB from us-east-1), PUT requests and storage in the destination, and extra for Replication Time Control. Cut it by:
    • replicating only the prefixes or tags DR really needs;
    • writing replicas to a cheaper storage class (Standard-IA or Glacier Instant Retrieval);
    • not replicating short-lived or easily regenerated data;
    • using Batch Replication only once, for existing objects.
  • DynamoDB global tables: each write is charged again as a replicated write in every replica Region, plus storage in each Region, so cost grows with the number of Regions. Add Regions for latency or recovery needs, not by default; consider Standard-IA table class for large, rarely read replicas; and remember TTL deletes are free on one table but replicated TTL deletes are charged.
  • Aurora Global Database charges replicated write I/O in each secondary Region plus inter-Region transfer, on top of the secondary cluster's instances.
  • Match replication to recovery objectives: backups copied with AWS Backup (cheapest, hours to restore), pilot light with replicated data only, or full active-active (most expensive). Recovery design is covered in Domain 4.
S3 replication rule: only the customer-records prefix, stored as Standard-IA in us-west-2 
{
  "Role": "arn:aws:iam::111111111111:role/s3-replication-dr",
  "Rules": [
    {
      "ID": "dr-customer-records",
      "Priority": 1,
      "Status": "Enabled",
      "Filter": { "Prefix": "customer-records/" },
      "DeleteMarkerReplication": { "Status": "Disabled" },
      "Destination": {
        "Bucket": "arn:aws:s3:::example-customer-data-usw2",
        "StorageClass": "STANDARD_IA"
      }
    }
  ]
}

"Reduce replication cost without losing DR for critical data" points to prefix or tag filters and a cheaper replica storage class. "Global table bill grew after adding a fourth Region" is the replicated write charge per Region. "Strict 15-minute replication SLA" is Replication Time Control, at extra cost.

Network architecture pricing

Skill 3.2.4Design cost-effective network architectures (for example, by using AWS Transit Gateway data processing charges, AWS PrivateLink pricing models).

  • Transit Gateway: $0.05 per attachment-hour plus $0.02 per GB processed, charged by default to the sender's account. It's the simplest hub for many VPCs and on premises, but heavy VPC-to-VPC flows pay the processing fee on every GB. Transit Gateway peering attachments add no processing charge for data entering from the peer.
  • VPC peering has no hourly or processing fee: same-AZ traffic is free, cross-AZ is $0.01 per GB each way, and inter-Region pays normal transfer. Add a direct peering for the few VPC pairs that exchange a lot of data, and keep the TGW for everything else.
  • PrivateLink ($0.01 per endpoint per AZ-hour plus $0.01 per GB, falling at petabyte volumes) exposes one service to many consumers without routing whole networks; consumers pay the endpoint fees. For cross-Region PrivateLink the consumer also pays inter-Region transfer, and the provider pays $0.05 per hour per remote Region.
  • VPC Lattice charges per service-hour, per GB and per request (with a free allowance), and includes cross-AZ transfer in its processing fee.
  • Shared VPCs (RAM subnet sharing) avoid attachments and processing between accounts in the same VPC, and centralize NAT and endpoints so each is paid once.
  • Who pays: Transit Gateway metering policies can charge data processing to the source, the destination or the TGW owner (not attachment hours), so a central network team can show each business unit its own cost.
  • Hybrid: Direct Connect transfer out is cheaper per GB than internet egress, so heavy on-premises flows usually justify it; flat-rate billing for dedicated connections makes cost predictable. Centralized interface endpoints in a shared-services VPC, reached through the TGW, trade per-VPC endpoint hours for TGW processing.

A centralized inspection or egress VPC behind a Transit Gateway pays TGW processing (and often cross-AZ) on every GB in both directions; that may be worth it for security, but count it. Interface endpoints are billed per AZ per hour even when idle, and Trusted Advisor flags idle NAT gateways and endpoints.

Data transfer for AI workloads

Skill 3.2.5Optimize data transfer costs for AI/ML workloads by using strategies such as cross-Region inference routing.

  • Cross-Region inference spreads Bedrock requests across Regions in a geography (or globally) for capacity, billed at the source Region's price with no routing fee; global profiles cost about 10% less than geographic ones. It's usually cheaper than buying provisioned capacity for peaks, within the residency limits in Task 2.4.
  • Keep the RAG pipeline in one Region: source documents in S3, the knowledge base, the vector store and the model calls in the same Region avoid inter-Region transfer on every ingestion and query. Replicate the source data or embeddings to a second Region only if DR needs it.
  • Training data next to compute: run SageMaker training in the Region where the data lives (S3 to SageMaker in the same Region is free), use FSx for Lustre linked to S3 for repeated epochs, and keep checkpoints in the same Region.
  • Batch and summarize at the source: Bedrock batch jobs read and write S3 in the source Region; aggregate or summarize where data is produced and move only results, not raw logs or media.
  • Private access: interface endpoints for Bedrock and SageMaker runtime keep traffic off NAT gateways, which charge per GB.

"Throttling at peak, lowest cost, data may be processed elsewhere in the US" points to a us. cross-Region inference profile, not Provisioned Throughput. "Knowledge base in us-east-1 but documents in eu-west-1" is paying inter-Region transfer on every sync; move one to the other's Region if residency allows.

Key takeaways

  • Edge: CloudFront for cheaper egress and fewer origin requests, small cache keys, Origin Shield for spread-out viewers and costly origins, origin groups for read failover, price classes or flat-rate plans for predictable bills.
  • Private and AZ-aware: gateway endpoints are free, interface endpoints beat NAT at volume, one NAT per AZ, same-AZ private-IP paths, no public or Elastic IP hops inside a Region.
  • Replication: filter what you replicate, cheaper replica storage classes, fewer global table Regions, recovery tier matched to objectives.
  • Network design: TGW for many-to-many with $0.02 per GB, direct peering for heavy pairs, PrivateLink for service exposure, shared VPCs, metering policies for chargeback.
  • AI: cross-Region inference at source-Region prices for peaks, RAG and training data in the same Region as the model or compute, move results not raw data.
