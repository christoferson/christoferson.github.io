Overview

The SAP-C03 guide (effective 17 November 2026) lists in-scope services in fourteen categories. The list is non-exhaustive and lists parent services, so features such as Bedrock Guardrails, AgentCore, Application Signals or IAM Identity Center count with their parent. Compared with SAP-C02 it adds 20 services, among them Bedrock, MemoryDB, Security Lake, Verified Permissions, VPC Lattice, Application Auto Scaling, the CDK, Clean Rooms, Cloud WAN, CodeCommit, Cost Categories, Data Transfer Terminal, the Distro for OpenTelemetry, Fault Injection Service, Local Zones, Resilience Hub, AWS Transform, Verified Access and Reserved Instances. It drops IoT, end-user computing, media services, the individual AI services (now under Bedrock and SageMaker AI), and services such as Batch, App Runner, Proton, Service Catalog and Wavelength.

Each entry says what the service is for on this exam and links to the task sections that explain it. Background means the notes don't cover it in depth: know in one sentence what it does. The cheat sheet maps question clues to answers, and the comparisons page sets similar options side by side.

Analytics

  • Amazon AppFlow: managed flows from SaaS applications into S3, Redshift and other targets. 1.5
  • Amazon Athena: serverless SQL over S3 and the lake; also how logs, CUR data and audit evidence are queried. 1.1, 1.5, 3.3
  • Amazon EMR: Spark and Hadoop on EC2, on EKS or serverless, chosen by utilization. 1.5
  • Amazon Kinesis Data Streams: ordered, replayable streams for real-time pipelines. 1.1, 1.5, 5.3
  • Amazon MSK: managed Kafka, including Express brokers, Serverless, Connect and Replicator. 1.5
  • Amazon OpenSearch Service: search, log analytics and a vector store for RAG. 1.2, 1.5
  • Amazon QuickSight: business intelligence dashboards, now Quick Sight within Amazon Quick; used for cost dashboards. 3.3
  • Amazon Redshift: the data warehouse, Spectrum over the lake, Iceberg writes, data sharing across accounts. 1.5, 1.5
  • AWS Clean Rooms: analysis of combined data with a partner without either side seeing the other's records. 1.5
  • AWS Glue: serverless ETL and the Data Catalog behind the lakehouse. 1.1, 1.5, 1.5
  • AWS Lake Formation: fine-grained lake permissions, LF-Tags and cross-account sharing; authorizes users through trusted identity propagation. 1.5, 1.5, 2.1

Application integration

  • Amazon EventBridge: event routing across accounts and Regions, Pipes and Scheduler, and the trigger for operational automation. 1.1, 1.1, 5.4, 5.4
  • Amazon MQ: managed ActiveMQ or RabbitMQ for applications that keep their broker protocol. 1.3, 4.1
  • Amazon SNS: fan-out and notifications; alarm and Health event delivery. 1.1, 5.3
  • Amazon SQS: queues for decoupling and buffering; FIFO ordering, dead-letter queues, Lambda triggers. 1.1, 5.4
  • AWS Step Functions: durable workflows, human approvals, Standard or Express by cost, retries and catch. 1.1, 2.5, 3.1, 5.4

Cloud financial management

  • AWS Budgets: cost, usage and commitment budgets with alerts and actions. 3.3
  • AWS Cost and Usage Report: line-item billing data, now CUR 2.0 in AWS Data Exports, with split cost allocation data. 3.3, 3.3
  • AWS Cost Categories: rules that map costs to business units, with split charges for shared costs. 3.3
  • AWS Cost Explorer: analysis, forecasts and Savings Plans recommendations. 3.3, 3.1
  • Reserved Instances: commitments for EC2 (zonal ones also reserve capacity) and reserved nodes and instances for databases. 3.1, 3.4
  • Savings Plans: Compute, EC2 Instance, Database and SageMaker AI plans, shared across the organization. 3.1, 3.4

Compute

  • Amazon EC2: purchase options, Graviton, Spot, capacity reservations, Auto Scaling health and refresh. 3.1, 3.1, 5.4
  • AWS Application Auto Scaling: scaling for ECS, DynamoDB, Aurora replicas, Lambda provisioned concurrency and more. 1.1, 5.4
  • AWS Elastic Beanstalk: a simple replatform target for web applications. 4.1
  • AWS Fargate: serverless containers for ECS and EKS; Fargate Spot for ECS. 1.1, 3.1
  • AWS Lambda: event processing, durable functions, Managed Instances, retries and destinations. 1.1, 1.1, 3.1, 5.4
  • AWS Local Zones: AWS compute near users or in a specific metro, with service limits. 1.3
  • AWS Outposts: AWS racks or servers on premises for latency or data residency. 1.3, 2.4

Containers

  • Amazon ECR: image registry with scanning, lifecycle rules, replication and managed signing. 1.1, 4.2, 5.2
  • Amazon ECS: orchestration on Fargate, EC2 or Managed Instances; Service Connect, native blue/green, Container Insights. 1.1, 1.1, 4.2, 5.3
  • Amazon EKS: managed Kubernetes; Auto Mode, Hybrid Nodes, Pod Identity, AWS Backup support, zonal shift. 1.1, 1.3, 2.1, 4.2

Database

  • Amazon Aurora: Global Database, Limitless, DSQL, Serverless v2 auto-pause, I/O-Optimized. 1.5, 1.5, 3.4
  • Amazon DocumentDB: MongoDB-compatible documents, with global clusters. 1.5, 1.5
  • Amazon DynamoDB: key-value at any scale; global tables with eventual or strong multi-Region consistency, capacity modes, Standard-IA. 1.5, 1.5, 3.4
  • Amazon ElastiCache: Valkey, Redis OSS or Memcached caching, node-based or serverless; semantic caches for GenAI. 1.5, 3.1
  • Amazon Keyspaces: Cassandra-compatible wide-column tables. 1.5
  • Amazon MemoryDB: durable in-memory database, with Multi-Region. 1.5
  • Amazon Neptune: graph database, including GraphRAG with Neptune Analytics. 1.5, 1.2
  • Amazon RDS: managed engines, Multi-AZ instances and clusters, RIs, RDS-managed master secrets. 1.5, 1.5, 5.1
  • Amazon Timestream: time series; LiveAnalytics is closed to new customers, so use Timestream for InfluxDB. 1.5

Developer tools

  • AWS CDK: infrastructure in code that synthesizes to CloudFormation; Aspects, validation plugins, Pipelines, refactor, drift. 5.1, 5.1
  • AWS CloudFormation: declarative stacks, Hooks, drift-aware change sets, StackSets, dynamic references. 5.1, 5.1, 5.1
  • AWS CodeBuild: managed builds, reserved fleets, Lambda compute, self-hosted runners. 5.2
  • AWS CodeCommit: managed Git, back to general availability since November 2025. 5.2
  • AWS CodeDeploy: in-place and blue/green deployments to EC2, Lambda and ECS, with alarm rollback. 5.2, 5.2
  • AWS CodePipeline: V2 pipelines with triggers, stage conditions and rollback; cross-account and cross-Region actions. 5.2, 5.2
  • AWS Distro for OpenTelemetry: the instrumentation standard for metrics, logs and traces. 5.3
  • AWS X-Ray: distributed traces, now fed by OpenTelemetry (the X-Ray SDKs are in maintenance mode). 5.3

Machine learning and AI

  • Amazon Bedrock: models through one API, inference profiles and service tiers, Knowledge Bases, Guardrails, Evaluations, invocation logging, and AgentCore for agents. 1.2, 1.2, 1.2, 2.5, 3.1, 5.2
  • Amazon SageMaker AI: real-time, serverless, asynchronous and batch inference, inference components, managed Spot training. 1.2, 3.1, 5.3

Management and governance

  • Amazon CloudWatch: metrics, logs, alarms, Application Signals, Synthetics, RUM, investigations and log cost controls. 5.3, 5.3, 5.3, 3.4
  • AWS CloudTrail: organization trails, data events, log file validation. 2.3, 2.4
  • AWS Compute Optimizer: rightsizing and idle-resource recommendations for compute, storage and databases. 3.1, 3.4
  • AWS Config: rules, conformance packs, aggregators, remediation, drift checks. 2.3, 5.1
  • AWS Control Tower: landing zone, controls (including data residency controls), Account Factory. 2.3, 2.4
  • AWS Organizations: OUs, SCPs, RCPs, delegated administrators, and service policies (backup, tag, Inspector, Bedrock). 2.3, 2.3
  • AWS Resilience Hub: resiliency policies, assessments, SOPs and resilience tests. 4.2, 4.2
  • AWS RAM: sharing subnets, Transit Gateways and other resources across accounts. 2.3
  • Service Quotas: quota alarms, automatic management and request templates for new accounts. 5.4
  • AWS Systems Manager: Automation runbooks with rate control, Patch Manager, State Manager, OpsCenter, Change Calendar. 2.3, 5.4, 5.4

Migration and transfer

  • AWS Transform MGN: rehosting by agent-based block replication, test and cutover. 4.1
  • AWS Data Transfer Terminal: bring your own storage to an AWS facility for large one-off uploads. 4.1
  • AWS DMS: full load and change data capture, Serverless, Schema Conversion. 4.1
  • AWS DataSync: scheduled and verified file transfer to S3, EFS and FSx. 1.3, 4.1
  • AWS SCT: desktop schema conversion, still used for data warehouses and ETL code. 4.1
  • AWS Storage Gateway: S3 File, Volume and Tape Gateways for hybrid storage. 1.3
  • AWS Transfer Family: managed SFTP, FTPS, FTP and AS2 into S3 and EFS. 1.3, 4.1
  • AWS Transform: agentic discovery, business cases, wave planning, VMware migration, and modernization of mainframes, .NET and SQL Server. 4.1, 4.1

Networking and content delivery

  • Amazon API Gateway: REST, HTTP and WebSocket APIs; throttling, canaries, legacy integration. 1.1, 1.1, 1.3
  • Amazon CloudFront: edge delivery, Origin Shield, origin failover, multi-tenant distributions, flat-rate plans. 1.1, 3.2
  • Amazon Route 53: routing policies, hybrid DNS with Resolver, health checks for failover. 1.3, 1.4, 4.2
  • Amazon VPC: subnets, IPAM, IPv6, endpoints, shared VPCs. 1.4, 1.4, 1.4
  • Amazon VPC Lattice: service-to-service networking and resource access across VPCs and accounts. 1.1, 1.4
  • AWS Cloud WAN: managed global WAN with segments and policies. 1.4, 1.3
  • AWS Direct Connect: resilient private connectivity, gateways, MACsec, flat-rate billing. 1.3
  • AWS Global Accelerator: anycast IPs with fast Regional failover and traffic dials. 1.4, 4.2
  • AWS Network Firewall: centralized and distributed inspection, native Transit Gateway attachment. 1.4
  • AWS PrivateLink: private access to services, including cross-Region endpoint services. 1.4, 3.2
  • AWS Transit Gateway: hub for many VPCs and on premises; route-table segmentation and metering policies. 1.4, 3.2
  • AWS VPN: Site-to-Site VPN as backup or overlay for Direct Connect, and Client VPN. 1.3
  • Elastic Load Balancing: ALB, NLB and Gateway Load Balancer ingress patterns, health checks and post-quantum TLS policies. 1.1, 2.2

Security, identity and compliance

  • Amazon Cognito: user pools and identity pools, M2M scopes, multi-tenant patterns. 2.1, 1.1
  • Amazon GuardDuty: threat detection, including AI Protection and Bedrock logging alerts. 2.3
  • Amazon Inspector: vulnerability scanning of EC2, ECR, Lambda and code, in pipelines and continuously. 2.3, 5.2
  • Amazon Security Lake: security data in OCSF format in S3 for analytics and SIEMs. 2.3
  • Amazon Verified Permissions: fine-grained application authorization with Cedar policies. Background.
  • AWS Certificate Manager: public and private certificates with managed renewal. 2.2
  • AWS CloudHSM: single-tenant HSMs and CloudHSM key stores for KMS. 2.2
  • AWS Directory Service: managed Microsoft AD and AD Connector, for example as an identity source. Background.
  • IAM: roles, policies, boundaries, ABAC, data perimeter keys, Roles Anywhere, Access Analyzer. 2.1, 2.1, 2.1
  • AWS KMS: customer managed keys, rotation, cross-account keys, ML-DSA and ML-KEM. 2.2, 2.2
  • AWS Secrets Manager: secrets with rotation, referenced from templates. 5.1
  • AWS Security Hub: posture checks (Security Hub CSPM) and the newer Security Hub that correlates findings. 2.3, 2.3
  • AWS Shield: DDoS protection at the edge. 1.1
  • AWS Verified Access: VPN-less access to private applications, including TCP. 2.1
  • AWS WAF: web application firewall at CloudFront, ALB and API Gateway. 1.1, 1.4

Storage

  • Amazon Data Lifecycle Manager: automated EBS snapshot and AMI policies with retention. 3.4
  • Amazon EBS: gp3, io2, snapshots, snapshot archive and Snapshot Lock. 3.4, 4.3
  • Amazon EFS: shared Linux file storage with lifecycle tiers. 1.5, 3.4
  • Amazon FSx: Windows File Server, NetApp ONTAP, OpenZFS and Lustre by protocol and workload. 1.5
  • Amazon S3: storage classes, lifecycle, replication, Object Lock, S3 Tables and Vectors. 1.5, 3.4, 4.3
  • AWS Backup: organization backup policies, Vault Lock, logically air-gapped vaults, restore testing, EKS backups. 4.3, 4.3, 3.4
  • AWS Elastic Disaster Recovery: continuous block-level replication for server recovery, drills and failback. 4.2

Testing and resilience

  • AWS Fault Injection Service: experiment templates with stop conditions, scenario library, safety lever and reports. 4.3, 4.3, 4.2

Named in skills, not on the list

The skills name a few services and features that the in-scope list doesn't, mostly because they belong to a listed parent:

  • Amazon Application Recovery Controller (ARC): zonal shift, routing controls and Region switch plans. 4.2
  • Amazon Bedrock AgentCore: runtime, gateway, identity, policy and observability for agents. 1.2, 2.5
  • IAM Identity Center and IAM Roles Anywhere: workforce federation and workload identity outside AWS. 2.1, 2.1
  • AWS Artifact: AWS compliance reports and agreements. 2.4
  • CloudWatch Application Signals, Synthetics and RUM: SLOs and user-experience monitoring. 5.3, 5.3
  • AWS Private CA and AWS Signer: private certificates and artifact signing. 2.2, 5.2

Renamed services

Old names still appear in questions, blog posts and the guide itself. Same service, new name:

  • AWS Application Migration Service is now AWS Transform MGN (same aws mgn APIs).
  • AWS Blu Age refactoring is now AWS Transform for mainframe.
  • AWS Chatbot is now Amazon Q Developer in chat applications.
  • AWS CodeStar Connections is now AWS CodeConnections.
  • AWS Security Hub (the posture checks) is now AWS Security Hub CSPM; the name Security Hub belongs to the newer service that correlates findings.
  • AWS Fault Injection Simulator is now AWS Fault Injection Service.
  • Amazon QuickSight is now Amazon Quick Sight, part of Amazon Quick.
  • Amazon Bedrock Agents is now Agents Classic.
  • Lambda functions are now Lambda Event Functions, alongside Lambda Web Functions.
  • The CloudWatch Logs Infrequent Access log class is now Essentials.
  • The Secrets Manager Agent is now the AWS Workload Credentials Provider.
  • Amazon Q Developer in the console is now the AWS assistant.
  • Route 53 Resolver appears as Route 53 VPC Resolver in parts of the documentation.

Out of scope

The guide lists these as out of scope, verbatim. The list isn't exhaustive, and services entirely unrelated to the job role aren't listed.

  • Blockchain: Amazon Managed Blockchain (AMB)
  • Compute: Amazon Lightsail
  • Databases: Amazon RDS Custom for Oracle
  • Frontend Web and Mobile Services: AWS Device Farm
  • Game Tech: Amazon GameLift
  • Machine Learning and Artificial Intelligence: Amazon Comprehend Medical, Amazon Transcribe Medical, AWS DeepComposer, AWS DeepRacer
  • Media: Amazon Interactive Video Service (Amazon IVS), AWS Elemental MediaConvert, AWS Elemental MediaLive
  • Quantum Technologies: Amazon Braket
  • Satellite: AWS Ground Station

Also no longer on the in-scope list (compared with SAP-C02): all IoT services, AppStream 2.0, WorkSpaces, Elastic Transcoder, Kinesis Video Streams, the individual AI services (Comprehend, Lex, Polly, Rekognition, Textract, Transcribe, Translate, Kendra, Personalize, Fraud Detector), CodeGuru, Pinpoint, SES, Amplify, App Runner, Batch, CodeArtifact, Data Exchange, Health Dashboard, License Manager, Proton, Service Catalog and Wavelength.

Out of scope isn't never seen. Some of these still appear in the task pages as context or wrong answers, for example App Runner (closed to new customers) and AWS Health events (used for operational automation). Know them well enough to rule them out.
