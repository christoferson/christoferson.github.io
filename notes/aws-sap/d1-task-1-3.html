Task 1.3: Design hybrid cloud integration patterns

Joining the data centre and AWS into one system: connectivity that survives a failed circuit or location, keeping data in step between the two, wrapping legacy systems in modern interfaces, one DNS namespace across both, and running AWS compute in your own facilities or close to your users.

Overview

Task 1.3

Design hybrid cloud integration patterns.

Hybrid questions give a data centre that isn't going away soon and requirements for availability, bandwidth, latency, data residency or a migration in progress, and ask how to join the two. Answers turn on details: how many Direct Connect locations, which way DNS queries flow, whether sync must be continuous, whether a site can lose its connection to the Region. The Advanced Networking notes go deeper on Direct Connect, VPN and Transit Gateway; this page focuses on the design choices.

Running example. The company still runs a data centre with VMware servers, an Oracle database, an NFS file share and a message broker used by its warehouse system. It connects to us-east-1 and us-west-2, uses corp.example.com internally, must keep a nightly copy of files in S3, and has two warehouses whose sorting systems need local compute.

Status changes to know. Amazon FSx File Gateway has been closed to new customers since 28 October 2024 (use FSx for Windows File Server directly). The AWS Snow Family is closed to new customers (use DataSync, partners or Outposts for edge compute). ECS Anywhere dropped Windows and several older Linux versions on 7 August 2026 (Amazon Linux 2023, Ubuntu 20 to 24 and RHEL 9 remain). New: EKS Hybrid Nodes (December 2024), second-generation Outposts racks (April 2025), Route 53 Profiles (April 2024), Cloud WAN's native Direct Connect attachment (November 2024), and Direct Connect flat-rate billing (September 2026). Route 53 Resolver is now called Route 53 VPC Resolver in parts of the documentation.

Resilient hybrid connectivity

Skill 1.3.1Design hybrid connectivity that provides redundancy and failover capabilities (for example, by using AWS Direct Connect, AWS VPN, AWS Transit Gateway).

Direct Connect resiliency models (from the Resiliency Toolkit):

  • Maximum resiliency: two locations, two connections at each on separate devices: 99.99% SLA, for critical workloads.
  • High resiliency: one connection at each of two locations: 99.9%.
  • Development and test: two connections at one location, no protection from losing the location.

Prove failover with the Direct Connect failover test, which takes your BGP sessions down for a chosen time. Then the routing details:

  • Virtual interfaces: a transit VIF to a Direct Connect gateway associated with Transit Gateways (many VPCs, many Regions), a private VIF to a virtual private gateway or Direct Connect gateway, a public VIF for AWS public endpoints. Direct Connect gateways connect VPCs in any Region (not China); SiteLink sends traffic between your own Direct Connect locations over AWS's backbone.
  • Steering traffic: AWS chooses routes to you by longest prefix, then local preference (set with BGP communities 7224:7100 low, 7224:7200 medium, 7224:7300 high), then AS path length, then MED. Advertise more specific prefixes on the preferred path, or prepend AS paths on the backup.
  • Fast failover: turn on BFD on your routers (AWS enables it on its side, but it does nothing until you do; minimum 300 ms × 3), rather than waiting for the 90-second BGP hold timer.
  • Encryption: MACsec on dedicated 10 Gbps and faster connections, or a Site-to-Site VPN over the Direct Connect link (private IP VPN, through a Transit Gateway).

Site-to-Site VPN as primary or backup:

  • Two tunnels per connection in different Availability Zones. Accelerated VPN uses Global Accelerator's network for better internet performance.
  • To a Transit Gateway, ECMP spreads traffic across several VPN connections to add bandwidth (not possible with a virtual private gateway).
  • Direct Connect primary, VPN backup: AWS prefers Direct Connect routes over VPN routes for the same prefix, so the VPN carries traffic only when Direct Connect fails.

Transit Gateway is the hub: route tables per segment (production, development, shared services, inspection), VPC, VPN, Direct Connect gateway and peering attachments, Transit Gateway Connect for SD-WAN appliances (GRE and BGP), and appliance mode for symmetric routing through firewalls. AWS Cloud WAN manages a global network of segments from one policy, including Direct Connect attachments, when there are many Regions and sites (Task 1.4).

Two connections in one Direct Connect location aren't highly available against a location failure; "the highest availability" means two locations with two connections each. On a Direct Connect gateway associated with a Transit Gateway, the allowed prefixes you enter are exactly what's advertised to your network (with a virtual private gateway they act as a filter).

Data synchronization

Skill 1.3.2Design data synchronization strategies for hybrid workloads (for example, by using AWS DataSync, AWS Storage Gateway, AWS Transfer Family).

  • AWS DataSync: scheduled or one-time bulk copies between NFS, SMB, HDFS or object storage and S3, EFS or FSx (and between clouds), with verification, filters, bandwidth limits and task reports, over the internet, Direct Connect or a VPC endpoint. An agent runs on premises (none is needed for S3 to other clouds); several agents add speed, not availability. Enhanced mode handles very large numbers of objects between S3 locations. Schedules run at most hourly.
  • AWS Storage Gateway for ongoing hybrid access:
    • S3 File Gateway: NFS or SMB shares on premises backed by S3 objects, with a local cache. Writes made directly to S3 aren't seen until the cache is refreshed (RefreshCache, or a cache expiry), and several writers to one bucket give unpredictable results, so use one writer per bucket or prefix.
    • Volume Gateway: iSCSI block volumes, either cached (data in AWS, hot data local) or stored (all data local, snapshots to AWS).
    • Tape Gateway: virtual tapes for existing backup software, archived to S3 Glacier classes.
  • AWS Transfer Family: managed SFTP, FTPS, FTP and AS2 endpoints over S3 or EFS for partners and legacy systems that exchange files, with your own identity provider, managed workflows after upload, connectors to push files to remote servers, and browser-based web apps. FTP and FTPS need a VPC endpoint.
Copy the NFS share to S3 every night at 01:00 UTC, verifying what was transferred (AWS CLI) 
aws datasync create-task \
    --name nightly-share-to-s3 \
    --source-location-arn arn:aws:datasync:us-east-1:111111111111:location/loc-0a1b2c3d4e5f60001 \
    --destination-location-arn arn:aws:datasync:us-east-1:111111111111:location/loc-0a1b2c3d4e5f60002 \
    --options VerifyMode=ONLY_FILES_TRANSFERRED,TransferMode=CHANGED,PreserveDeletedFiles=PRESERVE \
    --schedule '{"ScheduleExpression":"cron(0 1 * * ? *)"}' \
    --cloud-watch-log-group-arn arn:aws:logs:us-east-1:111111111111:log-group:/datasync/nightly

"Move 500 TB once, then keep it in sync until cutover" points to DataSync. "On-premises applications keep using a file share, but the data should live in S3" points to S3 File Gateway. "Partners upload files over SFTP" points to Transfer Family. "Back up to tape without changing the backup software" points to Tape Gateway.

Modernizing legacy integration

Skill 1.3.3Design integration patterns to modernize legacy systems by using data transformations (for example, by using API Gateway, Lambda, Amazon MQ).

  • Amazon MQ runs ActiveMQ or RabbitMQ brokers, so applications using JMS, AMQP, MQTT or STOMP move without code changes (active/standby across zones, or a cluster for RabbitMQ). A network of brokers with a duplex connection bridges an on-premises broker during a phased migration. For new cloud-native messaging, SQS and SNS are simpler and scale further.
  • API Gateway as a facade: expose a modern REST API in front of a legacy system, translating formats with mapping templates (VTL) or, as AWS now recommends for complex cases, a Lambda proxy integration. Private integrations reach systems over Direct Connect through an NLB or ALB.
  • Lambda for transformation logic between formats (XML to JSON, fixed-width files to records).
  • EventBridge Pipes connect a source (SQS, Kinesis, DynamoDB Streams, MQ, MSK) to a target with filtering, enrichment (Lambda, Step Functions Express, API Gateway or an API destination) and input transformation, without glue code.
  • Patterns: the strangler fig (route one feature at a time to new services behind the facade until the legacy system can be retired) and the anti-corruption layer (translation between the old system's model and the new one so legacy concepts don't leak in).
Reshape the legacy order response before returning it to the mobile API (Velocity, API Gateway integration response mapping template) 
#set($o = $input.path('$.ORDER_REC'))
{
  "orderId": "$o.ORD_NO",
  "status": "$o.STAT_CD",
  "total": $o.TOT_AMT
}

With passthroughBehavior set to WHEN_NO_TEMPLATES or NEVER, a request whose content type has no matching template gets HTTP 415. Pipes enrichment can call only Express Step Functions workflows, and an empty enrichment response drops the event.

Hybrid DNS

Skill 1.3.4Design DNS solutions for hybrid environments (for example, by using Amazon Route 53 Resolver endpoints, Route 53 private hosted zones, split-horizon DNS, conditional forwarding).

  • On premises resolving AWS names: an inbound Resolver endpoint (IP addresses in your VPC) that on-premises DNS servers forward the AWS zones to.
  • AWS resolving on-premises names: an outbound Resolver endpoint plus forwarding rules (conditional forwarding for corp.example.com to on-premises DNS servers).
  • Centralise in the shared networking account: create the endpoints once and share the rules through AWS RAM (which shares the outbound endpoint too); other accounts associate the rules with their VPCs but can't change them. Route 53 Profiles bundle private hosted zones, Resolver rules, DNS Firewall rules and interface endpoints, and apply them to many VPCs and accounts at once (up to 2 Profiles per VPC, by priority).
  • Private hosted zones across accounts: the zone owner authorizes the other account's VPC (create-vpc-association-authorization), the VPC owner associates it (associate-vpc-with-hosted-zone), then the authorization is removed. CLI or API only.
  • Split-horizon: a public and a private hosted zone with the same name give different answers inside and outside the VPC. If the private zone has no record for a name, the query returns NXDOMAIN; it doesn't fall back to the public zone.
  • Capacity: each endpoint IP handles up to 10,000 queries per second (less behind connection tracking or an NLB); add IPs (in two or more Availability Zones) before adding endpoints. DNS Firewall and query logging add security and audit.
Forward corp.example.com from AWS to the data centre's DNS servers (AWS CLI, shared networking account) 
aws route53resolver create-resolver-rule --name corp-forward \
    --creator-request-id 2026-11-12-corp \
    --rule-type FORWARD --domain-name corp.example.com \
    --resolver-endpoint-id rslvr-out-0a1b2c3d4e5f60001 \
    --target-ips "Ip=192.168.10.53" "Ip=192.168.20.53"

# Share it with the organization; each account then associates it with its VPCs
aws ram create-resource-share --name corp-dns-rules \
    --resource-arns arn:aws:route53resolver:us-east-1:111111111111:resolver-rule/rslvr-rr-0a1b2c3d4e5f60002 \
    --principals arn:aws:organizations::111111111111:organization/o-a1b2c3d4e5

A forwarding rule wins over a private hosted zone for the same domain, so a rule for example.com can hide a private zone for aws.example.com unless a more specific rule (or SYSTEM rule) covers it. Resolver endpoints can't be placed in a subnet shared from another account.

Hybrid compute

Skill 1.3.5Design hybrid compute patterns (for example, by using Amazon EKS Anywhere, Amazon ECS Anywhere, AWS Outposts, AWS Local Zones).

  • ECS Anywhere: your own servers (registered through Systems Manager) run ECS tasks with the EXTERNAL launch type, managed from the Region; billed per instance-hour. No load balancer integration or awsvpc networking, and it needs a connection to the Region.
  • EKS Hybrid Nodes: on-premises servers join an EKS cluster whose control plane runs in AWS (billed per vCPU-hour). It needs a reliable connection (AWS recommends at least 100 Mbps and under 200 ms round trip) and non-overlapping private node and pod CIDRs; not for disconnected sites.
  • EKS Anywhere: the whole Kubernetes cluster runs on your hardware and keeps working without a connection to AWS; support and curated packages need an enterprise subscription (about $24,000 per cluster per year on a one-year term).
  • AWS Outposts: AWS-owned hardware in your facility, managed by AWS, running EC2, EBS, ECS, EKS, RDS, S3 and more, for low latency to on-premises systems and data residency. Racks (second generation from April 2025) or 1U and 2U servers (servers run only EC2 and ECS). An Outpost needs its connection to the parent Region to be managed.
  • Local Zones: AWS infrastructure in a metro area, attached to a parent Region, for single-digit millisecond latency to local users (Dedicated Local Zones for sovereignty). They lack VPC endpoints and Site-to-Site VPN; Direct Connect reaches them directly, while Transit Gateway traffic goes through the parent Region.
An EKS cluster that accepts on-premises nodes from the warehouse network (AWS CLI) 
aws eks create-cluster --name warehouse-sorting \
    --role-arn arn:aws:iam::111111111111:role/EKSClusterRole \
    --resources-vpc-config subnetIds=subnet-0a1b2c3d4e5f60001,subnet-0a1b2c3d4e5f60002,endpointPrivateAccess=true,endpointPublicAccess=false \
    --access-config authenticationMode=API_AND_CONFIG_MAP \
    --remote-network-config '{"remoteNodeNetworks":[{"cidrs":["10.200.0.0/16"]}],"remotePodNetworks":[{"cidrs":["10.201.0.0/16"]}]}'
# On each warehouse server: nodeadm install, then nodeadm init with a NodeConfig using SSM hybrid activation

"Must keep running if the link to AWS fails" points to EKS Anywhere (or Outposts for workloads that tolerate a management outage). "Use existing servers, manage from AWS" points to ECS Anywhere or EKS Hybrid Nodes. "AWS services on premises for data residency" points to Outposts. "Low latency for users in a city with no Region" points to Local Zones.

Key takeaways

  • Connectivity: maximum resiliency is two Direct Connect locations with two connections each (99.99%); BFD for fast failover; local preference communities and longer prefixes to steer; VPN as backup or ECMP-aggregated over Transit Gateway.
  • Data sync: DataSync for scheduled bulk copies (hourly at most), S3 File Gateway for ongoing file access backed by S3 (one writer per bucket), Volume and Tape Gateway for block and tape, Transfer Family for SFTP, FTPS and AS2 partners.
  • Legacy: Amazon MQ to move broker-based apps unchanged, API Gateway facades with mapping templates or Lambda, EventBridge Pipes for source-to-target transformation, strangler fig and anti-corruption layer patterns.
  • DNS: inbound endpoints for on-premises to AWS, outbound endpoints and forwarding rules for AWS to on-premises, rules shared from a networking account or Route 53 Profiles, cross-account private zone association by authorization.
  • Compute: ECS Anywhere and EKS Hybrid Nodes need the Region; EKS Anywhere runs disconnected; Outposts brings AWS services on premises; Local Zones bring the Region closer to users.
