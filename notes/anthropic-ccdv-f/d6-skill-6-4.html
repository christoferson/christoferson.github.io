6.4: Grounding and Source Citation

Answers that come only from your documents, point to the passage they rest on, and admit when the documents don't say, plus the decision whether to hand Claude the whole library or just the pages that matter.

Overview

Skill 6.4

Grounding and Source Citation: "Constructing a request that grounds answers in the supplied documents, cites their source, and returns 'not found' when the documents do not contain the answer. This includes deciding, based on corpus size, cost, and freshness, whether to supply the full document set in context or retrieve only the relevant passages."

Exam items give a question-answering feature that invents policy, can't say where an answer came from, or costs too much. The fix is in how the request is built. Keeping claims attributed across several agents is covered in the architect notes (provenance in synthesis), and recognising a hallucination in a trace is skill 4.2.

Supply the documents, restrict to them, allow "not found", and require citations

Skill 6.4Four parts, each closing one gap.

  • The documents in the request, clearly separated from the question. Long material goes before the question.
  • An instruction to use only them: no general knowledge, and no guessing.
  • An explicit way out: a fixed reply such as NOT_FOUND when the answer isn't there. Claude's guidance on reducing hallucinations starts with exactly this: give permission to say you don't know.
  • Citations, so every claim can be traced to a passage and checked.

Send a small corpus as cached documents, or retrieved passages as search results

Skill 6.4Whole corpus as documents, or retrieved passages as search results.

Take a help assistant that answers customers from the returns, delivery and warranty policies. A customer was told the seller price-matches competitors, which no policy says.

grounded_answer.py (Python, anthropic SDK) 
"""Answer only from the shop's policy documents, cite them, and say NOT_FOUND when they don't contain the answer.
Small, stable corpus: send it all, cached. Large or fast-changing corpus: retrieve passages and send search results."""
import anthropic

client = anthropic.Anthropic()

SYSTEM = """Answer the customer's question using only the provided documents.
If the documents don't contain the answer, reply with exactly NOT_FOUND and nothing else. Don't use general knowledge,
and don't guess: a wrong policy answer costs more than no answer."""


def choose_mode(corpus_tokens: int, changes_per_day: int, budget_tokens: int = 200_000) -> str:
    if corpus_tokens <= budget_tokens and changes_per_day == 0:
        return "full"          # fits comfortably and rarely changes: send everything, cache the prefix
    return "retrieve"          # too big, too costly per question, or too fresh to cache: send the top passages


def full_corpus(docs: list[dict]) -> list[dict]:
    blocks = [{"type": "document", "source": {"type": "text", "media_type": "text/plain", "data": d["text"]},
               "title": d["title"], "context": f"updated {d['updated']}", "citations": {"enabled": True}} for d in docs]
    blocks[-1]["cache_control"] = {"type": "ephemeral"}       # every later question reuses the cached documents
    return blocks


def retrieved(passages: list[dict]) -> list[dict]:
    return [{"type": "search_result", "source": p["url"], "title": p["title"],
             "content": [{"type": "text", "text": p["text"]}], "citations": {"enabled": True}} for p in passages]


def answer(question: str, mode: str, docs=None, search=None) -> dict:
    sources = full_corpus(docs) if mode == "full" else retrieved(search(question, k=5))
    msg = client.messages.create(model="claude-sonnet-5-5", max_tokens=1500, system=SYSTEM,
                                 messages=[{"role": "user", "content": sources + [{"type": "text", "text": question}]}])
    text = "".join(b.text for b in msg.content if b.type == "text").strip()
    cites = [(c.title if c.type == "search_result_location" else c.document_title, c.cited_text)
             for b in msg.content if b.type == "text" for c in (b.citations or [])]
    if text == "NOT_FOUND":
        return {"found": False}
    if not cites:                 # an answer with no supporting passage isn't grounded: don't show it as policy
        return {"found": False, "reason": "uncited answer withheld", "draft": text}
    return {"found": True, "answer": text, "citations": cites}
  • Full mode sends every policy as a document block with citations enabled. Its date goes in context, which Claude sees but never cites, and cache_control sits on the last document so later questions reuse the cached prefix.
  • Retrieve mode sends the top passages from your search as search_result blocks. Each has a source, a title and its text, with citations enabled.
  • The same system prompt restricts both modes to the documents and defines NOT_FOUND. The parsing is shared too: NOT_FOUND becomes found: False, and so does an answer with no citations at all.

Use citations on documents or search results so every claim points to a passage

Skill 6.4Citations from documents and from search results.

  • Documents: with "citations": {"enabled": true}, cited parts of the answer come back as text blocks carrying cited_text and a location. That's a character range for plain text, a page range for PDFs, or a block range for custom content. The API extracts cited_text itself, so it always points into what you sent, and it doesn't count toward output tokens.
  • Chunking: plain text and PDFs are split into sentences, the smallest unit Claude can cite. To control the units, for transcripts or bullet lists, use a custom content document, where each text block you provide is one citable unit.
  • Search results (generally available) are the retrieval-shaped equivalent. Put them directly in the user message, or return them from your own search tool. Citations come back as search_result_location with your source and title, so the answer can link to the page.
  • Search-result rules: citations are off by default, and every search result in a request must have the same setting. A tool result that contains search results may contain only search results.
  • Limit: citations can't be combined with structured outputs (a 400 error). Return prose with citations, then structure it yourself (parsing free-text fallbacks).

Make "not found" an expected, exact reply, and withhold answers without citations

Skill 6.4Making "the documents don't say" an expected answer.

  • Define the reply exactly (NOT_FOUND and nothing else) and say why it's preferred: a wrong policy answer costs more than no answer. Your code can then detect it reliably and route the customer to a person.
  • Check the other way too: an answer with no citations has no supporting passage. The example withholds it rather than presenting it as policy, and keeps the draft for review.
  • For long documents, asking Claude to quote the relevant passages before answering, and to retract any claim it can't support with a quote, further reduces made-up answers.

"Add 'be accurate' to the prompt" doesn't stop invented answers. An explicit permission and format for "not found", a restriction to the supplied documents, and a citation check do.

Choose full corpus or retrieval by size, cost and how often it changes

Skill 6.4Corpus size, cost and freshness decide.

  • Size: current models have a 1M-token window, but accuracy and recall fall as context grows. "It fits" isn't the same as "it works well". A few policies (tens of thousands of tokens) can go in whole; a product catalogue or ticket history can't sensibly.
  • Cost: sending the whole corpus with every question pays for every token every time. Prompt caching cuts that sharply for a stable prefix, since cached reads cost a small fraction of normal input (skill 5.3), but the cache lasts minutes to an hour. Retrieval sends only the top passages, so cost per question stays small however big the corpus grows.
  • Freshness: a corpus that changes often breaks the cached prefix on every change. Retrieval reads the current version of each passage at question time.
  • Quality trade-off: the full corpus can't miss a relevant passage, while retrieval can, if the search returns the wrong passages. Evaluate retrieval recall separately from answer quality.

The example's choose_mode encodes the simple version: send everything, cached, when the corpus is small and stable; otherwise retrieve.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
A help assistant invents a price-match policy. Which request change addresses the cause?
  1. A. Add “be accurate”
  2. B. Restrict answers to the supplied policies, define an exact NOT_FOUND reply, and require citations
  3. C. Use a bigger model
  4. D. Lower temperature
Answer
B
Why
Grounding, an explicit way out and a citation check stop invented answers.
Question 2
Scenario
An answer comes back with no citations at all. How should the app treat it?
  1. A. Show it
  2. B. As not found: withhold it and keep the draft for review
  3. C. Retry until cited
  4. D. Add citations by hand
Answer
B
Why
No citation means no supporting passage.
Question 3
Scenario
A product catalogue of millions of tokens changes daily. Which approach fits?
  1. A. Send the whole catalogue, cached
  2. B. Retrieve the top passages and send them as search results
  3. C. Paste it in the system prompt
  4. D. Fine-tune a model
Answer
B
Why
Large, fast-changing corpora suit retrieval; cached full context suits small, stable ones.

A design needs both citations and a JSON schema in one request. What happens?

  2. B. The API returns 400; return prose with citations and structure it afterwards
  3. C. Citations are ignored
  4. D. The schema is ignored

B

Key takeaways

  • A grounded request has the documents (before the question), an instruction to use only them, an exact "not found" reply, and citations.
  • Documents with citations enabled return cited_text plus a location; custom content controls the citable units; cited_text is free of output tokens.
  • Search result blocks (source, title, text content) give retrieval citations as search_result_location; citations are off by default and all-or-nothing per request; no structured outputs alongside citations.
  • Treat NOT_FOUND and uncited answers as "not found", route them to a person, and ask for quotes first on long documents.
  • Full corpus (cached) for small, stable sets; retrieval for large, costly-per-question or frequently changing ones. Measure retrieval recall too.
