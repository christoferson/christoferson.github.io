Architect or Developer?

Anthropic's Claude certifications have three roles (Associate, Developer and Architect). This page compares the developer exam with the two architect exams: who each is for, what each tests, where they overlap, and what only the developer exam asks about.

Everything here comes from the four version 1.0 exam guides (effective July 2026) and the role descriptions on Anthropic's Partner Academy certifications page, checked on 8 November 2026. Updated guides for three of the exams, including the developer one, are due on 17 November 2026, so details may shift.

The roles

The Partner Academy page describes the roles in one line each:

  • Associate (CCAO-F): for consultants, sellers and delivery leads who guide customers toward the right Claude use cases.
  • Developer (CCDV-F): for engineers who build with the Claude API, Claude Code and MCP, from a first integration to production agents.
  • Architect (CCAR-F, then CCAR-P): for people who design Claude solutions end to end, choosing deployment platforms, shaping agentic architectures, and planning for evaluation, cost and safety.

The guides' candidate profiles sharpen this. The developer candidate is an AI or machine learning engineer, technical lead or senior software engineer with one to five years of software engineering, at least six months with Claude or similar systems, and Python or TypeScript; the guide explicitly excludes roles limited to prompt writing. The Architect – Foundations candidate is "a solution architect who designs and implements production applications with Claude", with about six months of hands-on work with the Claude API, Agent SDK, Claude Code and MCP. The Professional architect additionally selects models and architectures, integrates Claude into enterprise systems, handles governance and compliance, and communicates decisions to stakeholders.

The exams side by side

Claude Certified Developer – Foundations (CCDV-F). 53 items in 120 minutes, US$125, eight domains made up of 26 weighted skills. The largest domain by far is Applications and Integration (33.1%), followed by Model Selection and Optimization (16.8%), Agents and Workflows (14.7%), Prompt and Context Engineering (11.0%), Tools and MCPs (10.6%) and Security and Safety (8.1%). Claude Code (3.1%) and Eval, Testing and Debugging (2.6%) are small.

Claude Certified Architect – Foundations (CCAR-F). 60 items in 120 minutes, US$125, five domains with 30 task statements, and every question framed by one of four scenarios drawn from a published set of six (a support agent, code generation, a multi-agent research system, developer productivity, Claude Code in CI, structured data extraction). The domains: Agentic Architecture and Orchestration (27%), Claude Code Configuration and Workflows (20%), Prompt Engineering and Structured Output (20%), Tool Design and MCP Integration (18%), Context Management and Reliability (15%).

Claude Certified Architect – Professional (CCAR-P). US$175, seven domains: Integration (19%), Solution Design and Architecture (17%), Evaluation, Testing and Optimization (16%), Governance, Safety and Risk Management (14%), Stakeholder Communication and Lifecycle Management (14%), Claude Models, Prompting and Context Engineering (13%), and Developer Productivity and Operational Enablement (7%).

All three are proctored by Pearson VUE, pass at a scaled 720 out of 1,000, last 12 months, and are open only to people at Claude Partner Network organizations.

What both test

CCDV-F and CCAR-F share a large core, approached from different angles:

  • Agents. Both cover workflows versus agents, subagents and the Claude Agent SDK. CCAR-F goes deep on orchestration: agentic loops, coordinator and subagent patterns, hooks, sessions, task decomposition. CCDV-F is broader but shallower, and adds agent frameworks such as Strands, LangGraph and PydanticAI, and Anthropic-hosted versus self-hosted agents.
  • Tools and MCP. CCAR-F focuses on tool interface design, structured errors, distributing tools across agents and configuring MCP servers. CCDV-F adds building MCP servers and weighing built-in tools against custom tools, Skills and MCP.
  • Claude Code. A fifth of CCAR-F (CLAUDE.md, skills, rules, plan mode, CI); in CCDV-F a small Claude Code domain plus configuration management (CLAUDE.md, settings.json) inside Domain 2.
  • Prompting and context. Both, with CCAR-F stressing structured output, validation loops and context reliability, and CCDV-F stressing prompt and context engineering and output handling.

If you've studied the CCAR-F notes, much of CCDV-F's agents, tools and Claude Code material will be familiar.

Only the developer exam

This is where the tracks really part, and it's mostly Domain 2, Applications and Integration. The clearest evidence is CCAR-F's own list of topics that won't appear on that exam: streaming, vision, rate limits and quotas, pricing calculations, prompt caching details, API authentication and key rotation, and cloud-provider configuration. Nearly all of them are named skills in CCDV-F:

  • Claude API mechanics (skill 2.3): streaming, vision, thinking, prompt caching, calling Claude through cloud providers, and choosing between the real-time API and the Batch API.
  • Software engineering foundations (skill 2.4): REST APIs, JSON, asynchronous programming, version control, code review and refactoring, the general engineering a developer brings to a Claude project.
  • Application design (skill 2.5): how Claude interprets instructions differently in Claude Code, Desktop, claude.ai, the API and the SDKs; content boundaries; session hygiene; plugins.
  • Configuration management (skill 2.6): settings.json, model version pinning, prompt versioning and plugin dependencies.
  • Requirements and life cycle (skills 2.1 and 2.2): turning business needs into functional and infrastructure requirements, and running a system through its life cycle.
  • Model selection and cost (Domain 5): LLM fundamentals, model tiers, tokens, caching and batch processing for cost and latency.
  • Security (Domain 7): secure-by-design applications, guardrails through hooks, identity, secrets and key management.

Put simply: the architect foundations exam asks whether you'd design the agent system correctly; the developer exam also asks whether you can implement and run it against the actual API.

Only the architect exams

  • Scenario-based judgment (CCAR-F): every question sits inside a production scenario and asks for the best trade-off, for example plan mode versus direct execution, or when to escalate to a person.
  • Deeper agent reliability (CCAR-F): error propagation across agents, information provenance, human review and confidence calibration, long-context management.
  • Organization-level concerns (CCAR-P): solution design for business problems, governance, safety and risk management, stakeholder communication and life cycle management, and enabling developer teams.

Which to take

  • You write the application code, call the API and ship features: Developer.
  • You design agent systems and decide how tools, Claude Code and context fit together: Architect – Foundations, then Professional once you also own governance and stakeholder decisions.
  • You do both: the two foundations exams overlap enough that preparing for one covers much of the other; the developer exam adds the API and engineering detail.

The certifications page suggests starting at Foundations and moving to Professional where available; there are no formal prerequisites.

In short

  • Developer: engineers who build and ship; 53 items, 8 domains, 26 skills; a third of the exam is Applications and Integration.
  • Architect – Foundations: designers of agent systems; 60 scenario-based items, 5 domains; deep on orchestration, tools, Claude Code and reliability.
  • Topics CCAR-F explicitly leaves out (streaming, vision, caching details, rate limits, pricing, authentication, cloud providers) are core CCDV-F material.
  • Architect – Professional adds design for business problems, governance and stakeholder communication.
