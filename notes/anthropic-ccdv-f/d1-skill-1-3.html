1.3: Agent Pattern Diagnosis

Reading what a misbehaving agent did and naming what's missing: a loop that stops at the wrong moment, an agent stuck repeating itself, a subagent briefed with context it never saw, an agent that forgets between sessions, or one drowning in its own context.

Overview

Skill 1.3

Agent Pattern Diagnosis: "Analyzing a trace or description of a misbehaving agent to identify which design pattern is missing or misapplied, such as tool-use loop termination, subagent isolation, memory, or context-window management, and selecting the pattern that corrects the behavior."

Exam items give a trace excerpt or a description ("the agent stops halfway", "the subagent says it can't find the file"), and the answer is the pattern that fixes the cause. The four patterns the guide names each leave a recognisable mark in a trace. Diagnosing failures of the model's output itself (hallucination, refusal, format drift) is skill 4.2; this skill is about the agent's design.

Sources: Claude's documentation on the memory tool, stop reasons, context windows and context editing, and the Agent SDK subagent documentation, checked on 19 and 20 November 2026 and paraphrased. Both examples are plain Python and were tested on synthetic traces and a temporary directory.

Running example. Support engineers send the shop's agent team traces of runs that went wrong: order lookups, refund investigations, a code agent working on the refund service, and a returns assistant used across many days.

Symptoms to patterns

Skill 1.3What each missing pattern looks like from outside.

  • Stops too early, or answers half-done: loop termination. The loop ended on something other than the stop reason, such as text in the response, or treated a max_tokens cut-off as the answer.
  • Same call again and again: progress detection. Nothing notices the agent isn't getting anywhere, so it only stops at the turn cap.
  • Subagent can't find what the coordinator saw, or duplicates its work: subagent isolation misapplied. The brief assumes shared context, or the scopes overlap.
  • Coordinator's context explodes after delegating: subagent output. The subagent returned its whole transcript rather than a summary.
  • Each session asks the same questions again: memory. Nothing persists between conversations.
  • Quality drops late in a long run, files are re-read and earlier facts are contradicted: context-window management.

A trace checker

Skill 1.3The same reasoning as rules over a trace.

trace_doctor.py (Python) 
"""Read an agent trace and name the missing or misapplied pattern, with the evidence and the fix.
A trace is a list of steps: {"kind": "response", "stop_reason", "input_tokens", "tool_calls": [{"name", "input"}]},
{"kind": "loop_exit", "reason"}, {"kind": "subagent", "prompt", "returned_tokens"}, {"kind": "session_start", "asks_user": [...]}."""
import json

FIX = {
    "loop termination": "Loop while stop_reason == 'tool_use'; end on end_turn; treat max_tokens and refusal as their own cases; "
                        "keep the iteration cap only as a safety net that reports an error.",
    "progress detection": "Detect repeated identical calls and return an is_error result that says what to try instead.",
    "subagent isolation": "Write a complete brief: the subagent sees only its prompt, not the parent's conversation.",
    "subagent output": "Have the subagent return a short structured summary, not its whole transcript.",
    "memory": "Persist what was learned (memory tool, CLAUDE.md, a progress file) and read it at the start of each session.",
    "context-window management": "Delegate large reads to subagents, clear old tool results or compact, and keep key facts "
                                 "in a file or block that survives summarisation.",
}


def diagnose(trace: list[dict], context_budget: int = 200_000) -> list[dict]:
    found = []
    def add(pattern, evidence):
        found.append({"pattern": pattern, "evidence": evidence, "fix": FIX[pattern]})

    responses = [s for s in trace if s["kind"] == "response"]
    for i, s in enumerate(trace):
        if s["kind"] == "loop_exit" and i > 0 and trace[i - 1].get("stop_reason") == "tool_use":
            add("loop termination", f"loop exited ({s['reason']}) while the last response still asked for tools")
        if s["kind"] == "loop_exit" and i > 0 and trace[i - 1].get("stop_reason") == "max_tokens":
            add("loop termination", "a response cut off by max_tokens was treated as the final answer")

    calls = [json.dumps(c, sort_keys=True) for r in responses for c in r.get("tool_calls", [])]
    repeated = {c for c in calls if calls.count(c) >= 3}
    if repeated:
        add("progress detection", f"the same call was made {max(calls.count(c) for c in repeated)} times: {sorted(repeated)[0]}")

    for s in (x for x in trace if x["kind"] == "subagent"):
        if any(p in s["prompt"].lower() for p in ("as discussed", "the file above", "the earlier", "same as before")):
            add("subagent isolation", f"subagent brief refers to context it never saw: {s['prompt'][:60]!r}")
        if s.get("returned_tokens", 0) > 20_000:
            add("subagent output", f"subagent returned {s['returned_tokens']} tokens to the parent")

    starts = [s for s in trace if s["kind"] == "session_start"]
    asked = [q for s in starts for q in s.get("asks_user", [])]
    if any(asked.count(q) > 1 for q in asked):
        add("memory", f"each new session asks again: {sorted({q for q in asked if asked.count(q) > 1})}")

    if responses and max(r["input_tokens"] for r in responses) > 0.8 * context_budget:
        reads = [c for r in responses for c in r.get("tool_calls", []) if c["name"] == "Read"]
        paths = [c["input"].get("file_path") for c in reads]
        reread = sorted({p for p in paths if paths.count(p) > 1})
        add("context-window management", f"input reached {max(r['input_tokens'] for r in responses)} tokens"
                                         + (f"; re-read {reread}" if reread else ""))
    return found

Each rule looks for the evidence an engineer would look for. Did the loop exit right after a response whose stop reason was tool_use? Is an identical call repeated three times? Does a brief say "the file above"? Do two sessions ask the same question? Is the input close to the budget, with files read twice? Each finding names the pattern, quotes its evidence and gives the fix. A healthy trace returns nothing. Real traces need judgement, but practising the mapping this way is exactly what the exam asks.

Loop termination and progress

Skill 1.3Ending the loop for the right reason.

  • The rule: continue while stop_reason is tool_use, and stop on end_turn. Every other stop reason has its own handling: max_tokens means the output was cut off, pause_turn means send it back to continue, and refusal means don't retry the same request.
  • Misapplied versions: ending when the response contains any text (Claude often writes a sentence before a tool call), ending after a fixed number of turns, or parsing "I'm done" out of the text.
  • Progress: a turn cap is a safety net, not a stopping rule. When the same call keeps failing, return an is_error result that says what to try instead, or escalate.

The full loop is in the architect notes (stop reasons, anti-patterns).

Subagent isolation

Skill 1.3Fresh context is the point, and the pitfall.

  • Applied correctly, isolation keeps a subagent's large reads out of the coordinator and gives it a clean, focused context. Only its final message comes back.
  • Misapplied, part 1: the brief relies on the coordinator's conversation ("check the file above"), which the subagent never saw. The fix is a self-contained brief: the objective, the inputs, the output format and the boundaries.
  • Misapplied, part 2: the subagent returns everything it read, so the coordinator's context fills up anyway. The fix is a short, structured result.
  • Missing: one agent does everything, and a broad task's reading crowds out its reasoning. The fix is delegating independent parts to subagents.

Memory across sessions

Skill 1.3The memory tool and its client-side handler.

Every conversation starts empty, so an agent that should remember a customer's preferred carrier between sessions needs somewhere to keep it.

  • The memory tool (memory_20250818, generally available) lets Claude create, read, edit and delete files under /memories. The API adds an instruction to check memory before starting, and to record progress as it goes.
  • Client-side: Claude only asks for the operation; your application runs it against storage you choose, such as a directory or database keys per user. That's why it's eligible for zero data retention.
safe_memory.py (Python) 
"""The client-side half of the memory tool: run Claude's memory commands against one user's directory,
refusing any path that escapes /memories."""
from pathlib import Path
from urllib.parse import unquote

MEMORY_TOOL = {"type": "memory_20250818", "name": "memory"}   # the whole tool definition


class Memory:
    def __init__(self, root: str):
        self.root = Path(root).resolve()
        self.root.mkdir(parents=True, exist_ok=True)

    def _path(self, virtual: str) -> Path:
        virtual = unquote(virtual)                              # catch %2e%2e%2f as well as ../
        if not (virtual == "/memories" or virtual.startswith("/memories/")):
            raise PermissionError(f"{virtual} is outside /memories")
        real = (self.root / virtual.removeprefix("/memories").lstrip("/")).resolve()
        if real != self.root and self.root not in real.parents:  # canonical form must stay inside the root
            raise PermissionError(f"{virtual} is outside /memories")
        return real

    def run(self, cmd: dict) -> tuple[str, bool]:
        """Returns (tool_result content, is_error)."""
        try:
            c = cmd["command"]
            if c == "view":
                p = self._path(cmd["path"])
                if p.is_dir():
                    files = "\n".join(f"{f.stat().st_size}\t/memories/{f.relative_to(self.root).as_posix()}"
                                      for f in sorted(p.rglob("*")) if f.is_file())
                    return f"Here're the files and directories up to 2 levels deep in {cmd['path']}:\n{files}", False
                if not p.exists():
                    return f"The path {cmd['path']} does not exist. Please provide a valid path.", True
                lines = p.read_text().splitlines()
                return f"Here's the content of {cmd['path']} with line numbers:\n" + \
                       "\n".join(f"{i:6d}\t{l}" for i, l in enumerate(lines, 1)), False
            if c == "create":
                p = self._path(cmd["path"])
                p.parent.mkdir(parents=True, exist_ok=True)
                p.write_text(cmd["file_text"])
                return f"File created successfully at: {cmd['path']}", False
            if c == "str_replace":
                p = self._path(cmd["path"])
                text = p.read_text() if p.is_file() else None
                if text is None or text.count(cmd["old_str"]) != 1:
                    return f"No replacement was performed, old_str `{cmd['old_str']}` did not appear exactly once in {cmd['path']}.", True
                p.write_text(text.replace(cmd["old_str"], cmd.get("new_str", "")))
                return "The memory file has been edited.", False
            if c == "delete":
                p = self._path(cmd["path"])
                if p == self.root:
                    return "Error: the /memories directory itself can't be deleted", True
                p.unlink()
                return f"Successfully deleted {cmd['path']}", False
            return f"Error: unsupported command {c}", True
        except PermissionError as e:
            return f"Error: {e}", True
  • Your handler is the security boundary: a path such as /memories/../secrets.env, or its URL-encoded form, must be refused. Resolve each path to its canonical form and check it is still inside the user's directory. Also refuse deleting or renaming /memories itself.
  • Other options: CLAUDE.md or a progress file for a coding agent, the memory field on an Agent SDK subagent, and memory stores in Managed Agents. The guide's point is the pattern: persist what must survive, and read it at the start.
  • Multi-session work: the documented pattern is an initial session that sets up a progress log and a feature checklist. Each later session reads them first and updates them before it ends.

Context-window management

Skill 1.3When the agent's own history becomes the problem.

Long runs accumulate tool results, file contents and reasoning, and accuracy degrades as context grows. The symptoms are re-reading files, contradicting earlier findings, and generic answers. The fixes, in roughly the order to reach for them:

  • Delegate large reads to subagents.
  • Clear old tool results with context editing, or compact older turns.
  • Keep must-survive facts in memory or a file. The memory tool documentation pairs it with compaction for exactly this reason: the summary keeps the context small, and memory keeps what can't be lost.

The detail is in the architect notes (long interactions, codebase exploration).

Key takeaways

  • Map the symptom to the pattern: stops early or on a cut-off (loop termination), repeats a call (progress detection), subagent missing context or flooding the parent (isolation, output), forgets between sessions (memory), degrades late in a long run (context management).
  • Loop while stop_reason is tool_use; never end on "contains text" or a fixed count; caps report errors.
  • Subagents see only their brief and return only their final message: write self-contained briefs and ask for short, structured results.
  • The memory tool (memory_20250818) is client-side: your handler runs each file command and must block path traversal outside /memories.
  • For long runs, delegate reads, clear or compact old context, and keep must-survive facts in memory.
