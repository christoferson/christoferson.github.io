Overview

Task 2.1

Implement agentic AI solutions and tool integrations.

An agent is a foundation model in a loop: it reads the goal, decides on an action (often a tool call), sees the result, and repeats until it can answer. That autonomy is what makes agents useful and what makes them risky, so most of this task is about building agents and bounding them: limits on steps and time, permissions on tools, policies on actions, and people at the decisions that matter.

The examples extend the retailer's assistant into an agent that can look up orders, check warranties and issue small refunds.

Amazon Bedrock Agents is now Bedrock Agents Classic, closed to new customers since July 30, 2026 (existing users keep it, with no end date). AWS recommends Amazon Bedrock AgentCore, either its managed harness or your own agent code on AgentCore Runtime. Agent Squad, named in the exam guide, is open source and now maintained outside AWS (2fastlabs).

Agents with memory and state

Skill 2.1.1Develop intelligent autonomous systems with appropriate memory and state management capabilities (for example, by using Strands Agents and AWS Agent Squad for multi-agent systems, MCP for agent-tool interactions)

Strands Agents

A model-driven agent SDK

Strands Agents is AWS's open-source SDK (Python and TypeScript) for building agents in a few lines: give it a model (Bedrock by default), a system prompt and tools, and it runs the agent loop: call the model; if it asks for a tool, validate the call, run the tool, return the result; repeat until the model finishes. Tool errors are returned to the model as results, so it can recover, rather than crashing the loop.

A support agent with two tools (Python) 
from strands import Agent, tool
from strands.agent.conversation_manager \
    import SlidingWindowConversationManager

@tool
def order_status(order_id: str) -> dict:
    """Delivery status of an order.

    Args:
        order_id: Order number, e.g. 1042.
    """
    ...

agent = Agent(
    model="us.amazon.nova-pro-v1:0",
    system_prompt=("You are Northwind's "
        "support agent. Use tools "
        "for facts."),
    tools=[order_status, search_manuals],
    conversation_manager=
        SlidingWindowConversationManager(
            window_size=20),
)
result = agent("Where is order 1042?")

The @tool decorator builds the tool's definition from the function: the docstring's first paragraph is the description, the Args section describes each parameter, and the type hints become the JSON schema.

Memory and state

  • Conversation managers keep the history within the context window: a sliding window of recent messages (the default), or summarizing older messages.
  • Agent state holds values the agent and its tools share (the customer ID, a cart), outside the conversation.
  • Session managers persist conversation and state between requests, to files, S3, or AgentCore Memory, so a stateless host can resume a session.
  • AgentCore Memory adds long-term memory extracted across sessions (Task 1.6).

Structured reasoning

Skill 2.1.2Create advanced problem-solving systems to give FMs the ability to break down and solve complex problems by following structured reasoning steps (for example, by using Step Functions to implement ReAct patterns and chain-of-thought reasoning approaches)

ReAct

ReAct (reason and act) alternates thinking and doing: the model reasons about what it knows, chooses an action, observes the result, and reasons again. Agent SDKs implement it inside their loop; Step Functions makes each step an explicit, visible, auditable state, which suits regulated or long-running processes.

  1. ThinkA Bedrock task sends the goal, history and tool definitions to the model.
  2. DecideA Choice state reads the result: a tool request goes to Act; a final answer goes to Done; too many steps goes to Give up.
  3. ActA Lambda task runs the requested tool and appends the observation to the history.
  4. CountIncrement the step counter and return to Think.
The Decide state with a step limit (Step Functions) 
"Decide": {
  "Type": "Choice",
  "Choices": [
    {"Variable": "$.steps",
     "NumericGreaterThanEquals": 8,
     "Next": "GiveUp"},
    {"Variable": "$.model.stop_reason",
     "StringEquals": "tool_use",
     "Next": "RunTool"}
  ],
  "Default": "Done"
}

Chain-of-thought fits the Think step: instruct the model to reason before choosing an action, or use a model's built-in reasoning (Task 1.6). Step Functions' Bedrock integration invokes models directly; a new AgentCore integration can run a harness agent as a step.

Safeguards

Workflow choice matters for safeguards: Standard workflows run up to a year and support waiting for a human; Express workflows end within 5 minutes and can't wait on a task token. A human approval step needs Standard.

Coordinating models

Skill 2.1.4Create sophisticated model coordination systems to optimize performance across multiple capabilities (for example, by using specialized FMs to perform complex tasks, custom aggregation logic for model ensembles, model selection frameworks)

Patterns

PatternHowExample
SpecialistsEach step uses the model best suited to itA small model classifies, a multimodal model reads the photo, a strong model writes the answer
Plan and executeA strong model plans; cheaper models carry out the stepsAgentCore harness can switch models within a session
RoutingChoose a model per request by rules, a classifier, or Bedrock intelligent prompt routing (two models of a family, by predicted quality)Simple questions to a small model, hard ones to a large one

Ensembles multiply cost and latency, so reserve them for high-stakes decisions where a wrong answer costs more than several calls. In Step Functions, a Parallel or Map state runs the candidates and a Lambda function aggregates.

Humans in the loop

Skill 2.1.5Develop collaborative AI systems to enhance FM capabilities with human expertise (for example, by using Step Functions to orchestrate review and approval processes, API Gateway to implement feedback collection mechanisms, human augmentation patterns)

Where a person steps in

  • Approval before action: the agent proposes (a refund of $240), a person approves or rejects, then it acts.
  • Review of output: low-confidence or sensitive answers go to a reviewer before the customer sees them.
  • Escalation: the agent hands the conversation to a person with a summary.
  • Feedback: users and reviewers rate answers, feeding evaluation and prompt improvement.
MechanismHow it pauses
Step FunctionsA .waitForTaskToken task sends the request with a token; a reviewer's action (through API Gateway and Lambda) calls SendTaskSuccess or SendTaskFailure
Strands interruptsA hook or tool raises an interrupt; the agent stops with reason interrupt; the application resumes it with the person's response
AgentCorePolicy rules that require approval; harness inline function tools that hand control back to the application
Bedrock Agents ClassicReturn of control: the agent returns the action for the application to perform

Collecting feedback

An API Gateway endpoint receives ratings and corrections (with the conversation and prompt version IDs) and stores them in DynamoDB or S3; those examples feed evaluation sets and prompt fixes (Task 1.6). Amazon Augmented AI (A2I) is closed to new customers, so build review queues with Step Functions and your own interface.

Tool integrations

Skill 2.1.6Implement intelligent tool integrations to extend FM capabilities and to ensure reliable tool operations (for example, by using the Strands API to implement custom behaviors, standardized function definitions, Lambda functions to implement error handling and parameter validation)

Good tool definitions

  • Name and description say when to use the tool, not just what it does; the model chooses tools from these.
  • A strict input schema: types, required fields, enums and formats, so malformed calls are rejected before they run.
  • Small, single-purpose tools rather than one tool with many modes.
  • Clear results: a status and a short, structured payload; an error message the model can act on ("order_id must be digits").

Validation and error handling in Lambda

Treat every tool call as untrusted input: the model may pass wrong types, out-of-range values or another customer's ID. Validate against the schema and business rules, check that the caller may act on that resource, enforce limits, and return a useful error instead of throwing. Make actions idempotent (a refund keyed by request ID) so a retried call doesn't act twice.

Custom behavior with Strands hooks

Hooks run code at points in the agent loop (before and after each model call and tool call). A hook can change a tool's input, swap the tool, cancel the call with a message to the model, or retry, which is where business rules, logging and circuit breakers fit.

Block large refunds before they run (Python) 
from strands.hooks import (
    HookProvider, HookRegistry,
    BeforeToolCallEvent)

class RefundLimit(HookProvider):
    def register_hooks(self, registry):
        registry.add_callback(
            BeforeToolCallEvent, self.check)

    def check(self, event):
        use = event.tool_use
        if (use["name"] == "issue_refund"
                and use["input"]["amount"]
                    > 100):
            event.cancel_tool = (
                "Over $100 needs a "
                "person; offer to escalate.")

agent = Agent(tools=[issue_refund],
              hooks=[RefundLimit()])

To pause for approval instead of refusing, the hook can raise an interrupt, and the application resumes the agent once a person decides.

MCP servers

Skill 2.1.7Develop model extension frameworks to enhance FM capabilities (for example, by using Lambda functions to implement stateless MCP servers that provide lightweight tool access, Amazon ECS to implement MCP servers that provide complex tools, MCP client libraries to ensure consistent access patterns)

The Model Context Protocol

MCP is an open protocol (JSON-RPC) through which a client in an agent or IDE discovers and calls what a server offers: tools (actions), resources (data) and prompts (templates). Transports are stdio (a local process) and Streamable HTTP (remote; it replaced the older HTTP-with-SSE transport). Write a tool once as an MCP server and every MCP-capable agent can use it.

Where to host an MCP server

HostSuitsNotes
AWS LambdaLightweight, stateless tools (lookups, simple actions)AWS's open-source adapter starts the server per invocation behind API Gateway, a function URL or AgentCore Gateway; servers that keep state between calls don't fit
Amazon ECS on FargateComplex, long-lived or stateful tools, heavy dependenciesAWS guidance: CloudFront and WAF, an internal ALB, tasks in private subnets, Cognito OAuth
AgentCore RuntimeManaged hosting with session isolation and authServe Streamable HTTP on port 8000 at /mcp; stateless mode recommended
AgentCore GatewayExisting Lambda functions and APIs, without writing a serverExposes them as MCP tools, with semantic search over many tools
A stateless MCP server for AgentCore Runtime (Python) 
from mcp.server.fastmcp import FastMCP

mcp = FastMCP(host="0.0.0.0",
              stateless_http=True)

@mcp.tool()
def warranty_status(serial: str) -> str:
    """Warranty status for a serial."""
    return lookup_warranty(serial)

if __name__ == "__main__":
    mcp.run(transport="streamable-http")

Clients

The MCP SDKs (Python, TypeScript) provide clients; agent frameworks wrap them so MCP tools appear as ordinary tools. Use one client pattern across teams so authentication, tool filtering and error handling are consistent.

Use the server's tools from a Strands agent (Python) 
from mcp.client.streamable_http import (
    streamablehttp_client)
from strands import Agent
from strands.tools.mcp import MCPClient

client = MCPClient(
    lambda: streamablehttp_client(MCP_URL))

with client:
    tools = client.list_tools_sync()
    agent = Agent(tools=tools)
    agent("Is serial K200-77 covered?")

AWS's own MCP serversAWS publishes MCP servers for its services, and a managed AWS MCP Server (through the Agent Toolkit for AWS) gives agents one endpoint for AWS APIs and documentation, with IAM controls.

"Expose existing Lambda functions and REST APIs to agents as tools, with authentication, without writing servers" points to AgentCore Gateway. "A simple stateless tool server at low cost" points to Lambda. "A tool needing a long-running process or large dependencies" points to ECS on Fargate.

Key takeaways

  • Bedrock Agents is now Agents Classic (closed to new customers); build on AgentCore (harness or Runtime) with frameworks such as Strands Agents. Agent Squad is open source outside AWS.
  • Strands: model plus tools plus system prompt; the agent loop runs until the model finishes; @tool builds definitions from docstrings and type hints; conversation, state and session managers handle memory; multi-agent patterns are agents-as-tools, swarm, graph, workflow and A2A.
  • AgentCore: Runtime (isolated sessions up to 8 hours), Memory, Gateway (APIs and Lambda as MCP tools), Identity, Code Interpreter, Browser, Policy, Observability, Evaluations.
  • Step Functions makes ReAct explicit: think, decide (Choice with a step limit), act, repeat. Safeguards: step and token limits, timeouts, least-privilege tool roles, policies, hooks, circuit breakers, guardrails.
  • Coordinate models with specialists, plan-and-execute, routing, and ensembles with aggregation for high-stakes decisions.
  • Humans: approval with task tokens (Standard workflows), Strands interrupts, AgentCore policies, return of control; collect feedback through API Gateway. A2I is closed to new customers.
  • Tools need clear descriptions, strict schemas, validation, idempotency and useful errors. MCP standardizes tools: stateless servers on Lambda, complex ones on ECS, managed ones on AgentCore, existing APIs through Gateway.
