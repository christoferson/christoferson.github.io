Where to run a model

Domain 1. See Task 1.1 and Task 2.2.

OptionChoose it whenWatch out for
Bedrock on-demandYou want serverless, per-token pricing across many providers' modelsShared quotas (tokens and requests per minute); throttling at peaks
Bedrock Provisioned ThroughputSteady, high volume on one model, or a customized model that needs dedicated capacityBilled hourly per model unit whether used or not; limited model list
Bedrock Custom Model ImportYou fine-tuned an open-weight model (for example Llama, Mistral, Qwen) elsewhere and want Bedrock's serverless APISupported architectures only; no batch inference; charged per model copy in 5-minute windows
Bedrock MarketplaceYou need a specialized model not in the serverless catalogRuns on SageMaker-managed endpoints you size and pay for
SageMaker AI endpointsYou need full control: your own container, instance type, scaling, or models Bedrock doesn't offerYou run capacity, scaling and patching of the model server

Prompting, RAG and customization

Domain 1. See Task 1.1 and Task 1.2.

ApproachChangesChoose it when
Prompt engineeringOnly the instructions and examples sentFirst step for any task; fastest and cheapest to change
RAG (knowledge bases)The context: relevant passages retrieved per requestAnswers depend on your documents or data that changes
Supervised fine-tuningThe model's weights, from labeled examplesYou need a consistent style, format or domain behavior that prompting can't reach
Reinforcement fine-tuningThe weights, guided by a reward function (Lambda)You can score answers automatically but lack many labeled examples
DistillationA smaller student model trained on a larger teacher's answersYou want near-teacher quality at lower cost and latency

Neptune Analytics (GraphRAG)Combines vector search with a graph of entities and relationshipsQuestions need connections across documents

Vector stores

Domain 1. See Task 1.4 and Task 1.5.

StoreStrengthLimitation
OpenSearch ServerlessHybrid search, filters, high query rates, no servers to manageCapacity units cost money even when quiet (newer vector collections can scale to zero)
OpenSearch Service (managed domains)Full control of k-NN settings, shards, plugins and search pipelinesYou size and operate the cluster
Aurora PostgreSQL with pgvectorVectors next to relational data, SQL filters and joins, hybrid search in knowledge basesTuning HNSW and memory is up to you

ElastiCache or MemoryDB vector searchVery low latency, for example a semantic cacheMemory-bound; not a document store

Chunking strategies

Domain 1 and 5. See Task 1.5 and Task 5.2.

StrategyHow it splitsChoose it when
DefaultAbout 300 tokens, keeping sentences wholeA reasonable start for plain text
Fixed-sizeA set number of tokens with an overlap percentageUniform documents; you want predictable chunk sizes
HierarchicalSmall child chunks are searched; their larger parent chunk is returnedPrecise matching but answers need surrounding context
SemanticSplits where the meaning changes, using a model (extra cost)Documents mix topics and fixed sizes cut ideas in half
No chunkingOne chunk per fileFiles are already small and self-contained (you lose page citations)
Custom (Lambda)Your own code after parsingYou need to split on headings, sections or other structure

Improving retrieval

Domain 1 and 4. See Task 1.5 and Task 4.2.

TechniqueFixesCost
Metadata filtersResults from the wrong product, date or access groupNeeds good metadata on every chunk
Hybrid searchExact terms (part numbers, error codes) missed by vector searchSupported only on some stores; weights or RRF to tune
RerankingThe right passage is retrieved but ranked too lowAn extra model call per query
Query rewriting or decompositionFollow-up or multi-part questions that search poorlyExtra model calls; more latency
Higher ef_search or more resultsRelevant chunks missed by approximate searchSlower queries; longer prompts

Domain 5. See Task 5.1 and Task 5.1.

MethodUsers see the candidateUse it for

Handling Bedrock errors

Domain 5. See Task 5.2.

ErrorMeansAction
ValidationException (400)The request is wrong (format, parameters, too long)Fix it; don't retry
AccessDeniedException (403)IAM, SCP, inference profile or first-use prerequisitesFix permissions; don't retry
ThrottlingException (429)Your quota exceededBack off with jitter; bound concurrency; more capacity
ServiceUnavailableException (503)Service capacity, not your quotaRetry with backoff; cross-Region inference
ModelTimeoutException (408), ModelErrorException (424)The model failed or took too long on this requestRetry a bounded number of times; check the input

Priority and Flex tiersServed first at a premium versus served later at a discount
Batch inference and FlexOffline JSONL job in S3 versus individual requests that tolerate waiting
Managed and customer-managed knowledge basesBedrock runs the store, embeddings and reranking versus you choose and run them
Hybrid search and rerankingFinds exact terms vector search misses versus reorders retrieved results by relevance
Hierarchical and semantic chunkingSearch small chunks, return the parent versus split where the topic changes
RAG and fine-tuningAdds current knowledge per request versus changes the model's behavior and style
AgentCore and Agents ClassicCurrent agent platform for any framework versus earlier managed agents, closed to new customers
Strands Agents and AgentCore RuntimeSDK to write an agent versus the service that hosts and runs it
Contextual grounding and Automated Reasoning checksIs the answer supported by the source versus does it obey formal rules
Content filters and denied topicsHarmful categories versus subjects you define as off limits
CloudTrail and invocation logsWho called what versus what was actually sent and returned
Management and data eventsModel calls and configuration, logged by default versus retrievals, agents, flows and guardrails, enabled separately
