Overview

Task 2.3

Design and implement enterprise integration architectures.

In a large organization, a GenAI feature rarely stands alone: it reads from a 20-year-old order system, reacts to tickets from a SaaS help desk, must respect the corporate identity system, may not send customer data outside the EU, and has to pass the same release controls as every other change. This task is about those connections and controls.

The examples use the retailer's environment: an on-premises order management system, a SaaS help desk, a corporate identity provider, EU customers whose data must stay in the EU, and several teams building GenAI features.

Enterprise connectivity

Skill 2.3.1Create enterprise connectivity solutions to seamlessly incorporate FM capabilities into existing enterprise environments (for example, by using API-based integrations with legacy systems, event-driven architectures to implement loose coupling, data synchronization patterns)

Synchronous: APIs

Wrapping a legacy system

A legacy system with its own protocol or a fragile interface is put behind an API Gateway API: the GenAI application (or an agent's tool) calls a clean REST endpoint, and the integration translates. For a system on premises or in a private VPC, a VPC link connects API Gateway privately to a Network or Application Load Balancer in front of it (reaching on premises over Direct Connect or VPN).

Model calls can be slow. API Gateway's integration timeout is 29 seconds by default; for Regional and private REST APIs it can now be raised (possibly lowering the account's throttling quota). For anything longer, stream the response or switch to an asynchronous pattern.

Asynchronous: events

Loose coupling with EventBridge

Instead of systems calling each other directly, they publish events ("order shipped", "ticket created") to an EventBridge bus, and rules route them to consumers. The GenAI component can be added, changed or removed without touching the producer, and a slow model call doesn't slow the source system.

  • Rules match events and invoke up to five targets each (Lambda, Step Functions, SQS, SNS, API destinations and more). Bedrock isn't a direct target: route to Lambda or Step Functions, which call the model.
  • API destinations call an external HTTPS endpoint (a SaaS API, a legacy service) as a target, with a connection holding its credentials (basic, OAuth or API key, stored in Secrets Manager), a rate limit, and retries for up to 24 hours. The endpoint must answer within 5 seconds.
  • Pipes connect one source (a queue, stream or DynamoDB table) to one target, with filtering and an optional enrichment step in between, for example a Lambda function that adds a model-generated summary.
  • A newer custom event bus type adds event retention, ordering and replay; the original buses are now called "Classic".

Enhancing existing apps

Skill 2.3.2Develop integrated AI capabilities to enhance existing applications with GenAI functionality (for example, by using API Gateway to implement microservice integrations, Lambda functions for webhook handlers, Amazon EventBridge to implement event-driven integrations)

A GenAI microservice

Add GenAI to an existing application as a separate service with its own API (for example POST /summaries) behind API Gateway, rather than embedding model calls throughout the application. The application team calls one endpoint; the GenAI team can change models, prompts and retrieval behind it.

Webhooks

Receiving events from SaaS tools

Many SaaS tools announce changes by calling a webhook URL. A Lambda function behind a function URL or API Gateway receives the call. Two rules matter:

  • Verify the signature the sender attaches (an HMAC of the body with a shared secret kept in Secrets Manager), so only the real sender can trigger your workflow.
  • Respond fast, process later: senders time out in seconds, but a model call can take longer. Put the event on SQS (or EventBridge) and return immediately; a separate consumer calls the model.
Webhook handler: verify, queue, return (Python) 
import hashlib, hmac, os
import boto3

sqs = boto3.client("sqs")
QUEUE_URL = os.environ["QUEUE_URL"]
SECRET = load_secret()  # at cold start

def handler(event, context):
    body = event["body"]
    sent = event["headers"].get(
        "x-signature", "")
    mac = hmac.new(SECRET, body.encode(),
                   hashlib.sha256)
    if not hmac.compare_digest(
            mac.hexdigest(), sent):
        return {"statusCode": 401}
    sqs.send_message(QueueUrl=QUEUE_URL,
                     MessageBody=body)
    return {"statusCode": 202}

Function URLs are reachable only from the internet (no PrivateLink); use API Gateway when you need WAF, private access or usage plans. EventBridge offers a quick-start that deploys a signature-checking webhook for GitHub and Twilio and forwards the events to a bus.

Event-driven enhancements

Partner event sources

SaaS partners (for example Zendesk, Salesforce, Shopify, Stripe, PagerDuty, Datadog) can send events straight to a partner event bus in your account, with no webhook to host. A rule then starts a Step Functions workflow that summarizes a new ticket, classifies it and writes the result back through an API destination.

Rule pattern: new tickets from a help-desk partner (source and detail type as the partner documents them) 
{
  "source": [{
    "prefix": "aws.partner/helpdesk"
  }],
  "detail-type": ["Ticket Created"]
}

Step Functions calls Bedrock directly with its optimized InvokeModel integration (request bodies up to 256 KB, or larger payloads from S3), so the workflow needs no Lambda function just to call the model.

"A SaaS tool's webhook times out while the model is working" points to returning immediately after queuing (SQS) and processing asynchronously. "React to events from a SaaS partner without hosting an endpoint" points to an EventBridge partner event source.

Secure access

Skill 2.3.3Create secure access frameworks to ensure appropriate security controls (for example, by using identity federation between FM services and enterprise systems, role-based access control for model and data access, least privilege API access to FMs)

Least privilege to models

IAM for Bedrock

  • Converse is authorized as bedrock:InvokeModel, and ConverseStream as bedrock:InvokeModelWithResponseStream: allow or deny both to cover all inference.
  • Restrict which models by resource ARN: foundation models (foundation-model/..., with no account ID), inference profiles, application inference profiles and provisioned models.
  • A cross-Region inference profile also needs the foundation model allowed in every destination Region; the bedrock:InferenceProfileArn condition limits that to calls made through the profile.
Support team role: one profile, its model only through it 
{
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "bedrock:InvokeModel",
      "bedrock:InvokeModelWithResponseStream"
    ],
    "Resource":
      "arn:aws:bedrock:*:*:application-inference-profile/sup1"
  }, {
    "Effect": "Allow",
    "Action": [
      "bedrock:InvokeModel",
      "bedrock:InvokeModelWithResponseStream"
    ],
    "Resource":
      "arn:aws:bedrock:*::foundation-model/*",
    "Condition": {"StringLike": {
      "bedrock:InferenceProfileArn":
        "*:application-inference-profile/sup1"
    }}
  }]
}

Requiring guardrails

The bedrock:GuardrailIdentifier condition key can require that every model call uses a specific guardrail (version), pairing an allow with an explicit deny for calls without it. More broadly, guardrails can now be enforced for an account or for the whole organization (through AWS Organizations Bedrock policies), so they apply whatever the application sends; the most restrictive combination wins.

Bedrock API keys

Bedrock accepts API keys as a bearer token. Short-term keys (up to 12 hours, with the creator's permissions) are recommended for applications; long-term keys belong to an IAM user and are meant for exploration. Govern them with IAM conditions: deny bedrock:CallWithBearerToken entirely, deny only long-term keys with bedrock:bearerTokenType, or cap their age.

SCP: no long-term Bedrock API keys in member accounts 
{
  "Effect": "Deny",
  "Action": "bedrock:CallWithBearerToken",
  "Resource": "*",
  "Condition": {"StringEquals": {
    "bedrock:bearerTokenType": "LONG_TERM"
  }}
}

Identity federation and roles

WhoHow they get access
Employees (developers, analysts)IAM Identity Center federated with the corporate identity provider; permission sets per role (for example "GenAI developer" can use approved models in non-production accounts)
Application usersSign in with Amazon Cognito (or a federated IdP); the application's API authorizes them; a Cognito identity pool can exchange their token for scoped temporary AWS credentials, with claims mapped to session tags
Applications and agentsIAM roles with least privilege; no long-lived keys
Data behind the modelAttribute-based access (tags), Lake Formation permissions for data lake tables, and per-user metadata filters on retrieval so users only see documents they may open (Task 1.4)

Role-based access means mapping each job to the models, knowledge bases and actions it needs: a customer support group may call the support assistant's profile; only the data science group may invoke experimental models or start customization jobs.

Private network paths

Interface VPC endpoints (AWS PrivateLink) for bedrock-runtime, bedrock-agent-runtime and the other Bedrock services keep model traffic off the internet; with private DNS, code needs no changes. Restrict each endpoint with an endpoint policy (the default allows everything), for example to inference calls on approved models.

A hybrid design

  1. Data stays localCustomer records stay in the on-premises database (or on Outposts).
  2. Minimize what leavesA local service removes or masks personal data, sending only what the model needs.
  3. Private pathDirect Connect (or Site-to-Site VPN) to a VPC, then the Bedrock interface endpoint; Route 53 Resolver endpoints let on-premises systems resolve the endpoint's private name.
  4. Residency-aware model callsAn EU Region with an EU geographic inference profile (never a global profile) for EU data.
  5. Prove itCloudTrail records the Region that processed each cross-Region request; SCPs deny Regions outside the allowed set.

A Region-restricting SCP that allows only EU Regions will break a global inference profile (and should). It also needs to allow every Region in an EU geographic profile, or those calls fail with access denied.

CI/CD and the GenAI gateway

Skill 2.3.5Implement CI/CD pipelines and GenAI gateway architectures to implement secure and compliant consumption patterns in enterprise environments (for example, by using AWS CodePipeline, AWS CodeBuild, automated testing frameworks for continuous deployment and testing of GenAI components with security scans and rollback support, centralized abstraction layers, observability and control mechanisms)

A pipeline for GenAI components

Prompts, guardrails, knowledge base and agent definitions, flows and the application code are all deployable artifacts: define them in CloudFormation or the CDK (there are resource types for agents, knowledge bases, data sources, guardrails and their versions, prompts and their versions, flows and aliases, application inference profiles, prompt routers and enforced guardrail configurations) and release them through one pipeline.

  1. SourceA commit to the repository starts CodePipeline.
  2. Build and scanCodeBuild lints templates, runs policy checks on them, scans code and dependencies for vulnerabilities and secrets.
  3. TestUnit tests, then the GenAI regression suite against a test stack: golden questions, format checks, safety tests, evaluation scores (Task 1.6).
  4. ApproveA manual approval for production, if required.
  5. DeployTo production, then watch quality and error alarms.
  6. Roll backAutomatically if the stage fails or an alarm fires.
Build and test stage (buildspec.yml) 
version: 0.2
phases:
  install:
    commands:
      - pip install -r tests/reqs.txt
  build:
    commands:
      # template lint and policy checks
      - cfn-lint templates/*.yaml
      # prompt and RAG regression set
      - python tests/run_evals.py
          --min-score 0.85

Rollback in CodePipeline

A stage can roll back to the last successful run, manually or automatically when it fails (not for the source stage, and only after one successful run). Stage conditions add checks: before entering a stage (for example a deployment window), and after success or failure, with rules such as a CloudWatch alarm or a Lambda check, so a quality alarm after deployment rolls the stage back.

Production stage: roll back on failure or a quality alarm 
{

  "onFailure": {"result": "ROLLBACK"},

    "result": "ROLLBACK",
    "rules": [{

        "category": "Rule",

        "version": "1"},

The GenAI gateway

One controlled path to every model

When many teams consume models, a central gateway (an internal API in front of all model providers) applies the organization's controls once instead of in every application:

ControlHow
AuthenticationCognito or corporate IdP tokens checked by an authorizer
Quotas and rate limits per teamAPI Gateway usage plans and API keys, or virtual keys in the gateway
Approved models and routingAn allow list and routing rules in configuration (Task 1.2)
SafetyGuardrails applied (or enforced organization-wide) on every call
Cost attributionAn application inference profile per team with cost tags, and requestMetadata tags in each call
Logging and observabilityInvocation logging, CloudWatch metrics and dashboards per team and model, X-Ray traces
Edge protection and private egressAWS WAF in front, VPC endpoints behind

AWS starting points

  • The Guidance for Multi-Provider Generative AI Gateway on AWS runs the open-source LiteLLM proxy on ECS or EKS behind CloudFront, WAF and a load balancer, giving one OpenAI-compatible API to Bedrock, SageMaker endpoints and other providers, with keys, configuration and caching in RDS and ElastiCache.
  • The Generative AI Application Builder on AWS solution deploys governed RAG chatbots, agents and MCP servers from a management dashboard, using API Gateway, Cognito, WAF and CloudFormation; it handles long model calls with a WebSocket API that queues requests to Lambda through SQS.

"Many teams, inconsistent model use, no cost visibility, no central safety controls" points to a central GenAI gateway with per-team keys and quotas, guardrails, application inference profiles for cost tags, and central logging.

Key takeaways

  • Connect legacy systems through API Gateway (REST for keys, usage plans, validation, WAF, private APIs, streaming; VPC links to private backends); raise the 29-second timeout on REST APIs only if needed, otherwise go asynchronous.
  • Decouple with EventBridge (rules to Lambda or Step Functions, which call Bedrock; API destinations with connections for external APIs; Pipes with enrichment), SQS buffers, and CDC or zero-ETL for data sync.
  • Enhance existing apps with a GenAI microservice; webhooks verify signatures, queue and return fast; partner event sources bring SaaS events without hosting endpoints.
  • Secure access: InvokeModel and InvokeModelWithResponseStream on specific model and profile ARNs; required or enforced guardrails; govern Bedrock API keys; Identity Center for staff, Cognito for app users; VPC endpoints with endpoint policies.
  • Residency: geographic inference profiles, SCP Region limits, Outposts or Local Zones for local data and self-hosted models (no Bedrock there), Wavelength for 5G edge inference, private routing over Direct Connect to interface endpoints.
  • Release GenAI components as code through CodePipeline and CodeBuild with scans, evaluation gates, approvals and automatic rollback; front all model use with a central gateway for auth, quotas, routing, guardrails, cost tags and logging.
