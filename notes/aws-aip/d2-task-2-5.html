GenAI-aware APIs

Skill 2.5.1Create FM API interfaces to address the specific requirements of GenAI workloads (for example, by using Amazon API Gateway to handle streaming responses, token limit management, retry strategies to handle model timeouts)

What an FM API must handle

An API in front of a model has to cope with three things ordinary APIs rarely meet: responses that take many seconds (stream them, with REST response streaming or WebSockets, described in Task 2.4), inputs that can exceed the model's context window, and outputs that can be cut off at the token limit.

Managing token limits

Count before you call

The Bedrock CountTokens API returns how many input tokens a request would use, exactly as it would be billed, at no charge and without running the model. Use it to keep a conversation within budget: if the history plus the new question is too long, drop or summarize the oldest turns before calling.

Trim history to fit a token budget (Python) 
BUDGET = 6000  # input tokens

def fit(system, msgs):
    while True:
        r = brt.count_tokens(
            modelId=MODEL_ID,
            input={"converse": {
                "system": system,
                "messages": msgs}})
        if (r["inputTokens"] <= BUDGET
                or len(msgs) <= 1):
            return msgs
        # drop the oldest user+reply pair
        msgs = msgs[2:]

Not every model supports CountTokens on the runtime endpoint (some cross-Region-only models have a separate endpoint for it); check the model card.

Output limits

  • maxTokens caps the answer: set it to what the use case needs (it also governs quota reservation).
  • A stopReason of max_tokens means the answer was cut off: either raise the limit, or continue by sending the partial answer back as the assistant's turn and asking it to carry on.
  • model_context_window_exceeded means the input was too long for the model: trim, summarize or retrieve less.
  • Return token usage and the stop reason in the API response (or logs), so clients and dashboards can see truncation.

Timeouts and retries

  • Client and gateway timeouts must exceed the model's realistic latency, or the caller gives up while the model is still working (and you still pay for the tokens). For calls longer than a gateway allows, switch to asynchronous: accept, queue, return a job ID.
  • Model timeouts (ModelTimeoutException, 408): retry once, with a shorter input or a faster model, then fall back.
  • Retries must be safe: generation has no side effects, but tools and downstream writes may; make those idempotent.
  • Don't retry validation errors (400); fix the request.

Accessible interfaces

Skill 2.5.2Develop accessible AI interfaces to accelerate adoption and integration of FMs (for example, by using AWS Amplify to develop declarative UI components, OpenAPI specifications for API-first development approaches, Amazon Bedrock Prompt Flows for no-code workflow builders)

Amplify AI Kit

Declarative AI routes and UI components

The Amplify AI Kit (Amplify Gen 2) defines AI features in the app's data schema, and Amplify creates the backend (AppSync, Lambda, DynamoDB, Bedrock access):

  • Conversation routes (a.conversation): multi-turn chat with a system prompt and tools, history saved per user in DynamoDB, and responses streamed to the client (a Lambda function streams from Bedrock and pushes chunks over an AppSync subscription). Each user sees only their own conversations.
  • Generation routes (a.generation): one request, one structured response, for features such as "write a product description from these fields".
  • Tools let the model query the app's data with the signed-in user's permissions, so it can't read other users' records.
  • React components and hooks (AIConversation, useAIConversation, useAIGeneration) give a working chat UI in a few lines.
A chat route in the data schema (TypeScript) 
const schema = a.schema({
  chat: a.conversation({
    aiModel:
      a.ai.model("Claude 3.5 Haiku"),
    systemPrompt:
      "You are Northwind's support " +
      "assistant.",
  }).authorization(
    (allow) => allow.owner()),
});
The chat screen (React) 
const [
  { data: { messages }, isLoading },
  sendMessage,
] = useAIConversation("chat");

return (
  <AIConversation
    messages={messages}
    isLoading={isLoading}
    handleSendMessage={sendMessage}
  />
);

Models must support tool use through Converse; Claude models work for both route types, and Nova, Llama, Mistral and others for conversations.

API-first with OpenAPI

Describe GenAI capabilities as an OpenAPI contract first, then build to it: API Gateway imports OpenAPI definitions (2.0 or 3.0) to create REST APIs and generates client SDKs; and the same descriptions turn APIs into tools for agents. AgentCore Gateway turns each operation of an OpenAPI 3.0 or 3.1 specification into an MCP tool named by its operationId, so the description fields are what the model reads to decide when to call it.

An operation agents can call as a tool (OpenAPI 3.0) 
openapi: 3.0.0
info:
  title: Orders
  version: "1.0"
paths:
  /orders/{orderId}:
    get:
      operationId: getOrderStatus
      description: >-
        Delivery status of one order. Use
        when a customer asks where an
        order is.
      parameters:
        - name: orderId
          in: path
          required: true
          schema:
            type: string
      responses:
        "200":
          description: The order status

Business system enhancements

Skill 2.5.3Create business system enhancements (for example, by using Lambda functions to implement customer relationship management [CRM] enhancements, Step Functions to orchestrate document processing systems, Amazon Bedrock Data Automation to manage automated data processing workflows)

CRM enhancements

Typical additions to a CRM (customer relationship management system such as Salesforce or HubSpot, where sales and service teams record customers, contacts and cases): summarize a long case history, draft a reply, extract next steps from meeting notes, score and route new leads. The pattern: the CRM's event or webhook (or an EventBridge partner source) triggers a Lambda function, which reads the record through the CRM's API (credentials in Secrets Manager), calls Bedrock, and writes the result back to a field or note. Keep a person in the loop for anything sent to customers.

Contact centers

Amazon Connect (now presented as Amazon Connect Customer) has generative AI built in: AI agents (the former Amazon Q in Connect) that assist agents and customers, and generative post-contact summaries of voice, chat and email contacts, turned on in a flow block, readable through the Contact Lens APIs or a Kinesis stream for your own CRM sync.

Document processing

  1. IngestDocuments land in S3; an event starts a Step Functions workflow.
  2. ExtractBedrock Data Automation with a blueprint (or Textract plus a model) turns each document into fields; a Distributed Map processes large batches in parallel.
  3. Classify and validateA model classifies the document type; rules check required fields, totals and formats; a confidence check flags doubtful results.
  4. ReviewLow-confidence documents wait for a person (a task token and a review screen).
  5. DeliverResults go to the business system; everything is logged for audit.

AWS's open-source GenAI Intelligent Document Processing Accelerator implements this design (Step Functions, Lambda, SQS, DynamoDB) with a choice of Textract-plus-Bedrock or Bedrock Data Automation processing, human review, confidence assessment and evaluation against baselines. Asynchronous BDA jobs report completion through EventBridge, so the workflow doesn't poll.

Developer productivity

Skill 2.5.4Enhance developer productivity to accelerate development workflows for GenAI applications (for example, by using Amazon Q Developer to generate and refactor code, code suggestions for API assistance, AI component testing, performance optimization)

AI coding assistants

Amazon Q Developer

In the IDE, Q Developer's agentic chat reads the project, edits files (showing a diff you can undo) and can run commands: ask it in plain words to generate a function, refactor a module, write unit tests or document code. Inline suggestions complete code as you type, including AWS SDK calls. Code reviews scan for security issues (SAST), secrets, infrastructure-as-code problems, vulnerable dependencies and quality issues. Q Developer also works in the AWS console, including "Diagnose with Amazon Q" for console errors.

Kiro

Kiro, AWS's agentic development environment (IDE and CLI), is the successor for the IDE and CLI experiences. Features that matter for team work:

  • Specs: a feature starts as requirements.md, design.md and tasks.md, reviewed before code is written, then tasks run in order.
  • Steering files (.kiro/steering/) give the agent the project's conventions: product, technology and structure, always included or included for matching files.
  • Hooks run a command or an agent prompt on events such as saving a file or before a tool runs (for example, update tests when code changes).
  • MCP servers give it tools and current documentation, including AWS's documentation and API MCP servers.

Testing AI components

Unit tests shouldn't call a real model: they would be slow, cost money and give different answers each run. Stub the Bedrock client to return fixed responses and errors, so retry, fallback and parsing logic can be tested deterministically; test model quality separately with evaluation sets (Task 5.1).

Test the fallback path without calling Bedrock (Python) 
from botocore.stub import Stubber

stub = Stubber(brt)
# first call throttled, second succeeds
stub.add_client_error(
    "converse",
    service_error_code=
        "ThrottlingException",
    http_status_code=429)
stub.add_response("converse", OK_REPLY)

with stub:
    text, model = answer(messages)
assert model == FALLBACK_MODEL
stub.assert_no_pending_responses()

PerformanceAssistants can suggest optimizations, but measure: time to first token, tokens per request and cost per request from the metrics in Task 4.2.

Advanced applications

Skill 2.5.5Develop advanced GenAI applications to implement sophisticated AI capabilities (for example, by using Strands Agents and AWS Agent Squad for AWS native orchestration, Step Functions to orchestrate agent design patterns, Amazon Bedrock to manage prompt chaining patterns)

Agentic workflow patterns

AWS's prescriptive guidance on agentic AI describes a set of workflow patterns. Workflows (fixed steps you design) are more predictable than fully autonomous agents; use the simplest pattern that solves the problem.

PatternHow it worksExample
Prompt chainingEach step is a separate model call built on the previous output, with checks between stepsExtract facts from a ticket, then draft a reply, then translate
RoutingA first call classifies the request and dispatches it to a specialized pathRefund, how-to and complaint paths
ParallelizationIndependent subtasks run at the same time; results are aggregatedSummarize 50 reviews in parallel, then combine
Orchestrator and workersA central model plans and delegates subtasks to worker agentsA research task split across specialist agents
Evaluator and reflect-refine loopOne model generates, another critiques against criteria, and the draft is revised until it passes or a limit is reachedA policy-compliant reply checked before sending

Implementing them

  • Step Functions: Task states call Bedrock (the optimized InvokeModel integration) for each chain step; a Choice state routes; Parallel or Map states fan out; a loop with a counter implements reflect-refine. Every step is visible and retried individually. AWS provides a prompt-chaining sample project.
  • Bedrock Flows: the same chains and branches built visually.
  • Strands Agents: agents-as-tools for orchestrator-workers, graphs and workflows for structured multi-agent designs (Task 2.1).
  • Agent Squad: a classifier routing each message to one specialist agent (open source, now maintained outside AWS).

"Steps must run in a fixed, auditable order" points to prompt chaining in Step Functions or Flows. "Quality must be checked before output is released" points to an evaluator loop. "Many independent items" points to parallelization with a Map state.

Troubleshooting

Skill 2.5.6Improve troubleshooting efficiency for FM applications (for example, by using CloudWatch Logs Insights to analyze prompts and responses, X-Ray to trace FM API calls, Amazon Q Developer to implement GenAI-specific error pattern recognition)

Querying invocation logs

With model invocation logging sent to CloudWatch Logs (Task 1.6), every request and response is searchable with Logs Insights. Each record has the modelId, the caller (identity.arn), your requestMetadata tags, the request and response bodies (input.inputBodyJson, output.outputBodyJson) and token counts (input.inputTokenCount, output.outputTokenCount).

Tokens and calls per caller (Logs Insights) 
fields identity.arn as principal,
  input.inputTokenCount as inTok,
  output.outputTokenCount as outTok
| stats sum(inTok) as totalIn,
  sum(outTok) as totalOut,
  count() as calls by principal
| sort totalIn desc
Which features hit the output limit (Converse calls) 
fields @timestamp, modelId,
  requestMetadata.feature as feature
| filter output.outputBodyJson.stopReason
    = "max_tokens"
| stats count() as cutOff by feature
| sort cutOff desc

The second query assumes Converse responses, whose output body includes the stop reason; the field path differs for other APIs and native request formats, so check one log record first.

Dashboards and traces

  • CloudWatch generative AI observability has a prebuilt model invocations view (invocations, latency, tokens by model, throttles and errors, with drill-down from a request ID to its logs) and an AgentCore agents view of agent sessions, traces and tool calls.
  • Traces (OpenTelemetry, viewed in CloudWatch; the X-Ray SDKs are in maintenance mode) show each model and tool call as a span with attributes such as the model, operation and token usage (gen_ai.* attributes, which Strands Agents emits).

AI-assisted troubleshooting

CloudWatch investigations gathers related metrics, logs, deployments, CloudTrail events and traces when an alarm fires and suggests root-cause hypotheses; AWS DevOps Agent investigates incidents across AWS and other tools. In the console, Diagnose with Amazon Q explains errors, including IAM permission errors, and in the IDE an assistant can read a stack trace and invocation log excerpts and propose a fix.

SymptomWhere to look first
Answers cut offStop reason max_tokens in invocation logs; maxTokens setting
Intermittent failures at peakThrottle metrics and 429s; concurrency against quota
Slow responsesTraces: model latency versus retrieval and tool time; input token counts
Wrong or odd answers for one featureInvocation logs filtered by its requestMetadata tag: the actual prompt sent
Access deniedCloudTrail error; model, profile and guardrail permissions (Task 2.3)

Key takeaways

  • FM APIs: stream long responses; count tokens (free CountTokens API) and trim or summarize history; handle max_tokens and context-window stop reasons; set timeouts above model latency; go asynchronous when gateways can't wait; retry safely.
  • Accessible interfaces: Amplify AI Kit conversation and generation routes with ready-made React components; OpenAPI contracts for API-first design and agent tools; Bedrock Flows, Unified Studio apps and Amazon Quick Flows for no-code builders.
  • Business enhancements: CRM events to Lambda and Bedrock and back; Amazon Connect generative summaries; Step Functions document pipelines with BDA or Textract, validation and human review (the IDP Accelerator).
  • Productivity: Q Developer agentic chat and code reviews, with Kiro as successor (specs, steering, hooks, MCP); stub Bedrock in unit tests; evaluate quality separately.
  • Patterns: prompt chaining, routing, parallelization, orchestrator-workers and evaluator loops, built with Step Functions, Flows, Strands or Agent Squad.
  • Troubleshoot with Logs Insights over invocation logs (tokens, stop reasons, requestMetadata), CloudWatch GenAI dashboards, OpenTelemetry traces, and AI-assisted investigations.
