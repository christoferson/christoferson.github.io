Overview

Task 4.2

Validate and audit security by using network monitoring and logging services.

Where Task 1.4 and Task 3.2 use logs for operations, this task uses them as evidence: who changed a security group, whether a denied request came through a VPC endpoint, whether every VPC has flow logs, and which accounts have SSH open to the world. Expect questions on log destinations (which service can write where), on delivery rules (prefixes, Regions, accounts), and on which audit tool answers which question.

The travel company's auditors want a year of network logs in a central log archive account, alerts on any security group or route change in production, and monthly evidence that no security group allows SSH or RDP from the internet.

Monitoring and logging services

Knowledge 4.2.1Network monitoring and logging services that are available in AWS (for example, CloudWatch, AWS CloudTrail, VPC Traffic Mirroring, VPC Flow Logs, Transit Gateway Network Manager)

  • CloudWatch: metrics, alarms, logs, Logs Insights and Contributor Insights; the destination for most network logs.
  • VPC, Transit Gateway and Cloud WAN flow logs: who talked to whom and whether it was allowed.
  • Traffic Mirroring: full packets for intrusion detection and forensics.
  • Network Manager: topology and change events for Transit Gateways and Cloud WAN.
  • CloudTrail: the API record of every network change (who, when, from where).

CloudTrail for network auditing

  • Management events record calls such as AuthorizeSecurityGroupIngress, CreateRoute and ModifyVpcEndpoint with the caller, source IP and parameters. Event history keeps 90 days; a trail keeps them in S3 (and optionally CloudWatch Logs).
  • An organization trail (from the management account or a delegated administrator) covers every account, including new ones; member accounts can see but not change it. Its event history in the management account still shows only that account's events.
  • Network activity events (GA February 2025) record API calls made through your VPC endpoints, including calls from other accounts' credentials and calls the endpoint policy denied (errorCode VpceAccessDenied). They are off by default, charged extra, and selected with advanced event selectors per service.
  • Insights flags unusual API call rates or error rates (now for data events as well as management events).
  • Log file integrity validation adds hourly signed digest files to prove logs were not altered.
  • CloudTrail Lake (SQL over event data stores) closed to new customers on 31 May 2026; AWS points new customers to CloudWatch, or Athena over the S3 trail.
Record denied calls to S3 that pass through any of the organization's VPC endpoints (AWS CLI, advanced event selectors) 
aws cloudtrail put-event-selectors --trail-name org-trail \
  --advanced-event-selectors '[{
    "Name": "S3 through VPC endpoints, denied",
    "FieldSelectors": [
      {"Field": "eventCategory", "Equals": ["NetworkActivity"]},
      {"Field": "eventSource",   "Equals": ["s3.amazonaws.com"]},
      {"Field": "errorCode",     "Equals": ["VpceAccessDenied"]}
    ]
  }]'

This shows data perimeter policies working (and who is hitting them) without logging every allowed request. Keep the existing management event selectors in the same call, because the command replaces the trail's selectors.

Alarms

Knowledge 4.2.2Alert mechanisms (for example, CloudWatch alarms)

  • CloudWatch alarms: static thresholds, anomaly detection bands and composite alarms, with SNS, Auto Scaling, EC2, Systems Manager or Lambda actions.
  • Metric filters turn matching log lines (CloudTrail, flow logs, WAF logs) into metrics to alarm on.
  • EventBridge rules act on events directly: CloudTrail API calls, GuardDuty findings, Config compliance changes, Network Manager events, AWS Health.
  • Service alerts: GuardDuty and Security Hub findings, Shield DDoSDetected, Firewall Manager compliance.

Skill 4.2.3Implementing automated alarms by using CloudWatch

The CIS AWS Foundations Benchmark (Security Hub CSPM controls CloudWatch.10 to CloudWatch.14) expects metric filters and alarms on the CloudTrail log group for changes to security groups, network ACLs, network gateways, route tables and VPCs. The trail must deliver to CloudWatch Logs.

Alarm on any security group change in the organization trail's log group (AWS CLI) 
aws logs put-metric-filter --log-group-name org-trail-logs \
  --filter-name security-group-changes \
  --filter-pattern '{ ($.eventName = AuthorizeSecurityGroupIngress) || ($.eventName = AuthorizeSecurityGroupEgress) || ($.eventName = RevokeSecurityGroupIngress) || ($.eventName = RevokeSecurityGroupEgress) || ($.eventName = CreateSecurityGroup) || ($.eventName = DeleteSecurityGroup) }' \
  --metric-transformations metricName=SecurityGroupEventCount,metricNamespace=CloudTrailMetrics,metricValue=1

aws cloudwatch put-metric-alarm --alarm-name security-group-changes \
  --namespace CloudTrailMetrics --metric-name SecurityGroupEventCount \
  --statistic Sum --period 300 --evaluation-periods 1 \
  --threshold 1 --comparison-operator GreaterThanOrEqualToThreshold \
  --treat-missing-data notBreaching \
  --alarm-actions arn:aws:sns:us-east-1:777777777777:security-oncall

The other four filters follow the same shape: CreateNetworkAcl, CreateNetworkAclEntry, DeleteNetworkAcl, DeleteNetworkAclEntry, ReplaceNetworkAclEntry, ReplaceNetworkAclAssociation for ACLs; customer and internet gateway create, attach, detach and delete calls for gateways; route and route table calls; and VPC and peering calls. Metric filters only see events that arrive after they are created.

Which services create which logs

Knowledge 4.2.3Log creation in different AWS services (for example, VPC flow logs, load balancer access logs, CloudFront access logs)

  • VPC flow logs: per VPC, subnet or interface; to CloudWatch Logs, S3 or Firehose.
  • Transit Gateway and Cloud WAN flow logs: per gateway or attachment; same three destinations.
  • ALB: access logs, connection logs (mutual TLS) and health check logs. The original logs go to S3 every 5 minutes; ALB and NLB logs can now also be delivered as CloudWatch vended logs to CloudWatch Logs, S3 (with Parquet) or Firehose.
  • NLB: access logs only for TLS listeners.
  • CloudFront: standard logs (v2 to CloudWatch Logs, S3 or Firehose; legacy to S3) and real-time logs to Kinesis Data Streams.
  • AWS WAF: full request logs to CloudWatch Logs, S3 or Firehose, with name prefix rules.
  • Network Firewall: flow, alert and TLS logs to CloudWatch Logs, S3 or Firehose.
  • Site-to-Site VPN: tunnel and BGP logs to CloudWatch Logs.
  • Global Accelerator: flow logs to S3 only.
  • Route 53: public DNS query logs to CloudWatch Logs in us-east-1 only; Resolver query logs to CloudWatch Logs, S3 or Firehose.
  • Client VPN: connection logs to CloudWatch Logs. Verified Access and VPC Lattice: access logs to CloudWatch Logs, S3 or Firehose.

Field details are on Task 1.4. Most of these are CloudWatch "vended logs", billed by CloudWatch even when delivered to S3.

Log delivery

Knowledge 4.2.4Log delivery mechanisms (for example, Amazon Kinesis, Route 53, CloudWatch)

  • Direct to S3: cheapest long-term store; query with Athena; replicate to the log archive account.
  • CloudWatch Logs: searchable, metric filters and alarms; subscription filters (5 per log group, plus one account-level filter per Region) stream new events to Kinesis Data Streams, Firehose, Lambda or OpenSearch in near real time.
  • Amazon Data Firehose: managed delivery to S3, OpenSearch, Splunk, Redshift or HTTP endpoints, with buffering and transformation. WAF logs to Firehose need a stream named aws-waf-logs-... with Direct PUT as the source, in the web ACL's Region (us-east-1 for CloudFront).
  • Kinesis Data Streams: for real-time consumers; CloudFront real-time logs go only here (sampling 1–100%, per cache behavior). Add Firehose behind it for storage.
  • Route 53 query logging: public zones to CloudWatch Logs in us-east-1; Resolver logs (shareable configurations) to CloudWatch Logs, S3 or Firehose, with S3 recommended at high query rates.

Skill 4.2.6Implementing log delivery solutions

Central log archive account

  • Flow logs, Resolver query logs, WAF logs and Network Firewall logs write straight to an S3 bucket in the log archive account (bucket policy for delivery.logs.amazonaws.com, with conditions on source accounts).
  • Organization trail to the same account.
  • For logs that must be in CloudWatch Logs first, either a cross-account subscription or CloudWatch Logs centralization (September 2025): organization rules copy new log data from chosen accounts and Regions into one account and Region (first copy free, $0.05 per GB for extra copies).
Stream every production VPC's flow log group to a Kinesis stream in the log archive account (AWS CLI; destination in the recipient account, filter in the sender) 
# In the log archive account (777777777777), same Region as the source log groups
aws logs put-destination --destination-name network-logs \
  --target-arn arn:aws:kinesis:us-east-1:777777777777:stream/network-logs \
  --role-arn arn:aws:iam::777777777777:role/cwl-to-kinesis
aws logs put-destination-policy --destination-name network-logs \
  --access-policy file://allow-org.json   # allows logs:PutSubscriptionFilter for aws:PrincipalOrgID

# In each workload account
aws logs put-subscription-filter --log-group-name /vpc/flow-logs \
  --filter-name to-log-archive --filter-pattern "" \
  --destination-arn arn:aws:logs:us-east-1:777777777777:destination:network-logs
Send the booking web ACL's logs to Firehose (AWS CLI) 
aws wafv2 put-logging-configuration --logging-configuration \
  ResourceArn=arn:aws:wafv2:us-east-1:444444444444:regional/webacl/booking-alb/1a2b3c4d-5678-90ab-cdef-111122223333,LogDestinationConfigs=arn:aws:firehose:us-east-1:444444444444:deliverystream/aws-waf-logs-booking

A cross-account subscription destination must be in the same Region as the source log group, and lives in the receiving account. A WAF Firehose stream must be Direct PUT (not reading from Kinesis) and must use the aws-waf-logs- prefix, as must a WAF CloudWatch Logs group.

Creating and analyzing flow logs

Skill 4.2.1Creating and analyzing a VPC flow log (including base and extended fields of flow logs)

The default format has only the version 2 base fields (version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status). A custom format adds extended fields such as vpc-id, subnet-id, instance-id, tcp-flags, pkt-srcaddr, pkt-dstaddr, flow-direction, traffic-path, pkt-src-aws-service, reject-reason and encryption-status. The format cannot be changed after creation: create a new flow log instead.

Flow logs for the payment VPC with audit fields, to the log archive bucket as hourly-partitioned Parquet (AWS CLI) 
aws ec2 create-flow-logs --resource-type VPC --resource-ids vpc-0payment01 \
  --traffic-type ALL --max-aggregation-interval 60 \
  --log-destination-type s3 \
  --log-destination arn:aws:s3:::travel-log-archive/flow-logs/ \
  --destination-options FileFormat=parquet,HiveCompatiblePartitions=true,PerHourPartition=true \
  --log-format '${version} ${account-id} ${vpc-id} ${subnet-id} ${instance-id} ${interface-id} ${srcaddr} ${dstaddr} ${srcport} ${dstport} ${protocol} ${packets} ${bytes} ${start} ${end} ${action} ${tcp-flags} ${pkt-srcaddr} ${pkt-dstaddr} ${flow-direction} ${traffic-path} ${reject-reason} ${log-status}'

For audits, look for ACCEPT records from unexpected sources to card-data subnets, egress with traffic-path 8 (internet gateway) from subnets that should have none, and reject-reason values showing Block Public Access or Encryption Controls at work. Query techniques are on Task 3.2.

Traffic Mirroring for audits

Skill 4.2.2Creating and analyzing network traffic mirroring (for example, using VPC Traffic Mirroring)

Flow logs show metadata only; when an audit or investigation needs payloads (for example confirming that card data never crosses a link unencrypted, or feeding an intrusion detection system), mirror the traffic: filter by protocol, ports and CIDRs, send VXLAN-encapsulated copies to an NLB or Gateway Load Balancer endpoint in a security tooling VPC, and run IDS or capture tools there. Truncate with packet length when only headers are needed. Setup commands and limits are on Task 3.2. Keep captures in an access-controlled, encrypted store, because they can contain sensitive data.

Custom metrics

Skill 4.2.4Implementing customized metrics by using CloudWatch

  • PutMetricData: your own namespace, up to 30 dimensions, standard (1 minute) or high resolution (StorageResolution 1, 1 second); a new metric takes a few minutes to appear.
  • Embedded metric format: write structured JSON log lines (up to 100 metrics per event) and CloudWatch extracts the metrics, useful from Lambda.
  • Metric filters: patterns on space-delimited logs such as flow logs (named fields in brackets) or JSON logs such as CloudTrail ($.field); up to 100 per log group, Standard log class only, not retroactive.
  • CloudWatch agent: ENA allowance counters and other host metrics.
Count rejected SSH attempts in the flow log group, and publish a custom metric of open-to-world rules from an audit script (AWS CLI) 
aws logs put-metric-filter --log-group-name /vpc/flow-logs \
  --filter-name rejected-ssh \
  --filter-pattern '[version, account, eni, source, destination, srcport, destport="22", protocol="6", packets, bytes, windowstart, windowend, action="REJECT", flowlogstatus]' \
  --metric-transformations metricName=RejectedSSH,metricNamespace=TravelNetwork,metricValue=1

aws cloudwatch put-metric-data --namespace TravelNetwork \
  --metric-name OpenToWorldRules --value 0 --unit Count \
  --dimensions Account=444444444444,Environment=prod

The space-delimited pattern only matches the default format; a custom format needs a pattern listing its own fields in order.

Correlating log sources

Skill 4.2.5Correlating and analyzing information across single or multiple AWS log sources

Join keys

  • Addresses: flow log srcaddr and pkt-srcaddr; CloudFront c-ip and x-forwarded-for; ALB client:port (the proxy's address if one is in front; ALB logs have no X-Forwarded-For field); CloudTrail sourceIPAddress and, for network activity events, vpcEndpointId.
  • Request IDs: ALB trace_id (the X-Amzn-Trace-Id header, which also reaches the targets) and conn_trace_id (links connection logs and access logs); CloudFront x-edge-request-id.
  • Time: allow for aggregation windows (flow logs up to 10 minutes, or 1 minute) and delivery delays.

Tools

  • Amazon Security Lake collects CloudTrail, VPC flow logs, Route 53 Resolver logs, WAF logs, EKS audit logs and Security Hub findings across the organization into one S3 data lake in OCSF format (Parquet), queried with Athena or OpenSearch. It takes its own copy of each source except CloudTrail management events, which need a trail.
  • CloudWatch Logs Insights queries many log groups at once (and across accounts from a monitoring account); it now also accepts OpenSearch PPL and SQL, including JOINs across log groups.
  • Athena joins S3 tables of flow logs, ALB logs and CloudTrail.
  • Amazon Detective builds a behavior graph from flow logs, CloudTrail and GuardDuty findings for investigations.
Which source addresses that WAF blocked also reached the booking subnets directly, bypassing the load balancer? (Athena SQL over WAF and flow log tables) 
SELECT f.srcaddr, f.dstaddr, f.dstport, COUNT(*) AS flows
FROM vpc_flow_logs f
JOIN (
  SELECT DISTINCT httprequest.clientip AS ip
  FROM waf_logs
  WHERE action = 'BLOCK'
) w ON f.srcaddr = w.ip
WHERE f.dstaddr LIKE '10.40.12.%'
  AND f.action = 'ACCEPT'
GROUP BY f.srcaddr, f.dstaddr, f.dstport
ORDER BY flows DESC;

A hit means something other than the ALB exposes the booking servers, for example a security group that allows the internet directly.

Auditing network security

Knowledge 4.2.5Mechanisms to audit network security configurations (for example, security groups, AWS Firewall Manager, AWS Trusted Advisor)

Trusted Advisor

  • Security Groups – Specific Ports Unrestricted (free for every support plan): red for open 20, 21, 22, 1433, 1434, 3306, 3389, 4333, 5432 and 5500.
  • Security Groups – Unrestricted Access: any port open to /0 other than 25, 80 and 443; red when the group is not attached to anything.
  • Also: Application Load Balancer security group, Classic Load Balancer Security Groups, ELB Listener Security, Amazon S3 Bucket Permissions, AWS CloudTrail Management Event Logging, VPC peering with DNS resolution disabled.
  • The full set and the organizational view need a higher support plan (Business Support+ or Enterprise).

AWS Config

Records configuration history for security groups, ACLs, route tables, endpoints and gateways; managed rules (restricted-ssh, restricted-common-ports, vpc-sg-open-only-to-authorized-ports, vpc-flow-logs-enabled, vpc-default-security-group-closed, nacl-no-unrestricted-ssh-rdp) evaluate them; conformance packs (for example "Operational Best Practices for PCI DSS 4.0" or "...for Networking and Content Delivery Services") bundle rules; an aggregator gives a read-only view across accounts and Regions; advanced queries search current configuration with SQL.

Firewall Manager

Security group content audit policies flag (and optionally fix) rules outside an allowed template or matching a forbidden one; usage audit policies find unused and redundant groups; network ACL and Network Firewall policies report noncompliant VPCs. Audit policies are created with automatic remediation off, then switched on once reviewed.

Security Hub CSPM

Network controls in the foundational best practices and CIS standards, for example EC2.2 (default security group closed), EC2.6 (flow logs enabled), EC2.13 and EC2.14 (no SSH or RDP from anywhere), EC2.18 (only authorized ports open), EC2.19 (high-risk ports, critical severity), EC2.21 (no ACL ingress from 0.0.0.0/0 to 22 or 3389), EC2.171 (VPN logging), EC2.172 (Block Public Access) and EC2.183 (VPN uses IKEv2).

Skill 4.2.7Implementing a network audit strategy across single or multiple AWS network services and accounts (for example, Firewall Manager, security groups, network ACLs)

  1. Record everythingOrganization trail, Config recorder in every account and Region (an organization-wide aggregator in the audit account), flow logs on every VPC (enforced by a Config rule or Firewall Manager), firewall and WAF logs to the log archive.
  2. Evaluate continuouslySecurity Hub CSPM standards and conformance packs across the organization; Firewall Manager audit policies for security groups and ACLs; Network Access Analyzer scopes for forbidden paths.
  3. Alert on changeCIS metric filters or EventBridge rules for security group, ACL, route and gateway changes in production.
  4. RemediateConfig remediation runbooks or Firewall Manager auto-remediation for well-understood cases; tickets for the rest.
  5. ReportAggregator queries and Security Hub summaries as monthly evidence; Trusted Advisor organizational view for the security checks.
Security groups per account across the organization, and their history for one group (AWS CLI, Config aggregator) 
aws configservice select-aggregate-resource-config \
  --configuration-aggregator-name org-aggregator \
  --expression "SELECT accountId, COUNT(*) WHERE resourceType = 'AWS::EC2::SecurityGroup' GROUP BY accountId"

aws configservice get-resource-config-history \
  --resource-type AWS::EC2::SecurityGroup --resource-id sg-0bookingweb01 --limit 10

Config advanced queries match CIDRs as ranges (a value matches any range that contains it) and test array elements independently, so "open to 0.0.0.0/0" queries can give false positives. For compliance answers, prefer the managed rules or Security Hub controls; use queries to explore.

Key takeaways

  • CloudTrail: management events for every network change; organization trails for all accounts; network activity events (2025) for calls through VPC endpoints, including VpceAccessDenied; Insights; digest files for integrity; CloudTrail Lake closed to new customers (May 2026).
  • Alarms: CIS metric filters on the trail's log group for security groups, ACLs, gateways, routes and VPCs; EventBridge for direct event rules.
  • Log sources and destinations: flow logs (CloudWatch, S3, Firehose), ALB and NLB (S3, now also vended to CloudWatch or Firehose), CloudFront real-time (Kinesis Data Streams only), WAF (aws-waf-logs- names), VPN (CloudWatch), Global Accelerator (S3 only), public DNS (CloudWatch in us-east-1).
  • Delivery: subscription filters (5 per log group) to Kinesis, Firehose or Lambda; cross-account destinations in the receiver's account and same Region; CloudWatch Logs centralization (2025); direct S3 delivery to a log archive.
  • Flow logs: default format is base v2 fields; custom formats add extended fields; format fixed after creation; Parquet with hourly partitions for queries.
  • Custom metrics: PutMetricData (high resolution 1 second), embedded metric format, metric filters (100 per group, not retroactive).
  • Correlation: addresses, ALB trace IDs, CloudFront request IDs; Security Lake (OCSF), Logs Insights SQL joins, Athena, Detective.
  • Audit: Trusted Advisor security group checks (only Specific Ports Unrestricted is free), Config rules, aggregators and conformance packs, Firewall Manager content and usage audits, Security Hub CSPM network controls.
