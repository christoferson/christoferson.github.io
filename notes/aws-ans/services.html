Overview

The exam guide lists about 45 services in ten categories, and says the list is non-exhaustive and subject to change. Several services appear in more than one category: API Gateway sits under front-end, networking and serverless; EventBridge, Lambda, Fargate, SNS, SQS and S3 appear again under serverless. The list is short on the services that carry most of the exam's weight, so the domain text names many more (Gateway Load Balancer, Reachability Analyzer, Transit Gateway Network Manager, ACM, AWS Private CA, Kinesis), and current answers often use services the list never mentions (Cloud WAN, VPC Lattice, Verified Access, IPAM).

Each entry says what the service does for networking on this exam and links to the task sections that explain it. Background means the notes only mention it, or not at all: know in one sentence what it does. The exam itself retires on 31 December 2026, and no ANS-C02 has been announced. The cheat sheet maps question clues to services, and the comparisons page sets similar options side by side.

Application integration

  • Amazon EventBridge: routes Network Manager topology and route changes, Direct Connect and AWS Health events, GuardDuty findings and Config changes to automation; the trigger for event-driven network fixes. 2.4, 3.2, 1.4, 4.1
  • Amazon SNS: notifications from CloudWatch alarms and EventBridge rules, for example a tunnel down or a DDoS detected. 2.4, 4.2, 4.1
  • Amazon SQS: message queues; reached privately through an interface endpoint like any other AWS API. Background.

Compute

  • Amazon EC2: the network interfaces behind everything: ENIs, ENA and EFA, instance bandwidth limits, jumbo frames, placement groups, source/destination check for appliances, Elastic IPs and BYOIP. 3.3, 3.3, 3.2, 1.1
  • Amazon EC2 Auto Scaling: groups registered with load balancer target groups, ELB health checks, and the IP address demand that scaling puts on subnets. 1.3, 3.3
  • AWS Lambda: event-driven network automation, ALB targets, Lambda@Edge on CloudFront, and VPC-attached functions that need ENIs and a NAT path. 2.4, 1.1, 1.3, 3.2

Containers

  • Amazon ECR: image registry that private subnets reach through the ecr.api and ecr.dkr interface endpoints plus the S3 gateway endpoint for image layers. 2.2, 1.6, 3.1
  • Amazon ECS: bridge-mode tasks with dynamic ports and instance targets, awsvpc tasks with their own ENI and ip targets, and built-in blue/green with two target groups. 1.3, 1.3, 3.3
  • Amazon EKS: the VPC CNI and pod IP consumption (prefix delegation, custom networking), the AWS Load Balancer Controller, and network policies. 1.3, 3.3, 1.3
  • AWS Fargate: serverless containers; each task or pod gets its own interface, so load balancers must use ip target groups. 1.3, 1.3

Cost management

  • AWS Cost Explorer: finds data transfer, NAT gateway and Transit Gateway processing charges, and so shows where a peering or endpoint would save money. 2.4, 3.3

Front-end web and mobile

  • Amazon API Gateway: edge-optimized, Regional and private endpoints; private APIs through the execute-api interface endpoint with resource policies; VPC links to private ALBs and NLBs; WAF and mutual TLS. 1.1, 3.1, 4.1, 4.3

Management and governance

  • AWS Auto Scaling: scaling plans across several services; on this exam the scaling that matters is EC2 Auto Scaling behind load balancers. 1.3
  • AWS CLI: the commands in these notes for VPCs, Transit Gateways, Direct Connect, Route 53 and flow logs; most use aws ec2. 1.6, 3.2, 2.2
  • AWS CloudFormation: network infrastructure as code, parameters and mappings instead of hardcoded IDs, StackSets across accounts and Regions, drift detection, custom resources. 2.4, 2.4, 2.4, 2.1
  • AWS CloudTrail: management events for every network change, organization trails, network activity events for calls through VPC endpoints, Insights and digest files. 4.2, 4.2, 4.2
  • Amazon CloudWatch: metrics and alarms for VPN, Direct Connect, Transit Gateway, NAT and load balancers; Logs Insights and Contributor Insights over flow logs; the network monitoring features (Network Synthetic Monitor, Network Flow Monitor, Internet Monitor). 1.4, 1.4, 1.4, 4.2
  • AWS Config: configuration history of security groups, route tables and endpoints, managed and custom rules, conformance packs, aggregators and automatic remediation. 4.2, 2.4, 2.2
  • AWS Control Tower: landing zones with account vending, where network baselines (VPCs, Transit Gateway attachments) are applied to new accounts. 2.4, 2.4
  • AWS Health Dashboard: account-specific events such as Direct Connect and VPN tunnel maintenance, and the Region-specific WAF Classic retirement milestones. 1.4, 2.1, 3.1
  • AWS Management Console: the web interface; a few things are console-only or console-first, such as the new WAF protection pack setup and the Network Manager topology views. Background.
  • AWS Organizations: the account structure that RAM sharing, Firewall Manager, organization trails and SCPs rely on; declarative policies enforce VPC Block Public Access. 2.2, 2.1, 2.2
  • AWS Trusted Advisor: security group, VPN and Direct Connect redundancy and cost checks; the full set needs Business Support+, Enterprise or Unified Operations. 4.2, 2.4
  • AWS Well-Architected Tool: reviews against the pillars; the security pillar asks for a threat model, and the reliability guidance drives redundant hybrid designs. 4.1, 1.5

Networking and content delivery

  • Amazon VPC: subnets, route tables, internet and egress-only gateways, NAT gateways (including Regional NAT gateways), security groups and network ACLs, peering, gateway endpoints, flow logs, Traffic Mirroring, Block Public Access and Encryption Controls. 1.6, 1.6, 3.1, 4.1, 1.4
  • AWS Transit Gateway: the Regional hub for VPCs, VPNs, Direct Connect gateways, Connect (GRE and BGP for SD-WAN) and inter-Region peering; route tables for segmentation, appliance mode, multicast, policy tables and 1:1 NAT for overlapping CIDRs. 1.6, 2.2, 1.5, 3.3, 1.6
  • AWS Direct Connect: dedicated and hosted connections, private, public and transit virtual interfaces, Direct Connect gateways, LAGs, MACsec, SiteLink, BGP communities and the Resiliency Toolkit. 1.5, 1.5, 1.5, 2.1, 3.1
  • AWS Site-to-Site VPN: two IPsec tunnels per connection to a virtual private gateway, Transit Gateway or Cloud WAN; static or BGP routing, accelerated VPN, Large Bandwidth Tunnels, VPN Concentrators, CloudHub and VPN over Direct Connect. 2.1, 1.5, 1.5, 4.3
  • AWS Client VPN: managed OpenVPN-based access for remote users with certificate, Active Directory or SAML authentication, authorization rules and split tunnel. 2.2, 1.6
  • AWS PrivateLink: interface endpoints to AWS services and endpoint services behind an NLB or GWLB; one-way access that tolerates overlapping CIDRs; cross-Region access and resource endpoints. 3.1, 3.1, 1.6, 2.2
  • Elastic Load Balancing (ELB): ALB at layer 7, NLB at layer 4 (now with QUIC), GWLB at layer 3 with GENEVE to appliances, and the legacy CLB; target groups, cross-zone, TLS policies and mutual TLS. 1.3, 1.3, 1.3, 1.3, 3.3
  • Amazon Route 53: public and private hosted zones, routing policies and health checks, DNSSEC, VPC Resolver endpoints and rules, Profiles, DNS Firewall, query logging and domain registration. 1.2, 1.2, 2.3, 2.3, 3.3
  • Amazon CloudFront: edge caching, origin access control, VPC origins, Functions and Lambda@Edge, Anycast static IPs, viewer TLS policies and viewer mutual TLS. 1.1, 1.1, 4.1, 4.3
  • AWS Global Accelerator: two anycast static IPs over the AWS backbone to Regional endpoints (standard) or to specific EC2 addresses and ports (custom routing); traffic dials, endpoint weights, client IP preservation. 1.1, 1.1, 3.3
  • AWS Cloud Map: a service discovery registry that resolves names through DNS or API calls. Background.
  • AWS App Mesh: an Envoy-based service mesh; support ends on 30 September 2026, after which the console and resources can no longer be accessed. Background; know the replacements (Amazon ECS Service Connect, or VPC Lattice for service-to-service networking).
  • Amazon API Gateway: listed here too; see Front-end web and mobile.

Security, identity and compliance

  • AWS Firewall Manager: organization-wide WAF, Shield Advanced, security group, network ACL, Network Firewall and DNS Firewall policies, with audit and automatic remediation. 4.2, 2.2, 4.1
  • AWS Identity and Access Management (IAM): endpoint policies and condition keys such as aws:SourceVpce, cross-account roles for network automation, and authentication for Client VPN and Verified Access. 2.2, 1.6, 4.1
  • AWS Network Firewall: managed stateful and stateless inspection with Suricata rules, domain lists, TLS inspection, centralized or distributed deployment, and native Transit Gateway attachment. 2.2, 4.1, 4.1, 2.2
  • AWS Resource Access Manager (AWS RAM): shares Transit Gateways, subnets (VPC sharing), prefix lists, Resolver rules, Route 53 Profiles, IPAM pools and VPC Lattice service networks across accounts. 2.1, 2.3, 1.6, 1.5
  • AWS Shield: Standard protects every customer at layers 3 and 4 automatically; Advanced adds protection groups, health-based detection, the Shield Response Team and cost protection. 4.1, 1.1, 4.1
  • AWS WAF: layer 7 rules (managed rule groups, rate-based rules, geo and IP sets, Bot Control) on CloudFront, ALB, API Gateway and others; logging to destinations named aws-waf-logs-. 4.1, 1.1, 4.2

Serverless and storage

The serverless category repeats API Gateway, EventBridge, Fargate, Lambda, SNS and SQS (covered above) and adds Amazon S3, which is also the whole storage category.

  • Amazon S3: gateway and interface endpoints with bucket policies on aws:SourceVpce, a CloudFront origin behind origin access control, and the destination for flow logs, load balancer access logs and CloudTrail. 3.1, 1.1, 1.4, 4.2

Named in the domains, not in the list

The task statements name some of these directly, and the rest are the current AWS answer to a skill the guide describes. Expect them in questions.

  • AWS Cloud WAN: a global core network built from a policy document, with segments, edge locations, service insertion and Direct Connect gateway attachments; the managed alternative to peered Transit Gateways. 1.5, 1.6, 2.2
  • Amazon VPC Lattice: application-layer service networks across VPCs and accounts, with auth policies, overlapping CIDRs allowed, and resource configurations for databases and other TCP resources. 1.6, 1.6, 3.1
  • AWS Verified Access: VPN-less access to private applications, checking identity and device posture on every request; now also TCP, SSH and RDP. 2.2, 4.1
  • Amazon VPC IP Address Manager (IPAM): pools and allocation rules across the organization, overlap detection, BYOIP, and private IPv6. 1.6, 2.4, 3.3
  • AWS Network Manager: the console that holds Cloud WAN and Global Networks for Transit Gateways (the guide's "Transit Gateway Network Manager"): topology, route analysis, events and SD-WAN device registration. 1.4, 3.2
  • Route Analyzer: part of Network Manager; checks Transit Gateway routes between two addresses, including across peered gateways. 2.1, 1.4
  • VPC Reachability Analyzer: static configuration analysis of the path between a source and destination, naming the blocking component. 1.4, 3.2, 2.1
  • Network Access Analyzer: finds paths that break an access scope you define, such as "no internet path to the database subnets". 4.1, 3.2, 4.2
  • VPC Flow Logs and Traffic Mirroring: metadata for every accepted or rejected flow, and full packet copies to an analysis target. 1.4, 4.2, 4.2, 3.2
  • Gateway Load Balancer: inline third-party appliances with GENEVE on port 6081, GWLB endpoints, flow stickiness and appliance mode on the Transit Gateway. 2.2, 1.3, 4.1
  • AWS Load Balancer Controller: creates ALBs from Kubernetes Ingress and NLBs from Services, with ip or instance targets. 1.3
  • AWS Certificate Manager (ACM): free public certificates (now 198 days) with DNS validation and managed renewal, plus exportable and ACME certificates. 4.3, 1.3
  • AWS Private Certificate Authority: private CA hierarchies in general-purpose or short-lived mode, for internal TLS, mutual TLS and Client VPN certificates. 4.3, 2.1
  • Amazon Kinesis and Amazon Data Firehose: stream flow logs, WAF logs and Resolver query logs to S3, OpenSearch or partner tools. 4.2, 1.4
  • AWS CDK and AWS SDKs: network infrastructure in a programming language that synthesizes to CloudFormation; SDK scripts for automation. 2.4
  • Amazon GuardDuty, AWS Security Hub CSPM and Amazon Detective: threat findings from flow logs and DNS logs, network controls, and investigation. 4.1, 4.2, 4.2
  • Amazon Athena: SQL over flow logs and other logs in S3. 3.2, 4.2
  • AWS Secrets Manager and AWS KMS: VPN pre-shared keys in Secrets Manager; KMS keys for DNSSEC signing and log encryption. 2.1, 2.3
  • Amazon Application Recovery Controller (ARC): routing controls behind Route 53 health checks, zonal shift and Region switch. 1.2, 3.3
  • Route 53 Global Resolver: an internet-reachable resolver for branch and remote clients (Do53, DoH, DNS over TLS), generally available since 9 March 2026. 4.3, 2.2
  • AWS Systems Manager: Automation runbooks for remediation, for example closing an open security group port. 2.4

App Mesh is still on the in-scope list. The list was not updated when support ended. If a question offers App Mesh for new service-to-service traffic management, prefer ECS Service Connect for ECS workloads or VPC Lattice for cross-VPC and cross-account service networking.

Renamed services

Old names still appear in questions, blog posts and the guide itself. Same service, new name:

  • Route 53 Resolver is now Route 53 VPC Resolver in the documentation, renamed when Route 53 Global Resolver arrived; the API and CLI namespace is still route53resolver and the metrics namespace AWS/Route53Resolver. Older material also says Amazon DNS server or AmazonProvidedDNS.
  • AWS Security Hub (the posture checks and controls) is now AWS Security Hub CSPM; the name Security Hub now belongs to the newer findings correlation service.
  • Route 53 Application Recovery Controller is now Amazon Application Recovery Controller (ARC); the API namespaces still start with route53-recovery.
  • The new AWS WAF console calls web ACLs protection packs; the documentation says "protection pack (web ACL)", and they're the same WAFv2 web ACLs in the API.
  • Transit Gateway Network Manager is documented as AWS Global Networks for Transit Gateways inside the Network Manager console (since November 2022).
  • Amazon CloudWatch Network Monitor is now Network Synthetic Monitor, renamed when Network Flow Monitor launched (around December 2024).
  • The AWS ALB Ingress Controller is now the AWS Load Balancer Controller.
  • Asking AWS Support to pre-warm a load balancer is replaced by Capacity Unit Reservation.
  • Trusted Advisor checks were renamed: "ELB Security Groups" is now "Classic Load Balancer Security Groups", and "AWS CloudTrail Logging" is now "AWS CloudTrail Management Event Logging".

Out of scope

The guide's out-of-scope list, verbatim by category:

  • Analytics: Amazon CloudSearch; AWS Data Exchange; AWS Data Pipeline; Amazon EMR; AWS Glue; AWS Lake Formation; Amazon Managed Streaming for Apache Kafka (Amazon MSK); Amazon OpenSearch Service; Amazon QuickSight; Amazon Redshift
  • AR and VR: Amazon Sumerian
  • Blockchain: Amazon Managed Blockchain; Amazon Quantum Ledger Database (Amazon QLDB)
  • Developer Tools: AWS Device Farm; AWS X-Ray
  • Robotics: AWS RoboMaker
  • Satellite: AWS Ground Station

Out of the list isn't out of the exam. OpenSearch Service is out of scope as a service, but it still appears as a log destination for Firehose; the networking around a service (its endpoints, security groups and DNS) can be tested even when the service itself is not.
