All architectures

Grouped by theme, using the same travel company as the task pages. Each page stands alone. See also the official blogs and references.

Transit Gateway and global networks

  • Transit Gateway hub and spoke with segmentation: A shared Transit Gateway per Region with production, development, shared services and on-premises route tables across many accounts.
  • Centralized egress with NAT gateways and Network Firewall: Spokes reach the internet through one egress VPC per Region, filtered by domain, with the cost trade-offs of centralizing NAT.
  • Multi-Region network: Transit Gateway peering or Cloud WAN: Three Regions joined by Transit Gateway peering with static summaries, compared with a Cloud WAN core network and segments.

Inspection and perimeter

  • Centralized inspection with Gateway Load Balancer: Third-party firewalls behind a Gateway Load Balancer inspect east-west, egress and inbound traffic with appliance mode and ingress routing.
  • Inbound perimeter: CloudFront, WAF, ALB and inspection: The public booking platform behind CloudFront, AWS WAF and Shield Advanced, with a locked-down origin and optional IDS/IPS.

Hybrid connectivity

  • Resilient hybrid connectivity with Direct Connect: Four connections in two locations, transit VIFs to one Direct Connect gateway, BGP communities, VPN backup and SiteLink.
  • Encrypted hybrid connectivity: MACsec and private IP VPN: Card data over Direct Connect encrypted with MACsec or IPsec over a transit VIF, and proving it with Encryption Controls.
  • SD-WAN integration with Transit Gateway Connect and Cloud WAN: SD-WAN headends peering over GRE and BGP with Transit Gateway Connect, Cloud WAN Tunnel-less Connect, and small branches on a VPN Concentrator.

Services, DNS and addressing

  • Hybrid and multi-account DNS: Resolver endpoints in a shared services VPC, forwarding rules and Profiles shared to every account, and on-premises forwarders.
  • Shared interface endpoints and a data perimeter: One set of interface endpoints for every VPC, distributed through private hosted zones, with endpoint and bucket policies forming a perimeter.
  • Connecting overlapping networks: An acquired company that uses 10.0.0.0/16 everywhere, connected with PrivateLink, a private NAT gateway or Transit Gateway 1:1 NAT.
  • Global edge: CloudFront and Global Accelerator across Regions: Users and partners worldwide enter at the AWS edge, with origin failover, traffic dials and health-checked endpoint groups in three Regions.
