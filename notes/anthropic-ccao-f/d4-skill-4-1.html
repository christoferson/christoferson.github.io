Overview

Skill 4.1

End-to-End Deliverable Workflows: "Applying Claude across the lifecycle of a research, analysis, or planning deliverable, including requirements analysis, research with cited sources, data analysis through code execution, and synthesis into an actionable plan."

Exam items describe a deliverable part-way through and ask which stage is missing or done badly, or which feature a stage needs. Breaking big work into staged prompts in general is skill 1.2; this skill applies that to the four specific stages of a research, analysis or planning deliverable, each with the right capability.

Run a deliverable as four checked stages in one Project

Skill 4.1One Project, four stages, a check after each.

Take owners who want a recommendation on whether to start renting out camping gear at two stores next spring, and a 90-day plan if the answer is yes.

rental_deliverable.txt (Rental decision workflow) 
Deliverable: a recommendation to the owners on whether to start camping-gear
rental at two stores next spring, with a 90-day plan if the answer is yes.
All four stages run in one Project, "Gear rental decision".

STAGE 1 - Requirements (chat)
I need to recommend to the shop's two owners whether to start camping-gear
rental at our two largest stores next spring. Before any research, help me
pin down the requirements: what the owners must know to decide, which
questions need outside evidence and which need our own data, what would make
the answer "no", and what the final document should contain. Ask me up to
five questions first.
  -> Check: the owners agree with the list of questions before you go on.
     Save the agreed requirements to Project knowledge.

STAGE 2 - Research with cited sources (Research)
Using the requirements in Project knowledge, research how outdoor retailers
run gear rental: typical items rented, pricing models, damage and deposit
policies, insurance, and published examples from the last three years.
Cite every claim. Mark anything you could only find in one source.
  -> Check: open the citations behind the claims the decision depends on;
     replace any that are weak or out of date.

STAGE 3 - Data analysis (code execution)
Attached: sales_2024_2026.csv (tents, sleeping bags, stoves by store and
month) and returns.csv. Using Python, calculate for each store: monthly
units of the 20 items most likely to be rented, seasonality, and the return
rate for those items. Show the code and a chart. Don't estimate any figure
you can't calculate from the files; list what's missing instead.
  -> Check: rerun one total yourself in the spreadsheet; confirm the
     columns were read correctly.

STAGE 4 - Synthesis into an actionable plan (artifact)
Using the checked research and analysis, write a two-page recommendation as
a document: the decision and the main reasons, the evidence for and against
(with citations), the figures from the analysis, the risks, and, if the
recommendation is yes, a 90-day plan with owners, dates and the one measure
that would tell us to stop.
  -> Check: every figure traces to Stage 3 and every claim to a Stage 2
     source; a person signs off before it goes to the owners.

Each stage uses the capability that suits it (skill 3.1): a chat for requirements, Research for evidence, code execution for figures, an artifact for the final document. Running all four in one Project keeps the agreed requirements and checked results available to each later stage without pasting them again.

Settle what the deliverable must answer before producing anything

Skill 4.1Deciding what the deliverable must answer before producing anything.

  • What to settle: who decides, the questions they need answered, what evidence would change the answer, the constraints (budget, dates, policy), and the form of the final document.
  • Use Claude to find gaps: ask it to list the questions a decision-maker would ask and to ask you clarifying questions first. That surfaces missing requirements while they're cheap to fix.
  • Split the evidence: mark which questions need outside research and which need your own data, which decides the next two stages.
  • Confirm, then save: agree the list with the people who'll use the result, and save it to Project knowledge so later stages work from the same version.

Gather outside evidence with citations you can check

Skill 4.1Outside evidence you can check.

  • Web search or Research: web search grounds an answer in live web content, and every response includes citations. Research (paid plans) runs several searches that build on each other and decides what to look into next, across the web and connected apps.
  • Setting it up: web search must be on; choose Research from the "+" menu. Research runs on Opus 5.5 whichever model you've selected, and uses limits faster than a normal chat.
  • Know its blind spots: on mobile, Research searches only the web and gives no sign that your connectors were skipped. It also can't use local MCP servers set up in Claude Desktop.
  • Check the citations: the Help Center's advice is to cross-reference cited sources and use authoritative sources for critical decisions. Open the sources behind the claims the decision rests on, not every one (skill 2.2).

Calculate your own figures with code execution, and check its inputs

Skill 4.1Your own figures, calculated rather than estimated.

  • How: with code execution and file creation turned on, upload the CSV or spreadsheet and ask Claude to calculate with Python and show the code. It can also produce charts and Excel files.
  • Say what not to do: tell Claude not to estimate figures it can't compute from the files, and to list what's missing instead.
  • Check the inputs: confirm Claude read the right columns and date ranges, and recheck one total by hand. Code calculates exactly whatever it was given, including the wrong column.

Choosing exact calculation over prose figures is covered in skill 2.4.

Lead with the decision, then a plan with owners, dates and measures

Skill 4.1From evidence to a decision and next steps.

  • Lead with the decision: the recommendation and the main reasons first, then the evidence for and against.
  • Make it actionable: a plan needs owners, dates, the resources required, and a measure that tells you whether it's working, or when to stop.
  • Keep it traceable: every figure comes from the analysis stage and every outside claim keeps its citation, so a reader can check anything that matters.
  • Deliver in the right form: an artifact or a document file for something people will read and edit (skill 2.4), and a person signs off before it goes to the decision-makers.

Each typical fault has a specific fix

Skill 4.1Typical faults and the fix for each.

  • Skipping requirements: Research answers a question nobody asked. Fix: agree the questions first.
  • Uncited or unchecked research: claims in the final plan can't be traced. Fix: keep citations and check the important ones.
  • Figures written, not calculated: totals in the plan don't match the data. Fix: code execution on the source files.
  • Analysis without synthesis: a pile of findings with no decision, owners or dates. Fix: ask for the recommendation and a plan explicitly.
  • Doing it all in one prompt: no chance to check anything between stages. Fix: separate stages with a check after each.

"Ask Research to produce the final plan in one go" skips the requirements, your own data and the checks. Research is one stage of the deliverable, not the whole of it.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
Research returned a thorough report that answers a question the owners didn’t ask. Which stage was skipped?
  1. A. Synthesis
  2. B. Requirements analysis
  3. C. Data analysis
  4. D. Delivery
Answer
B
Why
Agree the questions first.
Question 2
Scenario
A plan’s totals don’t match the sales data. What should the analysis stage use?
  1. A. Prose estimates
  2. B. Code execution on the source files, with the inputs checked
  3. C. Research
  4. D. Memory
Answer
B
Why
Figures should be calculated, not written.
Question 3
Scenario
A final report lists findings but no decision, owners or dates. What is missing?
  1. A. More research
  2. B. Synthesis into a recommendation and an actionable plan
  3. C. Citations
  4. D. A chart
Answer
B
Why
Analysis without synthesis isn’t actionable.

  1. A. Nothing

  3. C. It used memory

Key takeaways

  • The lifecycle is requirements, research with citations, data analysis with code, and synthesis into a plan, with a check at each hand-off and the work kept in one Project.
  • Requirements: who decides, the questions, the constraints and the output form; have Claude ask clarifying questions; save the agreed version.
  • Research: web search answers include citations; Research runs chained searches on paid plans (always on Opus 5.5, web only on mobile); check the sources the decision rests on.
  • Analysis: calculate with code on the real files, show the code, list what's missing instead of estimating, and recheck the inputs.
  • Synthesis: decision first, then evidence, risks and a plan with owners, dates and a stop measure; traceable figures and citations; human sign-off.
