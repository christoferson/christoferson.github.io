Overview

Skill 3.3

Context and Memory Management: "Applying context and memory management to long or multi-session work, including when to restart, summarize, persist to a Project, or rely on memory, and maintaining memory quality through review, edits, deletions, and incognito chats."

Exam items describe work that has drifted, or that spans many sessions, and ask what to do with its context. What memory and Projects are is in skill 3.1; restarting because a prompt itself was wrong is in skill 1.3. This skill is about managing context over time.

A long chat rarely stops, but it may no longer be the best place for the work

Skill 3.3The context window and automatic context management.

  • Size: on paid plans, chat with the current models (Fable 5.2, Opus 5.5, Sonnet 5.5, Haiku 5.5) has a 1M-token context window; some older models have 500K or 200K.
  • Near the limit: for paid users with code execution turned on, Claude summarises earlier messages to make room, so conversations can continue "indefinitely in most cases". The full history is kept for Claude to refer to. Very large first messages can still hit the limit.
  • The cost: conversation length is one of the factors in usage, and chats that trigger this summarising use more of your limit. Tools and connectors are "token-intensive", so turning off ones you don't need frees context.

So a long chat rarely stops. The question is whether it's still the best place for the work. Signs that it's time to restart:

  • the topic has changed, so earlier material is now noise;
  • the chat holds rejected drafts, wrong figures or corrections that Claude keeps returning to;
  • you're repeating instructions Claude used to follow;
  • you want a clean start for a different audience or task.

Restart, summarise, persist to a Project or rely on memory, depending on what must carry over

Skill 3.3Restart, summarise, persist to a Project, or rely on memory.

  • Restart with nothing: a new chat for a new, unrelated task. Nothing from the old chat is needed.
  • Restart with a summary: the work continues, but the chat is cluttered. Ask Claude for a summary of decisions and open items, check it, and paste it into a new chat (below).
  • Persist to a Project: for ongoing work that will need the same documents and decisions again. Project knowledge is available in every chat in the Project, uses retrieval so only relevant parts are loaded, and reused documents count less against usage limits than new uploads. Keep Project instructions short: role, key rules and general context.
  • Rely on memory: for lasting facts about you and how you work (your role, audiences, style) rather than the details of one piece of work. Paid plans can also search past chats, so you can ask Claude to find an earlier conversation instead of re-explaining it.

"Ask memory to keep the plan" is a weak answer for detailed working material: memory holds topics and preferences, while exact figures, versions and documents belong in Project knowledge, where they can be reviewed and replaced. The opposite mistake is uploading a "how I like my reports" file to every Project when it's really a preference for memory.

Hand over with a checked summary of decisions and open items

Skill 3.3Moving the useful part of a long chat somewhere cleaner.

Take three weeks of planning next year’s store openings with Claude, across one very long chat and several shorter ones.

handover.txt (Handover summary) 
1. In the long chat, before you leave it:

Summarise this conversation so I can continue in a new chat.
Include: the goal, the decisions we made and why, the figures we agreed on
(with the file each came from), what is still open, and the next step.
Leave out options we rejected unless the reason matters later.
Under 300 words, as headed bullet points.

2. Check the summary yourself: wrong figures or missing decisions get copied
   forward, so fix them now.

3. Then put it where the next session will find it:

   one more session, same topic   paste it as the first message of a new chat
   ongoing work                    add it to the Project's knowledge as
                                   "Store-openings plan - decisions to 20 Nov"
   a lasting preference only       tell Claude to remember it (memory)

The check in step 2 matters most: a summary copies mistakes forward as confidently as it copies decisions. Naming and dating a summary in Project knowledge also makes it easy to replace when the plan changes, so old versions don't linger alongside new ones.

Review memory, edit or delete stale topics, and keep workstreams apart

Skill 3.3Review, edit and delete.

  • Review: in Settings, under Your Claude > Manage, memory is listed as topics. Look through them now and then, and especially when answers start assuming things that are no longer true (an old role, a finished project).
  • Edit or delete: change or remove a topic there, or ask Claude in a chat to update or forget something.
  • Deleting a chat isn't enough: memories made from a conversation stay after the chat is deleted, so remove the memory itself.
  • Pause or reset: pausing stops new memories and keeps existing ones; resetting permanently deletes all memories, including Project memories.
  • Keep workstreams apart: each Project has its own memory. Turning off "Use account memory" for a Project stops your general memory flowing into it, which suits work for separate teams or clients that mustn't mix.

Use incognito or memory-off chats for conversations that shouldn't shape later answers

Skill 3.3Keeping a conversation out of memory from the start.

  • Incognito chats (the ghost icon, on all plans) aren't saved to chat history or memory and aren't found by chat search. They suit one-off, sensitive or unrelated conversations that shouldn't shape later answers.
  • Not a deletion guarantee: on Team and Enterprise, incognito chats are still included in data exports and kept for at least 30 days.
  • Memory off for one chat: you can also turn memory off for a single conversation from the "+" menu.

Practice questions

Exam-style questions written for these notes. Decide your answer before reading the explanation.

Question 1
Scenario
A chat holds rejected drafts and wrong figures that Claude keeps returning to. What helps?
  1. A. Keep going
  2. B. Start a new chat with a checked summary of decisions and open items
  3. C. Turn on memory
  4. D. Use a bigger model
Answer
B
Why
A fresh start without the clutter, carrying only what’s confirmed.
Question 2
Scenario
Where should exact figures and documents for a long-running plan live?
  1. A. Memory
  2. B. Project knowledge, where they can be reviewed and replaced
  3. C. The first message
  4. D. An incognito chat
Answer
B
Why
Memory holds topics and preferences, not detailed working material.
Question 3
Scenario
A user deletes a chat, but Claude still remembers a fact from it. Why?
  1. A. A bug
  2. B. Memories made from a conversation remain after the chat is deleted; remove the memory itself
  3. C. Caching
  4. D. Projects
Answer
B
Why
Delete the memory topic, or ask Claude to forget it.
Question 4
Scenario
Is an incognito chat on Team or Enterprise a deletion guarantee?
  1. A. Yes
  2. B. No; it is kept for at least 30 days and included in data exports
  3. C. Only on mobile
  4. D. Only with memory off
Answer
B
Why
Incognito keeps it out of history and memory, not out of retention.

Key takeaways

  • Current models have a 1M-token chat context; near the limit Claude summarises earlier messages (paid plans, code execution on), so chats rarely stop, but long chats use more of your limits.
  • Restart when the topic changes or the chat is full of rejected material; carry work forward with a checked summary.
  • Persist ongoing documents and decisions to a Project (shared across its chats, retrieved as needed, cheaper to reuse); keep lasting preferences in memory.
  • Review memory topics, edit or delete stale ones, and remember that deleting a chat doesn't delete its memories; reset deletes everything, including Project memories.
  • Use incognito or memory off for chats that shouldn't shape later ones, and turn off "Use account memory" to keep a Project separate.
