1.3: Prompt Diagnosis and Iteration

When Claude's answer misses: working out which part of the request caused it, fixing that part rather than adding complaints, and knowing when to keep refining, when to start again and when to try a different approach.

Overview

Skill 1.3

Prompt Diagnosis and Iteration: "Analyzing an underperforming prompt and its output to attribute the deficiency to a specification gap, including missing context, ambiguous instruction, absent constraint, or wrong strategy for the task type, and judging when to iterate, restart, or change approach."

Exam items show a prompt and a disappointing result, and ask what caused it and what to do next. The key word is attribute: name the gap before choosing the fix. The parts of a good prompt are in skill 1.1; judging whether output is right, as opposed to why it went wrong, is Domain 2.

Sources: Anthropic's prompting best practices and prompt-engineering blog post, the AI Fluency course page, and the Claude Code best-practices advice on restarting, checked on 8 and 20 November 2026 and paraphrased. The cases are my own.

Running example. Staff across the outdoor-gear shop bring their disappointing Claude results to the team's internal AI champion: a generic product description, the wrong kind of contract summary, an update too long to read, and sales figures that don't match.

Four specification gaps

Skill 1.3The guide's categories, and what each looks like.

  • Missing context: Claude didn't have the facts, audience or background. The output is generic, or confidently fills blanks with plausible inventions.
  • Ambiguous instruction: the request had several reasonable readings, and Claude chose one you didn't mean. The output is good, but of the wrong thing.
  • Absent constraint: nothing limited length, format, tone or scope. The content is right, but unusable as delivered.
  • Wrong strategy for the task type: the method doesn't suit the work, for example a calculation answered by reading rather than computing, or current facts asked for without searching. The output looks plausible but is unreliable in a systematic way.

All four are gaps in the request, not faults to complain about. Each points to a specific edit.

Four worked diagnoses

Skill 1.3Symptom, gap, fix.

diagnoses.txt (Diagnosis notes) 
Case 1 - generic output
  Prompt:   "Write a product description for our new tent."
  Output:   Fluent, but could describe any tent; invents a weight and a "lifetime guarantee".
  Gap:      MISSING CONTEXT - no specifications, audience or brand voice; Claude filled the
            blanks with plausible guesses.
  Fix:      Attach the spec sheet, name the audience (first-time backpackers), give one example
            description in the house style, and say "use only the spec sheet; flag missing details".

Case 2 - the wrong kind of summary
  Prompt:   "Summarise this supplier contract."
  Output:   A neat overview of what the contract is about.
  Wanted:   The obligations and deadlines the shop has to meet.
  Gap:      AMBIGUOUS INSTRUCTION - "summarise" has several reasonable readings.
  Fix:      "List every obligation on us, with its deadline and clause number, as a table."

Case 3 - right content, unusable form
  Prompt:   "Draft the weekly update for the store managers."
  Output:   Three pages of headed sections; managers read it on their phones between shifts.
  Gap:      ABSENT CONSTRAINT - no length, format or reading context.
  Fix:      "Five bullet points, under 120 words, most urgent first; managers read it on a phone."

Case 4 - confident numbers that don't match the spreadsheet
  Prompt:   "Here's the sales export. What were our best-selling categories last quarter?"
  Output:   A ranked list with totals that are slightly off.
  Gap:      WRONG STRATEGY FOR THE TASK TYPE - a calculation done by reading, not computing.
  Fix:      Ask for the totals to be calculated with code from the file, with the calculation
            shown, then check one total by hand.

Each fix changes the request, not the tone of the follow-up. "Make it less generic" or "that's wrong, try again" gives Claude no new information, so the next attempt is a different guess. Adding the spec sheet, defining "summary", stating the length or switching to calculation removes the cause.

Reading the output for clues

Skill 1.3What the result tells you about the request.

  • Specifics you never gave (a weight, a guarantee, a statistic): Claude was filling a gap. Add the source, and allow "not stated" as an answer.
  • Correct but beside the point: the instruction was open to interpretation. Rewrite it so it has one reading.
  • Too long, wrong format, wrong tone: a constraint is missing. State it, with the reason.
  • Close but systematically off (totals slightly wrong, dates outdated): the method is wrong for the task. Change strategy.
  • Varies a lot between tries: the request leaves too much open. Add an example of what you want.
  • Apply the colleague test: Anthropic suggests asking whether a capable colleague with no background could follow the prompt. If they'd ask "which kind of summary?" or "for whom?", that question names the gap.

Iterate, restart or change approach

Skill 1.3Three responses to a miss.

  • Iterate in the same chat when the output is close and the gap is small: one missing constraint, one wrong emphasis. Name the change precisely ("cut to five bullets, most urgent first").
  • Restart in a fresh chat with a rewritten prompt when corrections are piling up, the conversation has drifted, or the first attempt went down the wrong path. Each failed attempt stays in the conversation and keeps influencing the next. Claude Code's guidance makes the same point for coding sessions: after a couple of failed corrections, clear and begin again with a better prompt. Rewrite the original request with what you've learned rather than adding more corrections.
  • Change approach when the method itself is wrong, not the wording:
    • calculate with code instead of reading;
    • use Research instead of Claude's general knowledge;
    • split the work into stages (skill 1.2);
    • attach the source;
    • or decide the task needs a person.
    More rewording won't fix a strategy problem.

"Ask Claude to try harder" or "tell it the answer was wrong" is the common wrong answer. Without new information or a changed method, the next attempt has nothing to go on.

The Description–Discernment loop

Skill 1.3The AI Fluency framing of this skill.

Anthropic's AI Fluency course pairs two of its competencies in what it calls the Description–Discernment loop:

  • Description: how you tell Claude what you want.
  • Discernment: how you judge what comes back.

Diagnosis is the link between them. Discernment notices that the output falls short; diagnosis asks which part of the description caused it; the next description fixes that part. Each turn of the loop should make the request more specific, not just repeat it more forcefully.

Key takeaways

  • Attribute the miss to a gap before fixing it: missing context, ambiguous instruction, absent constraint, or the wrong strategy for the task type.
  • Read the output for clues: invented specifics (missing context), right-but-beside-the-point (ambiguity), unusable form (no constraint), systematically off (wrong method), high variation (needs an example).
  • Fix the request, not the tone: "try again" adds no information.
  • Iterate for small gaps; restart in a fresh chat with a rewritten prompt when corrections pile up; change approach when the method is wrong.
  • In AI Fluency terms this is the Description–Discernment loop: judge the output, find the gap in the description, refine it.
