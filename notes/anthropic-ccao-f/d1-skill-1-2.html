1.2: Task Decomposition and Sequencing

Handling work that's too big or too mixed for one request: splitting it into steps, giving each step the approach that suits it, keeping the materials in a Project, and checking each result before building on it.

Overview

Skill 1.2

Task Decomposition and Sequencing: "Applying task decomposition to deliverables too large or multifaceted for a single request, including staged prompts, follow-ups, Project workflows, prompting-strategy differences by task type, and validation checkpoints between steps."

Exam items describe a big deliverable and ask how to split it, what order to work in, or where a check belongs. Writing each individual prompt well is skill 1.1. Turning a sequence you repeat into a reusable workflow is skill 4.3, and setting up the Project itself is skill 5.1.

Sources: Anthropic's prompting best practices and prompt-engineering blog post, and the Claude Help Center articles on Projects and Research, checked on 20 November 2026 and paraphrased. The staged plan is my own.

Running example. An operations analyst at the outdoor-gear shop has to produce the quarterly customer-insights report for leadership: return-rate figures, themes from 300 survey comments, and recommendations.

When one request isn't enough

Skill 1.2Signs a deliverable needs splitting.

  • It mixes kinds of work: calculating, reading and grouping, and persuasive writing each need different instructions. One prompt that asks for all three gets a compromise.
  • It's long: a multi-page document written in one go is harder to steer and to check, so problems surface only at the end.
  • Later parts depend on earlier answers: the recommendations depend on which themes turn out to matter.
  • You need to check things along the way: numbers that must be right before anything is written about them.

Anthropic's guidance calls this prompt chaining: a sequence of prompts, each doing one part. It's slower than one request, but each step is easier, so the result is more accurate.

A staged plan

Skill 1.2Five stages, each with its own check.

staged_plan.txt (Staged plan with prompts) 
Deliverable: the quarterly customer-insights report for the leadership meeting (about 8 pages).
Too big for one request: it mixes data analysis, reading 300 survey comments, and persuasive writing.
Workspace: a Project called "Q4 insights" holding the survey export, the returns data and last
quarter's report (for structure only). Project instructions: audience = leadership team; plain
English; every number must trace to the attached data.

Stage 1 - analysis (code-executed analysis)
  "Using returns_q4.csv, calculate the return rate by product category and month, and chart the
   three categories with the biggest change since Q3. Show the calculations you ran."
  CHECKPOINT: spot-check two numbers against the spreadsheet yourself before going on.

Stage 2 - themes (reading and grouping)
  "Read the 300 comments in survey_q4.csv. Group them into at most six themes, give a count and
   two verbatim quotes for each, and list comments you couldn't place."
  CHECKPOINT: read ten comments at random and check they sit in the right theme.

Stage 3 - outline (structure before prose)
  "Using the confirmed figures from stage 1 and the themes from stage 2, propose an outline:
   headline finding, three sections, one recommendation each. No full text yet."
  CHECKPOINT: agree the outline with your manager; change it now, not after drafting.

Stage 4 - draft, one section at a time
  "Write section 1 from the agreed outline, under 400 words, using only the figures and quotes
   above. Mark any sentence that isn't directly supported."
  CHECKPOINT: review each section before asking for the next.

Stage 5 - assemble and check
  "Combine the approved sections, write a one-paragraph summary, and list every number in the
   report with the stage it came from."
  CHECKPOINT: compare the number list with stage 1's output.
  • Facts before words: figures and themes are settled first, then the outline, then the prose. Mistakes are cheapest to fix at the earliest stage.
  • Structure before prose: agreeing an outline avoids rewriting eight pages because the order was wrong.
  • One section at a time keeps each request focused and each review short.
  • Each stage consumes the confirmed output of the last, not Claude's memory of it. The final stage lists every number and the stage it came from.

Follow-ups or a new step

Skill 1.2Continue the conversation, or start a fresh chat.

  • Follow up in the same chat when you're refining the current piece: "shorter", "add the Q3 comparison", "use the second quote instead". Claude has the context it just used.
  • Start a fresh chat for a new stage when the old conversation is long, went down a wrong path, or is about something else. Bring forward only the confirmed results, such as the agreed figures or the outline, not the whole history. A clean start avoids carrying over abandoned ideas.
  • Say what's settled: "these figures are confirmed; don't recalculate them" stops Claude reopening decisions.

Running it in a Project

Skill 1.2A workspace that holds the materials and the rules.

  • What a Project is: a self-contained workspace with its own chats, knowledge and instructions. The data files and last quarter's report go in project knowledge, and the audience and "every number must trace to the data" go in the instructions, so each stage's chat starts with them.
  • Retrieval: on paid plans, when knowledge approaches the context limit, Claude switches to retrieving the relevant parts, which the Help Center says expands capacity by up to ten times.
  • Chats share knowledge, not conversations: each stage in its own chat sees the same files and instructions. The Help Center doesn't say a chat can see another chat's messages, so carry confirmed results forward yourself.
  • Sharing: on Team and Enterprise plans, a Project can be shared so a colleague can review the stages.

Strategy by task type

Skill 1.2Each kind of step gets the approach that suits it.

  • Calculating from data: ask Claude to analyse the file with code and show the calculations, rather than to read the numbers and estimate. Then you can check how each figure was produced.
  • Reading and grouping (themes, extraction): give clear categories or a maximum number of groups, ask for counts and verbatim quotes, and ask for a list of what didn't fit.
  • Finding outside information: Research runs several searches that build on one another and can use connected sources such as email and documents. It needs web search turned on, is on paid plans, and uses up limits faster than a normal chat. From mobile it searches only the web.
  • Writing: audience, purpose, tone and length (skill 1.1); an example of the style helps.
  • Brainstorming: ask for many options without judging, then evaluate them in a separate step.

Checkpoints between steps

Skill 1.2Check before the next step builds on it.

  • Where: after any step whose output later steps depend on. Wrong figures in stage 1 would flow into every section.
  • How: spot-check numbers against the source, sample the groupings, agree the outline with the person who'll use the report. Ask Claude to mark anything unsupported, and list where each number came from.
  • Who: you, or the stakeholder whose decision it is. A checkpoint is a human judgement, not another request to Claude to "double-check itself". Judging output in depth is Domain 2.

"Ask for the whole report in one detailed prompt" sounds efficient, but it removes every chance to catch a mistake before it spreads, and mixes tasks that need different instructions.

Key takeaways

  • Split deliverables that mix kinds of work, are long, depend on earlier answers, or need checking along the way; chaining is slower but more accurate.
  • Sequence facts, then structure, then prose, one section at a time, each stage using the confirmed output of the last.
  • Follow up in the same chat to refine; start a fresh chat for a new stage and carry forward only the confirmed results.
  • A Project holds the files and instructions every stage needs; its chats share knowledge, not conversations.
  • Match strategy to task (code for calculations, categories and quotes for grouping, Research for outside information), and put a human checkpoint after any step later steps rely on.
