Decoupling and messaging services

Domain 1: Development with AWS Services. See Task 1.1 and Task 4.3.

ServiceModelChoose it when
Amazon SQSQueue: consumers pull; each message is processed by one consumer groupBuffering work for a worker, smoothing spikes, retrying failed work
Amazon SNSTopic: pushes each message to every subscriber, with filter policiesOne message must reach several queues, functions, HTTP endpoints, email or SMS
Amazon EventBridgeEvent bus: rules (or subscribers on the new custom bus) route events by contentMany event types and consumers, content-based routing, AWS and SaaS events, archive and replay
Kinesis Data StreamsOrdered, replayable stream of shards read by several consumersHigh-volume ordered records several consumers read independently, with replay
Step FunctionsWorkflow: one controller runs the stepsA multi-step process needs order, branching, retries and visible state

DynamoDB reads, capacity and consistency

Domain 1: Development with AWS Services. See Task 1.3.

ChoiceOption AOption B
Query or ScanQuery: one partition key value, optional sort key condition; efficientScan: reads every item; slow and costly on large tables (parallel scan helps)
Eventual or strong readsEventually consistent (default): half the cost, may miss the latest writeStrongly consistent (ConsistentRead=True): table and LSI only
On-demand or provisionedOn-demand (default, recommended): pay per request, scales to double the previous peakProvisioned: set RCUs and WCUs, optionally with auto scaling, for steady traffic
FilterExpression or key conditionFilter: applied after the read, saves bandwidth not capacityKey condition: reduces what's read

Often confused pairs

Pairs that sound alike but answer different questions.

PairThe difference
SQS visibility timeout and message retentionHow long a received message stays hidden versus how long an unreceived message is kept
SNS filter policy and EventBridge event patternPer-subscription filtering on a topic versus content routing on a bus
Reserved and provisioned concurrencyCaps and guarantees capacity versus keeps environments warm
Lambda execution role and resource-based policyWhat the function may do versus who may invoke it
ECS task role and task execution roleWhat the application code may call versus what ECS needs to start the task
Cognito ID token and access tokenWho the user is versus what they may access
API keys and authorizersMetering and throttling versus authentication
403 Missing Authentication Token and 401Usually a wrong path or stage versus an authorizer rejected the token
502 and 504 from API GatewayMalformed integration response versus integration timeout
FilterExpression and KeyConditionExpressionFilters after reading versus limits what's read
LSI and GSISame partition key, created with the table, strong reads versus any keys, any time, eventual reads
Lazy loading and write-throughCache on read miss versus cache on every write
SSE-KMS and client-side encryptionS3 encrypts with your KMS key versus the app encrypts before sending
Secrets Manager and Parameter StoreRotating secrets versus configuration and simple SecureStrings
Destinations and dead-letter queuesSuccess and failure with context versus failure only with the event
Canary and linearSmall share then the rest versus equal steps
Blue/green and rollingTwo full environments and a switch versus replacing in batches
Annotations and metadataIndexed and filterable versus extra data, not searchable
Liveness and readiness probesRestart the container versus stop sending it traffic
Metric filter and subscription filterTurns log events into a metric versus streams them elsewhere
validate-template and cfn-lintSyntax only versus property values and best practices
sam local invoke and sam remote invokeRuns locally in Docker versus invokes the deployed resource
