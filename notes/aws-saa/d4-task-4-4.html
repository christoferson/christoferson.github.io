Task 4.4: Design cost-optimized network architectures

Cutting the network part of the bill: NAT designs that don't charge for traffic they needn't carry, the cheapest connection to on-premises networks, routes that keep traffic private, local and in one Region, a CDN where it pays, finding the waste in existing networks, throttling that protects both systems and budgets, and links sized to the traffic.

Overview

Task 4.4

Design cost-optimized network architectures.

Network charges are mostly per gigabyte, so they grow with traffic and hide inside other services' bills: NAT gateways charge for every GB they process, traffic between AZs and Regions is charged both ways, and internet egress costs more than the same bytes through CloudFront or Direct Connect. The exam's cost questions usually ask which route, gateway or connection carries the same traffic for less, without breaking availability or security.

Prices are us-east-1 rates from AWS's pricing pages and price lists, checked in November 2026. Earlier pages introduced the basics: inbound data is free, internet egress is US$0.09 per GB for the first 10 TB a month (after a free 100 GB), cross-AZ traffic US$0.01 per GB in each direction, and Direct Connect egress US$0.02 per GB (Task 4.1).

Running example. Three-AZ production VPCs in us-east-1 with private application subnets, a DR copy in us-west-2, a shared-services VPC behind a transit gateway, offices and warehouses on premises, global customers, and a public API used by partners.

NAT gateway designs

Skill 4.4.1Configuring appropriate NAT gateway types for a network (for example, a single shared NAT gateway compared with NAT gateways for each Availability Zone)

AWS recommends NAT gateways for availability, bandwidth and lower administration. The AWS-supplied NAT AMI is past its end of support, so a NAT instance today means building your own AMI from current Amazon Linux. A small NAT instance can still be the cheapest choice for low-traffic development VPCs, accepting the operational work and the single point of failure.

One shared NAT gateway or one per AZ

The trade-off

A single NAT gateway shared by all AZs saves its hourly charge in each AZ you drop (about US$33 a month per AZ), but traffic from the other AZs crosses AZs to reach it (US$0.01 per GB each way), and if its AZ fails, the other AZs lose internet access. One NAT gateway per AZ, with each AZ's route table pointing at its own, avoids both, and is AWS's recommendation for production. The Regional NAT gateway (November 2025) is one resource spanning AZs, but it's billed per AZ it runs in, so it costs about the same as per-AZ zonal gateways; it saves management, not money.

Rule of thumb: production gets a NAT gateway per AZ (or a Regional NAT gateway); low-traffic development and test VPCs can share one.

Not sending traffic through NAT at all

The cheapest NAT traffic is none

  • Gateway endpoints for S3 and DynamoDB are free and remove the NAT processing charge for that traffic (Task 1.2).
  • Interface endpoints (US$0.01 per AZ-hour plus US$0.01 per GB) cost less than NAT's US$0.045 per GB for heavy traffic to other AWS services such as ECR, CloudWatch Logs or Secrets Manager.
  • IPv6 with an egress-only internet gateway has no hourly or processing charge, only data transfer.
  • Centralized egress through a transit gateway (Task 3.4) saves NAT gateway hours across many VPCs but adds US$0.02 per GB of transit gateway processing.

If a VPC has both a gateway endpoint and an interface endpoint for S3, turn on the interface endpoint's "private DNS only for inbound Resolver endpoint" option, so instances use the free gateway endpoint and only on-premises clients use the paid interface endpoint.

S3 interface endpoint for on-premises clients that leaves VPC traffic on the free gateway endpoint (AWS CLI) 
aws ec2 create-vpc-endpoint --vpc-id vpc-0shared1111111111 \
    --vpc-endpoint-type Interface \
    --service-name com.amazonaws.us-east-1.s3 \
    --subnet-ids subnet-0sharda11111111111 subnet-0shardb11111111111 \
    --private-dns-enabled \
    --dns-options PrivateDnsOnlyForInboundResolverEndpoint=true

"High NAT gateway data processing charges, mostly from S3 or DynamoDB" points to gateway endpoints. "Reduce NAT cost in a low-traffic test VPC" points to a single shared NAT gateway (or a small NAT instance). "Production must keep internet access if an AZ fails" points to a NAT gateway per AZ.

A single shared NAT gateway isn't free savings: every GB from the other AZs adds cross-AZ charges, and it's an AZ single point of failure. For busy VPCs the cross-AZ charges can outweigh the saved hours.

When Direct Connect pays for itself

Direct Connect saves US$0.07 per GB on outbound traffic compared with the internet, so a 1 Gbps dedicated port (about US$219 a month) pays for its port charge at roughly 3.1 TB of outbound traffic a month, before the carrier circuit and colocation costs. Inbound traffic is free either way, so Direct Connect saves nothing for a workload that mostly uploads to AWS. Billing for a dedicated port starts when it comes up or 90 days after the Letter of Authorization, whichever is first, and an idle port still bills, so order it when you're ready to use it. MACsec encryption (on 10, 100 and 400 Gbps dedicated connections) costs nothing extra.

Other connection options

  • Private or dedicated lines from a carrier connect your premises to a Direct Connect location; hosted connections bundle that capacity through an AWS partner.
  • Accelerated VPN adds two Global Accelerators per connection (US$0.05 per hour) plus their per-GB premium: better performance, higher cost.
  • Client VPN costs US$0.10 per subnet association-hour plus US$0.05 per connection-hour.
  • Verified Access costs about US$0.27 per application-hour plus US$0.02 per GB.
  • A common design is Direct Connect with Site-to-Site VPN as a low-cost backup (Task 1.2).

"Large, steady outbound transfers to the data center" points to Direct Connect. "Low volume, quick to set up, encrypted" points to Site-to-Site VPN. "Backup for Direct Connect at low cost" points to VPN. "Data mostly flows into AWS" means Direct Connect's per-GB saving doesn't apply.

Routes that minimize transfer cost

Skill 4.4.3Configuring appropriate network routes to minimize network transfer costs (for example, Region to Region, Availability Zone to Availability Zone, private to public, AWS Global Accelerator, VPC endpoints)

Within a Region

Private, local and same-AZ

  • Traffic over private IP addresses within one AZ is free; between AZs it costs US$0.01 per GB in each direction.
  • Traffic sent to a public or Elastic IP address inside the Region is billed at that same US$0.01 per GB, even within one AZ. Keep internal traffic on private IPs and private DNS names.
  • Place chatty components (an application and its cache, a batch job and its data) in the same AZ where availability allows, and compare AZ IDs (such as use1-az1) across accounts, because AZ names differ between accounts.
  • RDS Multi-AZ replication between primary and standby is free; your clients in other AZs still pay cross-AZ for their queries.

Peering, Transit Gateway and Lattice

VPC peering has no hourly or processing charge: traffic within one AZ (by AZ ID) is free even across accounts, and cross-AZ peering traffic costs the normal US$0.01 per GB each way. A transit gateway charges US$0.05 per attachment-hour plus US$0.02 per GB processed, billed by default to the sending VPC's owner; Flexible Cost Allocation (November 2025, no charge) can bill the receiver or the transit gateway owner instead. So peering is cheaper for a few high-traffic VPC pairs, and a transit gateway is worth its cost for many VPCs (Task 3.4). VPC Lattice charges per service-hour and US$0.025 per GB, with cross-AZ traffic included in that processing fee.

Endpoints and PrivateLink

Gateway endpoints are free; interface endpoints charge per AZ-hour and per GB. Reaching a PrivateLink service in another Region adds inter-Region transfer for the consumer in both directions, while the provider pays US$0.05 per hour per active remote Region. Creating interface endpoints in only the AZs that need them saves their hourly charge, at the cost of cross-AZ traffic from the others.

Between Regions and to the edge

Region-to-Region

Transfer out of us-east-1 costs US$0.01 per GB to Ohio and US$0.02 per GB to the other Regions checked; inbound is free. Every cross-Region copy (S3 Cross-Region Replication, Aurora Global Database, cross-Region backups, a transit gateway peering) pays it, so replicate only what DR or latency requires. Across a transit gateway peering, 1 GB from Virginia to Oregon costs about US$0.04 (US$0.02 processing plus US$0.02 transfer).

Global Accelerator and CloudFront

Global Accelerator adds a per-GB premium (US$0.015 per GB from the US to US or European edges, more to other regions) on top of normal data transfer, plus US$0.025 per hour even when disabled. It improves performance and failover, but never reduces cost. CloudFront is the edge service that cuts cost: fetches from AWS origins are free and its delivery rate is lower than EC2's internet rate (Skill 4.4.4).

Load balancer cross-zone traffic

Cross-zone load balancing on an ALB (always on) or a Classic Load Balancer carries no charge for the cross-AZ traffic. On an NLB or GWLB, turning cross-zone on adds the normal inter-AZ charges, which is why it's off by default.

"High inter-AZ data transfer charges" points to placing chatty components in the same AZ and using private IPs. "Two VPCs exchange lots of data, lowest cost" points to VPC peering rather than a transit gateway. "Reduce data transfer cost to global users" points to CloudFront, not Global Accelerator.

Using a public or Elastic IP to talk to a server in the same VPC is charged like cross-AZ traffic. And Global Accelerator is a performance service: choosing it to "reduce cost" is wrong.

CDNs and edge caching

Skill 4.4.4Determining strategic needs for content delivery networks (CDNs) and edge caching

When CloudFront pays off

The economics

Serving content through CloudFront instead of directly from EC2, a load balancer or S3 changes the bill in three ways: origin fetches from AWS origins are free; CloudFront's delivery price is lower (US$0.085 per GB in North America for the first 10 TB, falling to US$0.02 above 5 PB, against EC2's US$0.09); and cached responses never reach the origin, so the origin can be smaller. The always-free tier covers 1 TB of transfer and 10 million requests a month. A CDN pays off when the same content is downloaded many times, viewers are spread across regions, or the origin is expensive to scale; even uncacheable dynamic content gains from cheaper egress and connection reuse.

Levers that lower the CloudFront bill

  • Cache hit ratio: narrow cache keys (include only the headers, cookies and query strings that change the response) and longer TTLs mean fewer origin requests.
  • Price classes: Price Class 100 uses only North American and European edge locations, and Price Class 200 excludes South America and Australia and New Zealand. Viewers elsewhere are still served, from a cheaper location at the cheapest in-class rate, with higher latency.
  • Origin Shield adds a central cache layer (charged per 10,000 requests) that raises the hit ratio and cuts load on a costly or on-premises origin.
  • CloudFront Security Savings Bundle: up to 30% off for a one-year monthly spend commitment, with some AWS WAF usage included.
  • Flat-rate plans (from US$0 to US$1,000 a month per distribution, Task 3.4) bundle delivery, WAF and DDoS protection with no overage charges, for predictable bills.

Uploads

For large uploads from distant clients into one bucket, S3 Transfer Acceleration charges US$0.04 per GB (US$0.08 through more distant edges) on top of normal transfer, only when it speeds the transfer up; CloudFront is the delivery service. Direct uploads into S3 are free.

"Reduce data transfer costs for a popular website or downloads" points to CloudFront. "Most users are in North America and Europe, reduce CloudFront cost" points to Price Class 100. "Origin overloaded by cache misses from many edges" points to Origin Shield and better cache policies.

Reviewing workloads for network savings

Skill 4.4.5Reviewing existing workloads for network optimizations

Find where the gigabytes go

Billing views

In Cost Explorer, filter by usage type groups such as "EC2: Data Transfer - Inter AZ", "EC2: Data Transfer - Region to Region", "EC2: Data Transfer - Internet (Out)", "EC2: NAT Gateway - Data Processed" and "EC2: Elastic IP - Idle Address", and group by account, AZ or tag. In the Cost and Usage Report (CUR 2.0 through Data Exports), inter-AZ traffic appears as DataTransfer-Regional-Bytes line items (one in, one out), inter-Region traffic as {source}-{destination}-AWS-Out-Bytes, and internet egress as DataTransfer-Out-Bytes. Tag NAT gateways, endpoints and transit gateway attachments with cost allocation tags so owners see their share, and set Budgets on data transfer usage types to catch spikes (Task 4.1).

Finding idle and chatty resources

  • Compute Optimizer and Cost Optimization Hub flag idle NAT gateways (no route tables, connections or packets over 32 days).
  • Trusted Advisor lists inactive NAT gateways, interface endpoints, Gateway Load Balancer endpoints and Network Firewalls, unassociated Elastic IPs, and idle Classic Load Balancers (its idle load balancer check covers only Classic Load Balancers).
  • IPAM Public IP Insights lists every public IPv4 address across the organization, each costing US$0.005 per hour, including those used by NAT gateways, load balancers and VPNs.
  • VPC Flow Logs show who talks to whom; CloudWatch Network Flow Monitor shows the top flows between AZs, VPCs and services.

Common fixes after a review

  1. Add gateway endpointsMove S3 and DynamoDB traffic off NAT gateways.
  2. Localize trafficKeep chatty tiers in one AZ and use private IPs.
  3. Put CloudFront in frontServe repeated downloads from the edge.
  4. Move to Direct ConnectFor heavy outbound traffic to on premises.
  5. Delete idle resourcesUnused NAT gateways, endpoints, Elastic IPs and load balancers.
  6. Cut cross-Region copiesReplicate only what DR and latency require.

"Identify which traffic causes high data transfer charges" points to Cost Explorer usage types or the CUR, with VPC Flow Logs to find the sources.

Throttling strategies

Skill 4.4.6Selecting an appropriate throttling strategy

Limiting requests to protect systems and budgets

API Gateway throttling and usage plans

API Gateway throttles with a token bucket: the rate is how many requests per second refill the bucket, the burst is its size, and excess requests get HTTP 429. Limits apply in order: per-client and per-method limits in a usage plan, then per-method stage limits, then the account's 10,000 requests per second per Region, then AWS's own Regional limits. A usage plan, tied to API keys, gives each partner a throttle (rate and burst) and a quota (requests per day, week or month), which suits metering and fair use between partners.

Usage plan for partner API keys: 100 requests per second, bursts of 200, 1 million requests a month (AWS CLI) 
aws apigateway create-usage-plan --name partners-standard \
    --throttle rateLimit=100,burstLimit=200 \
    --quota limit=1000000,period=MONTH \
    --api-stages apiId=a1b2c3d4e5,stage=prod

AWS warns that usage plan throttles and quotas are best effort, not hard limits: don't rely on them to control costs or block access. Use AWS Budgets to watch costs and AWS WAF to manage abusive requests, and don't treat API keys as authentication (use IAM, Cognito or Lambda authorizers).

Other throttling levers

  • AWS WAF rate-based rules block or challenge any client exceeding a request rate over 60 to 600 seconds (300 by default), at the edge, before requests cost backend capacity.
  • Lambda reserved concurrency caps how many copies of a function run, which caps both downstream load and cost.
  • SQS queues absorb bursts so consumers run at a steady, cheaper rate (Task 2.1).
  • CloudFront caching answers repeated requests without touching the origin.
  • Clients retry with exponential backoff and jitter so throttled requests don't come back in a storm (Task 2.2).
  • Shield Advanced adds cost protection: credits for scaling charges caused by a DDoS attack on protected resources.

"Different request limits per partner, with monthly quotas" points to API Gateway usage plans and API keys. "Block a client sending too many requests" points to a WAF rate-based rule. "Prevent a Lambda function from overwhelming the database" points to reserved concurrency or an SQS buffer.

"Use usage plan quotas to make sure API costs never exceed the budget" is wrong by AWS's own guidance: quotas are best effort. Use Budgets (with actions) for cost limits and WAF for enforcement.

Bandwidth allocation

Skill 4.4.7Selecting the appropriate bandwidth allocation for a network device (for example, a single VPN compared with multiple VPNs, Direct Connect speed)

Site-to-Site VPN

One connection or several

A standard VPN tunnel carries up to 1.25 Gbps (140,000 packets per second), and each connection has two tunnels for redundancy. For more:

  • Large bandwidth tunnels: up to 5 Gbps each (US$0.60 per connection-hour), on a transit gateway or Cloud WAN only, not on a virtual private gateway, and not with Accelerated VPN.
  • Several VPN connections with ECMP: on a transit gateway with BGP, traffic spreads across all tunnels; AWS's example of two large-bandwidth connections with four tunnels gives 20 Gbps. ECMP is a transit gateway feature, so a virtual private gateway is limited to one tunnel's bandwidth per connection.
  • For many small sites (under 100 Mbps each), a VPN Concentrator on a transit gateway connects up to 100 sites for US$1.95 per hour plus US$0.01 per site-hour.

VPN tunnels use an MTU of 1446 bytes, with no jumbo frames.

Direct Connect

Choosing the speed

Dedicated connections run at 1, 10, 100 or 400 Gbps, and a port's speed can't be changed after ordering: a different speed means a new connection. Hosted connections (50 Mbps to 25 Gbps) can be changed only by your partner, and AWS polices them, dropping traffic above the rate, so size them for peaks. To add capacity at one location, a link aggregation group (LAG) bonds identical dedicated connections into one logical link: up to four connections below 100 Gbps, or two at 100 or 400 Gbps, all at the same speed on the same AWS device. For resilience, add connections at a second location instead (Task 1.2).

Monitoring utilization

CloudWatch publishes ConnectionBpsEgress and ConnectionBpsIngress for each connection and VirtualInterfaceBpsEgress for each virtual interface; ConnectionDiscardsPpsEgress shows drops from congestion. Size to sustained peak plus headroom, and resize (a new port, a LAG, or a hosted change) when utilization stays high. A smaller hosted connection is far cheaper than an idle 10 Gbps dedicated port.

Other devices

A NAT gateway scales from 5 to 100 Gbps (and up to 10 million packets per second); beyond that, split subnets across several NAT gateways. A transit gateway VPC attachment carries up to 100 Gbps per AZ.

"Need more than 1.25 Gbps over VPN" points to large bandwidth tunnels or multiple VPN connections with ECMP on a transit gateway. "Direct Connect 10 Gbps is saturated at one location" points to a LAG (or a 100 Gbps port). "Traffic is small but steady" points to a hosted connection sized to the need.

Adding more VPN connections to a virtual private gateway doesn't add bandwidth, because ECMP requires a transit gateway. And a dedicated Direct Connect port can't be resized in place.

DNS costs

The knowledge list for this task includes network services such as DNS. Route 53 is cheap, but has a few rules worth knowing:

  • Hosted zones: US$0.50 per month each for the first 25, then US$0.10.
  • Queries: US$0.40 per million for standard records, US$0.60 for latency, US$0.70 for geolocation and geoproximity, US$0.80 for IP-based routing.
  • Free queries: queries to private hosted zones, and alias queries to AWS resources such as CloudFront, load balancers, API Gateway and S3 websites. Prefer alias records over CNAMEs for AWS targets.
  • Health checks: US$0.50 a month for AWS endpoints (the first 50 are free) and US$0.75 for others, with extra for optional features.
  • Resolver endpoints for hybrid DNS: US$0.125 per ENI-hour, with at least two ENIs per endpoint, so about US$182 a month each before queries. Share them across VPCs and accounts rather than creating one per VPC.
  • TTL: longer TTLs mean fewer billed queries but slower changes and failover.

"Point the apex domain at CloudFront or a load balancer at the lowest cost" points to an alias record (free queries, works at the apex).

Key takeaways

  • NAT: gateways cost US$0.045 per hour plus US$0.045 per GB; NAT instances cost only EC2 but you run them (the AWS NAT AMI is past end of support). One NAT gateway per AZ for production; one shared gateway saves hours but adds cross-AZ charges and an AZ single point of failure; the Regional NAT gateway is billed per AZ. Bypass NAT with gateway endpoints, interface endpoints and IPv6 egress-only gateways.
  • Connections: VPN US$0.05 per hour plus internet egress; Direct Connect port-hours plus US$0.02 per GB out (pays off around 3 TB a month outbound for a 1 Gbps port, before circuit costs); inbound is free everywhere; idle ports still bill.
  • Routes: same-AZ private traffic free; cross-AZ and public or Elastic IP traffic US$0.01 per GB each way; peering has no processing fee (same-AZ free) while a transit gateway adds US$0.02 per GB; inter-Region US$0.01 to US$0.02 per GB from us-east-1; NLB and GWLB cross-zone is charged, ALB's isn't; Global Accelerator adds cost.
  • CDN: CloudFront's origin fetch is free and its rates are below EC2 egress; raise the hit ratio, use price classes, Origin Shield, the Security Savings Bundle or flat-rate plans.
  • Review: Cost Explorer data transfer usage types, CUR line items, Flow Logs and Network Flow Monitor; Compute Optimizer, Cost Optimization Hub and Trusted Advisor for idle NAT gateways, endpoints and Elastic IPs; IPAM Public IP Insights for public IPv4 charges.
  • Throttling: API Gateway token bucket, usage plans for per-partner rate, burst and quota (best effort, not a cost control); WAF rate-based rules, Lambda reserved concurrency, SQS buffering, caching, backoff with jitter; Budgets for cost limits.
  • Bandwidth: VPN 1.25 Gbps per tunnel, 5 Gbps large tunnels and ECMP only on a transit gateway; Direct Connect dedicated speeds fixed at order, hosted changed by the partner and policed, LAGs of up to 4 (or 2 at 100 and 400 Gbps); monitor ConnectionBpsEgress.
  • DNS: free alias queries to AWS resources and free private-zone queries; Resolver endpoints about US$182 a month each, so share them.
