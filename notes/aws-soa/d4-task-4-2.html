Data classification

Skill 4.2.1Implement and enforce a data classification scheme

Labeling and enforcing

A classification scheme in tags

Define a small set of levels (for example Public, Internal, Confidential, Restricted) and record each resource's level in a tag such as DataClassification. Then make the tag do work:

  • Consistency: an Organizations tag policy fixes the allowed keys and values; the Security Hub CSPM tagging standard and the Config required-tags rule report resources without them.
  • Access: attribute-based access control with aws:ResourceTag/DataClassification limits who can read Restricted data.
  • Controls by level: Restricted data gets customer managed KMS keys, stricter backup and retention, and no public sharing.

Amazon Macie: finding sensitive data

What Macie does

Macie inventories your S3 buckets and finds sensitive data in them. It produces two kinds of findings:

  • Policy findings: a bucket became public, lost default encryption or was shared outside the account.
  • Sensitive data findings: an object contains personal data, financial data or credentials.

Automated sensitive data discovery continuously samples objects across all buckets and gives each bucket a sensitivity score; discovery jobs analyze a chosen set of buckets in depth, once or on a schedule. Detection uses managed data identifiers (names, card numbers, keys), your own custom data identifiers (a regular expression with optional keywords, such as an internal customer ID format), and allow lists for text to ignore. Findings go to EventBridge and Security Hub; run Macie organization-wide from a delegated administrator account.

"Find which buckets contain personal data" or "alert when credit card numbers are uploaded to S3" is Amazon Macie. Macie then tells you what to classify; tags, policies and encryption enforce it.

Encryption at rest

Skill 4.2.2Implement, configure, and troubleshoot encryption at rest (for example, AWS KMS)

AWS KMS keys

Three kinds of key

  • AWS owned: used by a service internally; invisible to you and free.
  • AWS managed (aws/s3, aws/ebs, aws/rds): created for you in your account, rotated every year automatically; you can't change their policy, so they can't be shared with other accounts.
  • Customer managed: you control the key policy, rotation, grants and deletion. Needed for cross-account access, separation of duties or custom rotation.

Services use envelope encryption: KMS generates a data key (GenerateDataKey) that encrypts the data, and the KMS key encrypts only that data key. Direct Encrypt calls are limited to 4 KB.

Key policies

Every key has a key policy, and it is the primary control: IAM policies only work for a key if its policy allows the account to delegate to IAM, which the default key policy does. Use grants for temporary, delegated access (services such as EBS create them), and kms:ViaService to allow use only through a particular service. Cross-account use needs the key policy to allow the other account and an IAM policy in that account.

Key policy statement: let the analytics account decrypt 
{
  "Sid": "AllowAnalyticsDecrypt",
  "Effect": "Allow",
  "Principal": { "AWS": "222222222222" },
  "Action": [
    "kms:Decrypt",
    "kms:DescribeKey"
  ],
  "Resource": "*"
}

Rotation and deletion

  • Automatic rotation for customer managed symmetric keys is off by default; turn it on with a period from 90 to 2,560 days (default 365). On-demand rotation rotates immediately, up to 25 times per key. Old key material is kept, so existing data still decrypts; nothing needs re-encrypting.
  • Asymmetric and HMAC keys, and keys in custom key stores, can't rotate automatically: create a new key and move the alias to it.
  • Deletion is scheduled with a waiting period of 7 to 30 days (default 30) and can be cancelled until then. Data encrypted under a deleted key is lost for good, so disable a key first, and set a CloudWatch alarm on attempts to use a key pending deletion.

Troubleshooting KMS

  • AccessDeniedException: the key policy or IAM policy doesn't allow the action, or an explicit deny applies. Cross-account, check both sides; with an AWS managed key, cross-account is impossible.
  • KMSInvalidStateException: the key is disabled or pending deletion.
  • ThrottlingException: the account's per-Region request quota for cryptographic operations (10,000 per second by default, more in the largest Regions) is exceeded. Calls services make for you, such as S3 decrypting objects, count too. Turn on S3 Bucket Keys to cut S3's KMS calls, cache data keys, or request an increase in Service Quotas.

Encrypting the storage services

Amazon EBS

Turn on EBS encryption by default (a per-Region account setting) so every new volume and snapshot copy is encrypted. An existing unencrypted volume can't be encrypted in place: snapshot it, copy the snapshot with encryption, and create a new volume from the copy.

Encrypt every new volume in this Region 
aws ec2 enable-ebs-encryption-by-default

# use a customer managed key, not aws/ebs
aws ec2 modify-ebs-default-kms-key-id \
  --kms-key-id alias/orders-ebs

Amazon RDS

Encryption is chosen when the instance is created and can't be turned on later. To encrypt an existing database:

  1. SnapshotTake a snapshot of the unencrypted instance.
  2. Copy with encryptionCopy the snapshot, choosing a KMS key.
  3. RestoreRestore a new, encrypted instance from the copy.
  4. Switch overPoint the application at the new endpoint; plan for the downtime or use replication to shorten it.

Copying an encrypted snapshot to another Region needs a KMS key in the destination Region (or a multi-Region key). Sharing an encrypted snapshot with another account needs a customer managed key shared with that account.

Amazon S3

Every new object is encrypted with SSE-S3 by default. Choose SSE-KMS (with Bucket Keys) for key control and CloudTrail records of key use, or DSSE-KMS for two layers. SSE-C (customer-provided keys) is now blocked by default on new buckets. To insist on SSE-KMS, set it as the bucket's default encryption, or deny PutObject requests whose s3:x-amz-server-side-encryption header isn't aws:kms.

Encryption in transit

Skill 4.2.3Implement, configure, and troubleshoot encryption in transit (for example, AWS Certificate Manager [ACM])

AWS Certificate Manager

Public certificates

  • Free for use with integrated services: Elastic Load Balancing, CloudFront, API Gateway and others. They can't be installed on an EC2 instance; for that, use a paid exportable public certificate, or terminate TLS at a load balancer.
  • Regional: request the certificate in the load balancer's Region. CloudFront only uses certificates from us-east-1.
  • Validity is now 198 days, so renewal happens about twice a year; it must be automatic.
Request a DNS-validated certificate 
aws acm request-certificate \
  --domain-name orders.example.com \
  --subject-alternative-names \
    "*.orders.example.com" \
  --validation-method DNS

Why a certificate didn't renew

  • DNS validation: ACM renews automatically as long as the certificate is in use by an AWS service and the validation CNAME record is still in DNS. A deleted CNAME is the usual cause of failure.
  • Email validation: someone must click the link in the renewal email. It is being withdrawn during 2027; switch certificates to DNS validation.
  • Imported certificates are never renewed by ACM; replace them before they expire.

ACM sends daily "ACM Certificate Approaching Expiration" events to EventBridge (from 30 days before expiry for public certificates, 45 for imported and private ones; adjustable), and AWS Health notifies renewal problems. Alarm on them, or on the DaysToExpiry metric.

Private certificates

AWS Private CA issues certificates for internal services, mutual TLS and devices, where a public certificate isn't wanted.

Enforcing TLS end to end

Load balancers

An HTTPS listener on an ALB (or TLS listener on an NLB) uses an ACM certificate and a security policy that sets the allowed TLS versions and ciphers. The console's default is a TLS 1.3 and 1.2 policy with post-quantum key exchange; the CLI, CloudFormation and CDK default is still the older ELBSecurityPolicy-2016-08, so set the policy explicitly. Add an HTTP listener whose only action redirects to HTTPS.

HTTPS listener with an explicit TLS policy 
aws elbv2 create-listener \
  --load-balancer-arn "$ALB_ARN" \
  --protocol HTTPS --port 443 \
  --certificates CertificateArn=$CERT \
  --ssl-policy \
    ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09 \
  --default-actions \
    Type=forward,TargetGroupArn=$TG

Other services

  • S3: deny any request where aws:SecureTransport is false.
  • CloudFront: a viewer protocol policy of redirect HTTP to HTTPS or HTTPS only, a minimum TLS version, and an origin protocol policy of HTTPS to the origin.
  • RDS: require TLS with the rds.force_ssl parameter (PostgreSQL, SQL Server) or require_secure_transport (MySQL, MariaDB), and give clients the RDS certificate bundle.
  • Hybrid links: Site-to-Site VPN is IPsec-encrypted; Direct Connect isn't encrypted by itself, so add MACsec on supported dedicated connections or run a VPN over it.
Bucket policy: refuse unencrypted connections 
{
  "Sid": "DenyInsecureTransport",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": [
    "arn:aws:s3:::orders-in",
    "arn:aws:s3:::orders-in/*"
  ],
  "Condition": {
    "Bool": {
      "aws:SecureTransport": "false"
    }
  }
}

Rotation

Managed rotation

Some services own and rotate their secret themselves. The common case: RDS and Aurora can manage the master user password in Secrets Manager, rotating it with no Lambda function to maintain.

Let RDS manage and rotate the master password 
aws rds modify-db-instance \
  --db-instance-identifier orders-db \
  --manage-master-user-password \
  --apply-immediately

Lambda rotation

For other secrets, a rotation function (AWS provides templates for RDS, Aurora, Redshift and DocumentDB) creates a new credential, sets it on the database, tests it and promotes it. Rotation can run as often as every 4 hours. When rotation fails, check that the function can reach both the database and the Secrets Manager endpoint (a VPC endpoint or NAT gateway from private subnets) and has permission on the secret and its KMS key.

Rotate a reporting user's secret every 30 days 
aws secretsmanager rotate-secret \
  --secret-id orders/reporting-db \
  --rotation-lambda-arn "$ROTATION_FN" \
  --rotation-rules \
    AutomaticallyAfterDays=30

Getting secrets to workloads

  • Amazon ECS: the task definition's secrets section references a secret or parameter with valueFrom, and ECS injects it as an environment variable. The task execution role needs permission to read it.
  • Amazon EKS: the Secrets Store CSI Driver with the AWS provider mounts secrets as files.
  • Lambda: the Parameters and Secrets Lambda extension caches values to cut cost and latency.
  • CloudFormation: dynamic references ({{resolve:secretsmanager:...}}) instead of parameters with default values.
  • Deleted secrets have a recovery window of 7 to 30 days before they are gone.

A password found in code, user data or an environment variable in plain text: move it to Secrets Manager, rotate it immediately (it must be treated as exposed), and grant the workload's role read access. If it's an access key, deactivate it and switch to a role.

Findings and remediation

Skill 4.2.5Configure reports and remediate findings from AWS services (for example, AWS Security Hub, Amazon GuardDuty, AWS Config, Amazon Inspector, AWS Security Agent)

The services and what they find

Amazon GuardDuty: threats

Detects malicious or unusual activity from CloudTrail management events, VPC Flow Logs and DNS logs, with nothing to install: crypto-mining, calls from known bad IP addresses, credential misuse, data exfiltration. Protection plans add S3 data events, EKS audit logs, Runtime Monitoring (an agent on EC2, ECS and EKS), Malware Protection for EC2 volumes, S3 uploads and backups, RDS logins and Lambda network activity. Extended Threat Detection (on by default) links related findings into a single critical attack sequence. Use suppression rules for known-benign findings (suppressed findings are left out of attack sequences), trusted IP lists, and a delegated administrator for the organization.

Amazon Inspector: vulnerabilities

Continuously scans EC2 instances (with SSM Agent, or agentless from EBS snapshots), container images in ECR, Lambda functions and their code, and optionally AMIs and source code, for software vulnerabilities and unintended network exposure. The Inspector score adjusts the CVSS score for your environment, for example whether the instance is reachable from the internet. Fix by patching (Patch Manager), rebuilding the image, or updating the function's dependencies.

AWS Config: misconfiguration

Rules mark resources non-compliant (an unencrypted volume, a public bucket), and remediation actions run an Automation runbook such as AWS-DisableS3BucketPublicReadWrite, manually or automatically with retries. See Task 4.1 for rules and conformance packs.

AWS Security Hub: one view

  • Security Hub CSPM (the original Security Hub, renamed) runs security standards: AWS Foundational Security Best Practices, CIS AWS Foundations Benchmark, NIST SP 800-53, PCI DSS and others, as controls backed by Config. It also collects findings from GuardDuty, Inspector, Macie and partner products in one format (ASFF), aggregates Regions into one, and has automation rules to update or suppress findings and custom actions to send chosen findings to EventBridge.
  • AWS Security Hub (the newer service, generally available since December 2025) builds on CSPM, GuardDuty, Inspector and Macie to correlate their signals into exposure findings that show attack paths and prioritize risk.

AWS Security Agent

An AI agent, now part of AWS Continuum, that finds security problems before they reach production: it runs penetration tests against applications, reviews code and pull requests, produces threat models and checks designs against your security requirements, proposing fixes. It's preventive, complementing the detective services above.

Automating the response

Every one of these services publishes findings to EventBridge. A rule matches the findings worth acting on and invokes Lambda, an Automation runbook or a notification.

  1. MatchA rule for GuardDuty Finding with high severity, or Security Hub Findings - Imported (CSPM) from a custom action.
  2. ContainIsolate the instance by replacing its security groups with one that allows nothing, and detach it from its Auto Scaling group.
  3. PreserveSnapshot its EBS volumes for investigation.
  4. RevokeDeactivate exposed access keys or revoke the role's active sessions.
  5. RecordNotify the team and create an OpsItem or ticket.
Rule pattern: high and critical GuardDuty findings 
{
  "source": ["aws.guardduty"],
  "detail-type": ["GuardDuty Finding"],
  "detail": {
    "severity": [{ "numeric": [">=", 7] }]
  }
}

Threats in activity are GuardDuty. Software vulnerabilities are Inspector. Misconfigured resources are Config and Security Hub CSPM. Sensitive data in S3 is Macie. Pulling them together and prioritizing is Security Hub. Testing an application before release is AWS Security Agent.

Key takeaways

  • Classify with tags enforced by tag policies and Config, use the tags in ABAC, and find sensitive S3 data with Macie (policy and sensitive data findings, automated discovery, custom identifiers).
  • KMS: AWS managed keys can't be shared cross-account; customer managed keys are controlled by their key policy, rotate optionally (90 to 2,560 days, or on demand), and are deleted only after 7 to 30 days. Throttling means Bucket Keys, caching or a quota increase.
  • Turn on EBS encryption by default; encrypt existing EBS volumes and RDS databases by snapshot, encrypted copy and restore. S3 encrypts by default; enforce SSE-KMS with default encryption or a bucket policy.
  • ACM public certificates are free, Regional (us-east-1 for CloudFront), valid 198 days, and renew automatically only with DNS validation while in use. Imported certificates never renew. Set ALB security policies explicitly and redirect HTTP to HTTPS.
  • Secrets Manager rotates (managed for RDS master passwords, Lambda for others) and replicates; Parameter Store SecureString suits static values. Inject secrets into ECS, EKS, Lambda and templates by reference.
  • GuardDuty finds threats, Inspector vulnerabilities, Config misconfiguration, Macie sensitive data; Security Hub CSPM runs standards and gathers findings; the new Security Hub correlates exposures. Automate responses with EventBridge rules to Lambda or runbooks.
