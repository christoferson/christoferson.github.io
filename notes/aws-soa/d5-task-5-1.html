Overview

Task 5.1

Implement and optimize networking features and connectivity.

This task is about configuring the network correctly; Task 5.3 is about finding out why it doesn't work. Questions often combine the two layers of filtering (security groups and network ACLs), ask for the private way to reach a service, or ask for the cheapest design that meets a requirement.

The examples use the orders VPC, 10.0.0.0/16 in us-east-1, with public subnets for the load balancer, private subnets for the application and isolated subnets for the database, in three Availability Zones. Prices quoted are us-east-1 examples; check the pricing pages for current figures.

Configuring a VPC

Skill 5.1.1Configure a VPC (for example, subnets, route tables, network ACLs, security groups, NAT gateways, internet gateways, egress-only internet gateways)

Addresses and subnets

CIDR blocks

A VPC's IPv4 block is between /16 and /28; it can't be resized, but you can add secondary CIDR blocks (5 by default) that don't overlap. Each subnet lives in one Availability Zone and loses 5 addresses to AWS (see Task 3.1). For IPv6, the VPC gets a /56 and each subnet a /64; subnets can also be IPv6-only. Plan CIDRs so they never overlap with other VPCs or on-premises networks you may connect later.

Routing

Route tables

  • Each subnet is associated with one route table; subnets without an explicit association use the VPC's main route table, so keep the main table private.
  • Every table has a local route for the VPC's CIDRs, which can't be removed.
  • The most specific matching route wins (longest prefix match): a 10.1.0.0/16 route to a peering connection beats 0.0.0.0/0 to a NAT gateway.
  • A public subnet is simply one whose route table sends 0.0.0.0/0 to an internet gateway. A private subnet sends it to a NAT gateway, and an isolated subnet has no default route at all.

Gateways

Internet gateway

Connects the VPC to the internet in both directions, for resources with a public IPv4 address or an IPv6 address. One per VPC, highly available by design. Every public IPv4 address, in use or not, is charged by the hour, which is one reason to put only load balancers in public subnets.

NAT gateway

Lets instances in private subnets start outbound IPv4 connections to the internet without being reachable from it.

  • Zonal NAT gateway: lives in a public subnet in one Availability Zone. For high availability create one per zone and route each zone's private subnets to their own; one shared NAT gateway is a single point of failure and adds cross-zone charges.
  • Regional NAT gateway (newer): one NAT gateway for the whole VPC that needs no public subnet and spreads across zones automatically as workloads appear in them. It doesn't support private NAT.
  • Private NAT gateway (zonal only): translates to private addresses, for reaching other networks with overlapping CIDRs through a transit gateway or VPN.
  • Scale: 5 Gbps, scaling automatically to 100 Gbps, and 55,000 simultaneous connections to each unique destination per IP address; add secondary IP addresses if ErrorPortAllocation appears.
  • It has no security group: control its traffic with the security groups of the instances and the network ACL of its subnet.
One regional NAT gateway for the VPC 
aws ec2 create-nat-gateway \
  --vpc-id vpc-0abc1234 \
  --availability-mode regional

Egress-only internet gateway

The IPv6 equivalent of a NAT gateway: IPv6 addresses are globally unique and public, so this gateway lets instances start outbound IPv6 connections while blocking connections started from the internet. Route ::/0 to it from private subnets. It is stateful and free apart from data transfer.

VPC Block Public Access stops internet traffic through internet and egress-only gateways for a whole account and Region, either in both directions or inbound only, with exclusions for specific VPCs or subnets. Use it as a guardrail so that a misrouted subnet can't be exposed.

Chaining security groups

Reference groups instead of addresses: the database group allows 5432 from the app group, the app group allows 8080 from the load balancer group. New instances are then covered automatically. Groups can be referenced across a peering connection in the same Region, and inbound rules can reference groups in VPCs attached to the same transit gateway.

Network ACLs and ephemeral ports

Because ACLs are stateless, a public subnet that allows inbound 443 must also allow outbound replies to the client's ephemeral port, 1024 to 65535. Forgetting that is the classic ACL mistake. Use ACLs for coarse, subnet-wide denies (block an attacking range, keep the database subnet from reaching the internet), and security groups for everything else.

Private connectivity

Skill 5.1.2Configure private connectivity (for example, VPC endpoints, AWS PrivateLink, VPC peering)

VPC endpoints

Gateway endpoints

For S3 and DynamoDB only, and free. The endpoint adds a route to the service's prefix list in the route tables you choose, so traffic to the service stays on the AWS network without a NAT gateway. Limits: they work only for traffic from inside the VPC, in the same Region; on-premises networks and peered VPCs can't use them.

S3 gateway endpoint for the private route tables 
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-0abc1234 \
  --vpc-endpoint-type Gateway \
  --service-name \
    com.amazonaws.us-east-1.s3 \
  --route-table-ids \
    rtb-0aaa1111 rtb-0bbb2222

Interface endpoints (AWS PrivateLink)

For most other services (Systems Manager, CloudWatch, Secrets Manager, ECR, STS and many more, and S3 too). The endpoint places a network interface with a private IP in each subnet you choose, protected by a security group that must allow 443 from your clients. With private DNS on, the service's normal hostname resolves to those private IPs, so applications need no changes. They are charged per hour per zone plus per GB, and they can be reached from on-premises and peered networks.

Systems Manager endpoint in two subnets 
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-0abc1234 \
  --vpc-endpoint-type Interface \
  --service-name \
    com.amazonaws.us-east-1.ssm \
  --subnet-ids subnet-0aaa subnet-0bbb \
  --security-group-ids sg-0endpoint \
  --private-dns-enabled

Endpoint policies

Both kinds can carry an endpoint policy limiting what can be done through them, such as reaching only your own buckets, which stops data being copied to someone else's bucket. Pair it with bucket policies that allow access only through the endpoint (aws:SourceVpce).

Endpoint policy: only the orders bucket 
{
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": [
      "s3:GetObject",
      "s3:PutObject"
    ],
    "Resource": "arn:aws:s3:::orders-in/*"
  }]
}

Sharing your own services

Endpoint services and resource endpoints

A provider puts a service behind a Network Load Balancer and publishes it as an endpoint service; consumers in other VPCs and accounts create interface endpoints to it, after the provider accepts them. Traffic flows one way (consumer to provider), the CIDRs may overlap, and nothing else in either VPC is exposed. Endpoint services can now be offered to other Regions too. To share a single resource such as an RDS database without building a load balancer, use a resource gateway and resource endpoints.

Connecting VPCs

VPC peering

  • A private connection between two VPCs, in the same or different accounts and Regions. The CIDRs must not overlap.
  • The owner of the other VPC must accept the request (it expires after 7 days), and both sides must add routes to the other's CIDR and allow the traffic in their security groups.
  • Not transitive: if A peers with B and B with C, A can't reach C. There is also no edge-to-edge routing: A can't use B's internet gateway, NAT gateway, VPN or gateway endpoint.
  • No hourly charge; you pay only data transfer.

AWS Transit Gateway

A regional hub that VPCs, VPNs and Direct Connect gateways attach to. Routing between attachments is controlled by transit gateway route tables, which can separate environments (production attachments can't reach development). It replaces a mesh of peering connections once there are more than a few VPCs, and supports peering between Regions. Charged per attachment hour and per GB processed.

"Reach S3 or DynamoDB privately and cheaply" is a gateway endpoint. "Reach another AWS service privately" or "reach S3 privately from on premises" is an interface endpoint. "Expose one service to many consumer VPCs with overlapping CIDRs" is PrivateLink. "Connect two VPCs" is peering; "connect many" is a transit gateway.

Route 53 Resolver DNS Firewall

Rules on DNS queries

A rule group associated with a VPC holds rules that match domain lists, your own or AWS managed lists of malware and botnet domains, and take an action: ALLOW, ALERT (log only) or BLOCK, answering with NODATA, NXDOMAIN or an override CNAME. DNS Firewall Advanced rules also detect domain generation algorithms and DNS tunneling. If the firewall can't evaluate a query, it fails closed by default; set a VPC to fail open if availability matters more. Matches appear in Resolver query logs.

Block a domain list with NXDOMAIN 
# try ALERT first to see what would break
aws route53resolver create-firewall-rule \
  --name block-bad-domains \
  --creator-request-id block-bad-1 \
  --firewall-rule-group-id rslvr-frg-0a1 \
  --firewall-domain-list-id rslvr-fdl-0b2 \
  --priority 100 \
  --action BLOCK \
  --block-response NXDOMAIN

AWS WAF

Web ACLs and rules

A web ACL (called a protection pack in the new console) is attached to one or more resources: CloudFront distributions (create the web ACL in us-east-1), Application Load Balancers, API Gateway REST APIs, AppSync, Cognito user pools, App Runner, Verified Access and Amplify. Each resource can have one web ACL. Rules are evaluated in priority order and take an action: Allow, Block, Count, CAPTCHA or Challenge.

  • AWS managed rule groups: the core rule set, known bad inputs, SQL database, IP reputation, and paid groups for Bot Control and account takeover prevention.
  • Rate-based rules: block an IP (or other key) that exceeds a request count in a time window.
  • Capacity: each rule costs web ACL capacity units (WCUs); the base price covers 1,500 WCUs per web ACL, and the maximum is 5,000.
Rate-based rule: 2,000 requests per IP per 5 minutes 
{
  "Name": "limit-per-ip",
  "Priority": 1,
  "Statement": {
    "RateBasedStatement": {
      "Limit": 2000,
      "AggregateKeyType": "IP"
    }
  },
  "Action": { "Block": {} },
  "VisibilityConfig": {
    "SampledRequestsEnabled": true,
    "CloudWatchMetricsEnabled": true,
    "MetricName": "limit-per-ip"
  }
}

Auditing WAF

Introduce new rules in Count mode, watch what they would block, then switch to Block. Each rule publishes CloudWatch metrics, the console shows sampled requests, and full logs go to CloudWatch Logs (the log group name must start with aws-waf-logs-), S3 or Firehose. AWS Config can check that resources have a web ACL and that logging is on.

AWS Shield

Standard and Advanced

  • Shield Standard: free and automatic for every account, protecting against common network and transport layer (layer 3 and 4) attacks.
  • Shield Advanced: $3,000 a month per organization with a one-year commitment. Adds protection and visibility for specific resources (CloudFront, Route 53, Global Accelerator, load balancers, Elastic IPs), automatic application layer mitigation through WAF, health-based detection using Route 53 health checks, access to the Shield Response Team, WAF fees included for protected resources, and cost protection credits for scaling charges caused by an attack.

AWS Network Firewall

A managed firewall in the traffic path

Firewall endpoints sit in a dedicated firewall subnet in each zone, and route tables send traffic through them, for example internet gateway to firewall to public subnet (using an ingress route table on the gateway) and back. Routing must be symmetric, or stateful rules drop the replies. It can also attach directly to a transit gateway to inspect traffic between VPCs.

  • Stateless rules filter packets quickly by address and port; stateful rules track connections and include domain allow and deny lists (by TLS SNI or HTTP host) and Suricata-compatible intrusion prevention rules, plus AWS managed threat rule groups.
  • Logging: flow logs, alert logs and TLS logs, each to S3, CloudWatch Logs or Firehose.

"Allow the application to reach only api.partner.example.com on the internet" is a Network Firewall stateful domain list (or DNS Firewall for name resolution). "Block SQL injection against the ALB" is WAF. "Protect against DDoS with expert help and cost protection" is Shield Advanced.

The NAT gateway trap

A private-subnet workload that reads terabytes from S3 through a NAT gateway pays NAT processing on every GB. Adding a free S3 gateway endpoint moves that traffic off the NAT gateway with no application change. It's the most common cost question in this domain.

CloudFront

Serving content through CloudFront is usually cheaper than serving it from EC2 or S3 directly: transfer from AWS origins to CloudFront is free, CloudFront's own rates are lower, and cached responses never reach the origin. CloudFront also offers flat-rate plans (from free to a fixed monthly price) that bundle data transfer, WAF and DDoS protection with no overage charges.

Finding the cost

In Cost Explorer, group by usage type to see NAT gateway bytes, regional (cross-zone) data transfer and data transfer out. VPC Flow Logs show which instances and destinations generate the traffic, and IPAM's public IP insights list public IPv4 addresses in use.

Key takeaways

  • VPC CIDRs are /16 to /28, fixed in size but extendable with secondary blocks. A public subnet routes 0.0.0.0/0 to an internet gateway; private subnets use a NAT gateway (one per zone, or a regional NAT gateway); IPv6 uses an egress-only internet gateway.
  • Security groups are stateful, allow-only and can reference each other; network ACLs are stateless, numbered, allow and deny, and need ephemeral port rules for replies.
  • Gateway endpoints (S3, DynamoDB) are free route-table entries usable only from inside the VPC; interface endpoints are ENIs with security groups and private DNS, reachable from on premises. Endpoint policies limit what passes through.
  • PrivateLink exposes a service behind an NLB to other VPCs, even with overlapping CIDRs. Peering is non-transitive, needs non-overlapping CIDRs and routes on both sides; transit gateways are the hub for many VPCs.
  • DNS Firewall filters DNS queries (fails closed by default); WAF filters HTTP requests with managed and rate-based rules, logged to aws-waf-logs- groups; Shield Standard is free, Advanced adds response team and cost protection; Network Firewall inspects routed traffic in dedicated subnets.
  • Cost: replace NAT processing with gateway endpoints, keep traffic in one zone, prefer peering for heavy pairs and transit gateways for scale, serve through CloudFront, and cut public IPv4 addresses.
