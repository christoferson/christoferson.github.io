Overview

Task 5.2

Configure domains, DNS services, and content delivery.

DNS problems look like network problems ("the application can't reach the database") and are among the most common real outages, so expect questions on resolving names between AWS and on premises, and on picking the routing policy that meets a requirement. The delivery half is about configuring CloudFront and Global Accelerator; CloudFront caching for performance is in Task 2.1, Route 53 health checks in Task 2.2, and fixing caching problems in Task 5.3.

The examples use example.com, hosted in Route 53, with the orders VPC in us-east-1, a corporate data center using corp.example.com, and a second Region, eu-west-1.

DNS in and around VPCs

Skill 5.2.1Configure DNS (for example, Amazon Route 53 Resolver)

The VPC Resolver

DNS built into every VPC

Every VPC has a DNS resolver, now called the Route 53 VPC Resolver (formerly Route 53 Resolver; the APIs keep the old name). Instances reach it at the VPC's base address plus two (10.0.0.2), at 169.254.169.253, or at fd00:ec2::253 over IPv6. It answers for public names, private hosted zones associated with the VPC, and AWS's internal names.

  • It needs the VPC attribute enableDnsSupport; private hosted zones and interface endpoints' private DNS also need enableDnsHostnames, which is off by default in VPCs you create.
  • Security groups and network ACLs can't filter traffic to it; use DNS Firewall (Task 5.1).
  • Each network interface may send up to 1,024 packets per second to it (shared with the metadata service and time sync), a hard limit that busy instances can hit; cache DNS locally if so.

Hybrid DNS: Resolver endpoints

Inbound and outbound

  • Inbound endpoint: on-premises DNS servers forward queries for AWS names (private hosted zones, instance names) to IP addresses in your VPC, over Direct Connect or VPN.
  • Outbound endpoint plus forwarding rules: queries from the VPC for corp.example.com are forwarded to the data center's DNS servers.
  • Each endpoint has at least two IP addresses in different Availability Zones, each one a network interface; add addresses to scale (each handles up to about 10,000 queries per second). The endpoint's security group must allow DNS, TCP and UDP port 53.

Rules

A forwarding rule covers a domain and all its subdomains. A system rule makes the Resolver answer a subdomain itself (an exception to a forward). The most specific matching rule wins. Share rules with other accounts through AWS RAM, so one outbound endpoint in a networking account serves every VPC that the rule is associated with.

Forward corp.example.com to the data center 
aws route53resolver create-resolver-rule \
  --name corp-forward \
  --creator-request-id corp-fwd-1 \
  --rule-type FORWARD \
  --domain-name corp.example.com \
  --resolver-endpoint-id rslvr-out-0a1 \
  --target-ips \
    Ip=10.10.0.53 Ip=10.20.0.53

# then associate it with each VPC
aws route53resolver \
  associate-resolver-rule \
  --resolver-rule-id rslvr-rr-0c3 \
  --vpc-id vpc-0abc1234

Private hosted zones

Names only your VPCs can see

A private hosted zone (such as internal.example.com) answers only for the VPCs associated with it. If a public and a private zone share a name (split-horizon), VPCs associated with the private zone get its answers and everyone else the public ones; a name missing from the private zone does not fall back to the public zone. To answer on-premises queries from a private zone, associate it with the VPC that holds the inbound endpoint.

Associating a VPC in another account

Not possible in the console. The zone owner authorizes the VPC, then the VPC owner associates it:

Cross-account private hosted zone association 
# in the account that owns the zone
aws route53 \
  create-vpc-association-authorization \
  --hosted-zone-id Z0123ABC \
  --vpc VPCRegion=us-east-1,VPCId=vpc-0b2

# in the account that owns the VPC
aws route53 \
  associate-vpc-with-hosted-zone \
  --hosted-zone-id Z0123ABC \
  --vpc VPCRegion=us-east-1,VPCId=vpc-0b2

Route 53 Profiles

For many VPCs and accounts, a Profile bundles DNS configuration (private hosted zones, Resolver rules, DNS Firewall rule groups, interface endpoint DNS, query logging) and is shared through RAM and associated with VPCs in one step. A VPC can have one Profile; its own direct settings win over the Profile's for the same name.

DNSSEC

Signing a public hosted zone protects clients from forged answers. It needs a customer managed asymmetric KMS key (ECC_NIST_P256) in us-east-1, from which Route 53 creates the key-signing key, and then a DS record at the parent (the registrar). Validation of signed answers from other domains is turned on per VPC in the Resolver.

Global ResolverRoute 53 Global Resolver is a newer, internet-reachable anycast resolver for on-premises, branch and remote clients, with encrypted DNS (DoH, DoT), filtering and private hosted zone resolution. It is the reason the VPC Resolver was renamed.

Routing policies and logging

Skill 5.2.2Implement Route 53 routing policies, configurations, and query logging

Records

Alias or CNAME

  • Alias records point a name at an AWS resource (load balancer, CloudFront distribution, S3 website endpoint, API Gateway, Global Accelerator, interface endpoint, or another record in the zone). They work at the zone apex (example.com), queries to AWS resources are free, the target's IP changes are followed automatically, and you can't set a TTL. Evaluate target health lets routing policies use the target's health without a separate health check.
  • A CNAME can't be used at the apex, and no other record can share its name.

For non-alias records, the TTL is how long resolvers cache the answer: lower it (to 60 seconds, say) a day before a planned change, and raise it afterwards to cut query cost.

Delegation

A hosted zone answers only if the domain's registrar lists the zone's four name servers (from its NS record). After recreating a hosted zone, the name servers change; until the registrar is updated, the domain doesn't resolve.

Routing policies

PolicyAnswers withUse it when
SimpleThe one record (all its values, in random order)One resource, no health checks
WeightedRecords in proportion to their weights (0 to 255)Canary releases, gradual migration, A/B tests
LatencyThe Region with the lowest latency for the userMulti-Region applications, best performance
FailoverThe primary while healthy, otherwise the secondaryActive-passive disaster recovery
GeolocationThe record for the user's continent, country or US stateContent or legal rules by location; needs a default record
GeoproximityThe nearest resource, adjusted by a biasShifting load between Regions by growing or shrinking their area
IP-basedThe record for the user's IP range (CIDR collections)Routing specific ISPs or networks to specific endpoints
Multivalue answerUp to 8 healthy records at randomSimple client-side load spreading with health checks

Details that decide questions

  • Weighted: a weight of 0 stops traffic to a record, unless every record is 0 (then they share equally) or all non-zero records are unhealthy.
  • Geolocation: without a default record, users from unmapped locations get no answer.
  • Latency is about network latency, not geography: a user can be sent to a farther Region.
  • Policies can be nested: latency between Regions, then weighted or failover within each, through alias records pointing at other records, or with a Traffic Flow policy.
Weighted records: send 10% to the new stack 
{
  "Changes": [{
    "Action": "UPSERT",
    "ResourceRecordSet": {
      "Name": "api.example.com",
      "Type": "A",
      "SetIdentifier": "green",
      "Weight": 10,
      "TTL": 60,
      "ResourceRecords": [
        { "Value": "203.0.113.20" }
      ]
    }
  }]
}

A matching record with "SetIdentifier": "blue" and "Weight": 90 receives the rest. Apply each with aws route53 change-resource-record-sets.

Turning on public query logging

Route 53 needs a CloudWatch Logs resource policy allowing it to write to the log group; the console creates it, the CLI doesn't. A wrong Region or missing policy is the usual reason no logs appear.

Log queries for the example.com zone 
# the log group must be in us-east-1
aws route53 create-query-logging-config \
  --hosted-zone-id Z0123ABC \
  --cloud-watch-logs-log-group-arn \
    "$LOG_GROUP_ARN"

"Which instance is resolving a malware domain?" is Resolver query logging (it records the source instance). "How many queries does our public domain get, and from where?" is public DNS query logging.

CloudFront and Global Accelerator

Skill 5.2.3Configure content and service distribution (for example, Amazon CloudFront, AWS Global Accelerator)

Amazon CloudFront

Origins

  • S3 buckets with origin access control (OAC): the bucket stays private and its policy allows only the cloudfront.amazonaws.com service principal for your distribution (condition on AWS:SourceArn). OAC replaces the older origin access identity and supports SSE-KMS.
  • Custom origins: a public load balancer or any HTTP server. Restrict the origin to CloudFront with the com.amazonaws.global.cloudfront.origin-facing managed prefix list in its security group, or a secret header.
  • VPC origins: an ALB, NLB or EC2 instance in a private subnet, reachable only through CloudFront. Allow inbound traffic from the security group CloudFront creates for the VPC origin; the VPC still needs an internet gateway.
  • Origin groups: a primary and secondary origin; on chosen error codes (such as 500, 502, 503, 504, 403, 404) or timeouts, CloudFront retries GET, HEAD and OPTIONS requests on the secondary.

Behaviors and policies

Cache behaviors match path patterns (/api/*, /images/*, default *) to an origin and settings: allowed methods, viewer protocol policy (redirect HTTP to HTTPS), a cache policy (TTLs and what forms the cache key), an origin request policy (what is passed to the origin without being in the key), and a response headers policy (security headers, CORS).

Domains, access and edge code

  • Alternate domain names (www.example.com) need an ACM certificate in us-east-1 covering the name, and a Route 53 alias record pointing at the distribution.
  • Private content: signed URLs (one file) or signed cookies (many files) using a trusted key group. Geographic restrictions allow or block countries.
  • CloudFront Functions (lightweight JavaScript on viewer request and response: redirects, header changes, URL rewrites) or Lambda@Edge (Node.js or Python on all four events, with network access and longer run time, for authentication or calling other services).
  • Logging: standard logs to S3, CloudWatch Logs or Firehose; real-time logs to Kinesis Data Streams.
CloudFront Function: serve index.html for folder URLs 
function handler(event) {
  var req = event.request;
  // /docs/ becomes /docs/index.html
  if (req.uri.endsWith('/')) {
    req.uri += 'index.html';
  }
  return req;
}

Deploying changes safely

Changes to a distribution take minutes to reach all edge locations. Continuous deployment sends a share of traffic to a staging distribution to test configuration changes before promoting them. For content, prefer versioned file names (app.3f9c.js) to invalidations; the first 1,000 invalidation paths each month are free.

Remove changed files from the edge caches 
aws cloudfront create-invalidation \
  --distribution-id E1ABC2DEF3 \
  --paths "/index.html" "/css/*"

Cost and reach

Price classes limit which edge locations serve the distribution (all, or excluding the most expensive regions) to cut cost at the price of latency for some users. Origin Shield adds a central caching layer to reduce origin load. Flat-rate plans are an alternative to paying per GB and request.

AWS Global Accelerator

What it does

Gives an application two static anycast IPv4 addresses (plus two IPv6 addresses if dual-stack) announced from AWS edge locations. Users connect to the nearest edge, and traffic crosses the AWS backbone to the closest healthy endpoint: ALBs, NLBs, EC2 instances or Elastic IPs in one or more Regions. Nothing is cached.

  • Endpoint groups (one per Region) have a traffic dial (0 to 100%) to shift traffic away from a Region, for maintenance or blue/green; endpoint weights (0 to 255) divide traffic within a group.
  • Health checks move new connections away from an unhealthy endpoint immediately, with no DNS caching delay, because the client's IP addresses never change.
  • Client affinity set to source IP keeps a user on the same endpoint.
  • Custom routing accelerators map users to a specific instance and port, for multiplayer games and VoIP.
Drain the eu-west-1 Region for maintenance 
# Global Accelerator API: us-west-2 only
aws globalaccelerator \
  update-endpoint-group \
  --region us-west-2 \
  --endpoint-group-arn "$EU_GROUP" \
  --traffic-dial-percentage 0

Choosing between them

NeedCloudFrontGlobal Accelerator
ProtocolsHTTP and HTTPS, WebSocket, gRPCAny TCP or UDP
CachingYes, at the edgeNo
Static IP addressesOptional (Anycast static IPs, extra cost)Always, two per accelerator
Regional failoverOrigin groupsHealth checks and traffic dials, in seconds
Typical useWebsites, APIs, video, downloadsGaming, IoT, VoIP, non-HTTP apps, firewall allow lists of fixed IPs

"Customers must allow-list our IP addresses" or "UDP game traffic needs lower latency worldwide" is Global Accelerator. "Cache static content near users and protect the origin" is CloudFront. "Failover without waiting for DNS caches to expire" points to Global Accelerator rather than Route 53 failover.

Key takeaways

  • The VPC Resolver (VPC+2, 169.254.169.253) needs enableDnsSupport, and enableDnsHostnames for private zones and endpoint DNS. Inbound endpoints answer on-premises queries; outbound endpoints with forwarding rules (shared through RAM) send queries on premises.
  • Private hosted zones answer only associated VPCs (cross-account by CLI authorization); split-horizon doesn't fall back to the public zone. Profiles share DNS configuration across many VPCs. DNSSEC signing needs a KMS key in us-east-1.
  • Alias records work at the apex, are free for AWS targets and have no TTL. Know each routing policy: weighted for canaries, latency for performance, failover for active-passive, geolocation with a default record, geoproximity bias, IP-based, multivalue.
  • Public query logs go to CloudWatch Logs in us-east-1 with a resource policy; Resolver query logs (with source instance) go to CloudWatch Logs, S3 or Firehose.
  • CloudFront: S3 with OAC, VPC origins for private load balancers, origin groups for failover, behaviors with cache and origin request policies, ACM certificates in us-east-1, Functions versus Lambda@Edge, versioned names over invalidations.
  • Global Accelerator: two static anycast IPs, any TCP or UDP, endpoint groups with traffic dials, fast failover without DNS; choose it over CloudFront for non-HTTP traffic and fixed IPs.
