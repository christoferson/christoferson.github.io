Domain 1: Data Preparation for ML and AI

Collect and store data (Task 1.1)

  • Columnar, splittable training data → Parquet or ORC; CSV and JSON for small or interchange data (formats).
  • Very large datasets read repeatedly by many instances → FSx for Lustre; shared files across instances → EFS; default → S3 (storage).
  • Real-time clickstream into features → Kinesis Data Streams or MSK, then Lambda or Flink to Feature Store (streaming).
  • Export a database without load on production → RDS snapshot export to S3, DynamoDB export to S3 (point-in-time recovery).
  • Vectors for RAG at low cost, infrequent queries → S3 Vectors; high query rate or hybrid search → OpenSearch; data already in PostgreSQL → Aurora pgvector (vector stores).
  • Same features for training and serving → Feature Store offline and online stores (Feature Store).

Transform data and engineer features (Task 1.2)

  • Visual ML data prep inside SageMaker → Data Wrangler in Canvas; analysts' no-code recipes → DataBrew; scheduled serverless Spark → Glue; huge custom Spark → EMR (tools).
  • Distance-based or linear model → standardize; skewed values → log; few categories → one-hot; many categories → hashing or similarity encoding; trees need no scaling (feature engineering).
  • Accuracy too good to be true → a transformer fitted before splitting (leakage); fit on training data only.
  • Index and query embeddings → same model and dimension for both; Cohere input_type document versus query (embeddings).
  • Long structured manuals for RAG → hierarchical chunking; unstructured text → semantic; chunking is fixed at creation (chunking).
  • Redact names before indexing → Comprehend redaction jobs (real-time APIs only detect), Glue Detect PII; Macie only finds (redaction).
  • Fine-tuning data → prompt and response pairs in JSON Lines; continued pre-training → lots of raw text; distillation → prompts only (FM data).

Validate data quality and manage bias (Task 1.3)

  • Stop bad rows reaching the lake and keep them → Glue Data Quality transform in the ETL job, row-level outcomes; recommend rules for a catalog table → Data Catalog recommendations (data quality).
  • Cut labeling cost → active learning; sensitive data → private workforce (labeling).
  • Same customer in train and test → split by key or by time; rare label → stratify (bias sources).
  • One group under-represented → CI; one group gets the good label more often → DPL; gap vanishes within subgroups → CDDL (bias metrics).
  • 6% positives → resample the training split only, scale_pos_weight, F1 or AUC-PR (imbalance).
  • Screen fine-tuning data for toxic content → ApplyGuardrail, Comprehend DetectToxicContent, Rekognition moderation; Bedrock doesn't screen it for you (FM data integrity).
  • Fuzzy duplicates with no shared key → FindMatches (cleaning).

Domain 2: ML Model and Foundation Model Development

Choose modeling approaches (Task 2.1)

  • Pick a Bedrock model → read the model card (context, price, features, tiers, lifecycle); start with the smallest model that meets the bar (FM selection).
  • Answers from documents that change weekly → RAG, not fine-tuning; fixed tone and template → fine-tuning; cheaper narrow task → distillation (customization ladder).
  • Tabular, accurate and explainable → XGBoost with SHAP; explainable without tools → linear model or single tree (algorithms).
  • No ML expertise, least effort → AI service, Bedrock or Canvas (build or buy).
  • Exact product codes plus meaning → hybrid search; relevance poor → rerank; multi-part question → query decomposition (RAG patterns).
  • Cheaper interruptible training → Spot with checkpoints; quick reruns → warm pools; guaranteed GPUs → training plan (training cost).
  • Overnight FM job, lowest cost → batch or Flex; repeated long prefix → prompt caching; slow chat → streaming, smaller model, Priority (inference cost).
  • Read invoice totals → Textract Queries or AnalyzeExpense; images → Rekognition; text → Comprehend; speech → Transcribe (AI services).

Train, fine-tune and customize (Task 2.2)

  • XGBoost on CSV → label first, no header, text/csv content type (libsvm is the default); num_round required (built-ins).
  • Your own script in an AWS framework container → script mode: data in SM_CHANNEL_*, model to SM_MODEL_DIR (script mode).
  • Tuning takes too long → Hyperband, early stopping, Random with more parallel jobs, warm start; always set max_jobs (AMT).
  • Model doesn't fit one GPU → model parallel or FSDP; fits → data parallel; first try a bigger instance (training time).
  • Train 99%, validation 70% → overfitting: regularize, simplify, more data, stop early; fine-tuned model forgot general skills → mix general data, lower learning rate, LoRA (fit).
  • Nova fine-tuning on Bedrock → only epochCount, learningRate, learningRateWarmupSteps (hyperparameters).
  • Fine-tune an embedding model on Bedrock → only Titan Multimodal Embeddings G1; new embedding model → full re-index (retrieval).

Analyze and evaluate (Task 2.3)

  • Track and compare training runs → MLflow Apps on SageMaker AI (experiments).
  • Drift now that Model Monitor is closed → Evidently (PSI, KS) against the training baseline, results in MLflow, CloudWatch alarms (drift).
  • Compare a new model on live traffic with no user impact → shadow test (one shadow variant, operational metrics, accuracy offline) (shadow).
  • Explain predictions → SHAP (tree SHAP for trees); GenAI → citations, reasoning content, traces (explanations).
  • Loss NaN or exploding → lower learning rate, normalize inputs, clip gradients; tools → TensorBoard, MLflow (convergence).
  • Costly false positives → precision; costly misses → recall; imbalance → F1, balanced accuracy, AUC-PR (metrics).
  • Translation → BLEU; summarization → ROUGE; paraphrase-friendly → BERTScore; Bedrock automatic jobs use BERTScore and F1 (NLP metrics).
  • Grade answers for policy accuracy at scale → Bedrock LLM-as-a-judge with a custom metric (judges).
  • Is retrieval finding the right passages? → context relevance and context coverage; knowledge base logs cover ingestion only (RAG monitoring).

Domain 3: Deployment and Orchestration of ML and AI Workflows

Deployment infrastructure (Task 3.1)

  • 500 same-framework models, mostly idle → multi-model endpoint; different frameworks → multi-container; several LLMs sharing GPUs → inference components (packing).
  • 1 GB request, 20 minutes → asynchronous inference; spiky small requests → serverless; whole dataset offline → batch transform (inference styles).
  • Niche Marketplace model that must use Guardrails → Bedrock Marketplace (hourly SageMaker instances) (FM options).
  • Serve your own fine-tuned open model serverlessly → Custom Model Import (scales to zero, cold starts) (outside models).
  • Agent with your own loop and multi-agent graph → AgentCore Runtime; tools from APIs → Gateway; agent-to-agent → A2A (port 9000), tools → MCP (port 8000) (agents).
  • 70B model in fp16 → about 140 GB of weights: tensor parallelism, bigger instance or quantization (sizing).

Provision and configure resources (Task 3.2)

  • Guaranteed GPUs for an endpoint → training plan with CapacityReservationConfig; Savings Plans lower price only (capacity).
  • Share VPC IDs between stacks without export locks → SSM parameters or Fn::GetStackOutput; Ref on SageMaker hosting resources returns the ARN (IaC).
  • Tag always means the same image → ECR tag immutability and digests; language package CVEs → enhanced scanning (containers).
  • Force models into approved subnets → sagemaker:VpcSubnets with a Null check; serverless has no VPC (VPC).
  • Scale an LLM endpoint → high-resolution concurrency metrics; classic models → invocations per instance (peak × 0.5 × 60) (scaling metrics).
  • Knowledge base never refreshes → schedule or trigger StartIngestionJob; multi-tenant → server-side metadata filter (retrieval pipelines).
  • Agent forgets the customer between sessions → AgentCore Memory long-term strategies by namespace (agent state).

Orchestration and CI/CD (Task 3.3)

  • Roll out a model safely with automatic rollback → endpoint DeploymentConfig canary or linear with alarms (CodePipeline has no SageMaker action) (rollouts).
  • Pipeline never starts after connecting GitHub → CodeConnections connection still PENDING (developer tools).
  • Refuse a model worse than the threshold → ConditionStep plus FailStep in SageMaker Pipelines (pipelines).
  • Retrain when needed, not blindly → drift alarm or new data through EventBridge to the pipeline (no underscores in parameter names) (retraining).
  • Who approved which model → Model Registry approval status, lineage, CloudTrail (versions).
  • Promote an agent version, roll back instantly → AgentCore named endpoint moved between versions; DEFAULT follows the latest (agent pipelines).
  • Swap a fine-tune without changing callers → UpdateCustomModelDeployment or Provisioned Throughput desiredModelId (FM versioning).

Domain 4: Operating, Monitoring, and Securing ML and AI Solutions

Monitor inference and performance (Task 4.1)

  • Bedrock token, latency and error views → CloudWatch generative AI observability; request table needs invocation logs in CloudWatch Logs (observability).
  • Error rate misses throttles → throttles are in neither Invocations nor errors; add them with metric math.
  • Pipeline failed overnight → EventBridge execution status event to SNS; the reason is on the step event (workflow errors).
  • Join late labels to predictions → data capture with InferenceId (data changes).
  • Which variant answered → InvokedProductionVariant in the response (A/B).
  • Answers cut off but no errors → stopReason max_tokens; tool failures return as results (agents).

Optimize costs and performance (Task 4.2)

  • Which instance type for this model → Inference Recommender (cost per inference) (instances).
  • Slow in my model or the platform? → ModelLatency versus OverheadLatency; slow step across services → traces (troubleshooting).
  • Per-team Bedrock costs → tagged application inference profiles, cost allocation tags, Budgets (cost tools).
  • Steady SageMaker usage for a year → SageMaker Savings Plan (Compute Savings Plans don't apply) (purchasing).
  • Bedrock bill driven by long answers → output tokens cost several times input: maxTokens, concise prompts (FM costs).
  • Agent runtime costs high while it waits → memory bills for the whole session; end sessions, shorter idle timeout (agent costs).

Secure workloads and endpoints (Task 4.3)

  • Block vulnerable images in the pipeline → Inspector SBOM scan in CodeBuild or the InspectorScan action (CI/CD).
  • User passes an admin role to a job → limit iam:PassRole with iam:PassedToService (roles).
  • Who called the endpoint → CloudTrail data events for InvokeEndpoint; Bedrock calls are management events (audit).
  • Untrusted model must not send data out → network isolation; distributed training → self-referencing security group (isolation).
  • Instructions hidden in an uploaded document → indirect prompt injection: prompt attack filter, input tags, least-privilege tools (risks).
  • Client library expects an API key → short-term Bedrock API key; block long-term keys on bedrock and bedrock-mantle (credentials).
  • Users must not skip the guardrail → bedrock:GuardrailIdentifier condition or organization-level enforced guardrails (safeguards).

Numbers worth knowing

Data and models (Domains 1 and 2)
Labeling
Automated data labeling needs at least 1,250 objects, 5,000 recommended (Task 1.3)
Fine-tuning data
Nova Micro, Lite and Pro: 8 to 20,000 samples, 32K context; Nova 2 Lite: 200 to 20,000, no validation set; distillation: 100 to 15,000 prompts (Tasks 1.2, 1.3)
Embeddings
Titan Text Embeddings V2: 256, 512 or 1,024 dimensions; Cohere Embed v4: 256 to 1,536 (Tasks 1.2, 2.2)
Spot and capacity
Spot training up to 90% off; Savings Plans up to 64%; training plans 1 to 182 days (Task 2.1)
Bedrock tiers
Flex about 50% cheaper, Priority about 75% dearer; batch 50% off for 100 to 100,000 records; global profiles about 10% cheaper than geographic (Tasks 2.1, 4.2)
Nova on Bedrock fine-tuning
epochCount 1 to 5 (default 2), learningRate 1e-6 to 1e-4 (default 1e-5), warmup 0 to 100 (default 10) (Task 2.2)
Shadow tests
One shadow variant; up to 100% sampling; 7 days by default, 30 maximum (Task 2.3)
Deployment, operations and security (Domains 3 and 4)
Inference limits
Real-time 6 MB and 60 seconds; serverless up to 6 GB memory and 4 MB payloads; asynchronous 1 GB and 1 hour (Task 3.1)
Custom Model Import
Text models under 200 GB, context under 128K; scales to zero after 5 idle minutes; 3 imported models by default (Task 3.1)
GPU memory
fp16 weights = parameters × 2 bytes (13B about 26 GB, 70B about 140 GB); startup timeouts up to 3,600 seconds (Task 3.1)
Scaling
Target invocations per instance = peak RPS × 0.5 × 60; default cooldown 300 seconds; high-resolution metrics every 10 seconds (Task 3.2)
AgentCore
Sessions idle out after 15 minutes, last up to 8 hours; streams up to 60 minutes; ports HTTP 8080, MCP 8000, A2A 9000 (Tasks 3.1, 3.2, 4.1)
Prompts
10 versions per Bedrock prompt (not adjustable) (Task 3.3)
Bedrock API keys
Short-term keys valid up to 12 hours (Task 4.3)

Status changes

The exam guide no longer names several of these, but older questions may still expect them. The services page has the full list.

Closed to new customers or ended

  • SageMaker Clarify, Model Monitor, Ground Truth, Augmented AI (A2I) and Debugger: closed to new customers since 30 July 2026; use pandas and SHAP, Evidently and MLflow, your own labeling, TensorBoard (Tasks 1.3, 2.3).
  • Amazon Kendra, Amazon Q Business, Bedrock Agents (now Agents Classic): closed to new customers since 30 July 2026; use Managed Knowledge Bases, Amazon Quick, AgentCore (Tasks 2.1, 3.1).
  • Amazon Forecast (29 July 2024) and Amazon Fraud Detector (7 November 2025): closed to new customers; use Canvas or SageMaker AI (Task 2.1).
  • Comprehend topic modeling, event detection and prompt safety classification: closed to new customers on 30 April 2026; toxicity and PII detection unaffected (Tasks 1.3, 2.1).
  • Rekognition streaming video and bulk image analysis closed to new customers on 30 April 2026; People Pathing ended 31 October 2025 (Task 2.1).
  • SageMaker Edge Manager ended 26 April 2024; Elastic Inference is no longer available (Task 3.1).
  • Amazon CodeGuru: Reviewer accepts no new repository associations and CodeGuru Security is no longer in the documentation; use Amazon Inspector and Amazon Q code reviews (Task 4.3).
  • AWS Audit Manager and SageMaker Role Manager no longer accept new customers (Task 4.3).
  • AWS X-Ray SDKs and daemon in maintenance mode since 25 February 2026; use OpenTelemetry (Task 4.2).
  • Bedrock models: all Meta Llama models Legacy or end of life; Claude 3 Haiku fine-tuning ended (Task 2.1).

Renamed, moved or reopened

  • Data Wrangler now lives inside SageMaker Canvas; Autopilot's interface moved to Canvas, its API remains (Tasks 1.2, 2.1).
  • AWS CodeCommit open to new customers again since 25 November 2025; SageMaker Projects CodeCommit templates are still gone (Task 3.3).
  • CodeStar Connections renamed AWS CodeConnections in March 2024 (Task 3.3).
  • SageMaker Python SDK v3 replaces Estimator with ModelTrainer (Task 2.2).
  • MLflow Apps (serverless MLflow, December 2025) are AWS's recommended way to track experiments (Task 2.3).
  • Bedrock Managed Knowledge Bases (June 2026) are AWS's recommended knowledge base type (Tasks 2.1, 3.1).
